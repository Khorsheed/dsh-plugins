# masked credential proxy（假 key 换真 key）

- **分类**：plugin
- **状态**：idea（状态机无 `future`，按作者原话记 idea —— 能力目录的「skill env 注入（default-hide）」先跑通；本方案是后续防诱导加固，**本迭代不实现**。）
- **最后更新**：2026-08-29
- **官方依赖**：未定（两种候选形态都在插件侧：catalog 或兄弟插件的窄代理 / 短期句柄 + 映射；是否需上游契约扩展待立项时核）
- **问题**：即便 key 以 `DSH_*` 只进 shell 环境（模型默认看不到，但可 `echo` 主动读），**恶意注入/越狱仍能诱导模型 print 出明文**。只要模型持有真实 secret，套取风险就无法根除。
- **目标**：让模型**在正式调用前接触到的只是一个「假 key」**，实际发起操作时由一个可信组件**用真 key 替换**——模型始终不掌握真 secret，故无法被诱导出明文。
- **形态（两种候选）**：
  1. **代理/网关**：模型把「要执行的操作 + 假 key」交给 catalog（或兄弟插件）提供的**固定窄代理**；代理在真正调服务/API 前，从凭据库 `resolve(credentialRef(realKey))` 取真值替换假 key，再去执行。模型看到的、能 echo 的只是假 key。
  2. **句柄/一次性票据**：catalog 给模型发一个**短期句柄**（非 secret），服务端记住句柄→真值映射；模型用句柄调服务，服务端在落地前换真值。
- **关键约束**：
  - **窄 + 固定**：代理只允许固定的操作/接口（不能让模型指定任意命令/任意外发），否则「带密钥执行任意操作」本身就是大风险。
  - **真值不进模型上下文**：替换发生在服务端/落地前；工具结果、错误、日志不得含真值。
  - **每次现场 resolve**：凭据轮换立即生效。
- **与 default-hide env 注入的关系**：env 注入是「默认隐藏但可被诱导」；本方案是「模型压根不持有真值」——更硬的安全边界。代价：需要 catalog 认识那几个固定操作（不再完全服务无感）。
- **overlap**：这本质是「服务感知窄工具」的再上一层（窄工具已经做到真值不进模型；本方案更进一步连「假值/句柄」层面把真值隐去）。可作为合并/后续演进的方向。
- **备注**：若将来某 skill 确实需要「模型自己发任意查询且不能泄真值」，须回到本方案（窄代理）；这要求把「服务/操作」从模型侧挪到可信组件侧。
