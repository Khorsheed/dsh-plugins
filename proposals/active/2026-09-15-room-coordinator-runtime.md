- **分类**：plugin
- **状态**：idea

- **官方依赖**：纯插件（目标方案使用现有公开扩展面；具体宿主版本和传输能力须在 M0 验证，缺口走 upstream-change，不修改官方源码）

## 目标

用户进入 room 后，普通输入直接与协调者持续对话；协调者可以由原生 DSH、Codex、Claude Code 或 Kimi 承担，模型可选择。用户只有在指定其他角色时才需要 `@成员`。

第一版冷启动沿用原生 DSH：先邀请成员，再将已加入且就绪的成员设为协调者，之后普通输入才默认交给该成员及其模型。邀请不要求先 @ 任何人，也不自动转移协调者角色。

协调者在同一个房间中实时输出，能读取目标与必要上下文、组织不同颗粒度的任务、派发给合适成员，并根据成果、失败和阻塞继续推进。用户可随时补充要求、停止或接管。

本提案分两次交付：

1. **交付 A：统一交互底座。** 可靠模型选择 + 真实生成增量 + 可回放记录 + 可切换的默认协调者，支持普通聊天中的后台委派与自动回报。到此可正常持续对话、人工 @ 和轻量协作，不宣称自动目标闭环已完成。
2. **交付 B：目标闭环。** 目标 → 阶段计划 → 执行任务 → 成果回报 → 验收/返工 → 后续派发，具备持久队列、预算与暂停恢复。

## 1. 用户行为与待确认决定

下表是建议采用的产品合同，尚待确认。

| 编号 | 场景 | 建议行为 |
|---|---|---|
| D1 | 进入 room，发送普通消息 | 服务端路由到当前协调者；外部协调者直接 start/resume，不经过 DSH main 的模型转发 |
| D2 | `@成员` 或从 @ 菜单选中成员 | 只派发到明确选择的成员；不额外唤醒协调者。沿用既有 @ 解析规则，不把普通正文中的任意 @ 都当命令 |
| D3 | 创建/启用房间 | 保留“普通会话提升为 room”的入口；新房间和未配置协调者的旧 room 先用原生 DSH。通过邀请入口加入成员，再显式“设为协调者”；邀请本身不改变默认对话对象。重开已切换的 room 恢复其协调者 |
| D4 | 用户与成员单独 @ 对话 | 仍是房间内公开记录，不是私聊；协调者下轮可读取相关增量，但这条对话不自动成为给协调者的新指令 |
| D5 | 工作进行中用户再次输入 | 原生支持 steering 的参与者可接收运行中补充，否则显示为排队；不以取消重跑伪装 steering |
| D6 | 停止 | 输入框 Stop 停当前协调者轮次，并暂停它的自动续行；“暂停目标/停止全部成员”是独立、明确的房间操作 |
| D7 | 更换协调者 | 从已加入且就绪的成员中选择；原协调者与候选成员均空闲、无待处理输入且模型控制已收敛时，先暂停自动编排、持久保存交接信息再切换；不强行迁移外部 CLI 原生历史 |
| D8 | 委派与目标编排 | 普通聊天中的执行请求即可授权范围内的后台委派与自动回报；大目标由协调者决定是否建计划、拆分、并行和接力，无需用户先开模式或点启动。仅讨论方案/保存草稿不自动执行，既有暂停与预算仍有效 |
| D9 | 模型菜单 | 统一显示名称、选择值、推理选项与加载状态；保留自定义 ID；“继承配置”“harness 默认”“最近实际运行”各有明确含义 |
| D10 | 第一版任务规模 | 一个活动协调者，少量可配置并发成员；表达目标/里程碑/任务，第一版调度叶子任务之间的依赖，不开放无限递归建队 |
| D11 | live 输出粒度 | M2 整体退役 event 镜像档，真实增量成为唯一 live 输出路径；兼容读取旧配置，exec 评测模式保留 |
| D12 | 模型/effort 变更 | 随时选择，下一轮生效；core 持久保存待生效配置，room 与成员 composer 共用当前/待生效状态，支持覆盖与撤销。当前轮不变，评测冻结配置保持锁定 |
| D13 | 已有成员可见性与控制 | 保留面包屑/TaskPilot/页面入口到独立成员会话的导航、聊天记录、耗时/token 与单成员停止控制；更换协调者不撤掉其他成员的会话与操作入口 |

协调者缺席、未登录或协议不可用时，房间显示原因和恢复入口；不静默把消息交给另一个模型。配置加载前先等待路由状态，不短暂回落到原生输入框并误发首条消息。

输入合同同时声明文本、文件引用、图片等支持情况。第一版至少保证文本与可访问文件引用；不支持的附件在发送前说明，不能先接受再静默丢弃。真正支持的内容沿公共结构传递，不强制压成文本。

### 1.1 冷启动、邀请与设为协调者

第一版路径是：`原生 DSH 接待 → 邀请成员（harness、模型及可用 effort）→ 成员就绪 → 设为协调者 → 普通输入直达该成员`。用户可直接点击现有“邀请成员”入口，也可向当前 DSH 表达邀请要求并由工具执行；不依赖已有可 @ 的外部成员，不要求 DSH 先完成复杂目标拆解。

成员卡显示“设为协调者”动作，当前协调者显示徽标；输入框显示默认接收成员、harness 和当前/待生效模型。选择的是稳定成员身份上的协调者角色，不是固定的 harness+model 元组：该成员换模继续遵守 D12，不需要重新设为协调者。UI 统一称“协调者”，避免把原生 DSH 的内部 main 身份与可切换角色混用。

候选就绪至少包括登录/协议/协调者工具能力、工作目录和模型配置可用；无需先发一个无关任务来创建成员会话。若原生会话只能延迟创建，适配器在准备阶段完成必要初始化；准备或交接失败保留原协调者，不提前改变路由。切换提交后确认默认对象，并恢复可输入状态；已接收输入的目标不重写。

原生 DSH 在交接后保留为可 @、可切回的成员，不再自动消费普通输入。当前协调者不能直接移除，应先完成交接。第一版不做“保存外部 harness 为所有新房间默认”或自动邀请并晋升的模板；这是未来可组合的快捷流程，不是技术上只能由 DSH 协调。已保存外部协调者的 room 重开时恢复原选择，故障时明确提示，不按冷启动规则静默回落。

### 1.2 聊天即可委派，目标由协调者组织

“让 Kimi 查一下这个问题”是普通聊天中的执行请求：协调者选择已有成员或按授权邀请，提交后收到 accepted/queued 回执即可结束本轮或继续其他工作，不等待成员的最终结果才释放主对话。用户不必先创建目标、任务表或打开自动模式。插件保留轻量委派及回报记录供追踪，不强制展示完整阶段计划。

委派关联请求、成员、结果接收者与已授权范围。完成/失败/阻塞回报自动持久投递给协调者，不要求用户点击转发；协调者忙时进入 inbox，空闲时可触发一次处理轮，相关结果可合并。main 可据此汇总回复，或在原请求范围内继续必要协作。仅收到回报不授权无限派生新工作；用户直接 @ 成员仍遵守 D2/D4，不额外唤醒 main。

“不阻塞”指后台成员运行不占住协调者等待结果，也不锁住输入框；同一协调者仍遵守单轮串行与 D5 的 steering/排队规则。答案依赖成员结果时，显示等待该结果并让出执行，不空转轮询；用户可继续发消息，人类输入优先于尚未开始的自动回报处理，已有回报不丢弃。Stop/暂停之后结果可入账，但不绕过暂停唤醒；恢复沿原请求继续，不能重复派发。

“把这个大目标完成”同样可以直接在聊天里提出。协调者结合上下文与工作规模决定亲自执行、轻量委派或建立目标/阶段/任务并自动推进，计划按需逐步细化；用户不负责先把工作分级或手动编排。UI 展示已建立的计划、进展、证据与接管入口，按钮是等价操作入口，不是自然语言执行请求的前置门槛。仅讨论可行性、要求先出方案或只保存目标草稿时保持不执行；真正缺少必要信息时再澄清。既有暂停不被顺带聊天解除，用户明确要求继续或提出新的执行请求时才按其范围处理。

### 1.3 保留独立成员会话、统计与停止入口

协调者角色、默认输入路由和目标面板的改造不替代已有成员会话。非协调者仍可从现有面包屑/会话树、TaskPilot、room 运行行与成员卡等入口进入自己的会话，查看生成中与历史聊天、工具记录及已有统计，并独立发消息或停止当前轮。room 内的摘要/实时气泡是另一种视图，不能成为唯一记录或唯一控制入口。

保持稳定 child session ID、父子会话关联和运行身份；成员重命名、换模型、晋升/卸任协调者不重建会话树或使历史链接失效。某 harness 必须更换原生句柄时，适配器维护与既有成员会话的映射。面包屑与 TaskPilot 继续消费可识别的会话关系和运行状态；协调者角色不能冒充底层 parent/origin 属性。成员完成或被停止后，已有会话与历史入口继续可访问。

保留运行耗时和 harness 已提供的 token 消耗，刷新/重启后可回读。运行中显示已有真实用量，若只在结束时回报则保持“待回报”，缺失则标未知；不得以零替代。明确本轮/会话累计口径；累计快照替换同一记录，最终结果只校准一次，不能因真流式重绘、room 镜像、重复事件或角色变更重复计费。并行成员的耗时分别计算，房间总历时不简单相加；角色切换不重置既有统计。

保留用户所说的“暂停”入口，并如实区分底层行为：现有 Stop/interrupt 是停止成员当前轮、保留已生成内容，并非冻结 CLI 进程后原地接着运行。成员页、room 运行行与 TaskPilot 的停止动作必须命中同一个成员运行并同步状态；停止一个执行成员不误停协调者或其他成员。用户停止后该次工作标为 interrupted/需处理，main 可获知结果，但自动重试/派发不能绕过这次停止；用户继续或重新授权后再恢复。协调者 Stop 与目标级暂停/停止全部保持 D6 的作用范围。

TaskPilot 和相关宿主 UI 是兼容集成面，不新增 room 对它们的硬依赖。安装时保留现有入口与行为，缺席时成员页和 room 的导航/控制仍可用。M0 固定实际宿主版本、挂载组合与入口基线，M2/M3 用同一成员核对导航、记录、统计和停止，不能只验新 room 页面。

### 2.3 需要修正的假设与已发现问题

1. “Claude 没有 models 命令”不等于“没有枚举接口”。原生初始化目录应成为优先探索的主来源；原生目录仍可能只是候选快照，不保证穷举所有可输入 ID 或证明账号权限。
2. `/v1/models` 的 401 只能说明进入认证处理，不能单凭它证明有效凭据会得到完整、可运行目录。round3 当前固定官方端点、读取 macOS Keychain、未遍历分页；也未覆盖自定义网关与 CLI 有效模型限制。
3. round3 缓存冷读为空、后台完成无界面通知，失败覆盖成功缓存；读取时丢弃显示名称。认证失败、加载中与真实空目录未区分。
4. Claude 当前模型切换写共享 scoped `settings.json`，依赖内存保存原值，再退役进程并 resume。重启与并发成员读取存在语义风险，应验证原生 `set_model` 能否退役这条绕行。
5. Claude token 参数位于成员桥参数的 `--` 终止符之后；event → token 修改未重建缺少 partial 参数的存量进程。M2 退役粒度开关及其切换分支，不另修运行中切档；统一启动路径仍须保证 partial 参数被正确解析，并在升级时排空、退役旧进程，见 §5.4。
6. Codex 部分 MCP/动态工具只映射名称/参数，结果未完整映射；Claude 部分工具参数被摘要；room 输出只提取文本。当前“每行都 fold”不等于内容完整。
7. Codex/Claude/Kimi token 档的快照默认门槛是 `300ms/200字符`；例如 Claude 两个条件均满足才发布，稀疏输出还可能等待更久。四家 schema 仍默认 event；删掉 UI 粒度行没有改变机制。当前路径不能作为 §5.1 的 P95≤200ms 达标证据。
8. `DelegationCallOptions` 与 eval 的 `EvalDelegationOptions` 尚无 effort 通道。eval 条件已经含 `reasoning.effort`，`hashConditionDocument` 除 notes 外对整份条件取哈希；当前 `checkAgainstEffective` 对 effort 不匹配/缺失只作 warning。新增按次控制必须补执行约束，不能只添加菜单。
9. 当前 provider broker 的 `setMemberModel` 在成员忙时抛错，gateway/composer 展示拒绝原因。目标行为改为 core 接受并持久保存待生效选择，在轮次边界调用 provider 控制；room 与成员 composer 同步迁移，不保留两套说法。

## 3. 分层与公共接口

### 3.1 所有参与者使用一致的房间接口

```text
房间 UI：默认输入 / @ / 模型 / Stop / 任务与记录
                         ↓
room：成员身份、协调者选择、路由、任务与协作策略
                         ↓
参与者适配接口：能力、模型、会话控制、实时内容、回放
                ↙                         ↘
原生 DSH 适配器                     local-agent 家族适配器
官方 agent/model/events             Codex / Claude / Kimi / 子 DSH
```

协调者是角色，不是 provider 类型。稳定 member ID、显示名、harness、模型、原生会话句柄和协调者角色分别保存；重命名不改变任务归属与回报地址。

原生 DSH 直接适配公开 Agent/模型目录/事件，不为统一接口另起子 DSH。外部成员沿用 local-agent 的账号作用域、委派记录与恢复能力。底层因持久会话需要保留 DSH Agent 对象时，外部协调者消息不触发它的模型轮次；M0 实测确认没有双重消费。

成员工作目录和 scope 必须实际绑定到 provider 调用，不能只记在 roster。当前 room 未向门面传递 cwd 的缺口属于本阶段验证项；resume 更换工作目录或账号作用域时遵守家族约束，不能悄悄复用不匹配的原生会话。

### 3.2 core 统一机制，provider 取得事实，room 持有策略

| 面 | 统一内容 | provider 保留的差异 |
|---|---|---|
| 能力 | streaming、queue、steer、interrupt、resume、model switch、用户交互、内容类型 | 不支持的操作和当前不可用原因；配置为 live 不代表实际已用 live |
| 模型 | 丰富目录、选择/解析/观测状态、刷新与订阅 | 原生模型别名、认证、端点、协议、effort 取值 |
| 会话 | 发送回执、排队、中断、恢复、换模与能力检查 | 原生 thread/session 控制和进程生命周期 |
| 内容 | 有身份的增量、最终内容、工具参数/结果、可见错误、回放游标 | 原生事件到公共内容的映射，以及未支持类型的标记 |
| 交互 | 待回答问题、待处理批准、用户回复、取消 | harness 的原生交互请求与结果 |

不新增一套与现有 broker/facade 平行的 registry；采用增量接口与兼容读面。共用缓存、订阅和 UI 组件，而非复制四份菜单，也不把四家的抓取代码合并成一个大函数。

包依赖继续遵守独立安装规则：local-agent core 不依赖 room 类型或任务状态；room 通过可选适配调用家族，缺席时原生 DSH 可用。原生 DSH 适配器的放置、可选跨包声明及 tools 授权拓扑在 M0 固定，先过 `check:plugins`，不引入 core↔companion 循环。每个 provider 仍可在 room 缺席时独立委派。

## 4. 模型目录与选择语义

### 4.1 目录合同

目录项至少表达：原生选择值、显示名、已知的解析模型、原生推理选项、来源、是否支持自定义输入。目录快照表达：loading/ready/stale/error/unsupported、刷新时间、是否完整、诊断原因；已缓存内容可与刷新失败同时存在。

- 来源优先级：harness 原生目录 → 匹配当前环境的配置/网关目录 → 最近成功使用的建议。最近使用必须标为历史，不能冒充当前可用性证明。
- Codex 从 app-server `model/list` 读取并保留元数据，正确处理分页与 picker-visible/hidden 语义。
- Claude 从初始化/SDK 等价控制协议读取目录和默认解析；保留自定义 ID。HTTP 补充只有在端点、认证与权限语义明确且真实成功验证后启用。
- Kimi 优先探测当前 ACP 的模型面，缺席时读取实际作用域配置；DSH 使用对应会话可用的官方模型目录。
- 缓存按有效运行环境区分：provider、账号/scope、端点、相关配置/工作目录与 CLI 版本。缓存键只存非敏感身份或版本标识；不包含 token。
- 并发请求合并；认证/配置变化使目录失效；手工刷新有入口；刷新完成通知当前已打开菜单；短暂失败保留最后成功目录并标记过期。

### 4.2 选择、解析、实际运行分开

使用三个概念：`selected`（用户选择或继承意图）、`resolved`（运行前已知的解析结果）、`observed`（某轮实际报告的模型）。未知保持未知，模型替换/降级应显示。

“清除会话覆盖，回到委派时固定模型”不能标成“跟随 provider 设置”。第一版明确区分继承成员配置、显式 harness 默认与指定模型；持久保存用户意图，重启恢复同一语义。provider 原生别名保持原样，不能为了显示全名把动态别名改成固定版本。

Claude 先验证原生 `set_model` 的 fresh/resume/失败路径，再移除临时共享文件写入。变更成功回执后更新已应用配置；失败不能把待生效选择标为已应用。必须用真实后续轮次验证实际模型，控制 ack 不算出模证明。

**随时选择，下一轮生效。** 用户在生成中也能选择模型/effort；当前轮（含工具调用及后续生成）继续使用其启动时固定的配置。界面同时显示“当前使用 A / 下一轮使用 B”，收到持久接受回执后显示待生效，不能提前把 B 标为当前实际模型。空闲时可立即应用，单独换设置不触发模型生成；需要立即切换时，用户停止当前轮，待中断确认后应用新配置，再发送消息继续，已有输出保留。

local-agent core 持有成员的当前已应用配置、待生效模型/effort 组合、revision 与控制操作状态；provider 只实施原生控制，room 不持有私有换模队列。room、成员 composer 与其他控制入口读写同一状态并接收更新；原生 DSH 适配遵守同一合同。采用一个可覆盖的待生效配置槽，不按 FIFO 逐个执行所有中间选择：连续修改以 core 接受的最后有效 revision 为准，无效请求不覆盖之前有效选择；重复请求按 ID 去重，过期页面提交以 revision 冲突回执要求刷新。

轮次边界先处理最新待生效配置，再准入下一轮；已排队但尚未准入的普通消息也使用新配置，排队界面应说明这一点。准入与配置提交串行化，并为该轮绑定不可变 revision：与启动并发的修改若晚于准入，只影响再下一轮，回执明确其目标边界。应用中收到更新时保留最新意图，在新轮准入前完成收敛，不能因旧控制 ack 迟到覆盖新选择。权限等待、工具执行等仍属活动轮次，不是换模边界。

支持撤销待生效选择，撤销请求绑定 revision，不能误删另一入口更新的选择。尚未调用 provider 时直接清除；已在应用时先对账并恢复该次变更前的已应用配置，再解除下一轮准入阻塞；若变更已完成则明确报告已生效，回到旧配置应作为新选择。回执区分 pending/applying/applied/cancelled/failed/conflict，UI 区分已接受与已生效。

应用失败或回执不明时保留待生效意图及错误，阻塞该成员下一轮，包括自动续行；对账确认当前状态后允许重试、改选或撤销，不静默使用旧配置继续。重启恢复当前/待生效 revision 与操作状态，先和原生会话对账，再应用未完成选择；不得盲目重复已成功的控制。provider 不支持当前会话的组合或切换方式时明确返回 unsupported；可验证的退役进程并 resume 可由适配器实施，不能用丢弃会话历史的新会话冒充换模。

§6 的消息队列与此控制状态共用 core 准入仲裁。评测冻结配置在接受选择前返回 locked，不进入待生效槽；更换协调者仍遵守 D7 的交接规则，不等同于同一成员换模型。

### 4.3 effort 从选择贯通到运行

- 共用模型菜单按当前模型能力展示 effort 选择；保留原生值及默认/继承意图，例如 Codex 的 `supportedReasoningEfforts`。不能把四家的同名 high 当成等价计算预算；不支持的组合不可选，自定义模型的能力未知时明确标记并验证，不能静默忽略请求。
- 扩展 `DelegationCallOptions`、broker/控制面、持久委派记录、各 provider 的 live/exec 请求，以及 eval 的 `EvalDelegationOptions`。模型与 effort 作为一个配置组合验证和生效；更换模型使旧 effort 无效时明确要求选择，不暗中回落。原生控制无法原子更新时由适配器串行执行、失败回滚或对账，在确认前不准入新轮次。
- start 固定本次委派的模型/effort 意图，resume 默认重用持久值；不通过 resume 参数绕过轮次边界控制和评测锁。交互会话经统一控制面提交选择，在下一轮准入前应用并绑定新的配置 revision；旧轮次记录不重写。缺省字段兼容旧调用的配置继承语义。
- 逐轮记录 requested/resolved/observed effort（原生未回读则 observed 未知），与模型、配置 revision 一起留证；界面选中和控制 ack 都不能代替运行证据。执行能力验证通过后才开放对应旋钮。

### 4.4 web-eval 冻结条件与兼容

现有条件已经把 `reasoning.effort` 纳入公平因子，本次不重复造字段或重算历史基线。eval 从冻结条件传递模型/effort，覆盖选手与判官、宿主 exec 与容器 exec，以及多轮恢复；room/成员控件不得覆盖评测锁定的委派配置。

按次覆盖加入后，scope 的 `effectiveSettings` 只能证明默认值，不能独自证明本次执行值。校验应结合冻结声明、实际请求、provider 生效证据和可得回读：不支持所声明 effort、请求偏离条件或回读明确不匹配时，在执行前拒绝，或在执行后将该次标为不可比较；无法验证时明确记录未验证，不能当作已匹配进入严格基线。不能继续仅靠现有 warning 放行并宣称公平条件成立。

保持既有条件哈希算法、旧条件文件、lock 与历史结果不变；新增运行元数据可采用兼容的可选字段。变更 effort 必须创建新的条件/锁与 run，不在进行中的 run 更新锁。旧基线记录缺少新证据时如实标记，不回填“已验证”。若必须改变条件语义或 schema，M0 明确版本迁移与对照重跑范围，不能顺手重写旧 digest。M1 由 eval owner 同步校验、基线 fixture 与文档后才开放评测侧 effort 通道。

## 5. 真流式、内容完整性与回放

### 5.1 真流式的定义

harness 仍在生成时，room 同一个气泡持续显示已收到的原生增量，不等待完整 assistant message 或 turn/result。不把最终文本拆字回放来模拟。传输仍是事件，差异在于负载是生成中的增量。

建议 UI 合并刷新窗口 30–100ms，可调；在声明的本地验收条件下，增量到达 provider 后到界面可见的 P95 目标不超过 200ms，不含模型生成与外部网络等待。长消息受限速时仍须持续推进，最终更新不能被丢弃。

该指标是 M2 必过项。实时发布使用有最大等待时间的定时 flush，字符门槛只能触发提前刷新，不能阻塞到累计 200 字符；最后一小段也不等待下一个 delta。拆开实时投影与耐久快照的调度，不能让 `300ms/200字符` 落盘门槛继续阻塞唯一 UI 通道。若公开宿主接口不能支撑该时延，M0 记录接口缺口，M2 保持未通过，不放宽口径宣称达标。

验收记录 provider 收到增量、发布与浏览器实际绘制时间；跨进程/浏览器计时需校准时钟并报告误差，不能直接相减未同步的时间戳。覆盖低速小片段、突发输出、长文本与声明并发量，报告样本数、P95、最长停顿；除规定本地环境外的网络表现单列。

### 5.2 内容事件与权威终态

- 每个更新绑定 member/session、run/turn、item/message、content part、序号；明确 append-delta、replace-snapshot、final 三种语义。
- 正文、模型公开的思考/摘要、工具调用、工具结果、附件/产物引用、错误分开。不能拼接现有裸 `RunProgress.delta.text` 作为答案。
- Claude 使用原生消息/内容块边界及子代理关联字段配对；Codex 使用 item ID；Kimi/DSH 依各自原生标识映射。多次同类文本、并行工具、嵌套子代理不得互相覆盖。
- 完成时用原生权威最终内容校准同一 item；不能再追加一份相同最终答案。中断保存已有内容并标记 interrupted，不能显示为验收完成。
- 未支持内容类型保留可诊断标记和安全的原生记录引用；工具卡可折叠，但完整可见参数/结果应可展开或跳转。脱敏、大小限制与省略均明确显示。
- “完整”以 harness 对外提供的用户可见记录为边界；不承诺不可获取的内部状态或隐藏思考。不得存储协议凭据、认证消息或未经筛选的全量原始 wire。

### 5.3 实时通道与耐久通道

优先复用宿主公开流式/推送面和现有 session 镜像；若只能使用插件自有快照，也须在生成中持续更新。M0 验证承载方式、宿主投影与计费聚合，不能先假定 Typert 普通 RPC 天然支持订阅。

实时增量不要求逐 token 落日志。采用有界内存状态、节流检查点、权威最终记录；为长输出设置日志放大与背压边界，避免反复保存全前缀导致无界增长。

刷新/断线重连先读检查点，再按游标补齐；旧重复项幂等忽略。终态必须可回放；进程崩溃尾部缺口通过原生记录对账修复，无法修复时明确标为不完整。协调者活动气泡不能在中断或浏览器刷新后消失。

### 5.4 event 镜像档退役与升级

M2 删除四家 live driver 的 event/token 行为分叉、粒度 setter 与 schema 中 event 默认值，live 统一消费原生生成增量。退役对象是“等待完整事件才镜像”的档位，不是生命周期事件、权威终态校准或 exec 执行模式；web-eval 继续保留冻结的 exec 条件。

旧配置中的 event/token 键兼容读取并归一到唯一 live 路径，不因未知旧键导致启动失败；新配置不再写出粒度选项，升级提示说明语义变化。实际降级 exec 或协议缺失必须显式报告，不保留一个伪称 live 真流式的静默 event 回退。

Claude 的 partial 输出参数在统一启动路径中无条件按协议正确放置，必须位于 `--` 之前，并以真实 CLI 参数解析验证。移除开关不自动消除参数位置错误；这里作为启动路径重构验收，不单开切档修补。已有进程在升级时先排空活动轮次，再退役并按新合同重建/resume；记录待升级状态，不能把旧进程留在新能力标签下。无须再维护运行中 event→token 切换，但一次性升级收敛不可省略。

## 6. 默认协调者、会话控制与交接

1. 服务端持久保存当前协调者 ID 与 revision。人类输入进入同一 room 路由：明确 @ 优先，否则取当前协调者。
2. 接收时固定目标与消息 ID 并保存；路由切换不能把已接收消息悄悄改投另一成员。重试使用同一幂等 ID。
3. 同一成员串行运行；所有入口共用 core 成员消息队列，包括 room、成员 composer 与其他 facade 调用，不依赖 room 内存 FIFO 解决跨入口竞争。模型/effort 控制遵守 §4.2 的持久待生效状态，共用同一准入仲裁，在下一轮准入前优先收敛，不作为普通消息入队。
4. 接受、排队、开始、完成、失败分别回执；未知状态不解释成成功。已入队且未执行的意图可恢复；崩溃时无法证明是否已执行的任务进入对账/待处理，不盲目重跑有副作用的操作。
5. 输入框的模型/effort、运行状态、队列、Stop 与交互请求均绑定当前协调者；其他成员具有自己的状态和操作入口。
6. 普通对话不自动新建正式目标任务。聊天中的执行请求可后台委派并自动回报，保留轻量运行记录；协调者需要跨步骤计划和依赖时再建立正式任务。原有“每次派发自动开任务”与目标任务分离，避免任务板塞满聊天消息。
7. 原生 DSH 与外部协调者使用同一房间工具语义。外部工具根据已认证成员身份解析父 room 和角色权限，不能信任模型自行传入的任意 room ID；不直接沿用 child session 作为 room ID。
8. 从既有会话启用外部协调者或更换协调者时，发送目标、约束、已确认决定、开放任务、必要成果引用与上下文摘要；保留原始记录可追溯入口，不广播全部历史。
9. 更换 harness 创建/选择另一原生会话；旧会话保留。交接范围、目标 revision 和待回报任务持久化；迟到回报按 task/run 身份入账，不污染新的任务轮次。

现有 unattended 自动允许/拒绝策略不能直接成为人类面对协调者的交互合同。provider 报告需要用户输入时，room 显示可回答请求并回传；取消或超时有明确结果。原有用户授权持续有效，不重复审批已授权的普通协作步骤。

### 兼容、迁移与退回

协调者选择、模型意图、任务和消息投递使用版本化的增量 journal 词汇；旧记录无协调者字段时映射原生 main，旧名字式成员引用通过迁移映射到稳定 ID。兼容逻辑不得把“外部协调者失败”解释成旧 room 并自动转投 main。

功能按房间显式启用，先在隔离开发实例验收。禁用自动编排只停止续行与新派发，不删除记录；切回原生 DSH 按同一交接规则执行。降级旧插件前需验证其可读取新日志，不能假设忽略未知事件就是兼容；不能兼容时保留可导出的交接摘要和已验证版本。卸载时停止订阅、解除等待、收敛所属运行资源，保留可回放记录。

## 7. 目标驱动协作闭环

### 7.1 模型作决策，插件推进可靠状态

协调者负责理解上下文、选择成员、逐步拆分和验收；插件负责持久任务、依赖检查、投递、并发、预算及状态转换。模型不能仅凭一句“完成了”绕过必要证据。

任务合同包含稳定 ID、parent/milestone、目标 revision、负责人、输入引用、产物位置、验收标准、依赖 task IDs、状态与尝试记录。第一版只调度可执行叶子任务；计划可逐阶段细化，不要求一次拆到底。

建议状态：`pending → ready → running → submitted → accepted`，并允许 blocked、failed、cancelled；返工创建新 attempt 保留历史。进程一轮完成只代表 run settled；不自动将任务置 accepted。依赖默认在前置任务 accepted 后释放。

### 7.2 房间工具与自动回报

提供统一的读取增量状态、邀请成员、任务增改、派发/补充消息、报告成果/阻塞、验收/返工、暂停/继续面。工具名称在 M0 固定；外部 MCP 与 DSH room-tool 调用同一服务规则。

- 协调者拥有已授权范围内的组织和验收能力；执行成员可读取相关任务、报告本任务、通知允许的成员，不能自行改变全局协调者或扩大预算。
- 已授权委派的成果/阻塞/失败在 journal 落地后进入持久 outbox，自动通知协调者；轻量委派和目标任务共用这条路径，不以是否有正式目标为门槛。忙时排队，同批结果可合并，暂停时只入账不唤醒。发送方看到真实 delivered/queued/failed 回执。
- 接收端 inbox 按消息 ID 去重，采用至少一次投递 + 幂等受理，不宣称跨进程副作用恰好执行一次。传输重试与任务重试分别计数。
- 普通 @ 聊天不触发递归通知；授权委派通过请求关联自动回报，目标任务通过明确依赖自动接力。未关联授权工作的主动消息沿既有手动通知策略，不把它套到 main 已派发工作的回报上。
- 若所有任务在等待运行/外部输入，协调者休眠等待事件，不空转轮询。目标完成必须有验收证据；持续无进展、预算耗尽或异常循环进入暂停/需用户处理。

### 7.3 上下文、预算与恢复

协调者得到房间摘要、决策、任务图和自上次游标以来的结果；成员得到角色、目标、相关任务与依赖产物。全量历史按需查询，不强制复制给每个成员。上下文来源与任务归属可追溯。

显式配置并发数、运行轮次/重试上限、时间与可用的费用/token 预算。跨 harness 缺失的用量保持未知，不能填零伪装满足预算；先提供可机械执行的轮次/时间上限，费用硬门限仅在可可靠计量时承诺。

暂停目标停止新自动派发，并清楚展示仍在运行的成员；“停止全部”另行取消其轮次。用户取消不得被后台 idle/goal 驱动重新唤醒。宿主重启保存任务和待投递回报，但第一版自动执行保持暂停，用户继续后对账并恢复。

与宿主 goal 服务明确一个目标状态真源和一个续行所有者：不让 room 与 goal-round-driver 同时为空闲协调者排续轮。M0 决定复用/映射方式，并保留单 agent goal 的独立行为。

### 7.4 UI：保留聊天主界面，扩展目标与任务面板

目标闭环需要 UI 调整，优先扩展现有成员卡、目标/任务胶囊、展开面板与聊天事件，第一版不要求另建大型工作台或可编辑 DAG 画布。用户应直接看懂“谁在协调、当前阶段、谁在做什么、卡在哪里、成果在哪、是否需要我处理”。

| 表面 | 第一版调整 | 交付阶段 |
|---|---|---|

| 目标胶囊与展开卡 | 无目标时提供可选“设定目标”入口，与邀请并存且不阻塞普通聊天；保存草稿不启动执行，聊天中的执行请求或“开始推进”按钮都可启动，协调者自动建立必要计划。展示当前阶段、运行/暂停/需用户处理/完成、预算与继续入口 | M5 / B |

目标任务状态来自 §7.1 的同一持久数据；UI 不从聊天文本或某轮结束推断“已完成”。协调者可按既定验收标准自动验收，常规成果不逐项强制用户批准；需要用户决策或用户主动接管时才突出人工入口。计划调整记录 revision 与原因，不覆盖已经提交的成果。

现有 Todo 条需明确归属：协调者的轮内计划可以跟随当前成员展示并标注来源；原生未提供时不伪造。轮内 Todo 与房间的阶段/任务分开，前者完成不自动验收后者；切换协调者后不能继续把旧 DSH Todo 当成新协调者计划。目标任务计数以已验收叶子任务为准，排除取消项与重复 attempt，并显示计划 revision；逐步拆解会改变分母，第一版优先显示“已验收 3 / 当前计划 8 项”，不把它包装成目标工作量完成百分比。目标完成仍须目标级验收证据。

长任务列表按阶段折叠，详情按需展开；窄屏保持邀请、协调者身份、目标状态和待处理事项可达。所有操作走相同服务校验，失败显示原因；刷新/重连后从持久状态恢复，不因前端乐观更新把未提交、未验收或未交接标成成功。

## 9. 验收标准与交付边界

### 9.1 交付 A 必过

- [ ] 同一非协调者运行可由已安装的面包屑/会话树、TaskPilot、room 运行行与成员卡进入同一成员会话；运行中、结束、中断及刷新后记录可查。晋升/卸任、重命名与换模不破坏历史入口。
- [ ] 已有耗时/token 展示保持可用，本轮与累计统计口径明确；流式快照、最终校准、重连重复事件及角色变更不重复累计，缺失/尚未回报不显示为零。
- [ ] 成员页、room 与 TaskPilot 分别停止同一成员的等价测试均通过，状态同步、部分内容保留且不误停其他成员；停止后不自动重试该工作，用户可明确继续。TaskPilot 缺席时 room/成员页仍可导航与控制。
- [ ] 无正式目标时，“让 Kimi 做件小事”可后台委派并返回 accepted/queued；Kimi 未完成时用户可继续与 main 对话，不必等其 result，也不强制填写目标/任务表。
- [ ] 轻量委派的完成/失败/阻塞自动回报并可由 main 汇总；忙时排队、重连去重，暂停时不唤醒；直接 @ 聊天不额外驱动 main。结果依赖只阻塞依赖工作，不锁住整个房间或空转等待。
- [ ] 无外部成员的新房间默认直达 DSH，邀请不依赖 @；邀请成功保持原协调者，候选就绪并显式设置后才切换默认路由。无需先派发无关任务；准备失败不改变默认对象。
- [ ] 切换后成员徽标、输入框接收者与控制状态一致；原生 DSH 可 @、可切回；重开保存的外部协调者 room 不回落 DSH，当前协调者移除受交接约束。
- [ ] 每种协调者：用户无 @ 连续聊两轮，命中同一正确会话；@ 另一个成员只投递一次且不额外驱动协调者。
- [ ] 外部协调者首条消息、重开 room、配置加载窗口均无 DSH main 隐式模型轮次。
- [ ] UI 在最终结果到达前显示真实增量；长输出持续增长；多文本块、公开思考、并行工具、工具结果均有正确归属和顺序。
- [ ] 全新默认配置、旧 event/token 配置升级及旧进程排空重建均走唯一 live 增量路径；Claude partial 参数确实被解析；exec 模式明确区分。
- [ ] 按 §5.1 在稀疏小片段、突发/长输出及声明并发下测得 P95≤200ms；末段定时刷出，持久快照节流不阻塞实时投影。
- [ ] 三处保真对比覆盖文本、工具参数/结果、错误、附件/产物引用、子代理关联；不支持项明确标记，不静默丢弃。
- [ ] 中断保留部分输出；中断后再发送正常续聊；浏览器刷新/断线/宿主重启不会重复最终答案或丢掉已经耐久保存的记录。
- [ ] 模型目录覆盖冷加载、缓存命中、刷新、认证失败、无网络、有效配置变化和自定义 ID；失败不伪装为空目录。
- [ ] 换模型请求、确认状态和下一轮实际模型分开验证；两个同家成员选择不同模型互不污染，重启恢复意图；未知 observed 不以默认猜测补全。
- [ ] 生成中可选择模型/effort；room 与成员 composer 同步显示当前/待生效配置。当前轮及其工具链保持旧 revision，下一轮（含先前排队但未准入的消息）使用已确认的新 revision；空闲改选不触发生成。
- [ ] 连续有效选择以最后接受 revision 为准；无效选择不覆盖有效待生效值。覆盖、撤销、重复请求、多入口过期 revision、应用中再次改选及与下一轮准入竞态均有测试，旧 ack 不覆盖新意图。
- [ ] 控制失败/回执不明阻塞下一轮和自动续行，支持对账、重试、改选或撤销；宿主重启恢复待生效意图，无盲目重复控制或静默沿用旧配置。停止当前轮后换模再继续保留已有内容；评测 locked 请求不进入待生效状态。
- [ ] effort 选择贯通四家支持的 live/exec 路径、start/resume 与记录；不支持的组合明确拒绝，不默默采用默认；原生 DSH 使用同一语义。
- [ ] eval 选手/判官、宿主/容器和多轮恢复绑定冻结 effort；修改配置、请求覆盖与不匹配回读的反例不能成为可比较样本；缺失证据明确标记。旧条件哈希 golden fixture 不变，旧 lock/历史结果不重写，新 effort 条件单独 provision/run。
- [ ] 控件指向正确参与者；不支持 steering、换模或内容类型有明确解释；用户交互请求可回答、拒绝或取消。

### 9.2 交付 B 必过

- [ ] 聊天提出明确的大目标执行请求即可由协调者建立必要计划并推进，无需再点击启动；协调者自行选择任务粒度、成员、并行与依赖。只讨论方案/保存草稿不派发，用户暂停仍有效；空房间可发现邀请与可选目标入口。
- [ ] UI 可从目标定位阶段、任务、依赖与成果；待验收不显示已完成，返工历史与验收证据可查，完成计数不混入取消/重复尝试；轮内 Todo 不冒充房间计划。
- [ ] 自动验收与后续派发在 UI 有简洁可追溯记录，不强迫用户逐项批准；需要用户处理时原因和操作可见。暂停、仍在运行的成员及恢复状态在刷新/窄屏下均可识别。
- [ ] 一个实际目标经过计划、至少两个有依赖的执行任务、成果提交和验收，无人工复制消息完成接力。
- [ ] 拒收成果后创建返工尝试；run 正常结束不会直接通过任务验收；旧 attempt 的迟到回报不会覆盖新结果。
- [ ] 并发入口复用同一队列，通知可重试/去重；重启后先对账，无盲目重跑；等待中的协调者不会持续空转。
- [ ] 暂停/停止不会被自动唤醒绕过；预算与重试限制可观察；成员故障、协调者故障都保留明确恢复入口。
- [ ] 对同一组真实任务比较 DSH 配不同主模型与外部 harness 协调者，记录验收质量、人工介入、返工、耗时和可测成本，不预设某家能力不足。

### 9.3 版本与交付

每次验收记录宿主版本、CLI 版本、exec/live 实际模式、目录来源和能力快照。exec 仍可作为明确降级及既有评测模式，但不把 event-only 路径计为真流式验收通过。M2 不能靠手工切 token 档验收：默认与旧配置迁移均须通过，event 分支已退役；3080 在部署新版并完成真实矩阵前保持“未验证”，不能因现有 token 选项存在就标达标。

实现阶段按仓库要求 build/test、host-first 生成、兼容标注和插件独立性检查；合并前 gate。3080 只能经 deploy:3080 tarball 流程验证，push 与 npm 发布按既有协调规则执行。证据落 docs/acceptance，包级决定落 Agent Note。

仅在两次交付均完成、安装/卸载与降级通过且没有官方补丁依赖时标 done；M3 通过只标交付 A 完成。若公开接口缺口阻塞某项，记录准确缺口和 upstream 候选，不通过替换宿主实现规避。

### 风险与明确放弃

- **原生接口随版本变化。** 探测、版本化 fixture 与真实验收共同约束；`initialize` 成功或模型列表存在不等于账号端到端可用。
- **快照与最终记录不一致。** item/part 身份、权威终态、断线补齐与三处对账作为前置门禁；不能只测一条简单回答。
- **交接不是无损迁移 CLI 内部上下文。** 采用可追溯交接包与保留旧会话；第一版不在运行中热换协调者。
- **自动通知形成循环或预算失控。** 由任务/消息身份、明确唤醒条件和可执行预算约束；不让任意普通聊天触发自动递归。
- **直接替换宿主默认 AgentFactory。** 不采用：适配成本与兼容面过大，room 默认路由已能满足用户目标。
- **保留 DSH main 每轮转发外部规划。** 不采用：增加上下文偏差、延迟和双重调用，违背用户默认直接对话的目标。
- **将最终输出拆段伪装流式。** 不采用：无法实时中断或反映实际进展。
- **统一为四份字符串列表或硬编码大全。** 不采用：丢失别名/权限/推理能力与加载语义。统一丰富契约，保留各家目录事实。
- **广播全部房间记录给所有成员、第一版无限层级 agent 树。** 不采用：上下文成本和调度复杂度过高，优先按需上下文与渐进拆分。
