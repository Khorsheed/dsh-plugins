上一版"定位不到"的原因是我这边的错，不是没保存。画的框和渲染的框比例不一致：指针按一个固定尺寸换算，渲染却按面板宽度铺满，所以画在哪都往边上偏。现在两边共用同一个 600×400 的 3:2 逻辑框，指针等比换算——量过：在框的 25%/25% 处落笔，存下来是 150,100，正好是 600×400 的四分之一。

保留一直是好的：划几笔 → 保存 → 切回卡板，那张卡正面就有缩略图，卡角标的字节数也已经把画板算进去；再点开，笔画还在（这一轮我在页上跑过）。

三个图标 + 一个「全部清空」（这一轮改的）：笔 / 橡皮 / 撤销做成一组图标按钮，点亮的那个就是当前工具；鼠标形状跟着换——笔工具是斜笔尖，橡皮工具是橡皮头，所以不用回头看按钮也知道现在划下去是画还是擦。再点一次当前工具 = 回到打字。「全部清空」从组里退出来单独一个文字按钮（它是这批里唯一不可逆的，做成图标容易和撤销混）。没有笔画时点橡皮只会提示"先划一笔"，不会进那个工具。

局部擦：橡皮亮着时，鼠标移到哪一笔会先亮，点下去只擦那一条（容差按屏幕 12 像素算，框大框小都圈得准）；撤销只退最后一笔。

画完保存，编辑区也要看得见（你第 3 条问的就是这个）：之前只有右侧渲染列画了东西，左侧编辑区是个空textarea——那一栏其实什么都没丢，只是画板只在"正在画"的时候才占位。现在画板常驻编辑区顶部：不打字不画图时它是一块只读的画（铺的就是那份点列，和渲染列同一份数据），右下角一个「点一下接着画」，点它就切回笔工具。所以"只能在预览区看到"这一条不是限制，是上一版少画了一块。

量过的数（在这页上真算）：一笔 24 个采样点，存点列（x,y,粗细）= 287 B，存收尖轮廓 = 834 B（2.9 倍）。真版存点列，轮廓渲染时再算——这也正是 perfect-freehand 1.2.3（MIT，112KB）自己的数据形状。上面那行"落盘 / 轮廓"两个数就是同一张卡上现算的对照。

⑥ 选中：三个数分开报，不再让人自己算

⑦ 多标签：右栏本来就是真多标签，但画布只注册了一个 kind

能，而且不用我们自己造标签条。右侧栏是一个 dockkit：一个 pane 里放着 tabs: readonly TabId[] 加一个 activeTabId（ui-dockkit/src/contract/types.ts:71-80），标签条把所有 chip 都渲染出来（components/TabPanel.tsx:219）；openResource/openTab 默认是追加（engine/planner.ts:192-208），只有调用方显式传 replaceTab 才换掉当前那张。

卡点在这："页面"是每个 pane 唯一的。同一个 pane 里第二次 openTab('canvas') 只会聚焦那张已有的、把 params 再递一遍（ui-sidebar-right/src/client/stores.ts:315-332），duplicateTab 对 page 直接拒绝（:339-343）。而画布今天只注册了 一个 kind（packages/canvas/src/client/definition.ts:22-45），详情是那张 tab 内部的下钻，不是另一张标签。

所以"连线一张 + 详情一张"有三条路：① 详情注册成自己的 kind（canvasDetail）——两种 kind 天然并排，最省事；② 详情走 resource——按 (kind, contentId) 去重，revealIfOpened:false 能开同一张卡的第二份；③ 保持一个 kind，用 split() 开第二个 pane（停靠 pane 上限 2，浮动 pane 每个只装一张）。

你提的悬浮按钮"在新标签页打开详情"是现成动词：ctx.sidebarRight.openResource(地址, {params})，我们已经在用它开文件预览。"点的是哪张卡"走 params——它会以 navigation.params 交给 body，带一个 revision 计数，每次重开都再给一遍。

代价先说清：这套布局是按会话存在内存里的（stores.ts:41-57；docs/subsystems/sidebar-right.md:140 原文 "layout state is memory-only; a reload starts every session collapsed"）。刷一次页面，你摆好的两张标签就没了——所以它适合当"顺手开一张"，不适合当工作区配置来设计。另外对话区没有这种标签条（它的 slot 只有 conversation.session* / conversation.chat.*），你说的"本 sidebar 的多标签"正好是唯一走得通的那条。

这页现在这么摆：筛选条末尾一个虚线的「管理分类」，点开就地展开一块面板（不弹模态——378 宽的栏里摆模态，比它挡住的还挤；真版这里也一样，只有确认框用宿主那个 Modal）。面板里三件事：改名（输入框，失焦即改，卡上存的还是那个 id，一张卡都不动）、＋ 加一个（现分一个 id；代价在模型那一侧——canvas_propose_card 的 enum 要跟着这块画板的目录走，提案「风险」那节 ⑪ 那条）、停用。

"停用"而不是"删除"，是 §10.7 已经定死的一条：目录项写 enabled:false，不物理删。为什么——normalizeCard（types.ts:511）对认不出的 kind 是丢整张卡，只删定义等于下次打开板子那几张凭空消失，写回去就永久没了。所以停用一个底下还有卡的分类时弹一次确认，文案就那一句「「参考」下还有 1 张卡。停用之后这几张一起进归档，正文保留、随时能恢复」，按钮只有取消 / 确认停用。底下没卡 = 不弹，直接停用。

不引入"挑个去处"的选择器（那是 §10.7 的原判）：想把卡留在板上，就用卡板上那个勾选框批量选中 → 改分类——这一轮为了兑现这句话，批量条里补了「改分类」那颗（点它把这一行换成"把这 N 张移到 ‹分类 chips›"）。停用之后卡上的标签还在、卡照常渲染，只是不再出现在筛选条里，面板下方那节"已停用"里能一键启用回来（之前进归档的那几张不会跟着回来，得一张张还原——这条我在提示里明说了）。

量过的：改名「资料→参考」，chip 和卡角标同时跟上；停用「参考」→ 弹确认 → 确认后 1 张进归档（抽屉 2→3），chip 消失、"已停用"节里报 0 张；启用回来 chip 复位；新增「风险」→ 勾选 2 张 → 改分类 → 那两张的角标变「风险」、chip 计数 0→2。全程 console 干净。

⑫ 那句「还没落盘」删了之后，拦误删的那一道补在哪（你说"弹一次确认"）

只管从没保存过的那张。点 ＋ 开一张新卡详情，只要写过字或落过笔，再点标签上那个 × 就弹一次：「这张新卡还没保存过：正文写了 N 个字，画板上落了 N 笔。丢掉就一个字都不剩，板面上也不会多这张卡。」两个按钮——继续编辑（什么都不动，字和笔画原样还在）和丢掉（标签关掉，板上一张卡不多）。空草稿不弹：它没有可丢的东西；顶栏那个 × 走同一条路，因为它是同一个动作的第二个入口。实测四格：空草稿 × → 不弹、直接关；写了 12 个字 → 弹，报"12 个字"；点继续编辑 → 那 12 个字一个不少；重新点 × 选丢掉 → 标签没了、板上 .card 仍是 5 张。只画一笔不写字也弹，那句变「画板上落了 1 笔」。全程无异常。

说清没管的那半：一张已经保存过的卡，改了字再关标签，今天照样直接关（实测：给「碎片」那张加一句、点 ×，没弹，卡还在板上）。真版里那半也会丢编辑——但它在包里是 patchCard 的事，要不要一起拦，我不替你定。这一条等你一句"就这样"或"那张也拦"。

这一轮的体验顺序：切到连线视图 → 点一张连着线的卡（比如那张「依据」），看底栏写"要发出去 1 张，就是你点的那些"、只有它自己亮内框 → 点「顺线扩一圈 关」，同一张卡立刻变 3 张、算式那行出来 → 点「取消选择」，开关自己弹回关。回卡板 → 点筛选条末尾的「管理分类」：改个名（卡角标跟着变）、＋加一个、然后勾两张卡 →「改分类」把它们移进新分类 → 对着一个底下还有卡的分类点「停用」，看那次确认弹窗（底下没卡的不弹）。最后开一张已经有正文的卡点「试贴网页」：这次落的是纯文本那一份，不再给你一屏死标记。

要点头的四件事：① 「顺线扩一圈」这个默认关 + 它是临时取景（取消选择就弹回关）——定不定？② 分类管理就地展开面板（只有确认框用宿主 Modal），"停用而非删除、带卡一起进归档"这套照 §10.7 落地——定不定？③ 批量条补的那颗「改分类」要不要留在批量操作里（不留，⑪ 那句"想留在板上就先移空"就没有出口）；④ 粘贴在"会留下死标记"的场合退回纯文本——还是你要的是另一个做法（比如照样贴 html，但自动把整张卡转成网页）？

第五轮那两条，你回话了，已经做进这页：① 「＋ 新卡」保留——顶栏和标签条尾那颗 ＋ 是同一个动作（"先保留"那个"先"字我记在提案里，窄栏真挤了再回来判）；② 带字或带笔画的草稿点 × 弹一次确认——试试：点 ＋，写几个字或画一笔，再点标签上那个 ×，会弹"这张新卡还没保存过：正文写了 N 个字……丢掉就一个字都不剩"，两个按钮继续编辑 / 丢掉。什么都没写的空草稿不弹（它本来就没有可丢的东西），保存过的卡关标签也不弹。
