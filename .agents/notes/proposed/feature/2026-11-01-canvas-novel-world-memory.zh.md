# Agent Note: 长篇小说按世界记忆组织——设定、故事内时间轴、规划即检索

Status: proposed

## Problem

用户在一部真实作品（《潜梦者》，5 章、41 张卡）上用长篇小说画布，2026-11-01 提出：

- **设定是一堆连不起来的卡。** 41 张里 29 张是世界卡，其中 20 张是「规则」。生物（鹿蜀）被归成规则，几张「原则」卡其实是世界规则，势力（睡眠公司、断环）只存在于规则正文里。卡和卡之间互不指向，用户看不到自己设计的世界。
- **规划页少用、也不好看。** 大纲提议每卷是一整段长文；这一页占着第一个页签，可一部书只打开一次。
- **确认计划像没反应。** 它只记下 `planConfirmedAt`，用户还得在对话里再说一声 Agent 才动笔。
- **单章计划没有重点，「信息差 c2」看不懂。** `infoGaps[].who` 按模型打的原样存（如 ref `c2`），页面不解析 ref。
- **写稿材料包装不下。** `renderWriteBrief` 把所有世界卡都放进「硬约束」：世界卡约 4900 字、原则约 1200 字，预算约 2000。超了裁掉的是伏笔和前情，设定一条不裁；还没定的工作稿也被写成「违反即返工」。
- **没法自己写**，只能经 Agent 把写好的文件登记成用户原稿。

## Proposal

按记忆组织小说，借用常见的分法：

| 记忆 | 在书里 | 变化 |
|---|---|---|
| 语义记忆 | 世界观：体系 / 地点 / 势力 / 物种与道具 | 慢，用户确认才改 |
| 情景记忆 | 时间轴 · 已发生：按故事时间的事件，带起因和后果 | 每章对账 |
| 前瞻记忆 | 时间轴 · 将发生：预设、人物打算、后果、揭晓、承诺 | 每章打开、推进、释放 |
| 自传体记忆 | 每个人物的处境、当前打算、相信的事（带来源：亲历 / 听说 / 推测）、怎么看别人、瞒着别人的 | 每章对账 |
| 程序性记忆 | 写作原则 | 很少 |

人物只存自己相信的事。「误以为」「不知道」从不存：规划时拿信念对照工作集里的真相现算。卡上的「知道的事 / 不知道的事」合并为「相信的事」。

### 张力与分档

每件将发生的事有张力，参考勒温的张力系统、蔡格尼克与奥夫相基娜效应、目标梯度假设、期望 × 价值，以及 Steel 的时间动机理论：

`张力 = V × E × (1 + 0.25·Z) ÷ (1 + k·D) × 饱和折减`

- **V** 价值：Agent 建事件时给，可改；绑定灵感 +0.1。
- **E** 就绪：对账已勾掉的前置条件比例（每次打勾记章号）。
- **D** 距离：离时间窗口几章（没设窗口按 4 章算）。
- **Z** 积压：已经几章没写到。
- **S** 饱和：最近 4 章推进几次，3 次及以上乘 0.35。
- **k** 节奏：每部书一个值，先固定。

分档按顺序判断：饱和（S ≥ 3）→ 搁置（有前置没满足）→ 临近（D < 3）→ 积压（Z ≥ 3）→ 就绪。D、Z、S 的理由行读取时从流水套模板生成，不存。

### 规划即检索

1. 上一章结尾，一定带上。
2. **召回是一个工具**（`novel_read` 的一种模式）。引擎给全部将发生事件排序，返回至多 8 条一行候选：标了「优先推进」的先放；标了「本章屏蔽」的在交给 Agent 之前剔除；「临近」的全部召回；其余按张力补。除视角人物外，同一个人物至多出现在 2 条里。饱和、搁置的不进候选，只列名字。
3. Agent 选 1 条主线、1–2 条副线，计划记为「本章推进」。本章屏蔽在计划登记后清掉。
4. 第二次读取只展开选中的事件：相关人物的记忆与信念对照、原因链、沿卡片连线找到的设定、在场关系，以及绑定灵感的原文。
5. 对账按「本章推进」核对：推进了、释放了、还是计划了却没写到。

写稿材料包分三层：常驻（主线、主题、基调、原则，约 400）、本章（展开结果，约 1500）、目录（其余设定只列名字，约 300，Agent 可用 `canvas_read` 查）。

### 界面

- **页签**改为 章节 · 设定 · 时间轴 · 灵感。规划并入章节：卷作为章节列表的卷头，带分段和进度条；一页纸大纲挪到设定 · 总览。故事页签退役：每张卡关联的章节放进卡上的「出现在」，章节 × 卡的表变成时间轴的「按章节」视图。
- **设定**：总览（主线、世界层、写作原则）；世界观，含嵌套地点、卡片连线和现算的反向链接；人物；关系（可按章节拖动的关系图）。伏笔变成揭晓事件，详情是一架「读者此刻知道」的梯子，最上一级是真相。
- **时间轴**：已发生按故事时间排，时间是自由文字、顺序靠位置；写完的卷各收成一行摘要。将发生「按优先级」分组并展示公式。正文写到的将发生事件移到已发生、带章号；没做成的打算移过去标「落空」。
- **章节**：「下一章候选」带「优先推进 / 本章屏蔽」；「按计划开写」；就地编辑章节文件（含手机）；「新建一章，自己写」登记为用户原稿。已对账章节改动不到 5% 时保持已对账，标「对账后改过 N 字」。
- **灵感**：「记录灵感」只存不触发。「排进时间轴」往对话发一条消息，Agent 当轮提议，用户同意后写入。「手动绑定」按灵感里提到的名字给候选，不调模型。状态只有「待写入」「已写入第 N 章」，可删除。
- **设定改动**：对账用到这条设定的章节标「待检查」；下一轮对话里 Agent 委派子 agent 去查，冲突处标「与设定不符」并引原文。

### 不在后台静默调模型

插件从不在后台调模型。所有用到模型的步骤都发生在看得见的对话轮次里，以工具调用或委派子 agent 的形式，`context-lens` 都能看到。张力、分档、召回排序、理由行、灵感候选都是纯计算。

### 迁移

旧卡自动转换：

- 同主题的世界 · 规则卡收成一个体系的子条目。
- 地点卡补上级地点。
- 道具卡和被归错的生物归到物种与道具。
- 历史卡转成时间轴事件。
- 规则正文里提到的组织提议建成势力卡。
- 写法类原则卡归到写作原则；其实是设定的原则卡归到体系；全书命题与结局方向归到大纲。

转换在对话里一次性完成，最后给出「整理结果」供用户过目。技能和对账 schema 一起改，新卡按新分类建。

### 分批

1. **按计划开写**和信息差人物的解析。**本次已实现**：
   - 确认按钮改为「按计划开写」：确认后经会话输入框的 `submit`，以用户名义发出「第 N 章计划确认，按计划开写。」。用户正在打的草稿从不跟着发出，这时只把这句追加进草稿。
   - `resolvePlan` 把 `infoGaps[].who` 解析成卡片。
   - 章节 Remote 也把人物 ref（c2）映射成名字，修复之前存下的计划也能正确显示。
2. 世界观分类、卡片连线、迁移、三层材料包。**材料包的设定分层先做了**：
   - 计划新增「用到的设定」（`uses`），登记时解析成卡片，计划的文本编辑里也能改。
   - `gatherBrief({ for })` 全文带上：计划的 `uses`、前两章对账记下的设定（`ChapterRecord.settings`）、计划里点到名字的设定（规划材料包还扫最近两章摘要和上一章末段）。其余设定只列名字。
   - 正文写着「工作稿 / 待定 / 未决 / 暂定 / 待调整」的设定标「未定：别在正文里写死」。
   - 不带 `for` 的调用仍是旧的全量材料包。

   **架子、连线和迁移也已实现**（体裁 `novel@5`）：
   - 新分类 体系 / 地点 / 势力 / 物种与道具（角色 `system` / `place` / `faction` / `item`）在体裁里取代「世界」。引擎把四类都当设定读（EntryRole `world`，附 `RuleView.sort`），所以材料包、对账、编号都不变。「原则」改名「写作原则」。
   - 连线是 `ref` 字段，`refKind` 写分类角色：每个架子有 `parent`，势力有 `base`，人物有 `faction` / `home`。画布现在拿 ref 字段的 `refKind` 同时匹配分类 id 和分类角色（`refResolverOf`、字段选择器）。写卡时按编号或名字解析连线，解析不了的丢掉并在回复里说明。
   - `canvas_read` 的列表和卡片详情显示所在架子、属于和反向链接（下属 / 以此为据点 / 相关人物）。卡片页新增「关联」区块，数据来自 `card` Remote 的 `links`，点标签打开那张卡或那一章。
   - 整理设定是 `novel_write(what=organize)`。`phase=preview` 存下 `organize.json`：默认迁移（旧世界卡按类型归架）加上 Agent 的 moves 和新建条目，并返回整理结果。`phase=apply` 要求用户之后又发过消息（与确认计划同一种防护）。执行时先触发画布的体裁补齐，再建新条目、按原字段搬卡、设上级，最后关掉已经搬空的旧「世界」分类。
   - 第二批还没做：设定 · 总览页和地点树。设定页目前仍按画布原样列分类。
3. 时间轴、将发生事件、张力、召回工具、人物五项动态记忆。
4. 章节就地编辑与灵感页签。

定稿的交互稿在本地，位于 `proposals/` 下（gitignore）：`proposals/prototypes/canvas-novel-world-memory.html`（v3，以它为准）与 `canvas-novel-world-codex.html`（v2：设定布局、卡片连线、换一部书的样例）。

## Alternatives considered

- **给用户看一个优先级分数。** 否决：解释不了。用户看到的是按主导分量命名的档位，公式点开就有。
- **在人物上存「误以为 / 不知道」。** 否决：那是作者视角，人物只有「相信」。
- **在时间轴之外单设「未了之事」池。** 否决，改用将发生事件：用户主要讨论接下来发生什么，打算、后果、揭晓、承诺都是事件。
- **历法和故事时间换算。** 否决：顺序为主、时间只是标签，精度可以随意，两界流速不同也不用换算。
- **灵感存下后立刻让模型判断挂哪。** 否决：那会是一次后台静默调用。
- **让 Agent 从全部将发生事件里挑。** 否决：召回做成工具，几百件事件不会进模型。

## Acceptance criteria

- 在《潜梦者》上，第 6 章的写稿材料包不超预算，只带选中事件连到的设定，其余列名字。
- 设定页显示四个世界观分组，地点嵌套、有反向链接；没有世界 · 规则卡在用户不知情的情况下留着没转。
- 时间轴按故事时间排；写到的将发生事件移到已发生、带章号。
- 召回至多 8 条，从不含本章屏蔽的事件，总是含全部临近事件。
- 「按计划开写」恰好发出一条消息，从不发出打到一半的草稿。
- 对话轮次之外没有任何模型调用。

## Risks

- 对账要抽的更多（事件、信念变化、前置打勾）。原文依据仍是硬要求，但抽得浅会悄悄拉低规划质量。
- 自动迁移可能归错类，「整理结果」是兜底。
- 沿卡片连线展开可能漏掉某章需要、但没有连线到达的设定；名字目录让它仍然能被查到。
- 规划、故事两个页签退役，挪动了用户已经熟悉的位置。
