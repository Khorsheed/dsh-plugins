# Agent Note: Host 0.1.2-alpha.1 adaptation assessment

Status: proposed

## Problem

官方发布了 `dsh-v0.1.2-alpha.1`(GitHub tag `cd5ef814`,完整 changelog `dsh-v0.1.1-rc.2...dsh-v0.1.2-alpha.1`)。在它登上 npm 之前,我们需要知道:哪些插件要适配、哪些我们自建的机制官方已经原生提供、以及新的子代理模型配置与 local-agent 家族的差异。以下评估基于对该 tag 的只读审计(两路 explorer:宿主 API 面 diff + 子代理模型配置机制),并与本 monorepo 全仓 grep 交叉核对。

## Key findings

**尚未上 npm。** 所有 `@deepseek-ai/*` 包在 registry 上最新仍是 0.1.1-rc.2。我们的 peer 区间 `^0.1.0-rc.6` 本来就不匹配 prerelease `0.1.2-alpha.1`(会匹配将来的正式 0.1.2)。在那之前无法也不应走正常消费者路径验证。

**唯一的大 breaking:`@deepseek-ai/dsh-client-runtime` 被整体删除**(`be531688f3`)。本仓引用它 157 处、横跨 107 个文件(源码、测试、package.json peer)。符号迁移对照表(已对 tag 核实):

- `ClientContext` → cordis `Context`
- `createSnapshotStore`、`defineStore`、`SnapshotStore`、`shallowEqual` → `@deepseek-ai/dsh-client-store`
- `ISessions`、`SessionListState`、`SessionSummary` → `@deepseek-ai/dsh-api-session-controller/client`
- `IWorkspaces` → `@deepseek-ai/dsh-api-workspace-controller/client`
- chat 节点/契约类型(`UserMessageNode`、`ConversationNodeDefinition` 等)→ `@deepseek-ai/dsh-client-ui-chat`(slot `conversation.chat.node`/`turnTail` 键名与 owner props 不变,只是迁包,commit `c7d8e32aec`)
- `TypertRemoteNamespaceMap`、`RemoteResult` → typert-protocol(re-export 仍在,建议改直引)

**这个破坏是运行时级的,不只是编译期。** client bundle 把 `@deepseek-ai/dsh-client-runtime/client` 外部化(`build/tsdown.client.ts` 的 `RUNTIME_STORE_EXEMPTION`),运行时靠宿主冻结模块表应答 `require`。alpha.1 的种子表(`packages/client/web/src/seed.ts`)注册了 `@deepseek-ai/dsh-client-store`,但**没有 `dsh-client-runtime` 的行,也没有兼容别名**。当前有 7 个 bundle 带着这个 require——datasets、message-tools、mission、taskpilot、ui-file-preview、ui-shortcuts、worktrees——在 0.1.2 宿主上加载即抛错,**包括已经发布的 npm 第一波 tarball**。纯类型导入(`ClientContext` 等)在构建期被擦除,只是编译期迁移。双线兼容的修法:store 值导入切到 `@deepseek-ai/dsh-client-store` 并**内联**(扩 `INLINE_SAFE`),产物在两条宿主线上都不需要宿主行——前提是核实 store 实例不带宿主共享身份(我们的 store 都是自建自用,不跨插件边界)。

**较小的 breaking / 行为变化:**

- `SubagentCapabilities` 新增**必填** `agentOptions: boolean`;唯一会在类型升级后编译失败的是 `local-agent-tool-subagent/tests/scripted-provider.ts:36` 的内联字面量——生产 provider 用 `NO_START_CAPABILITIES` 常量,运行时不受影响。
- systemPrompt 官方 order 锚点重排(identity -100→-1000、工具指导 100–199→1000–2900、`TOOLS_SDK: 5000`),相等 order 改按 name 排序。靠 order 卡位的插件(mission 113、datasets 150、local-agent-dsh-headless 的 persona 覆写)相对位置会变——需目检渲染后的提示词。
- ui-input-trigger 的 `icon?: string` 收窄为联合类型;@ 菜单 DOM 变化(`role="listbox"` 移入 viewport 内层,新增 `data-trigger-menu`)。只影响 trigger source 作者;ui-file-preview 的 mention 拦截器需要重新冒烟。

**已核实兼容、无需动作:** 我们用到的全部 slot 键(含 `settings.plugin.item`——rc.2 就存在,release notes 里的"插件配置扩展位"不是新东西)、settings 注册 API、skills registry、`remote.commands.execute` 签名(含 rc.8 的 `images` 参数)、`contextPressure` projection schema、chat DOM 锚点(`data-chat-anchor-key`、`data-conversation-scroll`,另有新增 `data-chat-turn`)、Remote 挂载(浏览器插件对新的一次性 token cookie 鉴权透明)。没有任何插件碰过 ApiProxy——它的移除对我们是零事件。

**官方现在自带了我们自己建的东西:**

- `TurnNavigator` 轮次导航 rail(`d38ff54150`)——与 message-timeline 核心功能重叠。我们仍有差异(只看用户消息、阅读位置高亮、翻页);保留还是退役是产品决策,不是兼容性问题。
- token-meter 新导出 `deriveTurnTokenUsage` + turn tail 的每轮精确用量(`b565df3442`)——与 context-guard 的面相邻;taskpilot 的 token 汇总可选地改用官方推导。
- 子代理任务级模型配置——见下。

**子代理模型配置 vs local-agent 家族。** `SubagentStartRequest` 新增可选 `agentOptions: {provider, model, reasoningEffort, maxTokens}`;`tool-subagent`(仅 web preset 的 spawn 工具)暴露 `provider`/`model`/`reasoning_effort` 参数并伴随 `list_subagent_models` 工具,由用户白名单门控(`subagent-model-selection` settings namespace,默认关)。关键边界:它**只覆盖 in-process spawn/fork 和 dsh-sdk 子代理**——官方 claude-code/codex/ACP provider 显式 `agentOptions: false`(`out-of-process.ts`);这两个 provider 得到的是 deployment 级 `model?: string` 插件配置,为该实例钉死 CLI 原生模型。也就是说:外部 CLI 的任务级选模型,官方**并不**领先我们——那里是平手。官方真正领先的是自带维护中的 `dsh-subagent-claude-code`/`dsh-subagent-codex` 一次性 provider,与我们 claude-local/codex-local 的 exec 路径重叠。我们的差异化仍在:kimi-cli provider、live 常驻模式、member-channel、session-mirror、命令族、taskpilot。

## Proposal

1. **不适配 alpha。** CI harness 种子继续钉 `dsh-v0.1.1-rc.2`;prod 3080 留在 rc.2。等 0.1.2 rc 上 npm 再启动。
2. 适配时(一个集中波次):store 值导入切到 `@deepseek-ai/dsh-client-store` 并**内联**(产物双线兼容,见上);其余纯类型 `dsh-client-runtime` 导入按上表重定向并摘掉 peer;修 `scripted-provider.ts` 的 capabilities 字面量(补 `agentOptions: false`);重新冒烟 mission/datasets 提示词顺序、ui-file-preview mention 拦截、以及所有 Remote 消费者在新 token 鉴权传输下的表现;逐包刷新 `dsh.compat` 与 README Compatibility 段。由于内联让产物在 rc.2 宿主上也能跑,这一波可以在 0.1.2 上 npm 之前就在 worktree 里对着 alpha 种子开工——但合并与发布等 rc 落地。
3. 波次前要做的产品决策:message-timeline 与官方 TurnNavigator(差异化还是退役);三个 CLI provider 是否加实例级 `model` 配置(与官方对齐)以及/或者声明 `agentOptions: true` 并把 `request.agentOptions.model` 透传为 CLI 模型旗标(增强;语义由我们自己的委派工具定义)。
4. 跟踪官方 `subagent-claude-code`/`subagent-codex` 成熟度;长期家族可让出一次性 exec 路径,聚焦 live/member-channel/mirror。

## Alternatives considered

- **现在就对着源码 tag 适配**——否决:npm 上没有可安装产物,prerelease API 还可能变,client-runtime 迁移面大到值得等一个稳定目标。
- **立即退役 message-timeline**——否决:官方 rail 在内容(全部轮次 vs 仅用户消息)与行为上均有差异;重叠问题值得拿着截图做一次从容的产品决策,而不是恐慌删除。
- **抢跑给 CLI provider 加 `agentOptions: true`**——否决:官方自己就把外部 CLI 排除在任务级模型路由之外,没有需要抢的平手差;增强可以搭正常适配波次的便车。

## Acceptance criteria

- 本 note 存在,且评估可按所引 commit 复现。
- 适配波次 PR 在 0.1.2(rc 或正式)harness 种子上 build/test 全绿,各包 `dsh.compat.verifiedHost` 随之提升。

**第二轮(同一实例,值导入波次之后):又三个运行时断裂,同一形态——alpha 线删掉的成员,在 apply 或渲染期被无防护读取。** 类型对着 npm rc.2 仍可编译、测试 double 仍带旧成员,所以只有活体宿主看得见。修法全部是特性探测(绝不做版本判断),且每处都配了覆盖两个席位的 spec。

1. **`ISessions.currentProvideInfo` 被删**(随 runtime 包,`be531688f3`)。message-timeline 的 rail tracker 和 message-tools 的 dom-hider 在 apply 期订阅它——`undefined.subscribe` 在 loader entry 里抛(`failed to apply loader entry … reading 'subscribe'`)。现已改为探测式订阅;tracker 另加了 scrollport 绑定自愈(经既有 MutationObserver/resize 节奏重新解析 DOM),在两条线上都补齐了这个 feed 原本承载的重挂载信号。
2. **事件 Definition 注册表换席位**:rc 线是独立的 `conversationEvents` 服务,alpha 折进了 `uiConversation.events`。message-tools 的静态 `inject: […, 'conversationEvents', …]` 在 alpha 上让 fiber 永远 pending(`waiting for service: conversationEvents`,触发 boot 门禁)。它已移出静态 inject;两个席位各挂一条 `ctx.inject` 探测臂——两个名字互不存在于对方线上,恰好只有一臂触发。
3. **`Connection.hostDescription` 折进 `connection.generation`**(`e14d354e83`,快照 `?.host`)。datasets、ui-file-preview(×2)、worktrees(×2)把 undefined 成员放进 slot inject 的 `hooks`,渲染器在 `observableHook` → `WeakMap.set` 处崩("Invalid value used as weak map key")。各包现在在旧成员缺席时从 generation 派生同形 source;派生快照没有 `canOpenPath`(该能力变成 `remote.session.canOpenWorkspacePath` RPC 探测),0.1.2 上外部打开按钮隐藏——刻意降级,恢复列为跟进项。手势期助手也搬了家:`workspaces.openPath` → `remote.session.openWorkspacePath`,`workspaces.pickDirectory` → `uiWorkspace.pickDirectory`;所有调用点先探旧席位再探新席位,都没有则静默降级。

换装后(原地重打 tarball + profile 重装 + 重启),实例**零 console 错误**启动,含全部分支插件的组合 bundle 返回 200,14 个 `@khorsheed/*` 条目全部在启动图里。一条加载器层面的记录:各包的 `dsh.client.inject` 仍列着 `@deepseek-ai/dsh-client-runtime`;alpha 的 `arriveGraphRow` 对未知行静默跳过(`packages/client/modules/src/client/system.ts:165-168`),属于被容忍的死重——rc 波次摘 peer 时一并清掉。

**第三轮(同一实例,渲染期载荷):chat 快照拆分。** 条目级注册契约(key/id/order/priority/select/inject/store,`ui-slots/src/index.ts:843-858`)没有变;变的是 **chat 数据住在哪里**。rc 线它在会话快照里(`useSession(...).chat`、`Session.getSnapshot().chat`);alpha 把它拆给 ui-chat 自己的快照——组件读新增的 `useChat` 会话标准 prop(`ui-chat/src/client/contract/slots.ts:152-157`,快照 `{order, nodes, timeline, legacy}` 见 `contract/snapshot.ts:61-68`),apply 世界读 `ctx.uiConversation.binding(sid).target('chat')`(`ui-conversation/src/client/conversation/assembly.ts:185-202`),`runningCalls` 挪到 `chat.legacy.runningCalls`。三个活体崩溃同根:message-timeline 的时间轴(header.utilities 里 `reading 'order'`)、message-tools 的影子用户渲染器与撤回分隔条(chat.node 里 `reading 'nodes'`,外加 dom-hider 的会话订阅报两条 `[client-store] subscriber failed`)、message-tools 的 settle 探测(编辑/撤回的 waitIdle 里 `snapshot.chat.timeline`)。第四个是 composer 链 owner:`interactions: []` 变成单数 `pendingInteraction`(`ui-conversation/src/client/contract/slots.ts:301-308`),local-agent 的 `selectCliMember` 每次选举都在 `.length` 上崩。修法是按席位探测的助手(每包一个 `chat-hook.ts`:有 `useChat` prop / `uiConversation.binding().target('chat')` 就走新席位,否则走 rc 会话快照切片)——绝不判版本;每处配了 alpha 席位 spec。其余槽位全量核对无漂移:view(`ConvViewOwnerProps`)、overlay(标记 owner)、settings.plugin.item(按 namespace keyed)、input 各区(`InputZone`)、turnTail 链 owner(`{turn, seq, openFile}`)均未变,事件 Definition 状态机契约两线逐字段等价。

换装后活体验证:导航、发消息、设置对话框全程 console 零错误;我们的时间轴(左缘、用户消息刻度)随发消息从 1 行长到 2 行;用户消息气泡带复制/编辑/撤回按钮;设置页列出全部插件卡片(local-agent ×4、context-guard、ui-shortcuts)。**官方 TurnNavigator 在加载轮次 ≥2 时出现**(`items.length < 2 → null`,`ui-chat/src/client/chat/TurnNavigator.tsx:60`;由 `ChatView.tsx:575` 无条件挂载,数据来自 `useChat(s => s.navigation.items())`——无设置开关),并与我们的并排渲染(右缘轮次刻度 + 悬停预览 vs 我们左缘的用户消息轴)。(该页截图反复超时——合成器始终不空闲——故取证用可访问性快照 + DOM 几何探测,无图片。)

## Risks

- alpha → rc 之间 API 可能继续动(chat 分包当时仍在收敛);导入对照表可能需要第二遍。
- message-timeline 与 TurnNavigator 的重叠悬而未决:两者齐发会困扰用户;退役 ours 则丢掉其独有特性。
- 0.1.2 的 client-runtime 迁移几乎触及每个包——安排时避开大型在途 worktree(room、composition-rollback),或显式排定合并顺序。
