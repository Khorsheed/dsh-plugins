# Agent Note: room 协调者通过参与者合同统一各 harness

Status: proposed

[English](2026-09-15-room-coordinator-runtime.md) | 中文

## Problem

Room 将无显式寻址的消息发给原生 DSH agent，外部成员却具有不同的模型、控制和记录表面。已有流式镜像不等于房间流式，成员最终回复不等于任务验收通过。在这些差异解决前将外部成员设为默认协调者，会把问题带入每次普通对话。

## Proposal

[能力提案](../../../../proposals/active/2026-09-15-room-coordinator-runtime.md) 是范围与验收账本，等待用户评审。协调者作为稳定参与者身份上的角色；原生 DSH 经公开宿主接口适配，外部 harness 经现有 local-agent 门面适配。扩展公共模型、控制、内容与回放合同；各 provider 保留自己的目录发现与传输，room 持有路由和任务策略。保留可选包边界与现有会话提升入口。

先交付可靠模型选择、原生生成增量与默认直达路由，再实现任务依赖、持久回报、验收和目标续行。Claude 2.1.272 的隔离 initialize/set_model 探针支持优先验证原生控制、替代共享配置文件临时写入，但未证明真实账号推理或穷尽模型可用性。已有 208 个通过的测试主要覆盖模拟数据。

评审补充三项明确交付门禁。退役 live event 镜像档，归一旧配置、排空旧进程并验证 partial 输出参数；将有最大等待时间的实时 flush 与耐久快照节流分离，满足 P95 200ms 目标。模型/effort 选择贯通执行与记录，覆盖 eval 冻结条件，同时保留历史哈希、锁与结果。经用户评审，模型/effort 允许在运行中选择，下一轮边界生效。core 持久持有已应用与待生效配置，room 和成员 composer 共用状态；当前轮（含工具链）保持原配置。

采用一个可覆盖的待生效配置槽，不按 FIFO 执行中间选择。最后接受的有效 revision 生效，撤销绑定 revision；下一轮准入前先应用，包含先前排队的普通消息。控制与准入串行化，应用中变更和重启先对账；失败或回执不明时阻塞后续轮次直至解决。空闲改选不触发生成；需要立即切换时采用停止、应用、继续路径。评测锁定配置在接受待生效状态前拒绝修改。

新房间从原生 DSH 开始。现有邀请动作无需 @ 目标；邀请只增加成员，不改变协调者。已就绪成员经显式设置和交接后承接角色，双方须空闲且输入/控制状态已收敛；重开已配置房间恢复原协调者。原生 DSH 交接后仍可寻址。协调者是稳定成员角色，换模型不需重新设置角色；新房间自动采用外部协调者的模板不在第一版范围。

扩展现有成员卡、目标/任务胶囊和聊天事件。交付 A 增加邀请/设为协调者及可见的默认接收者控件；交付 B 增加里程碑分组、任务依赖、提交与验收区分、证据/返工历史、简洁进展事件及目标启动/暂停/继续控制。保存目标仍是草稿，显式启动才执行。轮内 Todo 与房间任务分开，归属当前协调者；已验收任务计数描述当前计划，不代表可靠的目标工作量百分比。常规自动验收不要求用户逐项点击批准。

## Alternatives considered

**替换宿主 AgentFactory。** 默认房间路由不需要它，且兼容负担超出本次需求。

**保留原生 DSH 作为模型转发者。** 增加第二层推理和上下文边界，无法让用户直接与选定协调者对话。

**集中四家目录抓取代码或把模型压成字符串。** 丢失原生别名、能力、环境相关可用性和加载状态。共享合同与缓存/订阅机制，保留 provider 实现。

**从最终文本模拟流式。** 无法展示真实运行中的进展，也无法诚实处理中断。

**保留可选 event 档或只在 room 排队换模。** 会让默认路径不符合流式合同，或使不同入口控制冲突。退役 live 档位分支，保留 exec 与终态校准；core 统一持有各入口的待生效控制。

**忙时拒绝模型/effort 选择。** 此前的第一版建议经用户评审已被替代：它不必要地限制了选择下一轮配置。立即接受意图，同时保留当前轮配置。

## Acceptance criteria

实现前由用户评审。交付 A 要求四种协调者都支持直接对话、真实控制状态与经验证的流式/回放；交付 B 另需依赖任务、独立验收、持久回报和受限续行。详细矩阵与证据边界见提案；本次文档提交不表示这些能力已交付。

交付 A 另覆盖默认/旧配置流式路径及稀疏末段时延；已应用/待生效控件同步、覆盖/撤销、过期 revision、准入竞态与恢复；start/resume 的 effort 绑定；以及 eval 覆盖/不匹配反例。历史条件 digest 保持不变；缺失运行证据保持未验证，不回填为匹配。eval 兼容是 M1 门禁，不能等旋钮开放后再补。

冷启动验收覆盖 DSH 接待、邀请不自动晋升、候选准备失败及保存的外部协调者恢复。目标 UI 验收覆盖草稿与活动区分、依赖与证据可定位、真实验收计数、阻塞可见，以及刷新和窄屏下的暂停/恢复。M3–M5 与对应服务合同一起交付这些 UI 改动。

## Risks

原生协议与模型菜单随版本和账号变化。共享运行状态假设可能污染模型选择；重复/迟到事件可能污染内容或任务。设计要求能力探测、稳定事件身份、作用域授权、明确交接和真实输出比对。公开宿主能力缺口走 upstream-change，不能本地修改宿主。
