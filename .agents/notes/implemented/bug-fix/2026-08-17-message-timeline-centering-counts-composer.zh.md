# Agent Note: message-timeline 居中盒计入输入框带

Status: implemented

English | [中文](2026-08-17-message-timeline-centering-counts-composer.zh.md)

## Problem

悬浮时间轴面板的垂直居中盒止于 sticky 输入框座顶部:`measureGeometry` 把实测的 `[data-composer-seat]` 高度从面板盒里扣掉。聊天会话流是底部锚定的——最新消息渲染在输入框正上方——而短列表却悬浮在窗口中部。在线上实例实测(1440×900、输入框 126px、3 条用户行):行位于 398–487px,蓝色阅读位置刻度(最新消息)在 ~457px,比会话流底部那条实际最新消息高出约 270px。时间轴读起来像悬在对话上方。另一处重复扣减(tab 条物理上在滚动区上方,扣它只会把盒子下移)经分析后保留不动——其影响很小(~17px),不是用户感知到的缺陷。

## Decision

面板盒不再扣减输入框座:居中盒现在横跨标题下方的整列——聊天区加上输入框带——短列表在"聊天+输入框"上居中,而不是悬浮在对话上方(`rail-tracker.ts` 的 `measureGeometry`)。盒子静止时保持透明且指针穿透(`.panel` 无背景、`pointer-events: none`),因此覆盖输入框带在行亮起前不产生任何视觉变化;短列表的行本来也落在聊天区内(实测窗口下 3 行从 398–487 移到 ~456–546)。长溢出列表把多出来的带当作可滚动空间;盒子底部不超过列底减 8px 留白。对输入框座的 ResizeObserver 观察保留——输入框尺寸变化会重发相同几何,被 `same()` 门跳过。

## Verification

`measureGeometry` 测试已更新:滚动区内的输入框座不再缩短盒子(fixture 上高度 284 而非 244,`tests/rail-tracker.client.spec.ts`)。包的 81 个测试全绿;`pnpm build` 通过。

## Alternatives considered

**底部锚定列表**(最新刻度贴着输入框顶、与最新消息对齐)。这是"刻度悬浮在消息上方"最忠实的修法,但把短列表从居中改成贴底——用户没有选择这个更大的设计变更。

**去掉 tab 条重复扣减**(tab 条渲染在滚动区上方,扣它会把盒子下移 ~17px)。方向上是让列表更高——与"感觉偏上"的反馈相反。

**覆盖区保持聊天区、只偏置居中点。** flex 自动外边距无法在不引入占位元素的情况下按更高的虚拟盒居中,而占位元素会被算作内容、把行推向错误方向;透明覆盖区让扩展盒子没有代价。

## Consequences

短列表整体下沉、更贴近对话,代价是面板盒覆盖输入框带(静止时不可见;只有长列表的底部行在悬停时会画在输入卡左内边距上方)。居中盒不再随输入框增高(如更高的输入框)而缩小,列表的垂直位置在不同输入框尺寸下保持稳定。
