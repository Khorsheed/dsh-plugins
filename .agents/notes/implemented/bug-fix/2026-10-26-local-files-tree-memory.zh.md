# Agent Note: local-files 文件树在切换页签和页面后保持原样

Status: implemented

## Problem

把右侧栏切到别的页签，或者把应用切到别的页面，再回来时，「文件列表」的树全部收起，滚动也回到了顶部。选中的文件还在，因为它存在宿主保留的槽位 store 里；但树的展开状态、已经载入的子项和滚动位置都是组件自己的状态，而只要别的内容占了位置，宿主就会卸载这个页签的内容。在真实实例上实测：三个展开的文件夹和 66px 的滚动位置，无论哪种切换之后都变成全部收起、回到顶部。

## Decision

`FileTree` 新增可选的 `memoryKey`。模块级的映射表按这个键保存三样东西：展开集合、懒加载得到的子项（按目录路径索引）和滚动位置。重新挂载时，第一帧就画出记住的树。滚动位置在绘制前恢复到最近的纵向滚动祖先上，因为树是在分栏布局的那一列里滚动，自己并不滚动。之后在后台重新列一遍展开的文件夹，页签离开期间的改动照样会显示。`WorkspaceView` 把（会话 id，当前根目录）同时作为 `key` 和 `memoryKey` 传入：换了根目录或会话，就重新挂载到各自的记忆上，记住的相对路径不会串到别的根目录。

## Alternatives considered

**把视图状态放进槽位 store**：store 能挺过卸载，但展开集合和子项缓存只属于视图，而且每次点击都会变。放进 store，会让这个 store 的所有订阅方（其中还有驱动预览的字段）都跟着每次点击刷新；另外还得自己写根目录和会话切换时的重置规则，而按键重新挂载天然就有。模块级映射和内容面板的滚动记忆用的是同一套做法，是「比组件活得久、不比页面活得久」的既有模式。

**存进 localStorage**：重新载入页面后也能保留，但重新载入本来就该是全新的开始。跨重新载入时记住的子项会过期，而且每个浏览过的目录都要存一份按路径的展开记录，存储会无限增长。

## Consequences

- 回到这个页签时和离开时一模一样，后台重新列出子项保证内容是新的。
- 记忆只在页面生命周期内有效，重新载入页面后依旧是全部收起，和以前一样。
- 搜索模式有自己的初始展开逻辑，不在记忆范围内。
- worktrees 面板的三种模式都有同样的丢失（实测：两棵树都收起并回到顶部，提交列表也回到顶部）。现在它按同一个决定处理，代码在 `packages/worktrees/src/client/scroll-memory.ts`：`expansionMemory` 和 `useScrollMemory`，按（会话，工作树，模式）分组，每种模式、每个工作树各记各的。它的树不懒加载，所以没有子项需要记住或重新列出。提交列表滚动的是它自己的 `.rows` 元素而不是外层列，所以这个 hook 先看元素本身是否滚动，不滚动再找最近的滚动祖先。`forgetViewMemory()` 用于在测试用例之间清空记忆：记忆比组件活得久正是设计目的，不清空就会在测试之间串。
