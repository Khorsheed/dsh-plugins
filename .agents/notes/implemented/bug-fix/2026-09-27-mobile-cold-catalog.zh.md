# Agent Note: 移动端冷会话列表读取

Status: implemented

## 问题

移动端直接展示会话列表的 displayTitle。0.1.7 宿主可能返回不含标题投影的冷会话条目，此时目录名只是展示兜底，并非已保存的会话标题。打开会话会补齐投影，因此选中项可能正确，未打开项却显示目录名。另外移动端通过 Room getState 查询成员数；其冷会话路径会检查持久化事件，可见行同时查询会与聊天历史加载争用资源。

## 决策

可见的非空会话缺少标题时，显式调用官方 sessions.refreshProjections。标题、去重和连接代际缓存仍由官方 store 管理；移动端不会仅为取标题而打开或 retain 会话。旧宿主缺少该接口时降级。读取失败保留官方兜底，再次进入可见区可重试。

列表级调度器将补充读取限制为两个在途请求，排队中的标题优先于可选的 Room 成员读取。交叉观察器以列表滚动容器为根；条目离开可见区、分组折叠、列表隐藏或卸载时取消排队任务。现有属主接口不接受取消信号，已经开始的请求继续完成并占用并发名额。Room 状态与修改仍归原属主管理。

## 考虑过的替代方案

逐个打开会话会加载历史并制造额外持有关系。独立标题缓存会在重命名或重连后产生分歧。不限制每行投影读取的并发，只会用额外冷日志压力替代标题缺失。已有公开的显式读取接口，不需要修改宿主源码。

## 后果

回归测试覆盖目录兜底通过补读变为已保存标题且不打开会话、隐藏列表不读取、可见读取并发上限、取消、失败恢复及标题优先级。包构建与测试针对已安装的 0.1.7 基线验证。这些测试不测量真实 iPhone 或隧道延迟，总加载时间仍包含网络、资源包和宿主历史读取。本次代码修改不包含生产重启。
