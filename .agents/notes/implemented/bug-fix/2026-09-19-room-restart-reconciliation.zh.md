# Agent Note: 让中断的 Room 执行可以从界面恢复

Status: implemented

## Problem

隔离协调者实例实际崩溃重启后，目标正确暂停、当前尝试投影为结果未知，但聊天记录仍显示两位旧成员正在运行。读取 Room 按设计不恢复 agent，因此持久化的运行中记录可能一直显示。同期中断的协调者对话虽然有宿主对账接口，却没有 Room 界面入口；只读队列只能说明阻塞，不能解除它。

## Decision

派发引擎把没有匹配进程内预留的持久化运行中投递投影为结果未知，把对应运行卡片投影为失败并明确说明结果未知。投影是只读的：查看既不追加恢复事件，也不启动工作。实际存在的运行预留仍显示运行中。没有证据的耗时显示未知，不从虚构的零值格式化。节点渲染器按成员和开始边界匹配，避免其他轮次覆盖历史卡片。

Room 为普通投递提供中断面板，包括协调者收到的报告。面板链接到同一成员会话，要求人类填写核对结论，再通过现有对账接口确认完成或放弃本次执行。文案说明对账后排队中的普通对话可以继续，而已暂停的目标仍保持暂停。正式任务的投递投影携带计划关联，只能走目标对账流程；宿主拒绝用普通对账绕过这一流程。记录结果时同步终结对应运行卡片，用人类结论替换过期的结果未知提示，并在最后一个未知尝试对账后更新目标恢复提示。目标仍需显式恢复。关闭目标会取消未启动的投递和暂存报告，恢复时发现的旧关闭目标同样处理。当前运行轮次可以正常结束并保留证据，但不能再为已关闭目标创建自动报告。关闭目标隐藏重试和验收操作，仍为结果未知的执行保留对账入口。

## Alternatives considered

**每次读取状态都恢复 agent。** 不采用，打开历史不应启动生成或重复执行结果未知的操作。

**要求用户通过原始 RPC 修复普通投递。** 不采用，常规界面必须能解除重启后的阻塞。

**把所有中断工作视为已取消。** 不采用，外部动作可能已经完成，必须由人类查看证据后决定结果。

## Consequences

结果未知的工作继续阻塞且可见，不再显示误导的运行计时。请求失败后面板保留核对结论。回归覆盖只读投影、现有并发派发测试中的真实运行保留、会话导航、必填结论、失败重试，以及普通对账排除正式任务。真实崩溃恢复仍纳入隔离 tarball 验收矩阵。
