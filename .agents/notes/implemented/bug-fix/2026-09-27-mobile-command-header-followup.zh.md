# Agent Note: 移动端指令与标题兼容

Status: implemented

## 问题

移动工具面板第一层避免了键盘聚焦，但选择「指令」仍会聚焦宿主编辑器。宿主指令菜单背景透明。新版模式图标和目录按钮结构绕过了移动适配；工具入口存在时还会误隐藏邀请成员按钮，即使没有替代的成员快捷入口。

## 决策

通过公开的 inputTriggers 会话控制器打开官方 command 来源，并传入捕获的插入位置及草稿版本。保留宿主的目录发现、指令选择和权限行为，不主动聚焦编辑器。缺少可选控制器时回退现有宿主按钮。移动端指令菜单使用主题实色背景及更大的触控行。

同时识别两种已核对的模式图标结构，将原有本地化名称移到移动副标题。通过宿主 data 属性隐藏打开目录的控件，并保留旧版图标识别。只有启用的移动成员快捷入口存在时才隐藏宿主邀请按钮。按用户要求，右侧边栏可见性保持不变。

工作区选择面板将标题和添加操作保留在有界滚动列表外。目录行不再溢出到页脚分隔线；添加操作与目录行保持相同行高和内边距，分隔线上下各保留八像素间距。

## 考虑过的方案

**点击宿主加号按钮**会重新聚焦编辑器。重建指令目录会产生行为分叉，公开控制器可保留原有行为。旧宿主没有控制器时，保留原按钮优于无响应的指令入口。

**只要工具入口存在就隐藏邀请按钮**会让没有成员快捷入口的普通会话丢失邀请入口。必须确认有可用的替代入口。

## 影响

仅调整移动展示，已禁用的插件仍保持禁用。标题图标识别仍依赖版本，同时兼容两种已验证结构。测试覆盖携带草稿版本的公开指令调用、两层工具流程不聚焦编辑器、邀请入口替代、模式提取及目录控件清理。iOS 键盘仍需真机验收，DOM 测试无法证明真机表现。
