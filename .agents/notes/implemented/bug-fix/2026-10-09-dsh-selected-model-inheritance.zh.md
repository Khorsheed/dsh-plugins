# Agent Note: 本地 DSH 继承所选模型路线

Status: implemented

## 问题

本地 DSH 的模型目录和默认选择来自父实例，但独立 headless profile 只收到 DeepSeek 凭据。因此选择父实例的 Kimi 路线时出现 `NO_ADAPTER`。live 镜像又将原生错误替换成 `UNKNOWN`，隐藏了原因。

## 决策

本地 exec 与常驻启动通过公开 settings 服务快照所选模型的有效配置。支持原生 DeepSeek，以及明确配置 API-key 引用的官方 pi-ai 路线。只复制选中的路线，只解析它声明的凭据。生成的 profile 仅包含环境表达式；实际配置和凭据通过显式启动环境传递，不进入 argv 或 profile 文件。保留原生 DeepSeek 的凭据覆盖配置。

私有内存指纹覆盖配置及解析出的凭据。任何一项变化，下一轮都会重建常驻进程并续接原会话；当前轮继续使用已有配置。认证状态检查所选路线，因此 Kimi 无需无关的 DeepSeek key。目录隐藏没有继承合同的适配器，并标记结果不完整。原生 live 失败保留原始错误码和消息。

容器执行和远程目标沿用各自的配置及凭据路径。官方子智能体工具的模型选择白名单属于另一项策略，不控制社区 `subagent_dsh` 工具。

## 考虑过的替代方案

**复制整个父 profile 或凭据库。** 不采用：这会把无关秘密、UI 服务和持久配置传入另一个目录。OAuth grant 的刷新所有权也不能作为静态 key 随意复制。

**只显示 DeepSeek。** 不采用：补齐所选配置后，原生适配器可以使用父实例的 API-key 路线。隐藏这些路线会移除用户希望使用的模型选择。

**新建模型代理。** 本次修复不采用：原生 API-key 适配器无需新增传输层、流式实现和认证边界。OAuth-only 路线及其他适配器仍需明确的继承机制，目前不支持。

## 影响

子进程保持独立会话及 profile 存储，同时使用父实例所选本地模型路线。配置和 key 变化无需重启父实例，下一轮即可生效。这不保证 key 有额度或网络可达，也不宣称支持全部宿主适配器。子进程会收到所选凭据，和此前传递 DeepSeek key 一样；不提供同一操作系统用户之间的进程隔离。

测试覆盖仅解析所选凭据、缺失与不支持路线、不依赖 DeepSeek key 的认证、原生错误保留、profile 环境表达式，以及重建常驻进程后续接同一会话。真实 Kimi 执行和续聊在部署前另行验收。
