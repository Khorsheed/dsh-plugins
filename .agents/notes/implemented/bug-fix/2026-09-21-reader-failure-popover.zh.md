# Agent Note：失败原因改为浮层——卡片保持一行高

Status: implemented

## Problem

3080 验收带截图报回：[失败分类 UI](../feature/2026-09-21-reader-failure-actions.md) 把抓取失败的原因作为一条可见红字放在卡片药丸下面一行——于是失败的卡片比邻居都高，墙的网格破了。卡片文字盒定高的规矩本来就是为了「卡片的内容永远不改变卡片的高度」（整墙翻译那轮立的）；原因行从没人量过的那一侧违反了它。

## Decision

药丸在任何状态下都保持一行高；原因与该原因对应的动作搬进锚在药丸上的浮层（卡片菜单的 fixed 定位惯例，由同一个全局外部点击效果加 Escape 关闭，按药丸的包围盒定位）。

- **每个失败药丸都开浮层**，包括终局的（http/empty/redirected）：浮层本来就是读原因的入口，而终局失败有内容、没动作——只有原因。红色图标/颜色与悬停 tooltip（title 属性）保留，是不点的兜底。
- **动作是分类学原有的，不变**：`unreachable`/未分类给重试（「重新抓取」），墙类给在浏览器打开（「在浏览器打开原文」，探测到应用内 Sidebar Browser 就开应用内，否则外部）——只是深了一层，住在浮层里。点药丸的语义变了：是揭示，不是执行。
- tooltip 文案跟着改：现在说「点一下看详情（可重试）」，不再直接许诺动作本身。
- 失败落定后浮层自己消失：它只在条目状态为 `failed` 时渲染，重试成功后它不是过期残留，而是直接不在。

## Alternatives considered

**原因行截断成一行带省略号。** 那就是昨天上线、今天破网格的东西——`flex-basis: 100%` 的一行怎么截都是一行。网格等高这条规矩不让步，所以内容离开卡片。
**点一下就地展开卡片。** 手风琴式卡片在读者手指底下改网格——同一个抱怨多绕一步。
**只留 tooltip。** 原因昨天正是从 tooltip 里搬出来的，因为只在悬停可见的文字读起来就是「无缘无故失败」；浮层让它在触屏和鼠标上都离读者一次点按，还装得下分类学指派的动作按钮。

## Consequences

- 失败卡片与健康卡片网格等高；失败仍是卡片上最显眼的东西（红药丸），原因与出路离一次点按。
- 失败药丸的点按语义从「一碰就执行」改成「先揭示」：重试是浮层里刻意的第二击，这也更贴「不做记仇爬虫」策略的精神。非失败状态（未抓/抓取中/待解析）照旧点了就抓。
- 没有新 locale 键：浮层组合既有的原因/重试/打开句子；两条 tooltip 文案改写（zh+en）。
