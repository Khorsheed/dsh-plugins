# Agent Note: a Kimi round's answer stays its last step

Status: implemented

## Problem

2026-10-26 改成按写入顺序编号（59c2cbb24）之后，Kimi 成员的聊天里只显示「已完成，用时 2 分 2 秒」，最终回复被折叠进了过程。原因是这一轮的日志在回复之后还写了几步：

- **重复的孤立工具。** 从 kimi 的第二轮开始，ACP 上报的调用 id 是 `1:tool_x`，wire 里记录的是 `tool_x`。折叠按 wire 的 id 释放预留，所以 ACP 的预留永远对不上。收尾时，这些调用都会被重新写成「被中断」的孤立工具，而现在它们排在回复之后。fbc8ba18 有 10 个，2e9c1ffb 有 15 个。改成按写入顺序编号之前，它们占用的是更早的预留编号，所以看不出来；但那些编号正是导致日志损坏的乱序步骤。
- **计划。** ACP 的计划更新原来是一个思考样式的流，在收尾时才定稿，所以待办清单变成了排在回复之后的一个推理步骤。

聊天界面把一轮的最后一步当作最终回复。

## Decision

- ACP 的 `toolCallId` 在比对前先去掉前缀（`^\d+:`）。这样 kimi 已经记录的调用只预留一次，由它的折叠释放，不会再被补写成孤立工具。
- 计划更新改写为宿主的 `todo/write` 整份快照，只在内容变化时写入。这和 Claude 的 TodoWrite 形式一致：只是记在日志里的界面状态，不会成为对话步骤。`todo/write` 这个类型由宿主的 todo 包声明，而本包没有依赖它，所以写入时做了类型转换，条目类型在本地定义。
- 两份受影响的日志已离线修复：删掉重复的孤立工具步骤和只有计划的推理步骤，按位置重新编号步骤，校验通过后再替换。

## Alternatives considered

- **在 wire 一侧去掉前缀。** 折叠、日志和工具结果用的都是 wire 里不带前缀的 id；只有 ACP 通知带前缀。
- **把计划保留为一步，写在回复之前。** 计划在整轮中不断更新，要到收尾时才完整，提前写就是过时的；而收尾时再写，又会排在最后。

## Consequences

- 新的轮次以回复结尾，聊天界面能重新显示回复。
- 修复后的日志不再保留那些被折叠成推理步骤的计划快照。计划只是进度展示，不是模型输出。

## Testing

`local-agent-kimi`（291）。live-driver 用例让 ACP 上报 `1:tool_x`、wire 记录 `tool_x`，断言只写入一次调用，并且回复在最后；旧代码会写出 `['tool_x', '1:tool_x']`。计划相关的用例断言写出了 `todo/write` 快照、没有计划推理步骤、回复在最后。
