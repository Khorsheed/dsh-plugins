# Agent Note：成员的实时预览在它自己的步骤开启时撤下

Status: implemented

## 问题

成员运行中的实时卡片里，同一条消息出现了两次：上面是一份停在半句的旧副本，下面是还在更新的副本。Codex 和 Claude Code 的实时驱动遇到某条消息暂时还不能在日志里开启自己的步骤（前面还有步骤没关闭）时，会先把它作为只在浏览器里显示的预览推送，键为 `<turn>:<临时 step>:<itemId>`。步骤开启后，这条消息改用正式键 `<turn>:<step>` 继续推送。预览却要等消息结束（`finish(stream.step)`）才清掉，所以在这条消息剩下的时间里，两个条目同时留在实时存储中。房间的实时卡片把所有条目都画出来，于是出现了重复。

## 决定

新增 `LiveStreamPublisher.dropPreview(step, itemId)`，把预览条目从实时注册表里撤掉。两个驱动都在 `openStreamStep` 里调用它，也就是消息改用正式键的那一刻。调用用了可选链，所以驱动配上旧版 core 时行为不变。Kimi 只做预览、从不切换到正式键，不受影响。

## 考虑过的其他方案

- **让 `update` 顺手撤掉同一条目的预览。** 预览没有记录它将来会用哪个正式 step，`update` 也拿不到条目 id，得额外做一次查找；而驱动手里本来就有这些信息。

## 影响

消息流式输出期间不再出现双份文字，最终的显示不变。

## 测试

`local-agent`：新增一个实时流测试：先预览一个条目，撤掉预览，再用正式 step 更新，预期订阅方的初始快照里只有正式条目。codex 和 claude-code 的测试套件保持全绿。
