# Agent Note：canvas-novel 对账修复——正文改了就重新对账、导入失败不锁章、用户原稿不带计划

Status: implemented

## Problem

一次生产会话导入了用户自己写的五章（用户原稿），结果在好几处出错：

- skill 里写着「用户跳过规划直接喊写：先登记一份默认 plan」。模型把这条也用在了用户原稿上，第 2–5 章因此多出了没人要的计划。
- subagent 调用因为一个参数错误失败了，模型就自己手写了对账 JSON。它的引用要么用省略号把两段拼在一起，要么超过 50 字，结果几乎全被证据闸丢掉。
- 这次空导入照样把章节标成了「已抽取」。每章只能对一次账，所以没有回头路。模型随后还告诉用户对账成功了。
- 和已有卡同名的世界设定被当成「重复」丢掉，章节里没有留下任何记录。名叫「透镜（已登记c6，无新角色需要登记）」的新角色变成了第二张卡。
- 模型还在用户文件夹里留下了临时 JSON，并往正文里加了标题行。

## Decision

- **正文指纹。**
  - `ChapterRecord.bodyHash` 记下上次对账时读到的正文（去掉空白后算 FNV-1a）。
  - 存的指纹和当前正文不一致时，`effectiveChapterPhase(chapter, fingerprint)` 返回新阶段 `stale`（待对账）。没有指纹的旧记录也算待对账，所以生产上的第 1–5 章可以重新对账。
  - `writing` 和 `stale` 的章都能对账。正文没改过的章拒绝第二次导入。
  - 不设「定稿」按钮：改正文本身就会让章节重新打开。
- **按章整体替换。** 重新导入时，先删掉这章在提及、经历、关系分三本流水里的记录和这章没处理的待审，再写入新的。待审编号不复用。
- **导入失败什么都不写。** 先把所有引用检查一遍，过半对不上就返回 `settled: false`，什么都不写。工具会回「未对完」，并逐条说明原因：
  - `evidence-spliced`：引用里有省略号；
  - `evidence-too-long`：超过长度上限；
  - `evidence-not-found`：正文里找不到。
  工具还会提示模型把这些引用交回 subagent 改，不要自己手拼 JSON。
- **用户原稿不带计划。**
  - `writeChapter` 拒绝给 byUser 章登记计划，报 `plan-on-draft`。
  - prepare 生成素材包时，会把 byUser 章的计划去掉。
  - byUser 章导入时，会删掉旧计划、确认时间和兑现记录。
- **已有设定。**
  - 世界设定的名字（去掉括号说明后）如果和某张在用的卡同名，或和一张无名卡的开头一致，就把它关联到这章，写进 `ChapterRecord.settings`。
  - 这章的写法和卡上不一样时，生成一条 `setting` 待审，让用户选以哪个为准；采纳后会改写卡的 `rule`。对账绝不覆盖或删除卡。
  - 人物名比较时去掉括号里的说明。
  - 和已有伏笔问题相同的新伏笔直接跳过。
- **故事日志只显示进了故事的卡。**
  - 伏笔要有标记，关系要有流水或来源章，人物要有出场。
  - 世界卡要被某个已对账章的 `settings` 收录，或有来源章。纯灵感卡留在画布上，不进日志。
  - 章节表头显示 计划 / 待对账 / 已对账。
- **Skill。**
  - 规划或续写之前，先把「待对账」的章对完；`novel_read(chapters)` 会列出这些章。
  - 不必等用户说「定稿」。
  - subagent 报错时改参数重试，绝不手拼 JSON。
  - 不改正文、不加标注行，不在用户文件夹里留临时文件。
  - 可以落灵感卡。
  - 对账素材包第 1 条改为「一段连续原文，不用省略号拼接」。

## Alternatives considered

**对账前让用户点「定稿」按钮。** 用户否决了：多一步操作，而且说了定稿之后照样会改。指纹不用问就能发现每一次改动。

**重新对账只追加（保留旧记录、再加新的）。** 那样每改一次稿，这章的伏笔提及和关系分都会重复计算。按章整体替换，流水才能如实反映当前正文。

**对上的引用照常落地。** 生产上的章节就是这样被一次空读锁死的。对上的不到一半时，subagent 的输出整体不可信，所以什么都不写，章节保持打开，等改好后重试。

**章节里的设定和卡不一致时直接改卡。** 对账只负责读正文，不该替用户决定哪个版本是正设。冲突作为待审交给用户。

## Consequences

- 部署后，生产上的五章会显示「待对账」。重新对账会重建这几章的流水，并去掉第 2–5 章多出来的计划。
- 模型已经写在存储之外的东西（临时 JSON、第1章.md / 第2章.md 里的标题行、c7 卡）代码不会去动，由用户手动清理。
- `normalizeChapter` 现在会保留 `bodyHash` 和 `settings`。旧版本读到新表会丢掉这两项，章节就又显示为待对账，这样是安全的。
