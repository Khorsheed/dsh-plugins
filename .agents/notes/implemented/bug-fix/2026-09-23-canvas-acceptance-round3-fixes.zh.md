# Agent Note：对已上线画布的一次验收，以及它找出的六处问题

Status: implemented

## Problem

画布这一轮的 ①–⑧ 需求以 0.4.5 出货并通过了 3080 的 canary，这只证明板子能打开——不证明它看着顺眼。用户随后真的用它，然后带着七条反馈回来，全部关于表面而不是数据模型：

- 「＋新卡」按钮在画布名旁边**看不见**，而画布切换器自己的标签被说太丑；
- 连线视图脚下有**好几行解释性文字**；
- **连线会穿透**它连接的那两张卡；
- 分区改名框比它所依据的**原型更难看**；
- 画板**盖住了卡片自己的正文**；
- 同一处重叠还在渲染视角里造成**一行悬浮的铅笔工具压在正文上**；
- 而打开一张卡变成了**宿主右侧栏标签**，我们之前讨论的是画布**内部**的标签。

其中六处当场修掉了。每一处背后的机制都不同，而且有两处是这个包里所有测试都看不见的——这才是要记下来的部分。

## Decision

- **一个入口挨着它作用的东西，而不是排在阅读行的末尾。**「＋新卡」从顶栏最远端挪到紧跟画布名切换器之后。按钮一直都在渲染；一个 `flex: 1` 的撑开元素在宽面板上把它推到约 1500 px 之外，所以在 1512 px 视口里它干脆在屏幕外。一个往*这块画布*添加内容的控件，不能待在眼睛顺着这一行读下去的那个位置——因为宽面板下，眼睛和按钮已经不在同一块面板里了。
- **切换器加外壳；它的下拉行不加。** `.topic` 变成一个带边框、带内边距的 pill，名字省略号截断，chevron 调暗（并新增 `.topicName` 这个 span，因为省略号需要一个 min-width-0 的盒子，而 flex 子项里的裸文本节点不是）。下拉的行反方向走：扁平、只有 hover 底色。**触发器和它的菜单共用一条规则，就是一份塞满小方框的菜单的由来。**
- **变更日志不是界面文案。** `link.hintData`——那段讲 `canvas.json` 多了 `links` 和 `lanes`、写给迁移文件的人看的段落——从两个语言包里一起删掉，`link.hint` 压成一行手势说明。板子靠被拖动来解释自己；图例属于这份 note，不属于绘制区下面。
- **一条线锚定在两张相向的边上，而哪两条边算相向仍然是几何。** `wirePathOf` 现在经由 `wireAnchorsOf`：先按主导增量选轴，再选那对相向的边，于是线从 A 卡离开的那一侧就是 B 卡所在的那一侧。B 在 A 左边时，目标不是 B 的左边，也不是 A 的右边——端点变成 A.left 与 B.right。存储的那一对仍然是 `{from,to}`，没有 side 字段，因为**存下来的边方向会在用户第一次把一张卡拖过邻居时把线尾留在错误的一边**。与此配套，每张卡现在有**两个**端口（`data-port="<id>:left"` / `:right`）：一个圆点会教用户横穿板面去找那条画得好看的边。手碰到哪个端口决定的是**实时**那条线从哪里起手；成线之后与它无关。
- **外推地板在这次改动里活了下来，但它的测试换了形状。** `WIRE_MIN_PUSH`（24 单位）仍然让贴得很近的邻居鼓起来，而不是压成一条看起来像渲染故障的直缝；变的是这个外推现在沿*选中的*轴、从*选中的*边施加，所以 `tests/layout-geometry.spec.ts` 里每一处钉住的 `d` 字符串和 `tests/link.client.spec.tsx` 里的挂载断言都按新契约重写了——外加一条属性测试，在一片摆放网格上断言**端点永不落进任何一张卡内部**，那正是用户看到的那个故障。
- **`outline: none` 是一个带样式 `<input>` 的必需声明，不是讲究。** `.laneInput` 从原型继承了 `<button>` 的尺寸，但它是一个真 input，而 Chromium 的默认焦点环粗到会被读成给整个分区套了个选择框。焦点改由边框承担，正如分类面板里 `.catInput` 已有的做法。
- **显式声明了 `min-height` 的 flex 子项就没有内容地板。** 这是七条里的两处同源的那一个根因。`.root` 是一个有确定高度的纵向 flex 容器，带 `overflow-y: auto`；`.body` 声明了 `min-height: 60px`，而这*替换*了 flex 子项默认拿到的 `min-height: auto`——于是一张 7000 字的卡被压扁成 239 px 的盒子，它的正文却仍按 1365 px 绘制，一路穿过下方的画板。画板看起来像浮在文字上；铅笔工具条看起来像一个悬浮 bug。`.body` 和 `.pad` 现在都取 `flex: none`，于是页面滚动，而不是内容相撞。

## Alternatives considered

- **用 `@xyflow/react` 画线**——整个阶段在[连线视图 note](../feature/2026-09-23-canvas-link-view.md)里已经否掉；它的边缘锚定本来是最强的重议理由，而上面的修法是 30 行代码，落在一个已经有 50 条测试的层里。
- **每条连线存锚定边**（`{from,to,fromSide,toSide}`）。否掉：这会让布局数据记录的是"这条线当时怎么画的"，而不是"哪两张卡有关系"，而卡拖动——无时无刻不在发生——会把它作废且无从察觉。
- **把整段提示收进帮助入口**（一个 `?` 弹层）。否掉：用户的诉求是"为什么这里有一堵文字墙"，而一行手势说明短到可以就是面板的一部分，不需要打开。
- **给 `.body` 写 `min-height: auto`** 以恢复 flex 默认值。否掉，改用 `flex: none`：`min-height` 同时还在承载一个真实意愿——空卡不该塌成零——`flex: none` 加上 60 px 地板让两个意图都明写着，而不是一个属性兼职。
- **用 JS 按正文实测高度重排画板位置。** 否掉：那是给一个 CSS bug 穿上功能外衣的绕过。

## Consequences

- **这个包里没有任何组件测试能抓到那次溢出，而这一点现在是承重知识。** jsdom 从不排版，所以 `tests/*.client.spec.tsx` 看到的 `.body` 盒和画板盒只是*存在*；会失败的那条断言是 `element.scrollHeight > element.clientHeight`，而那里根本没有 `scrollHeight` 可读。机制改在测试套件之外确认：一份复刻详情页 CSS 的一次性 HTML，在无头 Chromium 里量（`chrome-headless-shell --dump-dom`，结果写进 `document.title`），修复前报 `rectH 239 / contentH 1365 / overflows 1126`，修复后报 `1365 / 1365 / 0`。**这个包的布局 bug 需要一轮浏览器实测，而这次验收就是那一轮。**
- **删 `link.hintData` 是一次语言对删除**：两份字典丢同一个键，所以任何语言都不会渲染出一句孤儿。它承载的迁移事实没有丢——在连线视图 note 的 Consequences 里，那才是变更日志该待的地方。
- **每卡两个端口意味着卡角附近两倍的可点面积**，但端口只有 12 px 且落在节点框之外（`left:-6px` / `right:-6px`），并且 `startWire` 会阻止冒泡，所以按在端口上永远不会同时成为一次卡拖动。
- **规格里每一处钉住的线字符串现在都是边缘锚定的**，于是将来若改回中心锚定会大声失败而不是悄悄重推——这正是钉 `d` 的意义。
- **`＋新卡` 的位置成了一条可复用的约定**：它现在在附件芯片之前，芯片行保留自己的横向滚动。任何人往顶栏加控件，先问它作用于什么，再决定它放在撑开元素的哪一边。
- **第七条在同一轮里另外出货。** 打开一张卡变成*宿主右侧栏*标签是阶段 ⑧ 的形状，而用户对它的回答是一个产品决定而不是一个修补——标签放进画布 surface 内部，其中一些行是画布、一些是卡片。那次裁决和它做出的改动在 [画布自己接管那一排标签](../feature/2026-09-23-canvas-inner-tab-strip.zh.md)；上面六条在它的上面依然成立。

## Testing

- `pnpm --filter @khorsheed/dsh-canvas build`（gen-typert → 宿主 tsc → 客户端 tsc → tsdown），随后 `pnpm --filter @khorsheed/dsh-canvas test` — **23 文件 / 454 绿**（本轮之前 449；几何 +4，连线视图 +1）。
- `tests/layout-geometry.spec.ts`（+4，共 50）：两条相向边缘锚定、旧的横向画法在 45° 一对上发生的轴翻转、盒子真重叠时端点仍在两张卡之外的那一对，以及一片摆放网格上端点永不落进卡内的属性钉。
- `tests/link.client.spec.tsx`（+1）：从左边端口起手存的是同一对、画出来也是同一个 `d`；以及按侧挂载（两张卡四个 `data-port` 钩子）。`portOf` 多了一个默认为 `right` 的 `side` 参数，所以每条既有拖动测试仍然走右边那条边。
- 六处表面修改是**在跑起来的宿主里用眼睛验的**，不是靠测试：`~/.dsh-lab/profiles/canvas-v2-test` 在 3091 端口装载本次构建打出的包，七条反馈逐条对着看。
