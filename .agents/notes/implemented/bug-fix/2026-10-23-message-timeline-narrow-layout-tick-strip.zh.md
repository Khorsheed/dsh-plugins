# Agent Note: 窄布局下时间轴降级为刻度条而非整条隐藏

Status: implemented

[English](2026-10-23-message-timeline-narrow-layout-tick-strip.md) | 中文

## Problem

[宽度封顶笔记](2026-08-17-message-timeline-gutter-width-cap.zh.md) 在左缘沟槽放不下 120px 最小宽度时把面板整条隐藏。右侧栏打开时——Room 会话（成员/团队面板）或任何窄窗口的常见状态——聊天滚动区被挤到只剩几像素沟槽，时间轴就整条消失。用户读到的是"Room 里时间轴没了"，而不是一次有意为之的隐藏。

## Decision

沟槽低于 `PANEL_WIDTH_MIN` 时不再隐藏面板，改为窄模式：静止时是落在消息流左留白里的 24px 刻度条（只显示刻度，不遮任何消息文字）；悬停或键盘聚焦时，面板展开为 `min(panelWidth, 滚动区的 60%)`，带实底背景（`--dsw-alias-bg-layer-1`）、圆角和阴影，让预览文字可读地覆盖在消息流上。宽布局的沟槽封顶规则不变，流探针失败的兜底（滚动区比例宽度）也不变。隐藏条件里的 `tooNarrow` 已移除；窄模式下面板渲染为 `css.panelNarrow`，展开宽度经自定义属性 `--panel-wide` 传入（悬停规则需要 `!important` 才能压过内联的静止宽度）。

## Alternatives considered

**窄布局继续隐藏。** 否决：隐藏原本是为了守住"绝不遮住消息流"，但它让时间轴在非常常见的布局下直接不可用；窄模式让它保持可用，且静止时不遮任何东西。

**始终覆盖在消息流上，不做静止区分。** 否决：环境化静止态正是时间轴的意义；常驻覆盖会挡住每条消息的开头，正是宽度封顶决策要避免的。

**只下调最小宽度阈值。** 否决：2px 的沟槽依然什么都放不下——问题在摆放位置，不在阈值。

## Consequences

时间轴在右侧栏和窄窗口布局下不再消失：静止时是消息流左留白里的刻度条，只有用户主动悬停/聚焦时才以带底色的浮层覆盖内容。宽度封顶笔记中"低于最小宽度则隐藏"的条款被取代，其按沟槽封顶的规则仍然成立。覆盖：宽度策略 spec 改为断言窄模式 class、24px 静止宽度与 `--panel-wide`（旧的隐藏断言已移除）；悬停展开是纯 CSS 行为，不做单元断言。已在调试实例实测：右侧栏打开时面板不再消失，悬停展开为 360px 实底浮层。

后续（2026-10-24）：悬停底色起初铺满整段时间轴高度的面板框，消息少时列表悬在一张又高又空的卡片中间。面板不再固定 `height`，改为高度随行数、`max-height` 等于时间轴高度，并以时间轴中线居中（`top` 取中线，加 `translateY(-50%)`）。这样底色只包住列表；列表很长时仍铺满时间轴高度并滚动。auto-margin 居中占位已移除。宽度策略 spec 断言中线 `top`、`max-height`，以及不设固定高度。
