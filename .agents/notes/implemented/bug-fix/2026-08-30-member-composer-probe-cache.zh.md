# Agent Note: Member composer 核实窗口不再闪只读面板，成员身份按会话缓存

Status: implemented

[English](2026-08-30-member-composer-probe-cache.md) | 中文

## Problem

MemberComposer 每次挂载都通过 `memberOf` Remote 核实成员身份，两个缺口让家族成员会话会短暂渲染"一次性子代理"只读面板——room 演示暴露的错误不可用暗示：

1. **RPC 失败塌缩成"非成员"。** 注入的 `memberOf` 把 RPC 失败映射为 `undefined`，而组件用 `view ?? null` 落定——一次瞬时失败（挂载后 Remote 通道尚未就绪）就会给真正的成员渲染只读面板，直到 running 翻转或重新进入才重新核实。Promise 直接 reject 更糟：`.then` 没有拒绝分支，面板永远停在"核实中"并留下未处理拒绝。
2. **没有缓存。** 每次挂载都从核实态开始，同一成员会话反复进入时每次都重复闪现核实窗口。

## Decision

- **会话级正向成员缓存。** 模块级 `Map<childSessionId, LocalAgentDelegationView>`（与 auth-status 总线同形）为初始态和每次子会话切换供种；委派记录对会话生命周期不可变，所以命中的成员首帧直接渲染可写框，完全不再核实。null 答案绝不缓存——记录在首轮 settle（exec）或 live 握手时落账，现有的 running 翻转重核恰好覆盖这个窗口。
- **RPC 失败永远不是成员证据。** `undefined`（或 reject）答案保持中性核实态，在有界预算内重试（2 次 × 300ms）后才降级为只读面板——没有网关时发送本来就不可能，所以只读仍是诚实的终态，只是延后。核实态本来就是中性文案（"正在确认成员身份…"）；现在它也是瞬时失败唯一能展示的状态。
- 核实的拒绝分支走同一条重试路径，堵上永远挂死的洞。

## Verification

`tests/member-composer.client.spec.tsx`（+3，套件 27 绿；包 163 绿，build 绿）：RPC 失败停在核实文案、重试后翻成可写，全程不渲染只读文案；预算耗尽后降级只读，核实调用恰好 1 + 2 次；重新进入的成员会话首帧可写、`memberOf` 零调用。套件在 `afterEach` 通过导出的 `resetMembershipCache` 测试钩子清缓存。

## Alternatives considered

**网关宕机时无限重试**——否决：网关死了发送本就不可能，永恒转圈会掩盖真实降级；有界预算落回与确认非成员相同的只读面板。

**给 null 答案加 TTL 缓存**——否决：记录落账窗口已有 running 翻转重核覆盖，陈旧的 null 会让查看中途才成为成员的会话重新闪现。

**骨架/灰态框的核实视觉**——作为范围外否决：问题的实质是只读*语义*；核实态本来已是中性文案。消除闪烁靠的是修塌缩和缓存正向结果，不是重画窗口。

## Consequences

打开成员会话现在直接进入可写框（缓存命中）或短暂的中性核实节拍（首次查看）；只读面板只剩两个含义："确认非成员"或"网关在重试预算内不可达"。缓存随模块生命周期存在——每个查看过的成员会话几字节，无淘汰。非成员的一次性会话每次进入仍会闪一下中性核实态（其 null 答案刻意不缓存）。
