# Agent Note: library chapter-quiz review fixes

Status: implemented

## Problem

一次章节考的产品走查（《大转型》阅读项目）暴露出七个缺陷，都在 `packages/library`：

1. 题目的证据引用渲染在作答控件之前——网上/照片原文往往逐字包含答案（被走查那题的引用就是选项 C 的文字），引用先于作答出现等于直接给答案。
2. 选择题的 `answer` 指向的选项与解释辩护的选项不一致（answer 命中选项 C，解释论证的却是 A）——这是生成侧的不一致；更糟的是 answer 一个选项都命中不了时会被静默存下，之后侧栏把任何选择都判错。
3. 教练存好考卷后把整套题复述进会话——题目是在侧栏里作答的，复述纯属浪费 token。
4. 书页头部把版本信息放进 `PanelHeader` 不换行、不截断的 `meta`——长版本串溢出头部，把操作图标挤出去。
5. 路线下方的图例行（「方形是关卡，过章节考解锁下一关…」）是解释性噪音。
6. 从路线上点关卡进来直接落到章节考，而不是导读。
7. `focus: book` 的考卷仍然先读一遍用户的卡片（指引里的「出什么，按顺序」是无条件的），教练的口述让「只考书本内容」和「都考」没有区别。
8. 刚出好的考卷在章节考页顶部只是一行普通列表行——和历史考卷长得一样，教练忙活完用户根本注意不到。
9. 简答题可以只抛一个孤零零的说法（「社会的发现」是什么意思？），用户没有任何可以锚定讨论的内容。

## Decision

- **引用移作答后**（`src/client/views/quiz.tsx`）：证据引用只在作答后的反馈区渲染，与解释、出处链接同列。证据种类 chip 仍保留在题前——它只标来源，不漏内容。
- **选择题答案门**（`src/service.ts`）：`putQuiz` 拒绝 answer 命中不了任何选项的选择题——命中规则与侧栏判题一致（范围内的字母、带字母前缀、逐字文本、单向包含），并返回可教学的报错。超出范围的字母（两个选项配 answer `D`）同样视为未命中。
- **提示词**（`src/tool.ts` 的 `LIBRARY_PROMPT`）：改写两条、新增两条——选择题的 answer 就是其中一个选项（先据证据写出正确选项，再围绕它出干扰项，逐字抄进 answer，解释辩护同一个选项）；存好的考卷在侧栏章节考里作答，回复只要一行（几题、依据什么），绝不在会话里复述题目；`focus: book` 只考这一章的书本内容，完全跳过 `library_read · cards`；「出什么，按顺序」一条现在只约束 mine 和 mixed。
- **头部**（`src/client/views/book.tsx`）：BookView 头部去掉版本 `meta`（版本仍在下方 bookHead 行里，那里会换行）；标题只放书名。
- **删图例行**（`src/client/views/book.tsx`、`src/client/locales.ts`、`src/client/LibraryPane.module.css`）：`book.legend` 文案、zh/en 键和 `.legend` 规则一并删除。
- **默认导读**（`src/client/views/book.tsx`）：路线节点一律落到导读（原先是读节点进导读、考节点直接进章节考）。
- **最新考卷要显眼**（`src/client/views/book.tsx` QuizTab、`LibraryPane.module.css`）：最新的考卷渲染成 accent 色 hero 卡（「最新考卷 · N 题」、出题范围与证据构成、主按钮「开始作答」），紧随过关线之下；更早的考卷收进「之前的考卷」小节。等教练出题的轮询一看到新考卷落地，直接替用户打开它。
- **简答题自己交代讨论对象**（`src/client/views/quiz.tsx`、`LIBRARY_PROMPT`）：简答题的证据引用随题干渲染——它只负责说明讨论什么，漏不了答案——选择题和填空题的引用仍作答后才出现；提示词要求简答题点名所针对的段落、论点或章节，把段落写进 evidence.quote，不许只抛一个用户定位不了的说法。

## Alternatives considered

- **只对选择题隐藏引用**：填空题的引用同样漏答案（引用就是空格所在的原句）；只有简答题的引用留在题前——它负责框定讨论，漏不了答案。
- **考卷落地用 toast 或提示条而不是直接打开**：轮询的存在本就是因为用户点了出题并在等；既然下一步一定是进考卷，多点一下只是仪式。
- **列表保持新前旧后、给新考卷加个「新」角标**：长得一样的行加个角标仍会被当成列表噪音；hero 卡把新考卷变成这一页唯一的主操作。
- **服务端校验 answer 与解释一致**：一致性是语义层面的——存储无法判断解释辩护的是哪个选项；这条规则放提示词，机械规则（answer 必须命中选项）放服务端门。
- **在共享 panel-kit 的 CSS 里让 meta 可截断**：为局部问题动全局样式，且 kit 的设计注释本就把 meta 限定为「计数、上级目录」这类短注；版本信息由正文里会换行的那一行承担。
- **图例行改成首访才显示**：路线自身的图标语言（锁盘、编号关卡、侧边小圆点）已经能教会；这行每次来访都是噪音。
- **当前关保持落章节考**：否掉——导读是节点自己的页面（目标、对应目录），章节考只隔一次点击，用户预期也是落在导读。

## Consequences

- `putQuiz` 更严：原先能存下的坏选择题现在带着教训拒绝；两个新测试钉住这道门（游离文本、超范围字母、字母前缀被接受）。存储数据形状不变，门前存下的旧考卷照样按新位置渲染引用。
- 提示词改动只影响新会话的指引，不落在任何持久数据里。
- 78 个测试通过（新增 2 个）；`pnpm check:panels --package packages/library` 报 0 错误。渲染层的改动（引用位置、hero 卡、落地自动打开）用包自带的侧栏 fixture 做了 DOM 与计算样式验证——本机 Playwright 截图通道卡死，改走行为断言。
- NodeView 头部仍是长节点标题＋书名 meta 的组合；极窄面板上 meta 仍可能挤压标题——本次走查的溢出是 BookView 的版本串，NodeView 维持原样。
