# Agent Note：Codex 实时轮次结算报本轮用量，不再报整个线程的累计

Status: implemented

## 问题

app-server 的 `thread/tokenUsage/updated` 带 `last`（单次 API 调用）和 `total` 两个字段，其中 `total` 是整个**线程**的累计。房间成员每一轮都续接同一个线程，所以结算报上去的是这个线程至今的全部花费。房间 5d4f0d41 里，游戏策划大师各轮依次是 2.15M → 2.25M → … → 3.04M。房间统计行把各轮相加，显示 28.2M；宿主的会话切换下拉（按子会话里每次调用的用量累加）显示的是 5.3M。房间 2e44ba43 的 Codex 成员也一样（0.49M → 9.27M，只增不减），只是每轮只多约 65K，看起来像正常值。

## 决定

实时驱动把 `total` 减去本轮第一次调用之前的线程累计。这个基线等于第一条通知的 `total` 减去它自己的 `last`，所以不需要跨轮保存状态。逐条记录上每次调用的 `last` 用量不变。

## 考虑过的其他方案

- **把本轮各次 `last` 相加。** 每次调用恰好通知一次时，结果和相减一样；通知重复时，相减的结果仍然正确。
- **在房间里拿相邻两轮做差。** 这会把 provider 的协议细节带进房间，而且重启后的第一轮会算错。

## 影响

对新的轮次，房间每条回复的用量和统计总数都会和宿主的切换下拉一致。已经写进日志的 `room/execution-metadata` 仍是累计值，不会改写历史记录。
