# Agent Note: 宽屏移动端会话库为聊天和面板让位

Status: implemented

[English](2026-11-07-mobile-wide-library-visibility.md) | 中文

## Problem

在 iPad 这类宽屏视口上，移动端会话列表无法折叠。菜单始终写入 `library=true`，侧栏通过 `hidden={!library && !wide}` 忽略关闭状态，CSS 又把隐藏的侧栏强制设回 `display:block`。同一个被强制显示的列表还会遮住 Context Lens、游戏等受管理面板的左侧内容。窄屏手机的列表是可关闭抽屉，没有这个故障。

## Decision

宽屏会话库与窄屏抽屉遵循同一个 `library` 状态。在现有 960px 断点及以上，菜单切换该状态；断点以下保留原有打开抽屉行为。侧栏的 `hidden` 属性和列表元数据读取的可见性都直接跟随 `library`。320px 的框架偏移、工具栏偏移和分隔线只在存在 `data-mobile-library-open` 时出现。宽屏收起列表后，对话使用完整视口，不留下多余边线。

打开受管理面板时，无论列表状态如何都隐藏会话库并清除框架左侧偏移，即使面板由宿主能力而不是移动端按钮打开也适用。关闭面板后恢复原有列表状态。宿主保存的 dock 布局和面板内容保持原位。窄屏抽屉、960px 断点、320px/380px 宽度、手势，以及此前的宿主边框和阴影处理均不变。

## Alternatives considered

**宽屏列表始终固定，面板整体右移。** 不采用：这既保留无法满足的折叠预期，又会永久缩小每个面板的可用宽度。面板优先符合现有全宽移动面板契约。

**只修改菜单处理函数。** 不采用：CSS 仍会强制显示已关闭的侧栏，从移动端按钮之外打开的面板也仍会被遮挡。状态、元素隐藏、框架几何和面板可见性必须一致。

**单独做一套 iPad 布局。** 不采用：故障源于一条可见性规则，不需要另一棵组件树。同一套自适应界面能让手机和平板行为一致。

## Consequences

宽屏用户可以收起并重新打开会话列表，官方编辑器不会被替换，草稿不会丢失。Context Lens、游戏和其他受管理面板打开时获得完整内容视口，左侧导航和数据不再被会话库遮挡。隐藏的列表不再执行可见行元数据补全。宿主和 iOS 壳不需要修改源码。

覆盖包括 1024px 收起/展开组件测试，检查 `hidden`、`aria-expanded`、根可见性属性、编辑器节点身份和草稿保留；另有受管理面板 CSS 测试，检查列表消失、框架偏移移除及恢复。浏览器渲染覆盖窄屏抽屉和宽屏打开/收起/面板状态；原生设备视觉与触控验收仍需单独观察。
