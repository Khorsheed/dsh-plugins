# Agent Note: 重启造成的队列暂停在丢失轮次核对后自行解除

Status: implemented

## Problem

重启后，自动继续已经把被打断的成员接着跑起来了，但房间输入框上方仍显示「队列已暂停；重启后请先核对未完成消息。」，带一个继续按钮，队列里却什么都没有。启动时成员收件箱会把每条运行中的记录标成 `uncertain` 并暂停队列，防止丢失的那一轮还没定论就重放。自动继续（以及给成员发消息继续往下走）通过 `reconcileExecution` 了结这一条，但 `reconcile` 从不清除 `paused`。标记的理由已经不在了，标记还留着，提示让用户去核对已经不存在的消息。

## Decision

- 收件箱记下是谁暂停的：启动恢复时暂停记 `pausedBy: 'restart'`。操作者调用 `pause()` 会清掉这个标记，所以操作者的暂停不会自行解除。
- `reconcile` 和 `cancel` 在没有待决事项时解除重启暂停，即没有 `uncertain` 记录、也没有排队中的输入框消息。还有输入框消息在等时保持暂停，因为盲目重放正是暂停要防止的事。
- 如果暂停是操作者自己加的，恢复时不打标记。

## Alternatives considered

**自动继续开启时启动不暂停。** 自动继续是房间设置，收件箱属于成员核心；重启前排队的输入框消息仍需要定夺。

**自动继续后由房间清除暂停。** 这样也会解除操作者自己的暂停，而只有收件箱知道自己为什么暂停。

## Consequences

自动继续之后提示会消失，除非还有输入框消息在等。以前重启留下的暂停没有标记，需要点一次「继续队列」。

## Testing

`packages/local-agent/tests/member-inbox.spec.ts` 覆盖了以下情况：

- 已核对的房间轮次会解除重启暂停。
- 有排队中的输入框消息时保持暂停，取消后解除。
- 操作者的暂停不带标记。
