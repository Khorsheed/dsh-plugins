# Agent Note: publishing a game version mid-turn

Status: implemented

## Problem

版本只有一条路进试玩区：回合结束时的检查（`agent/turn-stopping`）。游戏开发模式下，agent 常常写好一版就用 `ask_user_question` 请用户试试——而提问并不会结束这一轮。2026-10-22 一个 3D 会话整整 22 分钟只有一轮，里面问了 13 次；agent 请用户「玩一分钟」时，试玩区还显示没有可玩版本，因为一次检查都没跑过（项目里连 `.game/` 都没有）。人设提示词还火上浇油：它告诉 agent 不要自己部署、检查「在你这一轮结束时」进行。

## Decision

- 新增第四个模型工具 `game_publish`，按需跑同一条 `checkTurn` 流程：数据校验 → 无头加载并冒烟 2 秒 → `tests/*.test.js`。通过就生成版本进试玩区（自动上线关着或换风格时成为候选）；不通过返回问题清单；构建没变时直接用上次检查的结论回答，不重跑。
- 它调用 `checkTurn` 时不设自动修复上限，所以主动发版永远不会把某个构建标成「已停止自动修复」；发版没过的构建，回合结束时照样检查（并送回修复）。发版通过的构建，回合结束时被现有指纹判断跳过。
- 规矩写在提示词各层：`gamedev` 技能、`game-agent` 引导段、`dsh-gamedev` 人设的两份副本（`packages/gamedev`、`packages/presets`）都要求请用户试玩或体验任何东西之前先 `game_publish` 并且通过，并说明纯设计问题不需要发版。

## Alternatives considered

**每次 `ask_user_question` 之前自动检查并发版（`tools/pre-execute` 钩子）。** 不需要模型配合，但 agent 常在文件写到一半时提问；钩子要么白跑检查，要么拿不相干的失败拦住一个设计问题。和用户讨论后否决；如果 agent 老是忘记规矩再考虑。

**按提示词规矩让 agent 自己验证能不能玩（用 bash 起无头浏览器）。** 即便自查正确也生成不了版本——只有插件会拍快照、编号、上线——试玩区照样是空的，正是这次观察到的问题；还会让每个 agent 各搭一套浏览器环境。

**只改提示词为「请用户试玩前先结束这一轮」。** 为了提问而结束回合，会打断用户喜欢的「问一句、接着干」的节奏，也让 agent 没法发完一版继续工作。

## Consequences

- 能不能及时交付取决于 agent 守不守规矩；回合结束的检查继续兜住这一轮留下的东西。
- 一轮中途可能跑多次检查；每次每个测试文件一次无头加载（小游戏几秒）。
