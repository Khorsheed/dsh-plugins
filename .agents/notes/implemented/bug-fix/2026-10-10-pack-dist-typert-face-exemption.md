# Agent Note: pack-dist exempts generated typert faces from the family-edge scan

Status: implemented

## Problem

Merging the game-development mode ([2026-10-09-game-dev-mode](../feature/2026-10-09-game-dev-mode.md)) registered `packages/game` in gen-typert's `TYPERT_PACKAGES`, so the next full gen-typert run embedded the game's chat-message source — `'dsh-game': { plugin: '@khorsheed/dsh-game' }` inside the merged `MessageSourceMap` declaration — into EVERY typert-faced package's generated `lib/typert.host.js`. From then on `verifyTarball`'s family-edge scan failed any such package at pack time with `family references without manifest edges: @khorsheed/dsh-game` (canvas, canvas-novel, file-preview, library, local-agent, mission, room, sidechat — 8 of the 9 typert packages). The failure was invisible to the game deploy itself (game is selfName-exempt and presets declares the reference), and surfaced only when packing any OTHER typert package — the whole-repo `pack-all-dist` gate, CI, and every future `deploy:3080` of those packages.

## Decision

`verifyTarball` skips staged files whose basename starts with `typert.` (the generated faces `lib/typert.host.*` / `lib/typert.remote-client.*`) when collecting family references. The generator stamps those files from the composition-wide FaceModel, so a sibling name inside them is generated composition data, not an edge the package chose — and no manifest field can honestly declare it: a dependency edge would claim canvas installs game (false), and `dsh.references` records data a package's own shipped content carries, while the typert mention belongs to the generator's output, not the package. The one runtime import a typert face makes (zod) is already pinned by the dedicated typert-face zod check, so the exemption hides no real edge.

## Alternatives considered

**Declare `dsh.references: ['@khorsheed/dsh-game']` in every typert-faced package.** Rejected: the merged surface changes whenever ANY plugin adds a declaration carrying a package literal, so each such change would force a manifest edit across every typert package — and the entry would be a lie about the package's own content, since the reference belongs to the generator's output, not the package's sources.

**Strip only the embedded declaration strings before scanning.** Rejected: the exemption would then depend on the generator's exact serialization (JSON-string escaping today, another shape tomorrow); the file-level boundary — generated file, do not edit — is the stable contract.

**Have gen-typert stop embedding foreign package literals.** Rejected: the merged declaration map's whole point is composition-wide type completeness; a message-source entry legitimately names its owning plugin.

## Consequences

- `pack-all-dist` packs all 39 bundle packages clean on a tree that includes the game registration; `scripts/pack-dist.spec.ts` pins both directions (the generated face is exempt; the same name in a hand-authored lib artifact still fails).
- The exemption is keyed to the `typert.` basename convention. A package hand-authoring a file under that name would escape the scan, but the name is the generator's (`Generated by @deepseek-ai/dsh-typert-generator — do not edit`), so such a file is a convention violation, not a loophole.
