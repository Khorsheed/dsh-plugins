# Agent Note: 端口冲突夹具等待真实监听就绪

Status: implemented

## Problem

即使串行调度，两个守护集成测试仍在宿主负载下不稳定。旧监听器的启动器在独立 HTTP 服务绑定端口之前返回，依赖 200 毫秒固定等待。其十秒生存期也可能在 previous 开始恢复前结束。六次重试测试要求所有进程启动在二十秒内完成，超时缺少有用的过程诊断。

## Decision

旧服务在 listen 回调通过 IPC 报告 ready，竞争目标收到就绪后才启动。孤儿进程最长生存期为九十秒，正常释放仍由 previous 首次绑定失败触发。两个完整场景使用已有的带诊断生命周期等待器，观察上限六十秒、测试上限九十秒。普通重试夹具额外断言恰好执行六次尝试，保留不回滚、不放弃断言。切换夹具仍要求两次 target 失败、一次 previous 绑定失败、不接受 target ownership，以及恢复后的 previous 响应。

## Alternatives considered

仅降低并发有帮助，但不能消除夹具时序假设。削弱断言、跳过测试或改变生产重试会掩盖被测行为。进程编排不属于延迟契约，因此适合采用更充足但有界的集成测试预算。

## Consequences

只调整测试搭建与观察。生产超时、重试上限、认证、归属校验和重启行为均不变。行为错误仍在有界等待后失败，并附生命周期诊断。

## Testing

完整守护测试集使用真实进程验证这两个场景，保留精确结果和尝试次数断言。合并前仍须通过完整仓库门禁。
