# Agent Note: 将 Kimi 原生配置解析器装入产物

Status: implemented

## 问题

候选 tarball 的全新安装与升级预检均因 `Cannot find package smol-toml` 无法导入 Kimi。源码清单声明了依赖，因此开发链接和全部包级测试通过；但仓库打包器按运行依赖已内置的合同移除了普通依赖，而默认 Node 打包仍将这个新增导入留在包外。

## 决策

Kimi 的包级配置通过共享 client bundle helper 的 Node 配置覆盖，将 `smol-toml` 强制打入 bundle。原生模型与推理配置的解析器因此随 provider 产物交付。官方宿主模块和已约定的家族依赖保持原有解析行为。

## 考虑过的替代方案

**在每个 profile 手动安装解析器。** 不采用，因为这会掩盖插件产物不完整，也违背独立安装约定。

**修改共享打包器的依赖政策。** 此包内缺陷不需要修改共享政策。现有打包合同已要求普通运行依赖内置，调整共享政策属于 mainline 职责。

## 影响

Provider 产物增加解析器的实现，不再要求消费者额外安装未声明的依赖。npm 宿主上的全新安装和升级预检是相关验证；开发链接测试不能单独证明这一属性。
