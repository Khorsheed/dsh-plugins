# Agent Note: 并发目标更新时仍执行用户暂停

Status: implemented

## 问题

Kimi/DSH 真实验收复现了暂停失效：浏览器显示计划版本后，成员提交成果改变了版本，用户暂停未通过乐观版本检查，自动返工继续执行。会话状态变化不应使用户的暂停请求失效。

## 决策

Room 目标面板在暂停命令中携带当前显示的目标标识。用户暂停且目标标识匹配时，服务在串行写入边界对最新状态执行暂停，不受版本推进影响。所有已提交证据保留，后续自动执行准入停止。已经运行的原生轮次仍可通过成员的定向停止按钮中止。

目标标识不匹配时拒绝。协调者暂停、没有目标标识的旧暂停命令、恢复、预算和证据验收仍校验版本。已关闭目标保持关闭。请求回执保留原始输入签名，支持确认响应丢失后的重试。

## 考虑过的替代方案

**浏览器自动重试所有过期操作。** 不采用，因为恢复、预算修改和证据验收可能面对已经实质变化的信息。暂停是范围明确的单向例外。

**所有暂停都忽略版本。** 不采用，因为旧页面延迟到达的请求可能暂停一个新目标。匹配页面显示的目标可避免跨目标误操作。

## 影响

用户暂停可跨越并发证据提交和调度更新，并保留这些更新。暂停到达服务前已经准入的原生执行无法撤销。回归覆盖证据保留、确认响应重试的幂等性、新目标和已关闭目标拒绝、协调者及恢复操作的原有校验，以及浏览器携带的目标标识。
