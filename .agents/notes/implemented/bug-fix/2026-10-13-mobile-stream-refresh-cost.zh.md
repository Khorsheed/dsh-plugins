# Agent Note: Avoid mobile refreshes for unchanged presentation

Status: implemented

## 问题

对话历史的流式更新触发整页手机布局和面板扫描。重复读取 Room 时，即使成员列表没有变化也发布通知，并在没有新发现房间时反复触发兼容输入框选举。

## 决定

布局和面板观察器忽略已验证的对话历史插槽内部变化，继续观察框架、标题、输入框和弹出界面。面板标题来自所属服务，因此面板观察器不监听文字节点。输入框高度继续使用已有的 ResizeObserver。

Room 读取只比较手机成员列表使用的字段；内容不变时保留原快照并更新缓存有效时间。旧版 Room 的兼容刷新只在新识别当前房间时触发，不随每次成员或运行状态更新执行。支持的旧安装仍保有兼容路径，远程刷新频率和所属插件的修改操作保持不变。

## 考虑过的替代方案

**删除全部 DOM 监听。** 当前支持的宿主仍需要已验证的布局锚点和延迟挂载恢复；未来可以通过公开布局事件替代。

**无条件移除旧 Room 兼容路径。** 最新 Room 已处理房间提升，但独立安装的旧版本仍需要兜底。

## 后果

消息增量不再触发昂贵的布局扫描，标题和结构变化仍能更新手机布局。未变化的 Room 读取不会通知订阅者。测试覆盖文字和元素流式变化、标题和面板更新、成员快照稳定性以及成员变更。这次没有合并两个 Room store，也没有改变共用宿主的启动加载。
