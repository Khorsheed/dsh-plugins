# Agent Note: 移动端目录选择留在手机内

Status: implemented

## Problem

移动端工作区流程支持输入电脑路径，但 Room 的纯路径选择直接调用 uiWorkspace.pickDirectory。因此在使用原生选择器的宿主上，选择移动成员工作目录会在电脑弹出窗口。宿主实例的 native 和 browse 目录能力互斥。

## Decision

两个公开工作区目录流程槽及纯路径选择共用移动端目录面板。添加工作区时直接打开电脑目录列表；成员目录选择先展示官方已有工作区。两者均提供返回上级、隐藏目录开关和筛选。手动完整路径输入收在默认折叠的辅助控件里。只有成功读取过的当前目录可以确认。接入工作区或更新成员仍交给原所有者；单纯选择路径不会修改 Room 或创建工作区。

在宿主提供纯路径选择 UI 槽之前，临时包装当前浏览器公开的 uiWorkspace.pickDirectory 方法。移动端调用共享一个待完成选择；桌面调用以原接收者委托原方法。取消、退出移动模式或服务卸载时以 null 完成待选请求。卸载时仅当包装器仍在位才恢复原自有属性或继承方法。未来的只读服务外观不能导致插件加载失败。不替换 Room 回调，不添加 Room 依赖，也不改变共享宿主的目录选择能力。

移动端宿主配套通过已认证的 Connection Fetch 路由提供只读目录浏览。使用 Node 文件系统操作返回一层目录，跟随可进入的目录符号链接，为隐藏目录加标记，并限制扫描及返回大小。完整路径按当前平台校验，错误不包含原始 OS 消息。包括移动公网入口在内，官方连接载体在分派前执行认证和 Host/Origin 检查。接口不读取文件内容、不创建文件夹。浏览请求可取消，过期结果不能覆盖新导航。失败后保留重试与手动路径输入，不回退到原生选择器。

## Alternatives considered

切换共享实例到 browse 后端会改变桌面行为，而且不能自动把 Room 仅支持 native 的 pick 调用变成应用内流程。另建 Room 表单会重复成员变更逻辑。只支持复制目录路径仍无法满足手机浏览。修改宿主源码会产生部署分叉。因此在上游提供展示扩展点前，使用可恢复的公开方法适配作为有边界的降级方案。

## Consequences

在现有操作者认证下新增一个只读文件系统路由，目录范围与官方浏览器相同。列表达到 1,000 个目录或扫描 10,000 个条目时停止并提示截断；完整路径输入可到达未展示的目录。系统磁盘权限仍然适用。接口依赖提供 HTTP 服务的连接载体和配套插件；离线或缺少配套时显示错误，不打开电脑窗口。宿主提供纯路径选择 UI 槽后移除此方法包装。测试覆盖真实文件系统过滤与失败、路由生命周期、异步取消、验证后接入及桌面恢复。
