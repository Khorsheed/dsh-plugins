# Agent Note: 恢复电脑端移动公网入口

Status: implemented

**更新（2026-09-28）：** 下述管理器已由[移除移动隧道自动部署](2026-09-28-remove-mobile-tunnel-manager.md)删除，其生命周期描述仅作为历史记录。匿名二维码检查与明确手动调用的地址轮换仍然保留。

## 问题

Quick Tunnel 进程存活时，远端注册和 DNS 仍可能失效。Web 连接页面原来只检查配置地址和宿主信任，因此继续生成失效地址的二维码。用户无法区分宿主部署重启与网络故障。

## 决策

移动插件在报告可用或签发官方登录链接前，匿名检查配置的公网根地址，限制六秒且不跟随重定向。客户端每十五秒复查正在显示的二维码，失败或地址变化就收起。探测不携带 token。

可选的电脑端管理程序 scripts/mobile-tunnel.mts 独立于宿主，拥有新 cloudflared 和 loopback 转发进程。本地宿主健康且公网连续三次失败才恢复；宿主故障时等待，恢复尝试间隔十分钟。候选转发仅接受分配给它的 HTTPS 地址。管理程序用经过校验的 mobile-origin 参数调用 deploy:3080，通过受控 reconfigure 精确替换已有公网地址及 trusted-host，包括配置探针的地址。原有构建、测试、部署锁、预检、回退及鉴权 canary 继续生效。移动端或部署文件存在未提交修改时阻止自动部署。部署结果不确定但新配置已提交时保留候选隧道，避免错误路径关闭正在使用的入口。

管理程序作为独立电脑服务安装，移动插件不自行启动服务或注册 Cloudflare 账号。地址变化后手机仍通过重新扫码恢复。不引入通配信任或新的地址发现服务。

## 考虑过的方案

**只重启 cloudflared** 会更换域名，但未更新宿主信任和二维码配置，手机仍无法连接。**每次请求失败都重建**会在短暂断网或普通宿主重启时频繁换域名。**有配置就展示二维码**混淆了配置有效与真实可达。

**动态通配信任或手机地址发现服务**扩大安全与产品范围。采用明确域名的受控切换复用部署职责，代价是真正轮换地址时会重启宿主。

## 影响

电脑侧检查不能保证手机网络同样可达。Quick Tunnel 仍是临时基础设施，管理程序提供有界恢复而非可用性保证。日志和状态只有公开域名与生命周期信息，不包含登录链接。测试覆盖匿名探测、二维码收起、地址精确替换、守护切换路径、候选进程所有权、部署失败清理、本地故障及重试退避。launchd 服务使已部署的电脑管理进程跨宿主重启保持运行。
