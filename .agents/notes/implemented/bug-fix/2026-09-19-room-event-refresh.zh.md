# Agent Note: 通过会话日志事件窗口刷新 Room

Status: implemented

## 问题

Room 会话已经显示协调者的新回复，目标面板和任务计数却停在旧状态。关闭第二个测试页面仍未恢复。检查当前宿主后确认：普通日志追加会更新公开的事件窗口，只有概要字段变化才通知会话概要。Room 订阅概要并假设所有日志都会触发通知；测试替身错误地把两种接口合成了一个 store。

## 决策

Room 监听 `SessionBinding.eventSource` 作为刷新信号，重新读取自己的 Remote 状态，不折叠或接管宿主事件窗口。事件源不可用时才回退到原概要订阅。测试台将静止的概要与独立变化的日志通知分开，覆盖真实宿主合同。

## 考虑过的替代方案

**持续轮询所有空闲 Room。** 不采用，因为公开日志已有变化信号，持续轮询增加不必要请求。

**把所有面板过期都归为连接池饥饿。** 单页面复现和源码检查否定了这一判断。共享成员订阅解决的是另一个已观察到的连接限制，不能修复订阅源错误。

## 影响

即便会话概要字段不变，宿主侧的计划更新、运行结束和任务进度也会触发刷新。现有防抖、运行中轮询和输入框选择机制保持不变。回归在概要静止的条件下分别覆盖日志触发刷新、Room 激活、延迟绑定和释放订阅。
