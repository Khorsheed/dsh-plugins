# Agent Note: 按原生模型归属 Kimi 消息

Status: implemented

## Problem

隔离模型控制验收中，Kimi 从成员的 K3 选择切到 harness 默认值，再切回。原生请求和用量记录确认了两种模型，但镜像的每条 assistant 消息仍标为 `k3`，因为消息工厂写死了该值。控制状态正确，聊天记录却与之矛盾。

## Decision

解析 wire 时，根据原生请求和用量记录为每一行内容保存当时已知的模型。新提示词或没有模型元数据的请求会清空逐行假设。回放混合模型的历史时逐条归属，不把整个记录里最后出现的模型套给此前所有消息。实时快照使用原生会话已确认的模型，以当前轮实测模型兜底。两者都不能确定时，消息工厂使用 `unobserved`。轮次观测也检查原生模型记录所属的轮次，避免后续未命名轮次继承较早的观测结果。

## Alternatives considered

**使用创建时的模型。** 不采用，同一成员续聊过程中可能多次换模。

**给整份记录应用最后实测模型。** 不采用，冷回放会悄悄篡改较早轮次的模型归属。

**保留友好的 K3 兜底名称。** 不采用，未知观测不能声称使用了某一具体模型。

## Consequences

新消息可以正确归属默认、继承和显式选择的模型；不重写既有持久化消息。修改仅涉及消息元数据，不改变凭据、模型选择、用量总数或冻结评测条件摘要。回归覆盖两个不同的原生模型记录，以及随后没有模型元数据的一轮，并运行既有流式和聊天记录测试。
