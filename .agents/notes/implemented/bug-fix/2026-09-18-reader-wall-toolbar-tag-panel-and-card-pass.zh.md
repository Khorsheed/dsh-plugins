# Agent Note: reader 墙的工具条、标签弹层与卡片 —— 首轮交接留下的四个缺陷一次 UI 过修

Status: implemented

## Problem

验收实例（3080，2026-09-18）上，用户对着正在跑的阅读器报了墙上的四个缺陷：

1. **筛选弹层一出来就盖住排序按钮。** 两个弹层都是相对**pane**的 `position: absolute; top: 62px; right: 10px`，而 62px 比工具条那一行本身还矮（43px 表头 + 40px 工具行），所以弹层直接画在工具条下半截上 —— 也就是排序按钮所在的那一端。这一行的顺序又加剧了它：筛选按钮在搜索框**左**边、排序在右，两个工具被摆在唯一可伸缩项的左右两端。
2. **卡片标签弹层是这一面里最难看的地方。** 它只是裸的一摞 `filterRow`，词表靠原生 `<datalist>`。那个弹层由浏览器自己画：跟不了 pane 的表面，标不出哪些标签已经在条目上，也表达不了词表里还没有的那个动作 —— 把你刚敲的名字建出来。
3. **卡片不像卡片。** 卡片是 pane 自身背景上的透明行，两列网格里相邻条目糊在一起；feed 自带分类与读者自建标签两种药丸尺寸不一，标签行会抖；那一行不能折行，会长出卡片边缘；而卡片是 `role="button" tabIndex={0}` 却完全没有 `:focus-visible` 环 —— 键盘能走，键盘看不见。
4. **正文比它夹在中间的列表短一截。** 段落被 `max-width: min(100%, 46em)`（中文）/ `min(100%, 72ch)`（拉丁）限宽，而 `ul`/`ol` 铺满整列，正文右缘因此参差 —— 用户把那条空白带读成了布局 bug，要求正文像列表一样跟随侧栏。

## Decision

**工具条字段在前，两个图标工具各自装在自己不可收缩的盒子里排在它右侧，每个弹层都锚在打开它的那个按钮上。** DOM 顺序即视觉顺序 —— 搜索框、筛选、排序 —— 键盘顺序因此和读者看到的一致。`.search` 是 `flex: 1 1 0` 加 `min-width: 44px` 下限：宽度来自行内剩余空间、绝不来自自身内容，所以再长的 placeholder 或 `#源id` 查询也推不走工具，同时字段自己也不会被压成一条缝。每个工具外面是 `.toolWrap { position: relative; flex: none }`，它让按钮成为弹层的定位上下文：弹层是 `top: calc(100% + 4px); right: 0`，于是弹层**按构造**开在自己按钮下面，而不是靠一个必须跟着工具条 padding 走的数字。三个弹层（筛选、排序、标签）也不再各说各话 —— 一个圆角、一条描边、一个表面（`--dsw-alias-bg-layer-2`）、一个阴影。

**词表是一个共享组件，不是 `datalist`。** `TagSuggestions` 每个标签渲染一行（固定的勾选列，让每个名字从同一条边起排；`data-on` 表示已应用），并在草稿没有精确命中时多出一行「新建这个名字」。卡片弹层现在是 表头（标题 + 回车提示）/ 可滚动清单 / 输入字段 三段；详情页的行内编辑器在自身文档流里渲染同一批行 —— 放在可滚动正文里的浮层会被裁掉。两个输入框都改成弹层自己的表面、不再套硬描边的药丸，强调色移到字段的 `:focus-within` 描边上。Esc 关闭弹层并忘掉半截草稿（重开是干净的）；弹层的落点改由 pane 计算 —— 视口放得下就开在卡片下方、放不下就开在上方，左右两边界都夹住 —— 不再是 `card.bottom + 4` 指到短侧栏屏幕外。

**筛选弹层是一个两级选择器，而且它的高度是视口规则。** 根页只有「阅读状态」一行，以及每个**可能无限增长**的清单各一行的钻取行：`按来源` 这一行自己带着**当前值**，点进去是来源页 —— 那一页独占弹层高度、自己的滚动、以及自己的搜索框（清单超过 6 条时才出现）。选中一个来源照旧关闭弹层并把查询写进搜索框，返回按钮只回根页、不关闭。这是对「订阅会一直变多」的正面回答：不管有多少个 feed，弹层第一页永远是固定几行，唯一无限的清单是唯一滚动的东西。弹层的 `max-height` 是 `min(62vh, 440px)` —— 视口单位，绝不写百分比：它的包含块是那个 26px 的 `.toolWrap`（锚在自己按钮下面正是靠它），而锚点一改，旧的 `60%` 就悄悄解析成 ~16px、发出去了一个带滚动条的一行细条（这是同一批改动被验收实例第二次报回来的问题）。百分比描述的是包含块，而这里的包含块是一个按钮，不是 pane。

**卡片是一个表面，已读状态在不隐藏任何东西的前提下可读。** 填充用宿主自己的卡片值（浅色 `--dsw-static-neutral-50` / 深色 `850`，经由一个组件变量加 `:global(body[data-ds-dark-theme])` 覆盖），描边静息 `--dsw-alias-border-l1`、悬停 `l2`，配 120ms 背景/描边过渡；圆角 12，网格列最小宽度降到 264px、间距 8px，窄侧栏仍能舒服地放下一列。未读条目把标题上墨（`data-unread` → `--dsw-alias-label-primary`、字重 650），叠在原有的 7px 瓷砖圆点之上；已读条目留在原位、只是安静一档。两种药丸共用一套尺寸（高 18px、圆角 999px、字号 10.5px），而且那一行可以折行，长标签表再也不会溢出卡片。卡片补上了宿主列表行的 `:focus-visible` 环（`--dsw-alias-brand-primary`）。随这次过修一起删掉的死 CSS：`.cardMenuButton`、`.segmented`、`.segment`、`.segmentOn` —— 悬浮卡片按钮与今日/全部分段控件都是更早的版本就退休了，只留下样式。

**正文不再有阅读量度：侧栏本身就是量度。** 段落上那两条 `max-width` 直接删掉（用户在「统一量度」与「跟随侧栏」之间选了后者），于是正文和列表共用同一条右缘，正文铺满读者给这个 pane 的宽度。`packages/dsh-reader/tests/host-pure.spec.ts` 锁住「不存在」这件事，将来若要把量度加回来，必须加在**每个块**上而不是只加在 `p` 上。

## Testing

渲染套件多了 9 个用例、CSS 不变量套件多了 2 个：`ReaderPane.client.spec.tsx` 断言工具条的 DOM 顺序、以及筛选弹层的父节点就是筛选工具自己的 wrapper（这正是旧魔法数字搞错的那个结构事实）；断言筛选弹层的根页只有阅读状态行与钻取行、而来源页才带搜索框 / 收窄后的清单 / 无匹配文案 / 以及只回根页不关闭面板的返回按钮；断言卡片弹层会列出词表 / 切换 / 提供新建输入的名字 / 说明空词表为何为空 / Esc 忘掉草稿；并断言未读卡片带 `data-unread` 而打开条目后消失。`host-pure.spec.ts` —— 它本来就在钉这一行的 flex 约束（曾经有个搜索框把控件挤出去）—— 现在钉新的那一组（`flex: 1 1 0`、`min-width` 下限、`.toolWrap` 的 `position: relative` 与 `flex: none`、两个弹层的 `top: calc(100% + 4px)`、筛选弹层的视口 `max-height` 且不许再出现百分比）、钉正文没有量度、并钉标签弹层的 CSS 盒子与 pane 计算落点用的常量保持一致。

`pnpm --filter @khorsheed/dsh-reader test`：8 个文件、133 个用例全绿。产物已重建（tsc + tsdown），新 CSS 与组件已在 `lib/client.js` 中核对存在。

## Alternatives considered

**只修弹层的魔法 `top`，不加 wrapper。** 否决：`top: 62px` 之所以坏，正是因为它是一个手工维护的、描述**另一个元素高度**的数字。修好的常量必须永远跟着表头 padding、工具行 padding 和两个图标走，任何一处变了都会无声失效。让按钮成为定位上下文，是消掉这一类 bug，而不是消掉当前那一次。

**保留筛选按钮在搜索框左边，只挪弹层。** 否决：用户的报告说的就是两个工具被挤，并明确要求按钮统一放到搜索框右边。一边一个还会让唯一可伸缩项的两侧各挂一个不同宽度的控件 —— 这正是上一次搜索框事故的配方。

**把弹层做成一整条 pane 宽、挂在工具条下方的面板。** 否决：筛选弹层是一列名字 —— 整条面板会盖住它正在收窄的那面墙，标签弹层会盖住它所属的那张卡。两个弹层按设计就是 200–236px 宽的竖向列表。

**来源保持平铺，只给它加一个搜索框。** 否决：那样弹层高度又变成订阅数量的函数，阅读状态与标签这些控件会随着 feed 增多被越推越下 —— 正是级联要限制的那种增长。钻取行让弹层第一页恒定是几行。

**把来源清单挪成 pane 自己的一个页面（视图切换）。** 否决：筛选是一次瞬时收窄，不是一个目的地。读者正在挑选时把墙换成选择页，等于把被筛的东西藏起来。

**给平铺清单加「固定 N 行 + 还有 42 个…」。** 否决：它把读者可能正在找的名字藏起来，且没有抵达它们的路径；搜索框加滚动能抵达每一个名字、又不必截断清单。

**保留 `max-height: 60%`，让弹层重新拥有 pane 级定位上下文。** 否决：把弹层锚在自己按钮下面正是它不会盖住另一个工具的原因，所以包含块不能退回 pane。视口单位描述的才是弹层真正拥有的空间，而且现在有测试禁止这里出现百分比。

**保留原生 `datalist`，只重做弹层外壳。** 否决：那个弹层在 Chrome 和 Safari 里都是浏览器自己画的 —— 接不了 pane 的表面、标不出已应用的标签、在 Chrome 里还会在深色 pane 中渲染成浅色系统列表。它也表达不了「新建这个名字」，而那是空词表的读者最先需要的动作。

**标签弹层改用模态对话框。** 否决：打标签是一张卡上的小、可重复、多标签的动作。模态会拦住每一次打标签时的墙，它的遮罩也会和弹层自己的「点外部关闭」习惯打架。

**反过来把列表也限制到段落的量度来消掉参差。** 被用户直接否决：在侧栏里，pane 自身的宽度本来就是舒服的量度；把每个块都限宽会留下同样一条空白带、只是边缘齐了；想要更短的行时读者可以自己把 pane 收窄。这个方向仍是一行改动，所以这里用测试钉住「不存在」，而不是任其漂移。

**卡片填充用 `--dsw-alias-bg-layer-1`。** 否决：浅色下所有 alias 层都解析成与侧栏相同的白，卡片会得到一个谁也看不见的填充。宿主自己的卡片组件用的是静态中性色（`--deliverable-fill`）配深色覆盖，这里跟随它。

## Consequences

- 卡片填充是本 pane 第一次使用静态中性色加一段 `:global(body[data-ds-dark-theme])`。这是对「只用 alias token」的一次刻意例外，取自宿主自己的卡片组件：沉默的替代方案是一个只在深色模式存在的填充。
- 标签弹层的盒子被描述了两遍 —— pane 里的 `TAG_PANEL_WIDTH` / `TAG_PANEL_MAX_HEIGHT`（算落点用）与 module 里的 `width` / `max-height`（限盒子用）。有测试钉住这一对；没有它，两者会漂移并把弹层重新开到屏幕外。
- 弹层的上/下方向来自对高度的**估算**（84px 外壳加每个标签一行）。因此在短侧栏底部向上开时，卡片上方的空隙可能比弹层实际所需略大；替代方案是 layout effect 量一次真实高度、每次打开多渲染一轮。
- 去掉量度意味着读者若刻意把 pane 拉得很宽，就会得到很长的行。这是用户的明确选择，而且只需改一处即可回退。
- 去掉量度也删掉了两种文字排版差异唯一在「宽度」上的表达；中文/拉丁之分现在只管行高与字距。
- 墙的工具条在任何宽度下都保持三个控件在同一行，弹层也不可能再盖住任何一个工具 —— 触发这次过修的那个缺陷，除非删掉 `.toolWrap`，否则无法复现。
- 按来源收窄现在多花一次点击（钻取行 → 清单），换回来的是永不变大的第一页；标签留在根页，因为词表通常很短。若标签也长到那种程度，同一套钻取行直接适用。
- 来源页的搜索框在 6 条（`SOURCE_SEARCH_MIN`）时出现：低于这个数，一个只过滤三行的输入框是噪音；高于这个数，它是唯一不必滚动就能抵达某个名字的方式。阈值写成常量，是为了让这个判断只被写下一次。
- 把弹层移到自己的按钮下面，静默改变了它内部百分比的解析基准。这条教训写进了 CSS 注释并被测试钉住：在这个 pane 里，弹层的尺寸只用量度单位（vh）或像素，绝不用 `%`。
