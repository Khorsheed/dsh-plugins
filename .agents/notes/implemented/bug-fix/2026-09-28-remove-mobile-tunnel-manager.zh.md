# Agent Note: 移除移动隧道自动部署

Status: implemented

## 问题

电脑端隧道管理器把公网不可达当成了部署及重启 3080 的授权。反复故障、域名轮换和昂贵的隔离预检造成了干扰。用户需要的是电脑端入口可用后，由手机手动重新扫码。

## 决策

删除 scripts/mobile-tunnel.mts、其生命周期测试和 mobile:tunnel 包命令。卸载并禁用已安装的 com.dsh.mobile-tunnel 服务，删除 plist，停止遗留进程。保留诊断日志。不安装替代的健康检查守护进程或重启触发器。

保留[公网入口改进](2026-09-27-mobile-public-entry-recovery.md)中的匿名可达性检查与失效二维码收起。保留 deploy:3080 --mobile-origin，仅供部署者明确手动执行，继续沿用构建、测试、地址校验、预检和 canary。用户另行授权了移除后的一次手动恢复；后续故障不构成再次重启的授权。普通隧道转发与自动部署分离。

## 考虑过的方案

延长重试间隔或改进故障分类，仍允许网络状况触发无人值守的宿主重启，不满足用户要求。删除二维码检查会重新展示不可达地址的二维码。默认禁用但保留自动恢复，仍留下误启入口，因此直接移除实现。

## 影响

公网隧道失效需要部署者处理。电脑端入口恢复后用户重新扫码，手机不会自动发现新域名。停止旧管理器也可能停止其持有的隧道，因此必须分别报告本地 3080 与公网入口的可用性。未来重新引入自动化需要新的明确产品决策，不能默认为已获准重启宿主。

验证启动项与管理器进程已消失，移除期间本地 3080 保持可用，且不再存在可执行的管理器或包命令。现有二维码、连接和手动轮换测试仍有效；已删除的管理器测试不再代表受支持行为。
