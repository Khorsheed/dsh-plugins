# Agent Note: 所有画布都能成为会话绑定的作品

Status: implemented

## Problem

会话头提供的是「绑定作品」，但菜单和存储层都只接受带创作体裁的画布。普通画布本来就能承载卡片和成稿，却会从这个菜单消失，其会话目标也只保存在进程内存里。Agent 新建的体裁画布会自动绑定，侧栏新建的画布却只获得临时 focus。清除体裁还会一并丢弃本来有效的会话目标。

## Decision

- 所有未归档画布都可绑定。体裁选择仍是独立的能力授予：体裁自己的工具继续检查绑定画布的体裁，不会把每块绑定画布都当成小说。
- `canvas_open` 在新建或切换普通、体裁画布时都会绑定，并照旧记录 focus。侧栏新建表单也通过同一个 Remote 显式绑定后再打开。绑定失败会如实提示，但不会把已经创建成功说成失败。
- 清除体裁不再解除会话绑定；删除画布仍会清理指向它的全部绑定。未绑定会话保留原有的侧栏 focus 回退。
- 绑定入口可以通过画布 agent 行或已安装体裁的 agent 行出现，不再要求必须存在体裁。

## Alternatives considered

- **保留仅限体裁的绑定，只在 UI 里解释。** 否决：普通画布同样支持卡片和成稿，这个限制与用户理解的「作品」相矛盾，并不对应真实的能力边界。
- **在 `createCanvas` 内部统一自动绑定。** 否决：Room 工具有意区分提供工作区围栏的成员和需要切换目标的协调会话，创建调用方必须拥有绑定决定权；两条面向用户的创建路径现在分别显式绑定。
- **完全取消 focus。** 否决：未绑定会话浏览画布时它仍是有用的回退；显式绑定则负责跨重启保留目标。

## Consequences

- 现有 `bindings.json` 无需迁移。普通画布沿用同一个 session → canvas 映射，用户或 Agent 再次选择作品后即生效。
- 体裁变化仍发出原有事件，小说工具会在适当时撤销授权，同时保留会话的普通画布目标。
- 画布包构建和全部 37 个测试文件通过，覆盖普通画布绑定与重启、清除体裁、两条创建路径和 chip 过滤。
