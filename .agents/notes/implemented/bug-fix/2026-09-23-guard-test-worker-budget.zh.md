# Agent Note: 守护测试分片遵守仓库并发预算

Status: implemented

## Problem

移动二维码验收期间，进程密集的守护测试分片在繁忙的开发机上反复超过已有期限。仓库的并发配置影响 Vitest，但守护脚本始终同时启动四个独立分片。

## Decision

调度 lane 任务时读取已有 DSH_TEST_MAX_WORKERS 设置。正整数可降低并发，上限仍是原 lane 上限；无效值保留默认值。所有任务、通过数量要求、断言和超时设置均保留。

## Alternatives considered

跳过无关测试或增加期限会削弱验证。停止其他用户的应用超出任务范围。调度预算可以减少争用，避免这两种做法。

## Consequences

繁忙机器可以串行执行全部分片。默认值和生产运行行为不变。资源充足时低并发耗时更长，也不能保证任意外部负载下都成功。

## Testing

调度回归覆盖降低预算、上限和无效值。使用 DSH_TEST_MAX_WORKERS=1 的完整守护测试集 212 项全部通过，保留全部分片的数量校验；包构建也通过。
