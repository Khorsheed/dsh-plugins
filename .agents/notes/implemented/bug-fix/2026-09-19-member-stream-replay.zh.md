# Agent Note: 成员流式回放与 Room 输出

Status: implemented

## Problem

浏览器中 Kimi 的实时回答完整，但成员落盘日志停在首个 `local-agent/stream` 检查点。真实存储后端在下一次读取时拒绝未注册的事件类型，使后续增量同步无法继续。模拟存储测试没有覆盖宿主的事件目录校验。Room 也只在最终回答前显示运行状态行，DSH 流式输出则将推理和正文合并在同一个条目中。

## Decision

Core 在安装包和源码两种宿主目录中注册 `local-agent/stream`，沿用 Room 的兼容接口。Core 与 Room 启动时都通过当前 loader 解析自己的事件目录：开发软链包可能只注册了自己的 npm peer，而运行中的存储后端使用另一份宿主检出。注册保留到进程退出，保证已写日志仍然可读。真实 JSONL 和 Zstandard 集成测试先读取初始检查点，再追加并回放剩余轮次。

共享流式发布器支持同一步内独立的原生内容条目，以及持久化的明确关闭检查点。DSH 分别保留推理和正文。四个 live provider 将尚未刷出的最早增量到达时间传入共享输出通道，而不是用发布时间代替。相同快照不会伪造新的到达时间。

Room 运行状态行使用可选的 core 输出渲染器及其共享成员订阅。轮次起始时间排除上一轮保留的内容。导航和定向停止与 Markdown 输出分开。运行节点移除后释放订阅，成员原生历史仍是最终记录的权威来源。

实时渲染器为每个挂载中的内容条目保留最多 256 条本地绘制延迟样本。页面可见时经过两次动画帧后采样，新更新不会取消旧回调以免丢弃慢绘制样本，卸载时取消剩余回调。这是本机验收使用的同钟保守诊断，不代表远程宿主时钟同步或延迟保证。

Kimi 在 ACP 会话加载和配置完成后才绑定新轮次的输出处理器。`session/load` 发出的历史片段不能变成新回答或流式检查点。原生会话仍保留加载后的原始上下文。

Room 客户端在首次成功读取将未知状态变为 Room 时重新选择输入栏，与原地升级为 Room 时一致。传输失败保留未知状态，后续实时通知可以重试。冷页面加载后无需切换标签页才能启用协调者输入栏。

## Alternatives considered

**将 Room 最终回答视为持久化证明。** 真实 Kimi 验收否定了这个做法：回答存在于内存中，而落盘记录不完整。

**只在成员会话里渲染。** 这迫使用户离开默认协调者对话才能看到生成进度。

**追加事件时标记为可忽略。** 检查过的宿主公开 `Session.append` 不接受该信封选项。注册事件类型使用既有插件接口，无需修改宿主。

**生成后删除重复回答前缀。** 不采用：相同文字可能是合法的新输出。排除历史加载阶段可以保留原生内容边界，无需文字启发式判断。

## Consequences

回归测试覆盖真实存储读取，并在回放时区分原生子条目。浏览器延迟仍需实测验收；时间戳修正和 50 ms 通道节流本身不能证明 P95 ≤ 200 ms。实验室中因缺失注册而截断的旧记录，需要在重启前从确认完整的内存快照或原生记录恢复；注册无法重建从未落盘的事件。

新增测试覆盖 ACP 历史重放排除、冷加载输入栏选择和传输失败后的重试。Kimi 与 Room 测试分别通过 244 和 272 项；真实冷启动和运行中配置控制仍单独验收。
