# Agent Note: 成员流式回放与 Room 输出

Status: implemented

## Problem

浏览器中 Kimi 的实时回答完整，但成员落盘日志停在首个 `local-agent/stream` 检查点。真实存储后端在下一次读取时拒绝未注册的事件类型，使后续增量同步无法继续。模拟存储测试没有覆盖宿主的事件目录校验。Room 也只在最终回答前显示运行状态行，DSH 流式输出则将推理和正文合并在同一个条目中。

## Decision

Core 在安装包和源码两种宿主目录中注册 `local-agent/stream`，沿用 Room 的兼容接口。Core 与 Room 启动时都通过当前 loader 解析自己的事件目录：开发软链包可能只注册了自己的 npm peer，而运行中的存储后端使用另一份宿主检出。注册保留到进程退出，保证已写日志仍然可读。真实 JSONL 和 Zstandard 集成测试先读取初始检查点，再追加并回放剩余轮次。

共享流式发布器支持同一步内独立的原生内容条目，以及持久化的明确关闭检查点。DSH 分别保留推理和正文。四个 live provider 将尚未刷出的最早增量到达时间传入共享输出通道，而不是用发布时间代替。相同快照不会伪造新的到达时间。

Room 运行状态行使用可选的 core 输出渲染器及其共享成员订阅。轮次起始时间排除上一轮保留的内容。导航和定向停止与 Markdown 输出分开。运行节点移除后释放订阅，成员原生历史仍是最终记录的权威来源。

实时渲染器在页面可见时经过两次动画帧后采样，新更新不会取消旧回调，以免丢弃慢绘制样本。共享浏览器输出服务保留不含正文的诊断记录，最多 32 个成员轮次、每轮 4,096 个版本，临时节点卸载后仍可读取。首次连接和重连的基线与实时更新分开统计；Room 和成员页面分别报告样本、最近秩 P95，以及待绘制、后台、卸载、时钟不匹配和未渲染数量。截断和轮次淘汰会明确计数。已有成员配置控件内的隐藏只读 DOM 探针最多每 250 ms 导出一次保留的报告，不改变产品流程。每节点 256 个样本的属性仅作为便捷读数。这些是浏览器已收到更新的同钟保守诊断，不代表远程时钟同步、传输合并前每个原生 token 的覆盖或延迟保证。

Kimi 在 ACP 会话加载和配置完成后才绑定新轮次的输出处理器。`session/load` 发出的历史片段不能变成新回答或流式检查点。原生会话仍保留加载后的原始上下文。

Room 客户端在首次成功读取将未知状态变为 Room 时重新选择输入栏，与原地升级为 Room 时一致。传输失败保留未知状态，后续实时通知可以重试。冷页面加载后无需切换标签页才能启用协调者输入栏。

四个 live provider 均在轮次结束事件和关闭检查点之后追加并等待最后一次成员存储同步，完成后才返回结果。真实 Kimi 轮次此前只保存 88 条中的 87 条事件，即使正常关闭后仍缺少 `turn/end`。流式期间的持久化失败会记录日志但不会阻断后续队列，最后一次同步可以重试缺失的后缀。这保留了既有的尽力持久化错误合同，避免在存储不可用时误报为原生生成失败。

Room 在取消或失败后把非空输出保留在发言日志里，并附带可选的 `interrupted` 状态。冷回放显示部分正文、明确状态、耗时和成员会话入口。部分回答不会触发末尾通知指令。原生结果返回时保留此前人工取消的终态，同时把部分输出保留给关联成果回报。

冷子会话恢复使用完整宿主生命周期：先 enter，再 announce；若发布失败，则 detach 并释放写句柄。创建事件让已打开的官方历史订阅收到仅由构造器追加的 `session/end-seed`。只有 enter 会持久化该标记，却使实时历史缺失一个序号：执行和 token 投影继续增长，聊天记录订阅则失败。回归测试使用真实宿主历史控制器跨越冷恢复及后续轮次，另一个测试验证发布失败后的回滚与重试。

## Alternatives considered

**将 Room 最终回答视为持久化证明。** 真实 Kimi 验收否定了这个做法：回答存在于内存中，而落盘记录不完整。

**只在成员会话里渲染。** 这迫使用户离开默认协调者对话才能看到生成进度。

**追加事件时标记为可忽略。** 检查过的宿主公开 `Session.append` 不接受该信封选项。注册事件类型使用既有插件接口，无需修改宿主。

**生成后删除重复回答前缀。** 不采用：相同文字可能是合法的新输出。排除历史加载阶段可以保留原生内容边界，无需文字启发式判断。

**将最后一个挂载节点的样本尾部当作延迟数据集。** 未采用：轮次结束会丢失数据，有界尾部会隐藏较早的慢样本，重放快照又测量了历史年龄。按轮次保留记录可以暴露缺失观测，而不是把它们算作成功。

## Consequences

回归测试覆盖真实存储读取，并在回放时区分原生子条目。浏览器延迟仍需实测验收；时间戳修正和 50 ms 通道节流本身不能证明 P95 ≤ 200 ms。实验室中因缺失注册而截断的旧记录，需要在重启前从确认完整的内存快照或原生记录恢复；注册无法重建从未落盘的事件。

新增测试覆盖 ACP 历史重放排除、冷加载输入栏选择和传输失败后的重试。Kimi 与 Room 测试分别通过 244 和 272 项；真实冷启动和运行中配置控制仍单独验收。

每个 live provider 都有异步存储回归，确认结果返回时持久化记录已经完整且以 `turn/end` 结尾。Provider 测试通过：DSH 187、Codex 224、Claude 232、Kimi 245 项。写入失败仍仅提供诊断；模型回答成功不保证存储始终可用。

Room 测试覆盖取消和失败时保留部分输出、不执行未完成的通知指令，以及冷回放部分回答的状态和成员入口。没有输出的取消仍不显示空白回答。Room 测试通过 275 项。

诊断回归覆盖重放排除、独立界面、慢回调、未渲染更新、未完成绘制、时钟不匹配、有界保留和结束后的 DOM 报告。四家完整前台延迟验收仍需单独完成；不完整或截断的报告不能证明达标。
