# Agent Note：一层给一条判据算分，不是给一格算分

Status: implemented

[English](2026-09-18-eval-report-per-criterion-merge.md) | 中文

## 问题

报告按**格**取一个判定层算分：`primaryPass` 沿 `human-final` > `llm-draft` > `script` 走，取第一个对这格有任何判定的层，整格只按它算。凡是只被更低层判过的判据，全部出局。

这条规则的代价在支付的当下看不见。I5·T37 实测：判官在一格上打了 4 条判据，人在判官台改判了其中 1 条，这格得分从 4 掉到 1。另外 3 条没有在任何地方以「被排除」的身份出现过——没有计数、没有附注、`results.jsonl` 里也没有一行说它。判官台是知道的（按钮前那段提示点名了 `draftOnlyCriteria`），这也是唯一有人发现它的原因；报告自己一个字没说。

有两件事让它比「一条可争论的约定」更糟：

- **触发它的动作正是流程想要的那个。** `human-final` 是人唯一能写的层，R1 又规定终评是人的动作。劝阻一条局部的人工判定，等于劝阻判官台存在的理由。
- **rubric 里 `kind: human` 的叶子通常就一条。** rubric 是按「该由谁判」拆判据的——`objective` 归探针、`llm-draft` 归判官、`human` 归人。于是判官台上那条**被设计出来**的路径，恰恰就是让判官的活计消失的那条。

## 决定

**每条判据各自取判过它的最权威那一层**（`human-final` > `llm-draft` > `script`）。人改过的判据用人的，没改的仍用判官的，判官没判过的用脚本的。于是一格的得分来源可以混合——而报告必须在每个出现这个数字的地方**标出来**。

- `primaryPass` 改成返回**逐判据**的层（`ns: Map<判据, ns>`），外加 `sources`：这格的「层 → 判据数」分布，按权威顺序排，使 JSON 稳定。它另外留下 `samples`（得分实际取自的那些判定）与 `superseded`（合并时被跳过的更低层判定）——「人改判了」这句话，只有挨着它替换掉的那条判定才读得懂。
- 两处调用点——格分与缺陷清单——都改成从判据取层。`scoreOf` 一个字没动：它本来就是在 `credit` 上求和，而 `credit` 现在是合并后的那张表。
- `report/results.jsonl` 每一行都带自己的 `ns`（原有）与该格的 `sources`（新增），逐行重复，与 `toolCalls` 的做法完全一致。
- 判官台按钮前那句话随规则一起改，从「会让你其余的判据出局」改成「只覆盖你答的那几条，其余仍按判官的算」。`draftOnlyCriteria` 这个字段留着：这件事仍然欠人一句交代，只是它不再是代价。
- 一致性数字：多采样 κ 不动（它本来就只看判官层）。`llm-draft` 对 `human-final` 本来就是按判据算的，现在**把这件事说出来**——那句话写明分母只含两者都判过的判据，并点出有多少条人评判据判官从没判过。

**同一份改动里还有第二个投影**，因为合并让一个页面答不上来的问题变得可以问了。用户看完结果页的原话是：「看不出来每个维度的得分对比和评委的评判依据。」这些事实一直都在 bundle 里，只是一条都没过线。于是现在每题一张**判据 × 对比组**表：行是判据（id、维度取 rubric 的 `axis`、权重、极性），列是对比组，格里是该判据在该组的结论——格下小字是这格的**得分来源**，也就是合并之后这条判据取到了哪一层。**点开一格**是逐条判定的原文：证据（默认折成一行）、判官条件名与模型（报告页是揭盲的地方）、多样本逐条列出，被改判掉的那条原判留在替换它的那条下面。

三条性质把它钉在报告的其余部分上：

- **同一道闸。** 四条不变量没全成立时 `criteriaTables` 是空的，与 `comparisons` 一模一样。一次被拒的比较，不能靠一条条判据重新打开。
- **同一份计算。** 底行是 `scoreOf` 自己的数，不是本表的列和，所以判据表与配对表不可能对同一题给出两个数。
- **它不是比较。** 单对比组的 run 也给这张表（一列）：判官给了什么依据，不取决于有没有第二列可比。

**没有判据标题**，这不是遗漏。派生权重表是从 grading 层生成的，它**刻意**只带 id、权重、极性、kind 与 axis——不带判据正文，那是该层自己的内容，也正是自动导出把那一层留在外面的原因。`axis` 是诚实的那个标签，而它恰好就是这条题问的那个**维度**。

## 后果

- **历史报告重算后数字会变。** 对一份带局部人工判定的 bundle 重跑 `dsh-eval report`，它的得分会涨。旧 bundle **不迁移**，已经写下的数字也不就地改写；重新导出才是把一个 run 换到新口径上的动作，README 里写明了这一点。
- 在一份真实且过闸的 bundle 上重建 T37 的形状做了前后对照（`run-20260918054718-8o0o`：判官判 B2/D1–D4、脚本判 X-no-patch，另加一条人对 D1 的判定）：本题得分 **0 → 3**，该格来源读作 `人 1 / 判官 4 / 脚本 1`。
- 两份带人工判定的真实 bundle 重算后逐字节一致，只多了新增的 `sources` 字段与那句分母说明——这两份里人答的都是判官判据的超集，正是旧规则本来就处理正确的情形。
- schema 一个字没动。`dataseek.verdict/1` 仍是一条判据、一个布尔、一段证据；判定本身什么都没变，变的只是报告读哪些判定。

## Alternatives considered（备选方案）

- **保留按格取的规则，把提示写得更狠。** 判官台本来就是这么做的，T37 就是它买到的东西：提示被读了，人照样只答了一条（而那正是 rubric 要求他答的那条），三条判过的判据从得分里消失了。一条需要在唯一入口前面立一块警示牌的规则，就是在那个入口上错了。
- **保留按格取的规则，但要求人整格重打。** 诚实，但按成本否掉：为了改一条判据而把整格重判一遍，会让人躲着判官台走，而他要重打的那些判据恰恰是 rubric 指派给探针的 `objective` 那些。它对「人工判定写在规则变更之前」的那些格子也无济于事。
- **按判据合并，但仍让一格对外声明一个来源**（比如按判据多数）。渲染起来更省事，也是一句话里的假话：三条按判官、一条按人的格子不是「判官的格子」，把它印成一个词，正是旧规则的隐身术从标签上绕回来的路。
- **判据表的底行按本表列和算。** 那是读者会用手验的数，而且它在逐判据均值上是线性的——直到某个 rep 缺了某条判据，两个分母就分家了。取 `scoreOf` 的数能让两张表背后只有一份计算；每列的 rep 数照样印出来，于是参差的矩阵是看得见的，而不是被静默平均掉。
- **只要 bundle 有判定就出判据表，不管闸。** 否掉：判据级的表一旦有两列**就是**比较，而四条不变量存在的意义就是说明什么时候比较没有意义。真正不算比较的是单对比组那一支，也正是它不过闸就出。
- **证据按平铺清单给，不做可展开的表**（`summary.md` 给负向判据就是这么做的）。页面上否掉：要问的是「哪个维度动了」，而一串判定读不成一张网格。`summary.md` 两样都留——网格，加上折在 `<details>` 里的证据原文。
