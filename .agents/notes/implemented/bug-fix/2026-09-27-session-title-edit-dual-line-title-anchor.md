# Agent Note: Dual-line title anchor for session-title-edit's in-place editor

Status: implemented

[English](2026-09-27-session-title-edit-dual-line-title-anchor.md) | [中文](2026-09-27-session-title-edit-dual-line-title-anchor.zh.md)

## Problem

The plugin edits the current session's title in place: it hides the official title node and overlays its own input on that node's measured rect, because the official header exposes no title seat. Up to host 0.1.6 the current breadcrumb was a disabled `<button>`, so the probe was `header nav button:disabled`. Host 0.1.7-alpha.1 (upstream `92101e1a5b`, "render the current crumb as text so the title joins the drag band") turned that crumb into plain text — on darwin the global no-drag rule subtracted the disabled button from the window drag band, leaving the title a dead zone that neither dragged the window nor could be selected. On that line the probe matched nothing, so clicking the pencil silently degraded to the row editor in the header actions row and the official title stayed visible (reported on a 0.1.7 web-eval instance, 2026-09-27). Renaming itself never broke — it rides the official `session.rename` RPC — but the feature's whole point ("the title itself becomes the input") was gone on the line users are moving to, while the 0.1.5 line kept working. The unit suite stayed green because its "official header" was a hand-written fixture that hard-coded the disabled-button markup, so the DOM move was invisible to it.

## Decision

One locator serves both lines. The current title is the leaf inside the crumbs nav's LAST crumb segment whose text equals the session's own `displayTitle`: the crumb renders `summary.displayTitle` from the same store the entry reads, so the comparison is exact on both DOMs, and a leaf match is preferred over the segment wrapper (which also holds the `/` separator and any lineage-slot content). Ancestor crumbs live in earlier segments and are never touched. The legacy shape survives as an explicit fallback arm scoped to that same segment (`button:disabled`) — which is what keeps 0.1.5/0.1.6 working when the store has not projected a title yet, and is deliberately *not* a global `document.querySelector` any more. The hide rule became element-agnostic (`header nav [data-ste-inplace]`, previously `button[data-ste-inplace]`). Detection failure still degrades to the row editor, and the rename path, byte-budget gate, input width fitting, and keyboard behavior are unchanged.

The primary anchor walks up from this entry's own rendered control until an ancestor's `previousElementSibling` is the crumbs nav — the actions row's `[data-slot=…]` anchor (`display: contents`) sits between the row and the entry — with the enclosing `<header>`'s nav as the fallback and the legacy disabled-button query as the last resort. Tests mirror the host skeleton per line — `titleCluster > nav > (crumbSeg per breadcrumb: separator, current title LAST) + actions row > slot anchor` — and the in-place suites run twice (`legacy` / `current`), with the entry mounted inside that slot anchor exactly as the host mounts it (a one-level `parentElement` walk fails these tests, which is the DOM detail that made the walk necessary). Neighbour safety is asserted directly: an ancestor crumb carrying the same text as the current title stays visible, and a sibling standing in for the official `conversation.session.header.lineage` slot keeps its attributes.

## Testing

The package suite is 62 green. The in-place suites (11 + 3 cases) run twice — `legacy` and `current` — over a fixture that mirrors each line's real markup, and they fail 11/11 when the previous locator is restored (measured by stashing the source change), which is what makes them a regression guard rather than a description.

Live check, 2026-09-27, on the line that was broken: a throwaway profile in a scratch `DSH_HOME` (`dsh plugin --profile web add <worktree>/packages/session-title-edit`, link install) booted on host `0.1.7-rc.2`, opened a real seeded session, and clicked the pencil. The official title node was a `SPAN` with text equal to the session title carrying `data-ste-inplace` at rect 300/11/184×28; the overlay input rendered at the same rect (300/11, 190×28) prefilled with the title; no row editor was present; Escape restored the node and removed the overlay. Before the fix the same click produced the row editor and left the title visible.

Coverage gap on the legacy line: the 0.1.5/0.1.6 arm is pinned by the dual-line suite and by the DOM read out of the published 0.1.5 bundle (`disabled: last`), not by a live run — a scratch 0.1.5 instance was booted, but its workspace browser would not list the seeded sessions (a harness-store limitation of the throwaway home, unrelated to this plugin), and the repo's CI `gates` job already runs this package's suite against the pinned `dsh-v0.1.5-rc.1` line.

## Alternatives considered

- **Keep the global disabled-button query and version-sniff the host.** The repo's dual-line rule forbids version sniffing, and the query would still have to change for the current line; one text-based probe covers both without a branch.
- **Locate by the CSS-module class (`span.crumbCurrent`).** The class is hashed per build (`wSkVaW_crumbCurrent`), so it is a build artifact rather than a contract; the rendered title text is the thing both lines genuinely share.
- **Register into `conversation.session.header.lineage`.** It is the only official slot that renders beside the title, but it is `single` and ui-subagent already occupies it at priority 0: registering at the same priority throws at boot ("single slot … already has a registration"), and shadowing at a lower priority would suppress the official subagent lineage for every session.
- **Ask upstream for a real title seat before fixing anything.** Correct as the end state (the plugin's TODO still says so), but users on the 0.1.7 line are losing in-place today; the DOM anchor is documented as a stopgap with a fallback, so it is repaired first and retired when a title slot exists.
- **Anchor structurally on the last segment's first non-separator child.** Breaks on subagent sessions, where the host renders the whole crumb through the lineage slot (`renderSlot(..., { fallback: title })`) and the title text lives inside ui-subagent's own markup; the text match still finds it, the structural guess would not.

## Consequences

- In-place editing works again on 0.1.7-alpha.1+ without giving up 0.1.5/0.1.6: one code path, one attribute, one CSS rule. The cost is that the locator depends on the rendered title text equalling the projected `displayTitle` (true by construction today); if a host ever renders a differently-normalized title there, the plugin degrades to the row editor rather than mis-hiding something — the same failure mode it always had, now tested in both directions.
- Coverage gap, stated plainly: the fixtures are hand-mirrored host markup, so a *future* host move will not be caught by unit tests alone. What stands in for it here is direct inspection of both lines (0.1.5's built bundle renders `disabled: last`; 0.1.7 renders the plain span) plus the live check below. The `conversation.session.header.lineage` slot is the upstream seam that should replace this overlay entirely; until the header opens a title seat, the TODO stays.
- Compatibility labeling moved with the fix: `dsh.compat.verifiedHost` 0.1.2-rc.1 → 0.1.7-rc.2 plus `notes`, and both READMEs now state that published ≤0.2.3 degrades on ≥0.1.7-alpha.1 hosts while the next release restores it. `minHost` stays at 0.1.2-rc.1 — the floor does not move for a fix.
