# Agent Note: 移动端会话库分隔线采用宿主框架语义

Status: implemented

[English](2026-11-06-mobile-library-separator.md) | 中文

## Problem

移动端会话库和它后方的对话可能都是白色背景。两者的交界处原来使用通用的半透明控件边线，导致打开的抽屉与对话之间不够清楚，在顶部栏和圆角附近尤其明显。PC 框架则使用宿主专门的分栏边框变量。

## Decision

打开移动会话库时，主内容和顶部栏的边线，以及宽屏固定布局的边线，统一使用 1px 的 `--mobile-divider`。浅色主题下它解析为 `--dsw-alias-border-l3`，并以 `--mobile-edge` 作为兼容性回退。根据 2026-11-09 的暗色设备反馈，`body[data-ds-dark-theme]` 下改为解析 `--dsw-alias-border-l4`（20% 白色），回退为主要文字颜色的 24%，因为 16% 的边线太不明显。会话库打开时使用宿主主要文字颜色的 12% 透明度投射轻柔的右侧阴影。根据 2026-11-11 的 iPad 反馈，宽屏固定布局也保留这层阴影，因为较大的白色表面上只有边线几乎不可见；收起会话库时不显示阴影。抽屉和固定栏宽度、断点、圆角、手势及关闭行为均保持不变。改动仅限移动端样式表，不触碰宿主和 iOS 壳源码。

## Alternatives considered

**使用更粗或更深的分隔线。** 不采用：粗重黑边会压过移动端其他界面元素，也不符合 PC 框架克制的分隔方式。窄屏抽屉更需要表面层次，而不是增加边线重量。

**调整抽屉宽度，或所有屏幕都固定为双栏。** 不采用：宽度和导航行为不同于本次报告的边界不清问题。永久双栏会挤压窄屏对话，并在没有需求证据的情况下替换既有抽屉交互。

## Consequences

分隔线现在与 PC 框架遵循同一套深浅色主题语义；窄屏抽屉在两个相同颜色表面相接时也能保持辨识度。没有框架变量的旧宿主保留原来的边线回退。DOM、导航、存储和原生签名行为均不变。

包构建及全部 168 项 mobile 测试通过。使用真实移动端样式的免凭据 Chromium 样例验证了 390px 浅色、深色抽屉和 1024px 浅色固定双栏：会话库与主内容边界的横坐标一致，窄屏阴影计算值为主要文字颜色的 12%，宽屏阴影为 `none`，三种状态均无横向溢出。该样例是样式证据，不是生产会话或原生设备视觉验收；原生设备观感仍需通过设备观察。
