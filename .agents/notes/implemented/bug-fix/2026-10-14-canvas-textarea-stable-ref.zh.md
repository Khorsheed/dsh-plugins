# Agent Note: Stable ref callback for the auto-sizing card textarea

Status: implemented

## 问题

画布详情页的编辑模式下，用户在长卡片里往下翻，每隔几秒页面会自动回到顶部。画板标签页每 4 秒轮询一次并递增 store 的 rev；详情视图订阅了该 rev，因此每次轮询都会重渲染打开的编辑器。CardTextarea 的自适应高度挂在内联 ref 回调上——每次渲染都是新引用，React 会在每次提交时先分离再重新挂载——而自适应高度会先把 textarea 压到 0 px 再读 `scrollHeight`，在塌缩状态下强制同步布局。内容高度低于滚动偏移时浏览器会钳制滚动位置，高度恢复后被钳掉的偏移不会还原。每次轮询都对块编辑器的每个文本块重复一遍，页面就这样一步步回到顶部。

## 决定

CardTextarea 的 ref 回调改为稳定的 `useCallback`：挂载时保存元素并做一次自适应高度，卸载时清空 ref。重渲染不再触碰元素高度：输入仍通过 `onInput` 调整，原先仅在挂载时运行的 `useEffect` 与 ref 挂载重复，一并移除。

## 考虑过的替代方案

**阻止 rev 订阅重渲染详情视图。** rev 是设计好的跨标签页刷新通道，重渲染本身无害——缺陷在于每次提交都执行的 ref 副作用。为了保护一个子组件而削弱通道，颠倒了归属。

**自适应高度不经过压零帧（镜像元素、只增不减）。** 为了绕开症状而改变缩小语义；只要高度调整只在挂载和输入时发生，就没有必要。

**用 `React.memo` 包裹 CardTextarea。** 只能减少渲染次数，任何仍发生的渲染（placeholder 或提示文案变化）都会重新挂载内联 ref，隐患仍在。稳定回调移除的是机制本身。

## 后果

4 秒的画板轮询不再移动卡片编辑器、源码面板和评论框的滚动位置；挂载和每次按键的高度行为不变。同款模式已在其他包排查：sidechat 的输入框使用稳定的 ref 对象且仅在输入和发送时调整高度，room 的输入框仅在 change 时调整——都不会在每次渲染时重新量高。
