# Agent Note: 连接手机页在快速隧道启动后能落到最终状态

Status: implemented

## Problem

在「设置 → 连接手机」里开启一键公网入口后，页面可能一直停在「暂时无法读取连接信息」，下面还是旧的「请由部署者配置 publicOrigin」说明，要重新打开对话框才正常。原因是 `ConnectPhone.tsx` 里的两个前端问题叠在一起。隧道守护的 `bind` 会把新域名写进连接行的 `trustedHosts`，这会让宿主连接重载；启动期间每 5 秒一次的轮询，正好撞上重载的那次连接信息读取会失败，页面把它当成错误显示出来。随后轮询在读到隧道 `ready` 的那一拍就停了，页面没有再读一次带新地址的连接信息。两者都与宿主版本无关（在 0.2.1-rc.3 验收实例上发现，rc.1 上是同一份代码）。

## Decision

- `load(generate, background)`：启动期间的轮询用后台模式读取，失败不显示，下一拍重试。
- 隧道状态离开 `starting` / `recovering` 时，页面再读一次连接信息（前台读取，所以就绪之后真的读不到仍会报错）。

## Alternatives considered

- **在一次读取内部反复重试直到成功**：否决。轮询本来就每 5 秒重试一次；再套一层重试，还要在关闭对话框时额外中止计时器。
- **域名已被信任时跳过写入**：接管已有隧道时已经这样做了；新申请的快速隧道域名必须写入，重载避免不了。

## Consequences

- 启动期间连接接口如果真的不可用，要等隧道落定后那次读取才会报错。
- 每次启动多一次连接信息读取。

## Testing

`tests/connect.client.spec.tsx` 新增一条：隧道变成就绪的同一拍里连接信息读取失败，页面不显示报错，随后恰好再读一次，轮询停止。旧组件上这条会失败（出现报错），现在通过；mobile 全部测试绿（167）。
