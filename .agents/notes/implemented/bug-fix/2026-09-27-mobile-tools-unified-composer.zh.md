# Agent Note：统一输入框下的移动端工具面板

状态：已实现

## 问题

宿主 0.1.7 将附件按钮合并进指令菜单。移动端仍预期隐藏文件输入框前有两个相邻按钮，导致工具面板不显示，宿主加号直接聚焦编辑器，并在键盘上方打开桌面指令列表。

## 决策

同时识别两种已核对的输入框结构。对于新版结构，同步点击保留的宿主文件输入框，其 change 回调继续负责校验、限制与上传。当宿主指令按钮或文件输入框禁用，或编辑器不可编辑时，附件操作禁用，对齐已绑定、未锁定、非提交阶段及非子代理的条件。未知结构保留宿主控件。权限识别也支持命名权限槽位。

打开移动面板时先让编辑器失焦，并在 showModal 前聚焦加号按钮，使原生焦点恢复返回加号而非键盘。仅明确选择「指令」时才打开宿主组合框并聚焦编辑器。面板使用主题实色背景、大尺寸入口、易读标题与行分隔线。标题/拖动条区域下滑及背景点击通过原生 dialog.close 关闭；正文滚动与控件交互保持不变。

## 考虑过的方案

直接打开宿主加号仍会弹起键盘。自行实现指令目录或上传流程会造成行为分叉。公开的会话输入动作接口没有文件选择方法，因此保留严格检查结构的 DOM 适配，复用挂载的输入框及原始回调，不调用私有 hub 或 keyboard 方法。

## 影响

这是需要随版本核对的展示适配层，未知结构保留原界面。旧版按钮回调及权限确认不变。测试覆盖两种结构、附件可用性、同步文件选择、草稿保留、焦点恢复与原生面板关闭。移动包构建及 125 项测试通过；WebKit 场景检查窄屏深浅色面板和原生弹窗焦点。iPhone 键盘与文件选择仍需部署后真机验收。本次未部署到 3080。
