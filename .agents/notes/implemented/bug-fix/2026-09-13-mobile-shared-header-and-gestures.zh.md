# Agent Note: 统一不同会话类型的移动端标题适配

Status: implemented

## Problem

移动端标题适配之前要求普通会话且 lineage 插槽为空。因此 Rooms 和带子会话的对话仍把模式、电脑打开方式、导出菜单和侧边栏按钮放在可交互插件控件旁边。改名复用宿主行内编辑器，覆盖了移动端标题，键盘弹出时还会挤动页面。目录关闭手势则因为会话行是按钮而拒绝处理。

## Decision

对所有活动会话应用同一套经过检查的标题展示锚点。把现有模式标签投影到工作区副标题，隐藏已识别的电脑专属工具。只有整行剩余内容全部得到处理时才折叠该行；保留祖先、子会话导航和未知插件动作。这是一层统一适配，不为 Rooms 单独实现；移除移动端插件会恢复所有被标记节点。

用移动端弹窗承载标题草稿，保存调用与 Web 工作区弹窗相同的 sessions.binding(id).session.rename。固定目标会话身份，保留服务端拒绝和重试，允许确认未改变的自动标题，并防止请求尚未完成时重复提交。不触发宿主行内编辑器，不写乐观标题缓存。打开、关闭弹窗时保持聊天输入框的焦点保护。

允许从移动端会话行、工作区分组和露出的聊天预览开始横向手势。只接管明确的横向移动；纵向或多指操作取消接管，并消费随后的合成点击。编辑器、文本选择、无关控件和可横向滚动的内容保持原行为。宽屏固定双栏保持稳定。宿主工作区侧栏通过现有开关向左关闭。已打开的右侧栏可以向右滑出，并调用原有关闭按钮；未识别面板保留其控件。收尾动画遵循减少动态效果设置。模式选项之间增加细分隔线，不改变选项回调。

当普通当前会话有已识别的子代理计数入口时，隐藏重复的禁用标题及计数前的分隔符。跨 provider 保留原有实时计数、活动指示和目录入口，同时保留真正的祖先链接与子会话切换器。未知 lineage 结构保持原样。

## Alternatives considered

给 Rooms 再写一套工具栏会扩大维护分叉。隐藏全部标题插槽会丢失插件动作和子会话导航。只调整行内输入框样式仍会保留键盘和布局干扰。另建改名 API 会重复宿主的规范化与自动标题固定语义。允许所有按钮触发导航手势会干扰无关控件。

## Consequences

宿主尚未提供展示元数据时，标题识别仍是经过检查的 DOM 降级适配；未知贡献保持可见。iOS 原生设置和第三方弹窗保留各自导航手势。历史 Remote stream frame 报错需要与展示改动独立定位：本次通过公网分别用 WebKit 和 Chromium 重新打开用户反馈的 Room 均成功，所以本次改动不宣称修复了未观察到的现场问题。
