# Agent Note: a Kimi wire usage record counts once

Status: implemented

## Problem

房间 2e44ba43 在 Context Lens 会话地图上有一根柱子远远高出其他所有柱子：一个 Kimi 成员请求记录的输入是 3,201,120 token，其中缓存命中 112,640（fbc8ba18 第 43 轮，这一轮 40 秒后被取消）。Kimi 自己的 wire 里，这一轮只有一条用量记录：输入 320,112，缓存命中 11,264。镜像把这条记录恰好记了十次。

镜像每读一遍，就认领 `[fromLines, consumedTotal]` 范围内的用量记录。这个范围包含右边界，这样紧跟在内容后面写入的记录不会漏掉。当某个单元一直挂起（这一轮唯一的 wire 步骤始终没有关闭）时，读取位置无法前进，于是每次实时轮询都会重读同一个范围。每次轮询都会把边界上的那条记录再当作未挂靠的用量返回一次，驱动把它累加进这一轮的剩余用量，取消时的收尾则把累计总数写到了这一轮唯一的步骤上。

## Decision

`mirrorKimiSessionDelta` 按子会话（以 `Session` 为键的 `WeakMap`）记住已经计过的用量记录所在的 wire 行号。已经计过的记录不再参与任何求和，每读一遍都会把本次范围内的记录标记为已计。wire 行号只增不减，所以无论跨读取还是跨轮次，都能用行号唯一识别一条记录。实时驱动和 exec 轮询都因此受益，调用方式无需改动。

## Alternatives considered

- **把右边界改成不包含。** 这样会漏掉紧跟在内容后面写入的记录，而包含边界正是为了这种情况。

## Consequences

一轮的用量就是每条 wire 记录各计一次。这次改动之前写入的日志，仍保留那个被放大的步骤。Context Lens 的地图现在按第 95 百分位缩放柱高，这类离群值不会再把其他柱子压扁。

## Testing

`local-agent-kimi`（292）：session-mirror 用例对一个挂起的轮次轮询十次，断言那条记录只被计一次。旧代码会记成 3,201,120，正是线上出现的数字。
