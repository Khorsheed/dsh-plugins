# Agent Note：完整客户端构建保留账号与版本元数据

Status: implemented

[English](2026-11-13-complete-client-build-metadata.md) | 中文

## 问题

直接运行宿主的 `build:web` 脚本不会提供完整的客户端构建环境。生成的浏览器包可能缺少 `DSH_CLIENT_VERSION`：通用设置会有意省略版本行，而账号操作需要 `accountClientMetadata()` 时，该函数会抛错。仅凭产物文件存在，不能判定可以交付。

这与生产启动覆盖层禁用 `ui-settings-account`、导致账号通知等待 `accountUi` 提供方的问题不同，也不同于官方在未登录时隐藏账号设置页的规则。把三个现象都当成上游删除功能，会误诊故障。

## 决策

在宿主仓库根目录运行完整的 `pnpm run build`，再通过仓库既有的 `deploy:3080` 门禁部署。不修改官方账号代码，不绕过版本元数据，也不把直接运行 `build:web` 当成完整发布构建。

`.dsh-build/client-build-environment.json` 完整构建记录必须包含实际宿主版本和提交。浏览器冒烟要检查可见版本与真实账号菜单路径；没有实际执行授权，就不能宣称外部账号登录成功。

## 未采用的方案

**只给生产页面注入一个任意版本号。** 否决：这会掩盖不完整产物，使显示版本与实际发布脱节。

**修改官方账号行为或删除缺版本时的异常。** 否决：社区仓库不 fork 宿主，支持的根目录完整构建已经提供所需元数据。

**只用构建失败解释账号设置页消失。** 源码和浏览器证据否决了这一说法：未登录客户端有意只显示登录菜单项，不显示登录后的账号设置页。另一个启动覆盖层不匹配问题记录在账号通知修复中。

## 影响

3080 候选重新携带 `0.2.2-rc.3` 及匹配的提交元数据。账号设置、通知和登录行为仍由官方负责。真实用户登录仍需单独在生产确认，构建或无凭据浏览器测试不能为其背书。

## 验证

宿主根目录完整构建的十项门禁全部通过，随后受控部署与 canary 成功。构建记录标明版本 `0.2.2-rc.3`、提交 `38a6a5c`、371 个客户端产物及其摘要。

`packages/basic/tests/account-notifications.host.spec.ts` 使用真实装配客户端检查未登录时的登录菜单项、与宿主清单一致的版本号、账号通知激活和无页面错误。测试刻意不启动外部授权，也不读取凭据。
