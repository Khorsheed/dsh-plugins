# Agent Note: 条件的最后一公里，以及题库该由谁挑（I5 · T58）

Status: implemented

[English](2026-09-17-eval-conditions-last-mile.md) | 中文

## Problem

I5 的端到端走查（T39）把八步走完并逐步记了人介入的次数。第 4 步「登录与 provision」花了**六次**，其中四次是缺口而不是决定：

- **G6.** `model.endpoint` 是就绪闸必看的字段——它是 null，条件就被拒——而没有任何一个面能改它：不在起草工具的六个可改字段里，不在条件页上，也没有任何表单。人只能拿编辑器开两份 JSON，而且两份必须填同一个值，否则实验凭空多一个因子。
- **G7.** `provision` 算出了 `home.sha`，却按设计不写回。`home.sha` 进条件哈希，于是人把一串 64 位摘要从 warning 里抄出来、贴进两份声明，再 provision **第二次**，好让 lock 重新锚住刚被自己改过的那份文档。同一个动作做两遍，中间夹一次人工转抄。
- **G4.** 从一条早于容器路径的条件复制出来的新条件没有 `unit` 段可继承，而六个可改字段表达不了它。计划一旦声明 unit，起草就根本造不出一条能跑的条件。
- **G5.** 绑定里存的是字面 `~`，`eval_conditions` 与 datasets 的读路径都不展开，条件页因此整页报错。（已拆给 T62，本任务不做；下面只处理**比较**那一半——那是 T58 无论 T62 怎么定存法都要有的。）

另外两条来自第 1 步，关乎的是边界而不是字段；它们放在本任务里，因为那是同一条最后一公里从 agent 那侧看过去的样子：

- **G1.** 在一个没人绑过题库的会话里，工具如实说了：*「传 repo，或者让人给这个会话绑一个」*。agent 没有停。它用 glob 搜磁盘，找到 `~/.dsh/scratch/dataseek-eval`——多个 agent 共用的那个检出，HEAD 还停在别人的分支上——并在里面写下三份文件，其中一份改写了当时正在跑的 pilot 计划。报错说对了该怎么修，而它旁边那个参数把绕过去的路开着。
- **G3.** `/datasets bind <repo>` 不带 `--layers` 时打印 `(all layers)`。实际生效的上限本来就是 modelFacing 下限，所以这句回执在**最要紧的方向上**说反了：读到它的人会以为 `answers/oracle` 与 `rubric.yml` 已经对规划 agent 打开了。
- **G2.** `/datasets bind` 没有任何人看得见的回执。它落在 tab 条上方那枚 chip 上，而 tab 条要等会话里有内容才出现——绑定恰恰是会话还空着时做的第一件事。

## Decision

### provision 把摘要写回去，于是它是一次动作（G7）

`provisionCondition` 多一个 `writeBack`，**缺省为真**。算完作用域家目录的哈希后，`home.sha` 对不上的声明就地被改正，条件**重新算哈希**，第 6 步写出的 lock 锚的是改完之后的那份文档。重算哈希才是重点：`home.sha` 是哈希输入，所以改正后的文档与读进来的那份是两条不同的条件，而按改前的 sha 写 lock，恰恰就是第二次 provision 存在的理由——那个过期状态。

slash 的 `--no-write-back`（服务面的 `writeBack: false`、页面动词的 `keepDeclaration: true`）恢复旧的两步形状。写只碰 `home.sha`、只在不一致时发生、只写 `--repo` 指的那份工作副本，不 commit。

`harness.version` 不在此列。CLI 报的自身版本是一次**测量**，属于 lock；`home.sha` 是声明作者留给 provision 去填的字段。

### 条件页拿到人的那两个写（G6、G7）

`provisionCondition({dataset, condition})` 与 `setConditionEndpoint({dataset, condition, endpoint})` 是两个新服务动词，各配一个 Remote 动词，**都没有模型工具孪生**。两者的工作副本都由调用会话的绑定解析，而不是收一个路径：浏览器若能指定 lock 写进哪里，它就是在挑工作副本，而那是绑定者的决定。

`setConditionEndpoint` 是任何面对**已有**声明做的唯一一个写，而且刻意只有一个字段。它是改因子：条件重算哈希、旁边的 lock 随即过期。回执点名这两件事，再 provision 一次是下一次点击——一个悄悄替人重锚受试对象的写，会让「这条条件是什么」取决于上一次有人看它是什么时候。

两个回执都带着**改完之后的那一行**，所以表格从刚返回的那次调用更新，而不是再走一遍 `conditions/` 目录去问自己点出来的结果。provision 回执的清单走 `provisionChecks`，与计划审阅页同一套扁平的 `ok / warn / error`——一个问题，一种呈现。

`model.endpoint` 同时成为起草复制件的**第七个**可改字段，于是常见情形根本走不到这一页。

### 容器段按一张四行的表补齐（G4）

`unit.ts` 里的 `HARNESS_UNIT_SCOPED_HOMES` 四家各一行——dsh、claude-code、codex、kimi——各自的容器内凭证挂载点与指向它的变量名。计划声明了 unit 而复制源没有可用的 `unit.scopedHome` 时，复制件从这张表拿一份，并补上 `env.keys` 里对应的那一项（否则 run 会按 `UNIT_SCOPED_HOME_VAR_UNDECLARED` 拒绝），notes 记下补了什么、为什么。

表里没有的 harness **一个字都不补**：validate 的 `UNIT_SCOPED_HOME_MISSING` 点名那个字段，比一个没人选过的凭证目录是更好的答案。补齐也刻意不计入复制件「改了哪些字段」，所以一条谁都没改的复制件照旧按「什么都没改」被拒——那是把复制件变得在计划所指的地方跑得起来，不是作者选的因子。

### `repo` 参数只能复述绑定（G1）

> T73 分支 2 部分取代了本节（[实验成为部署级对象](../architecture/2026-09-23-eval-experiments-deployment-level.zh.md)）：模型工具不再收 `repo` 参数，也没有任何东西再读绑定；agent 用 `<登记 id>/<set>` 指题库。下面一节记的是 G1 时的形态。

`EvalService.resolveRepoScope` 与 datasets 的 `resolveScope` 各多一个 `agent` 旗标，只有模型工具适配器会设它。设了之后：

- 没有绑定（datasets 侧还包括没有配置默认题库）→ 拒绝，点名 `/datasets bind`，无论有没有传 `repo`；
- `repo` 不是那个题库 → 拒绝，两边都点名；
- `repo` 就是那个题库 → 接受，由绑定解析。

比较按归一化路径做——展开 `~`、`resolve`、路径存在时取 realpath、去尾斜杠——因为走到这个检查前的两种写法出自不同的手。归一化放在 `packages/eval/src/validate.ts` 与新增的 `packages/datasets/src/repo-path.ts`，**刻意不放在绑定存储里**：存什么是 T62 的题目，而这个检查无论 T62 定成哪种形式都得照常工作。

人的面一律不动：CLI 的 `--repo`、`/eval conditions --repo`、题集 tab、实验室 tab 的 Remote 都照旧可以指定题库。

### bind 的缺省是一句话，两个地方说得一样（G3）

`effectiveLayers` 的下限现在**无条件**生效：没有显式白名单时，上限就是该数据集的 `modelFacing: true` 层，没有别的分支。原先那条「数据集一个敏感层都没声明就整体不过滤」让「没写白名单」在不同数据集上意味着两件事，而绑的人并不会先去读 descriptor；不过滤的那一支还顺带放行了没有任何 `register` 条目认领的 item 级目录——恰恰是没人为其表过态的那些。

`formatBindReceipt` 是 slash 与 CLI 共用的那句回执：缺省绑定写「agent 可见：仅模型可见层」，并点名 `--layers` 是开更多的办法；开宽过的绑定点名开了哪几层，并说明那是显式写下的。

### 绑定回执有了可以出现的地方（G2）

composer 工具行（`conversation.input.left`）上一枚只读 chip，显示绑定题库的名字与层上限，未绑定时是虚线的「未绑定」。它经同一个 `RegistrationToggle` 跟着 tab 的自隐判据走，所以两者不可能对「这是不是一个题集会话」各说各话；刷新靠订阅本会话自身的快照并节流 800 毫秒——slash 命令起止各动一次会话，正是回执该出现的那一刻。

## Alternatives considered

**写回之后让 provision 自己再跑一遍，而不是就地重算哈希。** 一次调用扫两遍同一个作用域家目录，而且第二遍还得赌中间什么都没动。对刚写出去的那份文档重算哈希，是同一个答案只算一次。

**把写回做成 opt-in（`--write-back`）而不是缺省。** 这是走查缺口报告里建议的形状。否掉：那样缺省留下的状态是「条件未就绪」加「声明与自己的 lock 不一致」，没人会故意想要它。这个旗标值得有，但作为退路——比如有人只想看作用域家目录当前哈希成什么而不想动文件——那是少数情形，少数情形该带旗标。

**让条件页能改条件的所有字段，而不只是 endpoint。** 否掉。造条件是起草动词的活，复制纪律由它保证；这一页上放一个通用编辑器就是写同一份文件的第二条路，两条会漂——这和 T36 把「新建条件」留成一个指路而不是表单是同一条理由。`model.endpoint` 之所以破例，是因为它是**已经存在**的声明上的就绪闸字段，而起草动词够不着那里。

**改 endpoint 后自动重新 provision。** 那正好省掉了「省不得」的那一次点击：这次编辑改的是受试对象本身，重新锚定它应当由人在看得见 lock 已过期的情况下决定。

**对 agent 直接拒绝 `repo` 参数，而不是接受复述。** 说起来更干净，但既没弄坏什么也没帮上什么：一个把自己已经拿到的题库原样写出来的 agent 没做错任何事，而那样的拒绝会打在正确行为上。要紧的是这个参数不能**放宽**。

**组合里根本没挂 datasets 服务时仍然认 `repo`。** 很诱人——那种组合里没有绑定可违反。否掉，因为它按构造就是一条洗白路径：没有绑定面的组合正是人从来没拿到过这个控制权的组合，那里诚实的答案是「工具没有题库」，而不是「agent 可以自己挑一个」。

**在本任务里顺手修掉 `~` 的存法。** 那是 T62，已经拆出去并写好了文案。在这条分支上做会和 T62 在 `binding.ts` 与各读路径上逐个文件撞车；而比较用的那个 helper 是 T58 真正需要的，且两种存法下都成立。

**把层下限的特例去掉的另一种做法：让*绑定*在 bind 那一刻记下一份具体的层清单。** 否掉：层名是每个数据集自己的，绑定是仓库级的，bind 时冻结的清单会对之后新增的数据集悄悄失效。下限是一条规则，规则不会过期。

**把绑定回执放进聊天流而不是 composer。** slash 的结果本来就经 `command/done` 进那里，而空会话里看不见——这正是那个 bug。本插件自己发一个持久 session 事件更糟：绑定存储的模块注释里记着为什么自定义类型事件会让会话不可恢复。

## Consequences

- **一条带 endpoint 起草出来的新条件，一次人的动作就 ready。** 第 4 步的六次人介入变成两次：run 需要的那次 `/<家> login`（dsh 这一轮没有，它走实例自己的 provider）与 provision 本身。转抄与重复的那四次没有了。
- **过期的 `home.sha` 现在被改正，而不是被报告。** 想要旧的报告行为的人有 `--no-write-back`；没注意到这次变化的人会少看见一条 warning、多看见一条就绪的条件。
- **为容器计划造的条件不用开编辑器就能跑**，限表里那四家。第五家是 `unit.ts` 里的一行加一个测试。
- **未绑定会话里的 agent 现在一个题库都拿不到。** 这是有意为之，而且是一次真的收窄：靠 agent 在未绑定会话里传 `repo` 的流程会停下来并说明原因。可能被这条打到的两种组合——会话没绑、实例没挂 datasets——回执都写着那句 bind 命令。
- **不带 `--layers` 的绑定现在也会过滤「一个敏感层都没声明」的数据集**，此前不会。对层全是 modelFacing 的数据集来说上限等于已声明的层，所以唯一可观察的变化是：没有任何 `register` 条目认领的 item 级目录不再到得了 agent 手里。那是更安全的缺省，也是回执现在承诺的那个。
- **composer 上多了一个常驻控件**，只在 preset 授予了 dataset 工具的会话里。两个 tab 的整体视觉收口归 T63，它可以重做这枚 chip 的样式；文案已经在 locale 词典里而不是写死在组件里。
- **G5 没动**——绑定仍然存字面 `~`，3171 上的条件页在 T62 落地之前仍打不开。上面所有经条件页走的能力都要等它；slash 与服务面今天就能用。

## Testing

`packages/eval`：739 条。新增覆盖——写回及其幂等、服务面与 slash 两侧的 `--no-write-back`、起草的第七个字段、四家的容器段补齐与它的两种沉默（宿主路径、表里没有的 harness）、条件页两个动词（含路径段拒绝与未绑定会话）、经软链与不存在路径的归一化，以及客户端那条「一次点击、那一行变就绪」。

`packages/datasets`：182 条。新增覆盖——agent 收窄（复述、不符、未绑定、配置默认、软链）、无条件下限、两种形状的 bind 回执、chip 的注册与它的自隐判据，以及 chip 本身（已绑、开宽、未绑、首答之前不闪、每个节流窗口只读一次、宿主不可达）。
