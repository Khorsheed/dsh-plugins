# Agent Note: Bound idle handoff polling cost

Status: implemented

## 问题

启动切换完成后，新页面的 capability 没有匹配的注册记录。可选链把记录不存在误判为尚未确认，立即结束长轮询，客户端又立刻请求。每次所有权校验还在 macOS 同步启动进程探针，阻塞其他 HTTP 响应。

## 决定

已结束的切换仅在注册记录存在且尚未确认时唤醒轮询。处理器在启动代际通道和回执通道之间共用自身的进程身份缓存，每次仍比较 PID 与启动标识；回执、注册、认证和 canary 检查仍实时执行。进程存活期间自身启动身份不会变化，重启会创建新的处理器。身份不可用时拒绝授权，测试注入的身份校验仍可使用。

浏览器收到 idle 后至少等待 250 毫秒，兼容旧服务端和立即响应的终止状态。正常空闲请求仍最多等待 25 秒，每 200 毫秒检查切换状态。

## 考虑过的替代方案

**仅限制浏览器频率。** 长轮询的每次检查仍有同步子进程开销，而且已打开的旧客户端不会受到保护。

**缓存任意 PID 检查或取消身份验证。** 都可能接受被复用的 PID。这里只复用当前处理器自身不变的身份，其他位置的外部进程校验保持原样。

## 后果

新页面不会再因已结束的切换回执形成快速请求循环。回执轮询仍读取状态文件，但不再按页面和检查周期创建子进程。立即返回 idle 时，后续请求最多增加 250 毫秒等待。测试覆盖并发未注册页面、身份仅查询一次、身份不符或不可用、浏览器节流和原有切换及代际协议。
