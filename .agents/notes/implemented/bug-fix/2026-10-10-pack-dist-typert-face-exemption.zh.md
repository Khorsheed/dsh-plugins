# Agent Note: pack-dist 对生成的 typert 面豁免 family-edge 扫描

Status: implemented

## Problem

合并游戏开发模式([2026-10-09-game-dev-mode](../feature/2026-10-09-game-dev-mode.md))把 `packages/game` 注册进了 gen-typert 的 `TYPERT_PACKAGES`,于是下一次全量 gen-typert 运行把游戏的会话消息源——合并后的 `MessageSourceMap` 声明里的 `'dsh-game': { plugin: '@khorsheed/dsh-game' }`——嵌进了每一个 typert 面包生成的 `lib/typert.host.js`。从此 `verifyTarball` 的 family-edge 扫描在打包任何这类包时都报 `family references without manifest edges: @khorsheed/dsh-game`(canvas、canvas-novel、file-preview、library、local-agent、mission、room、sidechat——9 个 typert 包中的 8 个)。这个失败在部署 game 本身时不可见(game 是 selfName 豁免,presets 已声明该引用),只有在打包任何其他 typert 包时才出现——全仓 `pack-all-dist` 门禁、CI、以及这些包未来的每一次 `deploy:3080`。

## Decision

`verifyTarball` 在收集 family 引用时跳过 basename 以 `typert.` 开头的暂存文件(生成的 `lib/typert.host.*` / `lib/typert.remote-client.*` 面)。这些文件由生成器按全组合的 FaceModel 盖章生成,其中的兄弟包名是生成的组合数据,不是该包选择的依赖边——而且 manifest 里没有任何字段能诚实地声明它:依赖边等于声称 canvas 会安装 game(假),`dsh.references` 记录的是包自身发布内容携带的数据,而 typert 里的提及属于生成器的输出,不属于该包。typert 面唯一的运行时导入(zod)已由专门的 typert-face zod 检查钉住,所以该豁免不会掩盖任何真实的边。

## Alternatives considered

**在每个 typert 面包里声明 `dsh.references: ['@khorsheed/dsh-game']`。** 否决:合并后的类型面随任何插件新增携带包名字面量的声明而变化,每次都要改遍所有 typert 包的 manifest——而且这个条目是对包自身内容的谎言,引用属于生成器的输出而非包的源码。

**扫描前只剥离内嵌的声明字符串。** 否决:豁免将依赖生成器的确切序列化形式(今天是 JSON 字符串转义,明天可能是别的形态);稳定的契约是文件级边界——生成的文件,禁止手改。

**让 gen-typert 不再内嵌外部包名字面量。** 否决:合并声明图的意义就在于组合范围的类型完整性;消息源条目合法地命名它的属主插件。

## Consequences

- 在包含 game 注册的树上,`pack-all-dist` 全部 39 个 bundle 包干净通过;`scripts/pack-dist.spec.ts` 钉住了两个方向(生成的面豁免;同名出现在手写的 lib 产物中仍然失败)。
- 豁免以 `typert.` basename 约定为键。若某包手工写了同名文件,它会逃过扫描——但该名字归生成器所有(`Generated by @deepseek-ai/dsh-typert-generator — do not edit`),这种文件是约定违规,不是漏洞。
