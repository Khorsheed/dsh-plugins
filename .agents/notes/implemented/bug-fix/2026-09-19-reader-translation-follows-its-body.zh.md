# Agent Note：译文现在跟着正文走

Status: implemented

## Problem

读者反馈：离开灵感空间（换会话 / 换面板）再回来，正文在，翻译没了。

恢复路径里有两个缺陷，都是关于**它在什么时候去看**：

- **它读的是挂载时那份副本。** `snapshotRef` 只在挂载时取一次 `readSession()`，所以**本次挂载期间**才点亮的翻译，是在那份副本之后才写进页面记忆的——而恢复逻辑比对的正是那份副本。于是之后任何一次正文替换，都会为一条此刻明明在翻译的条目查到「没有记录」。
- **它是按条目武装一次，而不是按正文一次。** `restoredTranslationRef` 只在 `openEntryId` 变化时重置。而那个掌管分段生命周期的 effect（`[openEntryId, articleHtml]`）在正文变化时**正确地**把翻译拆掉（注入的 span 随旧 DOM 一起消亡），却没有任何东西重新贴回来。于是正文在被翻译的文章**脚下**被替换时（最常见的形态：只发摘要的论文缓存正文已过期，打开时先显示 feed 的摘要，恢复逻辑把摘要翻好，随后重抓真正那一页落地），文章就停在未翻译状态，除非读者再点一次地球。

这两个缺陷在「切面板再回来」这一路里是看不见的：新挂载读到的是新副本，又从一个空 DOM 开始。它们恰恰出现在读者发现的那个位置：一篇已翻译的文章，正文在它脚下动了。

## Decision

- **恢复步骤直接实时读页面记忆**（`readSession()`），不再读挂载时那份副本。副本保留——hydrate 是一次性动作，之后再读会把读者此刻正在做的收窄抹掉——它只是不再是被恢复逻辑查询的对象。
- **重新武装的键是正文**：`restoredTranslationRef` 在 `[openEntryId, articleHtml]` 上重置。记录的含义是「这一条的地球是亮的」（读者关掉地球、或要求重新抓取时它就被删掉），所以被重建的正文会自动把译文拿回来。这条规则让行为可以用一句话说清，而不是「亮着，除非有别的东西替换了 DOM」。
- **同一时刻只跑一次翻译。** `startTranslation` 现在会先取消在飞的那一次、并把文章还原成宿主给的标记，再建立自己的分段：读者的重试和恢复现在可以合法地重叠，两次同时跑会把同一个 DOM 装饰两遍。

## Alternatives considered

**用定时器或 `MutationObserver` 把译文贴回去。** 一个轮询修 DOM 的循环，恰恰是这个面板在别处一直避免的机械；重新武装的键用 React 已经告诉我们的生命周期达到同样结果。
**用 `built.root.isConnected` 探测「React 重建了元素」。** 它能覆盖「`articleHtml` 未变但元素被重建」的重渲染。这个面板里不存在这样的路径（文章元素只出现一次、在详情视图里，而切换会话会整块卸载面板），所以这个检查是猜测性的——而重新武装已经覆盖了所有真实存在的路径。
**把翻译状态放进 store 而不是模块内存。** 同样会有一层新的陈旧（选择器捕获的 store 快照），而且会把第三方的文本放进宿主可能序列化的 store 里。
**把记录落盘，让刷新后地球也亮着。** 依然否决：刷新后没有可驱动的翻译会话，而正文也不允许落盘。见之前的 note。

## Consequences

- 「这一条的地球是亮的」现在是这个页面内条目的一个稳定属性：它扛过切面板、切会话、正文替换、重新抓取和重渲染，只在读者关掉它时（`orig` 会删掉记录）或要求重新抓取时结束（`重新抓取` 刻意忘掉它，因为正文马上要变成另一份文档）。
- 正文替换现在会花一次翻译运行。有了句子记忆，这通常是免费的（每句都已记住），只有真正新出现的文字才会送去翻译。
- 挂载副本与实时读取现在是**刻意**的两件不同的事，`snapshotRef` 上的注释写明了这一点——下一个人要加恢复步骤时，应该伸手去拿 `readSession()`。

## Testing

`packages/dsh-reader` 共 254 个测试（新增 1 个）：

- `tests/ReaderPane.client.spec.tsx`：打开一篇文章并翻译；随后在读者毫无动作的情况下替换它的正文（用的就是重抓会走的那条 store action）；文章必须显示**翻译过的**新文字。修复前，恢复已经用掉了它唯一的一次机会（`restoredTranslationRef`）且读的是陈旧副本，所以断言拿到的是英文原文而失败。
