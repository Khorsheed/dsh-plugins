# Agent Note: 页面自己画的插图抓不到，搜索框也不该撑出自己的行

Status: implemented

## Problem

两次反馈，其中一次是这个仓库几小时前自己引入的 bug。

**搜索框没有按侧栏宽度收住。** `content-box` 下 `width: 100%` 的实际宽度是 100% **加上**内边距和边框。刚给框内清空按钮腾出位置、右内边距从 8px 变成 28px 之后，输入框比面板右缘多出约 56px——看上去就是"没按 sidebar 宽度自适应"。同类错误在筛选弹层的来源搜索框上刚修过（`flex: none` 包着 100% 宽的 input），墙上的输入框还留着旧写法。

**文章的插图没抓全。** 抓取 `transformer-circuits.pub/2026/workspace/index.html` 后渲染出来只有文字和图注、没有插图：实测服务器 HTML 里有 102 个 `<figure>`、18 个 `<img>`，其中 **84 个 figure 里面只有空的 `<div class='intro-structural'>` 加一句图注**——插图是页面自己的脚本在运行时画上去的。详情页把这些图注渲染在一无所有之上，读者读到的只能是"插件把我的图弄丢了"，而不是"这一页就是这么画的"。

**徽章说得不对。** 那篇文章的卡片上带着「已补全」，而卡片显示的仍是 feed 的 167 字符摘要——因为徽章标的是"全文已经抓取并缓存"，不是"卡片上展示的就是全文"。文案和标签都没说清是哪一种。这正是上一批"摘要不是正文"处理的同一个混淆，而徽章是最后一个还在宣称"完整"的表面。

## Decision

- **输入框用 `border-box`。** 一个不许超出容器的表单控件声明 `box-sizing: border-box`；CSS 测试现在钉住这一条，因为同一个错误已经造成两次读者可见的缺陷。
- **没有画面的 figure 直接去掉，并计数。** `extractArticle` 删除所有子树里没有 `<img>` / `<svg>` / `<canvas>` / `<video>` / `<picture>` 的 `<figure>`，并返回删掉的个数。悬空的图注比没有图注更糟：它看起来像数据丢了。这个计数随正文一起走——持久化在条目 annotation 上（`ReaderEntryBody.scriptFigures`），由 `getEntryBody` 与抓取一起回报——详情页写明「这一页有 N 张插图由页面自己的脚本绘制，抓取时拿不到」，旁边是「阅读原文」。
- **徽章说它真正意思。** 「已补全」改为「已抓全文」，悬停说明实际情况：卡片上仍是 feed 自己的摘要，全文已经缓存，点开就能读。

## Alternatives considered

**保留图注、给缺失的图放一个占位框。** 不采纳：占位框是在宣称"这里本来有一张图、只是没加载出来"，而事实相反——页面根本没把图放进 HTML。正文上方那句说明才是诚实的版本。

**保留空 figure、什么都不说。** 不采纳：那正是被反馈的状态，而且它读起来像本插件的缺陷，而不是来源页面的性质。

**想办法执行页面脚本（无头渲染）。** 本包不采纳：`ctx.web.fetch` 是官方出网缝，它取的是字节；执行页面脚本需要 browser pane，而它仍是 planned、并被明确划在本插件范围之外。这也正是 feed 解析必须留在浏览器半的同一条边界。

**按有没有图注来计数，而不是按有没有画面。** 不采纳：带真 `<img>` 而没有图注的 figure 是好的，两者都没有的才是噪音。"里面有没有画面元素"才是决定"有没有丢东西"的问题。

**干脆去掉徽章。** 不采纳：它仍然携带摘要无法表达的信息——卡片背后的正文比 feed 自己给的文字更长——问题出在它的措辞，而不是它存在。

## Consequences

- transformer-circuits.pub 那篇的提示会写「84 张插图」——数字大是因为那一页确实几乎每张插图（含视觉目录）都是脚本画的。这个计数是关于"交付到手里的 HTML"的事实，不是估算。
- 脚本画的 figure 的图注会随图一起被丢掉，所以会损失一点描述性文字。这是"不把图注悬在空处"的代价，原文只有一次点击之遥。
- `ReaderEntryBody.scriptFigures` 随缓存正文一起持久化，所以重新打开同一条会看到同样的提示、不用重抓；没有丢弃时它是**缺失**（而不是 0），`normalizeStateDoc` 照旧会丢掉不认识的字段。
- 「已抓全文」徽章仍然只出现在**自动补齐**抓到的条目上，手动打开抓到的不会有——`noteBackfilled` 是唯一的写入者。这是对的：徽章标记的是插件自己做的活儿。
- 宽度修正把输入框收回面板内宽；预留的 28px 右内边距现在吃的是输入框自己的盒宽，而不是撑出布局。

## Testing

`packages/dsh-reader` 现在跑 212 个测试（新增 4 个）：

- `extract-article.spec.ts`：只有图注的 figure 被丢弃并计数，而带 `<img>` 的 figure 留下（相对 `src` 被绝对化）；所有 figure 都有画面的页面不报计数。
- `ReaderPane.client.spec.tsx`：打开一条抓取结果里带脚本插图的条目，会显示该计数的提示与「阅读原文」动作。
- `host-pure.spec.ts`：`.search input` 在 `width: 100%` 之外声明了 `box-sizing: border-box`。
