# Agent Note: 部署登记、依赖诊断与真实通报

Status: implemented

[English](2026-09-12-deployment-install-and-diagnostics.md) | 中文

## Problem

mobile 首次部署暴露了共享工具的三个缺口：仅刷新时仍声称重启/canary 成功；新插件可能仅成为依赖而未登记 bundle；失效的生成链接直到昂贵步骤或隔离快照准备时才被发现。

## Decision

用户明确指派了这次共享脚本修复。变更归于 `deploy-3080.mts`；ankh-guard 和各插件运行时行为保持不变。

对于本次指定的自挂载包，部署检查 dependency 或 bundle 登记是否缺失，并调用已构建的官方 CLI，以打包产物执行 `plugin add`。不自行拼写 bundle 条目。完整登记的包走更新路径。新的无 bundle companion 被拒绝，已有纯依赖包保留更新路径。安装后在录制凭证之前验证包名/版本、bundle 登记与 patch 文件存在。旧 tarball 只在本次流程成功后清理；失败退出会释放部署锁。

只读的物理目录链接诊断在部署写入前、安装后各运行一次，`deploy:check-links` 提供同一检查的独立入口。报告路径、链接目标及系统错误码，排除 git 元数据和 home 顶层 scratch；验证链接而不递归追踪目录别名。根目录缺失及目录不可读均阻断。外部依赖图遍历、隔离和组合验证继续归 ankh-guard。

仅刷新通报明确说明尚未重启、未验证运行实例加载新构建、未验证 canary。重启成功仍以既有守护重启/canary 路径为条件；任何步骤失败都不产生成功通报。

## Alternatives considered

**保留首次安装的手工前置步骤。** 未采用，因为只有依赖存在无法证明 bundle 已登记，同类错误会反复出现；官方 CLI 已拥有调和能力。

**在 guard 内自动删除失效链接。** 未采用，因为目标缺失可能意味着关键依赖需要重装，诊断无法判定应该删除。由所属维护者检查并备份确认废弃的生成链接后再清理。

**在诊断中复制隔离快照语义。** 未采用：快速物理目录检查即可提前捕捉此次失效链接，避免维护第二套隔离实现。诊断明确不认证完整外部依赖图，也不替代 guard。

## Consequences

首次安装与更新共用入口，并获得准确通报。额外只读扫描有文件系统成本，也可能提前暴露其他历史文件问题；不会静默修复或削弱 guard。与此前一样，后续安装失败可能留下部分更新的 profile；不宣称自动回滚 profile，失败时保留旧 tarball。隔离的命令边界测试覆盖安装、登记/patch 失败、依赖损坏、仅刷新通报、守护拒绝与锁释放，不连接生产服务。
