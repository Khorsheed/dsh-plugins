# Agent Note: 实验室与题集两个 tab 当一件设计来读 —— 一张状态词表、列头归条件、证据折起来

Status: implemented

[English](2026-09-17-ui-polish-lab-datasets.md) | 中文

## Problem

实验室 tab 的六个子页与题集 tab 的两页由不同的切片各自做成，单看每页都对，但没有人对着别的页看过。用户走查之后的结论是「可读性低、设计感弱、体验差」，而他点到的四件事是同一个形状：**页面把内部值当成文案渲染**。

- 矩阵的列头是**因子值**，而因子值可以是数组——真实 run 上出现过 `["DEEPSEEK_API_KEY","DSH_HOME"]` 当列头。
- 矩阵把条件文档里每一个不同的键都当成平等的因子，于是 `unit.scopedHome.var` 与 64 位的 `home.sha` 和「模型」并排坐在筛选行里。一个只换了一样东西的 run 有五行筛选。
- 格内阶段写着 `mixed (archived / ws-ready)`：mission 的英文标识，拼上英文标点，放在中文界面里。
- 报告页把宿主的英文拒绝原文与绝对路径直接打在页上；概览页把 `run.meta` 与就绪记录当成裸 JSON 块贴出来。

界面规格 §九 正是为这件事写的，硬规则都在那里。这一轮按它把两个 tab 从头到尾过一遍。任务给的约束：**只动呈现与文案**——功能不动、数据面不动，发现数据面缺字段就记下来，不顺手扩。

## Decision

**一张状态词表，两份副本。** 两个包各有一份 `src/client/vocab.ts`，把页面可能显示的每个内部标识——账本阶段、mission 的桶、重跑类别、条件文档的叶子路径——落成一个词典键，中英各一条。查表是**全函数**：没见过的标识照样返回一个词（「未知阶段（{token}）」），调用方把原标识留在元素的 `title` 上，于是页面上不会出现裸键，要 grep 账本的人也不会丢东西。阶段名是按 manifest 位置生成的（`stage-<n>`，见 `src/template.ts`），所以它不是闭合联合——前六个有专门的词，再往后走参数化的那条键，而不是现编一个数字。题集那份是同一个文件去掉因子那一半，手工复制——客户端包不 import 兄弟插件（§八），与 `ErrorState` 同一个做法。

**格内阶段是算出来的，不是解析出来的。** `mixed (a / b)` 是 `pivotMatrix` 在宿主端拼的。与其把这个字符串拆回来翻译——宿主一改措辞就碎——不如读 `cell.reps[].state` 自己组句。那个宿主字符串干脆不渲染。

**矩阵的列头是条件。** 界面规格 §九：列头是条件 id，因子值作副标题。pivot 一个字没改；`EvalMatrixColumn.conditions` 本来就说了这一列带哪些条件，只是标题与副标题换了边。一列带多条条件时它们全都列出来，而这正是旧写法埋掉的那个事实。

**设计因子与随动字段是两类东西。** `conditionFactors` 是诚实的，也不替人判断意图——它报告声明之间每一个不同的叶子，这是对的。但 `unit.scopedHome.var` 由 harness 决定，`env.keys` 跟着它走，`home.sha` 是家目录落地之后的摘要：人没法把其中一个钉住去变另一个，所以它们都不能做控件。`NAMED_FACTORS` 是界面规格 §九 点名的六个（按它的顺序）加上「新建实验」表单能改的另外四个字段；其余在矩阵底下折叠成一行报告出来，带名字带取值，永远不是 chip。于是**单个设计因子的矩阵页没有筛选行**，多于一个时「换列 · 分组 · 筛选」收在一个默认折叠的 disclosure 里。

**默认的列由浏览器半边挑。** 不给 `column` 时 pivot 取 `factors[0]`，而 `conditionFactors` 是**字典序**排的——这正是 `env.keys` 当上列头的原因。给 pivot 塞一个偏好，等于把界面的意见写进一个三个面共用的纯函数里；所以改成：矩阵的 effect 在第一次答案回来时纠正一次——人没选过列、且宿主挑的不是 `preferredColumn(factors)`，就再要一次对的。指定了列之后 `matrixColumn` 非 null，这个分支跑不了第二次。

**两个 tab 共用同一套组件。** `Chip`（五档 tone）、`EmptyState`（一句话 + 下一步 + 自己的动作）、`Section`、`Detail` 与 `Word`，两个包里是同名 class、逐字相同的样式规则。chip 的底色是 `color-mix(in srgb, currentColor 12%, transparent)`，跟着 tone 走，明暗两套只有宿主 tokens 一处真相。两份样式表里没有自造的颜色与字号。

**四个设计 token 根本不存在。** 界面规格 §九 第一条是「沿用宿主的设计 tokens」，还举了 `--dsw-alias-bg-l2` 当例子——而宿主主题包里没有这个别名，也没有 `--dsw-alias-label-warning`、`--dsw-alias-label-danger`、`--dsw-font-family-mono`、`--dsw-alias-fill-hover`、`--dsw-alias-fill-selected`、`--dsw-alias-state-success`。每一处都以两种方式失败：带兜底的冻成一个跟不了主题的写死颜色（琥珀 `#b8600a`、红 `#b3261e`、4% 黑），不带兜底的解析成空——所以 notice、note、`<pre>`、错误位、卡格底色在两套主题下**都没有背景**。现在换成主题包真有的：安静表面与 hover 用 `interactive-bg-hover`、选中用 `interactive-bg-active`（hover 是提示、选中是状态，设计系统本来就是两档），警告 `state-warn-label`、错误 `state-error-primary`、那一个浮层编辑器 `bg-layer-3`、等宽 `--ds-font-family-code`——最后这个正是 §九 自己点的名字，题集 tab 一直用对。

**证据留着、折起来，既不打在页上也不摘要掉。** 就绪闸的拒绝原文、finalize 的走查日志与逐格拒绝原因、报告找 bundle 的说明、`run.meta`、就绪记录原文、计划文件的绝对路径、bundle 目录、题库根——全都够得着，全都在「详情」里或 `title` 上。这对拒绝原文最要紧：被闸拒的 run 根本到不了 `runCreate`，账本里一行都没有，那段话是唯一记着「为什么」的地方。唯一有意的例外是抽屉里的 verify 块——界面规格 §五 要求原样，它一个字没动。

**两处哈希宽度是例外**（`matrix-view.ts` 打 16 位，`provision.ts` 有一处打全长），现在都是 12 位，与这一家其余地方一致。

## Consequences

- `packages/eval` 757 → 771 条测试（新增 `tests/vocab.spec.ts`，钉住查表的全性、两份词典都带齐它能产出的每个键，以及两条点名的回归：数组列头与字典序列）。`packages/datasets` 仍是 198 条。两套全绿；typecheck 绿。
- 五个 client spec 是**改**不是删——每一条改动的断言都是「页面读的是词而不是标识」或「原来裸贴的块现在折起来了」，每条都带上把它挪走的那句 §九。
- 工具条上的动作常驻，空态里那枚用自己的措辞（「新建第一个实验」，不是第二枚「新建实验」）。第一版是空态出现时把工具条那枚藏掉，重复确实少了，但读起来更差：加载时它在、答案回来时它消失。
- `report.comparisonClosed` 换了形状——现在接一个数字，没成立的不变量以上面那张表同样的 chip 摆在旁边，而不是在宿主端拼成一句话。
- 有一种情况多一次 RPC：宿主挑的列不是设计因子时，页面第一次打开会重拉一次矩阵。单因子的 run，以及字典序第一个恰好就是设计因子的 run，还是只拉一次。
- 截图这一轮还长出第二道闸：两个包各一份 `tests/copy.spec.ts`，读 client 源码、收集每一处字面 `t('…')`，对着**两份**词典核，另外核两份词典的键集相同、同一条文案的占位符相同。client spec 用的是恒等 `t`（把键原样吐回来，正是缺键渲染出来的样子），所以这一类缺陷它们根本看不见。
- 真机走一遍找出四处代码审查没找到的：概览与计划审阅仍打着题库的绝对路径、因子列把一行撑成三行、「条件数」列装不下「1（+1 判官）」、筛选 chip 的词与计数贴在一起。四处都改了；回报里的截图是改完之后的第二轮。
- **记下不改（行为）**：composer 上的题集 chip 靠会话活动重读，slash 命令绑定的回执就是这么来的（T39·G2）。在 tab 自己的「导入题集」表单里绑定不会动会话，所以绑完之后 chip 仍写「未绑定」，直到下一条 slash 命令——两扇门里只有一扇会通知它。
- **记下不改（数据面）**：`pivotMatrix` 的汇总句、`report` 的不变量明细与 `rankReason` 都是宿主端拼好的中文，英文界面下会中英混排。要修就得下发结构化字段、由浏览器半边组句——那是任务明确划到范围外的数据面改动。

## Testing

两个包各跑 `pnpm --config.verify-deps-before-run=false test` 与 `tsc -b --noEmit --force`。`tests/vocab.spec.ts` 把查表能产出的每个键对着**两份**词典核一遍：加了一个阶段或一个条件字段却没补两条词典，红在这里，而不是到用户面前渲染成一个裸键。

## Alternatives considered

### 为什么不在 `conditionFactors` 里把噪声因子过滤掉？

那会让一个纯粹而诚实的函数开始说谎。`conditionFactors` 回答的是「这些声明在哪些字段上不同」，而 `home.sha` 确实是其中之一——只差这一项的两条条件**就是**两个受试对象。同一个函数还喂着条件 diff、列表的因子列和 `eval_cells`；为了让一页干净而教它「有些不同不算数」，等于改掉三个面报告的内容。这里划的界不是「真不真」，而是「人能不能把它钉住」，那是界面的问题，所以它留在界面里。

### 为什么不让 pivot 默认挑设计因子？

同样的理由，往上一层：`pivotMatrix` 是 tab 与工具面共用的纯排布，而一个取自界面规格 §九 的偏好顺序是浏览器半边的意见。纠正只多一次请求、只发生在两者不一致的 run 上，而且把规则写在一处（`NAMED_FACTORS`），紧挨着它排序的那些词。

### 为什么用算的而不是解析 `mixed (archived / ws-ready)`？

解析是三行代码，也能跑通——直到宿主改了分隔符，那时页面会不声不响地退回去打印宿主字符串，也就是原来的 bug。reps 本来就带着各自的状态；从它们组句是同一份信息，却不耦合别人的标点。

### 为什么把宿主的英文句子折起来而不是改写成文案？

改写等于页面声称自己知道宿主想说什么。就绪拒绝那句点着一个作用域家目录和一种凭据状态；finalize 的拒绝点着一道闸和一个状态。把哪一句摘要掉都是猜；对被拒的 run 来说，这个猜还替换掉了唯一的记录。折叠让证据完整、页面也好读——两者都要，而不是拿一个换另一个。

### 为什么用一个带 tone 的 chip，而不是各页各写颜色类？

各页各写正是漂移的来源：「运行中」在列表里是 `--dsw-alias-state-business-primary`，在矩阵里是普通文字，在头部条上是一枚带边框的 pill。tone 是一句关于**含义**的声明（`warn` = 人有事要做），每一页都能诚实地作出，然后一条样式规则一次性回答明暗两套。
