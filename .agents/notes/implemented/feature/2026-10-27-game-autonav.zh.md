# Agent Note: the game panel goes to what changed

Status: implemented

## Problem

agent 改了元素或发了版本之后，用户得自己在右栏里找结果：打开页签、点开元素，或者切到「试玩」。用户希望面板自己跳过去，并标出改了什么。但自动跳转也可能把正在玩游戏或正在编辑的人从面板上拉走，所以需要定规矩。

## Decision

- **跳到哪。** `offerFor(report)` 根据一轮结束时的报告来决定。检查没通过、或者这一轮什么都没改，就不跳。新版本同时改了代码或参数时去「试玩」，只出了新版本、别的都没改也去「试玩」。只改了一个元素就打开它的详情页；如果这一轮还出了新版本，详情页上提供「去试玩 vN」。改了好几个元素就打开元素网格。只改了策划就打开对应章节。回合中途落地的版本，或者主会话根本没有回合时落地的版本（协作间里的 CLI 成员通过桥接的 `game_publish` 发版，主会话不会产生任何事件），都由页面级轮询发现：页面可见时每 6 秒、或者会话事件提前触发时，读一次 `liveVersion`，也就是当前会话所绑项目最新的版本，只读两个小文件。第一次看到某个项目时把当时的版本当作基准（没有版本就记 0），但如果那个版本是 90 秒内刚落地的，照样提示，所以新项目的 v1 也会提示。回合结束时不再重复提示同一个版本，用户自己发的版本永远不提示。同一个轮询也会发现没有事件的绑定变化（协作间成员调了 `game_open` 或建了项目）：右栏重新读取状态；如果变化发生在页面打开期间，面板会直接打开这个项目。（第一版只看会话事件，并且把第一个版本当成基准，2026-10-27 协作间成员发的 v1 两头都漏了。）
- **什么时候不跳。** 「试玩」里有游戏在运行时、用户 20 秒内在面板里操作过时、正开着另一个元素的详情页时，或者用户关掉了「改完自动跳转」开关时（每个浏览器各自一份，在「…」菜单里，默认打开），都不跳，改为在面板里显示一条带「去看看 / 不用了」的提示。面板关着时，只有窗口宽度至少 820px 才会自动打开，更窄的屏幕上打开会盖住对话，用户可以用轮末卡片上的「查看」。超过两分钟的报告算历史记录（比如刷新页面后读到的），不处理。
- **小圆点。** 这一轮改过的元素，卡片上会有一个小圆点，详情页被打开过一次后消失，用户手动打开或自动跳转打开都算。圆点记在当前浏览器里，每个人各自一份。
- **分段控件。** 视角、材质、画笔/换色这几组分段控件，改成一个带外框的整体：分段之间用细线隔开，选中的那段填强调色。旧样式默认只有两段，所以第三个视角按钮单独飘在外面，选中态也只体现为一圈边框。「正面 / 侧面 / 背面」在手动拖动转盘之前会显示当前选中的是哪一面。动画标签会标出正在自动播放的那个。

## Alternatives considered

**agent 每写一个文件就跳一次。** 一轮下来面板会一直闪。回合结束和发版的时刻，才是真正有结果的时候。

**面板关着时总是自动打开。** 在手机或窄窗口上，它会盖住用户正在读的对话。

**把小圆点存在服务端。** 看没看过是每个查看者自己的状态，多个人看同一个项目时会互相清掉对方的圆点。

## Consequences

- 页面可见时每 6 秒读一次 `liveVersion`（两个小 JSON 文件）。
- 不想被跳转的用户可以关掉开关，改动仍会以提示的形式出现。
