# Agent Note: 卡片正文是文字、手绘、图片交错的一条流

Status: implemented

## Problem

卡片原来只有文字加最多一幅手绘，而且手绘总是排在文字后面。编辑分成两块：先是文本框，下面再是画板。这带来三个限制：

- 不能在两段之间放一幅草图，也不能在一张卡上画两次；
- 截图不能贴在光标处；
- 贴进来的图只会以一行裸的 `![](attachment://…)` 追加到文末。

2026-09-27 评审时，用户要求文字、手绘、图片在同一个编辑器里交错排列，并提了三个约束：不引入大型编辑器库，粘贴图片必须可用，md/html 的渲染保持原样（记忆：画布改版决定，第 6 步）。

## Decision

**卡片仍是一段 markdown 字符串，由指针行构成流。** 一行只有 `![](draw://<id>)` 时，就把那幅手绘放在这里。在编辑器里，一行只有一张 `attachment://` 图片时，这一行就是这张图的块。其余都是文字。agent 读的、源码面板改的、卡板摘要的，都还是原来那段纯文本。解析集中在 `src/blocks.ts`，与运行时无关：

- `blocksOf` / `cardBlocksOf` 把文字切成块。切分时跟踪代码围栏，围栏里的指针仍算代码；行内指针和非法 id 仍算文字。
- 正文没放置的手绘仍属于这张卡，排在末尾，旧手绘在最前。老卡片、以及 agent 改写时丢了指针行的情况都靠这一条兜住。指向不存在手绘的指针，以及同一幅手绘的第二个指针，都会被丢弃。
- `textOfBlocks` 把流写回文字，块与块之间空一行。`freshDrawingId` 依次取 `d1`、`d2`……
- `withoutDrawLines` 给画不出手绘的读者去掉指针行：卡板摘要、引用进会话的内容、由卡片转来的成稿正文。
- `firstDrawingOf` 给卡板和关联图提供缩略图，取阅读顺序里的第一幅。

**一张卡可以有多幅手绘。** `CanvasCard.draw` 改为 `drawings: Record<id, strokes>`：

- 最多 `MAX_CARD_DRAWINGS`（12）幅；
- id 须匹配 `[a-z0-9]{1,16}`；
- 读取时丢掉没有笔迹的手绘。

老卡片的单幅 `draw` 读作 `drawings.main`（`LEGACY_DRAWING_ID`）。正文没有给它留位置，所以它排在最后，和以前一样。`putCard`/`patchCard` 接受 `drawings`，传空表会删掉这个字段。

**`BlockEditor` 不依赖任何编辑器库。**

- 每个文字块是一个非受控的 `CardTextarea`，没有自己的边框，所有块共用一张带边框的纸面。
- 每幅手绘是一个 `CardPad`，带「移除这幅手绘」。
- 每张图是一个 figure，移除按钮在悬停或聚焦时出现。
- 工具栏的「手绘」「图片」和粘贴图片，都插在最后聚焦的那个文字块的光标处：块在光标处一分为二，贴进来的内容落在光标前后两段文字之间。
- 移除一个块时，它两侧的文字合并成一段。
- 新加了但一笔没画的手绘不会保存。
- 不含图片的粘贴仍交给页面原有的粘贴处理（格式识别、去噪）。

编辑器用在两处：

- **新建草稿**：回车添加（`submitOn="auto-enter"`，沿用草稿原来的按键）。
- **卡片编辑**：⌘⏎ 保存（`submitOn="mod-enter"`）。Esc 用来收起画笔，所以画板提示写成「Esc 收起画笔 · ⌘⏎ 保存」。

**模式切换按格式区分。**

- markdown 卡是 阅读 / 编辑 / 源码：
  - 阅读：手绘嵌在原位渲染整条流（`CardFlow`）；
  - 编辑：块编辑器；
  - 源码：原文，能看到指针行。
- HTML 卡保留 渲染 / 源码 / 并列 和整卡渲染。它的手绘是页面批注而不是块，所以唯一的画板固定存在 `drawings.main` 上。

## Alternatives considered

- **编辑器库（ProseMirror/TipTap、Lexical、Slate）。** 按用户的约束排除：每个都是插件里的一大块包体，都带自己的文档模型，还得教它认手绘节点。只有三种块、只需拆分与合并，用不着它们。
- **在卡片上存一份 JSON 块模型。** 排除：agent、源码面板、引用、转成稿、卡板摘要都读 `card.text`。多一份表示，每个读者都得配转换器，两份迟早对不上。指针行让唯一的真相源仍是可读的 markdown。
- **仍只有一幅手绘，只是可以挪位置。** 排除：「这里画一下，这段后面再画一下」恰恰是用户要的场景。
- **contenteditable 编辑面。** 排除：混排内容里的光标和输入法行为，正是编辑器库体积的来源。普通 textarea 本来就能正确处理中文输入。

## Consequences

- `card.text` 里现在可能有 `![](draw://…)` 行，插件以外的读者会把它看成坏图。插件内的读者用 `withoutDrawLines` 去掉；agent 在文字里能看到这些行，保留的代价很小。
- 卡板结构：`drawings` 取代 `draw`。旧文件兼容读取，写入只写 `drawings`。
- HTML 卡除了画板改存到 `main` 下之外没有变化。

## Testing

- `tests/blocks.spec.ts`：切分、围栏、单独成行的图片、行内与非法指针、未放置与重复的手绘、往返、`freshDrawingId`、`withoutDrawLines`。
- `tests/block-editor.client.spec.tsx`：打开后原样保存、在光标处粘贴图片并拆分、非图片粘贴转交、移除后合并、没画的手绘被丢弃、改动上报。
- detail、strip、tab、link、board、quote 各测试都迁到 `drawings` 模型：509 个测试通过。
- 在临时实例上看图验收：
  - 阅读模式里手绘嵌在原位；
  - 编辑纸面与「手绘/图片」工具栏；
  - 先画一幅，再在正文中间贴图，然后保存；
  - 源码视图里的指针行；
  - 卡板缩略图取自第一幅手绘。
