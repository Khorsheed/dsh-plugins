# Agent Note: 章节编辑经输入框接力，本机恢复编辑现场

Status: implemented

## Problem

章节编辑器把依赖选区的「存为灵感」和与其无关的 Agent 续写按钮并列。续写时当前草稿可能只存在浏览器里，Agent 按要求读取章节时拿到的却是旧正文。编辑器只记住草稿文本，不记得章节、模式、光标和滚动位置，重新打开后还要自己找回写作现场。

## Decision

- 编辑顶栏只保留取消、字数和保存。「存为灵感」从编辑模式移除，独立「灵感」页和预览里的本章想法流程不变。续写是编辑框下缘的一条低强调入口，不再增加一排工具按钮。
- 续写先通过现有 `editChapterBody` 和 `baseHash` 冲突保护保存当前草稿。失败或 `stale` 时保留草稿、位置和编辑模式，不碰对话。成功后只清理已落盘的本地草稿、回到预览，再调用 `draftToConversation`，绝不调用 `sendToConversation`。已有输入内容保留，用户自行修改并决定是否发送。没有输入能力时隐藏入口；正文已保存但填入失败时如实提示。
- 生成的请求明确调用 `novel_read(what=chapter, chapter=N)`，要求以本次工具读取为准，不沿用对话记忆。请求携带准备时刚保存正文的最后 80 字作核对。末尾不一致说明已有更新版本：Agent 必须使用新读取的正文并说明变化，不能拿准备时的旧稿覆盖。
- 请求默认从正文末尾续写，不重复前文。为了衔接、修正矛盾或补足必要过渡，可以修改前文，但必须列出改动的原文片段和原因。调用 `novel_write` 时仍写回完整正文，包含保留内容、必要修改和续写，不能只交新增片段。
- 本机版本化记录按作品记住最后章节和模式，按章节记住光标/选区与 textarea 滚动位置。新的显式导航目标优先。主动返回目录会清除章节自动恢复，但不删各章编辑位置。取消同时清草稿和位置；保存与续写保留位置。现有草稿 key 和纯字符串值保持兼容。
- 恢复时把偏移夹到当前文本范围，在布局后恢复选区和内部滚动，并把编辑区带进视口，但不主动聚焦，避免手机自动弹键盘。选区变化立即记录，滚动写入经 `requestAnimationFrame` 合并，卸载时补写。损坏、过期或不可用的存储都回退到旧行为。

## Alternatives considered

- **常驻选区工具条或跟随 textarea 选区的浮层。** 否决：编辑就是编辑。通用引用菜单刻意排除 textarea，镜像文本测坐标又会增加复杂度，手机键盘周围尤其脆弱。
- **直接发送续写。** 否决：请求必须是普通可编辑的会话草稿。用户可以补充节奏、对话等要求，并自己决定是否发送。
- **不保存就填入续写请求。** 否决：模型读的是工作区正文，看不到浏览器草稿。为了让「当前基础」准确，准备请求前必须先保存，即使用户后来不发送。
- **一律禁止修改前文。** 否决：小幅修改可能是连贯续写所必需。有效的约束是交代改了哪些片段及原因，而不是静默重写整章。
- **服务端保存位置或跨设备同步。** 本轮不需要，也不符合现有草稿只在当前设备的承诺。无需修改宿主 Remote、正文格式或 Agent 工具 schema。

## Consequences

- 即使用户最后不发送，点击续写入口仍会保存当前正文。这是刻意行为：后续 Agent 必须能读到「当前基础」所指的版本。
- 主动返回目录就是退出章节/模式自动恢复；再次编辑某章时，其光标位置仍然可用。
- 位置记忆只属于当前设备的当前浏览器，只是便利功能，不是正文真源；工作区已保存正文和现有本地草稿仍是依据。
- 正文为空时续写入口不可用；尚未开写的章节仍走现有计划或对话流程。

## Validation

- 组件测试覆盖先保存后填入、不自动发送、请求里的精确章节读取与末尾摘录、允许说明原因的前文修改、保存冲突保留、章节/模式/草稿/光标/滚动恢复且不聚焦、显式导航优先和目录清除。
- 纯存储测试覆盖往返、作品与章节隔离、偏移夹取、损坏 JSON、非法范围、存储拒绝和末尾提取；现有草稿预览、取消与保存用例继续通过。
- `@khorsheed/dsh-canvas-novel`：41 个测试文件、317 个用例通过。
