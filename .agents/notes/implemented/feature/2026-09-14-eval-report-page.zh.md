# Agent Note: 报告页——不变量、配对、效率、一致性（I5 · T38）

Status: implemented

[English](2026-09-14-eval-report-page.md) | 中文

## Problem

八步流程的第 7 步——*finalize · 判官 · 报告*——在界面上没有落点。计算本身早就写好并冻结了：`analyzeBundle` 读一份 mission export bundle，答出四条不变量、推出的因子、过了闸的配对差值、判官一致性数字与并列的效率表。缺的只是一张页；在此之前看这些东西的唯一办法是 `dsh-eval report <bundleDir>`——一条命令行，对着一个读者得先知道的路径，还顺手写出三份没人要的文件。

建这张页的风险不在排版，在于：报告是这个 tab 里唯一一张**其全部价值就在于不肯多说一个字**的页。比较要过四条不变量，排名要 n ≥ 3，token 只在同模型内比，判了自家模型的判官要披露而不是剔除。这四条里的任何一条，都可能被一个「照发数据、把规则留给页面记得检查」的投影悄悄拆掉。

## Decision

- **`report` 是**导出**的投影，而且它自己找导出。** `runReport(runId, {outDir?})` 按写明的顺序找 bundle——调用方刚导的目录、plan 自己的 `exports`、`<题库仓库>/exports`（决策 11）——逐个试 `<runId>-bundle`，第一个命中的交给 `analyzeBundle`。一个数都不重算。
- **「还没导出」是一个带按钮的状态，不是错误。** 没有 bundle 的 run 返回 `bundleDir: null` 加上**找过的每一个目录**，页面把这句话和一颗导出按钮渲染出来。判断一个 run 是没导出还是坏了，靠的正是这两条事实；一片空白或一个抛出的 RPC 两者都不给。
- **比较闸在服务端合上：`comparisonAllowed` 为假时 `pairs` 是空的。** 数据根本不过线。另一种做法——把配对连同一个布尔值一起发下去——等于把这条口径变成客户端的一个 `if`，一次重构就能丢掉；而它守着的那一节，恰恰是不变量没过时读者最想看的一节。
- **`report` 一个字节都不写。** `results.jsonl` / `summary.md` / `usage.jsonl` 落盘仍然只有 `dsh-eval report --out` 一条路，页面把那条命令作为提示带上。打开一张页不该产生文件，而一次 run 的存档件放在哪儿是人的决定。
- **自评的标记属于**行**，不属于格。** 配对表的一行是两侧格子合起来的一个数；这些格子里只要有一格是被自家模型判的，整行就标出来。一个只出现在某几格上的提醒，等于没提醒。
- **「—」不是 0。** `toolCalls: null`（没有任何一轮报过计数）与 `cacheReadTokens: null` 都打破折号。「没人报过」和「一次没用」是两件事，只有「缺席」说得出前一件。
- **NaN 的 κ 过线时转成 `null`。** Cohen κ 在退化情形（评分者恒定）是 NaN。JSON 里没有 NaN，它无论如何都会变成一个悄无声息的 null；在投影这一层转，是唯一能把理由写下来的地方。
- **`finalize(agent, {runId})` 是人的一次点击**，以 `tab:<sessionId>` 记名，返回计数、逐格结局**和那次走的日志原文**。读者读不到的闸拒绝，等于无从处理的闸拒绝。页面在走之前问一次：这是从一张只读页上发起的整 run 写。
- **导出对话框现在把它写入的目录报出来**，tab 记住它作为报告的第一个查找位置。对话框收的是自由文本路径，不记住它，一个把 bundle 导到 plan 的 `exports` 之外的人，就会被告知他刚写好的那份「未导出」。
- **未导出态另给一个「换个目录找」的输入框。** 这条是真机上发现的、不是测试里想出来的：`t31-judge-panel` 当初是带 `--out` 跑的，它的 bundle 既不在 plan 的 `exports` 下、也不在 `<题库仓库>/exports` 下，而 `run.meta` 对导出去了哪里只字未记。没有这个框，页面就会把一份导好的 bundle 说成未导出，而唯一的出路是再导一次。
- **文案四节之外多带两条事实**，因为 `summary.md` 开头就是它们，丢掉会让这张页比它所映照的那份文件更不老实：expectedNs 全由 `tool:` 写入的红字警告，以及报告自己的保留条款。

## Alternatives considered

### 为什么不把配对连同 `comparisonAllowed` 一起发下去，让页面自己隐藏？

那是更小的载荷改动，也是显而易见的形状。但四条不变量正是这份报告值得读的原因：它们拦住的是「两个不同环境的 run 也能排出名次」。把布尔值放在它所管的数据旁边，等于把规则放进渲染器，而它只能活到下一次有人重构那一节为止。不发数据把规则变成结构性的——页面**做不到**显示一个 bundle 拒绝给出的差值——钉住它的测试断言的是「不存在」，不是某个 CSS 类。

### 为什么不调 `service.report` 再读 `ReportWrite.report`？

那是现成的入口，返回的正是需要的那份分析。它同时会往 bundle 里写三份文件。渲染一张页不该改动它所渲染的东西——读者打开两次 tab 就把 bundle 的 `report/` 重写两次，而一份本该只增不改的证据里会多出没人要的文件。`analyzeBundle` 是同一次计算去掉那次写，CLI 提示让落盘那条路只差一条命令。

### 为什么不在导出时把 bundle 目录记进 `run.meta`？

那样查找就从搜索变成精确命中。但导出是 mission 的动词不是 eval 的，而且人完全可以把同一个 run 反复导进不同目录（对话框就是干这个的）。记下来的那条路径只会指中其中一个、对其余都是错的，而且它需要一次当前并不存在的账本写。搜索顺序是三个候选，每一个都可能是读者有意选的；一个都没找到时，答案把三个都点名。

### 为什么不把判官标记留给前端从 `judgeAssignments` 里算？

页面已经收到了配对；把整份归属清单发下去在浏览器里 join，能少一个服务端函数。代价是「这个数背后是谁判的」被回答了两次——一次在 `summary.md` 自己的归属表里，一次在 tab 里——两者在任何一边改动的那一刻就能各说各话。这个 join 在投影里是八行，而且它把答案放在它所限定的那个数旁边。

### finalize 为什么不用模态框？

这个 tab 已经有一个模态框（导出），因为那道闸要求逐层确认。finalize 只有一个问题，而且它走的闸从不强推——被拒的格子留在原地并说明理由。两段式的就地确认问到了这个问题而不多开一个面，结果也落在同一张页上，而不是藏在一个已经被关掉的对话框后面。

## Consequences

- `EvalRemoteService` 多两个带会话参数的动词 `report` 与 `finalize`（共 20 个）。CI 的四个动词一字未动；两个新动词都**不**配模型工具——启动与释放的动词归界面（界面规格 R1）。
- `EvalService` 多 `runReport` 与 `finalizeView`；新增 `report-view.ts`，装 bundle 搜索、投影与 finalize 的整形。
- 报告子页建成；`placeholder.report` 删除，判官台是最后一个占位（T37）。
- `ExportDialog` 的 `onDone` 多带一个输出目录参数，store 以 `lookIn` 记住（随实验切换清空），报告页也能直接设它。
- T37 继承这张页的词汇：判官一致性那一块与自评标记，正是判官台要按格展示的同一批事实。
