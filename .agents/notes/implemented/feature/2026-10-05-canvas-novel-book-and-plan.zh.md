# Agent Note: canvas-novel 的成稿即书、结构化的章节计划、对话里的计划卡

Status: implemented

## 问题

第一版画布界面（[canvas-novel 画布界面](2026-10-05-canvas-novel-surfaces.zh.md)）在条子上每章一个 chip，每章再单开一个 `novel:chapter` 页。章节一多 chip 排不下，章节只能一页一页单看、没法往下读，章节页又和画布的成稿面重复。计划本身（`goal` 加几个松散列表）看不出剧情走向，帮不了人判断要不要确认。在对话里规划完一章，只留下一行通用的工具行，回不到它建的计划。

## 决定

- **条子收成一条细线**：当前章 / 待审 N / 伏笔台账 / 目录 · 共 N 章 ›。当前章是最早一章需要人的（有待审，或已抽取未审过），没有就是最后一章。每章的 chip 去掉了。
- **长篇小说画布的成稿就是书。** 体裁声明 `ownsManuscripts`，canvas-novel 用 `ChapterBook` 填 `canvas.board.manuscripts` 座位：目录页（每章一格的书脊、从哪章接着看、待处理 / 未审过筛选、每十章一组）和就地打开的章节阅读器。阅读器（`ChapterReader.tsx`）有阶段灯、计划块、本章待审、正文阅读栏、✓ 审过闸、下一章的开头预览，以及带目录的翻页。`novel:chapter` 页保留，作为同一阅读器的第二个宿主（入口 `ChapterPage` 现在在 `ChapterReader.tsx` 里）；原来的 `ChapterPage.tsx` 文件删掉。
- **计划围绕剧情来组织**：梗概 `summary`（必填）/ 走向 `beats`（每拍可带 `at`，可标转折 / 落点）/ 冲突 / 看点 / 伏笔 `foreshadowOps`（op + ref + 说明推进了什么、新埋了什么）/ 出场 `cast`（带角色和 POV）/ 章末钩子。老形状的计划（`goal`）会被 `novel_write` 拒掉，提示写明必填字段。
- **计划块随章节状态变**：规划中展开、带确认；有正文后折叠（主要看正文）；抽取后显示一行交付情况，加每个计划项的 ✓ / ✗。漏掉的伏笔操作进待审并挡住审过；漏掉的走向拍只做提醒。
- **对话里有计划卡。** canvas-novel 为 `novel_write` 注册 keyed 的 `tool.call.toolview` 座位。章节回答渲染成卡片（章号、标题、梗概、计数、等你确认 / 已确认标签），唯一的按钮打开回答里所写画布上的章节页。卡片本身不确认任何东西：计划要在页面上完整地看。计划等待确认期间，卡片每 10 秒重读一次，跟上在页面上做的确认。`novel_write` 的其它回答渲染成紧凑的一行，全文收在「详情」后面。
- **章节回答写明所在画布**（`已登记第 n 章《t》（画布 <id>）…`），几天前的卡片无论标签页当前显示哪块画布，都能打开对的那块。
- **画布提供 `canvasNav` 服务**（`openPage(canvasId, page, heading, param?)`），通过 `ctx.get('canvasNav')` 懒读。没有画布时卡片隐藏按钮。

## 考虑过的方案

- **保留章节 chip，改成可横向滚动。** 仍是一章一个 chip；80 章的书要的是目录页，不是更长的条子。
- **单独一个 `novel_plan` 工具，只有计划才出卡片。** keyed toolview 不能放弃某次调用，所以 `novel_write` 的行接管了所有写入（卡片、审阅），把它们渲染成普通一行。专用工具能让这些保持通用行，代价是模型多一个工具；等普通一行证明不够用再做。
- **在对话卡片里直接确认计划。** 一段摘要不足以判断计划；确认留在章节页上。
- **每拍一个「位置」字段和一列决策点。** 用户觉得「位置」奇怪（`at` 改为可选、由模型措辞），决策点又和确认计划冲突——不满意通过对话改。「变化」改叫「看点」。

## 后果

- canvas-novel 依赖这批改动里画布新增的两处接缝：带 `ownsManuscripts` 的 `canvas.board.manuscripts`，以及 `canvasNav` 服务。没有体裁的画布不变。
- `novel_write` 的工具行和其它插件的工具行长得不一样；README 的兼容性一节写明这一行需要 `tool.call.toolview` slot，没有时退回宿主的通用行。
- 已有画布上的老计划要重新规划（或手改成新形状）。
- `tests/client.spec.tsx` 覆盖条子、书（统计、筛选、就地阅读）、阅读器（翻页、预览、最后一章）、计划块的各个状态，以及 `novel_write` 行的解析和卡片入口。
