# Agent Note: side-chat M2 — inline ref expansion, the floating dock, the selection-quote probe, and context switching

Status: implemented

English | [中文](2026-09-16-side-chat-m2.zh.md)

## Problem

M1 shipped the conversation-scenario core ([side-chat M1](2026-09-16-side-chat-m1.md)): a right-Sidebar tab, one persistent agent session per contextKey, opaque refs. The [proposal's M2 row](../../../proposals/active/2026-09-16-side-chat.md) is the client-experience increment: ref chips that **expand inline to the full quote** (the quoted content travels with the conversation), a **floating dock mode** (chat beside a custom main panel — a canvas space — without yielding the detail tab), a **selection-quote probe** (is there an official seam for "any transcript text selection → ref"?), and a **multi-context switcher with unread marks**. Two published contracts constrain everything below: `ctx.sideChat.openWith`'s signature and the tab's `openTab('sidechat', { params: { contextKey } })` navigation params — the canvas M2 consumer already rides both, so M2 is additive only.

Two questions had to be answered before code, and the answers are what this note records:

**How does a quote shown as a chip survive restart?** Pending refs live in the contexts document, but once folded into a sent message they are gone from it — where does the transcript's chip come from then?

**Is there an official seam for transcript-selection quotes?** The proposal demanded a probe and forbade the DOM-anchor hack.

## Decision

**The transcript's refs are parsed back out of the durable message text — the fold round-trips.** The M1 fold format (`<quoted_context label="L">\n…\n</quoted_context>` blocks leading the user message, JSON-escaped labels) is ours, so `unfoldQuotedContext` inverts it: the journal projection lifts the leading run of blocks into structured `{ label, text }` refs and leaves the user's own text. User transcript rows carry `refs` (wire-additive), the transcript renders chips above the bubble, and restart changes nothing because the journal IS the store. A message not starting with a block passes verbatim (foreign text with a stray marker mid-body is never parsed); a ref body containing the literal closer breaks that block's parse and stays text — accepted, documented in the helper. The same `RefChips` component serves the pending-refs row and transcript rows: click expands in flow (label + full text, collapsible) — never an absolutely-positioned popover, because the panel roots clip overflow.

**The floating dock is the SHARED panel registered on `shell.overlay` (root-scope list seat, the worktrees badge precedent).** The M1 view's conversational core was extracted into `SideChatPanel` (selector, transcript, refs, composer, fetch/poll) with two thin wrappers: the tab (`SideChatView`, session scope, navigation params) and the dock (`SideChatDock`, root scope). The dock's slot store is a framework `defineStore` with a `persist` key — open state, served context, and frame position all survive reloads through the framework's own persistence, no hand-rolled localStorage. The tab and the root-scoped dock meet through an apply-closure controller (the worktrees panel-service pattern): the tab's `openDock` reaches the store actions once the overlay entry's inject attaches them; the dock's close hands the context back to the tab via `ctx.sidebarRight.openTab` (a hand-off, not a dismissal). Sends ride the CURRENTLY SELECTED session (`useSessions(s => s.current)`, the canvas space fence pattern); with none selected the composer is read-only. Degrades: no `shell.overlay` seat → the registration silently no-ops (slots.inject) and the tab's「弹出为浮层」button hides (probed lazily via `ctx.slots.spec` at the tab body's mount, after the shell's apply); narrow viewport → the entry hides and an open frame caps itself to the viewport.

**Selection-quote probe: NO official seam exists — registered as an upstream candidate, no DOM anchor.** The audit: (a) the `conversation.*` / `conversation.chat.*` SlotMap catalog (ui-conversation + ui-chat) has no selection/excerpt/quote seat — the assistant-actions list M1 uses is message-whole, not span-addressed; (b) every "selection" in ui-conversation is composer-input machinery (Lexical caret spans, `EditSelection`, `caretSpan()`), never transcript text; (c) message-tools — the message-surface plugin most likely to have built this — has no selection feature (its text moves are composer-draft backfill through the input machine); (d) `window.getSelection` over the transcript would be the DOM-anchor hack the design red line forbids. Conclusion: nothing to ride honestly. The composer keeps accepting pasted plain text (the standing fallback, unchanged).

**Context switching with unread marks, computed honestly on both sides.** `listContexts` rows gained `lastAssistantAt` / `lastActivityAt` (wire-additive): the host projects each context's journal — live from the session snapshot, cold from a persistence inspection, never a resume — so "did it reply?" is a projection fact, not a guess. The client keeps per-context last-seen marks in localStorage (the worktrees local-root idiom, with a version counter for whole-map recomputation); viewing a context marks it seen up to its latest assistant row, and a selector row whose `lastAssistantAt` is newer than its mark shows the dot. The selector synthesizes the current context in when it has no record yet (a never-sent conversation), and the list orders by last activity.

## Alternatives considered

### Why not persist sent refs in the record instead of parsing them back?

A second copy of what the journal already holds — it would drift on the first restart boundary (the M1 note settled this for the whole transcript). The fold format being ours makes the inverse parse exact for everything we wrote; anything we did not write stays verbatim. Parse beats mirror.

### Why not a `ctx.sideChatPanel`-style cross-plugin face or a second tab occurrence for the dock?

The dock is not another surface someone else drives — it is the same panel in a different frame, so the shared component plus a package-private controller is the smallest honest seam. A root-scope slot store is also the only state that fits: the tab is session-scoped and unmounts, while the dock's open/position must outlive it (persisted store), and the two meet only through the apply closure (the panel-service pattern), never through a published service.

### Why not compute unread on the host (a per-record `lastReadAt`)?

"Seen" is client UI state — which contexts the user has looked at, per browser, per profile. Persisting it host-side would mix presentation into the durable record, wrongly share it across browsers, and force state writes on every view. The host's part is the projection fact (`lastAssistantAt`); the mark is the client's.

### Why not implement selection-quote anyway behind a feature flag?

The only implementation available is `window.getSelection` over ui-conversation's DOM — a DOM anchor, the resort the repo conventions rank last and the task explicitly forbids. A flagged DOM hack is still a DOM hack, and it would ship an interaction the upstream must later support or break. The upstream candidate (a selection/excerpt seat beside `conversation.chat.assistant-actions`, or an `extraActions` owner carrying spans) is recorded below.

## Consequences

- Host (`types.ts`, `journal.ts`, `service.ts`): user transcript rows carry `refs`; `listContexts` rows carry `lastAssistantAt` / `lastActivityAt` and order by last activity; `unfoldQuotedContext` joins the shared vocabulary. All wire-additive — the published `openWith` signature and tab navigation params are untouched.
- Client: `SideChatPanel.tsx` (extracted shared panel), `SideChatView.tsx` (tab wrapper), `SideChatDock.tsx` + `dock-store.ts` (overlay entry and its persisted store), `RefChips.tsx` (inline expansion), `seen.ts` (last-seen store); `SideChatView.module.css` became `SideChatPanel.module.css` (+ `SideChatDock.module.css`); locales gained the M2 keys in both dictionaries; `contract.ts` gained `dockAvailable`/`openDock` on the tab face and the `SideChatDockInjected`/`SideChatDockProps` pair.
- `package.json` 0.1.0 → 0.2.0; new optional peerDep `@deepseek-ai/dsh-client-ui-layout` (the overlay seat's SlotMap merge) and devDep `@deepseek-ai/dsh-client-store` (the dock store's framework); `dsh.compat.notes` and both READMEs updated. No new runtime dependencies.
- One debugging lesson other packages may cite: **adding a dependency requires deleting the package's `lib/tsconfig.*.tsbuildinfo`** — tsc's incremental cache memoized the module-not-found from before `pnpm install` linked it, and `--traceResolution` only "worked" because it bypassed the stale graph.
- A React correctness fix worth restating: the panel's `rows` memo originally sat after the `fatal` early return — a hook-count violation that crashed exactly when the host-missing path flipped (caught by the client spec, moved above the return).
