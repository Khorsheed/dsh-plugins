# Agent Note：灵感空间视频与音频的打磨

Status: implemented

## 问题

视频功能上线第一天（`2026-10-20-reader-video-audio`、`2026-10-20-reader-local-transcription`）用户反馈：卡片看着和文章一样；视频在宽侧栏里铺满，转写稿只剩几行；转写稿没法好好翻译；也没有任何地方说明段落前的时间是可以点的。交互稿：`proposals/prototypes/reader-media-polish.html`（第 1 轮，当天定：B 站保持外链播放器、只做跳转——方案 A；视频卡不留简介；自动翻译是全局一个开关）。

## 决定

- **卡片和文章卡一样高。** 卡片墙是等高网格（来源时间、标题两行、摘要两行、药丸行）。有封面的视频/音频卡把封面放在第三列、跨标题和摘要两行，并去掉摘要，高度就对上了；窄屏的行式布局里封面在来源和标题右侧。YouTube 用 16:9 的 `mqdefault` 截图；其它封面带 `no-referrer` 加载（B 站图床拒绝外站 referrer）。
- **卡片上的药丸表示转写状态**，经新的 Remote `mediaStates` 读取（先看正在跑的本机任务，再看 `media.json` 的字幕记录），只有当某张卡在转写时才每 3 秒刷新。
- **控制收成一行，时间排成一栏。** 字幕 · 收起视频 · 来源/状态，B 站的限制收进 ⓘ。页签叫「转写稿」。转写段落左侧留 72 px，时间标记绝对定位在里面，前面一个 ▶，悬停提示「从这里播放」；第一次打开时有一条一次性提示（localStorage）说明点时间可以播放。
- **迷你条是同一个播放框缩小。** 往下滚过 160 px 时视频缩成 88 px 的画面，旁边是标题和时间（YouTube 还有播放/暂停和进度线）；回到顶部附近重新展开；点「收起视频」会固定成迷你条，直到点 ⌃。用 CSS 改 iframe 大小不会中断播放，也不会重新加载。
- **跟随只在手动操作时停止，而不是任何滚动。** 滚轮、触摸拖动、滚动按键会停止跟随，而且只在播放确实在前进时才算；「回到正在播放」恢复跟随。在预览里实测：播放器缩小本身会让正文滚动，单纯监听 `scroll` 会自己把跟随停掉。6 秒后自动恢复和「跟随」开关都去掉了。
- **翻译等转写稿完整再开始。** 转写进行中地球按钮置灰（正文每次轮询都会被替换）。「转完自动翻译」（全局一个 localStorage 偏好，默认不勾，地球菜单里也有）在显示完整转写稿时启动对照视图——前提是这对语言已经是 `available`，因为需要下载的翻译会话必须由一次点击触发。

## 考虑过的其它做法

**封面放在卡片顶部。** 在交互稿里被否：比相邻卡片高，网格的行对不齐。

**用自己的播放器播放 B 站视频，做双向同步**（方案 B）。用户暂时不要：清晰度低、流量经过宿主、属于灰色地带。

## 后果

- 没有封面的视频/音频卡保持原样（摘要加 ▶/♪ 类型药丸）。
- 设备上还没装翻译模型时，自动翻译不起作用，直到读者手动点一次地球按钮。
