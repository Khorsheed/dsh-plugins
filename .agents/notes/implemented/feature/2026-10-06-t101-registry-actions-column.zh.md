# Agent Note: datasets——单题集仓库合成一行，加「操作」列

Status: implemented

## Problem

题集 tab 给每个登记都单独加一个标题行，仓库里只有一个题集时也一样。所以单题集仓库占两行：先是写着仓库名的标题行，下面一行用题集 id 把同一个名字再写一遍。题集的显示名经常只差大小写，于是同一个名字会出现第三次。

操作也不好找。「交给 Agent 修改」「编辑登记」「删除」挂在标题行上，没有列头，单题集仓库的操作因此在它数据的上一行。

窄面板下表格会撑出版心：版本日期在中间断行，也没有哪一列能让出宽度。

## Decision

### 单题集仓库一行

`RegistryList`（`packages/datasets/src/client/RegistryList.tsx`）在三个条件同时满足时把登记渲染成一行（`SingleSetRow`）：有最新版本、没有问题、只有一个题集。

- 名字格用仓库名作打开按钮，悬停提示是题集的 ref。
- 题集 id 和仓库名不同时，才在下面用次要字号写出来。

多个题集、没有题集或有问题的登记，保留标题行加题集行。标题格跨所有数据列，「最新版本」除外：它单独占一个空格（原因见下面的窄宽度一节）。

### 次要名不重复

`quietNames(named, set)` 决定名字下面显示哪些次要名：

- 题集 id 和已显示的名字不同才显示。
- 显示名和 id、已显示的名字都不是忽略大小写相同（`sameName`）才显示。所以 `alpha` 下面不再写 `ALPHA`，`beta` 下面保留 `Beta tasks`。

多题集仓库里的题集行用同一条规则。

### 「操作」列

最右边新增一列，列头「操作」（`registry.colActions`），放登记级操作。单题集仓库放在它那一行上；多题集仓库放在标题行上，题集行留空。

格里有两样东西：

- 「交给 Agent 修改」：outline 文字按钮。
- ⋯ 触发钮：在 `src/client/more-menu.tsx`，照画布 `more-menu.tsx` 的样子包一层宿主 `Menu`。可访问名是「<id> 的更多操作」。

菜单有两行：

- 「编辑登记」：接原来的 `onEdit`。
- 「删除」：`danger` 行，接原来的 `onRemove`，T99 的删除确认框不变。

「用在哪些实验」仍是数据列。T99 层名格的悬停铅笔、横幅、删除确认都没动。

坏登记的提示（`registry.problemFix`）改为指向「操作」里的 ⋯，因为它原来说的行内「编辑登记」「删除」按钮已经没有了。

### 窄宽度

- **容器宽度 ≤ 720px：** 隐藏「最新版本」。所以标题行给这一列单独一个空格，不并进标题格的 `colSpan`。隐藏的格如果在跨列里，标题行会比题集行多出一列。第一版就这样把操作挤出了表格右边。
- **≤ 560px：** 沿用原来的折叠，行变成换行的块。
  - 操作单独占一行，题集行的空操作格隐藏。
  - 标题行的操作留在标题同一行，下面共用一条分隔线。这里操作格设成 `flex: none`，否则宽表的 `width: 1%` 会变成它的 flex basis，把按钮挤出去。
- **所有宽度：**
  - 版本日期不再在中间断行。
  - 空态「尚未用于任何实验」不折行（`.usageNone`），表格自动布局从名字列匀出宽度。有实验名时照常折行。
- **折叠后的标注：** 560px 及以下折叠时，题数的行内标注改用单位（`registry.itemsUnit`），读作「12 题」而不是「12 题数」。宽表列头仍是「题数」。
- **列表页标题：** 标题先占满自己的宽度（`flex: 1 0 auto`、`word-break: keep-all`）。窄面板上「添加题集」和导入按钮换到标题下一行，标题不再被挤成三行、在词中间断开。

### 图标

⋯ 图形 `IconEllipsisOutlineMedium` 和包里其他图标一样，内联进 `src/client/icons.tsx`。

完整跑 `scripts/sync-icon-artwork.mts` 目前会失败：它钉的是 0.1.7-rc.1 harness，画布要的 `IconCheckDoubleOutlineMedium` 这个 harness 里没有。这次只用同一个 harness 渲染 datasets 模块，所以生成头不变。

## Alternatives considered

**三个按钮都摆出来（交给 Agent 修改 / 编辑登记 / 删除）。** 在活实例上按 1440、700、420 px 对比过：

- 1440 放得下，但这一列宽约一倍，挤占「用在哪些实验」。
- 700 时操作格约占表格的 40%。
- 420 时仓库标题会断行（`harness-` / `bench`）。
- 每一行都有一个常驻的删除，旁边是同样分量的编辑按钮，点一下就到。

⋯ 菜单让人最常用的动作（交给 Agent）保持可见。两个少用的动作多一次点击，删除用危险色。代价是一眼看不到「编辑登记」，所以坏登记的提示改为点名 ⋯ 来补。

**全部收进 ⋯。** 不采用。「交给 Agent 修改」是这个 tab 改题集的主路径（T90），文案也要求它保持文字按钮。

**单题集仓库保留标题行，只加操作列。** 不采用。正是标题和数据分成两行，才让单题集仓库看起来像两样东西。

**窄宽度下隐藏操作列。** 不采用，文案要求操作始终可达。让位的是「最新版本」：版本在详情页点一下就能看到。

## Consequences

- 单题集仓库是一行。用户登记一样东西，列表上就是一行，名字不会出现两次。
- 每个登记的操作都在同一个有列头的列里，删除不再是标题上的散按钮。找「编辑登记」要多点一次 ⋯。
- 720px 以下表格去掉「最新版本」；560px 以下照旧折叠，操作单独一行。700 和 420 下都不会横向溢出。
- `more-menu.tsx` 是画布那份的手工副本，插件之间不互相 import。
- 图标生成器的 canvas/0.1.7 漂移仍未解决，归画布负责人或下一次 harness 基线迁移处理，不属于这次改动。

## Testing

`packages/datasets/tests/DatasetsView.client.spec.tsx` 的 describe「one row per one-set repository, every action in 「操作」 (T101)」覆盖：

- 单题集合并；
- 只改了大小写的显示名不重复；
- 多题集分组：列头数，标题格的跨列加上它单独的「最新版本」格，题集行的空操作格；
- ⋯ 菜单行一一对应 `onEdit`、`onRemove`、`onAskAgent`；
- 坏登记保留 ⋯。

原有测试改为通过 ⋯ 菜单触发编辑和删除。

活实例截图（1440 / 700 / 420、亮 / 暗、菜单展开、三按钮对比）已逐张看过，随 T101 报告交给协调者，没有提交进仓库。
