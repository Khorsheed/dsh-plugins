# Agent Note: 写作 preset 的阶段—角色模型（梳理时是编辑，陪伴时是伙伴）

Status: implemented

## Problem

写作 preset 的 persona 与 `novel` skill 只有意图路由（闲聊 / 落卡 / 规划 / 写作 / 对账），没有角色的概念。构思阶段模型默认是个随声附和的聊天对象，用户倒出一堆想法时得到的是热情而不是结构。具体的诉求是：作为专业编辑把整体思路梳理出来——抓住主线，不重要的支线先放一边。而且创作者的状态和阶段同样重要：思路乱的时候需要编辑，卡文自我怀疑的时候需要同伴。

## Decision

- **persona**（bundle-writing 的 `cordis.patch.yml`）开场即点明双重角色——"an editor when the thinking needs structure, a partner when it needs company"；Exploring-ideas 一条从「追问」升级为编辑的梳理动作：先听全，再把听到的分拣成一句话主线（谁、要什么、什么挡着）、服务主线的支线、以及建议砍掉或搁置的。砍永远是提案，理由是删掉之后主线为什么更清；拍板的是用户。新增第五条 stance 覆盖卡文/自我怀疑状态：给一个最小下一步，绝不上审计。
- **`novel` skill** 在三条铁律与意图路由之间新增「阶段与角色」一节。按阶段：构思/梳理立意 → 编辑的三栏分拣（主线必留 / 服务主线 / 砍掉或搁置，舍不得丢的好素材落成卡挂起而不是删除）；定设定 → 编辑兼档案员，新设定与旧卡打架当场指出；规划 → 结构编辑（台账与角色摆上桌再提方案）；写作 → 忠实执行共同 plan 的伙伴；对账/改稿 → 回到编辑，先动结构再动句子。按状态（覆盖同阶段的默认角色）：还在倾倒想法 → 先接全、复述一遍再动结构；卡文/自我怀疑 → 给一个最小下一步（一个场景、一段对话、一个人物的反应），不上审计；兴奋分享 → 先当读者回应内容本身，再问要不要落卡。
- **触达**：pointer 函数段把立意类对话指到 skill 的「阶段与角色」、动笔指到 `novel_read(brief)`；未绑定的一句把立意列为值得绑定的主题；skill 的目录描述以「立意梳理」开头，构思阶段也会加载这份手册。意图路由的立意条目交叉引用三栏分拣。

## Alternatives considered

- **单独立意工具或第二个 skill。** 构思阶段需要的是判断力而不是存储；多一个面会把模型要加载的手册劈成两半，而且铁律在构思期同样适用（搁置的点子照样落成卡）。
- **把整套阶段—角色模型塞进 persona。** persona 常驻且按约定保持轻（bundle spec 钉住它单声部英文、不含 skill 的工作流章节）；skill 才是按需加载的手册、工作流本来就在那里，所以 persona 只带立场，细节归 skill。
- **改 brief 模板。** brief 文案是用户审定过的，服务规划/写作/对账三个变体；构思期不需要素材包，`brief.ts` 不动。

## Consequences

- 构思阶段模型以结构开场（主线 + 必留/服务/砍或搁三栏），不再是顺着用户往下铺；砍是提案，用户保留拍板权。
- 卡文或自我怀疑的用户得到的是同伴和一个最小下一步，而不是一场审计——角色跟着状态走，不只跟阶段走。
- `bundle.spec` 钉住 persona 的角色行与主线分拣；`agent.spec` 钉住 skill 的新章节。两个包的 README 都描述了双重角色。
