# Agent Note: 画布 0.6.0：一页的类型页、分类页、桌面式卡板、类型提议行

Status: implemented

## Problem

P1a（`2026-09-30-canvas-card-types-p1a.md`）第一次用下来，暴露出五个问题：

- 类型页读起来是三个编号步骤，可第一次设计和之后重新设计其实是同一件事。
- 分类管理是压在卡板上的面板。有了卡片类型后，每行多了样式列和「设计」入口，面板太窄。
- 卡板显得平：chip 对比度低、卡和底同色，带标题的便签露出字面的 `#`。
- Agent 交了类型提议后，对话里没有任何东西通向用户做决定的那一页。
- 类型不记得自己为什么改过。

## Decision

**类型页收成一页**（8f6acd92，改版记录来自 5182a233）。从上往下：

1. 待确认的提议，有才出现。内容是这一轮的需求、卡面、字段表、采用后已有的卡会怎样，以及采用 / 不采用。
2. 「现在的样子」。
3. 「卡片样式需求」。这里放参考稿、设计按钮（有定义后显示「重新设计」）和改版记录：每次采用一行，能点回当时的会话。
4. 这个分类的卡，一律用同一种卡面。字段还空的卡由正文顶上。

没有回滚：想回去就再提一次。

**分类页**（b2d407b8）：

- 它是一种行位置 `{kind: 'categories', heading}`，与卡片、类型、成稿并列，所以刷新后还在，也有面包屑。
- 每行有色点、改名、卡数、样式、「设计 ›」和停用 / 重新启用。
- 它走标签页自己的目录写入。正在筛选的分类被停用时，筛选退回「全部」。

**桌面式卡板**（f3fee70d）：

- 卡板滚动区用 layer-1 底，卡片用 base 底加轻阴影。chip 加强了对比。
- 每个分类有一个色点：按目录顺序（含停用的行）取六种色相之一，与 `label-primary` 混色。这是唯一的颜色例外，色点永远跟着文字出现。
- 以 markdown 标题开头的便签，卡面以这个标题开头，加粗，不带 `#`。

**类型提议行**（e21500cf）：

- `canvas_propose_type` 的答复现在写明画布（`（画布 canvas_…）`）。
- keyed `tool.call.toolview` 注册从调用自己的结算块里读回这句话，给出「去类型页看看 →」。按钮会打开画布标签（`sidebarRight.openTab`，try/catch 包住），并把这一行放到该分类的类型页。
- 这个槽属于 ui-tool，经由注册表的结构化视图访问，沿用 eval 草稿卡的先例。没有 ui-tool 时，调用保持通用行。

## Alternatives considered

- **从调用参数里读画布。** `canvas_propose_type` 不接收画布参数，它作用于会话当前聚焦的画布。解析出来的 id 只出现在答复里，而解析答复也能让旧调用继续指向它当时去的地方。
- **分类管理留在面板里，把面板加宽。** 否决：面板盖住了它要管理的卡板；做成一页，面包屑、返回路径和刷新保留都由行模型白给。

## Consequences

- 画布对「只用 token」这条规则有一个颜色例外：分类色点。README 写明了这一点。
- 0.6.0 之前的答复不带画布 id，这些行不显示按钮。
- 下一轮：
  - 采用后唤醒 Agent（`agent.followup`）；
  - 卡片样式技能；
  - 迁移确认界面；
  - 兜底迁移按钮。它只在卡片落后于已采用版本时出现，绝不会仅仅因为提议被拒绝而出现。
