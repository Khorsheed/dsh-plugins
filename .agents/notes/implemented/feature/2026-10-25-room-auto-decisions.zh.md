# Agent Note: 房间自己的判断整理成一张场景表，并记录、展示出来

Status: implemented

[English](2026-10-25-room-auto-decisions.md) | 中文

## Problem

房间在两个地方调用决策模型（可选的 `typesafe` 服务，即 TypeSafe System One，默认 `jev-latest`）：把人发的消息归到某个进行中的任务，以及决定成员汇报的时机。这两处都没有任何地方显示。这些调用是房间代码发起的，不是模型工具调用，所以不会出现在任何会话里，Context Lens 也看不到。每次结果只记下了一部分：
- 消息归入已有任务时，记一条 `room/task-link`；
- 汇报时机记一条 `room/report-gate`，带结论和规则代码。

另一部分从来没记过：
- 房间发给模型的状态、问题和各选项概率；
- 用的模型、token、耗时、是否命中缓存；
- 调用失败的情况。

此外，有好几条规则在问模型之前就已经做出了决定，也没有任何地方写明是哪条。

## Decision

- **一张场景表。** `decisions.ts` 里每个场景一项，各自带固定的问题（`DECISION_SCENARIOS`）；另有一个共用、不会抛错的 `askDecisionModel`。目前的场景是 `task-filing` 和 `report-timing`，以后加新场景就是加一项。问题的措辞是代码里的常量，每次调用时只有状态是从房间记录里现拼的。
- **每次权衡过的判断都记录。** 每个判断记成一条 `room/decision` 事件：`scenario`、`outcome`、做出决定的 `rule` 或 `probability`，以及 `about`（任务归类记消息和任务，汇报时机记来自谁、给谁）。问过模型的，还带 `call`：服务返回的模型、耗时、缓存标记和 token；按原样发出的请求状态和问题；响应；以及 `failure`（原因和详情）。下列情况实际上没有做判断，所以不记：每条都交的设置、计划自带的节奏、关闭了自动分类、没有进行中的任务。不补历史。
- **设置。** 协作设置分成「协作」和「自动判断」两组。
  - 「自动判断」里有「自动任务分类」（`autoTaskFiling`，默认开；关闭后不带标签的消息一律算新任务）。
  - 「自动判断汇报时机」取代原来的「回报什么时候交给对方」二选一，改成一个开关，对应 `reportTiming` 的 `judge` / `each`。
  - 它下面的框里有「立即汇报阈值」（`reportThreshold`，0.1–0.9，默认 0.5）和「最长等待时间」（`reportWaitMinutes`，1–30，默认 3），后者决定暂存计时器的时长。
- **时间轴。** 新增 `room-decision` 节点，每个判断显示一行浅灰字，比如「合并到任务 3 · 修导出报错 0.82 · 1.2s」「bill 的结果立即汇报给 dsh（最后一个结果）」。只有问过模型的判断才有「查看判断」，点开后用 `{ sessionId, roomDecision }` 打开 `context-lens` 页签。

## Alternatives considered

**在房间里单独做一个「动态」页签。** 负责人否决：内容太少，撑不起一页。时间轴负责显示结论，Context Lens 负责显示请求。

**只记录模型调用。** 否决：负责人希望看到每一个权衡过的判断，包括规则做出的。

**让模型现写问题。** 不做：固定的问题让判断之间可比、也能测试。

## Consequences

- Context Lens 在「房间」页签里把记录下的模型调用当作请求列出（见 [2026-10-24-context-lens-room-rounds](2026-10-24-context-lens-room-rounds.zh.md)）；规则做出的判断只显示在时间轴上。
- 测试覆盖了：有调用和无调用两种情况下记录的归类和时机判断、关闭自动分类、设置的取值范围、判断那一行的文案，以及新事件的持久化。
