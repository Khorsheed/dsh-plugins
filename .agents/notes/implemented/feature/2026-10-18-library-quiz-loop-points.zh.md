# Agent Note: 图书馆 —— 考试闭环：状态化的考卷卡、一本错题账、考点

Status: implemented

## Problem

真实使用 mistake loop（见 [mistake-loop note](2026-10-17-library-mistake-loop.md)）暴露出四个缺口：最新考卷卡片在考完之后纹丝不动——「开始作答」一直是主按钮，同一套题永远占着主视觉位；章节考 tab 上堆了五个行动按钮，其中两个是同一个重考；项目页的「错题本」用另一套口径复制了站内的错题列表；掌握程度只有卡片 weakness，回答不了「这一站用户到底掌握没有」；用户也没办法指定一套题重点出哪些点。

## Decision

- **考卷卡片承载闭环**（`client/views/book.tsx` QuizTab）：读取最新一场判分并切换状态——未考 → 开始作答；过关 → 再出一套新题；未过关且有错题 → 重考错题 N——被降级的动作变成卡片底部的文字链接（重做这套 / 换方向再出一套）。出题范围 chips 去掉了「错题重考」选项（重考是目的，不是取材范围），错题列表删掉了重复的大按钮，成绩页直接承接（从分数页就能 重考错题 / 再出一套新题），交卷后不再是死路。
- **一本错题账**（`client/mistakes.ts`）：每份卷子取最新一场、判错且未作废的题。站内错题列表、折叠的「其他站」架（保留跨站的「围绕错题出一套」自由卷动作）、项目页统计行的「错题」入口（跳到最新错题所在的站）是同一集合的三个过滤视图；项目页的 `MistakesSection` 已删除。
- **考点**：quiz 站的 3–6 个考点在路线**草案**上拆分（每个 quiz 节点的 `points: [{ id, title }]`）——「采用」这一刻就是模型拆分的审查点。站点有考点后 `library_quiz` 强制每题带 `question.point`（站上的 id），`addPoints` 负责补点（不允许重复添加），整套卷漏掉某个考点会得到一条覆盖警告。掌握度按考点聚合（取探到该点的最新判分）；章节考 tab 把拆分渲染成可点的网格（已掌握 / 薄弱 / 未考），同时就是「重点出」选择器——选中的考点拼进出题请求（重点考：…），优先级高于状态默认的主按钮。过关语义不变（仍看总分线）：考点只做诊断与导向，不参与过关。
- **薄弱点随每次出题请求走**：站内弱卡片（weakness ≥ 1）在 tab 上显示为「薄弱」一行，并附加到预填的出题请求里——教练的"先考用户自己的卡片"不再依赖它记得去查。
- **出题请求带可选的题型 / 题量选择**（题型多选一排、题量一排，默认都是教练自己搭配）——选了就以后缀拼进请求。「凭什么 · 引用级证据闸」说明卡移出了 tab：闸门本身仍在服务端，每道题又已带证据来源 chip，这张卡纯属噪音。

## Alternatives considered

- **出题时才拆考点**：否决——每套卷会各拆各的名（「极限的定义」对「极限的概念」），掌握度永远聚合不起来，也没有审查时机；随路线草案拆分复用了「采用」这个现成的同意关卡。
- **考完自动再出一套**：否决——出题是教练的事（一轮会话），自动预填会在聊天中途劫持会话；成绩页的一键询问同样快，但不打扰。
- **按考点过关（每点都要过）**：暂缓——总分 80% 的线不动；考点先作为诊断跑起来，再谈参与过关。
- **单独的掌握度页面**：否决——考点网格放在用户行动的地方（章节考 tab），和选择器合并，一个表面既读又写。

## Consequences

- 站点有考点后，`putQuiz` 强制每题带 `question.point`——给有考点的站出题必须每题标注（拒绝会把合法 id 教回来）。
- replan 删掉某个考点 id 不会孤立历史（attempts 仍挂在各自的卷子上），但该点停止聚合。
- 考点随节点 id 在采用与 replan 中存续，与 quizStats / 讲义一致；`normalizeRoadmap` / `normalizeQuizQuestions` 宽松解析，旧数据照常读取。
