# Agent Note: 文档导入在本地拆章并复用对账

Status: implemented

## Problem

已经有小说原稿的用户，过去必须逐章粘贴或登记，画布才能开始建立作品记忆。一本书可能是一份 Word，也可能是一堆文本文件；交给模型拆分并改写整本书既慢，又容易丢失内容，还难以核验。

## Decision

- 「章节」页新增「导入小说」，可一次选择多个 `.txt`、`.md`、`.markdown` 文件。在宿主本机还可用「导入文件夹」调用官方 `directoryPicker`：native 的选择和读取留在宿主；3080 生产组合使用的 browse 后端则打开已注册的 `sidebar.workspaces.directoryFlow`。只有这个流程确认的路径会回传 Remote，由同一个 browse 能力校验，并读取它返回的规范化路径；native 请求携带路径会被拒绝。纯文本按 UTF-8 读取，失败时回退 GB18030。`.doc`、`.docx` 只提示转换格式，不再解析；空章和超过现有单章 200 万字符上限的内容都有明确错误。
- 目录读取最多递归 32 层、500 份支持文档、共 100MB，超限时明确标记截断。隐藏项、`node_modules`、`__MACOSX`、不支持格式和符号链接都会跳过。Word 文件只给出转换提示，不读取字节。预览只拿相对路径和选中支持文档的字节，不返回整棵目录树。
- 文件按文件名或相对路径自然排序合并，也识别中文章号。只按独立章节标题拆章：中英文数字标题、序章/尾声/番外和 Markdown 标题。没有标题的文档按一章导入；卷首内容并入第一章。绝不按字数硬切，也不让模型改写正文。
- 预览列出来源、标题和字数，可以取消勾选。确认后逐章调用 `importOwnChapter`。Remote 复用现有 `writeChapter` 并带 `byUser: true`，工作区权限、正文先落盘、章号分配和防覆盖行为不变。
- 某章写入失败会停止后续章节并报告实际成功数。预览记住已分配的章号，续传只处理剩余章节。全部成功后，用一条普通对话消息请求对这些实际章号对账。用户已有未发送草稿时只追加对账请求，不覆盖也不代发；界面不会声称后台已经整理完成。
- novel skill 按列表顺序走现有 `novel_extract(prepare) → subagent → novel_extract(import)` 流程。摘要、设定、人物、关系和伏笔的提取规则不变。

## Alternatives considered

- **私有后台模型流水线。** 否决：当前会话已经负责对账并展示进度；普通对话消息也能保留用户未发送的草稿，不需要另建隐蔽的 Agent 通道。
- **自画目录树、打包宿主 UI 或同时挂载两种 picker。** 否决：宿主已经提供 native 和 browse 两种交互，小说通过 slot 复用已注册的流程即可。native 不接受路径；browse 沿用宿主已有的目录列表权限和规范化返回，不新增文件系统能力。
- **服务端 Office 转换。** 否决：LibreOffice 和 Office skill 都是可选宿主能力，纯文本导入不需要转换器依赖。
- **让模型拆章或按字数拆章。** 否决：可能挪动、改写正文，还会为机械步骤增加模型成本。只有明确标题产生边界，无法判断的文档保持完整。

## Consequences

- `.doc`、`.docx` 需要先另存为 UTF-8 TXT 或 Markdown。标题不规范或没有标题的文档，需要先手动补标题才能自动拆成多章。
- 文件夹导入只在宿主本机提供，远程页面保留多文件上传。深度、文件数和总字节上限意味着特别大的作品可能需要按子文件夹分批，截断一定会显示。
- 部分导入会作为真实章节保留，不会自动回滚。用户可以续传剩余章节，已写入的章节不会重复。
- DOCX 最初使用 Mammoth，后来为了移除解析器依赖并修复浏览器加载而撤下；[纯文本导入决策](../bug-fix/2026-11-02-canvas-novel-text-only-import.md)记录这次部分取代。

## Validation

- 纯文本解析测试覆盖中英文与 Markdown 标题、卷首、自然排序和中文章号、GB18030、空文件、超长文件，以及 `.doc`、`.docx` 的转换提示。
- 真实嵌套目录验证递归、相对路径顺序、隐藏/依赖/不支持项跳过、符号链接拒绝、不读取 Word 字节的转换提示、native 取消、官方 browse 确认、能力缺失和 500 份文件截断标记。
- 真实 Remote + Store 测试验证 native picker 目录导入、native 分支拒绝路径、正文落盘、连续章号、`byUser`、`extractPrepare`、权限拒绝和已有正文防覆盖。browse 选择经过官方能力的规范化列表结果。
- 浏览器交互测试覆盖两个入口、预览、取消勾选、顺序写入、按实际章号对账、仅暂存消息、失败停止和续传、native picker 取消、宿主目录流程回退、能力缺失和远程页面隐藏。
- 包构建和测试覆盖类型生成、文本导入，以及在缺少 Node 设施时执行浏览器产物。
