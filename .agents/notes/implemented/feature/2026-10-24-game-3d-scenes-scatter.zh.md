# Agent Note: 3D scenes, instanced scatter and render-free checks

Status: implemented

## Problem

一个游戏 agent 在做「舆图加三座气候不同的山」时，向 3D 套件提了四件事，核对代码后都成立：

- dsh3d 整个 world 只有一份地形、一个高度函数、一套风格。`terrain()` 再调一次会多加一块地面，而不是换掉旧的。底色和雾在 `createWorld` 时就定死了。`onUpdate` 的回调无法移除。所以「换到下一座山」意味着要伸手进套件内部、手动释放资源。
- 重复的场景物件（92 棵松）是一棵棵克隆网格摆出来的；自己写的批量绘制，「指一下」又点不中。
- 检查里每次 `step` 都渲染一帧，而每个测试文件只有 8 秒，游戏越大越容易把自己的测试跑超时。
- 技能文档几乎没提 `assets/`，agent 以为项目里不能带图片和声音。

那个 agent 还说过 GLB 模型能导入、多场景是前提条件。这两点都不对：gltf 外观目前仍是占位方块，`world.scene` 也一直可以直接访问。记在这里，免得下次的提案再重复。

## Decision

- **场景。** `world.enterScene(name, setup, { style })` 先离开当前场景：上一个场景里登记的实体、批量物件、`onUpdate` 回调和地形全部移除并释放。套件共享缓存的材质不动，在任何场景之外登记的东西（玩家、镜头跟随）保留。随后套用这个场景的风格覆盖——先取 `game.json` 的 `style3d.scenes[name]`，再取 `opts.style`——涉及底色、地面颜色、水色、雾和光照，然后运行 `setup`；`setup` 里登记的东西都归新场景（挂在 `scene:<name>` 组下）。明暗层数和描边全局共用，因为所有材质共享它们。另外，无论在不在场景里，新的 `terrain()` 都会换掉并释放旧地面。`pick` 会返回当前场景名，`onUpdate` 会返回一个取消函数。
- **场景风格是游戏自己的数据。** `style3d.scenes` 用游戏自己起的名字作键，插件不带任何场景名或场景预设。`parseManifest` 对每个场景只保留颜色、雾和光照（最多 32 个场景），所以面板重写 `game.json`（定稿、自动上线、一页纸）时不会把它们丢掉。存成数据而不是写在代码里，给以后在面板里调单个场景的风格留了位置。
- **批量摆放。** `world.scatter(idOrLook, 数量或位置, { seed, spread, center, rotate, scale })` 只生成一次外观，把每个网格变成 `InstancedMesh`。每份按地形高度落地，朝向和大小由种子随机决定，重新加载后摆放不变。描边的顶点着色器现在会读 `instanceMatrix`，批量物件也有描边。点中其中一份，返回元素 id 和 `inst: 'id#n'`。`triangles()` 按份数计算面数。`highlight` 跳过批量物件，因为给整片树林画圈没有意义。元素外观实时重建时，会按原来的位置重新批量摆放。
- **检查时不渲染。** 在 `window.__GAMEDEV_TEST__` 下，`step` 推进逻辑，同步镜头位置和世界矩阵，但不画画面，所以已有测试里把位置换算成屏幕坐标的写法照样能用。`pick` 也这样同步。3D 套件的空白探测在读画布前先调一次 `dsh3dWorld.render()`，所以「什么都没画」照样能查出来。
- **技能文档。** 现在写清了 `assets/` 的用法（格式、相对路径、不能联网、单个文件 8MB / 全部 48MB 的上限）、`TextureLoader` 和 `CanvasTexture`、gltf 外观目前只显示占位方块，以及场景、批量摆放和检查时不渲染。15 万面明确标为建议值，按单个场景计算。

## Alternatives considered

**`world.swap(group)`（只换一个组）。** 最初是这么设想的。游戏 agent 指出，地形、风格和 `onUpdate` 回调都是整个 world 共用的，只换一个组，游戏还得自己去释放套件内部的东西。场景把这些全管起来。

**按场景换明暗层数和描边粗细。** 它们属于共享的材质缓存，按场景切换会重建所有材质，玩家的也不例外。颜色、雾和光照已经足以把湿润的青山和雪岭区分开。

**场景风格只由代码传入。** 更自由，也不用约定格式，但面板就永远看不到、调不了。用户选择了存成数据。

**远近细节（LOD）和地形分块加载。** 现在还用不上；一次只显示一个场景，本身就限制了绘制量。

## Consequences

- 不调用 `enterScene` 的游戏行为不变，唯一的区别是第二次调用 `terrain()` 会换掉第一块地面，而不是叠在上面。
- 批量摆放的物件是静物：没有逐份动效，也没有逐份的实体状态。
- 要读像素的测试得先调 `world.render()`；只测逻辑的测试会变快。
- 加载 glTF 仍是另一件更大的工作（加载器加面板预览）。
