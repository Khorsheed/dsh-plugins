# Agent Note：走查的十条——没落到 token 的颜色、被裁掉的一列、以及从没说出口的原因

Status: implemented

[English](2026-09-18-lab-walkthrough-fixups.md) | 中文

## 问题

T67 把实验室 tab 重做成四个阶段，协调者在临时实例上明暗两套逐页走了一遍。结构是立住的——交付表十四行在真数据上全部核到——剩下的是十条呈现层缺陷，其中三条值得说。

**五色选对了，涂错了。** 每一处调用点都按界面规格 §九 老老实实要的 `ok` / `busy`，而 `.chipTag[data-tone='ok']` 写的是 `--dsw-alias-state-business-primary`——**品牌蓝**；`busy` 写的是 `--dsw-alias-label-primary`，正文色。于是「已完成」是蓝的、「运行中」是灰的，恰好是 §九 讲得最死的那一对。这个没有测试抓得住：chip 的颜色是样式表里的一个 token，而 jsdom 既不加载样式表，也不算 computed style。

**判官台的第二份作答有一半在屏幕外。** `.judgeColumns` 还是三列网格——那是队列、产物、判据表三个面板时期的模板。T67 把判据表并进了每一列，第三列却留在模板里白占宽度：作答区只分到 1134 px 页宽里的 509 px，两列各 358 px，而 macOS 默认根本不画那条本可以提示「右边还有」的横向滚动条。

**就绪徽章在一个两个选手都不存在的实验上写着「✓ 环境就绪」。** 徽章数的是就绪**记录**，而记录只覆盖这次 run 真正探过的；一个谁都没解析过的对比组不是一个红叉，而是一个缺席，缺席就什么都不算。对比组表从另一头犯了同形的错——它按计划的 id 去筛注册表，注册表里没有的 id 就被静默丢掉。

## 决定

**W3 — 颜色。** `ok` → `--dsw-alias-state-success-primary`，`busy` → `--dsw-alias-state-business-primary`，两个 tab **手抄的两份** chip 一起改。外加一个 `tests/tones.spec.ts` 去读那两份样式表：断言每个 tone 取自己那族 token、点名那两处具体的错以免它们回来、并钉住 `neutral` **不取任何 state token**——给「未开始」写一条 tone 规则，本身就是灰的反面。

**W8 / W9 — 判官台。** 模板改两列，每列 `flex: 1 1 320px` 且不低于 320 px。每一列的产物**默认折叠**、判据表置顶：几千行 stage json 压在打分框上面，两列就永远不会在同一个滚动位置同时露出表单，而那是并排存在的全部理由。summary 上仍留着文件名和「替换掉 n 处指纹」，判官不打开也看得见洗法跑过。

**W12 / W15 — 徽章与红叉。** 徽章走**计划自己的受试对象清单**（先选手后判官），逐个解析：run 探过就用探针记录，否则用 review 的行，再否则就是「缺失」。一个受试对象不可能再从分母里消失。表里给每一个注册表没有的 `only` id 一行——不可点选、不可 provision、一排破折号加一个词——因为「这个实验点名了一个谁都没有的受试对象」是关于这个实验的事实，不是表里的一处空白。每个红叉行尾说清**为什么**，从 review 的**结构**读（status、有没有锁、锁还配不配、家目录哈希过没有）；只有「端点未解析」没有结构字段可读，才按 validate 自己写的 `condition <id>: ` 前缀去检查列表里找。没有一处是去解析句子的**含义**。

**W11 — 计划文件不在了。** `PLAN_UNREADABLE` 从检查列表里拎出来，走三段式：页面说「计划文件不在了」和怎么办，`cannot read plan file: /Users/…` 折进「详情」。共用的 `ErrorState` 多了一个可选的 `fix` 键，**只在分类器认不出原因时**生效——两份副本同改，所以两个 tab 仍是一份实现。

**W4 / W5 / W7 — 那些不是数字的数字。** 终态下「在态时长」显示「—」：账本量的是「最后一次转移到现在」，在一个已经结束的格子上那是「这次 **run** 多久以前结束的」。时间轴上那些等长灰条，查下来是阶段 chip 自己——它是 grid item，而 grid item 默认拉满——所以 chip 现在保持自己的宽度，旁边是一条**按本条记录内最长段归一**的真比例条。得分列改叫「判定」：一个表头写「得分」、格里写「终评」的列，是拿判官的名字给分数命名。

**W6 / W13 / W14 — 最后几个内部词。** `finalize` →「终评收口」；`rep` →「次数」；「保存草稿并 validate」→「…并校验」；「逐 rep Δ」→「逐次 Δ」。向导的预算缺省对齐计划模板的 30 分钟；第 ③ 步不再对一个**没东西可填**的步骤说「这一步填完才能往下走」。

**W10 — 并掉的那一页。** 五处文案还在把人指向「计划审阅」，它现在是实验设计的一部分。

## 影响

- `packages/eval` 850 → 860 条测试（多一个 spec 文件），`packages/datasets` 214；两个套件、两处 typecheck、gate 全绿。
- 两个客户端用例改的是**期望的数**而不是断言，而且两处改动本身就是修复：就绪徽章现在数出 3 个受试对象（原来数出 1 个），`LabReview` 的 provision 用例改成等「至少一个」——那个 id 在页面稳定之后本来就出现三次。
- `ErrorState` 在两个包里各多一个可选 prop。它**故意窄**：只作用在 `unknown` 那一支，认出来的原因照旧赢——分类器比任何调用方都更懂 `ENOENT`。
- **按文案不动的**：validate 的英文警告句（T66，宿主端）、`capabilities.source` 那条锁警告（T65 rev12 装上即消）、陈旧的「运行中 0/1」（README 写明的粗糙边）。
- **有一条我从代码里复现不出来**：W13 说「rep / 预算无缺省，下一步一直灰」。这三个字段自 T67 起就有缺省（`1` / `60` / `10`），而第 ③ 步唯一走不掉的情形是**题集没有声明任何阶段 schema**。我把预算缺省对齐成文案说的 30 分钟，并让那句通用的「填完才能往下走」不再出现在一个没东西可填的步骤下——但如果截图上是**空输入框**而不是选不动的阶段列表，真正的原因还没找到。

## 测试

两个包里 `pnpm test` 与 `tsc -b --noEmit`，然后 `pnpm gate`。最要紧的是 `tests/tones.spec.ts`：它在本轮修掉的那份代码上**会红**，两个包都会——回归测试必须有的性质就是这个。客户端用例钉住：徽章数的是计划的受试对象而不是探针、红叉带原因、注册表没有的受试对象是一行没有按钮的行、计划不在时三段式把宿主句子折起来、终态记录不显示在走的时长、每份作答的产物在 `<details>` 里。

## 其它方案

### 为什么在测试里读样式表，而不是断言计算出来的颜色？

因为没有东西可算。jsdom 不加载 CSS module，`getComputedStyle` 返回的是声明的层叠而不是 token 的值——要断言颜色就得上真浏览器，而这个套件不是、也不该为一条规则变成那个。读源码其实比看上去窄：它检查的是这条规则**讲的那件事**（tone → token 族），不是某个十六进制值，所以主题随时可以重新定义绿色，这条测试照样成立。

### 徽章为什么信 review 而不是注册表列表？

它们回答的是两个问题。review 是 `validatePlan` 针对**这份计划的受试对象**给出的结论；注册表是「这个仓库声明了什么」的一张清单。两者不一致时，被问到就绪的那个是 review，所以它赢；注册表的沉默只决定表里画不画得出那一行。让徽章也去惩罚一个清单里没有的受试对象，就是把两份载荷耦在一起，并且会在一个 review 刚刚判为就绪的对比组上画出红叉。

### 为什么折叠产物，而不是给每列自己的滚动条？

内滚区能让判据表一直可见，但它也**藏起了「下面还有多少」**，并且在一个本来就在宿主容器里滚的页面里再加一条滚动条——而按这次走查自己的证据，macOS 在你没碰它之前两条都不画。折叠会说清有多少（文件名和替换处数留在 summary 上），并把「什么时候把屏幕花在它上面」交回给判官。
