# Agent Note：让 Agent 润色灵感空间的译文

Status: implemented

## 问题

浏览器自带的本地翻译用小模型逐句翻：口语转写稿和长句翻得生硬，一个人用的术语前后也对不上。用户希望有一个像「考考我」那样的操作，把翻译交给会话里的模型。交互稿 `proposals/prototypes/reader-polish-translation.html`；2026-10-20 定：整篇分批做完；润色版替换机翻显示（可以切回，不记住）；暂不做术语表，也不做「只润色选中的段落」。

## 决定

- **把请求填进草稿，而不是悄悄调用。** 地球菜单里的「✦ 让 Agent 润色译文」（设备没有本地翻译时放在标题栏 / ⋯ 菜单里）会把请求填进会话输入框——标题、id、段数、分批读写的约定，再留一行给读者写要求——由读者自己发送。活由会话里的模型来做，花费在会话里看得见。
- **模型只依据原文翻译。** 它用 `reader_read` 读（带 ¶ 编号、时间和说话人），整段翻译；不把机翻发给它（那会让输入翻倍，还会把模型往机翻的错误上带）。批次之间的一致性靠同一轮对话里保留着前面的批次。
- **`reader_translate` 用纯文本写回**——每行 `¶12：译文`（没有 ¶ 的行接着上一段），可选一行 `文章：<id>`；用纯文本是因为有些模型会丢掉嵌套参数。它的回复给出进度和下一个 `from`，以此驱动循环一直做完。
- **润色层跟着原文走。** 每篇文章一个 `polish/<hash>.json`，存 ¶ → 译文、读者逐段的退回选择，以及一个源文本键：快照里的段落去掉 `[mm:ss] 名字：` 前缀后取哈希，所以给说话人改名不影响润色，重新转写则让它作废。
- **显示方式。** 每个润色过的段落，把它自己的内容包一层（`span[data-reader-orig-run]`），再追加润色译文和原文；由文章上的 `data-polish-view` 决定显示什么——机翻在运行时跟随地球按钮的视图，否则原文与润色对照。点段尾「✦ 润色」把这一段换回机翻；「看机翻」在本次访问里隐藏润色层。模型写回期间（或发出请求后的 20 分钟内）面板每 5 秒刷新一次，写回中途停了会给出「继续润色剩下的 N 段」。

## 考虑过的其它做法

**由宿主直接调用模型。** 没有公开的接口可用，而且会把花费藏起来；填进草稿让用户自己掌控。

**直接替换存储正文里的段落。** 不采用：笔记锚定在原文上，模型读的快照也必须保持原文。

## 后果

- 在润色译文上记的笔记，锚定的是原文里没有的中文；笔记最好记在原文上（对照视图）。
- 段数变了（重新转写）会悄悄开始一个新的润色层。
