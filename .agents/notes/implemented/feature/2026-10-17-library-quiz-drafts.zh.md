# Agent Note: 图书馆 —— 测验答题进度本地持久化（quiz-draft 存储）

Status: implemented

## 问题

答了一半的卷子一退出就没了：QuizView 把答题状态放在组件 state 里，退回站页、关掉侧栏、刷新页面都会清零。用户要求进度留存。

## 决定

一个小的客户端本地存储（`client/quiz-drafts.ts`）：每张卷子的进行中答题（当场判分的 `answers` + 开放题的 `drafts`）在每次作答/击键时写入 `localStorage`（`dsh-library:quiz-draft:<quiz id>`），打开卷子时恢复，交卷落账时清除。交给教练判分的场（开放题 prime 进会话）刻意保留草稿——判分前学员仍可能修改。

本地是它的语义：草稿不交卷就不落账，所以不动 host、不动 Remote 面、不需要迁移。卷子被 supersede 后旧草稿自然隔离（新卷子是新 id）；存储被禁（隐私模式）时退化为内存态，永不报错。

## 已否决方案

- **在 host 侧持久化进行中答题**（attempts 旁立草稿实体）：否决——未判分的答题不是图书馆的真相，且每次击键一次 Remote 调用换不来用户能感知的东西。
- **sessionStorage 而非 localStorage**：否决——报告的丢失正是"退出再回来"；随标签页而逝的草稿没有回答这个问题。
- **草稿放进面板 store（dsh-client-store）**：否决——面板 store 是内存态，刷新正是要修的丢失路径之一。

## 后果

- 重开一张卷子会看到之前的答案连同当场判定（选择/填空的对错判定也是保存状态的一部分）。
- 已落账的卷子重答从空白开始（交卷时清了草稿）——重考流程不变。
- 草稿按浏览器 profile 存（localStorage），不跨设备同步——进行中的答题可以接受；判分的真相在 attempts 里。
