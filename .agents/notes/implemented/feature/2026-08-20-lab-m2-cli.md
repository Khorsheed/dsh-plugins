# Agent Note: lab — the dsh-lab CLI (M2 second half)

Status: implemented

English | [中文](2026-08-20-lab-m2-cli.zh.md)

## Problem

The [lab proposal](../../../proposals/active/2026-08-19-lab-experiment-units.md)'s M2 includes a CLI face: scripts and agent-less flows (teardown scripts above all) need the eight verbs outside the host process. Building it surfaced a real M1 defect: `DockerProvider` never prefixed its argv with the `docker` binary, so the production `Exec` adapter would have spawned `run`/`pull`/… — the fake-exec unit tests encoded the same unprefixed shape, which is why 42 green tests didn't catch it.

## Decision

`src/cli.ts` is a thin bin entry (the mission cli.ts pattern: the entry guard must live in the entry module or tsdown chunking strands it); `src/cli-core.ts` holds `runCli(argv, io)` with injected stdout/stderr and exit codes 0 ok / 1 failure-or-refused / 2 usage. The CLI constructs the SAME `LabService` over a `child_process`-backed `Exec` (output caps 16 MB / 1 MB, `timeoutMs` → SIGTERM then SIGKILL after grace), so verb semantics — the gate, the ceiling, reconcile — are shared, not duplicated.

The mission face adapts to the `dsh-mission` bin, wiring exactly what that bin exposes: `release` gates on `dsh-mission is-releasable`'s exit code (0 releasable / 1 not / anything else throws → fail closed), and `verify` records through `dsh-mission annotate --ns lab --payload <json>`. Refs / artifacts / checkpoints have no mission-CLI verbs, so the CLI face warns once per kind and skips them; full registration parity stays with the in-host `ctx.lab` face. Presence is probed by spawning `dsh-mission --help` — any exit code counts as present, a spawn-level failure (ENOENT) means absent and the face degrades to the force-plus-warning path. `MissionFace.isReleasable` widened to `boolean | Promise<boolean>` so the in-process sync service and the subprocess CLI share one structural type.

The prefix defect is fixed at the provider: every command goes through a private `docker()` helper that prefixes the binary, and the fake `Exec` in `docker.spec.ts` now REJECTS any unprefixed invocation — the test double enforces the production contract instead of encoding the bug.

## Alternatives considered

- **A separate CLI code path not reusing `LabService`** — rejected: two semantic implementations of the release gate would drift; one kernel, two adapters.
- **Registering refs/artifacts from the CLI by shelling to per-verb mission bins that don't exist** — impossible without extending mission's CLI (another package's surface); the warn-and-skip degradation keeps lab independent and states the gap plainly.
- **Reading mission's JSON store directly from the lab CLI** — rejected: the mission proposal forbids consumers hand-writing its files; the bin's exit-code contract is the sanctioned script path.
- **Leaving the fake exec unprefixed and fixing only the provider** — rejected: the tests would keep passing against a contract production violates; the double now fails loud on any unprefixed argv.

## Consequences

- 50 tests; `tests/cli.spec.ts` runs the real entry (via tsx) against stub `docker` / `dsh-mission` binaries on PATH: usage exit 2, acquire JSON + label argv, the release gate's refuse/proceed/fail-closed trio through the mission bin's exit codes, the unbound-unit force path with warning, verify's verbatim JSON + `annotate --ns lab` call, and reconciled status.
- The terminate grace (`terminateGraceMs`, default 2 s) is real time in CLI tests — the release tests take ~2.6 s each.
- CLI-mode registration is partial by design (documented in both READMEs); if script-side registration becomes a real need, the change belongs to mission's CLI surface first.
- The docker-prefix fix changes no test-visible behavior beyond the new prefix assertion; production behavior changes from broken to working.

## Testing

`packages/lab/tests/cli.spec.ts` (8 tests) spawns `node --import tsx/esm src/cli.ts` with stub binaries (shell scripts logging argv to `$LOG`, answering from `$STUB_*` / `$MISSION_EXIT` env vars); `docker.spec.ts`'s fake `Exec` asserts the `docker` prefix on every call.
