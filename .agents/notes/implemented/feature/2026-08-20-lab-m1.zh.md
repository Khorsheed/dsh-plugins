# Agent Note: lab — 受控实验单元，里程碑 M1

Status: implemented

[English](2026-08-20-lab-m1.md) | 中文

## Problem

dataseek-eval 计划需要受控实验单元：隔离、条件一致、可重复的执行环境，其生命周期——获取、物化输入、取回产出、释放——此前没有插件承接。mission 有意只持有资源释放许可而不碰资源生命周期；datasets 有意不提供只读 worktree 视图之外的物化。本笔记对应 [lab 提案](../../../proposals/active/2026-08-19-lab-experiment-units.md)的里程碑 M1：`ctx.lab` 服务面 + docker provider——acquire / populate / collect / release / status、环境指纹、孤儿进程补偿、`maxConcurrentUnits` 上限。CLI 属 M2（连同 checkpoint / verify / archive），模型工具属 M3。

## Decision

交付为 `packages/lab`（`@khorsheed/dsh-lab`），纯 host，骨架照 ankh-guard/mission。`LabService`（`src/service.ts`）持有动词语义；`DockerProvider`（`src/docker.ts`）经可注入的 `Exec` 运行器调 docker CLI（生产环境是 `ctx.subprocess` 适配器；测试是脚本化假件），因此单测不需要 docker daemon。

**docker daemon 即注册表。** lab 不持有状态文件：单元 id、环境指纹、mission/run 绑定都骑在容器标签上（`dsh-lab.unit` / `dsh-lab.fingerprint` / `dsh-lab.mission` / `dsh-lab.run`），`status` / `release` / `acquire` 通过 `docker ps` + `docker inspect` reconcile（single-flight）。宿主重启不丢任何东西——release gate 照样保护 reconcile 回来的单元，因为 mission 绑定在标签上存活。invariant 伴生件（`src/invariant.ts`）是刻意的所有权预留，无数据可查。

**环境指纹是机制。** `acquire` 解析镜像的第一个 repo digest（回退镜像 id，本地缺席则先 pull），经探测式 `MissionFace`（`setRefs` / `addArtifact` / `isReleasable`，在 `src/types.ts` 里结构化声明——调用时 `ctx.get('mission')` 探测，绝不 import；插件独立性检查器禁止这条边）把 `{resource, fingerprint}` 登记进 mission 的 refs。登记类写入在插件缺席或失败时 warn 跳过，永不阻塞资源动词。

**release gate fail closed 且不可绕过。** 有 mission 绑定且插件在场时，`isReleasable` 裁决：未置 releasable → 拒绝；查询出错 → 拒绝；此路径上不存在 force 标志。无 gate 时（未绑定，或运行中途插件缺席），release 要求 `force: true` 并告警——这把 lab 提案的「warn 并放行」与 mission 提案的「显式 `--force`」对齐为：warn 且仅在 force 后放行。

**输入：两条诚实的路径。** 容器创建后无法追加挂载，因此零拷贝只读路径是 `acquire` 的 `mounts`（bind，`:ro` 由调用方选择），`populate` 则把宿主机目录 tar 拷贝（`docker cp`）进运行中单元的可写层。提案的「populate = 挂载」一行已据此修订。目录路径就是全部内容接口——datasets `worktree_path` 的产出或调用方自供路径皆可；lab 在代码层面不与 datasets 见面，层白名单由产出路径的那一侧强制。

**孤儿进程补偿。** 每条容器内命令都经过 `sh` wrapper，把自身 pid 记到 `/run/dsh-lab/pids/`；`terminate` 先按这些 pid SIGTERM 清扫（best effort——容器已停止时清扫会失败，这是预期内的），等待 `terminateGraceMs`，然后 `docker rm -f`。覆盖范围仅是 provider 自己的 exec 路径，与提案风险节声明的一致。

**`maxConcurrentUnits`**（config，默认 4）是纯数字上限：达到上限 `acquire` 拒绝并报错明确。它挡住误并发——误并发会悄悄毁掉对耗时敏感的测量——而不假装做调度。

## Alternatives considered

- **`populate` 走延迟启动**（acquire 只创建不启动，populate 登记挂载，首次使用时启动）——否决：lab 没有 exec 动词可锚定「首次使用」（编排方拿资源标识直接 `docker exec`），创建而未启动的单元要么不可用、要么逼出第八个动词；acquire 时挂载 + 拷贝式 populate 以无幻影生命周期状态的形态覆盖两种需求。
- **`$DSH_HOME/state` 下的宿主机单元注册表文件**（mission/ankh-guard 模式）——否决：它复制 docker daemon 已知的信息且可能与之漂移；标签 + reconcile 以零自持有持久化实现重启存活，兑现提案的「lab 自身不新增持久化」。
- **release 无 force 直接 warn 放行**（lab 提案原始措辞）——在交叉阅读 mission 提案后否决：该提案明确要求 lab 走显式 force；一个既无 gate 又无显式确认的不可逆销毁是更差的并集。
- **登记失败即 acquire 失败**——否决：mission 提案规定登记类写入 warn 跳过；严格性住在不可逆操作（release）上，且那里 fail closed。

## Consequences

- 26 个测试在无 docker daemon 的条件下覆盖动词语义：gate 的拒绝/放行/fail-closed/force 四路径、登记 warn 跳过、并发上限、指纹解析（digest / id 回退 / pull / 无法解析）、pidfile wrapper 与 terminate 清扫顺序、模拟重启后从标签重建注册表。
- 真实 docker 验收（委派取消后的孤儿收割、跨镜像指纹差异、上限拒绝）是对着活 daemon 的冒烟工作，不是单测；单测钉死的是这些冒烟所走的 argv 契约。
- `populate` 是拷入单元——输入需要 pin-commit 不可变性的调用方必须用 acquire 时的 mounts（datasets `worktree_path` 流程）；两个 README 均已写明。
- 镜像必须自带 `sleep` 与 `sh`；distroless 镜像需要自定义保活 `command`，且失去 pidfile wrapper。
- `worktree` provider 保持只有接口形状；落地时必须带上可比性警告（隔离强度差一个量级）。
- M2/M3（CLI、checkpoint / verify / archive、`lab_*` 工具）已在提案中设计，刻意缺席。

## Testing

`packages/lab/tests/`（26 个测试）：`docker.spec.ts` 用 `Exec` 假件脚本化（指纹偏好/回退/pull/失败、acquire argv 含标签/挂载/env/workdir/保活命令 + pid 目录创建、populate 的 wrapper mkdir + `docker cp`、collect、terminate 先清扫后 rm 的顺序含清扫失败容忍、`listManaged` 标签重建与空情形）；`service.spec.ts` 在内存 provider 与脚本化 `MissionFace` 上驱动 `LabService`（refs 登记、跨镜像指纹差异、上限拒绝、mission 缺席/失败的 warn 路径、populate 默认 target、collect 产物登记、release gate 全部四条路径、重启后 reconcile 含 gate 保护、未知单元报错）。
