# Agent Note: 画布与卡片有真删除

Status: implemented

## Problem

M1 以来画布空间只能归档，这是沿用 v1 稿纸的规矩（[灵感画布](2026-09-13-inspiration-canvas.zh.md)：`ctx.fs` 没有删除方法，所以「没有删除」）。放到画布上，这条规矩说不通了：画布不是用户工作区里的文件，而是插件自己状态根下的一个目录。「去文件管理器里删」等于让人手动去找 `$DSH_HOME/state/canvas/<id>/`。测试用的画布、误建的卡片越积越多，都堆在已归档区里出不去。2026-09-27 评审时，用户选了真删除，不再只归档。

## Decision

**新增两个 Remote 动词，和所有变更类动词一样 agent 优先。**

- `deleteCanvas`：删掉整张画布。
- `deleteCard`：删掉一张卡片，连同所有进出它的连线。它就是一次普通的、带版本守卫的 `canvas.json` 重写，走 `mutate`，所以写入过期时会重放一次，和其他板面变更一样。卡片的位置记在卡片自己身上，删掉后不会留下别的残余。

**删画布，是用 node 的 `rm -r` 删插件自己的状态目录。** `ctx.fs` 仍然没有删除原语，所以 `CanvasBoardService.deleteCanvas` 分四步：

1. 先查会话解析出的模式，`read-only` 下直接拒绝，和围栏对写入的「默认拒绝」一致。
2. 经 `ctx.fs` 确认这张画板存在。
3. 执行 `rm(canvasDir, { recursive: true, force: true })`。id 先经过 `normalizeCanvasId`，不可能穿越到别的目录。
4. **再经 `ctx.fs` 读一遍**，画板还在就回 `io`。

最后这一步读回是诚实的关键：状态根如果在 node 够不着的挂载上，`rm` 对一个不存在的路径也会「成功」，这时删除会如实报失败，不假装删掉了。删除成功后，所有会话对这张画布的焦点也一并清掉。

删目录的函数做成构造参数（`RemoveTree`），spec 用它在内存文件系统上驱动删除。

**删除只给人，不做成 Agent 工具。** `tools.ts` 没有暴露这两个动词。Agent 可以提议、可以归档，但不能销毁。

**界面：**

- **卡片**：每张卡的 ⋯ 菜单（宿主 `Menu`，卡板和详情页都有）提供「归档」和「删除」。归档仍能在 toast 里撤销；删除要过一次普通的确认 `Modal`，不用输入画布名，因为对话框标题已经写明了删的是哪个。
- **画布**：打开画布的 ⋯ 菜单提供「归档画布」和「删除画布…」。已归档的画布是只读的，所以它的横幅上「恢复」旁边多了一个「永久删除…」。
- **标签条**：删除成功后，客户端 face 调用 `selection.forget`：
  - 去掉这张画布的所有行，或这张卡片那一行；
  - 如果正在显示的行被删了：删的是卡片就退回它所在画布的卡板，删的是画布就换到相邻那一行，不会留下一行点开是「找不到」。

v1 稿纸不变：它的文件在用户的工作区里，仍然没有删除。

## Alternatives considered

**维持只归档**（原来的做法）。放弃的理由：画布在插件状态里，不在用户的文件里，用户没有任何地方能删它，已归档区只会越堆越多。

**软删除（打个墓碑标记，连已归档区也看不到）。** 不采用：这只是换了个更糟名字的归档。字节照样留着，还多出一层隐藏状态，要另想怎么恢复。

**先请宿主加一个 `fs.remove` 接缝。** 长远看这才是对的形态，但要走上游变更流程；而且状态根是插件自己的目录，不是受围栏保护的工作区路径。`rm` 只作用于 `canvasDir(normalizeCanvasId(id))`，读回这一步会让缺口暴露出来。宿主哪天有了删除原语，存储层就切过去，这个接缝随之去掉。

**输入画布名才能确认。** 用户认为对笔记工具来说太重了，普通确认框就够。

**给 Agent 一个 `canvas_delete_card` 工具。** 不采用：销毁留给人来做。Agent 想让什么消失，可以归档，而归档能撤销。

## Consequences

- **贴进来的图片不会回收。** 删卡片或删画布，丢掉的只是 `attachment://` 指针；像素仍留在宿主的内容寻址附件库里，因为那个库没有删除 API。README 的「已知限制」写明了这一点。
- **删除不可撤销。** 和归档不同，删除没有撤销 toast；确认框是唯一的防线，框里写明了「无法恢复」。
- **状态根在够不着的挂载上时删不了。** 这时存储层回 `io`，不谎报成功。
- [灵感画布](2026-09-13-inspiration-canvas.zh.md) 那篇里「稿纸没有删除」的结论对稿纸文件依旧成立。本篇只在画布空间内取代它。

## Testing

- `tests/board.spec.ts`：
  - `deleteCanvas` 删掉目录、清掉焦点，另一张画布仍在列表里；
  - 拒绝不存在的画布和非法 id；
  - 删除函数抛错时回 `io`，删完文件还在时也回 `io`；
  - 只读模式下拒绝；
  - `deleteCard` 去掉卡片，只去掉碰到它的那些连线；卡片不存在时回 missing。
- `tests/remote.spec.ts`：两个动词都把调用方 agent 的会话传下去。
- `tests/strip.client.spec.tsx`：`forget` 退回卡板那一行（没有就插进来）；删的不是正在显示的行时视图不动；删掉的画布把视图交给相邻行，没有相邻行就变空。
- `tests/tab.client.spec.tsx`：
  - 卡片 ⋯ →「删除」确认之后才写，取消什么都不写；
  - 画布 ⋯ →「删除画布…」能删掉画布；
  - 已归档画布的横幅提供「永久删除…」，同时两个 ⋯ 菜单都隐藏。
- `tests/detail.client.spec.tsx`：详情页 ⋯ 先归档一张收下的卡，确认后再删除它。
