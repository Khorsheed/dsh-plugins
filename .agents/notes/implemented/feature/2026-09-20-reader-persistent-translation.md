# Agent Note: the reader's translations persist

Status: implemented

## Problem

The reader's owner reads mostly LONG articles, and every page reload wiped all three client-side translation layers — the sentence memory, the translator sessions, and the globe records — so a reload re-paid the whole model run. Two of the three cannot survive (a `Translator` session needs a user gesture to build; the globe record is inert without one), but the sentence memory is just strings, and strings can persist.

This is a deliberate DECISION REVERSAL, approved by the user on 2026-09-20 with the design below. The decision being reversed — "the translated text never leaves the page" — was established across [the reader rewrite](../feature/2026-09-17-reader-rewrite.md) (which owns the persistence seams this builds on), [the on-device translation note](../feature/2026-09-18-reader-on-device-translation.md) (whose rejected "cache translations" alternative this supersedes), [the session-memory note](../feature/2026-09-19-reader-session-memory.md) and [the state-boundaries note](../architecture/2026-09-19-reader-state-boundaries.md) (whose boundary rule put translated text in never-persisted browser memory). What made the reversal safe: the privacy argument was always about a NETWORK, not a disk — translations on the host's state directory are derived content of pages the reader already read, the same sensitivity class as the cached originals sitting next to them; and the failure the rule prevented (a persisted globe record that cannot drive a session after a reload) is orthogonal — sessions and the globe record still never persist, and the globe still stays off until the gesture.

## Decision

Two host-side tiers, reusing the store's existing machinery (`store.ts` sidecar files, atomic commits, `pruneBodies`), plus a write-through page mirror:

- **The global sentence memory** (`translationMemory`): the table lives in one named file (`bodies/translation-memory.json`); the document carries only a manifest (`version`, `file`, `entries`, `chars`, `updatedAt`), because the document is rewritten whole on every commit and a 50k-sentence table must not ride `recordRead`. Keys are `<src>→<tgt>:<sentenceHash>` — the pair is part of the key, which also settles the old smell of the page memory keying on the bare sentence. Values carry source, translation and `lastUsedAt`; the cap is 50 000 entries with LRU eviction.
- **The per-entry translation** (`annotations[entryId].translation`): `{ version, pair, bodyHash, segments, translatedAt, lastUsedAt }` — a hash→translation MAP, never translated markup. A body re-fetched with minor edits invalidates only this exact-fit record (`bodyHash` mismatch); every unchanged sentence still hits the global tier. Large maps sidecar through the same `writeBody`/`bodies/` mechanism bodies use, and `pruneBodies` sweeps their orphans (along with the memory file's).
- **One shared budget, no TTL**: `cache.translationBudgetChars` (default 64 MB of characters, read/write through the existing `getCachePolicy`/`setCachePolicy`). Translations deliberately do NOT inherit the 24 h body TTL — rebuilding one costs a gesture plus per-sentence model work. `boundTranslations` (a pure function in `store.ts`) evicts LRU by `lastUsedAt` across BOTH tiers in one ordering, and evicts schema-version mismatches on sight. Reads never rewrite the file: the LRU stamp moves when a run reports what it reused (the batched `recalled` list), not when hashes are asked for.
- **Schema versions on both tiers** (`TRANSLATION_STORAGE_VERSION`): a browser Translator model upgrade or a segmentation change bumps it, and every old record becomes a MISS, evicted lazily by the next write or budget pass — never wiped eagerly.
- **Three Remote verbs, minimal by construction**: `getEntryTranslation(entryId)` (the exact-fit map, resolved host-side), `getSentenceTranslations(pair, hashes)` (a slice — the client hashes the body's sentences itself, so the whole table never crosses the wire), `rememberSentences(pair, entries, recalled, entryId?, bodyHash?)` (one batched write per run: upsert learned, bump recalled, rewrite the entry map to the run's full sentence set; file before document, `storeRaw`'s order).
- **The client**: `translate.ts`'s `MEMORY` is keyed by pair now and is a write-through MIRROR — `runTranslation`/`translateTexts` return `learned`/`recalled` lists, and the pane persists them in one call per run (the run is the batching boundary; there is no per-sentence write). `startTranslation` warms the mirror before spending the model — entry map first (gated on pair + `bodyHash`), then a global slice for what it did not cover — and the wall pass warms per language group. Sessions, the globe record, and the restore choreography are unchanged: after a reload the globe is off until the reader clicks it, and then the body re-paints from disk with the model untouched.
- **The linkage rule** (user-approved 2026-09-20, same day): an entry's map dies with its BODY — budget eviction in `boundAnnotations`, a `storeEntryBody` whose `bodyHash` no longer matches (the client hashes the markup it stores; a same-body re-store keeps the map), and `removeSource` (the caller passes the entry ids it parsed; a link source's one entry is derivable host-side) all drop the entry's translation in the same commit. The global sentence memory never participates — it is cross-entry by design. A body that is EXPIRED but still on disk keeps its map: TTL is a serving decision, not a removal, and the next successful refetch's `storeEntryBody` is where the linkage fires. Cached bodies are NOT linked to source deletion — the body budget owns their lifetime, as before.
- **The storage surface** (user-approved 2026-09-20, same day): two more verbs — `getStorageStats` (per-tier counts and characters, aggregated host-side; the tables never cross the wire for a readout) and `clearTranslations` (drops both tiers, and nothing else; the commit's own `pruneBodies` takes the files). The manage page gains a storage block in its existing settings-row idiom: body usage, translation usage, the budget input (MB, committed on blur/Enter through `setCachePolicy`), and a two-step 清空 button.

## Alternatives considered

**Persist through `sessionStorage` / `localStorage` instead of the host.** What the earlier notes rejected still holds for the RECORD (view + source), which stays in page memory; for the sentence text, the browser stores would strand the memory per browser and per tab-lifetime semantics — the host's state directory is where the cached originals already live, and the reader is one deployment reading one wall.
**Inline both tiers in `state.json`.** The document is read and rewritten whole per commit, including one commit per article opened; a multi-megabyte memory table would tax every reader gesture. The manifest-plus-sidecar split is the same answer the body store already gives.
**Persist translated HTML per entry.** One refetch would invalidate megabytes of markup; the segment map survives minor edits at sentence granularity, and the DOM is rebuilt from the stored body either way.
**Refresh `lastUsedAt` on slice reads.** Turns every warm into a file rewrite; the batched recall report moves the same stamps at one write per run.
**A per-pair memory file.** More files, same content; the pair-prefixed key already namespaces one table, and one file keeps the budget walk to one read.

## Consequences

- After a reload, the article and the position come back as before, the globe waits for its gesture as before — and after the gesture the translation is a disk read, not a model run.
- The pane's page memory is no longer the only copy of anything translated; `primeMemory` never overwrites a fresher in-page write.
- `cleanupAnnotations` treats a translation (and, fixed along the way, a bare `fetch` record) as load-bearing, so a tag edit never drops them; a BODY eviction is the opposite case — the entry map goes with it (the linkage rule above), because a map keyed to a body that no longer exists answers nothing.
- The privacy story is restated, not abandoned: the model runs on-device as before, and what persists is derived sentence pairs next to the cached originals, under one budget, uninstalled with the same directory.
- `dsh.compat.notes` and both READMEs carry the new persistence story.

## Testing

`packages/dsh-reader` runs 320 tests (+30 over the pre-feature line; every new case red against the pre-change code — the host cases against the absent verbs, the client ones against the unwarmed pane / unkeyed memory):

- `tests/boot.spec.ts` (+12, real context + tmpdir): pair keying across a restart; the entry map (inline vs sidecarred, swept on eviction); cross-tier LRU eviction; stale-schema reads as a miss with no eager wipe, replaced by the next write; `recalled` bumps the use clock. The linkage rule: a budget-evicted body takes its map (memory untouched), a refetch that changes `bodyHash` drops it (a same-body re-store keeps it), an expired-but-retained body keeps it, and `removeSource` drops exactly the source's entries' maps. Plus `getStorageStats` aggregation and `clearTranslations` clearing both tiers and nothing else.
- `tests/annotations.spec.ts` (+6, pure): the shared-budget LRU across both tiers, stale-version eviction on sight, the count cap, under-budget identity, normalizer laziness, and `boundAnnotations` dropping the translation with its body while the tags survive.
- `tests/translate.client.spec.ts` (+4): pair keying (another pair misses and re-pays), the `learned`/`recalled` reports, `primeMemory` warm semantics, hash stability.
- `tests/ReaderPane.client.spec.tsx` (+7): a stored entry map paints without the model; a stale `bodyHash` skips the map but the global slice still serves; one run persists in exactly one batch with pair + entryId + bodyHash; the full reload story — article restored from `sessionStorage`, globe clicked, whole body from the store, zero new model calls, and the recall batch bumps the clocks. The manage page: the storage block renders the aggregated readout and the current budget, a budget edit commits through the policy keeping the TTL, and the clear button is two-step with a re-read afterwards.
