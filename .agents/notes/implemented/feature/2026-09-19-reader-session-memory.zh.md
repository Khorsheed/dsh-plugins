# Agent Note：灵感空间记住读者刚才在哪

Status: implemented

## Problem

两条反馈，各自一个根因，但都属于同一段路程——离开灵感空间，再回来。

**回来之后什么都不剩了。** 宿主在另一个主面板接管时会**卸载整个右侧栏**（`RightbarRoot` 只在 `activePanelId === null` 时渲染），而这个面板的 store 是**每次挂载新建**的。于是切到侧边对话再切回来，读者会落回灵感墙的默认状态：打开的正文没了、阅读位置没了、墙上的搜索和排序没了，**读者已经为之付出代价的翻译也没了**。翻译这件事更糟：`Translator` API 的 `create()` 需要用户手势，所以第二次进入连"重建一个自己已经有的会话"都做不到。

**进一篇已经抓过的文章还会再抓一遍。** 只发布摘要的 feed，打开条目时会**无条件**触发 `fetchBody`——`summaryOwed` 是 **feed 条目**的属性，一旦为 true 就永远为 true。正文缓存好之后，`getEntryBody` 明明把它交回来了，代码却照样走网络，用同一份字节把文章的 DOM 换掉。这就是读者翻译过的论文"又得重新翻译"的原因：译文活在那个刚被丢掉的 DOM 里。

## Decision

- **`src/client/session.ts` 按会话在模块内存里保存"读者刚才在哪"**：`view`、`openEntryId`、`openSourceId`、`filter`、`query`、`sort`、`unreadOnly`、`read`、墙上的 `wallOn`/`wallBoth`/`cardTranslations`、每条目的阅读位置，以及每条目的翻译记录。**刻意不持久化**：刷新就是一次新的到访。（位置后来在 2026-09-19 移进了 `sessionStorage`——见状态边界 note；译文**句子**则在 2026-09-20 有了宿主侧的存储，见[译文落盘 note](2026-09-20-reader-persistent-translation.zh.md)；仍然绝不落盘的是翻译会话与地球记录，因为它们在重载之后没有手势就无从驱动。）这张表有上限（12 个会话，LRU），因为它活在这个标签页的整个生命周期里。
- **store 只加一个动作 `hydrate`**，只接受这些会话内的字段——**不含** `sources`、`parsed`、`fetchStates`、`articleHtml`。宿主拥有的事实永远重新读取，所以重新挂载的面板绝不会展示宿主信息的陈旧副本。
- **正文用"和点击完全相同的那次调用"重新建立。** 恢复逻辑等解析出的条目到齐，找到快照点名的条目，调用 `open(row)`；宿主机从缓存作答，**因此回来一次不花任何网络请求**。条目没到齐之前什么都不恢复：打开一个已经不存在的条目，只会把读者丢进一个没有条目的详情页。
- **阅读位置属于详情页的滚动容器**（`detailBody`）：每次 scroll 都写（不做节流——丢掉最后一个事件，恰好就是让阅读位置差一次滚动），并在它所归属的正文上屏之后再应用（更早应用会被较短的页面钳掉）。
- **译文靠页面级的会话缓存恢复，而不是重建。** `session.ts` 现在持有翻译会话表（墙和详情页共用）；有会话就用，**只有存在会话时**才允许回来时自动点亮地球。没有会话就不自动恢复——记录还在，读者下次点地球依旧零成本，因为同一个缓存会作答。
- **记录按条目、且极小**：视图（`trans`/`both`）加上构建它的源语言。"原文"不写记录——地球是关的，一条活过这个选择的记录会把地球又点亮。**手动重新抓取会清掉记录**，因为正文马上要变成另一个 DOM。
- **打开时的自动抓取，现在要求屏幕上这段文字是 feed 自己的**（`view.value.fromFeed === true`），而不只是"欠一篇正文"。宿主已经持有的正文原样展示。
- **详情页有了自己的「重新抓取」**，放在标签行里、紧挨条目的标签。它和卡片上药丸用的是同一个 `startFetch`，走同一条宿主路径（原始 payload 先落盘、浏览器半抽取）：读者想换一份新副本，站在哪儿都是同一个动作。

## Alternatives considered

**`sessionStorage` / `localStorage`。** 否决，而且是用户的决定：读者对一次到访的记忆不该活过刷新，第三方译文更不该落盘；`sessionStorage` 还会把阅读位置恢复到一份刷新后重建的 DOM 上。
**不卸载、把面板留着。** 那是宿主行为（`RightbarRoot`），不是本包能改的；插件侧开 portal 会和侧栏自己的可见性规则打架。
**打开时重抓一次以确认有没有更新版本。** 那是 TTL、卡片药丸和新的「重新抓取」的职责。每次打开都付一次请求（外加一次翻译）正是被修掉的 bug。
**把译文文本存进会话快照（先前设想的"最近 20 篇 / 约 4 MB"）。** 不必要：记录 + 页面级会话 + `translate.ts` 自己的句子记忆足以复现译文，不需要第二个更大的缓存；这也让快照小到"每次滚动都写"是免费的。
**没有缓存会话时自动 `create()` 一个。** 没有用户手势做不到：`create()` 会拒绝，读者会为一次已经付过账的翻译收到一个报错。缓存才是让恢复诚实的东西。

## Consequences

- 面板记住的是**读者在哪**，永远不是**宿主有什么**。TTL 过期的正文，打开时依旧会重抓，和以前一样。
- `tsconfig.client.json` 是显式文件清单：新增客户端模块必须加进去，否则 `tsc -b` 会以 `TS6307` 失败（错误信息里完全没有"文件清单"的线索）。
- 客户端 spec 的 `afterEach` 必须 `forgetSession('s1')` + `forgetTranslators()`：每个用例都渲染同一个会话 id，不清理的话，上一个用例的打开条目、筛选和翻译会话会被恢复到下一个用例里。
- 写快照的镜像 effect **跳过第一次运行**，因为 hydrate 在同一次 commit 里落在它之后——不跳过的话，挂载时会用 store 默认值盖掉记录，然后再去读它。
- 只发布摘要、但正文已缓存的条目，不再每次打开都花一次请求；卡片上的绿药丸现在是对正文的**事实陈述**，而不再是"马上还要再抓一次"的暗示。

## Testing

`packages/dsh-reader` 共 240 个测试（新增 18 个）：

- `tests/session.spec.ts`（新增，12 个）：合并语义、会话之间互不串台、`undefined` 会删字段、12 个会话上限与 LRU 顺序、按条目的阅读位置、翻译记录（含"原文"会清掉记录）、按语言对索引的翻译会话缓存。
- `tests/ReaderPane.client.spec.tsx`（75 个，+6）：已缓存正文**不**调用 `fetchEntryBody`；没抓过的条目仍然恰好抓一次；「重新抓取」从详情页再抓一次；以及三个重新挂载用例（同一个会话 id 的第二个面板恢复打开的正文与墙上的查询、**不用点击**就把地球重新点亮、重开时不再向宿主索要它已经持有的正文）。
