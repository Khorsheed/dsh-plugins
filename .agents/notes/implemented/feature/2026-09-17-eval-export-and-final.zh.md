# Agent Note：一次导出写两样东西，与第 6、7、8 步的最后一公里（I5 · T60）

Status: implemented

[English](2026-09-17-eval-export-and-final.md) | 中文

## Problem

I5 走查（T39）把八步流程完整地在界面上走了一遍，并数了每一次人不得不动手。链本身是通的：一句话进去，草稿出来，人批准，两格在容器里跑完，四条不变量全成立，比较节打开。不通的是**产物的最后一公里**。十七次人介入里有九次是缺口，其中五条落在第 6、7、8 步：

- **G15** —— 报告页的「导出」写了 bundle，`report/summary.md` 仍然是一条要人去终端敲的命令（`dsh-eval report <bundle>`）。一次**每个面都在屏幕上**的走查，还是以敲命令收尾。
- **T53** —— 带 `--out <目录>` 导出的 bundle 在 run 上不留痕迹。`run.meta` 记的是 plan 与题库仓库，而 bundle 两个都不在，于是报告页对着一份已经在盘上的 bundle 说「未导出」，并给一个让人手敲路径的输入框。
- **G17** —— bundle 是 run **结束时**导的；终评在其后从判官台写下，进不了一份已经写好的目录。走查是靠打开 `manifest.json`、发现它的 `exportedAt` 比那条 human-final 早几分钟才知道这件事的。两处界面一个字都没说。
- **G11** —— `runStart` 在 `runCreate` 之前就回了 run id，于是批准触发的那次刷新读到的列表上还没有这个 run。矩阵页与格子页停在「Not started yet」，而同一页的概览已经是 `Running`；点一次 Refresh 全好了——这是最糟的一类 bug。
- **G16** —— 第 8 步 agent 读完 bundle 写分析，而分析该落在题库里。会话工作区不是题库工作树，于是 `write` 撞上沙箱，要人批一次升级到 `danger-full-access`：为存一份 markdown，把整台机器开一次。
- **G13** —— 成员子会话的 tab 条里带着 **Missions**，而主会话那边是正确隐掉的。自隐判据读的是**当前会话**的 preset，而选手那次委派的会话根本没有 preset。

这里没有一条是关于流程骨架的。每一条都是某一步末尾的一个文件、一个字段，或者一句话。

## Decision

### 一次导出写三样东西：bundle、它里面的报告、以及它去哪儿了

`EvalService.exportRun` 仍把 guarded 层的闸原样转发给 mission 的 Remote —— 那道闸是 mission 的，泄题闸有第二份实现就有第二个地方会错。eval 补上的是缺的那一半：mission 写完 bundle 之后，`writeEvalReport` 把 `report/summary.md`、`results.jsonl`、`usage.jsonl` 写**进**这个 bundle，用的就是 `dsh-eval report` 调的那个函数。CLI 动词保留——任何来路的 bundle 都还得有办法补一份报告——但页面不再以一条命令行收尾。run 循环自己结束时的那次导出同样处理，所以一次 run 留下的 bundle 自带 summary。

两件事都是**在一个已经存在的产物周围尽力而为**：报告渲染失败不会把 bundle 变成没导出。失败走回执（`reportError`，并把命令打出来），因为**不声不响的半成功**正是把人赶去终端查个究竟的那件事。

### 导出注解：用逐格的门记一条 run 级的事实

`src/export-note.ts` 记下导出了什么、去了哪儿：导出目录、bundle 目录、时刻、收录的层、快照引用。这是一条 run 级事实，而 mission 没有 run 级的门——`annotate` 收的是 mission id，`run.meta` 在 `runCreate` 时就冻住了。于是这条注解**写得窄、读得宽**：写在本 run 第一格的 `orchestrator` ns 上，读的时候扫全部格子取最新的那条。一格都没有的 run 什么都不记，页面退回按目录候选找——正是它此前的行为。

报告页把注解记的目录排在**第二位**：先试本次访问里人刚敲的那个，再试注解的，然后才是 plan 的 `exports` 与 `<题库仓库>/exports`。这就是 T53：`--out` 导出的 bundle 重新可达，「换个目录找」那个输入框退化成兜底，而不是唯一出路。

### bundle 早于终评，就把这句话说出来，按钮放在句子旁边

报告页显示 bundle 自己 `manifest.json` 里的 `exportedAt`——用 manifest 不用注解，因为那是**文件**的时刻——并与本 run 最新的一条 `human-final` 比。早了就是一句人话（点名那条终评的时刻）加一颗**重新导出**。判官台上同一对，只用账本的两个时间戳判（每写一条终评就要重渲染的页面，不该再去读一次磁盘）：**写**终评的那一页，正是该说这件事的地方。

**重新导出只重复，不放宽。** 它读 run 的注解，把那次导出原样再发一遍——同一批层、同一个快照引用、`confirmed: []`——进一个新目录。guarded 层一个都不重新确认，mission 仍按一份新鲜的 plan 复核，某一层若已变成 guarded 就整体拒绝，把人送回对话框去有意识地勾。新目录是 `<原 outDir>/re-<UTC 时间戳>/`：mission 给 bundle 起的名字是 `<outDir>/<runId>-bundle`，eval 改不了它，换**父目录**是唯一能让第一份 bundle 一个字节不动的杠杆。可能已经有人从那份里引过数字。

### 详情页会等自己刚起的那个 run

批准之后，只要打开的那一行还没有 run id，视图就每 4 秒重读一次列表，id 一出现立刻停——这是一段有终点的等待，不是轮询节奏；上限 15 次，因为被就绪闸**拒掉**的 run 根本不会进账本（它的拒绝原文在概览已经显示的 job 日志里）。这段时间里，四个按 run 取数的子页显示「正在启动」而不是「未开始」：回执已经点名了一个 run，说「未开始」既没用也不对。

### `eval_repo_write`：分析初稿自己的那道窄口

> T73 分支 2 部分取代了本节（[实验成为部署级对象](../architecture/2026-09-23-eval-experiments-deployment-level.zh.md)）：工具现名 `eval_analysis_write`，门是部署状态根下某个实验的 `analysis/<path>`；不再有任何东西写进题库。下文是 I5 · T60 时的形态。

这一行的第二个写，而且是**新工具**而不是给 `eval_plan_draft` 加参数。它往会话绑定的题库里写**一个**文本文件，路径白名单硬编码在 `src/repo-write.ts`：

- `docs/<path>` —— 仓库自己的文档，完全在 `datasets/` 之外。
- `datasets/<题集>/plans/<path>`、`datasets/<题集>/conditions/<path>` —— 起草已经在写的那两类透传文件。
- `datasets/<题集>/analysis/<path>` —— 按题集放的分析初稿目录，给愿意把它放在题集旁边的仓库。

`datasets/<题集>/items/…` **不在**表上，任何深度、任何写法都不行——题干、`standards.yml`、rubric、oracle 一个都不行——不管绑定的**读**白名单开到多大。一场评测的题目材料，不是起草这场评测的 agent 该改的东西。字符串检查（`..`、绝对路径、`~`、不在表上的前缀）在任何文件系统调用之前跑完；只有已经过了这一关的路径才去碰磁盘，且只为确认它没有顺着一个软链目录走出仓库。仓库解析走每个 agent 面都走的那个 `resolveRepoScope`，所以 T58 的收窄在这里同样成立：`repo` 只能复述绑定。不传 `overwrite` 就不覆盖，空内容拒绝，每条拒绝都把路径与整张白名单原样回给调用方——只说「拒绝」而不说这两样，正是 agent 开始猜路径的起点。

### 自隐判据沿父链走

`effectivePresetOf` 在会话自己没有 preset 时沿 `parentSessionId` 往上找，带深度上限与环检测。既没 preset 也没有父的会话照旧失败开放。同一处改动落在 eval、mission、datasets 三份拷贝上（M3' 的推迟决定让它们各自内联），而 G13 的完成判据点名的是**成员子会话里 Missions 不出现**——那是 mission 那一份。

## Alternatives considered

**扩 `eval_plan_draft`，不加新工具。** 否决。那个工具的契约是「一份 plan 与它引用的条件，验过」——它的每一条拒绝都是关于契约的，而且它 `isConcurrencySafe: () => false`，因为两次起草会在同一个 `plans/` 目录上打架。把一次自由文本写折进去，等于一个工具干两件不相干的事、让写笔记白白排在起草后面，而**真正要命的那点**是：工具账本与能力目录里会出现一条「起草了实验」，而它实际上是第 8 步写了一份分析。独立动词能带自己的白名单、自己的拒绝措辞，以及提示词里直指它的一句话。

**重新导出就地覆盖。** 否决：第一份 bundle 是可能已经被人引用过的产物，而 `exportedAt` 正是读者要比的那个字段。第二次导出是同一个 run 在更晚时刻的**新**产物；为了不多一层目录而让它销毁前一份，是拿一条真实的保证换整洁。

**让 mission 给 bundle 名字加版本。** 本次否决：bundle 的名字是 mission 的词汇，改它就是动一份共享契约（CLI、导出对话框、每一个按 `<runId>-bundle` 匹配的读者），而这是一个 eval 自己换父目录就能解的 eval 侧问题。

**报告页单给一颗「写报告」按钮，与「导出」并列。** 否决。那还是这条缺口说的两步形状；导完的人仍然得知道还有第二颗按钮。一个动作两样产物才是修法。

**把「等 run 进账本」做成通用轮询。** 否决——文案明写「轮询节奏不改」，而通用轮询会在一个被拒的 run 上永远读下去。这段等待只在「批准回执」到 `runCreate` 之间上膛，拿到 run id 即下膛。

**窄口放宽成「除 `items/` 外整个仓库」。** 否决：拒绝表要对题库将来长出的**每一个**目录都判对，允许表只要对四个判对。这道门比走查里的实际需要还窄一点，将来要放宽是一行加一条测试。

## Consequences

一次 run 留下的 bundle 现在自带报告，两个能产出报告的页面都会说自己写了什么。`--out` 导出的 bundle 重新能从 run 找回来。记下一条终评的人，会在**记它的那一页**被告知 bundle 还没有它——而修法是一次点击，且这次点击不可能放宽第一次导出确认过的范围。第 6 步不再需要点 Refresh，第 8 步的分析初稿不再需要一次沙箱升级。

代价：三个需要持续保持诚实的新面（注解的形状、白名单、父链走法），以及一层比「带版本的 bundle 名」更难看的 `re-<时间戳>/` 目录。注解是 eval 自己的记录，对 `dsh-mission export` 导的、或从别的机器拷来的 bundle 一无所知——这正是「早于终评」要读 manifest 的原因，也是没有注解的 run 只给对话框、不给一键重复的原因。父链走法一次改变三个包的可见性：一个原本会显示某 tab 的子会话，现在继承父的答案——这既是要修的那件事，也是对任何出于别的原因创建无 preset 子会话的宿主的一次行为变更。

## Testing
