# Agent Note：图书馆——以考点掌握为中心（错题待订正，教练备注挂到考点）

Status: implemented

## 问题

3080 实测（2026-10-19）中，知识卡片承担了它本不该承担的东西：没挂卡的错题都会自动建卡，标题取题干前 80 个字（把 `$…$` 截成一半，卡片列表露出原始 LaTeX，复习里出现「用一句话说说：关于反函数与函数复合，下列正确的是？」）；教练把用户对出题质量的反馈记成了用户的弱点；站页的章节考 tab 六块内容并列、没有主线；今日页「教练最近记下」显示的是题目和反馈，而不是用户哪里没掌握。

## 决定

按提案（[proposals/active/2026-10-19-library-point-mastery.md](../../../proposals/active/2026-10-19-library-point-mastery.md)），与用户讨论定论：

- **一份规则，三处共用**：`src/mastery.ts`（纯函数）计算一站各考点的状态（未考 / 薄弱 / 掌握）与待订正的题，服务端、每轮上下文、侧栏都用它。一道题的最新一次非作废判分——不论来自原卷、重做原卷还是订正——是错的，它就待订正。掌握 = 该考点没有待订正的题，且最近一次考到它答对；薄弱 = 有待订正的题，或教练备注晚于最近一次答对；未考 = 既没作答也没备注。
- **错题待订正，不再变卡片**：没挂卡的错题只有在教练点名单词或概念（`missedCard.term`）时才建卡；拿题干兜底的逻辑删除。
- **侧栏订正**：`createRetake` 生成 `type: 'retake'` 的订正卷，原样重问本站待订正的题（每题带 `origin`）；当场判（问答题照旧交给教练），影响考点，**不影响**节点的统计与过关——这是用户定的：订正不计入过关成绩。
- **教练备注挂到考点**：`notePoint` 追加到 `points[].notes`，考点变薄弱；在以考点为单位的项目里，`library_cards` 中带 `point` 的条目（`node` 缺省为绑定教材的当前站）走这条路。工具说明写明：对题目或工具的反馈不是弱点。
- **考点变化落账**：每次让考点变化的写入都追加 `point.changed` 事件（from、to、待订正数，以及作为原因时的最新备注）；`recentChanges` 供今日页「最近的变化」（与对话中记下的单词卡合并）；`LibraryAssessResult.pointChanges` 供结果页。
- **教练看得到考点**：绑定摘要带上绑定教材的当前站及其掌握情况；每轮上下文列出各考点的状态与原因、待订正题数，以及一行学科提示。
- **学科配置**：`src/profiles.ts`（纯数据）收拢随模板变化的东西——划线类型、是否以考点为掌握单位、填空判题方式（`math` / `spelling`）、公式预览、教练提示。先有 subject 与 language 两份，custom 跟随 subject。侧栏用 `judgeFill(profile.fill, …)` 判填空，只在 `profile.math` 时预览公式。
- **章节考 tab**：过关线 → 考点地图（点开是考点详情：备注、待订正的题、最近一次考到它、「订正这 N 题」/「围绕它出一套」）→ 按状态只出现一个主动作（有未作答的卷子 → 开始作答；有待订正 → 开始订正；否则 → 出题）→「出一套新题」一行摘要配「调整」与「出题」→ 作废题一行 → 之前的考卷折叠。不显示其他站的错题。
- **修复**：卡片列表的词条与释义渲染公式。
- **数据**：3080 上项目里的 10 张题干卡和 1 张出题反馈卡已删除（用户定，不迁移）。

## 后续（2026-10-20）

- **今日复习就是待订正**（用户定，取代之前的「先不做」）：每个有待订正题的项目一行，点开是整个项目的订正卷（`createRetake` 不带站，`scope: {}`）；到期卡片仍是第二行（语言项目的单词、划线的概念）。`LibraryProjectSummary.openMisses` 统计所有站的待订正，同时供这一行和项目页的「错题」数字使用。订正卷的每题通过 `origin` 记回所在站，因此 `stationMastery` 现在读取所有订正卷，只认出处是本站考卷的题；跨站订正卷会为它涉及的每个站报告考点变化。
- **过期的行**：`recentRecords` 去掉卡片已全部删除的记录（只列仍存在的卡）；`recentChanges` 去掉所在教材、站或考点已不存在的变化——事件日志只追加，删掉的卡片之前还留在「最近的变化」里。
- **学员的记录，不是教练的记事本**：新说明上线后，教练仍把自己写错答案的经过记成了对话卡片，所以改为结构性拦截——以考点为单位的项目里，`library_cards` 拒收不带 `point` 的对话卡片，拒收信息列出本站考点，并说明教练自己的失误和对题目的反馈都不记录；提示段第一句改为：图书馆是学员的记录，不是教练的记事本。那张卡已在 3080 上删除。

## 考虑过的方案

- **订正计入过关**：用户否决——反复订正同几道题就能刷过关线；过关仍要考整卷。
- **把旧题干卡迁移成待订正**：没必要——错题本来就在作答记录里，自然会显示为待订正；旧卡直接删除。
- **复习队列里排入到期错题**：用户定先不做，等考点模型跑一段时间。
- **单独的 `library_points` 工具**：暂不做——`library_cards` 带 `point` 既不增加工具数量，也延续教练「学员卡住 → library_cards」的习惯，路由在背后完成。

## 后果

- `LibraryAssessment.type` 新增 `'retake'`；`LibraryQuizQuestion.origin`、`LibraryPoint.notes`、事件字段 `nodeId` / `from` / `to` / `detail` 与类型 `point.changed` 都经规范化函数读回；旧数据照常读取。
- Remote 新增 `createRetake`、`recentChanges`；服务新增 `createRetake`、`notePoint`、`recentChanges`，以及 `bindingSummary().station`。
- 语言项目仍以单词卡为单位（`pointsDriven: false`）；订正流程同样可用，因为它只读作答记录。

## 测试

172/172 全绿：`tests/mastery.spec.ts` 钉住规则（待订正 / 被订正解决 / 备注晚于答对 / 作废 / 重做原卷 / 变化计算）；service.spec 覆盖无名错题不建卡、`point.changed` 事件、订正不动统计、没有待订正时的拒收与考点备注；tool.spec 覆盖 `library_cards` 带 `point` 落成备注，以及上下文列出本站考点。界面在侧栏 fixture 中核对过（有待订正的章节考、考点详情、深色下展开的设置、今日「最近的变化」）。
