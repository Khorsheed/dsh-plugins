# Agent Note: 工具 tab 变为三段筛选（内置 / 插件 / 其他），MCP 以服务器卡片呈现

Status: implemented

[English](2026-08-30-tool-catalog-segment-filter.md) | 中文

本笔记记录 `@khorsheed/dsh-capability-catalog` 0.1.69 中工具目录重构的决策（「工具与技能」设置页的工具半区）。

## 问题

工具 tab 原先用来源 `<select>`（全部 / 内置 / 插件）筛选，并把 MCP 工具在网格下方单独折叠成 server 分组。这带来两个问题：筛选没有干净地映射到三个真实的用户桶，且 MCP 管理被压在高大工具网格之下。曾提议「按最近更新排序」，但工具行没有 `updatedAt`（工具是动态注册的，没有可供参考的文件 mtime），因此按时间排序没有有意义的数据源头。

## 决策

**1. 工具 tab 由搜索框下方的三段筛选（内置 / 插件 / 其他）驱动，取代来源下拉。** 三段与 `CatalogToolChannel` 的用户可见桶一一对应：内置 = `builtin`，插件 = `plugin`，其他 = `mcp`。每个段按钮显示各自的计数。排序下拉对工具被放弃——搜索框成为唯一剩余控件，与之前「工具暂无更新时间、暂缓排序」的决定一致。

**2. 其他是用户自导入的 MCP 视图，以与内置/插件卡片同解剖的服务器卡片呈现。** MCP 不再是压在网格下的独立分区，而是第三个网格视图。每个 MCP 服务器渲染为一张卡片（名称 + transport 徽章 + 工具数 + 外侧启停开关 + 详情/移除脚部操作）。点击卡片打开**管理弹窗**，其内部视图刻意区别于内置/插件的详情弹窗：脱敏的配置 JSON、逐凭据输入（明文不上 wire）、逐工具启停开关，以及「连接并发现工具」动作。旧的按 server 折叠的 MCP 分组卡片已移除。

## 备选方案

- **把 MCP 保留为网格下方的按 server 折叠分区。** 已否决：它被压在高大工具网格之下，且把 MCP 管理与浏览拆开。
- **把 mcp 段渲染成扁平逐工具卡片（同内置/插件）。** 已否决：MCP 的单元不是单个工具，而是带逐工具开关与凭据、可配置的服务器；用户明确要求卡片点进去是「开关里面的工具、配置凭据」，因此卡片以服务器为单位。
- **为工具保留排序下拉。** 暂时否决：工具行没有 `updatedAt`，按时间排序会是空操作/不透明，等工具带上时间戳再说。

## 影响

- **MCP 服务器卡片没有描述正文。** `CatalogMcpServerConfig`（及服务器分组）没有 `description`；只有单个 MCP *工具*有。因此卡片正文以工具数代替文字描述。
- 其他段计数的是 **MCP 服务器**而非 MCP 工具（网格每服务器一张卡，而非每工具一张），所以该计数不会与工具 tab 总数相加（总数按单个工具行计，含 MCP 工具）。
- 默认段为内置（最大/宿主桶）。「新增 MCP」工具条按钮在每个段都可用；空的其他视图会指向它。
- MCP 服务器管理从原地展开改为弹窗；管理弹窗按 server 名从当前分组派生（读最新状态），因此变更会就地重渲染。
- **工具很多的 server 不会把弹窗撑爆。** 管理弹窗（0.1.70）把脱敏配置 JSON 折叠进 `<details>`（默认收起，summary 即「配置」标签）、给工具列表一个有界独立滚动列（`max-height: min(48vh, 480px)` + `overflow-y`），并加一个按名称/描述过滤的 server 内工具子搜索框——因此大量工具仍可导航，「连接并发现工具」等操作行也始终可达。
