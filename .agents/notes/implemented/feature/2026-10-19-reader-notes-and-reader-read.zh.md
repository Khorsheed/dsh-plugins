# Agent Note: 灵感空间笔记、带着笔记讨论，以及灵感空间的模型工具

Status: implemented

## Problem

灵感空间能读、能引用，但读者对文章的想法留不下来：摘抄存不了，评论写不了，和模型讨论只能从贴进草稿的那几段开始。模型自己也读不到文章——宿主从不解析文章（由浏览器半抽取），订阅源里的条目正文根本不会到宿主。本文覆盖 `proposals/active/2026-10-19-reader-notes-feynman.md` 的 P1 与 P2：笔记与带着笔记讨论、模型读文章、讨论结论写回笔记、「让Agent考考我」。P3（笔记同步到画布）另行处理。

## Decision

- **笔记是读者自己的状态，单独一个文件。** `src/notes.ts` 在灵感空间状态根目录下、`state.json` 旁边维护 `notes.json`：按文章存摘抄（`n1`、`n2`……，编号不复用），每条可带评论，以及讨论过这篇的会话。写入原子（临时文件 + rename）、经一条 promise 链串行；根目录不可写就退回内存；解析不了的笔记文件拒绝覆盖。笔记刻意不做成 `state.json` annotation 的字段：annotation 围绕正文缓存设计（`boundAnnotations` 按正文淘汰，`normalizeAnnotations` 丢掉不认识的字段），而笔记要比这两者都活得久。
- **摘抄以原文为锚。** `ReaderNoteAnchor` = 块（阅读位置的单位：顶层子元素，去掉翻译插入的 reveal）+ 字符偏移 + 摘抄文字。在译文视图里划的，摘抄存它碰到的每一句的原文，另附选中的译文。摘抄文字是唯一真相：重新抓取后的文章按文字重新查找，找不到就如实标出，不猜。
- **高亮不碰正文 DOM。** `translate.ts` 会把正文文本节点切成句子 span；用 `<mark>` 包摘抄会在每次切换视图时和它打架。`src/client/notes.ts` 改用 CSS 自定义高亮 API，每次重建后重算 range：原文视图精确到字，译文视图整句高亮（并高亮旁边显示的原文行）。
- **入口。** 「记笔记」经 `ctx.quoteActions` 挂进引用插件的选区菜单（apply 时探测；只在选区落在灵感空间正文里时出现，并路由到拥有该文章的面板）；详情页底栏有同名按钮，给没装 quote 的组合用。记笔记抽屉在面板内部升起（不用 fixed 定位），所有宽度同一套布局。
- **笔记视图。** 详情页用面板组件库的 `UnderlineTabs` 在「正文」和「笔记 n」之间切换。显示笔记时正文仍挂载、只是隐藏——它的分句、翻译和阅读位置都在那棵子树上。笔记可编辑、删除、跳回原文；「带着笔记讨论」把选中的笔记（¶、编号、摘抄、评论、文章 id）合入草稿——读现有草稿合并、绝不覆盖、绝不发送——并在文章上记下当前会话；有 ui-workspace 的 `openSession` 时可「回到会话」。
- **模型读的是快照。** 正文渲染出来时，浏览器解析存下的标记（不读屏幕，屏幕可能是译文），每块一个字符串交给宿主（`snapshotEntry`）；存在 `snapshots/<sha1>.json`，没有笔记也没讨论过的文章只留最近 30 篇。新的 `./tool` 组合入口注册 `reader_read`：不带参数读最近打开的那篇；`entry` 可以是 id、链接或标题片段；正文按 ¶ 编号、每 6 万字一页（`from`），后附笔记。在会话里读一篇文章，会把这个会话记到文章上。patch 把工具行挂在 profile 根上（全会话可见，2026-10-19 决定）。
- **写回的是讨论的结论，不是对话记录。** `reader_note`（同一个 `./tool` 行）：`op=conclusion` 在笔记 `n2` 下加一行；`op=discussion` 记一条讨论笔记（`d1`、`d2`……，最近的在前），每行一点、`¶n` 标段落、「其余……」一行作旁注，`kind=check` 表示一轮考考我。不给 `entry` 时写到这个会话讨论过的文章（`sessionEntry`），没有就拒绝而不是猜。参数全是扁平字符串，也可只靠 text（`笔记：n2` / `类型：考考我` 头行）——K3 丢嵌套参数的教训。模型不能改、也不能删读者写的东西；读者可以追加一句、改写结论（改写后归读者，标「改自讨论结论」）或删掉，也能删讨论笔记。完整对话留在会话里，文章只链回去。
- **考考我是一次请求，不是一个模式。** 「让Agent考考我」（文末与笔记页）把请求合入草稿，请求本身带着这一轮的约定，没加载技能也能用；`reader` 技能（由 `./tool` 行注册）写全：当学生、一次问 3–5 个「讲给我听」的问题、等一条消息答完、只讲没到位的并带 ¶（先不追问——2026-10-19 用户决定）、记一条 `kind=check` 笔记；不打分、没有重考。
- **笔记页跟着会话走。** 显示时每 5 秒重读一次宿主（只在页面可见时，画布卡板的先例），模型写回的结论不用刷新就出现；讨论要点的 ¶ 点一下跳回那一段并闪一下。
- **笔记类型放在 `src/notes-types.ts`**，经 `./types` 转导出：Typert 生成器要求 Remote 边界类型在公开类型子路径上，浏览器半也不能 import 存储层的 `node:` 模块。

## Alternatives considered

**把笔记做成 `state.json` annotation 的字段。** 不采用：那里每个归一化和淘汰逻辑都以正文缓存为键，每一处都得为笔记开例外；而且进行中的 `feat/preset-visibility-refresh` 分支正在改 `store.ts`——单独的文件让两件事互不相干。

**在正文里插 `<mark>`。** 不采用：它改动 `translate.ts` 拥有的子树，破坏其「原样还原」的保证；Highlight API 的代价只是需要浏览器支持（不支持的只是没有底色）。

**把讨论记录整段搬进灵感空间。** 不采用（用户决定）：笔记只有装着结论才值得重读；对话记录在原会话里，一点就到。

**考考我在记笔记之前先追问。** 暂缓（用户决定）：含糊的回答在解释里直接点出来；读者想深聊就接着在会话里问。用过之后再议。

**让模型自己抓文章（对链接 `web_fetch`）。** 不采用：重复抓取读者已有的内容，拿不到订阅源发布的正文和渲染抓取的正文，也没法按笔记用的方式给段落编号。

**快照屏幕上的文字。** 不采用：屏幕可能是译文；模型要读作者写的原文，¶ 编号也必须和锚点一致。

## Consequences

- 笔记经得住正文淘汰、重新抓取和翻译切换；摘抄是自足的文字。
- 读者打开过的文章（也只有这些）模型都能读，不用读者手贴；从没打开过的会如实说没有正文。
- 状态根目录多一个文件和一个目录（`notes.json`、`snapshots/`）；快照有上限（每篇 40 万字，无笔记的 30 篇）。
- 不支持 Highlight API 的浏览器里笔记照常，只是正文没有底色。
- 「记笔记」只在 quote 先加载时出现在引用菜单里，否则用底栏按钮。
- 模型只在被要求时或一轮考考我结束时写笔记——工具描述和技能这么写，除此之外没有强制；读者可以删掉任何一行。
- 新增可选 peer：`@deepseek-ai/dsh-tools`、`@deepseek-ai/dsh-agent`（仅工具行用）。
