# Agent Note: the canvas link view is a second face of one board, drawn by hand

Status: implemented

## Problem

`proposals/active/2026-09-16-canvas-space.md` §11.4's stage ⑥ is the oldest unshipped demand in the canvas round: a board is a **list**, and nothing in it says "these four cards are one argument". The user asked for the ability to draw that grouping on the board itself and then hand the group to the model as one thing — 「就这一组提问」/「生成文章」 over a cluster, not over whatever the filter chip happens to show.

Four constraints made that more than a canvas widget:

- **A position may not be a screen pixel.** The right sidebar is user-resized, and a card's place has to mean the same thing at 380 px and 900 px of panel width.
- **A line has to be data.** If the grouping lives only in the drawing surface, it disappears the moment the panel closes, and the model can never be told which cards the user meant.
- **One gesture has to be one write.** Dragging a group box moves the box *and* every card inside it. Anything per-card means N requests that each carry the version token the previous one invalidated.
- **Every board on disk has none of it.** Forty-odd `canvas.json` files exist with no positions, no lines and no lanes; whatever this is, it may not need a migration.

And one constraint specific to this package: the browser half ships as **one** `lib/client.js` whose only styling channel is inlined `.module.css` (`build/tsdown.client.ts` compiles class names to hashes and injects them as `<style data-plugin-css>`). That decides what node-graph libraries can be installed here at all.

## Decision

- **Three fields, all tolerant-read.** `canvas.json` gains `links[]` (`{from,to}`), `lanes[]` (`{id,label,x,y,w,h}`), and a card gains `x`/`y` — **a pair or nothing**, never one coordinate alone. `normalizeLanes` / `normalizeLinks` / `normalizePositions` (`src/types.ts`) apply the board's usual per-field tolerance: junk rows drop, legal rows survive, a hand-edited file never makes a canvas unopenable. Caps: 400 lines, 40 lanes, lane titles 24 code units. A line whose far end is not a card on this board is dropped — but an **archived** card counts as present, because hiding a card is not deleting it and its lines should come back when it is restored.
- **A coordinate is a space, not a viewport.** `LAYOUT_BOX` (= `DRAW_BOX`, 600×400) is the unit a layout is written in, and it is deliberately **not** a clamp: the link view pans, so `x: 900` is legal. What must never happen is a stored screen pixel — that puts every card in the wrong place the next time the panel is another width. Values round to whole units.
- **Lane membership is geometric, never stored.** A card belongs to a lane iff the card's **center** falls in its rectangle (`laneHolds`); there is no `laneId` field. Membership therefore has exactly one source, and it survives both parties moving. Edge counts as inside, so a two-pixel shrink that catches up with a center does not orphan a card nobody touched. When two lanes overlap, the **first holder in list order** wins — an ambiguous overlap is the board's to fix, not the read's to flip on.
- **One verb: `setLayout`.** `{ canvasId, positions?, lanes?, links? }` lands a whole gesture behind the same version guard every other board mutation uses. **"Absent" and "empty" are two different requests**: omitting a part leaves it alone, `[]` clears it.
- **Two layers, cut where the DOM ends.** `src/client/space/layout-geometry.ts` is pure — no DOM, no store, every box arrives as four numbers — so containment, marquee hits, lane limits and wire shapes are answered in a node test. `src/client/space/LinkView.tsx` is left with gestures and rendering only. Each gesture installs its own `window` pointer listeners through one `runGesture` helper and **re-derives its result from the event that released it** rather than from remembered state: a stale mid-drag frame cannot be committed, and no `useEffect` dependency array has to hold the design together.
- **Three decisions set every shape.** Containment reads the card's center, not its area. A wire's control points push along the **dominant axis** with a **signed** push and a 24-unit floor, so tails always leave on the neighbour's side whichever way round `{from,to}` was stored, and near neighbours bulge instead of collapsing into a line that reads as a rendering error; a tie reads horizontal, because that is the direction the board flows. A flick under 8 px on **both** axes is a click, not a rubber band.
- **The faces are one board, so the switch is beside both.** 「卡板 / 连线」 sits in the tab header, not inside either view. Clicking a node selects and **never** edits; the pen button on the node opens the detail tab, which is the only editor (that is the round's other decision — [detail as the only editor](2026-09-23-canvas-detail-tab.md)).
- **「顺线扩一圈」 is a gesture, not content.** It takes the transitive closure along lines, then **one hop** of lane mates — and only of the seeds, never of cards the lines pulled in, or one line would quietly take a whole chapter. Off by default, never persisted, and a seed the lookup cannot resolve (an archived card) drops out.
- **Read-only closes the write half only.** Picking a node and box-picking still work; drags, lane edits and wire edits do not. A read-only canvas that could not be selected could not be asked about either, which is the one thing the view is for.
- **The hand-drawn stage.** No node-graph dependency is installed. See the measured rejection under Alternatives.

## Alternatives considered

- **`@xyflow/react`** — the pick this round had agreed earlier, and **reversed here**. Three reasons, the first of which is decisive on its own. (1) *Its styling cannot be mounted.* The package's public face is `index.js` plus `dist/base.css` and `dist/style.css` (see its `exports` map) — plain global stylesheets whose selectors target `.react-flow__*` element classes, not CSS-module classes. This bundle inlines only `.module.css` and hashes every class name, so importing either file either fails the build or drops unstyled DOM, and the honest workaround is a hand-rolled second stylesheet that repaints their internals. (2) *Size.* 1,216,002 bytes unpacked across 516 files at 12.11.6, measured with `npm view @xyflow/react dist.unpackedSize` — about **2.4× our entire current `lib/client.js`** (504 KB). (3) *Theme.* Its visuals arrive as tokens on its own stylesheet, while this package's rule is that every colour is an official `--dsw-*` token. What the library actually buys — node dragging, edge drawing, pan/zoom — is ~300 lines in a layer that is already unit-tested on its own; what it would cost is the whole styling seam. (`tldraw` stayed disqualified on the earlier measurement: no-production licence plus telemetry.)
- **One `patchCard` per moved card.** Rejected for the arithmetic in the Problem: a lane drag is N writes that each present the token the previous one invalidated, so a group drag fails its own version guard by construction. `refileSelected`'s sequential fan-out was already the in-repo witness.
- **Store `laneId` on the card.** Rejected: two sources of truth that must be re-synced whenever either party moves, and a drag that stops mid-frame leaves a card claiming a lane its center has left.
- **Index-as-position (order in `cards[]` is the layout).** Rejected: the list order is display vocabulary the switcher and the board already depend on, and reordering to move a card would silently refile every card after it.
- **Make the link view its own tab kind.** Rejected: the demand was two readings of one board, and a second tab would give two places to be when there is one board.
- **Let the line pick cards for you** (hover a card while a wire is drawn = select it). Rejected in the prototype round and kept out here: a line is dropped onto an explicit target, and selection stays a deliberate act.
- **Persist the expansion.** Rejected: 「顺线扩一圈」 answers "what would I send right now", and storing it would turn a gesture into board content that a later reader has to interpret.
- **A blanket `readonly` gate on the whole node gesture.** What I first wrote, and a real defect the component test named: it closed selection along with the writes, while the marquee path stayed open — so a read-only board could be box-selected but not clicked. Selection is not a write; the gate moved to the write half.

## Consequences

- **`CanvasBoard` grew `links` and `lanes` as required fields** (they are always present after a normalized read), so every hand-built fixture must carry them. Three client specs' `board()` helpers needed the two lines added in this change. Note for whoever revisits this: **no package in this repo typechecks its tests** — `tsconfig.client.json` lists `src/` files only, everywhere — so a fixture that drifts from a wire type is invisible to `pnpm run build` and only surfaces if someone runs `tsc` over the spec by hand. That is the repo convention and this note does not change it; it records that the convention has this cost.
- **Downgrading is safe in a way `categories` is not.** A 0.4.4 host reading a 0.4.5 file ignores `links`, `lanes` and `x`/`y`: every card still lists, nothing hides. The three new fields carry no *content*, only arrangement.
- **A card can be dragged out of view.** The world box grows to fit content and there is no minimap or "jump to first card" affordance. Node drags clamp to the **visible stage** rather than the world, so the world cannot grow without bound, but a lane drag can still park cards below the fold.
- **The DOM carries `data-*` hooks on purpose** (`data-node`, `data-wire="from:to"`, `data-port`, `data-lane`, `data-world`, `data-open`) — CSS-module class names are hashed at build time, so a test that asserted on them would be asserting on a build artifact.
- **jsdom reports every box as 0×0**, so an unaided node test sees `UNMEASURED` (168×64) and clamps every drag to `{x: 0, y: 0}`. What a stub has to reach is **`clientWidth`/`clientHeight` on the stage and `offsetWidth`/`offsetHeight` on a node** — not `getBoundingClientRect`, which jsdom already answers at the origin and which the view only uses for its own offset. `tests/link.client.spec.tsx` pins those four on the prototypes for the whole file (a 620×420 stage, a 180×60 node, so a drag's ceiling is 440×360) and overrides `scrollLeft` per test to put the stage in scroll position; a scrolled band is the one case that only means anything once the numbers are real.
- **Wire selection is held by object identity, not index.** The visible list is filtered by what is archived; an index into it would move under the user's feet.
- **31 new zh/en locale pairs** (`view.*`, `link.*`, `compose.*`, `detail.compose`), and the 「卡板/连线」 switch is hand-built because the host ships no Segmented/Select primitive — the same fact that made the category panel's rows plain buttons.
- **Two send texts are now pinned verbatim in `tests/prompt.spec.ts`**: 「生成文章」 and 「就这一组提问」. They are the model's instructions, so rewording one fails a test on purpose. The prototype's second line broke off mid-clause and the sentence was completed here rather than carried forward broken.
- **Still open from §11.8**: a direction or label on a line, and lane grouping across canvases. Neither is this note's to answer.

## Testing

- `pnpm --filter @khorsheed/dsh-canvas build` (gen-typert → host tsc → client tsc → tsdown) then `pnpm --filter @khorsheed/dsh-canvas test` — **23 files / 447 green** (319 before stage ⑥).
- `tests/layout.spec.ts` (new, 27): the tolerant reads (`[undefined, null, 'nope', {}, []]` → empty, junk rows dropped around legal ones, the caps), pair-or-nothing on `x`/`y`, the unordered-pair dedupe, a line to an archived card surviving and to an unknown card dying, `setLayout`'s absent ≠ empty, and the version guard.
- `tests/layout-geometry.spec.ts` (new, 47): every pure answer — center-containment including the edge, first-holder overlap, the signed wire push on all four approaches and the tie, the crossed-bounds `fit` pinning low, `dragLane` carrying its cards and tightening its limits to the title band, `resizeLane` never carrying, `groupOf`'s one-hop rule, and the marquee threshold on both axes.
- `tests/link.client.spec.tsx` (new, 37): the mount (stored coordinates honoured, unplaced cards on the auto grid, one wire per link and none to an archived card), the gestures (sub-threshold press selects and writes nothing; a 3px/4px pair pins the threshold itself; a real drag writes integral clamped `positions` and does not select; a drag that begins on a card never starts a band; the marquee adds and toasts; a port drop writes the pair and a reversed duplicate is refused; a release on nothing and a release back on the origin card both write nothing), the lines (only the picked row is deleted, the picked row survives a changed card list because it holds the row and not its slot, a thin band keeps a picked line alive and only a sub-8px flick on both axes gives it up), the lanes (＋分区 mints a `lane_…` id, rename-on-Enter with no write when nothing changed, a lane drag writing lane **and** carried positions, a corner resize writing no positions), the send set (「就这一组提问」/「生成文章」 reaching `askAgent` with `lens:'ask'` and the pinned text, `data-cluster` only where the expansion added, 取消选择 forgetting the expansion), the band measured in world units on a scrolled stage, and the read-only half — including the asymmetry this note records as a fixed defect.
- One of those read-only cases earned its keep twice over: a band 0–210 wide × 0–3 tall was catching cards that start at y 14. The cause was a typo in `rectsOverlap`'s last clause (`b.y < a.y + b.h`, reading the *card's* height where the *band's* belongs), which is not symmetric — so the pure spec could not see it, because every fixture card there sits at y 0 with the same height as the band. `rectsOverlap` now has its own two-order symmetry pin and a thin-band-over-an-offset-card pin; the component test that found it stays as the second witness.
- `tests/prompt.spec.ts` (+2): the two send texts pinned verbatim.
- Verified against a running host, not only a test: `~/.dsh-lab/profiles/canvas-v2-test` boots the packed 0.4.5 tarball on port 3091 with prod 3080's bundle set, and the shipped `lib/client.js` was confirmed to carry the link view.
