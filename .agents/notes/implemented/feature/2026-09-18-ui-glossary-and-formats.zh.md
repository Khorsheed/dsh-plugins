# Agent Note: 界面说的那套词——对比组、运行记录、五档颜色、人能读的数字

Status: implemented

[English](2026-09-18-ui-glossary-and-formats.md) | 中文

## Problem

T63 把两个 tab 内部拉齐了，然后用户走了一遍。他的意见干净地分成两半。一半是结构：四阶段导航、向导、详情重做、图表、并排盲评——归 T67。另一半是：**界面在用编排器的语言，对一个正在做实验的人说话**。

「条件」是 `conditions/<id>.json` 声明的东西；而看这一页的人在比较实验的两个组。「格子」是 pivot 排出来的矩阵的一格；而人看的是某一次运行的记录。「因子」「快照」「矩阵形状」「四条不变量」「判官台」都是同一个形状的错位——从里面看每个都精确，从外面看每个都是行话。列头还写着 `canary`、`validate`、`attempt`、`rep`，条件页干脆把点号键名当列头（`model.declared` / `model.endpoint` / `scope` / `preset` / `lock`），动作词是英文的 `provision`。数字是生的：`98,765` 个输出 token、`21.0 min`、判官一致性一行三个数。颜色还说反了：一条已释放的记录——结束了、不会再有事发生——是绿的，和一条通过的判定同一个绿。

界面规格 §九 正为这件事加了三条（术语表 / 色彩语义 / 数字与句子）。这一轮按它落地。**只动文案、颜色、格式**，结构一寸不挪。

## Decision

**一张术语表，扫到正文而不止列头。** 条件 → 对比组、因子 → 对比变量、格子 → 运行记录、快照 → 题库版本、矩阵形状 → 实验规模、四条不变量 → 实验有效性校验、判官台 → 人工评估（判官本身保留原名）；矩阵那一页按 §九 现在的写法叫网格。列头里的英文术语一并给词（canary、validate、attempt、rep；`harness` 按定案保留）。条件页的键名列头换成词、键名留 `title`，`provision` 在词典里定一次为「准备环境」，两处不会再漂。这次**有意**扫过了列头、进到句子里：列头写「对比组」而下面两行的空态写「这个题集还没有条件」，读者完全有理由以为那是两样东西——§九 对状态词的那条（「同一状态在列表、矩阵、格子页、报告页写法一致」）往上一层就是这条。四十来条正文字符串还在说旧词。**没有改的**：指磁盘上那个文件时的「条件文件」，以及占位符里的 `conditions/` 路径——那是契约，不是词汇。

**桶与阶段并成一列「运行状态」，而这个「并」不是拼接。** 阶段是具体事实，永远显示；桶只在它说了阶段说不出的事时出现：「阻塞」（有依赖没满足）与「排期」（在等一个时钟）。`ready` / `active` / `done` 都由阶段蕴含，两枚 chip 说同一件事，正是这一轮要去掉的噪音。

**五档颜色，其中一档初看是反的。** §九 点了名：已归档 / 可释放 / 已释放是**灰**。跑到流水线尽头是「结束了」，不是「成功了」——绿留给「已判」，那是唯一带着结论的状态，于是一列绿意味着「这些判过了」而不是「这些跑到头了」。桶里的「阻塞」从橙改红：阻塞是走不下去，而橙是一条人可以选择忽略的警告。

**数字不再是生的。** 计数压成 `31.5k`，一千以下一个不舍——轮数与工具调用小到每一位都有意义，舍进去会把一个 1 抹掉。时长是**组句**出来的而不是格式化出来的：「4 分 48 秒」不是 `4m 48s` 换个数字，所以 `durationParts` 只挑哪两个单位、词由词典给。判官一致性从三个数收成一个读者能据以行动的词——「评分者一致性：高（κ 0.85）」——κ 挂悬停，样本数安静地留在旁边，因为「高」建立在两对上和建立在四十对上不是同一个断言。κ < 0.6 时多一句这一页唯一能给的建议：考虑增加判官。

**宿主给的判定句改成提示。**「无可比较，事实见下」变成「当前为单对比组实验，无对比数据，下方是基线表现」；比较节未开从橙色警告框改成普通提示——那是实验的一种状态，不是实验里的一个错误。

**人工评估队列按评分者说话的方式命名。**「P0-placeholder · 第 1 次」——题，和第几次，永远不带对比组——序号退成安静的后缀；队列加筛选（全部 / 未评 / 已评，题多于一道时再加一行按题）。筛选是视图本地的，且**从不重排**：种子顺序本身是盲评的一部分，一个会排序的筛选就是泄漏。

## Consequences

- `packages/eval` 830 → 834 条测试，`packages/datasets` 214 条；两套与 gate 全绿。新的纯函数都钉住了，包括「它们能说出的每条文案两份词典都有」——文案闸已经抓缺键，这一条抓的是缺**短语**。
- 合并那一列让两个词典键（`cells.col.bucket` / `cells.col.stage`）失效，删掉而不是留成死文案。
- 英文词典保留它自己的语体：它本来就没在露键名、也没混中文，而 `condition` 在英文里就是实验设计的标准词。术语决定针对的是中文界面，所以只落在中文侧——两份词典共享的是键集，不是词汇表。
- **有意留给 T67**：四阶段导航、向导、详情重做、图表、并排盲评，以及 §九 的「每页一个主动作，底层信息默认折叠」——最后那条是版式规则，不是文案规则。
- **仍然只记不改**：`pivotMatrix` 的汇总明细、`report` 的不变量明细与 `rankReason` 在宿主端拼成中文。这一轮把**浏览器**组的每一句都改温和了；那四处是它够不着的，要改得动数据面。

## Testing

两个包各跑 `pnpm test` 与 `tsc -b --noEmit --force`，再跑 `pnpm gate`。`tests/vocab.spec.ts` 钉住压缩的分界点、时长的拆分、κ 的分档与词典覆盖；上一轮的 `tests/copy.spec.ts` 继续核「没有页面问两份词典里缺的键」与「同一条文案两语言占位符一致」——报告页判官块换形状时，正是它先红。

## Alternatives considered

### 文案只点了列头与子页名，为什么扫到正文？

因为停在列头的术语表不是术语表。列表列头写「对比组」，下面两行的空态写「这个题集还没有条件」，读者有充分理由认为那是两样东西。§九 对状态词的那条规矩往上一层就是这条。四十条正文在决定做出之后是机械劳动；文案定的是那个决定。

### 为什么不把英文词典里的 condition 也改成 arm？

因为英文本来就有这个词，而且在英文里它不是行话：`condition` 正是实验设计文献里的叫法，`arm` 是临床试验的词。中文的问题在于「条件」对没读过契约的人读起来像「前提」。两份词典同步改名等于把它们当成同一段文字的两种编码——它们不是。

### 为什么「已释放」是灰不是绿？

这条值得单写，因为初看是反的。这套色板里绿的意思是「这件事做成了」。一条已释放的记录，是归档过、走过闸、容器销毁了——那是流水线走完了，它对里面那份工作好不好一个字都没说。一个每格都已释放、每条判定都没通过的 run，会是满屏的绿。「已判」才是带着结论的状态，绿就给了它。

### 合并那一列为什么不两枚 chip 都显示？

那是「并成一列」的字面读法，我第一版也是那么写的。但桶是阶段的一个五向投影：`stage-2` 永远是 `active`，`archived` 永远是 `done`。两个都印，等于每一行把同一件事印两遍——而那正是这一页一开始难读的原因。不能由阶段推出的那两个桶（阻塞、排期）恰好就是留下来的两个。
