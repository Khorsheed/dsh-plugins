# Agent Note：保存链接的卡片学会论文自己的标题

Status: implemented

## Problem

3080 验收报上来的：粘一个链接（比如一篇 arXiv 论文）上墙之后，卡片的标题永远是 URL 推出来的那串（`arxiv.org/2604.03147`）——哪怕正文已经抓过、读过。读者的原话：「能从卡片就看出来内容，如果很多论文不用一篇篇点」。面板在加载时本来就做提取（详情页要正文），只是从来没用过提取知道的东西，也没有任何持久化跨过载荷的寿命。

## Decision

提取现在捕获文章的身份证，卡片优先读它——会话内立即，持久化跨过淘汰：

- **`extractArticle` 随正文返回 `title` 与 `excerpt`**：正文自己的第一个 `<h1>`（在一切实测形状上它都是文章名），否则文档 `<title>`（在噪音剥离**之前**读——`<title>` 在 `DROP_TAGS` 里，剥离之后 `doc.title` 就死了），封顶 200 字符；摘要取第一段达到打分器自己的分语言散文门槛的段落，按卡片的 280 字符量截断。
- **标注携带它们**（`ReaderEntryAnnotation.title`/`excerpt`，写入与读取都封顶 300/1000）：`storeEntryBody` 随正文接收——新给的胜过已存的，已存的胜过没有，于是一次不带 meta 的重存保留已捕获的值。它们比正文长寿：归一化、正文预算淘汰、标签清理清扫三处都保留只有 meta 的标注。`getBodies` 把它们接到**链接**源的载荷回答上（feed 源永不接——它条目的标题本来就是发布方的），这本来就是墙的既有读取路径，所以不存在新动词。
- **面板在合成时升级卡片**（`load()`）：新鲜提取 > 已存 meta > URL 标签，两个分支（载荷在场 / 已淘汰）一致。`noteExtractedMeta(entryId, meta)` 是写进已解析墙的唯一路径：它改条目的 `title`/`summary`，并且**拒绝 feed 条目**（feed 标题是发布方自己的；打开时的欠账抓取对 feed 条目也跑同一道提取，绝不能顶替）。它在两个会话内提取时刻触发——`fetchBody` 成功（打开 / 卡片药丸 / 重抓）与 `sweepRaw`——而 `persistFeedBody` 为标题真的被升级过的链接行携带 meta（`title !== sourceLabel`），于是「带着 contentHtml 打开」不花请求就把升级落盘。
- **详情页与最近阅读白捡这次升级**：两者都读解析后条目的标题，而 `recordRead` 写下的就是升级后的那个。

## Alternatives considered

**放在源级字段而不是标注上。** 链接源就是它唯一的条目，所以 `ReaderSource` 也能带 meta，`listSources` 不用 join 直接出。否决在所有制：标注表本来就是每条内容住的地方（正文、标签、译文），而失败/标题/摘要这些事实回答的都是「这个条目是什么」——拆到两张表就是两份真相。
**专用 `noteEntryMeta` 动词，加载时写。** 否决为多余线面：每一条要紧的持久化路径本来就在存正文（`fetchEntryBody`、`sweepRaw`、打开时的 `persistFeedBody`）。留下的缺口窄且诚实：从未打开也从未抓取的链接，载荷被淘汰后回到 URL 标签——从来没有提取过，就没有可记的。
**从抓取状态轮询里改卡片。** `entryFetchStates` 是墙的另一条按条目通道，但它是**状态**镜像（五态药丸）；把内容字段挂上去，就是把[抓取状态 note](../bug-fix/2026-09-20-reader-fetch-state-propagation.md) 分开的两份推导又混在一起。载荷通道（`getBodies`）才是墙本来读条目内容的地方。
**连源标签一起升级。** 否决：标签是读者给源起的名字（订阅管理里可改）；卡片标题是文章的名字。两者只在链接上重合，混为一谈会让读者的改名不生效。

## Consequences

- 粘一个 arXiv 链接，卡片从第一次加载就写出论文名与摘要；这份身份跨过重启、载荷淘汰（走标注）与 feed 窗口存活。
- 翻译面不受影响：整墙翻译读 `entry.title`/`entry.summary`，现在它们装的就是真文字。
- 存下的 meta 是每个链接两个字符串——不配占用一次政策讨论的体量。
- 已知的窄缺口（已接受，见上）：从未打开、从未抓取的链接在载荷淘汰后回到 URL 标签。
