# Agent Note: capture — a rendered-fetch host service (reader ingest M1)

Status: implemented

## Problem

The reader's main scenes are image-heavy tech blogs and papers, and one whole class of pages arrives as an empty shell: transformer-circuits.pub renders all 102 of its `<figure>`s from a d3 bundle (~20 of them only through IntersectionObserver — a fast scroll-by does not even trigger them), so the sanctioned `ctx.web.fetch` seam brings home markup with holes where the article lives. The [ingest proposal](../../../proposals/active/2026-09-20-reader-ingest-capture-documents.md) decided (D1) that the fix is a separate package, not reader innards: a hundred-MB browser binary and an SSRF/security surface deserve their own boundary, and other consumers (canvas, datasets) can ride the same verb later. The reader's M0 already shipped the integration slot: a 「渲染抓取」 gesture that renders only while a `capture` Remote probes present (`ctx.get('remote.capture')?.render`, structural, never imported). M1 is the package that makes that probe answer.

## Decision

`@khorsheed/dsh-capture` (`packages/capture`): a host-side rendered-fetch service. One Remote namespace `capture`, one verb `render({url, timeoutMs?}) → { html, finalUrl?, title?, truncated? }` — the exact shape the reader mirrors at `packages/dsh-reader/src/client/contract.ts:56-64`; refusals are thrown `RemoteError`s with `capture/*` codes (`invalid-url`, `private-target`, `unavailable`, `navigation-failed`, `timeout`, `busy`), never a second `{ ok }` union inside the value.

- **Process model**, reused from the closed [browser-pane](../closed/2026-09-13-browser-pane.md) review: one managed Chrome process (`pipe: true` — stdio, no TCP listener), a fresh temporary `BrowserContext` per render (zero cookie/credential persistence), idle-timeout shutdown (60s), crash-relaunch on next render. The Chrome for Testing binary lives under `$DSH_HOME/state/dsh-capture/` and downloads lazily on the FIRST render; install/launch failure is that call's `capture/unavailable`, never a boot crash. `executablePath`/`channel` config overrides. What capture does NOT build from that proposal: frame streaming, IME, model tools — a capture is one request/response verb.
- **SSRF gate** (`src/url-policy.ts`, pure): http(s) only; credential-bearing URLs refused (login state in the address bar is still login state); every hostname resolved and EVERY answer must be public — loopback/private/CGNAT/link-local (metadata 169.254.169.254 included)/multicast/reserved refuse, IPv4-mapped/NAT64/6to4 classify by their embedded IPv4, exotic IPv4 spellings arrive pre-normalized by the WHATWG parser; `localhost` refuses by name. Request interception re-runs the whole gate on EVERY redirect hop (a public URL 302ing into the private network is the escape this exists for); subresources pass on http(s)/data/blob only.
- **The render pipeline** (`src/service.ts` + `src/page-tasks.ts`): navigate (`load`, 30s default, caller `timeoutMs` clamped 1–120s) → HTTP ≥400 refuses → landed-URL belt re-check → network quiescence (500ms quiet, 5s cap) → full-page scroll sweep dwelling 500ms per 0.8-viewport step (the IntersectionObserver requirement, measured) with a 20s budget → in-page inline-and-serialize.
- **Style inlining is the product, not polish**: matched CSSOM rules cascade by (important → inline-ness → specificity → document order) into `style` attributes with `var()` resolved along the custom-property cascade (fallbacks, nesting, cycle guard); SVG presentation properties are ALSO written as attributes so a whitelist that keeps attributes but strips `style` still sees colors. Then scripts, style blocks and stylesheet links are removed and the output caps at ~8M chars with `truncated`. The in-page functions are self-contained by construction (they are stringified into the page) and run unchanged under jsdom in tests.
- **Permission is gesture-gated (v1)**: the reader calls `render` only on an explicit user click, which IS the approval; the first SUCCESSFUL render of a host persists a per-site allow record to `state.json` (atomic `node:fs`, never `ctx.fs`; corrupt reads empty and is never overwritten) so a future non-interactive caller can gate on "approved before". Dangerous targets refuse regardless of any record.
- **The browser half is mount-only, and it must exist**: `remote.capture` materializes on the client only when someone `$mount`s the generated contribution, and the client-bundle purity gate forbids the reader from importing `@khorsheed/dsh-capture/remote` — so this package's thin client half (`src/client/index.ts`, `dsh.client.immediately`) does the mount and nothing else. There is no settings UI; that is deferred, not omitted by oversight.
- **The puppeteer surface is consumed through structural interfaces** (`src/browser.ts`), with the driver itself loaded by variable-specifier dynamic import: the typert generator analyzes sources against the harness checkout, which does not carry puppeteer, and a static import would fail the face generation (and load the driver at boot).

## Alternatives considered

**No client half at all** (the proposal sketch's "宿主半一个包，无客户端半（或极薄）"). Then nothing mounts the contribution and `ctx.get('remote.capture')` never answers — the reader's M0 probe is dead code forever. The mount-only half is the minimum that makes the Remote reachable; it carries no UI.
**The closed browser-pane's fuller 许可门** (site allow/block table with a first-visit approval dialog, plus model-facing tools). Deferred: v1's only caller is already gesture-gated, so the click is the approval and a dialog would approve an approval. The per-site record is written today precisely so that gate can land later without re-deriving history; non-interactive callers (the proposal's openreview title extraction) are the trigger for building it.
**Rasterizing figures to PNG screenshots** (the proposal's fidelity fallback). Loses the SVG text's quotability — and quoting is the reader's whole point; the inline route was measured sufficient (all 102 figures are DOM/SVG, zero canvas). Kept as a degradation option if a canvas-heavy site shows up.
**A `getComputedStyle` snapshot per element.** Resolves the real cascade but emits hundreds of properties per element — multi-MB noise for the same figure colors; matched-rules inlining emits only what the document actually declares.
**The reader imports `@khorsheed/dsh-capture/remote` and mounts it itself.** The purity gate forbids cross-plugin value imports by construction, and an import would couple the reader's build to capture's presence — the mirror-structurally contract (`ReaderCaptureRemote`) exists precisely so either side ships alone.
**Full `puppeteer` instead of `puppeteer-core` + `@puppeteer/browsers`.** Its postinstall downloads Chrome at npm-install time into a shared cache — the opposite of lazy, state-rooted, and overridable.

## Consequences

- JS-heavy pages become ordinary reader entries: the rendered capture rides the SAME whitelist extractor, so quoting, translation memory and reading-position memory cover them unchanged (the M0 flow was already complete; this package is all M1 adds).
- One render costs seconds (dwell × steps) and one Chrome holds hundreds of MB while alive; the queue keeps that to one process and the idle timeout returns the memory. Callers must treat render as a slow gesture, never a bulk fetch — the bounded wait line refuses `capture/busy` instead of queueing a crawler's ambition.
- The fidelity limits (frozen interactions, headless ≠ pixel-perfect, unreadable cross-origin sheets, approximate cascade, sweep budget) are user-visible honesty and live in the README, not in code comments alone.
- Future consumers (openreview title extraction per D3, canvas/datasets) call the same verb; the `capture/*` error vocabulary is the stable part they contract on.

## Testing

`packages/capture` — 61 tests, all green locally:

- `tests/url-policy.spec.ts`: the refusal matrix pure (schemes, credentials, the whole IP classification table incl. mapped/NAT64/6to4 and parser-normalized exotic forms, stubbed-DNS resolution outcomes, localhost by name).
- `tests/page-tasks.spec.ts` (jsdom): CSS-var inlining onto SVG (style + presentation attribute), inheritance and nested `var()` chains, fallbacks, specificity/order/important cascades, the rightmost-compound prefilter, script/style stripping, the size cap, sweep stepping/dwell/budget against a scripted scrollable page.
- `tests/queue.spec.ts` / `tests/store.spec.ts`: serialization, order, failure containment, the busy line; empty/corrupt/atomic persistence, prototype-key guard, the 500-record LRU cap.
- `tests/boot.spec.ts`: real-Context boot (service + Remote face both answer), the refusal matrix through both faces, unavailable/timeout/status mappings, mid-flight redirect refusal, queue busy, disposal — over a fake managed browser through the launch/install seams.
- `tests/render.integration.spec.ts`: a local fixture server serving an IntersectionObserver-gated, CSS-var-colored SVG page, driven through REAL Chrome (loopback fixture is reached via `--host-resolver-rules` + the resolver seam, since the policy refuses loopback by design): the lazy figure arrives with resolved colors, redirects report `finalUrl`, a loopback-escaping redirect is refused mid-flight, 404 maps with its status. **Skips wholesale when no Chrome binary exists** (CI has none; resolution order: `DSH_CAPTURE_CHROME_PATH`, the managed install under the default state root, the system `chrome` channel). Verified locally against system Chrome.
