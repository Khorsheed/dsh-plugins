# Agent Note: 游戏面板的「看变化 → 试玩 → 指出来 → 看结果」闭环

Status: implemented

## Problem

能做 3D 游戏之后（见 [3D 套件](2026-10-22-game-3d-kit.zh.md)），面板仍然是 2D 的思路：试玩区点选要三步（点选 → 卡片 → 「引用」），插进草稿的还是纯文本；候选栏在页签顶部，离它要对比的画面很远；看不出候选版本改了什么；3D 元素完全没有预览。用户要的闭环是「看到变化 → 试玩 → 指着某个东西说想法 → 看到修改结果」，每一步都需要 3D 下的做法。

## Decision

- **点选一步成芯片（决定 G5）。** 在「指一下」里点一下，就往输入框插入一个引用芯片（按住 Shift 可以接着点第二个），用户写完自己发送。芯片走宿主的 `slash/input-insert-reference` 作用域 bail 事件，配一个带编解码的无头触发源（`src/client/refs.ts`，照 quote 插件的做法）；芯片上显示短标签，发送时展开成完整引用：元素名和 id、实例、区域、坐标、状态。宿主没有芯片接口或拒绝插入时，把同样的文字追加进草稿。点选期间游戏暂停（桥接的 `pause` 消息），指针处提示点下去会选中什么（悬停时节流地问一次游戏）。
- **候选栏放到画面下方**，挨着它要对比的东西，和「当前 / 候选」切换放在一起。
- **差异圈。** `ProjectView.candidateDiff` 列出候选相对线上版本改了、加了哪些元素（比较两份快照的元素文件）；试玩候选时，试玩区把它们作为桥接的 `highlight` 列表发给游戏，有开关可关。
- **3D 预览在沙箱里画，不在面板里画。** `Preview3D` 用线上版本自己的 bundle（含套件文件和项目 `src/looks.js` 里的注册），换上一个预览入口，所以面板里没有第二份拼装器。`spin` 是元素转盘（可拖动，改动实时跟随）；`still` 渲染一次，把 PNG 发回来后缓存成图片。外观方案卡片、元素网格里的卡片和轮末改动卡片都用它，滚动到可见时才渲染，同时最多渲染两张（其余先显示主色色块，排队轮到再画）。2026-10-25 起镜头（`preview-entry.ts`）改为绕模型转的透视镜头；按套件约定模型面朝 +x：静态图从正面偏 3/4、略俯（yaw 35°、pitch 18°）拍，外观写了 `preview: { yaw, pitch }` 就按它拍；转盘在被拖动前会慢慢转（左右拖转动、上下拖调俯仰），并有「正面 / 侧面 / 背面」按钮。原来固定的 45° 正交镜头加上模型转 0.5 弧度，拍面朝 +x 的角色时拍到的是背后。
- **配方编辑器。** `parts3d` 外观用按配方本身生成的滑块和取色器编辑（`Recipe3DEditor`）：比例、每个部件的数值（包括项目自定义部件的 `extra`）、配色、动效、整体大小。改动和像素外观一样保存，并立刻进到正在运行的游戏：dsh3d 会就地重建所有由该元素 id 拼出的模型。
- **轮末卡片的前后对比。** 轮末记录带上改动元素的 3D 外观改前、改后（限长 JSON）；卡片把两者都显示成静态图。

## Alternatives considered

**在面板 bundle 里放一份 three.js 来渲染预览。** 首次出图会更快，但面板会多一份可能和游戏不一致的拼装器（外加 three.js），而且看不到项目自己注册的身体和部件。沙箱跑的正是游戏跑的东西。

**轮末在宿主端（无头 Chrome）渲染卡片图。** 那时检查用的浏览器是热的，但每轮都会多出磁盘状态，也多一条渲染路径。客户端的静态图缓存在内存里，只有真正看卡片时才有开销。

**保留点选卡片上的「引用」按钮。** 用户正在组织想法的那一刻，多一步就是多一次打断；芯片直接插到用户要打字的地方。

## Consequences

- 每个实时 3D 预览都是一个独立沙箱、占一个 WebGL 上下文。元素卡片用静态图而不是实时模型，静态图一次只画两张，所以整格卡片也远离浏览器的上下文上限；渲染期间卡片先显示主色色块，还没有线上版本时就一直是色块。
- 项目自己的身体和部件必须在 `src/looks.js` 里注册，面板才能预览；3D 技能里写明了这一点。
- 芯片的序列化按源名称查找，源未挂载时插入的芯片会发送失败；所以只有触发源已注册时才插芯片。

## Testing

`tests/refs.spec.ts` 固定了实体、裸 id、地面三种情况的芯片标签和文本，以及编解码往返、损坏芯片拒绝发送。`tests/store.spec.ts` 固定了 `candidateDiff`（跨快照的改动与新增 id；没有候选时为 null）和轮末记录里的 3D 改前改后外观。运行时一侧（点选引用、暂停、高亮、按元素实时重建）由套件的无头测试覆盖。
