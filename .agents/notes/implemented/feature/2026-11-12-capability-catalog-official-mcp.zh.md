# Agent Note：迁移完整启用的 MCP 服务器，同时保留单工具控制

状态：implemented

[English](2026-11-12-capability-catalog-official-mcp.md) | 中文

## 问题

能力目录原来在发现和每次工具调用时都新建 SDK 连接。宿主 0.2.2-rc.2 提供持久 MCP manager，包含 Settings 配置、探测、重连、富结果与凭据更新。直接换用它会丢失目录的粘贴导入和单工具开关；同时运行两座桥又会重复注册模型工具。

## 决策

仅在 manager、Settings 和工具服务可用时启用新桥。逐台迁移已启用且全部工具开启的服务器，在目录设置中保存版本化归属记录和原始配置。旧 `secretRef:` 分别映射为确定性的、符合官方命名约束的 `${credential:...}`，env、header 和 query 不混用。用户配置通过 `settings.update` / `mutate` 写入，绝不使用仅供插件生命周期的 `register()`。

官方项先禁用写入，探测成功后记录归属再启用。失败恢复原凭据和旧连接；同名但不同的配置属于其他所有者，不覆盖也不遮蔽。工具名、参数和执行来自官方注册表，特殊字符名称遵循官方哈希规则。目录保留原配置和密钥值用于回滚，官方配置只含引用。

官方没有单工具过滤。关闭一个工具时先禁用官方服务器并等待其工具卸载，再把该服务器退回现有连接；恢复全选后允许再次迁移。旧宿主、缺少能力与已有工具过滤的服务器继续使用旧路径。

凭据服务晚到时动态绑定。若 manager 因先于它启动而 load-failed，成功探测后重启该实例；普通断连仍由官方重连策略负责。编辑、删除和外部回滚进入同一迁移队列，避免旧任务重建已删除项。工具元数据不变时不重复写 Settings。

## 未采用的方案

**全部走 `mcpManager.register()`。** 否决：它是插件生命周期贡献，不是用户 Settings 文档。

**删除旧连接与单工具开关。** 否决：官方没有等价的单工具策略。旧桥只保留这个差异和旧宿主路径，健康迁移服务器不再双注册。

**启动时迁移全部服务器。** 否决：禁用、已过滤或缺少必要配置的服务器不能被静默改变。

**复制后立即删除旧密钥。** 本次不采用：工具过滤回退与探测回滚仍需原值。删除已迁移服务器时会移除其官方项和生成的凭据引用。

## 影响

目录仍负责能力清单和技能管理。官方 manager 接管迁移服务器的连接、重连、完整工具注册与结果投影。旧桥只在单工具过滤需要它或没有官方 manager 时保留，仍有纯文本限制。

测试覆盖迁移回滚、名称归一化、同名外部配置、凭据轮换、凭据服务晚启动、真实 stdio fixture、完整 Settings/Loader 组合、重启恢复、工具过滤、重新探测与删除。该源码变更不表示已部署或已发布 npm。
