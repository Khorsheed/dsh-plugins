# Agent Note: 默认自动显示的 select 化模型字段

Status: implemented

[English](2026-09-13-model-ux-select-round.md) | 中文

## Problem

prod 上第三轮模型 UX 反馈：选了值之后设置卡下拉变少、样式突变（原生 `<datalist>` 按输入过滤——两套列表机制打架）；未设置时必须亲手选一次才能"看到"默认（诉求：四家都把默认自动显示出来，并去掉单独的跟随行）；(i) 提示文案（「本插件一个模型参数都不传」）读起来像"选了别的模型也不生效"；成员作曲器的选择弹窗样式粗糙、空候选时还会开一个空框；邀请弹窗的模型字段埋在高级设置抽屉里、名字也不一致。

## Decision

**设置卡（四家统一）。**datalist 删除——chevron 菜单是唯一且始终全量的列表。未设置时控件直接显示继承的默认（来源链不变：作用域配置 → 目录命名 → 最近实测 → 通用文案），用 caption 暗色标识——纯显示，绝不钉死；留空保存仍然是取消设置。菜单首项 `默认（跟随 …）` 在未设置时选中，点它清空草稿；输入框下方单独的跟随行删除（信息已进控件）；(i) 提示重写（留空 = 跟随所示默认；选择或手输后保存即用于之后委派；按会话切换在成员作曲器；保留手动输入）。

**成员作曲器——只动选择弹窗**（用户限定：composer 其他部分一律不碰）。弹窗对齐官方 ModelSelect 菜单（r20、`--dsw-specific-menu`、显著阴影、38px 行、尾部对勾、分隔的重置行）；空候选渲染一行禁用的 暂无候选模型 提示，而不是一个空框。

**room 邀请弹窗。**模型字段移出高级设置抽屉、放到 Provider 行正下方，改名 默认模型，控件与设置卡一致（默认暗色显示、首项 默认、无 datalist）；邀请/编辑语义不变。客户端接线从裸 choices 改为完整 broker 表面（`modelSurface`）。

## Alternatives considered

**datalist 与菜单并存。**否决：那正是"下拉变少、样式突变"的根源——只留一套始终全量的列表。

**把默认自动钉成真实保存值。**再次否决：留空即跟随是刻意语义；自动钉死会冻结今天的默认、掩盖上游变化。

## Consequences

家族里每个模型字段现在是同一个 select 控件、同一套语义；"默认"处处可见、不用点一下。测试：四张设置卡重写，成员作曲器 +2，room 成员 +约 6；各套件全绿（kimi 228、codex 216、claude-code 204、dsh 180、local-agent 267、room 217）。
