# Agent Note: canvas-novel 规划——一页纸大纲、分卷路线、字数预算、核心悬念

Status: implemented

## Problem

小说只有单章计划，上面一层什么都没有。一句话主线只写在 skill 的说话指导里，对话往下走就没了。全书多长、分几卷、写到哪了，都没有地方放。实际使用中（用户的《幻梦境》《梦境守护者》，2026-10-08）由此出了三个问题：

- 单章计划没有篇幅，模型一章塞七八拍、五条伏笔操作。
- 本该终局揭晓的谜在第一章就被直接问出来。所有伏笔一视同仁：6 章没动就标 ⚠，「待埋」也从不说什么时候埋。
- 讨论阶段立的卡在正文还没写时就落成「已埋」，一张卡塞好几个问题。前一半已单独修掉，见故事日志那条笔记 2026-10-08 的补充。

## Decision

- **前置页签「规划」。** `@khorsheed/dsh-canvas` 新增 `CanvasGenreFaces.lead`：排在成稿前面的体裁页签。还没写正文的体裁画布默认打开它，store 的体裁摘要会把它带出去。小说声明 `faces: { view: 'story', lead: 'plan' }`，页签变成 规划 · 章节 · 设定 · 故事。旧版画布在摘要里丢掉 `lead`，小说就只是没有「规划」页签。
- **`outline.json`**（每部作品一份，和 `chapters.json` 放在一起）存下面这些，读取经过 `normalizeOutline`：
  - **一页纸**：一句话主线、核心冲突、主角（人物卡 id）、成长弧线、主题、基调、结局方向、篇幅 `{words, volumes, chapters, perChapter}`。
  - **分卷** `{id, title, chapters（估计）, goal, landing}`。
  - **近处一两章的一句话**。
  - **一份待采用的提议**，以及改版记录。
- **大纲只到卷。** 大纲阶段能想清的就到这一层：每卷约几章、要完成什么、卷末落在哪。具体某一章写到附近才细化：规划一章时，模型可以顺手提议接下来一两章的一句话；再往后，卷里显示「约 N 章，写到附近再细化」。
- **模型提议，用户采用。** `novel_write(what=outline, sheet/volumes/sketches/rationale)` 合并进唯一一份待采用的提议：
  - 一页纸字段逐项合并；分卷整份替换；一句话细化按章号合并。
  - 卷 id 保持稳定：标题和已采用卷相同的沿用原 id，挂在它下面的章节不动。
  - 主角必须能解析到一张人物卡（否则 `unknown-protagonist`）。
  - 只有规划页上的「采用」（`decideOutline`）才把提议并入，记一个版本、一行改版记录；「不采用」直接丢弃。
  - `novel_read(what=outline)` 读回全部内容，包括核心悬念。
- **主角就是那张人物卡。** 人物类型新增「抱负」（`ambition`）和「价值观」（`values`），定义升到 v3（体裁 `novel@4`，画布追平机制会给已有作品补上这两栏）。一页纸只存指向人物卡的指针和成长弧线。规划参考材料的一页纸部分列出主角的目标、抱负、价值观、缺失。
- **章节挂在卷下。** `ChapterRecord.volume`：
  - 新建章节进入指定的卷（`volume=卷二`，可以写 id、卷名或序号；对不上返回 `unknown-volume`）；没指定就跟上一章，再不行就是第一卷。
  - 重新规划时可以挪卷。
  - 没挂卷的章节算第一卷。
- **字数预算。** `ChapterPlan.words` 是目标字数；计划里没写时默认取一页纸的 `perChapter`。默认值只在计算时取用、不写回计划，这样计划门禁比较「是否改过计划」时仍然准确。
  - `capacityOf`：每拍 750–1000 字；伏笔操作至多 2 条（4000 字以上 3 条）；出场至多 4 人（6 人）。
  - 规划参考材料开头写明这份预算。
  - 登记计划时只提醒、不拦：拍数、伏笔操作或出场人数超了，以及核心悬念在它的卷之前被揭晓。
  - 计划卡显示目标字数和能装多少；对账后显示「计划 N · 实际 M」。章节 Remote 返回 `targetWords`。
- **核心悬念。** 伏笔卡新增「揭晓时机」（`reveal`，自由文本，由 `parseReveal` 解析：本章内 / 卷N / 终局），定义升到 v2。
  - 定在某一卷揭晓的伏笔，不再按章数判超期：`isOverdue` 一律返回 false。
  - 节奏由 `coreSuspenseNudge` 给出：到揭晓卷之前显示「定在卷N揭晓，现在卷M：可以暗示，不能揭」。只有两种情况轻提醒一句：一卷快写完还没碰过它，或者到了揭晓卷之前碰过不到两次。过了揭晓卷还没揭，显示「原定…已经过了」。
  - 「本章内」的小钩子 2 章没回收就标出来。
  - 谜底只在揭晓那一卷、或计划里写了揭晓它的那一章，才放进参考材料。
  - 线索不预排。「已放线索」就是对账记下的提及（`ForeshadowView.mentionChapters`；规划 Remote 连同类型和备注一起列出）。
- **对账不再成批立伏笔。** 对账规则改成只收读者会一直惦记、后文必须回收的问题，一章至多 2 条。
- **规划页**（`PlanView`，`canvas.board.view` 键 `novel:plan`）从上到下是：
  - 进度：写到第几章、在哪一卷、篇幅完成多少；
  - 一页纸，主角那块点名字打开人物卡；
  - 提议，虚线框，带「采用 / 不采用」；
  - 分卷：每卷的章节、近处已细化的章、折叠行、卷末落点、这卷揭晓的伏笔；
  - 核心悬念：每条的线索阶梯和节奏提示。
  
  一套布局，按面板宽度自适应。

## Alternatives considered

**大纲阶段逐章列路线。** 交互稿第一版是这样画的，用户否了：大纲阶段能定的是几卷、约多少章、每章多少字，定不了每一章写什么，硬列出来只会被推翻。改成分卷加近处一两章的细化。

**给每个谜预排线索阶梯。** 同样的理由否了：事先只能定在哪一卷揭晓。线索等正文写出来时再记。

**主角字段存进大纲。** 否了：名字、身份、想要、缺失、旧伤已经在人物卡上，存两份会走样。大纲只指向人物卡，人物卡补上抱负和价值观。

**用 `faces.views[]` 支持多个体裁页签。** 更通用，但一个具名的 `lead` 槽位就够用，旧版画布也能干净地忽略它。

**把默认目标字数写回计划。** 否了：存下的计划会和模型重发的计划不一致，计划门禁会当成改过计划而拒绝写正文。

**叫「大谜」或「核心冲突」。** 用户定了用「核心悬念」指读者心里的问题。「核心冲突」是一页纸里单独的一栏（主角要的 ⟷ 挡他的力量）：一个推情节，一个管信息什么时候给。

## Consequences

- 作品可以带大纲了。规划时模型能看到主线、主角、在本卷的位置和字数预算，核心悬念也不会再被提前到开头几章。
- 没有大纲的作品，各份参考材料的输出和以前完全一样，有测试锁定。
- 对账规则改了一行（快照已更新）。
- `NovelError` 新增 `unknown-protagonist`、`unknown-volume`、`no-proposal`，都配了界面文案。
- 没做：「整理伏笔」菜单项。拆分一卡多问的旧卡目前在对话里完成：skill 要求模型先说明拆法，再用 canvas_write 落卡。
- 测试：`tests/outline.spec.ts`（解析、卷 id、节奏提示、容量、工具全流程）、`tests/plan-view.client.spec.tsx`（规划页和计划预算），以及画布页签测试里的前置页签用例。
