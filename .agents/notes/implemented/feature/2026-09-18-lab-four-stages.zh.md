# Agent Note：四个阶段，每个一个主动作——实验室 tab 不再是一堆标签正确的字段

Status: implemented

[English](2026-09-18-lab-four-stages.md) | 中文

## 问题

T63 把实验室 tab 内部对齐了，用户走了一遍，结论是问题还挺多，而举的例子形状都一样：概览与计划审阅几乎是同一份定义列表，两页都没有按钮；条件页把整个仓库的声明摆在一份只用其中两条的计划旁边；矩阵页与格子页把同一个 run 画了两遍、分在两页，人只能看着一页记着另一页；实验的形状在跑起来之前是一个算式（`4 × 2 × 2`），等它变成一张图的时候已经改不动了。

这些都不是执行缺口。ui-spec §五 v1 只定了**七个子页各装什么**，从没定**人在每页做什么**，于是「七个标签正确的字段堆」正是它规定出来的东西。§五 已改成 v2——四个阶段、每页一个主动作，加上同一天补进 §九 的术语表与色彩语义——本轮就是照它落地。

## 决定

**四个阶段替掉七个子页**，合并按「事」而不按「数据」：实验设计吃掉概览、计划审阅、条件三页；运行记录吃掉矩阵与格子；结果对比与人工评估留住报告和判官台。

**tab 条下面一条 stage bar：状态、一句话、一个动作**，动作由一张表按实验状态选——草稿 →「去校验」，待批准 →「批准并启动」，运行中 →「看运行记录」，评估中 →「去人工评估」，已完成 →「看结果」，被拒 →「重新检查」。六个动词里三个把人带去别的阶段，一个重读，**「批准并启动」就在这条 bar 上按**：它是人的动作（R1），该在人站的地方按，而不是翻到某个子页去找。validate 有错时它是禁用的、旁边写着原因——一个只能换来拒绝的按钮比一个说明自己为什么灰着的按钮更糟；而且在审阅走完之前，这个原因取自**列表那一行自己带的 validate 计数**，所以它不会在一份已经被拒的计划上短暂地亮一下。

**批准之后人留在实验设计。** 就绪检查拒绝写在这一页的运行日志里，**别处没有**——被拒的 run 根本到不了 `runCreate`，账本里一行都不会有——把人带去一张空网格，等于把他马上要找的原因留在身后。本次会话里做出的批准在 bar 上**压过列表行的状态**：`runStart` 比 `runCreate` 先返回，那一行还会有几秒钟写着「待批准」，而在一个已经跑起来的 run 上摆一个「批准并启动」，是这条 bar 上唯一一个标错了会真出事的按钮。

**同一个网格组件画两遍。** 行是题，列是对比组。跑前每格写「计划 n 次」，跑中每格是 rep 圆点、运行状态、有判定就显示判定、以及告警。两个渲染器对着一张表迟早会分叉，一张表两种格子不会。计划网格是从计划审阅的 digest（题目 id 与对比组 id）搭的，而那份 digest 实验设计页本来就要读。

**对比组表只列本实验的受试对象**——选手加判官，判官那行挂一枚「判官」chip。在一页只讲**一次**比较的地方摆上仓库里所有声明，正是本轮要去掉的数据倾倒；它还把计划网格挤出了屏幕。

**就绪徽章替掉就绪原文。** 全过一枚「✓ 环境就绪」，否则一个红叉一行加一个计数和「重新检查」。原文照旧、逐字保留，折在旁边。validate 清单同理：现在只摆需要读的那几条，通过的折起来——一条干净的检查不是新闻。

**运行记录的五档筛选在浏览器里做，一个 run 只读一次。**「失败」根本不是桶——`halted` 被投进 `done`，因为那一格**确实**结束了——服务端按桶筛只能答三档，另外两档照样得把整份拿回来，而 chip 旁边的计数就会开始数两拨人。

**得分那一列显示的是判定的来源，不是数值。** 见「其它方案」。

## 影响

- `packages/eval` 834 → 843 条测试；`tsc -b --noEmit` 干净；gate 绿。
- `MatrixPage.tsx` 与 `PlanReviewPage.tsx` 没了，内容分别进了 `Grid.tsx`（共用网格、排布折叠、汇总带）与 `DesignPage.tsx`。`CellsPage.tsx` 改名 `RunsPage.tsx`；`ConditionsPage.tsx` 现在导出 `ConditionsTable`，是一节而不是一页。
- 实验设计是**落地页**，所以打开一个实验现在要花一次计划审阅和一次条件读。这跟原来打开计划审阅页的花销是同一笔，只是挪到了真正讲这件事的那一页；列表仍然两笔都不花。
- **25 个词典键随着它们所属的页一起死了**（两张直方图、`overview.draftNotice`、`review.approve*`、`conditions.new*`、`cells.bucketAll`……），直接删掉而不是留成死文案。本轮之前就已经没人引用的另外八个没动——那不是这个任务的垃圾。
- 原概览上的桶与阶段**直方图**没了，也不打算补：网格直接摆出每一格的状态，汇总带数了卡住的和未释放的，再给同一批状态画一张直方图是同一件事的第三个视图。
- **没做到的一条**：文案要求「未绑定题库时『绑定题库』按钮弹出题集 tab 的导入表单（同一个组件）」。按钮有了，弹出来的是**一段话**不是一张表——说清楚去哪个 tab、按哪个动作、它要什么，不抛命令行。它做不成题集 tab 那张表：eval 的 Remote 没有 bind 动词，客户端包不 import 兄弟插件（§八），宿主也没给一个 `conversation.view` 注册去选另一个注册的口子。要补齐得走这两条之一，而两条都超出「不扩数据面」。

## 测试

`packages/eval` 里 `pnpm test` 与 `tsc -b --noEmit`，然后 `pnpm gate`。客户端用例是**改写**不是放宽，其中三处改写本身就是断言：`MatrixCells` 现在断言五档筛选是在 `fetchCells` **只被调用一次**的前提下收窄行的；`LabReview` 断言计划网格在什么都还没跑的时候就画出 4 题 × 2 组 = 8 个格子、断言表里不出现本实验没用到的那个对比组、断言批准之后**留在**实验设计且 bar 变成「看运行记录」；`LabView` 断言 bar 的那句话，以及它的按钮真的执行那个动作。`vocab.spec.ts` 钉住判定的权威顺序与「失败 ≠ 完成」那条规则。

## 其它方案

### 为什么不在运行记录列表和网格里放真的得分？

因为「得分」有两个，而只有一个站得住。格子投影带的是各 ns 各有**几条**判定，从来不带值；读者拿来比的那个数是 `report.ts` 从**导出的 bundle** 算的——判据的正负极性来自 rubric、每格只取最权威的那一个 ns、同判据多样本按多数计、rubric 带权重时再算一遍加权。照着活账本再算一份就是第二套评分实现，而失效方式很具体：运行记录页和结果对比页会对同一格报出两个数，读者没有任何办法判断哪个在说谎。文案也点名了允许加的两处数据面字段，这不在其中。

所以这一列显示投影诚实持有的那个事实：这一格带的是哪一种判定（终评 / 判官初判 / 脚本判定 / 未判），按报告同一套权威顺序排，悬停里写清楚数值在哪一页。网格白拿到同一个事实——运行记录列表在那一页本来就加载了，格子按 `missionId` join 它，不用给投影加字段。

### 为什么文案点名可加的两处数据面字段最后一处都没加？

文案允许两处：格子投影带各阶段 transition 时间戳（时间轴用），报告投影带每条不变量的「为什么影响比较」一句（悬停用）。先读代码把两处都消掉了。`EvalCellAttempt.history` 本来就逐条带 `{from, to, at}`，`checkpoints` 也本来就带时间，所以时间轴用抽屉今天已经拿到的东西就能算。而那句「为什么影响比较」按不变量 id（`materialization` / `fingerprint` / `subject` / `procedure`）是**常量**——它是文案不是数据，该进词典，那里才能有两种语言；宿主端一个中文字符串给不了英文。两处都归里程碑二，两处都在客户端。

### 为什么主动作是真动作，而不是跳到放着那个动作的页面？

一个有时跳转有时执行的按钮，是两个按钮共用一个标签。全做成跳转，「批准并启动」就还是 bar 上的一个词、指着下面某处的一个按钮——那正是走查在抱怨的安排。全做成执行，「看运行记录」又做不到。解法是：**动词属于状态，不属于 bar**——三个状态想把人带走，两个想把事做掉，表说明是哪一个，标签永远说出按下去会发生什么。
