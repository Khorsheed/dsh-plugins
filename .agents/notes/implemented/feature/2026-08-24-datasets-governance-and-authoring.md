# Agent Note: default safety, operator view, register mapping, validate verb, and the authoring protocol document

Status: implemented

English | [中文](2026-08-24-datasets-governance-and-authoring.zh.md)

## Problem

Two reviewed proposals converged on one implementation round. The [datasets proposal](../../../proposals/active/2026-08-19-datasets-store.md)'s pending review items: (①) with no explicit binding layers whitelist, sensitive (`modelFacing: false`) layers were still agent-readable — the default was "everything"; (②) the whitelist also gated the human's tab, so reviewing a rubric meant permanently widening the agent's boundary — the worst trade. The [authoring-protocol proposal](../../../proposals/active/2026-08-23-dataset-authoring-protocol-skill.md)'s M1: the protocol had no home document, no `validate` verb, and no `register` mapping — free-form files had to move into convention directories to gain a role.

## Decision

All four landed in `@khorsheed/dsh-datasets` over one service core:

- **Default floor**: `effectiveLayers(scope, descriptor)` is the one ceiling every layer-gated path consults. Operator scope → unfiltered; explicit binding whitelist → exactly it (listing a sensitive layer is deliberate); no whitelist → the dataset's `modelFacing:true` layers when it declares any sensitive layer, unchanged (unfiltered, undeclared item directories included) when it declares none. The floor covers list/show/read/put_item and the worktree default; an explicit `layers` ask intersects it (an empty intersection is the only error — M1 semantics). `DatasetScope.operator` marks the human view: the tab's Remote reads and the CLI's read verbs run as operator (the whitelist constrains the agent's tools and worktree materialization, never a person reading their own repository); CLI `worktree path` stays non-operator (it is a container boundary); `previewRepo` is operator (the binder must see everything to choose).
- **register**: `dataset.json` gains an optional `register: [{item, layer, files}]` mapping **item-relative** paths or single-level globs (`*` never crosses `/`, no `**`) onto roles — item-relative because the conformance sample (`dataseek-eval`'s harness-comparison, P0-placeholder) is built that way and is the acceptance fixture; the appendix's bare "paths must stay inside the repo" reads as item-scoped there. `buildRegistry` expands globs against the commit's file list, fails loud on layout conflicts (a display path claimed by both the convention directory and a register entry of the same role), dangling exact paths, escapes, and `item.json` re-homing; zero-match globs are allowed (content may arrive later). Registered files re-home into their role in `list`/`show` (display = item-relative path), `read` resolves display → git object, register-only items list, and a register-claimed file never ALSO surfaces under its physical directory as a pseudo-layer (a partially-claimed directory keeps only its unclaimed remainder). Worktrees translate registered paths into sparse patterns: exact object paths and single-level globs ride as non-cone gitignore patterns (`/datasets/<id>/items/<item>/<pattern>`), folded into the cache key alongside the layer set.
- **`datasets_validate`** (CLI verb + `datasets_validate` tool): per-dataset shape errors fail loud (CLI exit 1; warnings never block), three warnings — `MODELFACING_UNDECLARED` (existing), `FIELD_NAME_SENSITIVE` (item.json keys containing note/hint/answer/rubric roots — item.json is always visible), `UNREGISTERED_FILES` (files covered by no layer directory or register entry fall into the always-visible passthrough zone; single-level globs not covering subdirectories is the common trap). Validation sees everything (operator semantics): it reports on the passthrough zone by design. The CLI `describe` verb now reads through `show` (identical descriptor JSON; the summary carries the warnings).
- **Tab tree rules**: register-mapped files render under their declared role; contentless layers stay hidden; the passthrough zone is a visible, non-clickable group row ("透传 · N 个文件 · 不受白名单保护" — `ListItemsResult.passthrough` rides the wire); sensitive layers stay readable for humans with a `· 敏感` marker; the bind form's fold initializes layer picks to the modelFacing floor (an opened-then-confirmed fold can never widen past the default).
- **Post-smoke refinements** (same round's user feedback): (1) item.json now shows as a per-item quiet line `item.json · 不受白名单保护` when expanded — chosen over folding it into the dataset-level passthrough count, because one line per item puts the warning exactly where the author writes metadata, while merging it into the group would flood the row and hide the signal; (2) layer rows carry a second marker `· agent 可读` for the session's agent-visible layers (the binding's explicit layers, else the modelFacing floor) — readable-only marking because readable is the minority after default-deny, and the marker re-renders live when the binding moves (it is the user's confirmation channel that an edit took effect); (3) the shared group's label is `题集级共享` / `Dataset-level shared` to disambiguate same-name layers at the two levels (the "visible · visible" reading reported from the demo tree); (4) binding-bar/form copy names the whitelist what it is — `agent 可见：…` with the floor phrased `agent 可见：可见层（敏感层默认拦截）` when no layers are written, replacing the inaccurate "全部 layers"; (5) density polish over the IDE tree (19px guide steps, item-title weight, settled preview header strip, products-tab pane breathing) without changing the established shape.
- **Protocol document**: `docs/dataset-authoring-protocol.md` (Chinese, the repo's Chinese-first convention) + `docs/dataset-authoring-protocol.en.md`, versioned v1-rev1. Its `dataset.json` example is valid JSON (annotations live outside the fence) and feeds the validator in `tests/protocol.spec.ts` — both language copies, so doc and implementation cannot drift.

Wire additions (all object-carried, the exact-arity lesson untouched): `ListItemsResult.passthrough`, `ReadQuery` unchanged, `DatasetScope.operator` is host-internal. Artifacts regenerated.

## Alternatives considered

- **Floor = only declared modelFacing:true layers even when nothing is sensitive** — rejected: it would newly hide undeclared item-level directories in plain datasets; the floor engages only when sensitivity is declared at all.
- **Repo-relative register paths** (the appendix's loose reading) — rejected: the conformance sample (the acceptance fixture) registers item-relative paths that do not exist at the repo root; item-relative is also the safer scope (register can never reach outside the item).
- **Silently skipping dangling exact register paths** — rejected: a typo'd exact path is a broken descriptor; fail loud. Globs may match zero (content arrives later) and `UNREGISTERED_FILES` covers the reverse direction.
- **Filtering validate's view to the caller's ceiling** — rejected: validate is the author's hygiene tool and must report on the passthrough zone, which by definition no layer ceiling can see.
- **Interactive confirm-on-empty whitelist groups writing `[]`** — rejected: the schema reads absent as "all" and `[]` as "nothing"; the form forbids an unchecked-everything group instead (see the M2 note).

## Consequences

- Bindings without an explicit layers whitelist became safer by default: agents stop seeing sensitive layers unless the binding lists them. Operator surfaces (tab, CLI reads) are unaffected; `worktree_path` defaults narrowed the same way, so containers materialize only model-facing layers unless asked.
- Existing managed worktrees orphan once (the cache key now folds register patterns); `worktree prune` collects them.
- The `datasets_validate` tool runs unfiltered by design — an agent validating a dataset sees its full layer vocabulary (layer names are low-stakes metadata; content stays gated).
- `describe` on the CLI now lists items as a side effect (it reads through `show`) — a slightly heavier verb, same output.
- The protocol document is the single source the validator's consistency test, the bind form's prefill, and (later) the skill derive from.

## Testing

`packages/datasets/tests/` — 87 tests over 12 files green. New: the floor block in service.spec (mixed default narrows, operator sees all, explicit whitelist widens deliberately, no-sensitive datasets unchanged, write path floored, worktree ask intersects silently), register.spec (shape constraints, role re-homing, register-only items, read resolution, worktree physical contents, conflict and dangling fail-loud, no double-show with the partial-claim remainder rule), validate.spec (the three warnings, per-dataset error isolation, CLI exit codes), protocol.spec (both language copies' `dataset.json` examples validate clean), the operator-view rewrite of remote.spec (the tab never narrows; the tool boundary keeps the whitelist in the same test), and the tab's passthrough/sensitive/floor tests. Live smoke on :3091 against `dataseek-eval` verified the tree shape (passthrough row, shared sensitive layer, register re-homing) and `dsh-datasets validate`'s real output.
