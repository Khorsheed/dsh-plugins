# Agent Note: 章节删除先预览影响，并进入可逐章恢复的回收站

Status: implemented

## Problem

用户和 Agent 可以删除卡片、事件和灵感，却不能删除章节。章节同时是 `chapters.json` 的登记、挂载工作区里的 Markdown 文件，以及对时间轴、人物、关系、伏笔、待审、想法和对齐的贡献。只删文件会留下仍在生效的记忆；只删登记会留下无人管理的正文，随后还可能复用章号。要求删除第 3–6 章的会话同时包含已对账章节和重复规划章，只支持规划删除的捷径不够。

## Decision

- 删除采用统一的规划/执行模型。现有 `deleteNode` 保留为非章节节点的兼容入口，并与章节操作进入同一个按作品串行写入队列。章节使用独立策略，因为它们拥有文件和派生记忆，不能机械复用卡片图清理。
- 章节内部身份与展示章号分离。墓碑只保留通用标题、id、章号、文件名和操作 id；恢复的章节使用全新 id。章号因此可以复用，而不会继承对齐状态、浏览器草稿或旧记忆。
- 预览在修改前持久化准确的章节记录、正文版本、派生记录和级联候选。Agent 必须在预览后收到新的用户消息才能执行。记录或正文指纹变化会以 `stale` 拒绝；`chapter + delete=true` 会被拒绝，不再误更新计划。
- 执行先写墓碑，再按版本保护删除源文件、重写派生文档、移除按章日志并归档合格的级联卡片。共享事件只失去被删章的贡献，灵感只失去“已写入”标记。手动人物记忆、用户历史编辑和手动关系阶段调整保留。
- 清理幂等，单独报告 `cleanup-pending`。清理完成前，读取也排除已删除章节及其贡献；同章号复用则必须等重试成功。未确认的预览 24 小时后过期，已接受的快照长期保留。
- 恢复使用 `createIfAbsent` 写回正文，支持原章号或下一空闲章号，只恢复正文和计划并使用新 id。旧日志不倒放：含正文的章节恢复为写作中并重新对账。级联卡片只在明确选择时恢复。彻底删除按章移除快照，并且只在级联卡片仍归档时永久删除；会话日志、外部副本和系统备份不在范围内。
- Remote 和浏览器提供影响预览、执行、回收站总容量与单章大小、按选择恢复/彻底删除和清空。Agent 使用 `what=delete` 的 `chapters`、`deletionId` 和 `phase=preview/apply/restore/purge`。导航回到章节目录，不指向已删除章节。
- 共享卡片不做猜测性回滚，而是把受影响节点标记到现有按点对齐流程，不把历史记录当作可靠的逆向补丁。

## Alternatives considered

- **只删 Markdown 或只删登记。** 否决：会留下生效中的故事记忆或无人管理的文件，也无法安全恢复。
- **让 `deleteNode` 直接套用卡片规则。** 否决：章节拥有不同资源，需要正文快照、可重试清理和恢复语义。
- **永久禁止章号复用。** 否决：删除尾部章节准备重写时，应该允许从第一个空闲章号开始，但必须使用新的内部身份。
- **把整本书恢复到某章之前。** 否决：后续对账和用户编辑使卡片逆向更新不可靠，按点对齐才是诚实边界。
- **永久保留每次预览。** 否决：废弃预览会无价值地膨胀状态。已接受的快照采用不同保留规则，直到恢复或彻底删除。

## Consequences

- 用户和 Agent 可以批量删除规划章或已对账章，明确知道哪些内容会一起删除，并可只恢复某一章，不复活其他已删除内容。原文件只在快照成功后移除。
- 多文件删除不宣称原子事务。墓碑是提交点，每个文件仍有版本保护；部分清理时读取保持一致，重试路径明确。失败后恢复或彻底删除前，可能需要先完成报告的清理。
- 彻底删除不是安全擦除，也不是删除所有痕迹。它清除插件控制的内容，保留非内容的章节版本与操作元数据；外部副本、会话历史和系统备份不在操作范围内。
- 存储、工具、Remote 与客户端测试覆盖版本身份、物理删除、派生记忆过滤、过期预览、后续消息确认、部分恢复/彻底删除、级联归档、清理重试、清空和浏览器交互。包构建和全部 324 个测试通过。
