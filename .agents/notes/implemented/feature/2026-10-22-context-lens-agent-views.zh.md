# Agent Note: Context Lens agent views

Status: implemented

## Problem

一轮里的工作可能分散在主对话、dsh 子 agent、外部 agent（由 local-agent 拉进来的 Claude Code、Codex、Kimi）和压缩调用里。Context Lens 原来把它们放在互不相连的地方：
- 子 agent 只是普通的胶囊。
- 用户邀请进房间的外部 agent，在日志回放时根本没有视角。原因是日志回放只为和委派工具调用配对的 catalog 行建子视角。
- 压缩是轮次切换器里的独立伪轮次，和它所打断的那一轮没有关联。
- 单独打开一个子会话时，看不出它是谁的子会话。
- 从日志回放的压缩请求只显示被压缩的消息。宿主实际发出的总结请求还带着开头的系统提示和请求头里的工具定义。

## Decision

- **先放会话地图，下面放这一轮的参与者。** 趋势图放在标签上方，铺满面板宽度、立在同一条基线上，始终显示主对话，用来选轮次。每一轮占一格，请求多的轮次更宽；当前轮用浅色底带标出，轮号加粗。接着是这一轮的提问，前面写轮次编号。再下面是一行扁平的下划线标签，构成头部的底边（`AgentTabs.tsx`），列出主对话和所选轮次的全部参与者：外部 agent、子 agent、压缩，不分组，没参与的不显示。主对话之外超过 4 个时，露出 3 个（当前选中的一定露出），其余收进「+N」；展开「+N」按启动顺序列出全部，带委派请求编号和请求数。默认选中主对话。头部各块之间间距 12px。
- **关系说明只放能跳转的事实**：委派它的那次请求、压缩的位置，放在标签行末尾。不写 provider 名，也不写说明；主对话没有关系说明。失败只在标签的 ✗ 和下方的失败卡片上显示；成功不加标记。
- **不是由人发起的轮次，标出触发来源。** 某一轮没有用户消息时，取这一轮第一条来自非常驻写入方的消息，作为 `TurnListItem.trigger`。常驻写入方包括运行时上下文、技能、提醒和压缩摘要。面板在提问行显示来源标签和这条消息的最后一段，不再留空。注入类消息开头是固定的说明，结尾才是这一轮真正送来的内容，所以最后一段才是每轮不同的部分。
- **外部 agent 和子 agent** 按子会话 `subagent/descriptor` 里的 provider 区分：`dsh*` 是子 agent，其余（`codex-local` 等）是外部 agent。provider 在实时捕获时从子会话的事件里读，回放时从子会话日志里读。标签行不按它分组，这个字段留在视图数据里，给需要区分的地方用。
- **只有 catalog 行的子会话也建视角。** 没有被任何待配对委派调用认领的 `subagent/catalog` 行，作为一次 `callId: ''` 的委派处理。状态记为 `ok`，因为没有工具结果不等于失败；也不带 `delegatedBy`。
- **委派关系。** 和工具调用配对的子视角带 `delegatedBy`，也就是发出这次调用的主对话请求。主对话请求带 `delegates`，列出它的调用启动了哪些子视角，趋势图据此画小圆点。
- **压缩挂到它发生的那一轮。** 压缩伪轮次挂到 `compaction/start` 记录的那一轮；没有轮次的（发生在两轮之间），挂到紧接着开始的下一轮。它从轮次列表里消失，变成那一轮的 `compaction:<伪轮次 turnSeq>` 视角，带 `replacedCount` 和它之前的那次主对话请求。所有指向压缩请求的链接（构成里的来源、变化清单的跳转、请求视图自己的 `scopeId`）都经过同一个 `addressOf`，所以跳转会落到新位置。趋势图在压缩发生的位置画一条虚线。
- **压缩回放** 在被压缩区域前面补上当时第 0 个节点的系统消息和最近请求头里的工具定义，和 compaction-basic 的 `buildSummarizationInput` 一致。只有末尾那段压缩指令仍然缺失，因为它写在宿主代码里；界面上标为未记录，请求保留 `inputPartial`。
- **父会话链接。** 回放时，如果会话的日志头写有 `parentSession`，就读一次父会话日志，取出父会话标题、启动这个子会话的 catalog 行所在的轮次，以及 catalog 里的名字。这些放在 `ListTurnsResult.parent` 里，面板显示在视角行上方。
- **趋势图。** 柱宽按面板宽度适配：可用宽度 ÷ 请求数，限制在 2–7px；不足 2px 时改为横向滚动。轮与轮之间留出间隔，轮号标在开头。当前轮只描边，不铺底色。命中率的画法不变。虚线表示压缩，点击打开。地图上不放参与者标记：试过在委派请求下面放小圆点、在有其他 agent 的轮次上加标记，都去掉了，因为它们和下面的标签重复，而且光看地图读不出含义。

## Alternatives considered

**分组胶囊，外部 agent 在每一轮保留。** 这是先上线的版本：主对话、外部 agent、子 agent、压缩分组放在趋势图上方，每个外部 agent 的标签在每一轮都保留，没调用的变暗。实际用下来，阅读顺序是反的（趋势图放在一个它自己也依赖的视角选择器下面），而且很多标签点进去是空的。改成先放轮次地图、只列这一轮的参与者，两个问题都没了；代价是不能再从标签上跟着某个 agent 跨轮看，地图上的轮次标记能看出其他 agent 在哪几轮参与过。

**下划线标签（方案 A）。** 更轻，但子会话多时要横向滚动。

**会话级的压缩标签，固定放在最右边。** 这样压缩就和轮次切换器、以及趋势图上标出它发生位置的虚线脱节了。挂在所在轮次，三者能对得上。

**所有子视角都在每一轮保留标签。** 会留下点进去是空的标签。现在只列所选轮次的参与者。

**用开头文字，或者用「和上一次触发消息的差异」做预览。** room 的每条消息开头都是同样的协调者提示词和成员名册。去掉相同开头的办法在名册一变时就失效了。在真实的房间会话里，最后一段每一轮都对应真正送来的内容。

**按「没有工具调用」判断外部 agent。** provider 也可能通过工具调用启动子会话。descriptor 里的 provider 才是记录在案的事实。

**趋势图里把未命中画成绝对长度的红色段。** 提出过，用户觉得看起来别扭，没有采用。保留现有的命中率填充。

## Consequences

- 强调色（选中、当前轮、标签下划线、焦点框）用 `--dsw-alias-state-business-primary`；链接用 `--dsw-alias-link`；压缩标记用面板色板里的紫色 `--ri-compaction`。`--dsw-alias-brand-primary` 是主题的中性强调色（亮色下接近黑、暗色下接近白），不是强调色：误用它会在亮色模式下出现黑色描边和灰色底带。
- 面板里的浅底统一用 `--ri-fill-1`（`bg-module-platform`）和 `--ri-fill-2`（`button-ghost-active-fill`），不直接用 `bg-layer-2/3`：宿主的亮色主题把三个背景层都设成白色，结果分段切换、时间线轨道和所有灰色卡片底都看不见了。时间线把空闲时间画成斜纹段，标明是首次请求前、请求之间还是最后请求后，让整条时间线覆盖整轮的时长。
- 压缩请求在 `listTurns` 里不再有自己的轮次。按伪轮次寻址的调用方仍然可以通过 `getTurn`/`getRequest` 拿到，但面板只从所属轮次进入。
- 标签行里子视角的名字去掉了 `#scopeSeq` 前缀；序号以委派请求编号的形式保留在折叠列表里。
- 每个被单独打开的子会话，在每个进程里多读一次父会话日志，只读一次。
- 趋势图不再支持拖动滚动。只有柱宽会低于 2px 时才出现原生滚动。

## Testing

`tests/agent-views.spec.ts` 覆盖：
- 带系统提示和工具定义的压缩回放；
- 只有 catalog 行的子会话；
- `delegatedBy` 和 `delegates`；
- 压缩挂到轮次、链接改址（包括趋势图）；
- 父会话链接。

`tests/client-agent-tabs.spec.tsx` 覆盖扁平的参与者标签行、「+N」折叠时当前选中项保持露出、关系行和父会话行。原有的面板和压缩测试按 tab 角色和新的轮次列表更新。

用 3080 的会话日志跑过一遍，结果如下：
- 房间会话「邀请Claude、Kimi和Codex打招呼」现在在第 1 轮显示 Kimi Code、Codex、Claude Code 三个视角；改动之前一个都没有。
- 一个同时有压缩和裁剪的会话，把压缩挂到了第 5 轮、请求 #23 之后，压缩请求带有 9,253 字的系统提示和 15 个工具定义。
