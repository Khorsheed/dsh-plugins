# Agent Note: the judge bench — blind queue, de-fingerprinted artifacts, the one human-final door (I5 · T37)

Status: implemented

English | [中文](2026-09-15-eval-judge-bench.zh.md)

## Problem

Step 8 of the eight-step flow — *the final verdict and the first draft of the analysis* — had no surface. `human-final` was written with `dsh-mission annotate --ns human-final`: a CLI call, against a mission id a person had to look up, with a verdict document they had to hand-write and a `by` they had to remember to set. The mechanical half of judging was already automatic (probes write `script`, the blind LLM panel writes `llm-draft`); the half that the whole design says must stay a person's was the one with no place to stand.

Two things make that page harder than the six before it.

The first is that **blindness is a property of a payload, not of a layout**. A judge bench whose page merely declines to render the harness is one careless `title={...}` away from unblinding the person using it — and the giveaway is not only the obvious fields. The orchestrator names cells `<item>-<conditionId>-rep<N>`, and a condition id names a harness as often as not (`codex-scope-a` contains `codex`). So the mission id — the natural handle for "which cell am I grading" — is itself a fingerprint, and the decided interface (`humanFinal(agent, {runId, missionId, verdicts})`) would have put the subject in the DOM of the one page that must not carry it.

The second is that **this page creates the only write path to `human-final` that will ever exist**. R1 says approving, logging in and the final verdict are always a person's act, and for the first two that holds because the verbs live behind the interface. For the final verdict it now holds because this code exists and no model tool reaches it. That is not a property to assert in a comment; it is one to build so that it cannot be otherwise.

## Decision

- **Blind is enforced at the seam, not in the renderer.** `judgeQueue(agent, {runId})` sends no condition id, no harness, no model — and no mission id. Each cell travels as an **ordinal plus an opaque ticket** (`sha256(runId\0missionId)` truncated to 16 hex), and `humanFinal` resolves the ticket back host-side by re-deriving it over the run's own cells. The ordinal follows the run's own seeded order, which is part of the blind: consecutive numbers say nothing about which cells share a condition. Judge conditions get the same treatment — the panel reads **Judge A / Judge B** by the run's sorted judge order. The test does not assert that the page hides these things; it serializes the whole payload and searches it for every identifier the run declared.
- **This changes the decided signature: `humanFinal` takes `ticket`, not `missionId`.** The brief fixed `{runId, missionId, verdicts}`. Keeping it would have contradicted the brief's own blind boundary two lines later, and on the real acceptance run the mission id is `p0-placeholder-codex-scope-a-rep1` — the harness, spelled out, in the page's markup. The ticket is the same handle with the fingerprint removed.
- **One de-identifier, reused, not reimplemented.** The artifacts come out of the same `deidentify` the run loop hands the LLM judge, over rules rebuilt from the same `run.meta.conditions`. The text is read from the **archive** (`archive/workspace/`, written by the host path's directory copy and the container path's `lab.archive` alike), not from the per-cell scratch directory, which does not outlive the run. Each file reports how many fingerprints were replaced — the one number that tells a grader the scrub actually ran rather than silently no-oped.
- **One rubric parser.** `llmDraftCriteria` became a thin wrapper over `rubricCriteria(text, kind)`, and `humanCriteria` is its sibling. The protocol splits a rubric three ways with one reader each; three readers each parsing it their own way is three places for "what does this rubric say" to diverge.
- **One consistency implementation.** `judgeConsistencyOf` was widened to a structural input (`JudgeConsistencyCell`) and exported, so the bench's header and the report page's block are the same function. Only the source differs: the report reads a bundle, the bench reads the **live ledger** — a verdict a grader just recorded has to move the numbers they can see, not wait for a re-export.
- **Append-only, and the page says so.** `humanFinal` forwards mission's `annotate` and does nothing else. A second pass over a cell appends; the report reads the latest value per criterion and the earlier one stays in the ledger. A cell that already carries a verdict shows what it carries and says that recording again appends rather than replaces. An identical repeat is mission's own no-op, and the result reports `duplicate` rather than claiming a write.
- **`by` is the session (`tab:<sessionId>`), the verdict document's own `by` is `judge-bench`.** The report's top red flag fires on `human-final` verdicts written by a `tool:` origin. A verdict from this bench cannot raise it, and the reason is structural rather than a check.
- **Every verdict needs evidence, and unanswered criteria are not sent.** The schema would accept an empty `evidence`; the protocol would not ("a checkable fact, not an opinion"), so the host refuses a blank one and the button will not offer it. A criterion nobody touched is not a verdict of "does not hold".
- **The bench states what a first verdict costs — found during acceptance, not designed in.** The report picks a cell's scoring source as the most authoritative namespace holding **any** verdict and scores the whole cell from that one (`primaryPass`); it does not merge per criterion. So the *first* `human-final` verdict on a cell — even one answering a single `kind: human` criterion — makes human-final that cell's only scoring source, and its llm-draft-only criteria stop counting. Measured: on `t31-judge-panel`, answering C2 alone drops B2 and D1–D4; on a synthetic two-condition bundle the paired mean falls from 4 to 1. The bench does **not** change that rule — it is the report's, it predates this slice, and changing it would move every report ever produced — but it now carries `draftOnlyCriteria` and prints the consequence, with the criteria named, above the button.

## Alternatives considered

### Why not keep `missionId` in the write verb, as the brief decided?

It is the decided interface and the obvious handle, and the ticket costs a resolve step on every write. But the same brief says "页面上不出现条件 id、harness、模型", and a mission id is a condition id with an item and a rep glued to it. Keeping the parameter would have meant either sending the mission id to the browser (unblinding the page) or sending the ticket anyway and translating in the client (putting the blind boundary in the renderer, which is the thing this design is trying not to do). The deviation is one parameter; the alternative is a contradiction between two lines of the same brief.

### Why not a random opaque id, minted and stored per queue read?

A random ticket is unguessable, which sounds stronger. It also needs a server-side map with a lifetime, and it changes on every read — so a grader who reloads mid-verdict loses their place, and two tabs disagree about what "cell 3" is. Blindness does not need unguessability: it needs a name that carries no fingerprint. A hash of `(runId, missionId)` is stable, needs no storage, and cannot be replayed into another run because the run id is inside it.

### Why not read the de-identified copies the run loop already wrote under `<stateRoot>/judge/`?

Those files exist, are retained for review, and are already scrubbed — reading them would have been strictly less code. They are also the *LLM judge's* copies: they exist only for cells that reached the blind-judging phase with a rubric that had `llm-draft` rows, and their scrub table was the one in force when the run executed. A cell that halted early, or an item with no `llm-draft` criteria at all, has no such directory — and those are exactly the cells a person is most likely to be asked to grade by hand. Reading the archive and scrubbing on the way out covers every cell with one code path, and reuses the same function rather than trusting a file someone else wrote.

### Why not compute the agreement numbers from the exported bundle, like the report page does?

It would have been one call to the same projection. But a bundle is a snapshot of an export, and the bench's whole purpose is to *add* verdicts: a grader who records a verdict and sees the header unchanged has no way to tell a working write from a broken one, and the fix — "export the run again" — is a step nobody should have to take to see their own act. Reading the ledger keeps one implementation of κ and puts the effect where the cause was.

### Why not fix `primaryPass` to merge per criterion, since the bench is what makes the hazard reachable?

It is the right end state and the change is small. It also silently re-scores every run ever analyzed — including the pilots whose numbers are quoted in `iterations.md` — and it is a methodology decision (does one human answer supersede a cell, or one criterion?), not a UI slice's call. Naming the cost where the cost is paid keeps this slice honest without moving anybody's history; the merge belongs in its own task, with its own review of what the old numbers meant.

### Why not offer the `llm-draft` criteria on the bench so a grader can answer them all?

That would remove the hazard above outright. It would also erase the rubric's own three-way split: a criterion the author marked `llm-draft` is one they decided a model's reading of the artifacts can settle, and turning the bench into a place to re-answer all of them makes the panel decorative. The warning tells a grader the consequence and lets them decide; widening the form would decide for them.

## Consequences

- `EvalRemoteService` grows two session-scoped verbs, `judgeQueue` and `humanFinal` (22 total). Neither has a model-facing twin, and `humanFinal` is the only write path to the `human-final` namespace in this family.
- `EvalService` grows `judgeQueue` and `humanFinal`; `judge-bench.ts` is new and holds the projection, the ticket, and the write.
- `faces.ts` grows `MissionAnnotateFace` — one verb, deliberately: it is the entire surface through which `human-final` can be written, and keeping it to one verb is how R1 stays structural.
- `judge.ts`: `llmDraftCriteria` is now a wrapper over the new `rubricCriteria(text, kind)`; `humanCriteria` is new. No behaviour change for existing callers.
- `report.ts`: `judgeConsistencyOf` is exported and takes a structural `JudgeConsistencyCell[]` instead of `BundleCell[]`. Same computation, same numbers.
- The seven-sub-page shell is complete; `placeholder.judging` is gone and `PAGE_PLACEHOLDER` with it. `LabView.client.spec.tsx`'s placeholder case became "a draft says so on every sub-page that needs a run".
- The `draftOnlyCriteria` field and its warning are a standing note about `primaryPass`; if that rule is ever changed to merge per criterion, both should go.
