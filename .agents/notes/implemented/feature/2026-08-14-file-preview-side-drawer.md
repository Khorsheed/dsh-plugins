# Agent Note: The file-preview side drawer

Status: implemented

English | [中文](2026-08-14-file-preview-side-drawer.zh.md)

## Problem

The web GUI showed session artifacts only as tool-call cards; previewing a read, written, or edited file meant opening it in an external editor. The client has no filesystem channel — the object layer exposes only the conversation snapshot and the workspaces `openPath` OS-open verb — so a browser-side drawer cannot read file content on its own, and the client's paged, compacted session window is not an authoritative source for "which files did this session touch". The host session log is that source, but nothing exposed it read-only to the UI, and file links in the conversation only ever opened the OS.

## Decision

Ship a dual-half plugin pair. The host half, [`@deepseek-ai/dsh-file-preview`](../../../../packages/fs/file-preview/README.md), is a read-only `filePreview` Remote service with two methods: `list(agent)` folds the agent session's `tool/call` events for the `read`/`write`/`edit` tools (all keyed on `file_path`) — plus settled `tool/code-dispatch` events for those tools, so Code Mode sessions (which mutate files only through nested dispatches) are covered too — into a first-seen, deduplicated file list, appending each write/edit change's diff from the `tool/result` presentation meta to the entry's `diffs` in event order (each carrying its seq/turn/step, with `lastDiff` kept as the final change for callers that want just the latest; pure log fold, no filesystem access); `read(agent, path, signal)` resolves the path against the session cwd and serves current text content through `ctx.fs`, capped by `maxReadBytes` and classified as text/image/binary/missing/too-large/error. Image reads return a browser-loadable URL served by a dedicated host route (`/file-preview-image/<sessionId>/<path>`); the route registers only when the optional `webServer` and `agents` services are composed (the structural `ImageRouteHost` face keeps the package free of a webserver dependency), and image reads answer `binary` on headless hosts. The browser half, [`@deepseek-ai/dsh-client-ui-file-preview`](../../../../packages/client/ui-file-preview/README.md), is a pure additive plugin over official extension points — it edits no core package. It mounts its own Remote through `ctx.remote.$mount` — because the plugin both mounts the `filePreview` namespace and consumes it, the namespace is NOT declared as an inject (that would deadlock the loader: the fiber waits for the service, which only this apply's `$mount` can provide; the property proxy also cannot see the sibling namespace fiber `$mount` spawns), so the mount is awaited and the namespace is read back from the global service store via `ctx.get('remote.filePreview')` — registers a turn-files fold through `conversationEvents`, and registers three surfaces: the `'file-preview'` entry in the `conversation.view` tab ring (beside chat and trajectory, the trajectory registration precedent) with a session-scoped store that lists the session's products (written/edited files only, matching the chat area's vocabulary), latest activity first, and previews the selected file — its current content by default (with a content-search box that highlights and jumps matches), a changes tab that steps through every recorded diff, and inline images; a per-turn mutation card in the `conversation.chat.turnTail` chain; and a content-only drawer (`shell.overlay`) that previews a single path without a file list. While the drawer is open it marks the document (`data-file-preview-drawer-open`) and its own CSS pushes the conversation's scroll body and composer seat left by the drawer width, so chat never sits underneath. Both surfaces share one preview pane, fetch `list` on each tab activation / drawer open and `read` on selection, and drop stale in-flight requests when the selection moves or the surface unmounts. Each surface scrolls independently of the surrounding page (the bounded-height composer-overlay precedent), and diff lines soft-wrap through the plugin's own CSS (the shared `DiffBlock` is untouched).

File links route through official extension points only — the plugin edits no core package. Each finished turn's mutations render as a "N files changed" card in the `conversation.chat.turnTail` chain — the chain elects one entry per turn (first non-null `select` by ascending priority), and the plugin's entry preempts the official produced-files row so the two never coexist; see [the rerouting note](2026-08-15-file-preview-official-open-rerouting.md) — folded client-side by the plugin's own `ConversationNodeDefinition` (`kind: 'filePreviewMutations'`) from the write/edit `file_path` arguments, with per-file line deltas from the diff call views. A card file-row click opens the plugin's drawer in place (the drawer needs no session handle), whose header also carries "show in folder" / "open in IDE" host gestures gated by loopback + `canOpenPath`. Official prose mentions are rerouted into the drawer by the same note's capture-phase interceptor; arbitrary file paths in prose keep the host OS open — the core offers no third-party hook for arbitrary link interception. The controller attaches each session's store under its session id, adopts the drawer's store, and parks a pending path for a gesture that lands before the view ever mounted.

The service is read-only and trusted: it can read whatever `ctx.fs` allows for the session, so composing it grants preview access to the session's filesystem view — it is not a security boundary, and it emits no session events (model-visible ⟺ logged is unaffected).

## Alternatives considered

**Client-side scan of the conversation snapshot.** Rejected: the client window is paged and compaction-truncated (not the full log), and even a complete list would leave content reads blocked — the client has no file channel and adding one from the browser would duplicate the host `fs` seam.

**A session projection unit for the file list.** Rejected for v1: projections exist for whole values the client must render live with push updates, while the drawer refreshes per user gesture; a `list` RPC keeps the host computation an ordinary method with no cache/persistence machinery. A projection remains addable if a live-push requirement appears.

**Taking over the `details` column.** Rejected: that column is occupied by ui-conversation's tool-details panel; the file view uses the additive `conversation.view` ring instead, so no existing surface is replaced.

**Patching the conversation package to route file opens.** Rejected: a patch can replace config rows, not another package's compiled code; routing is instead an optional-service seam owned by the core, keeping the plugin independently distributable.

## Consequences

The view previews text only (binary and oversized files render classified notices), shows the current session's files, and is read-only. The list is a point-in-time fold; there is no push channel for new files. A conversation whose core lacks the seam opens file links in the OS as before. Coverage: the host fold/read paths and the view's list/preview/diff lifecycles are unit- and component-tested, and a keyless Loader composition e2e (`examples/headless-agent/tests/fixtures/file-preview`) boots the real service with `fs-local`.
