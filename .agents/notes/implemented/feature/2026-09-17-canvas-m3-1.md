# Agent Note: canvas M3.1 — selections belong to the quote plugin, and fullscreen was never suggestible

Status: implemented

English | [中文](2026-09-17-canvas-m3-1.zh.md)

## Problem

Two pieces of 3080 feedback landed on M3 within a day.

**The detail page's text-selection "问 Agent" float was a duplicate.** M2 built a floating button over text selections in the card-detail reader (select prose → ask the agent about it). The quote plugin (`@khorsheed/dsh-quote`, M1 on main) has since taken over selection interaction app-wide — its float offers quote-to-current-session / quote-to-side-chat / copy wherever a selection happens. Two floats answering the same gesture in the same spot is not redundancy, it is interference: the canvas's bespoke copy of an app-level interaction had to go.

**The M3 wide-mode suggestion backfired.** M3 suggested fullscreen on tab open (`openRightbar(track, fullscreen)`). The host's fullscreen mode **hides the right panel's resize handle** (the user measured: the width became unadjustable), and "保留会话列宽" preserves a LARGE width. A suggestion that removes the user's own adjustment affordance is not a suggestion, it is a take-away — and its fallback ("click to exit fullscreen") requires knowing the affordance it just hid.

## Decision

**The selection float is deleted, not adapted.** Removed from `CanvasDetailView`: the `mouseup` selection listener, the floating button and its position math, the `.askFloat` styles, and the `chat.ask` / `chat.selectionRef` locale keys, plus the matching detail-spec case. What deliberately stays: the lens bar's「就此提问」and the comment thread's「追问」— those are card-level and comment-level actions, not selection behavior, and the quote plugin makes no claim on them. The `askAgent` verb and the whole `openWith` wiring are untouched (lens and follow-up still ride them). The contract sentence going forward: **the canvas owns no selection interaction**; the quote plugin's float is the single answer wherever text is selected, canvas detail included.

**The fullscreen suggestion is reverted to the plain track panel.** `suggestWideMode` no longer calls `openRightbar(track, fullscreen)` at all — the right panel stays in normal track mode: resize handle present, width user-adjustable, layout remembering. What stays is the per-session one-shot `toggleSidebar()` suggestion for the LEFT session list (DOM-gated on the frame's `data-sidebar-collapsed` marker, never a blind toggle, never re-forced) — collapsing the list removes nothing the user can't bring back with one click, which is the property a default suggestion must have. The upstream candidate gains its rider: a per-tab presentation seam is still the honest shape for "this tab wants to be wide", but **fullscreen itself is disqualified as a default suggestion** — it hides the handle.

## Alternatives considered

### Why not keep the float only where the quote plugin does not reach?

The quote float is app-level by design — it reaches every selectable surface, including our detail body. Carving out "quote-less zones" would mean checking which float won the gesture race on every selection, which is exactly the interference the user reported. One owner per gesture: the plugin built for the app level owns it.

### Why not keep the fullscreen suggestion but fire it only once per canvas open rather than once per session?

Frequency was never the problem; the mode itself was. Once per open would still hide the resize handle on every open, and the user's fix (exit fullscreen, resize, never touch the tab again) teaches them to avoid the tab. A suggestion whose every instance needs undoing is a bug with a schedule, not a feature.

### Why not suggest a custom wider track width instead of fullscreen?

There is no public face for "set this panel's width" — the track width is ui-sidebar-right's store fact, same ownership problem as fullscreen itself, and the same upstream seam covers both. The honest default is the normal panel plus the handle the user already has.

## Consequences

- `packages/canvas/src/client/detail/CanvasDetailView.tsx`: the selection listener, the float, and its `textPick`/`bodyRef` state are gone; the ask flow keeps only its two card-level entrances.
- `packages/canvas/src/client/detail/CanvasDetailView.module.css`: `.askFloat` block removed.
- `packages/canvas/src/client/locales.ts`: `chat.ask`, `chat.selectionRef` removed (both dictionaries).
- `packages/canvas/src/client/index.ts`: `suggestWideMode` drops the `openRightbar(track, fullscreen)` call and its `fullscreen` parameter; the per-session `toggleSidebar()` suggestion is unchanged.
- `packages/canvas/src/client/contract.ts`: the face's `suggestWideMode` signature narrows accordingly; `packages/canvas/src/client/tab/CanvasTab.tsx` no longer reads `useTabInfo` for it.
- `tests/detail.client.spec.tsx`: the selection-float case removed (167 green, from 168); `tests/tab.client.spec.tsx`: the wide-mode assertion follows the new signature.
- `package.json` 0.4.0 → 0.4.1.
- The M3 note's wide-mode paragraph is the fact this one corrects; the two notes are cross-linked. The Remote surface, the tools, the side-chat seam, and every other M3 decision are untouched.

## Testing

- `packages/canvas`: **167 tests green** (168 − 1 removed float case). `rm -rf lib` then `pnpm --filter @khorsheed/dsh-canvas build`, `pnpm check:hygiene -- packages/canvas`, `pnpm check:plugins`, `pnpm test:scripts` all green.
- The two surviving ask entrances (lens「就此提问」 and comment「追问」) keep their spec coverage, so the kept wiring is proven, not just kept.

## Deferred

- A per-tab presentation seam ("this tab wants more width", definition- or navigation-level) stays an upstream candidate — now with the rider that fullscreen (handle-hiding) is disqualified as its default.
- The quote plugin's float reaching the canvas BOARD (not just the detail body) is its own package's surface decision, not canvas's to wire.
