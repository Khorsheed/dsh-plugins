# Agent Note: request-inspector client panel — the 请求明细 right-sidebar tab and its two entries

Status: implemented

## Problem

The M1 host capture (see [the host-capture note](2026-10-09-request-inspector-host-capture.md)) puts every turn's requests on the `requestInspector` Remote, but nothing a user can open existed. The browser half had to port the approved interactive design (`scratch-request-inspector/index.html`, real captured data inlined) onto the Remote verbs faithfully — including the parts the mock could not express (turn switching, live session identity, per-scope config) — while satisfying the panel-design spec (one width-adaptive layout, `--dsh-panel-*` type, `--dsw-alias-*` theme colors) and the visibility convention (session-bound content self-hides by preset composition).

## Decision

One right-sidebar page tab (`request-inspector` kind, the worktrees two-stage registration: `sidebarRightTabs.register` for the type, the body under `sidebar.right.pane.tab` keyed by the package id) plus two entries opening it: the assistant message's action-row icon (`conversation.chat.assistant-actions`, resolving `messageId` → `turnSeq` via `TurnListItem.closingMessageId`, latest-turn fallback) and a session-header utility (`conversation.session.header.utilities`, latest turn). All three registrations ride the canvas-pattern `RegistrationToggle` over the preset-visibility probe — the criterion is this package's own row (root-mounted by the bundle patch → granted to every session; the preset path is checked too), every unreadable path fails open. Unlike canvas, the slot entries also toggle at registration level (the toggle wraps `ctx.slots.inject` directly — it returns a synchronous disposer).

The panel itself:

- **Header**: title 请求明细 + the design's mini segmented switch (Token 分布 / 耗时分布）; the query line carries the query text, the turn switcher, and the scope tag. The design's close button is dropped — the host's tab chip already closes the tab (the panel-design 不重复 rule).
- **Turn switcher** (2026-10-10): the native `<select>` shipped first and read wrong; it is now the host's own `Menu` (ui-primitives — keyboard walk, Escape/outside-click, focus return), trigger `turn N · query 预览`, rows carrying the turn number, query preview, request count, and token totals (newest first). Next to it the 定位到最新 button shows only while a newer REAL turn than the selection exists (pseudo-turns have no conversation anchor).
- **Scroll-sync** (2026-10-10): switching the panel's turn — from the menu, from the action-row navigation params — scrolls the conversation to that turn over the DOM anchors `[data-conversation-scroll]` + `[data-chat-turn="<hostTurn>"]` (the exact row, else the nearest mounted turn ≥ it in DOM order, the host `scrollToTurnAtOrAfter` semantics), reduced-motion aware, every failure a silent no-op. No public API exists; the seam is registered as docs/upstream-seam-registry.md S20. The 最新 button bottoms the scrollport out instead (`scrollTo(scrollHeight)`, largest turn row as the anchor fallback).
- **Scope chips** (the kit's `ChipRow`): 主对话·N 请求 + one chip per delegation run (▸ #firstSeq label ✓/✗, never merged). A failed run with 0 requests shows the failure state page — 运行失败 · error · 耗时 · 0 次模型调用 — the emptiness IS the diagnostic. A failed run WITH requests shows the failure card above the normal view (the design replaced the body unconditionally; hiding captured requests would lose data).
- **Token 分布**: request cards left (`#seq · responseSummary`, 输入/输出 tok · 耗时， 缓存命中 + mini bar), the selected request right (anchor row with config, the category stacked bar + click-to-filter legend, and the four isomorphic blocks — system per-section rows, the tools two-column grid, history collapsed with top-3 category chips, added open). Rows expand to verbatim `full` text; assistant rows unfold the `{reasoning, text, calls}` JSON into labeled sections.
- **输入/输出 split** (2026-10-10, on the host's `CapturedRequest.response`): the four-segment detail retitled 输入 (it is the request's input), and a default-expanded 输出 block after it gives THIS request's response a first-class home — the header merging the old anchor line (本次响应 → summary · 输出 N tok · Ns), the body verbatim (reasoning / text / one row per tool call), streaming → 进行中, failed-before-blocks → the error text, absent otherwise → an inert header with nothing fabricated. Rows in 新增 that are a previous response carry the「← #N 的响应」provenance label, N resolved client-side: the scope's request list within the turn, else a lazy fetch of the previous REAL turn's overview (scopes are continuous across turns; pseudo-turns never count); a scope's first-ever request gets no label.
- **耗时分布**: the design's scope chips filter this tab too, and the lanes make that exact — `TimingLane` carries `scopeId`, `requestSeq`, and `tool` on tool-args/tool-exec lanes, so the panel re-derives buckets, the per-tool rows, and the call rows from `TurnTiming.lanes` for any scope selection (main = the whole turn). Inter-lane gaps fold into 其他开销， the design's 调用间隙 rule; the host's `TurnTiming.buckets.otherMs` covers only intra-request gaps, so the panel's whole-turn other bucket is lanes + gaps by design. Call rows click through to the token tab's that request.
- **Footer**: 结构化 / 原始 JSON (the `CapturedRequest` serialized) / wire body — the last is the not-yet-implemented enhancement seat, rendered disabled with the `需要宿主 ≥0.1.2` tooltip, exactly as the design shows.

`<details>`/`<summary>` rows are driven through controlled state (the summary's click is pre-empted): jsdom never performs the native toggle, and a re-render must never snap a user's fold back. State is React-local (no slot store): no surface outside the tab reads it. The sample page for the screenshot self-check lives in `scratch-ri-panel/` (gitignored).

## Alternatives considered

- **Whole-turn-only timing tab (the milestone brief's literal reading)**: the design's scope chips filter the timing view, and dropping that would strand the chips on one tab. Lanes carry everything the filter needs, so the per-scope view is exact rather than degraded; whole-turn sums equal the host's buckets by construction (before the gap fold, which the design mandates).
- **A `defineStore` slot store (the worktrees pattern)**: rejected — the store exists so the badge/title share tab state; nothing outside this tab reads the inspector's selection, and React-local state keeps the component directly testable with composed props.
- **Keeping the native `<select>` for the turn switcher** (the first cut): rejected on review — it renders the OS chrome, not the product's; the host `Menu` gives the keyboard walk, dismissal, and focus return for free and carries two-line rows (title + count/tokens) a `<option>` cannot.
- **Rendering `ToolTiming.tools` for the per-tool section**: the host aggregate has no `scopeId` and no per-bucket split, so a scope-filtered timing tab could not use it; the lane-derived rows (calls · argsMs · execMs) are what ships. The design's per-tool 等待/思考/输出 columns have no data source and are dropped.
- **`remote.pluginInventory` in `inject`**: rejected per the visibility doc — a host without the namespace would pend the whole client; the probe goes through `ctx.get` and fails open.

## Consequences

- The token tab defaults to a scope's FIRST request (the design's `selected = 0`), not the last; the ＝弹层 marker from the mock is gone with the mock's chat column.
- Contract gaps found while porting (reported, types unchanged): `responseSummary` hardcodes「直接回答」host-side (store.ts `summarizeResponse`), so the anchor and card titles stay Chinese under the English locale; `AgentScopeOverview` carries no delegation-run seq, so a failed 0-request run's chip has no `#seq`; `ToolTiming` is whole-turn-only (worked around via lanes); `TurnTiming.buckets.otherMs` excludes inter-request gaps (the panel folds them in).
- The package still lacks `README.md` / `README.zh.md` with the Compatibility section — required by the npm pre-publish checklist, deferred to the publish milestone.
- The M1 note's two deferred gate failures are closed here: `check:panels` passes (PanelRoot + container queries + palette exemptions), and `docs/packages.md` lists the package (regenerated).

## Testing

The screenshot self-check ran on the sample page (390px light/dark + 800px, no horizontal overflow).
