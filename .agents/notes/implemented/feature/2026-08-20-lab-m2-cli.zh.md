# Agent Note: lab — dsh-lab CLI（M2 后半）

Status: implemented

[English](2026-08-20-lab-m2-cli.md) | 中文

## Problem

[lab 提案](../../../proposals/active/2026-08-19-lab-experiment-units.md)的 M2 含 CLI 面：脚本与无 agent 流程（销毁脚本首当其冲）需要在宿主进程外调用八个动词。实现过程中暴露了一个真实的 M1 缺陷：`DockerProvider` 从未给 argv 加 `docker` 二进制前缀，生产环境的 `Exec` 适配器会去 spawn `run`/`pull`……——fake-exec 单测编码了同样的无前缀形状，所以 42 个绿灯没抓住它。

## Decision

`src/cli.ts` 是薄 bin 入口（mission cli.ts 的模式：入口守卫必须住在入口模块里，否则 tsdown 分块会让它失效）；`src/cli-core.ts` 持有 `runCli(argv, io)`，注入 stdout/stderr，退出码 0 正常 / 1 失败或拒绝 / 2 用法错误。CLI 用 `child_process` 版 `Exec`（输出上限 16 MB / 1 MB，`timeoutMs` → 先 SIGTERM、宽限后 SIGKILL）构造**同一个** `LabService`——gate、上限、reconcile 的语义是共享的，不是复制一份。

mission 面适配到 `dsh-mission` 二进制，正好接线它暴露的动词：`release` 的 gate 走 `dsh-mission is-releasable` 的退出码（0 放行 / 1 拒绝 / 其他抛错 → fail closed），`verify` 经 `dsh-mission annotate --ns lab --payload <json>` 落记录。presence 探测是 spawn 一次 `dsh-mission --help`——任何退出码都算在场，spawn 级失败（ENOENT）即缺席，降级为 force + 告警路径。`MissionFace.isReleasable` 放宽为 `boolean | Promise<boolean>`，进程内同步服务与子进程 CLI 共用一个结构类型。

**更新（第二轮接触，mission 提交 `5ca20b1` 之后）：** mission CLI 补齐了 `set-refs` / `add-artifact` / `add-checkpoint`，CLI 面因此改为真实接线（非零退出 → 抛错 → 走服务的 warn 跳过纪律），不再是 warn 跳过。下文「登记是部分的」结论随之退役；被否决替代方案的前提（这些动词不存在）已消失。

前缀缺陷在 provider 修复：所有命令经私有 `docker()` 助手统一加前缀；`docker.spec.ts` 的 fake `Exec` 现在**拒绝**任何无前缀调用——测试替身强制执行生产契约，而不是编码缺陷。

## Alternatives considered

- **CLI 单独实现一套语义、不复用 `LabService`**——否决：两份 release gate 语义会漂移；一个内核，两个适配器。
- **CLI 侧登记 refs/artifact 走 mission 尚不存在的 CLI 动词**——当时不动 mission 的 CLI 面（另一个包的领土）就不可能；warn 跳过保持 lab 独立。mission 后来补齐了动词（`5ca20b1`），接线随之落地——见上文更新。
- **lab CLI 直读 mission 的 JSON store**——否决：mission 提案禁止消费方手写其文件；二进制的退出码契约才是 sanctioned 的脚本路径。
- **只修 provider、测试假件保持无前缀**——否决：测试会继续通过一个生产环境违反的契约；现在替身在无前缀 argv 上直接失败。

## Consequences

- 共 50 个测试；`tests/cli.spec.ts` 用 PATH 上的桩 `docker` / `dsh-mission` 二进制跑真实入口（经 tsx）：用法退出 2、acquire JSON + 标签 argv、经 mission 二进制退出码的 release gate 拒绝/放行/fail-closed 三联、无绑定单元的 force + 告警路径、verify 的原样 JSON + `annotate --ns lab` 调用、reconcile 后的 status。
- terminate 宽限（`terminateGraceMs`，默认 2 秒）在 CLI 测试里是真实等待——release 测试各约 2.6 秒。
- CLI 模式的登记现覆盖 mission 二进制的全部动词集（set-refs / add-artifact / add-checkpoint / annotate / is-releasable）；更丰富的登记仍走进程内服务面。
- docker 前缀修复除了新增的前缀断言外不改变任何测试可见行为；生产行为从坏到好。

## Testing

`packages/lab/tests/cli.spec.ts`（8 个测试）以 `node --import tsx/esm src/cli.ts` 配桩二进制（shell 脚本把 argv 记入 `$LOG`，按 `$STUB_*` / `$MISSION_EXIT` 环境变量应答）运行；`docker.spec.ts` 的 fake `Exec` 对每次调用断言 `docker` 前缀。
