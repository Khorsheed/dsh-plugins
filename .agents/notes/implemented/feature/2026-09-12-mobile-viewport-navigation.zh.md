# Agent Note: 移动端视口导航与保留归属的选择面板

Status: implemented

[English](2026-09-12-mobile-viewport-navigation.md) | 中文

## Problem

移动外壳可能整体滚动，在输入框下面露出空白。会话列表完全替换聊天页，桌面菜单的位置不适合手机，标题编辑按钮落在单独的插件行里。原生安全区和网页可能出现色差。用户还反馈，Web 发起的回复在手机端要等完成才出现。

## Decision

移动呈现将应用框架固定在可视视口内，通过 ResizeObserver 测量原有输入区。只有聊天内容滚动，底部留白跟随输入区高度。原编辑器保持挂载，保留草稿、队列和插件插槽。

横向手势展开最多占屏幕 84%、上限 380px 的列表，右侧保留聊天预览。宽度达到 960px 时，列表固定为 320px，聊天区可继续操作。控件、文本选择、弹窗和横向滚动内容保留自己的手势。其他移动页面共用列表导航；不另建历史栈，也不覆盖弹窗关闭行为。

标题旁的铅笔调用原 session-title-edit 控件。工作区和模式菜单保留原条目及选择回调，经已验证的新会话触发器识别后，将其下一个菜单呈现为底部面板。工作区搜索保留添加入口。未知插件控件仍由原插件负责。移除新会话中的 DSH 字标。

原生外壳使用网页框架背景填充安全区，禁用整个 WebView 回弹，并让移动呈现接管横向导航。外观消息继续经过原生桥来源检查。前台恢复将原生恢复、隐藏转可见和持久化 pageshow 事件合并为官方连接重连，仅在移动呈现启用时生效，不重发提示词。

## Alternatives considered

**另做移动编辑器或传输层。** 这会重复队列、流式和插件行为。原有输入区、会话订阅和菜单继续作为唯一行为来源。

**把其他插件的 React 节点搬进移动容器。** 这会引入归属和清理风险。呈现层使用经过验证的锚点和 CSS，关闭后移除自己的尺寸和装饰。

**宣称同步延迟已经修复。** 独立前台客户端在执行完成前均显示递增正文。这排除了无条件等完成才显示的路径，但没有复现所有挂起或网络场景，原反馈仍是验收缺口。

## Consequences

导航、选择面板和滚动布局改善，宿主和其他插件源码不变。DOM 特征仍是兼容边界，宿主升级后需要浏览器验收。窄屏显示预览，宽屏才保留两个可操作栏。原生安全区和键盘行为仍需真机验收。

## Verification

移动包构建及 64 项测试通过，覆盖手势排除、选择回调归属、输入区尺寸清理和合并恢复事件。iOS 模拟器构建通过。浏览器连接真实服务、仅替换移动客户端包，验证聊天区滚动 900px 后导航及输入区坐标不变、窗口滚动为零、手势展开、原标题编辑器位置、宽屏列表为 320px 且聊天可交互，以及工作区搜索保留添加入口。已查看深浅两套配色；浅色验收仅在浏览器本地应用配色，没有写账户偏好。

独立浏览器上下文中，一条普通回复在结束前出现三组长度递增的助手正文。公网入口测试也收到递增流式帧，但没有提供同等完整的正文对比。对尚未复现的用户延迟不指定根因，也不将前台恢复处理当成全部跨端延迟已解决的证明。
