# Agent Note：卡详情页成为画布唯一的编辑器——并且它带一支笔

Status: implemented

## Problem

四条令同时落在 `@khorsheed/dsh-canvas` 上（用户原话）：① 点卡片进详情页，而不是在板上就地改；② 详情页要能吃下粘贴的 markdown / HTML / 图片并渲染；③ 详情页要能自由绘画（后续给模型当多模态参考）；④ 外层卡片样式不对。四条共同过一道很硬的评审程序：**"先画到 html 给我体验看看，体验 OK 之后你可以按照对应的交互来考虑如何实现"**——六轮可点原型（`proposals/prototypes/canvas-link-compose-draw.html`）之后才动包内一行源码。

六轮把一件结构性的事照了出来：板上有一个就地 textarea，详情页又有一个编辑器，于是每加一样能力都得做两遍；而且板上那个 textarea 一直和它旁边的渲染器打架（一张卡的格式是从**合成后的整张卡正文**嗅出来的，从不看标志位，就地编辑面恰好就是同一个判定被做两次、还做得不一样的地方）。

## Decision

一个编辑器、一个座位，外加"画是内容"。

- **卡板只读**；详情页（`detail/CanvasDetailView.tsx`）是卡正文唯一被改动的地方。「＋新卡」把草稿交给同一个页面——草稿的字和笔画住在 **tab 的 state** 里（`tab/CanvasTab.tsx` 的 `newCard`），详情页只能通过 `CanvasDetailCreate` 那组回调去够它们，所以草稿永远不会以"半张卡"存在。草稿页开在**源码**态（`if (drafting) setMode('source')`）：一个空渲染面不是书写面，而「＋新卡」这个手势的意义就是键盘已经在手上。每次选中变化都把正文退回阅读态——同时把笔放下。
- **出口围栏数的是"字或笔画"，且只弹一次。** 只有草稿真有字或有笔画时才弹确认（`Modal`，两个按钮）；没动过的草稿静默离开；**已经落盘的卡一律不拦**（它的改动早就存了——"要不要连它一起拦"是 11.8 ⑥，仍未裁决）。
- **画是内容，不是题注。** `card.draw` 是受类型字段（`CanvasStroke[]`），`putCard` **有画就接受空正文**，并且画跟着卡的模型面形态走：`promptFormOf` 三个分支都追加 `drawPromptOf` 的 `<board width height strokes>` 点列段——读到一张卡就读到它的墨，读的是几何，不是一张还得另外递给它的位图。
- **笔交出一笔，键盘交出草稿。** 一笔完成就用整份点列 `patchCard` 立刻写盘，所以画板没有脏标记、也没有自己的保存钮；`mutate` 的 toast key 因此改成可选——**一笔落在屏幕上就已经说完了它要说的话**，再 toast 一次只是噪声。`draw: []` 是"清空"，与"不带 `draw` 键"必须可分：不分开，「清空」就永远存不下去。
- **存的是逻辑框里的点列，既不存轮廓也不存像素。** `{ pts: [{x,y,w}], color }`，单位是 600×400（3:2）的框，轮廓由 `perfect-freehand` 在渲染时现算。实测一笔 24 个点：**点列 287 B、收尖轮廓 834 B**。用框单位才让 378px 窄栏里画的一笔在宽面板上落在同一个位置；`normalizeDraw` 逐点夹边界，所以手改过的 `canvas.json` 依然打得开。
- **三条出口、一笔一笔擦的橡皮、和一块留下来的画板。** 11.2 行 8 的三个抱怨各自落成：工具条排在字段**上方**；橡皮先点亮它准备拿走的那一整笔（容差按屏幕 12px）；收笔之后字段留在正文下方变成只读图形，右下角「点一下接着画」。再点铅笔、Esc、离开这张卡，三条都把笔收起来；⌘⏎ 挂在画板自己的 window 监听上，所以笔接管页面之后草稿照样能存。
- **贴进来的图片是卡里的一行指针，不是卡里的字节。** 像素进宿主的内容寻址附件库（`ctx.get('attachments')`），卡里只留 `attachment://…`（markdown）或 `<img src="attachment://…">`（HTML）；两条渲染臂都只解析这一个 scheme，经 24 条 LRU 换成 **`data:` URL**（不是 blob object URL：没有 revoke 生命周期、不留游离对象，淘汰就是一次 map 删除）。
- **`perfect-freehand` 死锁在 1.2.3**，由 tsdown 打进 `lib/client.js`——宿主不用装东西，profile 不加行。这个锁法是一次实测的记录：它的 `StrokeOptions` **没有 `caps`** 这一项（是 `start:{cap}` / `end:{cap}`），而且**没有 `toSvgPath`**，所以 `draw.ts` 里那段多边形→路径的走法是手写的。挪动这个 pin 意味着重新量一遍，不是把范围往上抬。
- **11.4 那条改判是"被当作点头"，不是收到的裁决。** `card.draw` 取代 §10.8 的"矢量 JSON 落 `card.text`"当时还挂在 未裁决，旁边写着"没点头之前…阶段 ⑦ 不开工"，然后"OK，你开动吧"到了，整轮被读成批准。如果这个读法错了，回退就是一格提交：数据面只多一个可选字段，容忍式读意味着回滚不会在盘上留下任何东西。

## Alternatives considered

**板上就地编辑，详情页继续当阅读器。** 那是已上线的形状，输在令上：两个编辑面意味着粘贴、图片、绘画各做两遍，而且第二遍正是和渲染器打架的那一遍。由此退役，不是重写。
**点列塞进 `card.text`（§10.8 原案）。** 否掉的理由就是 §11.4 那三条，前两条如今长在代码里：一段点列混进正文，等于把坐标当散文交给模型；而 `detectCardFormat` 看的是整张卡正文，正文里长出一块 JSON 之后"这张卡是 md 还是 html"变成不可判。256KB 正文上限和板上 clamp 摘要也都是按正文算的量。
**存收尖轮廓（或位图）。** 按字节否（实测每笔贵 2.9 倍），按模型边界否：位图是"得另外给它"的东西，点列是模型本来就在读的那张卡上直接可读的东西。
**画笔用 Excalidraw / tldraw。** 更早一轮就按同一页的证据否了：tldraw 带非生产许可 + 遥测，Excalidraw 是 MIT 但 46.8MB，而这项能力全部需求只是一份笔画列表。`@xyflow/react` 当时留在阶段 ⑥（连线与泳道），因为相信那才是唯一值得上图库的东西——阶段 ⑥ 落地时是手绘的，这个前提也一起翻在打包契约上：见[连线视图](2026-09-23-canvas-link-view.md)。
**画板配脏标记 + 保存钮。** 否：那会在 ⌘⏎ 旁边立第二套保存模型，而"一笔不能自己存"和"一笔不能自己撤"是同一件事。逐笔提交直接沿用板已有的版本围栏，不再新增第二套。
**贴图用 blob object URL。** 否：`revokeObjectURL` 是一条能搞错的生命周期，也是游离对象的来源；`data:` URL 的淘汰就是一次 map 删除。
**这一波顺手把详情注册成自己的标签 kind（`canvasDetail`，阶段 ⑧）。** 故意不做：dock 布局按会话存在内存里，"把一张卡开成一格"是对工作区配置的承诺，本轮不作这个承诺。

## Consequences

- 画布只有一个编辑面，于是这三样新能力各占一个座位，而不是两个。
- `lib/client.js` 长成 421.55 kB（gzip 90.13 kB），`perfect-freehand` 在里头；部署侧不多装一个包。
- 绘画**目前只测到单元与 jsdom，还没被真光标划过**：验收那一次点击在 3080 上（那正是用户要看的效果）。已知视觉风险在字段的几何（aspect-ratio 加绝对定位的图形），不在笔画数学。
- 墨不进任何存储：一笔就是 `canvas.json` 里几百字节，擦掉它是一次重写，背后不留东西（本轮"不会被回收"的字节是**贴进来的图**——`ctx.fs` 没有删除接口，这条 limitation 两份 README 都写着）。
- 故意留在未裁状态：压感（`w` 现在来自屏幕速度）、给多模态参考用的位图导出、以及"已保存的卡改了字没关标签要不要也拦一次"（11.8 ⑥）。
- 旧板照常打开——`draw` 是带容忍读的可选字段，所以这一波向前向后都不需要迁移。

## Testing

`packages/canvas`（本轮：197 → **295 绿，18 文件**；`pnpm --filter @khorsheed/dsh-canvas build && test`）。

- `tests/draw.spec.ts`（新）：框坐标换算（含零尺寸矩形与带偏移矩形）、采样距离/时间双闸与点数上限、笔宽夹边与其"按屏幕像素算速度"的语义、橡皮命中/落空/空板、`appendStroke` 的上限、轮廓外溢保持在 `±MAX_DRAW_WIDTH` 内，以及"一个点是一个圆点"。
- `tests/board.spec.ts`：只有画的 `putCard`（空正文被接受）、经 `readBoard` 的往返、对手改越界 `canvas.json` 的逐点夹边，以及 `patchCard` 的替换 / 清空 / 别动三态——含"最后一笔也擦得掉：清空是个手势，不是陷阱"。
- `tests/prompt.spec.ts`：`<board>` 段的形状、一笔一行、它随普通卡出发、自己就是内容、与 HTML 卡的指针同时在场，以及摘要写成 `N-stroke drawing`。
- `tests/detail.client.spec.tsx`：一笔带首个点的精确坐标抵达 `patchCard`、下笔即可见且「撤一笔」一次一笔、橡皮一次拿走一整笔、落空只提示不写盘、Esc 收笔、单击不存笔，以及幽灵卡上没有铅笔。
- `tests/tab.client.spec.tsx`：⌘⏎ 存下只有画的草稿（`text: ''` 加画）、丢弃确认报的是「1 笔」而不是「个字」，以及板上为有画的卡渲染出图形。
