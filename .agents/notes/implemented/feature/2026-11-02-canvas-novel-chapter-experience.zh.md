# Agent Note: 章节引导遵循原稿顺序，总览使用独立摘要面板

Status: implemented

## Problem

章节页可能在更早章节还没有正文时，就展示更后章节的计划，并总是把下一章作为待办。看计划需要明确落到「哪一章的哪个计划」。动作按钮各自定制样式，唯一的新建入口不显眼；总览把一页纸、人物、关系、伏笔、世界观排成一长串相似行，区域边界不清。

## Decision

- 「接下来」依次处理：待对齐改动、待对账正文、待用户确认、最早未完成章节。只有现有章节全部对账后，才出现下一章候选。下一章的规划和候选屏蔽使用章节列表计算出的章号，不再读取时间轴里的缓存章号。
- 打开章节时同时携带章号与意图：看计划或编辑正文。当前章的「看计划」会精确打开该章并展开计划，不用最新章号替代。
- 卷进度只统计已对账章节，不把只有计划的登记章计成「已写」。
- 动作统一使用宿主 Button 的同一尺寸；只有第一个可执行步骤使用主按钮，其余用次按钮，取消用 ghost。按用户确认的布局，「导入」和「新建第 N 章」菜单放在筛选行：导入可选文档或文件夹，新建可选「自己写」「让 Agent 规划」。两个新建入口都取现有最大章号加一，不按阅读位置，也不补中间空缺。列表底部另保留一个轻量新建菜单，导入不再占用章节行。手写仍先在同名弹窗填标题再登记；Agent 只发送原有规划请求，不登记空章。即使候选没有进入「接下来」，底部仍可主动规划。
- 「总览」保留一页纸为全宽主文档。人物、世界观、关系、伏笔各有独立摘要面板，带标题、数量、边界、内边距和完整详情入口；关系与伏笔不再藏在人物区底部。宽面板两列，窄面板一列。写作原则仍是独立的后续区域。

## Alternatives considered

- **继续用 `currentChapter()` 决定下一步。** 否决：它用于继续阅读时找待审项或最后一章，不是找最早未完成任务，用它做「接下来」会打乱原稿顺序。
- **永远显示下一章候选。** 否决：规划后章是可选动作，不是前置任务。它留在新建区域，不再与未完成正文抢注意力。
- **只调整按钮颜色。** 否决：尺寸、圆角、字重和强调层级需要统一的宿主组件与规则，不是再补一套本地配色。
- **全部对账后才允许新建。** 否决：用户可能有意提前规划或写作。底部新建动作始终保留，只是不提升为「接下来」的任务。
- **每条记录各套一张卡，或在总览再放各类数据的完整列表。** 否决：更合适的是主文档加链接摘要面板，参考 Notion 数据库摘要与 Linear 项目总览。总览负责摘要和导航，不复制所有详情列表。

## Consequences

- 更早未完成章节重新获得优先级，后章计划可从顶部工具条或列表底部的轻量菜单主动进入。
- 总览分类边界更清晰，混合内容更少；窄面板会多占一些纵向空间，每个摘要面板只展示少量条目。
- 章节、规划、卡片、对账与导入的数据格式都不变，改动只涉及客户端呈现和导航意图。

## Validation

- 第 2 章待对账、第 5/6 章只有计划的场景，现在先显示第 5 章、隐藏第 7 章候选、按实际对账计数，并精确打开第 5 章计划。全部对账的场景则规划真实下一章。
- 测试覆盖主/次按钮、两种新建路径、两个新建入口及其自己写/规划菜单项、先填标题再编辑、下一章章号，以及关系与伏笔各自的摘要面板和跳转。
- 修改后小说完整测试通过 29 个文件、246 项测试。
