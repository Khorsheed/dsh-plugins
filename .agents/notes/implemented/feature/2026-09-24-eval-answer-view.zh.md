# Agent Note：一个作答视图、三个入口、盲评是一个开关

Status: implemented

## 问题

看选手到底交了什么，散在三个地方，各有各的样子（web-eval T75，ui-spec §五 作答视图）：

- 运行记录抽屉只能打开**一格的一个文件**（`cellArtifact`，T69）——不能并排，判定也不在文字旁边；
- 结果对比的表点得出「题 × 组」，却看不到一个数字背后的作答；
- 人工评估自己渲染每列的产物块（所有阶段文件全展开，json 和 markdown 一样当原文贴），读的是同一样东西，只是排版不同。

两组 × 两阶段并排再配上判定，要八次 `cellArtifact` 往返外加一次判定读；同一样东西三套排版，对齐就有三处可能走样。

## 决定

- **一个具名批量读**，`cellAnswers({runId, task})`（`src/answers.ts`）：这道题在 run 里按种子顺序的每个「组 × 次」，各带判过的阶段文件（`JUDGE_MATERIAL_FILES`，先读归档 `workspace`、再读 attempt 目录）、当前 attempt 的 script / llm-draft / human-final 判定（判官按判官台的面板标签，不给判官条件 id）、脚本输出、选手子会话与父会话 id，rubric 的人工判据给一次。只给文件名不给路径；只要文本；每个文件 256 KB 截断并说明。`cellNo` 数的是 run 的每一行（与判官台一致），盲评字母因此跟 run 的种子顺序走。这个读**具名**——它从具名的记录详情打开——除此之外什么都没放宽。
- **一个组件**，`AnswerView`（`src/client/AnswerView.tsx`），由一份纯模型喂（`src/client/answer-view.ts`）：每次一行，每组一列（种子顺序），阶段按文件 stem 在整行取并集对齐。两个视角：「提交的报告」（markdown 按段、json 折叠）与「判定证据」（按判据、按层，外加脚本输出）。「过程」复用 T69 的开子会话入口。
- **三个入口落到同一个模型**：运行记录抽屉的「看作答」→ 那一格（组 × 次，那一组描边）；配对表的题行与判据表的展开行 → 题 × 组、每一次；人工评估队列 → 那道题，盲评锁定。底下的实验室页面保持挂载（`display: none`），「返回」回到人离开的地方。
- **人工评估就是盲评锁定的这个视图**：`rowsOfQueue` 从 `judgeQueue` 的格子建出同样的行；判据表置顶、产物折叠，每列一块打分（原来的表单，改名 `ScoringBlock`），经 `humanFinal` 写入——它仍是唯一写入口。打分块在行内字母之上保留 run 级的「第 N 份」，因为补判提示和提交按钮按 cellNo 称呼作答。
- **判定只在 evidence 引用某段时挂到那段下面**：「」“”""''``‘’ 括起、去掉 markdown 标记与空白后 ≥ 6 字的一段，出现在某个 markdown 块里，就挂在那块下，每条至多一次。其余都在「判定证据」里读。
- **盲评字母每一次重新从 A 起**：跨次沿用会让人把第 1 次的 A 与第 2 次的 A 配上——正是盲要藏的配对。
- **盲评时入口描边也去掉**：入口点名了一组，描边的「作答 A」就等于说出了那一组是哪个字母（临时实例上正是这么露的）。

## Alternatives considered

**页面上调 N 次 `cellArtifact`。** 不加新动词，但最小的真实场景就要八次往返，判定另读，而且由页面决定哪些文件算「报告」——把服务端的事实（`JUDGE_MATERIAL_FILES`）在客户端再推一遍。
**让 `cellAnswers` 也盲、去掉 `judgeQueue` 的产物。** 两个读并成一个，但盲是载荷的属性（线上没有条件、没有 missionId），具名入口又需要名字；在一个动词上加盲旗标，等于页面承诺不显示它收到的东西。所以具名面的盲开关只是显示层，真正的盲面仍是 `judgeQueue`。
**按词重叠或判据措辞挂判定。** `dataseek.verdict/1` 没有位置，只有一句 evidence；任何更弱的关联都是页面在猜，猜的锚点看起来和真的一样。pilot-d 实测：llm-draft 多半引用 stage1.json 的字段，所以大多数判定挂不上——这才是诚实的答案。
**字母跨次连续。** 如上否决（跨次配对泄露）。

## Consequences

- 作答怎么读（排版、对齐、判定挂段），今后一改三个入口同时生效；判官台不再有自己的一套产物排版。
- `cellAnswers` 是继 `cellArtifact` 之后的第二个产物读，读的是固定清单（判过的阶段文件）而不是任意路径，没有新增路径面。
- 具名面的盲只在显示层：报告没有去指纹，要真正的盲读就用人工评估页。
- 按现有数据，大多数 llm-draft 判定挂不上段落，因为它们引用的是 json 字段；要改在数据面（见下），不靠换一个更聪明的匹配器。
- 这个视图只读一道题；跨题对比仍归结果对比表。

## Testing

- `tests/answer-view.spec.ts`：分段、引用抽取、判定挂段（挂上的情形，以及只引 json 挂不上的情形）、按次分行、每次各自编字母、描边、阶段占位、判据排序、盲队列的行。
- `tests/answers.spec.ts`：服务端读——归档优先、截断、判定分层、按 attempt 过滤、判官面板标签；线上既没有判官 id，也没有路径；没有 dataDir 时给说明；未知题目时拒绝。
- `tests/AnswerView.client.spec.tsx`：组名、描边、挂段判定、过程按钮；盲评开关；判定证据视角；打分锁定与顺序。原有的判官台客户端用例在新的台面上照样通过。
- 在临时实例上用 pilot-d 数据走了一遍：三个入口、盲评开关、打分、渲染都核对过，亮色、暗色、400 各截了图。

## 数据面（记下、未做）
