# Agent Note: 成稿是独立实体，可保存到工作区

Status: implemented

## Problem

画布收集的是素材：片段、问题、文档、手绘。用户最终想从中得到的是一篇文章。在此之前，这篇文章只是又一张 `document` 卡片：

- 它没有版本，agent 改写和用户编辑会悄悄互相覆盖；
- 它不说明用了哪些卡片、没用哪些；
- 它没有「写完了」的状态；
- 想把它带出部署，只能手工复制文字，图片还是 `attachment://` 指针，换个地方就什么都不是。

2026-09-27 评审时，用户选择了独立的成稿实体、写作在主会话里进行，而不是继续扩充文档卡片（记忆：画布改版决定）。

## Decision

**成稿是板面上的独立实体。** `CanvasBoard.manuscripts[]` 存元数据：

- id（`ms_…`）、标题、状态（`writing` 写作中 / `final` 定稿）、版本号；
- 来源：`used` 与 `unused` 两组卡片 id（重点在「未用」，即写作时舍弃了什么）；
- 谁创建、谁最后写；
- 由卡片转来时记 `fromCardId`；
- 保存到工作区后记 `exported`（工作区、路径、文件令牌、时间）。

**正文不放在 `canvas.json` 里**，每个版本一个 markdown 文件，放在 `manuscripts/<id>/` 下。写入时先建新版本的文件（`createIfAbsent`），再经普通的、带版本守卫的 `mutate` 提交元数据：

- 提交失败，就删掉新文件；
- 提交成功，就删掉被取代的旧文件。

所以成稿只会指向存在的文件，大段正文也不会拖累每一次板面读取。

**冲突靠 `baseVersion` 发现，从不自动合并。**

- 改写要带上它起步时的版本号。板面已经往前走了，写入就返回 `stale` 和 `currentVersion`。
- agent 工具（`canvas_write_manuscript`）会告诉模型先重读（`canvas_read_manuscript`），再在最新版上改。
- 页面保留用户的文字，并用横幅给出两条出路：载入最新（丢弃编辑、重读），或覆盖（在输掉的那个版本上重新保存）。
- agent 写入会把 `final` 的成稿重新打开成 `writing`。

**写作在主会话里进行。** agent 用 `canvas_write_manuscript` 直接写到板面上；侧边对话已经退役（3f7cd8b5）。页面上的「让 Agent 改」会把成稿 id 和当前版本号引用到主输入框，这样 agent 的改写带的是正确的 `baseVersion`。

**转为成稿是手动操作。** 「文档」分类仍然是素材。文档卡片的 ⋯ 菜单里有「转为成稿」，它用卡片文字建一篇成稿，这张卡片记为第一个已用来源。卡片已经转过的话，同一菜单项显示为「打开成稿」，打开 `fromCardId` 相同的最新一篇，不会再分叉出第二份。HTML 文档不能转（菜单项置灰）。

**「保存到工作区」写进已挂载的工作区。**

- 产物是 `<工作区>/<标题>.md`，图片写进旁边的 `<标题>.assets/`，指针改写成相对链接。文件名取图片摘要的开头，所以重复保存沿用同一批文件名，同一张图贴两次也只写一次。
- 围栏重新定根：模式仍由会话决定（`read-only` 拒绝），但可写边界是用户挂到这张画布上的那个工作区。请求里指定任何别的路径都返回 `denied`。
- 保存路径和文件令牌会被记住，下次保存写同一个文件。以下两种情况会停下，由页面询问用户：
  - 文件在外面被改过：返回 `changed`；
  - 首次保存会落到一个画布从未写过的已有文件上：返回 `exists`。

  用户点「覆盖」后带 `overwrite` 重发，写入仍然对刚观察到的文件做版本守卫。
- 先写图片，保证 markdown 不会链接到不存在的文件。写不出的图片保留原指针，计入 `missingImages`。
- ⋯ 里还有「复制 Markdown」，直接拿纯文本。

**宿主缺口：`ctx.fs` 只能写文本。** 图片字节走 node 的 `writeFile`，放在构造函数接缝（`WriteBytes`）后面，写之前先用 `ctx.fs.contains` 对工作区根做检查。宿主提供二进制写入后，退役这个接缝。

**卡片命名。** 文本以 `# 标题` 开头的文档卡片，原先在 tab 标题、面包屑和来源 chip 上都显示成「# 标题」。新增的 `cardNameOf`（card-format.ts）对文档优先取 markdown 标题，取不到再回落到 `cardTitleOf`。成稿阅读视图也会去掉和标题相同的开头标题，避免标题显示两遍。

**删除**和所有删除一样只归操作者：元数据先离开板面，再删正文目录。已经保存到工作区的文件归用户所有，保留不动。删卡片时，也会把它从每篇成稿的来源列表里移除。

## Alternatives considered

- **继续用带版本字段的文档卡片来写。** 否决：来源、状态、导出都属于成品，不属于素材；混在一起会让「文档」分类同时有两种含义。
- **正文存进 `canvas.json`。** 否决：正文最长 512k 字符，每次读板面都要带上所有成稿。
- **冲突时自动合并。** 否决：散文的三方合并出错的频率高到不如直接问；两条明确的出路更清楚。
- **所有「文档」卡片自动变成成稿。** 用户否决：文档也是参考素材。
- **导出允许指定任意路径。** 否决：挂载的工作区是操作者有意划定的边界，任意路径会绕过它。
- **导出的 markdown 里把图片内联成 data URI。** 否决：编辑器和 git diff 里都没法读，而且臃肿。

## Consequences

- 板面多了一个「成稿」视图（列表，按最新排序，显示已用/未用数量），成稿在条带里作为独立页面打开。
- 板面 schema 新增 `manuscripts`（旧板面归一化为 `[]`），每个画布目录下可能多出 `manuscripts/`。
- 成稿图片能否带出取决于附件存储：部署没挂附件存储时，保存只写 markdown，所有图片报缺失。
- 在 `ctx.fs` 支持字节之前，二进制写入是宿主侧对 node 的依赖。

- `tests/manuscripts.spec.ts` 跑在内存文件系统（`tests/fake-fs.ts`）上，覆盖：
  - 创建、改写、stale；
  - 旧版本文件清理、patch、删除；
  - 导出围栏（`denied`、`read-only`）；
  - `exists` / `changed` / `overwrite`；
  - 图片改写与缺失图片。
- `tests/manuscript.client.spec.tsx` 覆盖：阅读视图与来源清单、⌘⏎ 带 `baseVersion` 保存、冲突横幅的两条出路、导出询问、「让 Agent 改」、列表。
- 另有 tools、agent、remote、detail（「打开成稿」而不是再分叉一份）与 card-format（`cardNameOf`）的用例；共 489 个测试通过。
- 在临时实例上看图验证过：阅读视图、分栏编辑、保存到 v2/v3、⋯ 菜单、保存到工作区、覆盖确认框、列表视图。
