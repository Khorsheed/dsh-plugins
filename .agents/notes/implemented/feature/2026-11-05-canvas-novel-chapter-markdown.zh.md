# Agent Note: 章节 Markdown 通过原文偏移 token 渲染

Status: implemented

## Problem

章节阅读页把标题以外的内容都按字面段落显示，引用、加粗和分隔线因此以源码字符出现。直接换成普通 Markdown 渲染器又会丢失渲染文本与原始正文之间的映射，破坏划选批注和已有高亮；这些功能依赖原文偏移、引文及上下文定位。

## Decision

- `ChapterMarkdown` 实现明确的安全子集：标题、段落、引用块、加粗、斜体、行内代码、无序和有序列表、分隔线。原始 HTML 保持字面文本，不进入 DOM，也不新增渲染依赖。
- 每个可划选的行内 token 都携带原始 `start`、`end`。Markdown 标记不显示，但仍在源字符串中，因此跨格式选择仍能返回准确的原文和偏移。
- 批注区间先在原始正文中定位，再与各 token 求交。高亮可以跨 token，`data-idea-id` 跳转目标和划选映射都不变。
- `ChapterReader` 委托给该渲染器。空章节、首个标题省略、编辑、引用来源元数据和只读行为仍由阅读页负责。
- 宿主发布的 `MarkdownText` 无法提供这种映射，发布物中也没有解析器源码。因此实现只拥有所需子集，不引用不受支持的内部模块。

## Alternatives considered

- **直接使用宿主 MarkdownText。** 否决：其语义化 GFM 输出不暴露原文偏移，`chapterSelectionFromRange` 无法还原原始引文。
- **深引用宿主解析器。** 否决：npm 安装物不含解析器源码，这种做法只能在源码检出中工作，社区安装会失败。
- **渲染任意 HTML 或引入完整 Markdown 依赖。** 否决：章节批注需要的是源感知渲染，而不是更大、更不安全的通用管线。支持语法保持明确且有测试。

## Consequences

- 常见作者说明和分隔线可以正确显示，已有批注仍能跨引用、加粗、代码和段落边界工作。
- 该子集有意小于完整 GFM。链接和其他未支持结构保持字面文本，不获得会破坏偏移的局部行为。
- 测试覆盖渲染、HTML 文本回退、高亮和原文划选偏移。小说插件完整测试通过 37 个文件、284 条测试。
