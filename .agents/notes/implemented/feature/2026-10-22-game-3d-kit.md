# Agent Note: the game workbench's 3D kit

Status: implemented

## Problem

The game workbench made 2D canvas games only. The user wants to build a 3D game rooted in the 山海经 (Classic of Mountains and Seas): many creatures, elements and environments, drawn in an ink-painting style they chose after trying the interaction prototype (`proposals/prototypes/game-3d-qingqiu.html`). The model can only write code and data — there is no text-to-3D — so 3D has to be something a model can author reliably, and it has to fit the existing loop: the sandboxed play area, end-of-turn checks in headless Chrome, candidates, and the panel's pick.

## Decision

A second runtime kit, `3d-three` (`src/kits/three3d.ts`), on the seam from [game runtime kits](../architecture/2026-10-22-game-runtime-kits.md).

- **Runtime.** Every bundle of a 3D project carries `_dsh/three.module.js` (the pinned `three@0.170.0` dependency's minified module build, read from disk once) and `_dsh/dsh3d.js` (`packages/game/runtime/dsh3d.js`, plain ES module, shipped in `files`), plus `_dsh/imports.json` mapping the bare names `three` and `dsh3d`. Games import by bare name; nothing is copied into the project or its snapshots.
- **dsh3d** gives a game: `build(look)` (a `parts3d` recipe → a model with procedural motion), the `ink` / `qinglv` styles (toon material, inverted-hull ink outline, paper background and fog), and `createWorld()` (45° orthographic camera, `step(dt)` / `start()`, `terrain`, `place`, `add` for pickable entities, `follow`, `focus`), plus the workbench hooks `pick(x, y)`, `pause(on)` and `highlight(list)`.
- **Looks.** `src/look3d.ts` validates `parts3d` recipes (base `quadruped` / `bird` / `fish` / `serpent` / `humanoid`; parts `ear` / `horn` / `tail` / `wing` / `fin` / `eye` / `face`; counts such as `legs`, `heads` and `segments` are integers in their own ranges) and `gltf` looks (a project-relative path; the glTF loader is not shipped yet, so dsh3d shows a stand-in block, or builds the embedded `recipe` when there is one). `ElementView` gains `look3d` beside the pixel `look`, so the panel's pixel editor is untouched.
- **Creating.** `game_open` takes `runtime: 3d`; the gate then offers the 3D styles (`ART_STYLES_3D`) and pins `runtime: { kit: '3d-three', version: 1 }`. 2D creation writes exactly what it did before.
- **Bridge.** A game's `pick` may return a structured reference (`id`, `inst`, `name`, `state`, `point`, `region`); the `picked` message carries it as `ref`. New `pause` and `highlight` messages call the game's hooks when present. These are what the panel's one-step pick-to-chip and the candidate diff rings (M1c) build on.
- **Checks.** dsh3d's renderer keeps its drawing buffer, so the 2D blank-screen read-back works on the WebGL canvas unchanged; headless Chrome renders WebGL without extra flags on this host.

## Alternatives considered

**Babylon.js.** It ships physics, a GUI layer and an inspector, but it is several times heavier and less familiar to models than three.js; the workbench needs a renderer the model writes correctly, with the game-specific layer kept thin and our own.

**Vendoring three.js into the repository.** That freezes the file in git (about 700 KB) and hides its version. A pinned exact dependency keeps provenance in the lockfile and is installed with the plugin like any other dependency.

**Letting the model write raw three.js meshes.** That works, but every creature then becomes bespoke code the panel cannot read or edit, and the 山海经's 「其状如 X 而 Y」 maps naturally onto a body plus parts. A recipe is data: the panel can show sliders for it, the model can propose three variants, and the refine path can bake the same recipe in Blender.

**Shipping the glTF loader now.** Nothing produces glTF yet (that is the refine milestone), and a loader without a producer is untested surface. Until then a gltf look renders its embedded recipe or a stand-in, never an error.

## Consequences

- A 3D bundle is about 0.75 MB larger than a 2D one at play, check and export time; exported single-file HTML grows by the same amount.
- The sandbox loader rewrites import specifiers textually, so an import statement spelled inside a comment in a vendored module is rewritten too. `dsh3d.js` says so at the top; the first version tripped exactly this (a self-import "cycle").
- The look builder's fidelity is the ceiling of the fast path: the procedural shapes are deliberately simple and read well under the ink outline; finer models come from the refine path, not from growing `build`.

## Testing

`tests/look3d.spec.ts` pins recipe normalization (clamping, dropped parts, count ranges such as six legs), gltf path containment, kit-aware validation, and the gate (3D pins the kit and offers the 3D styles; 2D gets no `runtime` key). `tests/three3d.chrome.spec.ts` runs a real 3D game through `ChromeChecker` with the 3D kit: a nine-tailed fox built from its recipe on terrain is not blank, `pick` at the fox's projected position returns `jiuweihu` with its instance, state and region, the ground picks as ground, the scene stays inside the triangle budget, and `pause` / `highlight` work; a 3D world that never draws is flagged blank. Screenshots of all five body bases in both styles were reviewed by eye.
