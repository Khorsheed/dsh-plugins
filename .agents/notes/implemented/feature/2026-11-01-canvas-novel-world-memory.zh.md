# Agent Note: 长篇小说按世界记忆组织——设定、故事内时间轴、规划即检索

Status: implemented

## Problem

用户在一部真实作品（《潜梦者》，5 章、41 张卡）上用长篇小说画布，2026-11-01 提出：

- **设定是一堆连不起来的卡。** 41 张里 29 张是世界卡，20 张是「规则」。生物被归成规则，几张原则卡其实是世界规则，势力只存在于规则正文里。卡和卡之间互不指向。
- **规划页少用、也不好看。** 每卷的大纲是一整段长文，占着第一个页签。
- **确认计划像没反应。** 它只记下 `planConfirmedAt`，用户还得在对话里再说一声 Agent 才动笔。
- **「信息差 c2」看不懂。** `infoGaps[].who` 按原样存成 ref，页面不解析 ref。
- **写稿材料包装不下。** 所有世界卡都进「硬约束」：约 4900 字，预算约 2000。超了以后伏笔和前情被裁，草稿也被当成硬规则。
- **用户没法自己写。** 只能经 Agent 把写好的文件登记成用户原稿。

## Decision

把小说按记忆组织：

| 记忆 | 在书里 |
|---|---|
| 语义记忆 | 世界观：体系 / 地点 / 势力 / 物种与道具 |
| 情景记忆 | 时间轴 · 已发生 |
| 前瞻记忆 | 时间轴 · 将发生：预设 / 打算 / 后果 / 承诺 / 揭晓 |
| 自传体记忆 | 人物的处境、当前打算、相信的事（亲历 / 听说 / 推测）、怎么看别人、瞒着别人的 |
| 程序性记忆 | 写作原则 |

人物只存自己相信的事。「误以为」「不知道」从不存。

### 设定（体裁 `novel@5`）

- **四个架子。** 体系 / 地点 / 势力 / 物种与道具（角色 `system` / `place` / `faction` / `item`）取代「世界」。引擎把四类都当设定读：EntryRole `world` 加 `RuleView.sort`。「原则」改名「写作原则」。
- **连线。** 每个架子有 `parent`，势力有 `base`，人物有 `faction` / `home`。每条连线都是 `ref` 字段，`refKind` 写分类角色。画布拿 `refKind` 同时匹配分类 id 和分类角色。写卡时按编号或名字解析连线，解析不了的丢掉并在回复里说明。
- **反向链接。** `canvas_read` 的列表和详情显示所在架子、属于和反向链接。卡片页的「关联」区块来自 `card` Remote 的 `links`。
- **整理设定。** `novel_write(what=organize)` 的 `phase=preview` 存下 `organize.json` 并返回整理结果。`phase=apply` 要求用户之后又发过消息。执行时先触发画布的体裁补齐，再建新条目、按原字段搬卡、设上级，最后关掉已经搬空的旧「世界」分类。
- **材料包里的设定。** 计划有「用到的设定」（`uses`）。`gatherBrief({ for })` 全文带上：`uses`、前两章对账记下的设定、计划里点到名字的设定（规划时还扫最近几章摘要）。其余设定只列名字。未定的设定标「未定：别在正文里写死」。

### 时间轴（`timeline.ts`、`timeline.json`）

- **事件。** 每个事件有故事时间标签（`when`）、位置 `order`、状态（happened / preset / planned / hidden / failed）、来源、人物、地点、价值 V、时间窗口、前置条件、起因和推进记录。伏笔卡是派生的揭晓事件 `fs:<cardId>`。
- **张力。** `V × E × (1 + 0.25Z) ÷ (1 + k·D) × 饱和折减`，k = 0.4。分档按 饱和（S ≥ 3）→ 搁置（有前置没满足）→ 临近（D < 3）→ 积压（Z ≥ 3）→ 就绪 的顺序判断。
- **召回。** `recall` 先取优先推进的，从不取被屏蔽的，再取全部临近的，其余按张力补满，至多 8 件。除视角人物外，同一个人物至多占 2 件。优先推进 / 本章屏蔽只对设定时的那一章生效。
- **写入。** `novel_write(what=event)` 写事件，人物和地点按名字解析，`after` 决定它在故事时间里的位置。
- **对账。** 新增 `events`、`event_progress`（advanced / happened / failed）、`preconditions_met`、`beliefs`、`intents`，每一条都要有原文依据。相信的事和打算写进 `minds.jsonl`。事件发生后，绑在它上面的灵感标「已写入」。

### 规划即检索

- 规划材料包列出召回的候选，一件一行。`novel_read(what=events, ids)` 展开选中的事件：起因、人物的打算和认识、相关设定、绑定的灵感。
- 计划记下「本章推进」（`advances`）。写稿材料包展开这些事件，带上用户写的灵感原文，在场人物带上「现在打算」和「相信」。

### 界面

- 页签依次是 章节 · 设定 · 时间轴 · 灵感。画布新增了第三个体裁页签位 `faces.extra`，以及 `faces.board`：体裁用自己的页面占「卡板」的位置，只在该体裁的画布上替换卡片墙（连同它的筛选和网格 / 连线切换）。
- **设定**（`novel:codex`，数据来自 `codex` Remote）照定稿的交互稿做，分五块：总览（一页纸大纲和大纲提议、四个架子速览、待定、写作原则、整理设定按钮）、世界观（左树右详情，双向连线和出现章节）、人物（按势力分组，带此刻 / 打算 / 相信的事）、关系（可按章节拖动的关系图）、伏笔（「读者知道」推进梯，最上面是真相）。编辑卡片时打开画布的卡片页。
- **章节**按卷分组列目录，带进度条、卷目标和卷末落点；另有「下一章候选」（可设优先推进 / 本章屏蔽），以及「新建一章，自己写」（登记为用户原稿，直接打开编辑框）。
- **阅读页能直接改章节文件。** `editChapterBody` 走带权限检查的写入路径，保存前检查文件有没有被改过，草稿暂存在本机。已对账章节改动不到 5% 时保持已对账，记在 `editedAfterExtract`。编辑框里可以把选中的一段存为灵感，也可以让 Agent 接着写。「按计划开写」确认计划后，经输入框的 `submit` 发出「第 N 章计划确认，按计划开写。」；打到一半的草稿从不发出。
- **时间轴**左边按故事时间列已发生的事，右边按优先级列将发生的事，附公式和每件事的各项分量。「按章节」是原来的故事表。
- **灵感**只存不触发（`ideas.json`）。「排进时间轴」往对话发一条消息；「手动绑定」按灵感里提到的名字给候选事件。状态只有「待写入」「已写入第 N 章」，可删除。
- 人物卡显示「当前打算」和带来源的「相信的事」。

### 不在后台静默调模型

所有用到模型的步骤都在可见的对话轮次里，`context-lens` 都能看到。张力、分档、召回、理由行、灵感候选都是纯计算。

### 有意没做

- 节奏 k 固定为 0.4，还不是每部书一项设置。
- 人物卡上的「知道的事 / 不知道的事」字段保留，新的人物记忆写进「相信的事」。

## Alternatives considered

- **一个数字优先级。** 否决：解释不了。用户看到的是按主导分量命名的档位。
- **在人物上存「误以为 / 不知道」。** 否决：那是作者视角。
- **单设「未了之事」池。** 否决。打算、后果、揭晓、承诺都是将发生的事件。
- **历法。** 否决。顺序为主，时间只是标签。
- **存下灵感后让模型判断挂在哪。** 否决：那会是一次静默调用。
- **让 Agent 从全部将发生事件里挑。** 否决。召回做成工具，几百件事件不会进模型。

## Consequences

- **换来的。** 写稿材料包带的是这一章用得上的设定，不再是全部设定。规划从故事欠下的东西出发：打算、后果、承诺、揭晓。用户可以按事件掌舵，并和 Agent 一起写。
- **对账要抽的更多。** 原文依据仍是硬要求，但抽得浅会悄悄拉低规划质量。
- **迁移。** 自动迁移可能归错，整理结果是兜底。
- **展开可能漏设定。** 沿连线展开可能漏掉某章需要、但没有连线到达的设定；名字目录让它仍能被查到。
- **页签挪了位置。** 规划并进了设定 · 总览和章节，故事改成了时间轴，卡片墙从小说画布上撤下。
- **验收方式。** 界面用真实作品的数据、经真实组件渲染（本地预览页）截图，与交互稿逐页对照，不只靠测试。
