# Agent Note: mission — 通用任务管理，里程碑 M1

Status: implemented

[English](2026-08-19-mission-m1.md) | 中文

## Problem

dataseek-eval 计划（以及日常 agent 工作）需要一个通用任务管理器：成批的工作项、冻结并被强制的状态机、不可逆资源的确定性释放闸、保留失败记录的重跑，以及宿主进程、模型工具、宿主外脚本三面可达的同一份 store。这是 [mission 提案](../../../proposals/active/2026-08-19-mission-tasks.md)的里程碑 M1：store、带三种 guard 的声明式状态机、模板 lint、计划数据与五桶投影、`ctx.mission` 服务面、十二个模型工具、`dsh-mission` CLI。slash 命令与 bundle 导出属 M2；会话 tab 属 M4。

## Decision

交付为 `packages/mission`（`@khorsheed/dsh-mission`），纯 host 包，骨架照 ankh-guard。一个 run 一个 `runs/<runId>.json`；`runs/<runId>/data/<missionId>/attempt-<N>/…` 是追加式运行数据树。所有写都走 `MissionStore.update`（`src/store.ts`）：per-run 锁文件（手写 `wx` 创建，携带 `{pid, at}`，pid 已死或锁龄超 60 秒即回收——依赖树里没有 `proper-lockfile`，本里程碑也不加依赖），随后 读 → 改 → 临时写 → 原子改名。服务、工具、CLI 是同一个 `MissionService`（`src/service.ts`）的三个适配器，宿主内与宿主外写者在同一把锁上串行。

状态机是建 run 时冻结进 run 的数据（`src/template.ts`）：恰需一个初始态；终态 = 无出边、初始态 = 无入边，都只从 transitions 推导。`transition` 拒绝一切未声明转移（fail loud），执行声明的 guard，向 `history` 追加调用方（`tool:<sessionId>` / `cli` / `service`）。guard（`src/service.ts` 的 `runGuard`）：`file-check` 的 `dir` 相对该 attempt 运行数据目录解析，绝对路径与 `..` 一律拒绝（无插值）；`schema-check` 用手写 JSON Schema 子集校验器（`src/schema.ts`：type/required/properties/items/if/then/const/enum/additionalProperties——不用 ajv）校验已登记的 submission；`attested` 要求经 `attest` 登记的 key。`submit` 先用其 JSON payload 对所有离开当前状态的 schema-check guard 校验，违规则一字节不写，然后追加文件、登记 artifact、记录 submission、登记无 ref checkpoint；服务面的 `addCheckpoint` 以**合并**方式填 `ref` 进同名 checkpoint——同一时刻只有一条。

Lint（`lintTemplate`）复用已有语义：`releasableStates` 非空时，进入可释放状态的无 guard 转移是 error（拒绝建 run）；不经任何可释放状态即可到达的终态是 warning；schema-check 的 schema 必须存在、可解析、且在子集内。五桶投影（`src/projection.ts`）是纯函数：由形状 + 计划数据得 done / blocked / scheduled / ready / active；`dependsOn` 与 `scheduledAt` 永不点火。`retry` 在初始态新开 attempt，原 attempt 不可变。写操作幂等（相同的 transition/annotation/attestation/submission 字节/artifact/create 重复提交 = no-op），`retry` 是写明文档的例外。

内置 `simple` 模板（`queued → active → done | failed`，`releasableStates` **为空**）支撑零配置隐式 run（`session-<id>`，CLI 为 `default`）。服务面为进程内消费方（lab）增加 `setRefs` / `addArtifact` / `addCheckpoint` / `annotate` / `isReleasable`。十二个 `mission_*` 工具经 `defineTool` 注册，配 `tool:mission` 系统提示词段；export 刻意不在工具面。CLI 同语义，退出码 0/1/2（`is-releasable` 为 0/1，供销毁脚本使用）。`src/invariant.ts` 携带身份三角的 PACKAGE_NAME，对默认数据根下任何畸形 run 文件报错。

## Alternatives considered

- **YAML 模板 + YAML 依赖**——M1 否决：本里程碑不加依赖，模板文件用 JSON；文档模型相同，以后接纳 YAML 无需格式变更。
- **schema-check guard 用 ajv**——否决：同样的依赖约束；手写子集校验器同时兼任 lint 期的子集闸，schema 不会静默少于作者所写。
- **`simple` 模板 `releasableStates = 终态`**（提案的宽松措辞）——否决：lint 规则会要求每个 `active → done` 挂 guard，零配置隐式 run 将不可用；日常工作项不持有可销毁资源，故 `simple` 为空表。
- **仅 submit 期校验 schema**——否决：guard 声明在转移上，转移时会重校验已登记的 submission；submit 期校验只是更早的失败面（违规一字节不写），不是替代。
- **按时间戳去重 checkpoint**——否决：不同调用方时间戳必不同；合并键是 attempt 内同名，`ref` 冲突 fail loud。

## Consequences

- store、引擎、服务面、工具、CLI 由 48 个测试覆盖，含真实跨进程竞争（4 个 CLI 子进程 + 4 个进程内写同一 run 文件，零丢写）。
- `retry` 是唯一不幂等的写——每次调用真实新开 attempt；README 已注明。
- 锁对 pid 复用是尽力而为（最坏等 10 秒锁超时）；存储层可换 sqlite 而不动数据模型。
- M2/M4（slash、带泄题闸与 expectedNs 完整性报告的导出、会话 tab）已在提案中设计，刻意缺席；run status 的 expectedNs 报告随 M2 导出工作一起做。
- 上游 retry 后未到终态的下游 mission 重新投影为 blocked，但其记录原样保留——append-only 的 backfill 立场。

## Testing

`packages/mission/tests/`（48 个测试，fixture 全用运行时临时目录）：schema 子集校验器接受/拒绝；模板校验与 lint（无 guard 的可释放入口 → error 拒绝建 run；可绕过的终态 → warning）；全部未声明转移被拒、声明路径 + history + 幂等重复；guard 确定性（file-check 相对解析含绝对路径/`..` 拒绝、schema-check submit 先行 + 转移重校验、attested）；simple 与任意多终态形状下的五桶；dependsOn blocked→ready；scheduledAt；ods→dwd→dws→app 链与上游 retry 保下游记录；ns 隔离 + append-only + 带 attempt 号的 annotation；attempt/checkpoint 分离含 submit/addCheckpoint 合并；幂等写；歧义 id 消歧；cordis 挂载的服务面端到端；CLI 退出码（is-releasable 0/1、lint、用法）；run status 表输出；进程内与跨 CLI 子进程的锁串行；invariant 伴侣的畸形 run 报告。
