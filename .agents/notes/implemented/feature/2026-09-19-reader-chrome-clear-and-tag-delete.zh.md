# Agent Note: 灵感空间的控件退到后面 —— 可清空的搜索框、贴合面板的来源搜索、可删除的标签、一行压缩设置

Status: implemented

## Problem

读者一次反馈了灵感空间控件的四件事（带截图）：

1. **搜索框清不掉。** 只能全选再删，而这里比普通搜索框更难受：框里还装着筛选值（`#源id`、`@标签id`），你以为的"我打的那几个字"可能是你根本没打过的收窄条件。
2. **筛选弹层里的来源搜索框超出了面板右缘。** `.filterSearch` 在面板的列向 flex 里是 `flex: none`，而它的 input 是 `width: 100%`——百分比是对一个"由这个 input 自身固有宽度撑出来的父级"求值的。字段比它所在的面板还宽。
3. **标签只能建、不能删。** `deleteTag` 与 `pruneTags` 从标签词表上线起就在 Remote 上，**没有任何界面调用过**。打错一个字建出来的标签会永远留在词表、每条卡片的标签位和筛选弹层里。
4. **订阅管理页给两个设置各花了三行，筛选是八片散装胶囊。** 每日刷新时间与正文保留各占一个通宽描边块 + 一段说明，类型/排序两排没有标题——而这页真正的活儿是那张源列表。

## Decision

- **墙上的搜索框自己清空。** 有内容时框内右侧渲染一个 `×`，点它清 `query`——手输词和任何收窄（`#源id` / `#rss` / `#link` / `@标签id` 都只是 query）一次清掉。两个搜索框都在右内边距里预留这 24px，所以文字永远不会压到它下面，按钮出现/消失也不会让字段跳动。
- **来源搜索是 flex 尺寸问题，不是宽度取值问题。** `.filterSearch` 改成 `flex: 1 1 auto; min-width: 0`，input 加 `box-sizing: border-box`。一个"收缩到贴合子元素"的父级套着 100% 宽的子元素，靠一个魔法宽度值是修不好的。
- **标签在使用它的地方就能删。** 筛选弹层「按标签」每行右侧一个安静的 `×`（**常驻可见**——只在 hover 出现的控件对触屏等于不存在），调用已有的 `deleteTag`。两个后续动作属于决定本身、不是打磨：删掉的正是当前收窄时一并清掉收窄；并新增 store 动作 `dropTag`，同时清理词表、使用计数**和**每条条目的标签 id——客户端有三处持有标签 id，留着任何一处都会画出一个再也匹配不到的胶囊。
- **订阅管理页压缩成一行设置 + 两组带标题的筛选片。** 每日刷新时间与正文保留并排一行（各自的长说明收进 `title`）；胶囊加上内联的小标题（`按类型` / `排序`）并收紧尺寸。控件、id 与行为都不变。
- **正文保留的说明文案改成实际行为。** 它原来承诺"过期后再打开会问你"，而现在的行为是：打开一条缺正文/缓存过期的条目会直接抓一次。

## Alternatives considered

**用原生 `type="search"` 的清空按钮。** 不采纳：这个交互随浏览器引擎而变、无法样式化也无法依赖，而自己画的 `×` 是三行 CSS、行为到处一致。

**把清空按钮放在字段外面的工具栏里（筛选、排序旁边）。** 不采纳：窄侧栏里最稀缺的就是工具栏宽度，而且需求本身就是"框内"。

**给来源搜索一个固定像素宽。** 不采纳：它在别的面板宽度下会溢出、还要跟滚动条打架；缺陷是内在尺寸问题，flex 修法在所有宽度下都成立。

**删除标签加二次确认，或单独做一个标签管理页。** 暂不采纳：标签就是一个名字，重建它只是再打一遍；为一个可逆的命名动作弹一个对话框，比动作本身还重。代价记在下面。

**把两个设置收进「高级」折叠区。** 不采纳：每日刷新时间是读者会改的设置，折叠反而让常见路径深一层；压缩能让两个都留在视线里。

**保留两段内联说明。** 不采纳：它们只被读一次，却每次访问都占一行。`title` 让它们仍然可达，而且每个控件都还有可见的内联标签——没有任何控件的含义只能靠 tooltip 得知。

## Consequences

- **删除标签是立即且全局的，没有撤销。** 它会把标签从每一条带它的条目上移除。这就是那个 wire 动词本来有的语义，界面现在把它暴露出来了。想要回来就再打一遍名字。
- **`dropTag` 是必需的客户端状态卫生，不是装饰。** 没有它，词表、计数和逐条卡片的标签三者会互相矛盾，弹层还会渲染出一个匹配不到任何东西的筛选。
- **墙上的 `×` 连筛选值一起清。** 这是刻意的（它清的是"当前收窄"），而且那个值本来就显示在框里，不存在"悄悄清掉了什么"。
- **订阅管理页的说明变成了 hover-only**，而 `<label>` 上的 `title` 并不是读屏软件的描述。每个控件仍保留可见的内联标签，所以标签本身从不依赖 tooltip。
- **wire 未变**：`deleteTag` 本来就存在，这次只是把它接上，并新增一个客户端 store 动作。

## Testing

`packages/dsh-reader` 现在跑 201 个测试（`ReaderPane.client.spec.tsx` 新增 3 个）：

- `×` 只在框内有文字时出现，能清空输入，随后自己消失。
- 在弹层里删标签会以该 id 调用 `deleteTag`，并把正在生效的收窄（`@tag-id`）一并清掉。
- 压缩后的设置行仍然暴露两个控件（`#reader-refresh-time`、`#reader-cache-ttl`）。
