# Agent Note：对话引用署名与草稿删除

Status: implemented

## 问题

从助手回复里引用时，标签显示的是正文摘录而不是所在会话，输入框和预览里的来源都不够直观。预览的关闭按钮只会收起卡片：草稿里的 chip 虽然能按退格删除，但界面上没有明确的删除动作。

## 决定

- **来源标签回退为当前会话。** 优先级依次是内容声明的 `data-quote-source`、当前会话的 `displayTitle`、正文摘录。前两种在发给模型的引用块里写带来源的署名；摘录兜底仍用无来源署名。侧边对话 ref 使用同一个解析后的标签。文件、文章自己声明的名称和 `data-quote-ref` 位置仍然优先。
- **删除和关闭分开。** chip 预览的 ×、Esc、点击外部仍然只关闭。明确的「删除引用」动作携带 `openReference` 的会话 id 和 ref，只删除草稿里的这个 chip。已发送的引用卡片不变；纯文本回退路径照样直接编辑。
- **删除保留其余草稿。** 实现找到唯一匹配的 quote occurrence，把它的 clipboard 偏移换算成 detect 投影里的单字符 span，携带当前 `draftRev` 通过 `slash/input-insert-text` 写入空文本。CAS 拒绝后重读快照重试一次；只有成功才关闭预览并聚焦 composer。绝不整段重写草稿，也不摊平其他 chip。
- **重复目标拒绝删除。** 宿主的 `openReference` 载荷没有 occurrenceId。同一个 quote ref 出现多次时，动作返回 false，预览和草稿都保持不变；仍可退格手动删除。

## 考虑过的其他方案

- **所有引用都写当前会话。** 否决：文件或文章自己的标题更具体，必须保持优先。
- **让 × 删除 chip。** 否决：用户会认为预览上的 × 只是关闭；删除需要独立、可见的动作。
- **通过 `setDraft` 删除引用。** 否决：公开的纯文本整写会把 composer 里其他引用 chip 全部摊平。
- **删除第一个重复匹配。** 否决：相同 ref 可能位于草稿的不同位置，宿主手势无法说明点的是哪一个。

## 影响

- 当前会话标题存在时，本次决定取代[引用 locator 决策](./2026-10-24-quote-locator.zh.md)里“无来源引用不写署名”的部分；显式来源和 locator 规则保持不变。
- 在宿主激活载荷携带 occurrence 身份之前，重复 ref 不能用预览删除；普通的唯一 ref 路径不需要上游改动，也不提高最低宿主版本。
