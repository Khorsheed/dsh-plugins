# Agent Note: lab — checkpoint / verify / archive 动词（M2 前半）

Status: implemented

[English](2026-08-20-lab-m2-verbs.md) | 中文

## Problem

M1 交付了 acquire / populate / collect / release / status。实验生命周期还缺 [lab 提案](../../../proposals/active/2026-08-19-lab-experiment-units.md)的三个动词：可回溯的推进点（`checkpoint`）、执行并记录的一步（`verify`）、带完整性校验的导出（`archive`）——它们正是 release gate 的 `file-check` guard 所消费的东西。M2 的 CLI 半另行跟进。

## Decision

三个动词都落在既有的 `LabService` / `DockerProvider` 分工上，红线保持为机制：

**`checkpoint(unitId, {name})`**——工作区（单元的 `workdir`，默认 `/workspace`，现为 `UnitInfo` 一等字段并骑在 `dsh-lab.workdir` 容器标签上，reconcile 不丢）被提交并以检查点名打 tag；commit sha 即 `ref`，经 `MissionFace.addCheckpoint` 登记（提案的「`ref` 只由资源持有方填」）。还不是 git 仓库的工作区在首次 checkpoint 时自动 init；只读挂载的工作区在 `git init` 处报错——它无法被提交，这正是正确的信号。提交用逐次 `-c user.name/user.email` 身份，绝不改全局 git 配置。

**`verify(unitId, {command, source?, timeoutMs?})`**——可选验证物先拷入容器内临时目录 `/run/dsh-lab/verify`（先清空，`finally` 里移除——失败的运行也不会留下挂载物），命令经同一 pidfile wrapper 在工作区执行（超时的客户端会留下可清扫的容器内 pid），结果**原样**返回：`{exitCode, stdout, stderr, durationMs, timedOut}`。非零退出是数据不是异常——代码路径上没有任何通过/失败分支；mission 在场时同一 payload 注解进固定的 `lab` 命名空间（mission 侧约定：程序化写入方占固定 ns）。`timedOut` 是记录的事实，不是裁决。`Exec` 运行器新增可选 `timeoutMs`（`ctx.subprocess` 适配器把它映射为 `AbortController`，走 spawn 的终止阶梯）。

**`archive(unitId, {target, kind?})`**——工作区收集进 `<target>/workspace`，然后写 `manifest.json`：单元事实（id、provider、resource、指纹、工作区、mission 绑定）、`archivedAt`、逐文件一条有序记录（`sha256` + `bytes`；符号链接记目标）。以 kind `archive` 登记为 mission 产物——run 模板的 `file-check` guard（如 `archive/` 期待 `workspace/` + `manifest.json`）正是据此放行 `releasable`。

三个动词的登记都保持 M1 纪律：mission 缺席或写入失败 → warn 跳过；资源动词本身永不因记账而阻塞。

## Alternatives considered

- **checkpoint 用 `docker commit`**——否决：它把整层容器文件系统快照成新镜像层（重，且把环境与内容混在一起）；工作区上的 git tag 才是提案的语义，回溯点保持内容域、可检视。
- **验证物走临时绑定挂载**——否决：docker 无法给已创建容器追加挂载（M1 的 populate 因此拆成 acquire 挂载 + 拷贝的同一约束）；临时目录拷贝 + `finally` 移除给出相同的「仅验证期间可见」窗口。
- **verify 非零退出即抛异常**——绝对否决：那会往这条红线为「只记录不判断」的动词里偷渡判断；调用方自己读 `exitCode`。
- **archive 用 `docker export`**——否决：整 rootfs tar 复制了指纹已钉死的镜像内容；工作区 + sha256 manifest 才是 gate 真正守护的增量。

## Consequences

- 共 42 个测试（新增 16 个）：checkpoint 的 init 跳过/报错路径与 tag→sha ref，verify 的三种验收形态（失败/超时/静默成功）原样记录且无裁决，失败后的验证物清理，超时传递，archive manifest 对照已知 sha256 值校验，三动词的 mission 缺席 warn 路径。
- `checkpoint` 要求镜像内有 `git`（已写文档）；只带 `sleep`/`sh` 的镜像失去它。
- 输出巨大的 verify 结果整体进入 annotation payload——原样是红线；需要截断的消费方在自己一侧做。
- CLI（M2 后半）与 `lab_*` 工具（M3）待定；CLI 将复用 `LabService` 配 `child_process` 版 `Exec`，release gate 走 `dsh-mission is-releasable` 的 0/1 退出码（mission CLI  sanctioned 的脚本路径）。

## Testing

`packages/lab/tests/`——`docker.spec.ts` 新增 checkpoint（init 序列、已是仓库时跳过、只读失败）与 verify（工作区 cwd + pidfile wrapper、非零结果原样返回、验证物进出顺序含失败后清理、超时传递）。`service.spec.ts` 新增 checkpoint 登记 + 自定义 workdir + warn/缺席路径、verify 三种原样形态 + mission 缺席告警 + 空命令拒绝、archive manifest 内容对照已知 sha256 摘要校验。
