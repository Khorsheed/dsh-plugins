# Agent Note：图书馆——一站就是一课；自编教材的讲义要讲透每个考点

Status: implemented

## 问题

3080 实测（2026-10-25，「添加Blender 3D游戏制作项目」）：教练自编了一本教材，整条路线只排了一站，覆盖第 1–5 章。那一站的讲义写成了术语表——一串名词，开头一段「第 1 次更新 · 方向修正说明」，还夹着内部词 acceptance。用户想要多邻国式的节奏：站切小、由浅入深，讲义细到能学会每个考点，觉得掌握了再去章节考。

## 决定

与用户讨论定论：

- **站的大小按考点数，不按章节数。** 模型自编的书章节是它自己划的，「跨几章」没有意义。章节考站有 3–5 个考点（`service/rules.ts` 的 `STATION_MIN_POINTS` / `STATION_MAX_POINTS`）：超过 5 个拒收并要求拆开，少于 3 个拒收并要求合并。真实书的长章可以拆成同一段内容上的几站。
- **自编教材一章一站。** 它的章节就是教练写的课，所以一站覆盖自编教材超过一行目录就拒收。
- **自编教材的讲义就是课本身。** `lessonProblems` 检查：缺少以考点标题开头的 `##` 小节，或某节不到 `LESSON_SECTION_MIN`（120）字，就拒收并点名缺了或太薄的考点。每节写：是什么 → 为什么重要 → 例子或步骤 → 常见误区 → 一道自测题。真实书的讲义是导读加批注，不做这项检查。
- **任何讲义都不能有更新记录或内部词。** 出现「第 N 次更新」「修正说明」「更新说明」或 acceptance 就拒收；侧栏本来就显示第几次更新。
- **对话里的节奏。** 提示词写明：一次讲一个考点，问一个检查问题，懂了再往下。自编教材在开站时就写讲义，照着讲。
- **本轮不做：** 侧栏每节的「再讲讲这节」按钮。用户先体验，再一起打磨。

## 考虑过的方案

- **一站跨两章以上就拒收。** 这只能约束真实的书；自编的书，模型想把一章写多大都行。

## 后果

- 已有路线不会重新校验。用户会删掉 Blender 项目，新建项目来试新规则。
- `addPoints`（出题时给一站追加考点）没有上限，一站可能借此超过 5 个考点。

## 测试

183/183 全绿。service.spec 新增：6 个考点被拒、1 个考点被拒、自编教材上跨两行目录的站被拒；术语表式的讲义会列出缺的考点、只有一句话的小节被判「太薄」、带更新记录的开头被拒，以及带编号标题和 `###` 子标题的完整课文能写入。旧测试补到 3 个考点。
