# Agent Note: canvas-novel 首次试用修复——重复卡、世界卡起名、正文分段

Status: implemented

## 问题

用户在临时实例上把写好的几章交给模型整理，碰到三个问题：

- **人物卡和世界卡重复**：import 只认已采纳的人物，同一份结果里新登场人物的经历全被丢掉；报告里也不给新幽灵卡的编号。模型于是又用 `novel_write(card)` 把人物重建了一遍，世界卡也写了重复的。
- **世界卡没有标题**：一张世界卡只有一段 `rule`，看板上分不清哪张是地点、哪张是道具、哪张是规则。
- **正文没有分段**：模型写正文时一段只换一行，Markdown 渲染出来就是一整堵墙。

## 决定

- **一个名字只有一张卡**：
  - `writeCard` 新建人物卡或世界卡时，如果有未归档的同名卡（幽灵卡也算），就回 `duplicate` 并带上那张卡的编号；工具文案让模型改那张卡。
  - import 同理：同名的世界设定丢弃，记 `duplicate`；同一份结果里重复的也一样。已在画布上的人物不算新人物，它的经历照样按名字挂上去。
- **同一份结果里的新人物照样收经历**：import 先落卡，再处理 `experiences` / `current_states`；新人物的卡 id 按名字找到。
- **报告带编号**：`newCards`（当时叫 `proposedCards`）每项带 `ref`，模型按编号补内容。
- **世界卡改成「名称 + 类型 + 设定」**：
  - `name` 必填，用作卡片标题；`kind` 是选项（地点 / 势力 / 道具 / 规则 / 历史 / 其他）；`rule` 是具体内容。体裁升到 `novel@2`。
  - 抽取 schema 加了 `name` / `world_kind`；没给名字时取正文的第一个分句（最多 16 字）。
  - brief 里写成 `名称（类型）：设定`。
- **已有画布跟上新体裁（canvas）**：`mutate` 写入前，如果 `board.genre.version` 落后于注册的体裁，就把种子定义里缺的字段补进分类定义。用户改过的字段（标签等）保留，用户加的字段排在后面，定义 version +1。只在画布下一次写入时发生，不另起迁移。
- **正文分段**：`writeChapter` 收到没有空行的多行正文，就把每一行当一段，补成空行分段；已有空行的正文原样不动。

## 考虑过的其他方案

- **按定义 version 比较种子和已存定义。** 分类定义每采纳一次 version 就 +1，跟种子的 version 没法比；所以改成比较画布上记的体裁版本。
- **重名时合并进旧卡。** 合并会悄悄改用户已采纳的卡；拒绝并给出编号，让模型显式去改，更可控。

## 后果

- 旧的世界卡没有名字，标题回落到卡名或 id，要用户或模型补上。
- 已经生成的重复卡不会自动清理，由用户 ✗。
- 早先已写好的、没分段的正文不会被改写。
