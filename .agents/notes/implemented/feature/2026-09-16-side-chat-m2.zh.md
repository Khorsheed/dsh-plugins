# Agent Note: 侧边对话 M2——引用内联展开、浮动 dock、选区引用探针与多上下文切换

Status: implemented

[English](2026-09-16-side-chat-m2.md) | 中文

## Problem

M1 交付了会话场景核心（[side-chat M1](2026-09-16-side-chat-m1.md)）：右栏 tab、每个 contextKey 一个持久 agent 会话、不透明引用。[提案的 M2 行](../../../proposals/active/2026-09-16-side-chat.md)是客户端体验增量：ref chip **内联展开全文**（引用内容随对话走）、**浮动 dock 模式**（在自定义 main 面板——如画布空间——上边看内容边聊天，详情 tab 不让位）、**选区引用探针**（"任意文本选区 → ref"有没有官方 seam？）、以及**多上下文切换列表与未读标**。两条已发布契约约束以下一切：`ctx.sideChat.openWith` 的签名与 tab 的 `openTab('sidechat', { params: { contextKey } })` 导航参数——canvas M2 消费方已在用，M2 只做增量。

两个问题必须先有答案，而答案正是本 note 要记录的：

**chip 展示的引用如何活过重启？** 待发送引用存在 contexts 文档里，但折叠进已发送消息后就不在其中了——transcript 里的 chip 从哪来？

**选区引用有没有官方 seam？** 提案要求探针，并明令禁止 DOM anchor hack。

## Decision

**transcript 的引用从持久消息文本里解析回来——折叠格式往返闭环。** M1 的折叠格式（用户消息开头一串 `<quoted_context label="L">\n…\n</quoted_context>` 块，label 经 JSON 转义）是我们自己的，所以 `unfoldQuotedContext` 可逆：journal 投影把开头的块串还原为结构化 `{ label, text }` 引用，剩下用户正文。用户 transcript 行携带 `refs`（线上增量），transcript 在气泡上方渲染 chip，重启不改变任何事——journal 就是存储。不以块开头的消息原样通过（正文中间出现杂散标记的异己文本绝不被解析）；引用正文包含字面闭合标签会破坏该块的解析、按文本保留——已接受并写在 helper 文档里。同一个 `RefChips` 组件服务待发送引用行与 transcript 行：点击就地展开（label + 全文，可收起）——绝不用绝对定位浮层，因为面板根裁剪溢出。

**浮动 dock 是共用面板注册在 `shell.overlay` 上（root 作用域 list 座位，worktrees badge 先例）。** M1 视图的会话核心抽成了 `SideChatPanel`（选择器、transcript、引用、composer、拉取/轮询），两个薄包装各就各位：tab（`SideChatView`，session 作用域，导航参数）与 dock（`SideChatDock`，root 作用域）。dock 的槽 store 是带 `persist` 键的框架 `defineStore`——开关状态、所服务上下文、框架位置全部经框架自己的持久化活过刷新，不写一行手搓 localStorage。tab 与 root 作用域的 dock 经 apply 闭包控制器相会（worktrees panel-service 模式）：tab 的 `openDock` 在 overlay 条目的 inject 挂好 actions 后可达；dock 的关闭经 `ctx.sidebarRight.openTab` 把上下文交还 tab（是交接，不是解散）。发送搭**当前选中会话**（`useSessions(s => s.current)`，画布空间的围栏模式）；无选中时 composer 只读。降级：无 `shell.overlay` 座位→注册静默空转（slots.inject），tab 的「弹出为浮层」按钮隐藏（在 tab body 挂载时经 `ctx.slots.spec` 惰性探测，晚于 shell 的 apply）；窄视口→入口隐藏，已开的框架自我钳制到视口内。

**选区引用探针：没有官方 seam——登记 upstream 候选，不做 DOM anchor。** 核查记录：(a) `conversation.*` / `conversation.chat.*` SlotMap 目录（ui-conversation + ui-chat）没有选区/摘录/引用座位——M1 用的 assistant-actions 列表是整消息级的，不按文本片段寻址；(b) ui-conversation 里所有 "selection" 都是 composer 输入机件（Lexical 光标区间、`EditSelection`、`caretSpan()`），与 transcript 文本无关；(c) message-tools——最可能建过此事的消息面插件——没有选区功能（它的文本搬运是 composer 草稿回填，走输入机）；(d) 对 transcript 上 `window.getSelection` 就是设计红线禁止的 DOM anchor hack。结论：没有可诚实骑乘的缝。composer 照常接受粘贴纯文本（既定兜底，不变）。

**多上下文切换与未读标，两侧都诚实计算。** `listContexts` 行新增 `lastAssistantAt` / `lastActivityAt`（线上增量）：宿主投影每个上下文的 journal——live 读会话快照，cold 走持久化检视，绝不唤醒——"它回复了吗"是投影事实，不是猜。客户端把每个上下文的 last-seen 标记存 localStorage（worktrees local-root 手法，配版本号供整图重算）；查看一个上下文即把它的最新 assistant 行时间记为已读，选择器里 `lastAssistantAt` 新于标记的行显示未读点。当前上下文没有记录时（从未发问的会话）由选择器合成补入；列表按最后活跃排序。

## Alternatives considered

### 为什么不把已发送的引用存进记录，而是解析回来？

那是 journal 已有内容的第二份拷贝——第一个重启边界就会漂移（M1 note 已为整个 transcript 了断此事）。折叠格式是我们自己的，逆解析对我们写的一切都精确；不是我们写的就原样保留。解析胜过镜像。

### 为什么不做 `ctx.sideChatPanel` 式的跨插件面，或为 dock 开第二个 tab 实例？

dock 不是别人驱动的另一块表面——它是同一个面板换了个框架，所以共用组件 + 包内私有控制器是最小的诚实 seam。root 作用域槽 store 也是唯一合适的状态：tab 是 session 作用域会卸载，而 dock 的开关/位置必须活得比它久（持久化 store），两者只经 apply 闭包相会（panel-service 模式），绝不发布成服务。

### 为什么不把未读算在宿主（每个记录一个 `lastReadAt`）？

"已读"是客户端 UI 状态——用户看过哪些上下文，按浏览器、按 profile 各不相同。存到宿主会把展示层混入持久记录，还会错误地跨浏览器共享，并且每次查看都逼一次状态写入。宿主负责投影事实（`lastAssistantAt`）；标记归客户端。

### 为什么不用特性开关把选区引用先做出来再说？

唯一可用的实现是对 ui-conversation 的 DOM 做 `window.getSelection`——DOM anchor，仓库惯例里排在最后的手段，也是任务明令禁止的。带开关的 DOM hack 仍是 DOM hack，还会上线一个上游日后必须维护或打碎的交互。upstream 候选（在 `conversation.chat.assistant-actions` 旁边设选区/摘录座位，或扩展 owner props 携带片段）已记录在案。

## Consequences

- 宿主（`types.ts`、`journal.ts`、`service.ts`）：用户 transcript 行携带 `refs`；`listContexts` 行携带 `lastAssistantAt` / `lastActivityAt` 并按最后活跃排序；`unfoldQuotedContext` 加入共享词表。全部为线上增量——已发布的 `openWith` 签名与 tab 导航参数原样未动。
- 客户端：`SideChatPanel.tsx`（抽出的共用面板）、`SideChatView.tsx`（tab 包装）、`SideChatDock.tsx` + `dock-store.ts`（overlay 条目及其持久化 store）、`RefChips.tsx`（内联展开）、`seen.ts`（last-seen store）；`SideChatView.module.css` 更名 `SideChatPanel.module.css`（另加 `SideChatDock.module.css`）；两部词典新增 M2 键；`contract.ts` 的 tab 面新增 `dockAvailable`/`openDock`，另增 `SideChatDockInjected`/`SideChatDockProps` 一对。
- `package.json` 0.1.0 → 0.2.0；新可选 peerDep `@deepseek-ai/dsh-client-ui-layout`（overlay 座位的 SlotMap merge）与 devDep `@deepseek-ai/dsh-client-store`（dock store 的框架）；`dsh.compat.notes` 与双语 README 同步更新。无新增运行时依赖。
- 一条其他包可引用的排错教训：**加了依赖要删掉包的 `lib/tsconfig.*.tsbuildinfo`**——tsc 增量缓存记住了 `pnpm install` 链接前的 module-not-found，而 `--traceResolution` 之所以"能过"，只是因为它绕过了那张 stale 图。
- 一条值得复述的 React 正确性修正：面板的 `rows` memo 原本在 `fatal` 提前返回之后——hook 数违规，恰好在 host-missing 路径翻转时炸掉（client spec 逮住，已移到返回之前）。
