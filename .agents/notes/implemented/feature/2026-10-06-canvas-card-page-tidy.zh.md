# Agent Note：卡片页与故事日志详情整理——空字段收成标签、来源进元信息行、人物的「在故事里」

Status: implemented

接续 [故事日志](2026-10-06-canvas-novel-story-log.zh.md)。用户在 3195 试用作品上指出两个界面：人物卡页（戴娜）和故事日志窄宽度下的人物详情。实施前先做了前后对照原型，用户认可后动手。

## Problem

卡片页：

- 九个没填的字段显示成九行「—」。
- 名字出现两次：一次是页面标题，一次是第一个字段。
- 「先写正文…」空正文提示出现在本来就不需要正文的类型卡上。
- 来源章节单独占一个附件框，放在正文下面。
- 小说区块的「此刻」显示三行「未定」。它的值没设字号，按页面的 16px 显示，比字段表的 13px 还大。

故事日志窄宽度详情：

- 面包屑是「故事日志 / 人物 / c2」，眉标又重复一遍「人物 · c2」；`c2` 是内部编号，对写作者没有意义。
- 每一步出场都以同一个词「出场」开头。
- 「计划」单独占一行，空心记号按整块居中，没有对齐第一行。

## Decision

**画布外壳（`@khorsheed/dsh-canvas`，对所有体裁的所有类型卡生效）**

- **`FieldList`**
  - 只列已填字段。
  - 没填的收成一行「还没写」加虚线标签。点标签就打开字段表单，并定位到那一格（`FieldForm` 的 `focus`）。
  - 传了 `titled` 时（详情页只要面包屑已经点名就会传），省掉已填的标题字段。
- **详情阅读面**
  - 有类型、正文为空、也没有手绘的卡，不再显示正文区和提示。
  - 来源移到元信息行，写作「出自 {name} ↗」（链接、打开文件或纯文本）。附件框及其 CSS 和文案键（`detail.attachment`、`detail.openFile`）已删除。
- **体裁页面块**（`CanvasTab`）：去掉重复的标题，面包屑已经写了页名。

**小说（`@khorsheed/dsh-canvas-novel`）**

- **`card` Remote** 为人物返回 `appearances`。它复用 `storyLog` 的读取，不另写一份出场名单、视角、经历日志、来源章节的逻辑，所以卡片页的出场和故事日志天然一致。
- **卡片区块：人物合成一块「在故事里」**
  - **此刻**：还没整理时只写一句话；整理过的只列有值的部分。
  - **出场**：一行章号，用故事日志同一套实心/空心点；计划中的章带「计划 · 戏份」。
  - **关系**：列出关系，或一句「还没有关系卡」。
  - **「在故事日志中看 ›」**：打开故事日志并定位到这张卡（`openPage(STORY_LOG_PAGE, …, card.id)`）。
  - 区块里的值统一用字段表的 13px。`card.state.unset` 和 `card.relationsHelp` 已删除。
- **故事日志**
  - **深链**：`param` 为卡片 id 时，打开这一行所在的分类、选中这一行；窄宽度下直接显示详情。
  - **窄详情**：面包屑只剩一个「‹ 分类」，眉标隐藏。眉标只在伏笔上带编号，因为 `#12` 在伏笔上是真正会被引用的名字。
  - **人物轨迹不带动词**：每一步直接写这一章的经历或计划里的戏份，都没有时轻声写「在场，这一章没整理出经历」。
  - **「计划」**在所有分类上都改成第一行前的内联小标签，记号对齐第一行（行高 20px）；`.logPlanned` 已删除。
  - **宽度**：窄详情最宽 640px。
  - **链接**：人物详情加上「读第 N 章」，指向第一个已写的出场章。

## Alternatives considered

- **空字段整个隐藏。** 不采纳：没填的字段本身就提示下一步写什么，点标签直接进表单，比点「编辑字段」再找那一格更短。
- **在 `card()` 里另算出场。** 不采纳：第二份逻辑迟早会和故事日志对不上。

## Consequences

- **与画布负责人 P3（响应式布局）重叠。** 这里的外壳改动只动内容（字段表、正文、元信息行显示什么），不动布局、断点和详情框架。后合入的一方 rebase 到前者之上，冲突面在 `CanvasDetailView.tsx` 和 `fields.tsx`。
- **人物的 `card` Remote 变重了。** 它现在要读一次完整的故事日志。卡片页一次只开一张，可以接受；如果以后列表视图逐行调用，再回头处理。
- **测试**：
  - 画布 `fields.client.spec` 加了三条（标签与 `onFill`、全部没填、表单定位），`detail.client.spec` 跟着来源的移动改了。
  - canvas-novel `client.spec` 加了三条（「在故事里」区块、部分此刻、深链加「读第 N 章」）。
- **验证**：在 3195 上，浅色和深色、1440px 和 760px 下看过：戴娜的卡片页、点标签进表单的定位、此刻编辑表单、一张伏笔卡、故事日志宽窄两种详情。
