# Agent Note: Flat always-on timeline list without the dot rail

Status: implemented

[English](2026-08-15-message-timeline-flat-list.md) | 中文

## Problem

[全高面板笔记](2026-08-15-message-timeline-full-height-panel.md)落地的全高面板仍有三处不符合预期:悬停时圆点轨道的横杠与面板的竖刻度同时出现——两套互相竞争的标记;面板保留了卡片外壳(边框、背景、阴影、可见滚动条),看起来仍是一个需要自己滚动的列表框;内容不足一屏时面板顶部锚定而不是垂直居中。

## Decision

圆点轨道移除,时间轴只剩一条扁平列表,当时由 header 按钮开关,随后改为常开——按钮由[去开关跟随笔记](2026-08-16-message-timeline-toggleless-follow.md)移除。静止时只显示压淡的行刻度(deepseek-400,opacity 0.55)作为环境标记——行文字不可见,页面不显杂乱——且只有每行前 20px 的刻度条响应指针(面板本身不接收指针事件),划过去点会话侧边栏不会触发亮起;文字淡入带 90ms 延迟,吸收最短暂的掠过。当前阅读位置的刻度保持蓝色(行 opacity 0.75),tracker 应答前默认选中最新一条;悬停刻度条或键盘聚焦面板时行展宽并显示所有行的文字,蓝色行仍然最亮,悬停或方向键移动的行保持加粗预选。面板无外壳——无边框、无背景、无阴影、无可见滚动条——通过行前后的 auto-margin 撑块垂直居中(内容超出时撑块坍缩,长列表顶部锚定并隐形滚动);居中框顶部扣除会话 tab 条的高度,因为居中是对整个窗口读的。分页机制完整保留并支持自举:在会话视图上,面板持续翻页直到第一条用户消息物化(超长助手回合可能把所有用户消息顶出已加载事件窗口,导致零行且无从开始翻页),上限 initialPages 页,外加滚动到顶的 `loadOlder` 触发。配置随轨道删除 `dotPitch`;`TimelineDot`(其 `time` 只用于圆点提示)改名 `TimelineItem`(`{ key, node }`);`rail.dotAria` 与 `formatTime` 随圆点移除。高亮推导链形态不变(`focusKey`,其次 tracker 的 `activeKey`,兜底最新一条)——"选中"仍是阅读位置,跳转即设定;tracker 的 `activeKey` 在可视区没有用户消息行时锚定到视口上方最近的用户行,停在超长回复中间时蓝刻度留在所回答的问题上,而不是回落到会话最新消息。

## Alternatives considered

**保留圆点轨道作为收起态总览。** 否决:圆点(横杠)与行刻度(竖条)是两套互相竞争的标记系统;扁平列表独自承担导航与位置指示。

**用隐形热区悬停展开替代开关按钮。** 否决:没有轨道就没有可悬停的目标,隐形热区无法被发现;当时 header 按钮负责展开/收起(后被移除——见[去开关跟随笔记](2026-08-16-message-timeline-toggleless-follow.md))。

**圆点原位长出文字。** 否决,理由同上一篇笔记的分析:10px 圆点间距对文字行太密,行高需要约 26px 后位置隐喻就失效了。

**为可读性加不透明卡片背景。** 暂缓:扁平列表按设计覆盖在会话文本上,静止压淡使覆盖保持环境化。若收到可读性反馈,可以加回浅色平台背景,无需结构改动。

## Consequences

单一标记系统,无框,无可见滚动条;时间轴读起来像页面的一部分。静止态只有刻度条拦截指针事件,列表从不阻挡下方的会话内容。`dotPitch` 与此前的 preview 配置键一样成为未知字段(pre-release 立场:不留兼容层)。本笔记取代[全高面板笔记](2026-08-15-message-timeline-full-height-panel.md)的交互一半——其中被否决的"移除圆点轨道"方案被采纳;分页与高亮推导的决策仍然有效。覆盖:组件规格驱动行渲染、高亮、键盘与翻页;纯 CSS 的亮度分层不做单元断言(jsdom 不计算悬停样式)。
