# Agent Note：Context Lens 在调用发生的地方显示它

Status: implemented

## 问题

Context Lens 里一次请求的历史会列出工具调用和结果，但读者常常要看调用前后的现场：它运行时会话是什么样子。比如 8 条一模一样的 `Replaced 1 occurrence in …`，其实来自 8 次不同的编辑，只有会话里才看得出每条对应哪次编辑。lens 可以在自己的面板里跳转，却没法把读者带到左边会话里的那次调用。在协作间里，外部成员的调用根本不在房间对话里，而是在成员自己的会话里。

## 决定

- **调用在本会话里时，调用行提供「在会话中查看」。** 这包括主 agent 的调用，以及它通过工具调用派出的子任务的调用（嵌在那次调用下面）。跳转按宿主的 `data-chat-call-id` 找到调用行（ui-tool ToolCallTree）。还没渲染出来的调用，先用 `loadThrough` 把历史翻到它所在的那一轮；实在找不到，就退到那一轮。刚切过去的会话还在加载自己的第一页，这时发出的 `loadThrough` 不会翻页。一次性实例上实测到：`loadThrough(1148)` 立刻返回，渲染出来的仍然只有第 74–82 轮。所以跳转（`locateCallPaging`）先等会话渲染出第一批行，再翻页，最多重翻三次，仍找不到才退到那一轮。
- **折叠的步骤组逐层展开。** 宿主把这些行留在 DOM 里，标成 `hidden="until-found"`，收到 `beforematch` 时展开（ui-chat searchable-hidden）。展开要经过一次 React 重渲染，所以跳转先给滚动容器发一次 `beforematch`，之后每帧重新找到这一行，展开它最外层仍然关着的那层。等这一行渲染出来，或过了大约 60 帧，再定位。这就是宿主自己的展开写法（session-inspector `chat-node/reveal.ts`），只是不用它的 `flushSync`。
- **协作间成员的调用提供「在成员会话中查看」。** 适用于房间轮次里的成员运行，以子会话 id 为键。房间的 lens 面板没法自己完成这次跳转：右侧栏按会话保存，切换会话时这个面板就被卸载了。所以交接放在插件层做（`client/member-jump.ts`）。它用 `uiWorkspace.openSession` 打开成员会话，这和房间「轨迹→」用的是同一个入口。然后等右侧栏自己当前显示的会话（`ctx.sidebarRight.mounted`，也就是 `openTab` 实际作用的会话）变成成员会话、lens 页签类型也能在那里打开，超过 5 秒就放弃。会话列表可能先变，这个空档里打开的页签会落进房间的右侧栏。接着用 `locateCall: { callId, hostTurn?, request?, session }` 导航打开 lens 页签。`request` 是读者当时看的那次请求（开始时间、请求编号）。成员会话的 lens 选中包含它的轮次和这次请求，两边看到的就是同一份上下文。原先选的是调用自己所在的轮次，看到的是更早的上下文：第 79 轮的 #201 有 135 条历史，那条编辑结果在 089、×8 重复；调用所在的第 71 轮只有 84 条，它在 071、不重复。成员 lens 上的 #201 和房间里的一致，两边也都和 Kimi 实际发出的一致（线路日志请求 74.1：messageCount 74 加保留的 63 条用户消息共 137，与 `token_counting` 的 length 相同）。之后 lens 再翻到调用自己所在的那一轮，定位到调用。`session` 写明目标会话，收到别的会话 `locateCall` 的 lens 会忽略它。
- **房间面板记住自己的位置。** 交接前，它把当前选中（查看的会话、轮次、对象、请求、主页签）存进一个按会话索引的模块级 Map。回来路上的每次挂载都能取回，因为右侧栏可能把面板挂载不止一次。读者离开这个位置后就丢掉，30 分钟后过期。更新的导航（revision 更大）会永久取代存下的位置，除非那次导航是给别的会话的调用。回来后再点顶栏的 lens 按钮，仍会打开最新一轮，这是那个按钮约定的行为。
- **定位到的调用会展开并描边。** 落点之后，如果这次调用的卡片头是收起的，就点一下它（ui-primitives DisclosureRow：带 `aria-expanded` 的 `data-disclosure-row`；跳过嵌套调用的卡片头），和读者自己点一样；再用一段会自行消失的 Web Animations 描边把调用框圈出约 2.4 秒。
- **阅读状态随调用带过去，回来时连同位置一起恢复。** 交接时还带上读者当时怎么读这个请求：构成过滤，以及展开的那一行（按所在层和层内位置；同一个请求在两边 lens 里重建出的行一样）。成员会话的 lens 只把它们用在这个请求上（按开始时间匹配），等请求详情上屏后再展开那一行并滚到可见处。回来时保留的位置也带上这些，外加详情面板的滚动位置（没有展开行时用它）。已在临时实例上实测：房间 85/85 · 尼尔盖曼 · #228，开着「只看重复」、展开 094 → 成员会话 lens 停在 #228，「只看重复」开着、094 展开，左边落在第 71 轮那次 Edit 调用上，卡片展开并描边 → 经面包屑回房间，lens 的过滤和展开的 094 都还在。
- **面板内跳转返回时恢复过滤。** 跳到被当前过滤藏起来的行（「只看重复」下点「看调用它的」）会清掉过滤。跳转记录里存下每次跳转时的过滤，「返回」时把它放回去。
- **一切都静默降级。** 没有 `uiWorkspace.openSession` 时不显示成员按钮。打开会话报错就停在原处，会话一直没出现就结束等待。

## 考虑过的方案

- **在房间面板里完成成员跳转。** 不采用：会话一切换，面板就被卸载了。
- **让宿主提供「打开会话并定位到锚点」的通道。** 不采用：用不着。公开的打开入口、会话绑定的 `loadThrough` 和这些 DOM 约定已经够用，这一点在一次性实例上对着真实的房间会话验证过。
- **一次性给所有折叠层发 `beforematch`。** 不采用：外层重渲染时，内层可能在展开之前就被替换掉了。

## 后果

- 如果成员的调用比成员 lens 已加载的轮次窗口更早，跳转拿不到可翻页的那一轮的 `startSeq`。这时只能落到那一轮，或者在那个窗口加载之前什么也不做。
- 浏览器后退回不到房间，因为切换会话不产生浏览记录。回房间要用房间的面包屑，或成员会话里的「回到房间」。
- 在一次性实例上看到，成员会话里按轮跳转会偏约 3800px。这是另一个问题：按调用 id 跳转不走按轮那条路。
