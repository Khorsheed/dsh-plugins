# Agent Note：图书馆——讲义单独成页，学员开始一站时才写

Status: implemented

## 问题

讲义放在站页的「讲义」页签里：380px 宽的一整段 markdown，没有目录，看不出读到哪个考点，读完也没有去章节考的入口。侧栏里没有任何东西能「开始」一站，于是什么时候写讲义、什么时候开讲全由教练自己决定（10-26：学员还没采用路线它就开始了）。讲义正文还内嵌在路线 JSON 里，每次读路线都把所有讲义一起带回来。

## 决定

与用户对照 `proposals/prototypes/library-lesson-page.html` 定论（方案 B：图书馆里的一页，不是单独的侧栏标签）：

- **站页去掉「讲义」页签**，只剩导读 / 我的记录 / 章节考。导读顶部的讲义卡有三种状态。没有讲义：「开始学这一站」，把这一站和它的考点填进对话框，留出位置让学员补一句，不自动发送。等待中：「教练正在备课…」，每 4 秒重读一次，10 分钟后可以再问一次。有讲义：列出考点和掌握小圆点，加「打开讲义」，直接打开讲义页，不经过教练。
- **讲义页**是图书馆里推进的一页（路由 `lesson`）。按 `##` 标题把 markdown 切成节，一个考点一节。窄屏时目录是顶部一排小胶囊，容器宽度 ≥720px 时目录在左栏；每条目录带对应考点的掌握小圆点。页尾是「觉得掌握了？」→ 去章节考 / 问教练。「问教练」在对话框里填「我看了「…」的讲义，想问：」。原来整份重写的「请教练补讲」按钮去掉了。
- **讲义页自动打开**：点「开始」之后写入的讲义一到就打开（等待标记存在面板 store 里）。
- **教练等学员**：提示词和 `library_notes` 的返回都要求教练只用一句话告知讲义已好，让学员先读、再提问（第一批已做）。如果问题暴露了讲义的缺漏，就补上那一节。
- **存储**：正文存在 `notes/<教材>/<站>.md`；路线节点只留 `{ updatedAt, revisions }`，readRoadmap 读路线时把正文补回来，所以所有读取方都不用改。重写时被替换的版本存为 `<站>.<n>.md`。旧数据里内嵌正文的节点照常能读，下次写入时迁到文件。删除教材时一并删除它的讲义目录。

## 考虑过的方案

- **讲义单独开一个侧栏标签**（第一版样机）：用户否决。讲义会出现在两个地方，标签也会越开越多；宿主的全屏本来就作用于整个图书馆标签。
- **讲义写好后教练立刻开讲**：用户否决。学员先读，再提问。

## 后果

- 旧路由里的 `tab: 'notes'` 会回落到导读。
- 旧版本只存在磁盘上，暂时没有「查看上一版」的界面。
- 教练仍要等学员把填好的那句话发出去。讲义卡上写明了这一点，10 分钟后按钮会恢复可点。

## 测试

190/190 全绿。新增 service 测试：讲义存到文件、路线 JSON 不含正文、重写时归档第 1 版、删除教材时清掉目录；旧的内嵌讲义照常能读，下次写入时迁移并保留原来的版本号。界面在侧栏 fixture（深色）中核对过：有讲义和没讲义两种导读卡，以及讲义页在 420px（顶部胶囊目录）和 900px（左栏目录）下的样子。

## 后续（2026-10-26 当天）：讲义都是课本身，站都是章节考

这几批上线后第一次实测暴露了三个问题：
- **讲义写成了读书指引。** 在模型选的教材（Blender 手册）上，教练写的是「读书指引」：去读手册哪几页、注意什么，学员只能在侧栏和手册之间来回切。用户要的是像他自己 `lessons/` 系列那样的课：核心问题、「你将学到」、热身问题，每个考点一整节，带例子和思考题，最后小结。现在 `lessonProblems` 对所有教材都生效，外部材料（手册页、视频、学员自己书上的页码）只放在最后的 `## 参考`。`library_notes` 的说明和两种「开始学这一站」请求都写明了这一点。
- **只有验收标准的站。** 第一批会根据验收行推断出动手验收站，于是教练写的「学完能做到」把两站变成了没有考点的验收单，学员不知道该交什么。现在，除非显式指定 gate，站一律是章节考站，验收行并进这一站的目标。`library_roadmap` 拒收没有考点的章节考站，并点名是哪一站。服务端对旧数据和直接调用保持宽松。
- **「推荐下一站」**孤零零地放在一个空框里。现在下一站的站名旁边带一个小标签「下一站」（悬停提示：路线上第一个还没过关的站，哪一站都可以先学），按钮直接放在下面。
