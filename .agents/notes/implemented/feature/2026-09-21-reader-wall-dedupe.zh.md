# Agent Note：墙把转载的重复折起来

Status: implemented

## Problem

聚合 feed 会转载同一篇文章——读者 3080 的墙上 "An Alien Mind" 同时出现在聚合源和原始博客下面；同一篇出现两次，订阅墙的可用性就实实在在地打折。读者批准了形状：去重作为墙级收窄，默认开，隐藏——绝不删除。

## Decision

- **检测绝不做模糊匹配**（`client/selectors.ts` 的 `dedupeRows`，纯函数）：先按归一化链接分组——协议、`www.`、尾部斜杠剥掉，追踪参数（`utm_*`、`fbclid`、`gclid`、`spm`、`ref`……）移除，其余查询参数排序——链接没分上组才退到**折叠标题 + 同一发布日**：大小写、音标、标点折叠，两个日期都必须存在，折叠后标题不足 6 个字符不组。漏配代价是一张重复卡片，误配代价是一篇文章；每个边角都由这个不对称决定。
- **幸存者的选择**，按序：宿主已经持有正文的成员（`ready` 抓取态——那份点开秒读）胜过更新的成员；再平手保持输入顺序。「非聚合源」信号刻意跳过：行上的任何字段都诚实地推不出它，而猜出来的聚合源排名恰恰是这道闸要防的模糊逻辑。幸存者坐在自己在排序里的位置上。
- **被隐藏的子项是报备，不是删除**：幸存卡片带「N 个重复来源」徽章，tooltip 写出其它来源（v1 就是 tooltip；点开列副本是评审为不需要的升级），底部在折叠发生时注明「已隐藏 M 条重复」。
- **阅读状态跨组归并**：任何一个副本读过 → 卡片显示已读。归并发生在展示时；底层按条目的已读游标不动。
- **开关是一个收窄，所以住在收窄住的地方**：筛选弹层的阅读状态区，「只看未读」下面一行——不是新的工具条按钮（表头已满）。默认开；骑 `unreadOnly` 那份会话快照恢复（hydrate、镜像、以及[卸载冲刷](../bug-fix/2026-09-21-reader-unmount-narrowing-flush.md)——去重状态也能扛住那次丢筛选的分栏）。
- **折叠覆盖墙展示的一切**：行列表、表头未读数、匹配行、空态，以及自动补抓的工作池（被隐藏的副本不抓——幸存者作答；重新打开视图会重新入池，`backfillTried` 保证不形成风暴）。

## Alternatives considered

**在 `selectRows` 内部去重（300 条切片之前）。** 否决：`selectRows` 是墙的本地谓词，而幸存者信号要抓取状态镜像——那个函数从来不需要它。对它的输出单跑一道，两边都保持纯，而且切片语义保持诚实（它数的是折叠前的行——那是渲染上限，不是内容上限）。
**模糊标题相似度。** DOI 解析器的双因子闸存在，正因为纯标题匹配在真实数据上会误中；墙上没有作者 corroboration 可配对，所以墙的回答是完全匹配加同日，否则不组。
**删掉重复条目，或在写入时归并已读游标。** 折叠是**视图**：被隐藏副本自己的状态（标签、抓取记录、它所属 feed 的窗口）原样保留，而归并在展示时计算，于是「已读」永远不需要一个「反已读」的逆操作。
**徽章点开列出重复副本。** v1 保留 tooltip：徽章的职责是出处，不是导航；重复副本离一次开关切换。

## Consequences

- 转载的文章是一张卡；徽章让这组出处可发现，tooltip 写出其它来源。
- 未读数与匹配行读的都是读者看到的（折叠后），折叠的墙和它的计数器永不打架。
- 去重键由已经算出的行逐渲染推导；没有新请求、没有新线面字段、没有宿主状态。
- 已知边角，按设计接受：同一天两篇真的不同的短文共享短标题会折叠（6 字符地板让它罕见）；没有日期的保存链接永不按标题分组（链接就是它的身份）；未读筛选先于折叠——被它藏掉的已读副本会留下一个未读重复单独站着显示未读——筛选自己的语义优先。
