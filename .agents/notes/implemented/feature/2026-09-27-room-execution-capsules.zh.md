# Agent Note: Room 执行与计划胶囊

Status: implemented

[English](2026-09-27-room-execution-capsules.md) | 中文

## Problem

Room 输入栏展示聊天任务板和空的正式目标表单，成员会话入口与中止操作却散落在聊天消息里。按成员只保留最近一次运行的投影，无法表达同一持久会话里的多次执行。打开同一会话的入口使用不同名称，还暗示了并不存在的独立成果查看器。

## Decision

输入框上沿放默认折叠的「后台 Agent」与「当前计划」胶囊。同一时刻只展开一个面板，内容位于胶囊上方；点击外部或 Escape 收起。后台 Agent 胶囊只含名称与图标，有执行时图标换成不闪烁的绿点；数量和详细状态放在面板或可访问的悬停提示内。存在已保存计划才显示计划胶囊。简短任务列表通向宿主可选的、按会话绑定的计划侧栏，复用证据与验收控件；侧栏服务缺失时在原位展开详情。侧栏注册沿用 Room 的 preset 显隐规则。

Room 从已有运行事件增量投影执行历史，不改变派发、交付或目标调度。执行身份和子会话在后续轮次、成员改名和移除后保留。模型、强度与单轮 token 总数只记录 facade 完成回报里实际观测的字段，缺失保持未知。观测值使用独立的纯日志元数据事件，不会重新触发聊天渲染器的运行生命周期。原生后代会话读取宿主公开会话列表，排除无关会话和重复 Room 成员，用量与耗时明确标注「会话累计」。从成员自身输入框直接续聊、没有对应 Room 执行记录时，仍以运行中的会话累计行显示；协调者会话仍排除。不虚构宿主未登记的 harness 内部 worker。

执行卡片中止请求携带所展示的执行身份和准入时间，宿主先比较两者，再触及取消通道。原生后代中止会校验完整父链确实回到当前 Room，再使用既有宿主或 facade 控制。所有会话入口打开真实子会话，不复制消息列表。执行完成与证据验收保持不同状态。当前协调者轮次和完成报告交付不显示为后台执行卡片。

完整计划控件保留版本校验、证据要求和重启对账。运行限制默认折叠；手动创建时分别提供「开始推进」和「保存草稿」。普通聊天不创建计划。没有执行历史或正式计划的房间及原有包内入口仍保留旧任务与目标控件。

## Alternatives considered

**在右上角新增工具栏。** 宿主没有提议中的 Room 专用位置。输入框上沿胶囊符合已有产品形态，也让输入栏保持自包含。

**用「查看成果」和「消息记录」分别命名同一目的地。** 两个操作实际无差异，因此统一使用「查看会话」；真实证据仍位于计划详情。

**每个成员只放一张卡片，把累计 token 当作任务消耗。** 持久成员可以执行多轮，因此 Room 持久执行与原生会话摘要保留不同统计单位。

**新增调度器或强依赖 TaskPilot。** Room 已拥有持久派发和验收，公开会话投影能提供后代可见性，无需依赖兄弟插件。

## Consequences

默认输入栏减少常驻控件。历史执行结算后仍可查看，旧中止操作不会作用于后续轮次。旧记录缺失的模型和用量不补造；打开旧成员会话不承诺定位到具体消息。大量历史在展开面板内滚动。可选侧栏增加官方 peer 依赖，但不增加必需的运行时 inject。测试覆盖历史回放、改名与移除、过期中止、原生父链、缺失观测、折叠指示器、面板关闭和主动打开详情。
