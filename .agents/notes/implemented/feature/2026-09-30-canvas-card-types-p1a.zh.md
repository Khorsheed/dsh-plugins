# Agent Note: 画布卡片类型 P1a：类型页、两个类型工具、三种版式、字段表单

Status: implemented

## Problem

提案 `proposed/feature/2026-09-30-canvas-card-types.md` 已获批。第一阶段要让分类的「类型」端到端跑通：

- 用户说清想要什么（文字、草图、图片）；
- Agent 读了之后起草一份定义；
- 用户看到效果，采用或不采用；
- 采用的定义改变卡片的样子，也约束之后的 Agent 怎么建卡。

## Decision

**宿主一半**（提交 b2a6c217）：

- 分类行带 `brief`（参考稿）、已采用的 `definition` 和一份待确认的 `proposal`。存储新增 `setTypeBrief`、`proposeType`、`decideType`。
- 采用时按草案的 `renames` 搬动卡上的值。不采用一个从未采用过的草稿分类时，分类一起撤掉。
- `canvas_read_type` 返回参考稿。手绘在宿主侧画成灰度 PNG（`src/raster.ts`），线路能看图时作为附件带上。提案里「Agent 能不能看到手绘」这条风险就此解决，不需要上游改动。
- `canvas_propose_type` 提交唯一一份待确认提议，替换之前那份。
- `canvas_propose_card` 接受 `fields`，按定义校验，一次列出所有问题。
- `canvas_read_board` 列出每份定义的字段名和类型。hint 只放在 `canvas_read_type` 里。

**客户端一半**：

- **类型页**是画布详情的第三种页面。标签条把它存成行内位置（`{kind: 'type', catKind, heading}`），刷新后还在。页面分三段，带编号：
  - ① 参考稿，用卡片编辑器；
  - ② 待确认的提议：按提议的版式画出的样例卡、理由、字段表，然后是「采用」/「不采用」；
  - ③ 当前定义，下面最多列十二张样例卡。
- 「交给 Agent 设计」把分类引用进主输入框，不自动发送。
- **入口**：分类面板每行一个「设计」按钮。有提议（或未采用的草稿）的分类，在行上和筛选 chip 上亮一个标记。
- **三种版式**：note 保持现在的卡面。profile 和 entry 在卡有字段值后画 `TypedFace`（标题字段，再加填了的卡面字段）。凡是提到卡名的地方，类型标题都替代正文标题。
- **卡片页**在正文上方多一块字段区：
  - 阅读态列出值。引用是按钮，点了跳到那张卡；卡没了就禁用并标出。定义里已不存在的字段值折在「已移除的字段」下面。
  - 「编辑字段」打开表单。保存时整份写回，所以被删字段的值会跟着保留。必填字段为空时表单不关，并给出提示。引用选择只列字段 `refKind` 对应分类的卡，且不含本卡。

## Alternatives considered

- **保存参考稿时在客户端栅格化手绘。** 这样每次保存都要上传，图片还可能过期。在宿主侧从存下的笔画现画，天然保持一致。
- **把类型页做成弹窗。** 提案里已否决；行内位置自带面包屑、返回路径和刷新保留。

## Consequences

- 从卡板新建卡仍然只有正文，字段之后在卡片页补。
- 留给 P1b：给已有卡片回填字段（`canvas_propose_fields`），以及 Agent 发起的类型用虚线 chip。P1c：自定义 HTML 版式。
- 版本 0.5.0：模型可见工具从五个变成七个。

## Testing

- `tests/card-types.spec.ts`：定义、采用时的重命名、草稿不采用、字段校验、栅格化。
- `tests/fields.client.spec.tsx`：卡面、字段列表（打开引用、失效引用、被删字段的值）、表单（标签、数字、保留值、必填、引用过滤）、类型行刷新后恢复。
- `tests/type-view.client.spec.tsx`：参考稿和提议预览后采用、引用进输入框、不采用草稿后返回。
