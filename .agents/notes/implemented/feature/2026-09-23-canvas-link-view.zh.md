# Agent Note：连线视图是一块画布的第二张面，手写

Status: implemented

## Problem

`proposals/active/2026-09-16-canvas-space.md` §11.4 的阶段 ⑥ 是这一轮画布里最老的一条未落地需求：一块板是一个**列表**，里面没有任何东西能表达「这四张卡是同一个论证」。用户要的是把这种分组画在板面上，然后能把这一组当作一件事交给模型——「就这一组提问」/「生成文章」问的是一簇卡，不是筛选芯片当下显示的那些。

四条约束让它不止是一个画布控件：

- **位置不能是屏幕像素。** 右栏宽度由用户拖，一张卡的位置必须在 380 px 和 900 px 的面板下是同一个意思。
- **线必须是数据。** 如果分组只活在绘制面上，面板一关它就没了，模型也永远无从知道用户指的是哪几张。
- **一个手势必须是一次写。** 拖动一个分组框会同时动框**和**框里的每张卡。逐张写意味着 N 个请求，每个都带着上一个刚刚作废的版本号。
- **盘上每块板都没有这些。** 四十多个 `canvas.json` 没有坐标、没有线、没有分区；不管这次做成什么样，都不该需要迁移。

还有一条只属于这个包的约束：浏览器半边以**一个** `lib/client.js` 出货，它唯一的样式通道是内联的 `.module.css`（`build/tsdown.client.ts` 把类名编译成哈希，再以 `<style data-plugin-css>` 注入）。这一点直接决定了哪些图编辑库能装进这里。

## Decision

- **三个字段，全部宽容读。** `canvas.json` 增加 `links[]`（`{from,to}`）、`lanes[]`（`{id,label,x,y,w,h}`），卡增加 `x`/`y`——**成对出现或者都没有**，绝不落单。`normalizeLanes` / `normalizeLinks` / `normalizePositions`（`src/types.ts`）沿用板面一贯的按字段宽容：坏行丢掉、好行留下，手改过的文件永远不会让一块画布打不开。上限：400 条线、40 个分区、分区标题 24 个码元。指向不属于这块板的卡的线被丢弃——但**已归档**的卡算作在场，因为隐藏一张卡不是删除它，它恢复时线应该跟着回来。
- **坐标是一个空间，不是视口。** `LAYOUT_BOX`（= `DRAW_BOX`，600×400）是布局写入的单位，而且刻意**不加夹取**：连线面能平移，所以 `x: 900` 合法。绝对不能发生的是存屏幕像素——那会在面板换个宽度的下一次，把每张卡都摆错位置。数值取整到整单位。
- **分区归属是几何算出来的，从不存。** 一张卡属于一个分区，当且仅当卡的**中心**落在它的矩形里（`laneHolds`）；没有 `laneId` 字段。于是归属只有一个来源，并且任何一方被拖动之后它依然自洽。边界算在里面，所以两像素的缩小不会把一张没人碰过的卡甩出分区。两个分区重叠时，**列表里先到的那个**赢——重叠是这块板要自己收的口子，不是这一次读取该翻来覆去裁的题。
- **一个动词：`setLayout`。** `{ canvasId, positions?, lanes?, links? }` 把一整个手势落在和其他板面变更同一道版本守卫之后。**「没带这个字段」和「带了一个空数组」是两种请求**：省略 = 这一盘不动，`[]` = 清空。
- **两层切分，切在 DOM 结束的地方。** `src/client/space/layout-geometry.ts` 是纯的——无 DOM、无 store，每个盒子进来都是四个数——于是归属、框选命中、分区可达边界和线的形状都能在 node 测试里回答。`src/client/space/LinkView.tsx` 只剩手势与渲染。每个手势通过同一个 `runGesture` 助手各挂各的 `window` 指针监听，并且**从松开那一刻的事件重新算一遍结果**，不读记忆里的那一刻：拖拽中途的旧帧不可能被提交，也不需要一条靠依赖数组撑着的 `useEffect`。
- **三个决定管住所有形状。** 归属看卡心而不是看面积。线的控制点沿**主轴**推、推力**带符号**、并有 24 单位下限，所以不管 `{from,to}` 怎么存，线尾都从邻居那一侧出去、曲线不会自己打结；相邻的卡会鼓起来，而不是塌成一条看着像渲染故障的直线；两轴相等时读作水平，因为板面就是这个流向。*（端点自己在这里是按卡心锚定的，现已改锚在相向的两条边上、每侧各一个端口——见[那轮验收，它发现的正是线穿过卡片](../bug-fix/2026-09-23-canvas-acceptance-round3-fixes.md)。）*两个维度都不到 8 px 的抖动是点击，不是框选。
- **两张面是同一块板，所以切换器在两张面之外。** 「卡板 / 连线」在 tab 顶栏里，不在任何一张面内部。点节点只选中、**绝不**编辑；节点上那支笔打开详情标签，而详情标签是唯一的编辑器（这是本轮另一个决定——[详情即唯一编辑器](2026-09-23-canvas-detail-tab.md)）。
- **「顺线扩一圈」是手势，不是内容。** 它取沿线的传递闭包，然后补**一跳**同分区的卡——而且只从种子出发，绝不从被线拉进来的卡继续扩，否则一条线会悄悄带走一整章。默认关，永不落盘；解析不出来的种子（归档卡）直接出局。
- **只读只关写的那一半。** 点选和框选照旧，拖拽、分区编辑、连线编辑关掉。一块不能选中的只读画布也就不能被提问，而「被提问」正是这张视图存在的理由。
- **手写的绘制面。** 没有安装任何图编辑依赖。带测量的否决理由在下面的 Alternatives。

## Alternatives considered

- **`@xyflow/react`** ——本轮先前选定的方案，在这里**被推翻**。三条理由，第一条单独就足以定案。(1) *它的样式挂不进来。* 这个包的公开面是 `index.js` 加 `dist/base.css`、`dist/style.css`（看它的 `exports` 映射）——普通的全局样式表，选择器打的是 `.react-flow__*` 这种元素类名，不是 CSS module 类名。本 bundle 只内联 `.module.css` 且把类名全量哈希，所以 import 那两个文件要么构建失败、要么落成一堆没有样式的 DOM，而所谓"解决办法"是手写第二张样式表去覆盖他们的内部结构。(2) *体积。* 12.11.6 解包 1,216,002 字节、516 个文件（`npm view @xyflow/react dist.unpackedSize` 实测），约等于**我们整个 `lib/client.js`（504 KB）的 2.4 倍**。(3) *主题。* 它的观感来自自己那张表上的 token，而这个包的规矩是每个颜色都是官方 `--dsw-*` token。它真正能替我们做的事——拖节点、画边、平移缩放——在已经独立被测的那一层里大约 300 行；它要我们付出的代价是整条样式通道。（`tldraw` 沿用先前测量继续出局：生产许可不覆盖 + 遥测。）
- **每张被拖的卡发一次 `patchCard`。** 因为 Problem 里那道算术被否：拖一个分区是 N 次写，每次的守卫都会被上一次的结果作废，所以一次分组拖动会按构造撞自己的版本守卫。`refileSelected` 那次串行扇出就是仓库里现成的证词。
- **把 `laneId` 存在卡上。** 被否：两个真相来源，任何一方移动都要重新同步，而且一个中途停下的拖拽会留下一张声称属于某个分区、中心却早已离开的卡。
- **用数组下标当位置（`cards[]` 的顺序就是布局）。** 被否：列表顺序是切换器和板面都已经依赖的展示语义，为了挪一张卡去重排，会把后面每张卡都悄悄改一遍。
- **把连线面做成另一种 tab。** 被否：需求是一块板的两种读法，而第二张 tab 会在只有一块板的地方给出两个"我在哪"。
- **让线替你选卡**（拉线过程中悬停到某张卡就选中它）。原型轮就被否，这里继续不接：线落在明确的靶子上，选中始终是一个有意的动作。
- **把扩圈结果落盘。** 被否：「顺线扩一圈」回答的是"我这一次要发出去哪几张"，存下来就把手势变成了板面内容，后来的人还得替你解释它。
- **在节点手势入口一刀切 `readonly`。** 我最初就是这么写的，是组件测试当场点名的真缺陷：它把选中和写一起关掉了，而框选那条路还开着——于是只读板能框选却不能点选。选中不是写；那道守卫挪到了写的一半上。

## Consequences

- **`CanvasBoard` 多了两个必填字段 `links` / `lanes`**（过了归一化读就一定在），所以每一个手搭的 fixture 都得带上它们。这次改动同时给三个客户端 spec 的 `board()` 补了这两行。给后来的人记一句：**这个仓库没有任何一个包对测试做类型检查**——`tsconfig.client.json` 到处都只列 `src/` 下的文件——所以一个 fixture 和 wire 类型漂移了，`pnpm run build` 看不见，只有谁手工对 spec 跑一遍 `tsc` 才会浮出来。这是仓库既定约定，本 note 不改它；只记下这个约定确实有这个价钱。
- **降级比 `categories` 安全。** 0.4.4 的宿主读到 0.4.5 的文件会忽略 `links`、`lanes` 和 `x`/`y`：每张卡照旧列出，一张都不藏。这三个新字段承载的不是**内容**，只是摆法。
- **卡可以被拖到看不见的地方。** 世界框随内容长，没有缩略图也没有「回到第一张卡」。节点拖拽夹在**可见舞台**而不是世界框里，所以世界不会无界地长，但拖分区仍然可能把卡停在折叠线以外。
- **DOM 上刻意留了 `data-*` 钩子**（`data-node`、`data-wire="from:to"`、`data-port`、`data-lane`、`data-world`、`data-open`）——CSS module 的类名在构建期被哈希，拿它做断言等于在断言一个构建产物。
- **jsdom 把所有盒子报成 0×0**，于是没人搭手的 node 测试里看到的是 `UNMEASURED`（168×64），每次拖拽都夹到 `{x: 0, y: 0}`。要伸手打桩的是**舞台的 `clientWidth`/`clientHeight` 和节点的 `offsetWidth`/`offsetHeight`**——不是 `getBoundingClientRect`，jsdom 本来就答在原点，而视图只拿它读自己的偏移。`tests/link.client.spec.tsx` 把这四个 getter 钉在原型上、整份文件生效（620×420 的舞台、180×60 的节点，于是拖拽的天花板是 440×360），并按用例覆写 `scrollLeft` 把舞台推进滚动位置；滚起来之后的那条框，是数字不真就毫无意义的那一种。
- **线的选中态按对象身份持有，不按下标。** 可见列表会按归档状态过滤，用下标会在用户脚下自己挪位。
- **新增 31 对中英 locale**（`view.*`、`link.*`、`compose.*`、`detail.compose`），而「卡板 / 连线」切换是手搭的，因为宿主没有 Segmented/Select 原语——这和分类面板那几行只是普通按钮是同一件事。
- **两条发送文本现在被逐字钉在 `tests/prompt.spec.ts` 里**：「生成文章」和「就这一组提问」。它们是模型的指令，所以改一个词就该挂一条测试。原型里第二句断在半句上，这次是把话说完，而不是把破句往下传。
- **§11.8 仍未裁决**：线要不要有方向或标签，以及跨画布的分区归属。这两条都不是本 note 该答的。

## Testing

- `pnpm --filter @khorsheed/dsh-canvas build`（gen-typert → 宿主 tsc → 客户端 tsc → tsdown），然后 `pnpm --filter @khorsheed/dsh-canvas test` —— **23 文件 / 449 绿**（阶段 ⑥ 之前是 319）。
- `tests/layout.spec.ts`（新增，27 条）：宽容读（`[undefined, null, 'nope', {}, []]` → 空、坏行在好行旁边被丢掉、各个上限生效）、`x`/`y` 成对、无序对去重、指向归档卡的线活着而指向不存在的卡的线死去、`setLayout` 的省略 ≠ 清空，以及版本守卫。
- `tests/layout-geometry.spec.ts`（新增，47 条）：每一个纯回答——卡心归属（含边界）、重叠取先到、四个来向的带符号推力与平局、交叉边界时 `fit` 钉在低值、`dragLane` 带着卡收紧极限直到标题带、`resizeLane` 从不带卡、`groupOf` 的一跳规则，以及框选阈值要求两轴同时不达标。
- `tests/link.client.spec.tsx`（新增，37 条）：挂载（已存坐标被照收、没摆过的卡走自动网格、一条线一条 wire 且归档端不画）、手势（未达阈值的按下只选中不写；3px/4px 一对把阈值本身钉住；真实拖拽写出取整夹取的 `positions` 且不选中；从卡上按下的那一趟永远不会起框；框选追加并提示；端口落下写入这一对，反向重复对被拒；松手在空处、松手回到起点卡自己身上，两种都不写），线（只删被选中的那一条，且选中的那一行扛得住卡列表变化——它攥的是这一行不是它的位置，一条扁框留着选中的线，只有两轴都不到 8px 的轻点才把它交出去）、分区（＋分区铸出 `lane_…` id、回车改名且标签没变时不写、拖分区同时写分区**和**被带的卡、拉角缩放不写任何位置）、发送集（「就这一组提问」/「生成文章」带着 `lens:'ask'` 和被钉住的文本到达 `askAgent`，`data-cluster` 只落在被扩圈加进来的卡上，取消选择连扩圈一起忘掉）、滚动了的舞台按世界单位量框，以及只读那一半——包括本 note 记为"已修缺陷"的那处不对称。
- 其中一条只读的用例值回了两倍票价：一张宽 0–210、高只有 0–3 的扁框，抓到了起点在 y 14 的卡。根因是 `rectsOverlap` 最后一个子句的笔误（`b.y < a.y + b.h`，把*卡*的高度当成*框*的高度），这条式子因此是不对称的——纯测试那边一个都看不见，因为那里每张夹具卡都躺在 y 0、高度和框一样。`rectsOverlap` 现在有了自己的两条钉法：交换参数必须同答，以及扁框压在错位的卡之上必须不抓；找到它的那个组件测试留作第二证人。
- 同一个文件接着在变绿之前先 flake 了一场，而这场 flake 是真的。「连线」开关挡在两次 awaited 读取之后（先列表，再自动打开的那块板），`findByRole` 给这条链的预算是 testing-library 默认的 1000 ms——单跑从不失手，几个包的 vitest 实例一起跑就 3/3 稳定倒下，正是 `build/vitest.ts` 为 `testTimeout` 记过的那堵墙，这次从 async-util 那一侧撞上来。`tests/link.client.spec.tsx` 把 `asyncUtilTimeout` 设成 5_000：只是把预算放大，一条断言都没松。
- 读那次失败的 DOM 快照，从它背后翻出一个真缺陷：明明有画布的账号，面板在说**还没有画布**。`CanvasTab` 那条提示只问了*列表知不知道*，于是"列表已落地、板还在路上"的整段窗口都在宣称账号是空的——平时一闪而过（一次渲染），机器负载重时是好几秒。条件现在改成只声明它真的能声明的事（列表已知、没有已开或在开的画布、且列表为空），`tests/tab.client.spec.tsx`（+2 条）把两种文案都钉住：在途的那段读 加载中…，真空账号才读 还没有画布。
- `tests/prompt.spec.ts`（+2 条）：两条发送文本逐字钉住。
- 不止跑在测试里，也跑在真宿主上：`~/.dsh-lab/profiles/canvas-v2-test` 用 prod 3080 的同一套 bundle 启动打了包的 0.4.5 tarball（端口 3091），并确认出货的 `lib/client.js` 里确实带着连线视图。
