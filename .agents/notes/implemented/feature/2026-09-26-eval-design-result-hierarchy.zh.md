# Agent Note: eval —— 实验设计与结果对比按交互稿 v5 排层次（T80d）

Status: implemented

## Problem

T79 走查（P1-4、P1-5、P2-12、P2-13）的结论是：设计页与结果页的信息已经齐了，缺的是层次。

- 设计页是十几块同一分量的内容。
- 对比组表把每个字段都列出来，不管各组在这个字段上是否相同。
- 就绪块重复一遍「准备环境」，提醒也不说代价。
- 结果页上，结论、有效性审计、导出按钮和单元挤在同一层。
- 结论卡的答案只在 plan 写了问题时才有（T74），没写问题的 plan 看到的是配对表而不是答案。

## Decision

- **设计页顺序**：问题 → 对比组 → 用哪些题 → 怎么判 → 规模与成本（一句话）→ 就绪。
  - 只有问题块与阶段条抬起。
  - 计划网格折进「计划网格 · N 次运行」。
- **对比组的列从行算**（`compareColumns`，`packages/eval/src/client/ConditionsPage.tsx`）：
  - 一列在两种情况下出现：已声明的行在这一列上不一致；或者这一列是端点，且有端点未解析。
  - 各组都相同时退回 harness 与模型两列。
  - 页脚列出相同的字段；不同处多于一个时警告「不同处：N 个（…），结论只能描述」，字段按 `splitFactors` 给出的因子顺序排。
  - sha 只放在悬停里。开跑后 home 变过，才标「开跑时 / 当前」。
- **用哪些题**：
  - 列为「题 / 怎么判」，「怎么判」写全：判官 / 人工终评 / 检查脚本。
  - 没有 plan review 时，「怎么判」仍写出这一行的判官，看不到的两层不写。
- **提醒**：写「不影响启动」加一句后果，按代码取（`reminderConsequenceKey`，`journey.ts`）。没有句子的代码不出句子，也不出原始键。
- **报告投影新增两个字段**，各带单测（`report-face.spec.ts`）：
  - `pair.verdict`：`ranked` / `tied` / `withheld`，从 `comparePair` 已经走过的闸读出来。
  - `pair.coverage`：覆盖缺口，按（组，原因）归并。
  - 算法一个没动。
- **结论卡**：
  - 不论有没有问题，答案都是 暂时不能下结论 / A 优于 B / 未分高下。
  - 每组一个大号分数，差值一句话。
  - 不能排名的一对，原因逐条用人话写：✗ 是阻断，! 是提醒。
  - 下一步至多三个：补判（第一个有覆盖缺口的组）、并排看作答、让 agent 写分析初稿。
  - 两个交给 agent 的动作都走页面现有的 `handToAgent`：优先放进输入框，没有输入框时进剪贴板。
- **折叠**：
  - 有效性校验与「导出与来源」（终评收口、导出、重新导出、单元）都折起，摘要行带 ✓ / ✗ 与导出状态。
  - 判据表按维度分组，缺值挂「未判」chip，列序与结论卡一致，读法说明折起。
  - 效率保留柱图，明细表折起。

## Alternatives considered

- **从 rubric 或题库补出「考什么 / 满分 / 看题面」**。否决。`planReview` 没有这三项的逐题数据，猜出来就是页面上一句没有文件支撑的话。按文案的「缺数据的列不显示」隐去，缺口报给协调者。
- **用 `conditionDiff` 决定高亮**。否决。那份 diff 要先选一对，读的是声明而不是屏幕上的行。从行本身算，高亮的格子才正好是屏幕上显示的差别。
- **在浏览器里从 `rank` / `ciWithheld` / `n` 推出判定**。否决。那等于把 `comparePair` 的闸再抄一份。投影在闸旁边说一次就够了。
- **给「补判」开一个 Remote 动词**。否决。补判是运行决定（R1），新的写面也不在本轮范围内。把一句话交给 agent，复用的是就绪清单已经有的那条路。
- **全部通过时隐藏有效性校验**。否决。摘要行带 ✓ 的折叠离证据仍只有一次点击，而这条链接是 T72 结论卡承诺过的。

## Consequences

- 手写 `EvalReportPair` 的测试夹具需要补 `verdict` 与 `coverage`。
- 设计页上题号现在出现两次（用哪些题、网格）。原先用 `getByText` 查题号的测试改成数出现次数。
- 如果将来逐题的考点、满分或题面进了 `planReview`，用哪些题直接多出这几列，版式不用改：这些列是按数据有无显示的，不是删掉了。
