# Agent Note: lab — controlled experiment units, milestone M1

Status: implemented

English | [中文](2026-08-20-lab-m1.zh.md)

## Problem

The dataseek-eval program needs controlled experiment units: isolated, condition-consistent, reproducible execution environments whose lifecycle — acquire, materialize inputs, collect outputs, release — no existing plugin owns. mission deliberately holds resource release permission without touching resource lifecycles; datasets deliberately ships no materialization beyond read-only worktree views. This is milestone M1 of the [lab proposal](../../../proposals/active/2026-08-19-lab-experiment-units.md): the `ctx.lab` service face with the docker provider — acquire / populate / collect / release / status, environment fingerprints, orphan-process compensation, and the `maxConcurrentUnits` ceiling. The CLI is M2 (with checkpoint / verify / archive), the model tools are M3.

## Decision

Shipped as `packages/lab` (`@khorsheed/dsh-lab`), host-only, skeleton after ankh-guard/mission. `LabService` (`src/service.ts`) owns the verb semantics; `DockerProvider` (`src/docker.ts`) shells the docker CLI through an injectable `Exec` runner (production: a `ctx.subprocess` adapter; tests: a scripted fake), so no unit test needs a docker daemon.

**The docker daemon is the registry of record.** lab keeps no state files: unit id, environment fingerprint, and the mission/run binding ride container labels (`dsh-lab.unit` / `dsh-lab.fingerprint` / `dsh-lab.mission` / `dsh-lab.run`), and `status` / `release` / `acquire` reconcile against `docker ps` + `docker inspect` (single-flight). A host restart loses nothing — the release gate still protects reconciled units because the mission binding survives on the labels. The invariant companion (`src/invariant.ts`) is a deliberate ownership reservation with no data to check.

**Environment fingerprint is a mechanism.** `acquire` resolves the image's first repo digest (falling back to the image id, pulling when absent locally) and registers `{resource, fingerprint}` into the mission's refs via the probed `MissionFace` (`setRefs` / `addArtifact` / `isReleasable`, structurally typed in `src/types.ts` — a `ctx.get('mission')` probe at call time, never an import; the plugin-independence checker forbids the edge). Registration writes warn-and-skip on absence or failure; they never block the resource verb.

**The release gate fails closed and cannot be bypassed.** With a mission binding AND the plugin present, `isReleasable` decides: not releasable → refused; query error → refused; no force flag exists on this path. Without a gate (no binding, or the plugin absent mid-run), release requires `force: true` and warns — this reconciles the lab proposal's "warn and proceed" with the mission proposal's "explicit `--force`" into: warn AND proceed only when forced.

**Inputs: two honest paths.** Container mounts cannot be added after creation, so the zero-copy read-only path is `acquire`'s `mounts` (bind, `:ro` by caller choice), and `populate` tar-copies (`docker cp`) a host directory into the running unit's writable layer. The proposal's "populate = mount" row was amended accordingly. A directory path is the entire content interface — a datasets `worktree_path` product or any caller-supplied path; lab never meets datasets in code, and layer allowlists are enforced by whichever side produced the path.

**Orphan-process compensation.** Every in-container command goes through a `sh` wrapper that records its own pid under `/run/dsh-lab/pids/`; `terminate` sweeps those pids with SIGTERM (best effort — a stopped container makes the sweep fail and that failure is expected), waits `terminateGraceMs`, then `docker rm -f`. Coverage is the provider's own exec path only, as the proposal's risk section states.

**`maxConcurrentUnits`** (config, default 4) is a plain ceiling: `acquire` refuses at the limit with an explicit error. It blocks accidental concurrency — which silently corrupts timing-sensitive measurements — without pretending to schedule.

## Alternatives considered

- **`populate` via deferred container start** (create-not-started at acquire, mounts registered by populate, start on first use) — rejected: lab has no exec verb to anchor "first use" on (orchestrators `docker exec` directly with the resource id), so a created-not-started unit would be unusable or force an eighth verb; acquire-time mounts plus copy-populate covers both needs with no phantom lifecycle state.
- **Host-side unit registry files under `$DSH_HOME/state`** (the mission/ankh-guard pattern) — rejected: it duplicates what the docker daemon already knows and can drift from it; labels plus reconcile give restart-survival with zero owned persistence, honoring the proposal's "lab adds no persistence of its own".
- **Warn-and-proceed release without any force flag** (the lab proposal's original phrasing) — rejected after cross-reading the mission proposal, which assigns lab an explicit force requirement; an irreversible destroy with neither gate nor explicit opt-in was the worse union.
- **Failing acquire when ref registration fails** — rejected: the mission proposal assigns registration writes warn-and-skip semantics; the irreversible operation (release) is where strictness lives, and it fails closed there.

## Consequences

- 26 tests cover the verb semantics without a docker daemon: gate refuse/proceed/fail-closed/force paths, registration warn-skip, the concurrency ceiling, fingerprint resolution (digest / id fallback / pull / unresolvable), the pidfile wrapper and terminate sweep ordering, and registry reconstruction from labels after a simulated restart.
- Real-docker acceptance (orphan reaping after delegation cancel, fingerprint difference across images, ceiling refusal) is smoke work against a live daemon, not unit tests; the unit tests pin the argv contracts those smokes exercise.
- `populate` copies into the unit — callers needing pin-commit immutability for inputs must use acquire-time mounts (the datasets `worktree_path` flow); documented in both READMEs.
- The image must ship `sleep` and `sh`; distroless images need a custom keep-alive `command` and lose the pidfile wrapper.
- The `worktree` provider stays interface-shaped but unshipped; when it lands it must carry the comparability warning (an order of magnitude weaker isolation).
- M2/M3 (CLI, checkpoint / verify / archive, `lab_*` tools) are designed in the proposal and deliberately absent.

## Testing

`packages/lab/tests/` (26 tests): `docker.spec.ts` scripts the `Exec` fake (fingerprint preference/fallback/pull/failure, acquire argv incl. labels/mounts/env/workdir/keep-alive + pid-dir creation, populate's wrapped mkdir + `docker cp`, collect, terminate sweep-then-rm ordering incl. sweep failure tolerance, `listManaged` label reconstruction and the empty case); `service.spec.ts` drives `LabService` over an in-memory provider and a scripted `MissionFace` (refs registration, differing fingerprints across images, ceiling refusal, absent/failing-mission warn paths, populate default target, collect artifact registration, all four release gate paths, reconcile-after-restart incl. gate protection, unknown-unit errors).
