# Agent Note：成员用量表按成员 id 合并，在总量之外拆出输入、缓存命中和输出

Status: implemented

## 问题

房间 75844e33：用户把 Codex 成员「顾言」改名为「Susan」之后，成员用量展开表里出现了两行：顾言（2 轮）和 Susan（1 轮）。原因是 `memberUsage` 按 `member` 分组，也就是每一轮运行时用的名字。另外「用量」列只给一个总数，而每条执行记录里其实已经有计费拆分（`usage`：输入、缓存读写、输出）。

## 决定

- 按 `memberId` 分行（没有 id 的旧记录按名字分），只显示成员当前在名单里的名字（不列曾用名，改过多次名也不需要特殊处理）。主 agent 通过 id 找到名单里的成员类型来识别。
- 「用量」列改名为「总量」，后面新增三列：「输入」（全部输入，含缓存读写）、「缓存命中」（缓存读取占输入的百分比）和「输出」，各自只累加有拆分记录的轮次。没有拆分的旧记录只是历史 bug 留下的数据，拆分列显示「—」，总量照常显示，不做专门的兼容。
- 展开表加宽到 540px；在手机上改为横向滚动，不再撑出屏幕。

## 考虑过的其他方案

- **去掉总量列，把没有拆分的行合成一格显示总数并标注「（未拆分）」。** 这种行只会因为历史 bug 出现；保留总量列（用户的意见）就不需要为它们做特殊显示，代价是表格变宽。

## 影响

改过名的成员只占一行，包含它的全部历史。表格能看出每个成员的 token 花在哪里：输入多少、其中多少是缓存命中、输出多少。

## 测试

`room`：用量测试让一个成员在两轮之间改名，预期只有一行（只用当前名字、2 轮、拆分合计）；展开表显示剪刀手（不带旧名）、10.5K 和 86%。只有总数的成员仍在总量列显示它的总数。
