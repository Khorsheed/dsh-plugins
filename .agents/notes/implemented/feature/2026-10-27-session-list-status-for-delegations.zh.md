# Agent Note：会话列表显示 CLI 成员的运行、完成和待处理状态

状态：已实现

[English](2026-10-27-session-list-status-for-delegations.md) | 中文

## 问题

宿主的会话列表有这几种状态：

- 等待审批 / 待审阅计划 / 等待回答（待处理交互）；
- 运行中（会话自己的 agent 在跑）；
- 「N 个子 agent 运行中」（会话 `subagentCatalog` 里的子会话在跑）；
- 已完成（从运行变为空闲、用户还没看过）；
- 空闲。

「运行中」只来自宿主的 `api-session/status`，而 session-controller 只给宿主自己的 agent 发这个事件。CLI 委派的子会话背后没有宿主 agent，所以成员正在干活的房间、或委派给 kimi 的普通会话，在列表里都看不出状态。房间的提问卡和审批卡是房间日志里的事件，不是宿主的交互，所以「等你处理」也从来不显示。

## 决定

- **local-agent 核心**：委派的一轮登记进「正在进行的委派」表、以及从表里移除时，发出 `api-session/status(childSessionId, running)`。facade 和工具发起的委派都经过这张表。子会话那一行显示「运行中 → 已完成」，父会话那一行把它计入「N 个子 agent 运行中」。
- **room 服务端**：在 `session/event` 上跟踪 `room/run-state`，为每个房间维护一组正在运行的成员。第一个成员开工时把房间会话标为运行中；最后一个收工时撤掉，除非房间自己的 agent 还在跑。房间自己的 agent 停下而成员还在干活时，再标回运行中。这样房间那一行会显示「运行中」，结束后变成「已完成」。
- **room 服务端**：用同一路事件跟踪还没处理的 `room/question` / `room/approval` 卡片，通过 `pendingCards` 这个 Remote 提供出去。
- **room 客户端**：每 4 秒取一次 `pendingCards`，把每张卡片通过 `uiSession.registerPendingInteraction` 登记出去。优先级设为 −1，同一会话里有官方审批时官方的胜出；key 以 `room:` 开头。房间输入框遇到 `room:` 开头的交互不再让位；官方面板用 `instanceof` 认领自己的交互，不会接手房间的卡片。

## 考虑过的方案

**宿主正式提供「插件报会话活动状态」的接口。** 现在还没有。发出宿主自己的事件属于临时借用的接缝，已经写了上游提案（`docs/upstream-proposals/2026-10-27-session-activity-contribution.md`，只在本地）。官方接口上线后撤掉这个接缝。

**由服务端主动推送待处理卡片，而不是轮询。** 插件现在没法声明自己的推送事件。轮询读的只是一张内存表。

## 后果

- 浏览器刷新后，状态要等下一次变化才会重新出现：列表的初始「运行中」仍然只看宿主自己的 agent。
- 房间里有卡片在等时，宿主的停止快捷键在这个房间里不可用，这和任何待处理交互的效果一样。
- 宿主启动以来没被打开过的房间，不会报告卡片；它们的卡片本来就随重启过期了。
