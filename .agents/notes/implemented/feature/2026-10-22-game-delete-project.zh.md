# Agent Note: 从面板删除游戏项目

Status: implemented

## Problem

游戏项目能建、能切换，却删不掉：登记表里的记录一直留在项目切换器里，会话一直绑着它，文件夹也一直留在工作区。用户要求在界面上能彻底删除一个项目。

## Decision

项目切换器的每张项目卡片上都有一个删除入口（常驻显示，触屏没有悬停）。点了以后卡片翻成就地确认，给两个操作：

- **移到废纸篓**（`deleteProject(…, 'trash')`）：删掉登记记录和所有绑定这个项目的会话，项目文件夹移到系统废纸篓（`src/trash.ts`）：macOS 是改名移进 `~/.Trash`，Linux 走 freedesktop 废纸篓并写一份 `.trashinfo` 还原记录。删得彻底，但还能找回。
- **只从列表移除**（`'forget'`）：删掉记录和绑定，文件夹原样保留，之后可以用 `game_open path` 重新登记。

在动任何东西之前先检查三道限制：文件夹里必须还是这个项目自己的 `game.json`，否则返回 `not-a-project`（登记记录指向的文件夹如果已经换成别的东西，绝不会被移进废纸篓）；它不能就是发起删除的会话的工作区本身（`is-workspace`）；只读会话两种操作都不能做（`denied`）。移动失败时（不支持的平台，或文件夹和废纸篓不在同一个磁盘）返回 `trash-failed` 并附上原因，什么都不改，卡片上改为建议「只从列表移除」。删除只能在面板上操作，模型没有对应的工具。

## Alternatives considered

**直接删掉文件夹。** 这样也算「彻底」，但项目里是用户的代码、素材和策划文字，点错一下就找不回来。移进废纸篓，对插件和工作区来说同样是删干净了，又给用户留了退路。

**通过 AppleScript 调用 macOS 访达（支持「放回原处」）。** 它可能在点击过程中弹出自动化权限请求，请求方是宿主进程，而后台运行的宿主没法回应。改名移进 `~/.Trash` 不需要任何权限。

**给模型一个删除工具。** 删除是破坏性操作，很少需要在对话里做；让用户在面板上带确认地操作。

## Consequences

- 在没有受支持废纸篓的平台（Windows）上，只有「只从列表移除」能成功，文件夹留给用户自己处理。
- macOS 废纸篓里的条目不带「放回原处」信息；文件夹保留原名（重名时加时间戳），可以手动拖回去。

## Testing

`tests/store.spec.ts` 覆盖了只从列表移除（文件夹保留，记录和绑定删除）、每一道限制（`not-a-project`、`is-workspace`、移动失败时记录保留），以及移到废纸篓（文件夹被移走、所有绑定删除、再删一次返回 `not-found`）。`tests/trash.spec.ts` 覆盖了 macOS 改名及重名处理、Linux 的 files/info 目录结构和还原路径，以及其他平台拒绝操作且不动文件夹。
