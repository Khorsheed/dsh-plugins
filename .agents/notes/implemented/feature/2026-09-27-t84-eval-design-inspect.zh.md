# Agent Note: 实验设计页改成「启动前检查这份实验」（T84）

Status: implemented

## Problem

设计页（`packages/eval/src/client/DesignPage.tsx`）是人批准 agent 起草的实验的地方。设计走查 `profiles/web-eval/docs/t84-design-inspect.md` 收集了五点反馈：

- **题目。** 「用哪些题」只有看题面。看不到阶段说明、判据、检查脚本，也看不到判分依据的参考材料。
- **判官提示词。** 判官看到什么，开跑前后都看不到。
- **就绪。** 「检查项」每组只写一个「就绪」，看不出查了什么。
- **阶段。** 「阶段 stage1, stage2」放在高级设置里，离它限定的题目很远。
- **退回。** 「让 agent 改…」是死路。

走查还查出三个缺陷：

- **满分。** 满分算进了本次不跑的阶段的判据。F2 显示 100，但 stage3/4 的 35 分根本拿不到。
- **重新检查。** 「重新检查」号称重探各组，实际只重跑 validate。
- **已退回提示。** validate 通过后提示不清。

## Decision

协调者对走查里待拍板问题的裁定也是这份决定的一部分。

### 满分只算本次阶段内的判据，处处一致

- **过滤在哪里。** `leafStages` / `inStageScope`（`weights.ts`）判断一条 rubric 叶子是否属于 plan 跑的阶段。同一个过滤用在三处：
  - 设计页满分，显示成 `65 / 100`，悬停列出被剔除的叶子；
  - 报告计分和导出的权重表。`run.meta` 记下 plan 的阶段，报告剔除范围外的判定并注明。本改动之前的 bundle 仍按全部判据计分，附说明；
  - 判官。`judgedCriteria`（`judge.ts`）按 plan 阶段过滤 llm-draft 叶子，所以一次运行只把范围内的判据发给判官。
- **叶子怎么绑定阶段。** 通过显式的 `stage(s)` 字段、`stageN.json` / `stageN.md` 证据，或 `verify.json` → `runIn`。plan 没写阶段时退回全部判据。
- **为什么。** 此前，本次没跑的阶段的叶子照样发给判官，也照样算进分母。

### 页面顺序跟着检查走

区块顺序：

1. 问题；
2. 比什么；
3. 在哪些题上比，带阶段范围行和「本次阶段」列；
4. 怎么判；
5. 规模与花费，计划网格挂在「作答份数」下，每格预算和判官采样也在这里；
6. 准备好了没有；
7. 原始文件（核对用）。

**原始文件。** `plan.json` 在页内全文只读展示。作者备注和校验原文也在这里。

### 退回

「退回给 agent…」在页首展开一个面板，里面有：

- 由阻塞项生成的建议 chips；
- 一个自由输入框。

**草稿放到哪里。** 默认预填进**当前会话**的输入框。起草这份 plan 的会话是可选的切换项。投递按顺序逐级尝试，直到有一级接住：

1. 起草会话（选了它时）；
2. 当前会话；
3. 剪贴板；
4. 文字留在页面上。

它从不自动发送。

**已退回提示。** plan 的 sha 变了或 validate 通过时清除。等待期间，页面每 8 秒离线重读一次 plan。

### 题目抽屉（右侧；手机宽度下整页）

题目行上的**查看**打开一个五页签的抽屉：

- 题面；
- 阶段说明；
- 判据；
- 检查脚本；
- 参考材料。

**内容从哪来。** 全部按 plan 钉住的 commit 读，走两个 Remote：

- `itemMaterials` 返回每个页签的文件列表，以及带阶段范围的判据行；
- `datasetFile` 读单个文件，限额与 `experimentArtifact` 相同。

**读取路径。** 走 `DatasetsFace.read`。这个 face 不提供的题集级文件（`schemas/<stage>.json`）走可选的 `DatasetsFace.readPassthrough`。datasets 包没有它时，这些文件显示为读不到，不会失败。

**顺序与范围标记。**

- 每个页签先打开读者最想看的文件：`task.md` 最先，然后是本题自己的文件（markdown 在前），最后是题集级文件。
- 不在本次阶段内的判据叶子置灰。
- 每个页签写明谁读它：选手、判官，或都不读。

### 判官提示词：只做查看（方案 A）

- **开跑前。** `judgePromptPreview` 为一道题构建判官会拿到的提示词。它和真实运行用同一个构建器，带范围内的判据和占位材料。提示词显示在「怎么判」里，拆成四段：固定文本、判据、材料、输出要求。
- **开跑后。** `judgePrompt` 返回判官实际收到的每个样本的 `prompt.md`。入口在作答视图的「判定证据」。
- **不做：方案 B。** plan 层的「判官追加说明」没有做。它需要改 plan 协议、validate 和冻结。设计稿把它记为后续。

### 就绪：每行带依据、可展开、warn 挂回所属行

`readinessTable`（`packages/eval/src/client/readiness-basis.ts`）把 review 转成这些行：

- 题集；
- 每个对比组；
- 每个判官；
- 判分来源。

**行内容。**

- 每行一句**依据**（例如「声明=锁 · home 已登记 · 已准备」）。
- 每行展开后逐项列出检查和证据：声明哈希对锁、home 指纹、provision 记录、判官模型、阶段 schema N/N。
- 判官与选手同模型时标**自评**。
- 开跑前，每组最后一行写明真探会在开跑时自动做。
- 开跑后，真探结果决定状态并排在依据最前。展开区显示观测到的模型和秒数，以及一个打开探针子会话的按钮。

**warn。**

- 关于已就绪的组、题集或判分来源的 warn，挂到那一行下面，带修复按钮。
- 「提醒」只留不属于任何行的 warn。
- 阻塞项判定不变（`splitReadiness`）。关于未就绪组的 warn 仍是阻塞项。

**编号。** 按显示顺序编号：行内 warn，然后阻塞项，然后提醒。退回句子里的「第 k 条」指的就是读者看到的那一条。

**标题行。** 区块标题行写明这些行是**离线文件核对（不花 token）**，还是**开跑时真探过一次**。

### 重新检查是离线重校验，并如实这么写

- **它做什么。** 「重新检查方案」重读 `plan.json`，重跑 validate 的离线检查，不重跑就绪真探。按钮文案、悬停说明和代码注释都这么写。
- **为什么不重探。** 真探对每组发一次委派，而且开跑时自动做。一个每点一次就悄悄花一次委派的按钮，会让批准的人意外。所以改的是说法，不是行为。

## Alternatives considered

- **本轮就做判官提示词配置（方案 B）。** 本轮不做。它要同时改 plan 协议、validate、冻结和 `judge.ts`。只做查看（A）不改协议，就回答了「判官看到什么」。
- **满分照旧，加一句说明。** 不采用。结果页会继续比较分母里含拿不到分数的成绩，判官也会继续收到范围外的判据。
- **题目行内展开（v5 的看题面）。** 不采用。五个页签的内容行内放不下。右侧抽屉让题目表保持可读，400px 下变成整页。
- **重新检查时重探。** 不采用。每点一次每组花一次委派，而开跑本来就会探。见 Decision。
- **退回默认放到起草会话。** 不作为默认。实验室 tab 本来就开在某个会话里，多数情况下就是同一个。不同时，起草会话只差一次点击。
- **所有 warn 都留在「提醒」里。** 不采用。关于某个组的 warn 离那个组的行很远，这本身就是「看不出查了什么」的抱怨。

## Consequences

**换来的。**

- 审阅的人能看到：
  - 判分依据的每个文件，按钉住的 commit；
  - 判官的确切提示词，开跑前后都能看；
  - 每一行的「就绪」具体指什么。
- 跑不同阶段的 plan 之间，分数可以比较。
- 判官不再看到本次没跑的阶段的判据。

**代价。**

- 四个新 Remote：`itemMaterials`、`datasetFile`、`judgePromptPreview`、`judgePrompt`。
- 一个可选的 datasets face 方法 `readPassthrough`。
- 设计页更长。
- 新旧结果不能直接比较。记录了阶段的运行按阶段内满分计分；本改动之前的 bundle 保留全部判据的分数，附说明。

**验证。**

- 单元与客户端测试：
  - `tests/item-materials.spec.ts`；
  - `tests/inspect.client.spec.tsx`；
  - `tests/readiness-basis.spec.ts`；
  - `tests/LabReview.client.spec.tsx` 里的就绪用例。
- 每批都在冻结基线上的临时实例截图。
