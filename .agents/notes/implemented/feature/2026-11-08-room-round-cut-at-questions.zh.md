# Agent Note: 房间里的一轮在提问处切开

Status: implemented

## Problem

CLI 成员一轮中途向人提问（`room/question`），人回答后它在同一轮里接着做。改动前，问题卡只渲染在运行卡片里、而且只在没回答时渲染，所以一回答它就消失；成员接下来的话长在同一张卡片里，位于人刚才回答的位置上方；一轮结束时，问题又嵌回一整段回复的中间。人的阅读位置跳了两次。设计稿：`proposals/active/2026-11-08-room-timeline-interaction-order.md` 的 E1 步（用户 2026-11-08 拍板，待定 6 选 A）。

## Decision

一条规则：时间线按发生先后排，成员的一轮在它停下来等人的地方切开。提问前说的话随问题卡留在提问处；回答之后说的话从回答下面接着长，标「接着说」。不加事件类型，也不加事件字段。

- **问题卡就是这一轮到提问为止的卡片**（`RoomSegmentView`，room-question 渲染器拿到新的可选 `segment` 能力时经 `RoomQuestionView` 进入）。带 `runId` 的 `room-question` 节点不再隐藏。等待中它用运行行的卡头（「X 在等你回答」、用时、停止），运行卡片此时不渲染；回答或过期后显示身份行加「问了你」小标签和收起的问题。收起的问题按交互稿的「问 + 答」样式（只在这张卡上；旧日志内嵌在回复里的样子不变）：卡头「问了你」、绿色「✓ 已回答」、「你」小头像加粗体答案；用消息回答时写「用下面这条消息回答了」（靠房间写的「用消息回答」前缀识别，客户端有一份副本，测试钉住两者相等）。
- **它的文字看数据**：回复落地且放置了这个问题时，取回复里到这个问题为止的一段；这一轮还在跑时，取成员实时输出里从上一个问题结束到这个问题之间的部分（`renderMemberOutput` 的 `since`/`until`）；这一段没有实时输出（刷新后）或这一轮没放置它就结束了（被停止、没有回复）时，显示「……」加问题记下的 `before` 尾巴。
- **回答会挪卡片**：`answerQuestion`，以及这一轮还在跑时问题过期，都会在 `room/question-resolved` 之后为提问者的运行写一条 `room/run-moved`（取消 10-27 note 里「问题卡不挪运行卡片」的例外）。用消息回答不需要额外处理：`postMessage` 本来就把运行卡片浮到消息下面。
- **回答后的运行卡片**只显示最近一次结束之后的输出，带「接着说」标签。
- **落地的回复**（`room/speech` 带 `asks`、偏移全部 ≥ 0）只显示最后一个问题之后的文字，头部写「接着说」。复制仍然复制整段回复。
- **同成员成组**：「接着说」卡片在渲染出来的时间线里紧跟这一轮的问题卡（中间没有可见内容）时，不显示头像和名字。相邻关系从 DOM 读（`data-chat-flow-key` 座位；问题卡带 `data-room-seg=<runId>`），每次渲染和座位增减时重新判断。用消息回答时消息夹在中间，那张「接着说」保留头像。
- **回放**（`journal.ts`，只是状态）：`RoomAsk` 新增 `before`、`resolvedAt`（第一次结束时间）和 `reply`（`seq`、`at`、`said` 片段、`inline`），由落地回复的 `asks` 填写。
- **local-agent**：`renderMemberOutput(id, startedAt, { since, until, empty })`（`MemberOutputOptions`）；实时输出的最后一个订阅退出时等一个宏任务，这样同一次提交里一个视图把输出交给另一个视图（运行卡片 → 问题卡）时，已经结束的步骤的文字不会丢。

### 旧日志（看数据，不看日期）

- `asks[].at ≥ 0` → 按上面切开。
- 一条回复里有 `at = -1` → 这条回复照旧把问题放在自己最前面，标「提问于这一轮中途」；它的问题卡不渲染。
- 没有 `runId` 的问题（10-27 之前）→ 单独一行，不变。

## Alternatives considered

**问题留在运行卡片里但不再消失（待定 6 的 B）。** 改动更小，但回答和成员接下来的话仍不相邻，落地的回复仍要重读整轮。用户否决。

**切开但不加「接着说」、不成组（待定 6 的 C）。** 两张卡片会读成两轮不同的发言；成组后读起来是同一个人分两次说。

**从日志而不是 DOM 判断成组。** 视图不重算宿主的排序就无法知道两个锚点之间有哪些可见节点；读卡片前面那个座位既准确又便宜。

**把整轮文字记在问题事件上。** 能让刷新后的情况也准确，但改变了 `before` 的含义并让日志变大；160 字尾巴加「……」是设计稿约定的兜底。

## Consequences

- room 和 local-agent 必须一起部署：旧版 local-agent 会忽略 `since`/`until`，问题卡和「接着说」会各显示整轮的实时输出。
- 一轮进行中，实时片段的分界用宿主的 `receivedAt` 对比房间事件时间——两者都是宿主时钟；提问时 Kimi 仍在流式预览的那一句可能落进「接着说」而不是问题卡（10-27 已知缺口）。
- 按卡片复制/引用：「接着说」卡片的复制按钮仍复制整段回复（和成员自己会话一致）；引用工具按卡片取文字时只拿到这张卡片那一段。
- 折叠：600 字折叠只看「接着说」自己的文字；问题卡里的片段不折叠。
- 事件刚发生时，节点状态（立即）和房间 store 的问题记录（去抖刷新）可能短暂不一致，例如回答后运行卡片要等下一次刷新才重新出现。
