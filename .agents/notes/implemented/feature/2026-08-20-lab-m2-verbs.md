# Agent Note: lab — checkpoint / verify / archive verbs (M2 first half)

Status: implemented

English | [中文](2026-08-20-lab-m2-verbs.zh.md)

## Problem

M1 shipped acquire / populate / collect / release / status. The experiment lifecycle still needs three verbs from the [lab proposal](../../../proposals/active/2026-08-19-lab-experiment-units.md): a rewindable progress point (`checkpoint`), an execution-and-record step (`verify`), and an integrity-checked export (`archive`) — the pieces the release gate's `file-check` guard consumes. The CLI half of M2 follows separately.

## Decision

All three verbs land on the existing `LabService` / `DockerProvider` split, keeping the red lines mechanical:

**`checkpoint(unitId, {name})`** — the workspace (the unit's `workdir`, default `/workspace`, now a first-class `UnitInfo` field riding the `dsh-lab.workdir` container label so reconcile keeps it) is committed and tagged with the checkpoint name; the commit sha is the `ref` registered via `MissionFace.addCheckpoint` (the proposal's "only the resource holder fills `ref`"). A workspace that is not yet a git repo is auto-initialized on first checkpoint; a read-only mounted workspace fails loud at `git init` — it cannot be committed, which is the correct signal. The commit uses per-invocation `-c user.name/user.email` identity, never a global git config mutation.

**`verify(unitId, {command, source?, timeoutMs?})`** — optional verification material is copied into the in-container scratch dir `/run/dsh-lab/verify` (reset first, removed in a `finally` so a failed run never leaves it mounted), the command runs in the workspace through the same pidfile wrapper (so a timed-out client leaves a sweepable in-container pid), and the outcome returns VERBATIM: `{exitCode, stdout, stderr, durationMs, timedOut}`. Non-zero exits are data, not exceptions — the code path contains no pass/fail branch; when a mission face is present the same payload is annotated into the fixed `lab` namespace (mission-side convention: programmatic writers own fixed namespaces). `timedOut` is a recorded fact, not a verdict. The `Exec` runner gained an optional `timeoutMs` (the `ctx.subprocess` adapter maps it to an `AbortController` against the spawn's terminate ladder).

**`archive(unitId, {target, kind?})`** — the workspace is collected into `<target>/workspace`, then a `manifest.json` is written: unit facts (id, provider, resource, fingerprint, workspace, mission binding), `archivedAt`, and one sorted entry per file (`sha256` + `bytes`) or symlink (target). Registered as a mission artifact with kind `archive` — exactly what a run template's `file-check` guard (e.g. `archive/` expecting `workspace/` + `manifest.json`) can then gate `releasable` on.

Registration on all three verbs keeps the M1 discipline: mission absent or the write failing → warn and skip; the resource verb itself never blocks on bookkeeping.

## Alternatives considered

- **Checkpoint via `docker commit`** — rejected: it snapshots the whole container filesystem into a new image layer per checkpoint (heavy, and mixes environment with content); a git tag on the workspace is the proposal's semantics and keeps rewind points content-scoped and inspectable.
- **Verify material as a transient bind mount** — rejected: docker cannot mount into a created container (the same constraint that split M1's populate into acquire-mounts + copy); a scratch-dir copy with `finally` removal gives the same "mounted only during verification" visibility window.
- **Throwing on verify's non-zero exit** — rejected absolutely: it would smuggle a judgment into the one verb whose red line is "record, never judge"; callers read `exitCode` themselves.
- **Archive via `docker export`** — rejected: the full rootfs tar duplicates the image content the fingerprint already pins; the workspace plus a sha256 manifest is the diff the gate actually guards.

## Consequences

- 42 tests total (16 new): checkpoint's init-skip/fail-loud paths and tag→sha ref, verify's three acceptance shapes (failure / timeout / silent success) recorded verbatim with no verdict, material cleanup on failure, timeout plumbing, archive's manifest hashes against known sha256 values, mission-absent warn paths for all three verbs.
- `checkpoint` requires `git` in the image (documented); images shipping only `sleep`/`sh` lose it.
- Verify outcomes with huge outputs land whole in the annotation payload — verbatim is the red line; consumers needing truncation do it on their side.
- The CLI (M2 second half) and `lab_*` tools (M3) remain; the CLI will reuse `LabService` over a `child_process`-backed `Exec`, with the release gate consulting `dsh-mission is-releasable`'s 0/1 exit code (the mission CLI's sanctioned script path).

## Testing

`packages/lab/tests/` — `docker.spec.ts` adds checkpoint (init sequence, skip-when-repo, read-only failure) and verify (workspace cwd + pidfile wrapper, verbatim non-zero outcome, material in/out ordering incl. cleanup-after-failure, timeout forwarding). `service.spec.ts` adds checkpoint registration + custom workdir + warn/absent paths, verify's three verbatim shapes + mission-absent warning + empty-command rejection, and archive's manifest content checked against known sha256 digests.
