# Agent Note: 房间成员的模式工具落在房间桌面上

Status: implemented

## Problem

房间里，协调者和成员各跑自己的模式，可以和房间本身不同（开发模式的房间，由写作模式的 Codex 成员协调）。外部成员的模式工具以替身身份在成员**自己的**子会话上执行（local-agent 的 preset tool host）。于是协调者调 `canvas_open` 时，画布开在 CLI 自己的会话里，房间里看不到；focus 也记在那里。用户在房间侧栏切了画布，协调者的 `canvas_write` 仍写旧的那块。而开发模式的房间干脆把画布侧栏入口藏了，因为房间自己的 preset 没有授予画布那一行。

## Decision

规则由用户在 2026-10-29 的对话中逐条确定：

- **工具、提示词、skills 仍只按成员自己的 preset。** 不混入房间或其他成员的模式。这一条本来就成立，没有改动。
- **桌面标记。** room 的 `memberMode` 额外返回 `desk: { sessionId, role, member }`，成员此刻是房间协调者时 role 为 `coordinator`。local-agent 的 `PresetToolHost` 每次 list/call 都在替身上挂 `Symbol.for('dsh.agent.desk')` = `{ session, role, member }`，交接后角色随之变化。房间不在本进程活着、或房间没给桌面时撤掉标记。执行、审批、记录的模式、插件状态都留在成员自己的会话上。
- **画布（试点）。** `src/desk.ts` 读这个标记：
  - 协调者的写入目标是房间会话的画布；成员先用自己选过的，没有再用房间的。
  - 协调者的 `canvas_open` 对**房间**会话做 focus 和绑定；成员的打开留在自己会话。
  - 两者都往房间追加一条只进日志的 `canvas/desk-opened` 事件。
  - 写入和新建画布的围栏仍是成员自己的会话和工作区。
  - 画布客户端认领这条事件（`client/open/desk-row.ts`），在房间里渲染「bill 切到了画布《雨夜》 打开 →」。看着它到达的行（事件 20 秒内、每页一次）会跟随：协调者的打开画布标签页；成员的把画布加进标签栏但**不切过去**，标记为新（`CanvasSelectionStore.addCanvas`，标签上亮一个小点，直到被看过）。这就是方案 A。
- **长篇小说（canvas-novel）。**
  - 小说工具读同一个标记（`src/desk.ts`）：协调者的 `novel_bind` 绑定**房间**会话，并用画布的 `canvas/desk-opened` 事件通知房间（小说就是一块画布，由画布那一行渲染）；成员绑定自己。所有小说工具按画布的方式找作品：协调者用房间的，成员先用自己的，没有再用房间的。
  - 小说工具按 `agent/created` 逐个 agent 授予，而替身从不触发这个事件。所以改之前，写作模式的 CLI 成员只拿到 `novel_bind`，3080 的 `mode-tools.jsonl` 里能看到。现在 local-agent 用带作用域的 `local-agent/stand-in-created` / `-disposed` 事件通知每个替身。小说的授予逻辑跟踪替身，不管有没有绑定都给它三个工具：CLI 启动时只列一次工具，没绑定时调用会说明怎么绑定。
- **侧栏并集。** room 客户端从 store 的成员名单提供 `ctx.roomModes`（`presetsOf`、`subscribe`）。画布的可见性判据加第三条路径：在房间里，任一成员的 preset 授予了画布那一行就显示。用 `ctx.get` 探测，再用延迟的 `ctx.inject(['roomModes'])` 订阅，没有 room 时判据不变。`docs/plugin-visibility.md`「房间桌面」一节把这套规则写给所有插件。

## Alternatives considered

- **把替身的 `session` 直接换成房间会话。** 会往房间追加 `agent-preset/selected`，把房间本身切成成员的模式；各插件的私有状态也会被成员们共用。
- **通用 room 渲染器 + 右栏 `navigation.params`。** "打开指定的那一块"靠各插件自己的客户端状态；导航参数只在 0.2.1 宿主线上有；room 还得认识每个插件的标签栏。所以改成各插件认领自己的事件。
- **侧栏入口一律不按模式区分。** 要撤回 09-17 在约 8 个包上做的可见性改动，每个会话的入口列表都会变长。并集只显示房间成员真能用到的。
- **给替身触发 `agent/created`。** 所有监听这个事件的插件都会把没有模型的替身当成真 agent。替身事件只送到主动监听它的组合入口。
- **每个成员的打开都切前台。** 多个成员并行时，用户正在看的侧栏会被来回抢。用户选了方案 A。

## Consequences

开发模式房间里的写作协调者，现在操作的就是房间正在显示的画布，用户能看到每次切换。成员把画布加在旁边，不抢视图。房间外的会话行为与原来完全一样。

缺口：

- 新标签的小点刷新后会消失；房间时间线那一行仍记录着谁打开了什么。
- 剪辑、游戏、图书馆仍只读自己的会话，是下一批，按 `docs/plugin-visibility.md` 接入。图书馆的附件也要走桌面，房间里发的照片成员才拿得到。

## Testing

- `room`：`memberMode` 给出桌面角色，协调者交接前后都覆盖。
- `local-agent`：替身带上标记、角色会刷新；没有桌面或房间不在时没有标记；执行仍在成员自己的会话上。
- `canvas` 工具：协调者新建画布会 focus 房间并通知房间；协调者写到房间正在显示的画布；成员切换留在自己会话，没选过时回落到房间的画布。
- `canvas-novel`：替身没绑定时也有工具，销毁时撤掉；协调者使用房间的小说。协调者的 `novel_bind` 绑定房间并通知房间；成员绑定自己，绑定之前读房间的小说。
- `local-agent`：每个替身创建时通知一次，销毁时也通知。
- `canvas` 客户端：Definition 和那一行（只跟随一次、成员的放旁边、历史行只给门）；标签栏的 `addCanvas` 和新标记；可见性并集随成员名单变化。
