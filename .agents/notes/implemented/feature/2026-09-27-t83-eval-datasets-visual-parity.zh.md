# Agent Note: 实验室与题集 tab 视觉对齐交互稿 v5（T83）

Status: implemented

## Problem

实验室（eval）和题集（datasets）两个 tab 的版式已经照交互稿 v5（`proposals/prototypes/eval-journey-redesign.html`）改过，见[实验室旅程那份 note](2026-09-26-eval-lab-journey-v5.zh.md)、[设计与结果层级那份 note](2026-09-26-eval-design-result-hierarchy.zh.md) 和[题集层级那份 note](2026-09-26-datasets-tab-v5-hierarchy.zh.md)。但在真机上看，页面仍然像半成品。原因都能具体指出来：

- **按钮。** 宿主 `Button` 默认 `variant="ghost"`。两包一共 83 处 `<Button>`，62 处没写 variant，渲染出来是裸文字，主要、次要、破坏性动作看上去没有区别。
- **版心与字号。** 正文拉满整个 tab 宽（1440 下 1158px）。正文字号 12px，v5 是 13px。
- **token。** 插件 CSS 引用了两个宿主没有定义的 token（`--dsw-alias-bg-l2`、`--dsw-alias-state-danger-label`）。它们解析为空，于是背景透明、颜色继承。
- **场景差距。** 几个场景仍和 v5 不一样：
  - 人工评估表一打开就把所有证据框都展开。
  - 方案估算拿不相干题目的平均值去补缺的题。
  - 题集详情卡片里的文件连成一段、自动换行的等宽文字。
  - 运行记录时间线的圆点全是灰的。

## Decision

### 按钮分变体，承载动作层级

每一处 `<Button>` 都写明 variant，不再依赖宿主默认值。

- **`primary`** 标出这一页要人做的那一个下一步，每页至多一个。
- **`outline` + `sm`** 就是 v5 默认的 `.btn`。宿主 28px 胶囊在视觉上等价，所以不在插件里自造按钮。
- **`danger`** 标破坏性动作。
- **`ghost`** 只留给显式的工具性动作（刷新、返回）。

层级本身就是信息：样式一律相同时，读者分不出哪个按钮是推动实验往前走的。

### 分段控件：每个包各有一份薄实现 `Seg`

- **eval。** `packages/eval/src/client/parts.tsx` 里有 `Seg` / `Seg2`：`radiogroup`，方向键移动。
- **datasets。** 题集 tab 目前还没有用到分段控件的地方。出现时，把 eval 的 `Seg` 照抄一份到自己的 `packages/datasets/src/client/parts.tsx`，同名同形，不 import。

两包永不互相 import（eval / datasets 独立规则）。宿主没有提供分段控件。只为一个约 40 行的组件另建一个共享包，会给两包的每一次安装都加一条跨包依赖。两份小副本是更便宜的约定。

### 人工评估：选定一行后才展开证据框

判官表是紧凑的三列表：判据、判官结论、你的终评（成立 / 不成立的 `Seg`）。

- 只有这一行的终评选定之后，证据框才展开在这一行下面，而且仍然必填。
- 一开始就全部展开，一张 13 条判据的卡片就成了一面空文本框墙。评审最先扫的判据和判官结论之间隔得很远。
- 证据属于某个终评。终评还没有就先要证据，只会招来套话。

### 方案估算只给下限，不外推

`planEstimate`（`packages/eval/src/plan-items.ts`）只对有过往作答的题累加每题均值。

- **覆盖口径。** 一道题要在某个字段（活跃时长、输出 token）上算作覆盖，必须每个对比组都至少有一个样本。只有一个组答过的题按未覆盖处理。
- **显示。**
  - 所有题都覆盖时，合计显示为「≈」。
  - 部分覆盖时显示为「≥」，下面一行写明覆盖了哪几道题、各有几次作答，以及哪些题无估算。
  - 一道都没有覆盖时显示「无估算」。
- **理由。** 之前的版本用已覆盖题的均值去补未覆盖的题。实际效果是拿一道单阶段的占位题去给 L3/L4、四个阶段、跑在容器里的题定价。这样猜出来的数永远偏低，而偏低的数会误导批准运行的人。既定规则是「没有同类运行记录就不猜」。

`plan-items.spec.ts` 钉住这条规则：部分覆盖时只累加覆盖到的题，只有一个组的作答不算。`LabReview.client.spec.tsx` 钉住「≥」文案和部分覆盖的说明行。

### 题集详情：一行一个文件，列表只列最近的

- **文件卡片。** 两张卡片一行一个文件：路径用等宽字，右边小字写大小或标注（「13 条判据」「题集级」）。两张卡顶部对齐、靠 grid 拉伸做到等高；内容多时在卡内滚动（`max-height: 260px`）。
- **用过这道题的实验。** 只列最近 5 个，后面接「等 N 个」，点了展开。
- **作答记录。** 只显示最近 5 组，其余收进「更早的作答记录 · N」。

### 运行记录时间线带状态

每个阶段圆点都带状态：

- 已完成的阶段是宿主成功色的实心点；
- 进行中单元的当前阶段是 business-primary 蓝圈；
- 停下的单元，其最后一个阶段用错误色。

点和上一个点之间用一条细竖线连起来，和 v5 一致。只画这条记录实际走过的阶段。

### 剩余差距表在哪里

分场景的差距表在 `profiles/web-eval/docs/t83-visual-parity.md`：§十一是裁决批，§十二是第四阶段。协调者认可以下几处作为与 v5 的长期差异：

- 满分取真实值，不照 v5 的示例数。
- 面包屑不带版本切换。
- 时间线只画实际走过的阶段。
- 「打开子会话」文案保持不改。

## Alternatives considered

**为什么不改宿主 `Button` 的默认值？** 宿主是跟踪而不修改的。改默认值是一次影响所有插件的宿主级行为变更。在每个调用处写明 variant，也等于在做决定的地方把层级写了下来。

**为什么不通过公共包共享 `Seg`？** 这会造出独立规则正要防止的 eval↔datasets（或 eval / datasets → 新包）依赖边，而这个组件小到可以直接复制。如果宿主将来提供分段控件，两份副本一起退役。

**为什么不把证据框都留着，只折叠成一行？** 折叠的空框仍然夹在判据之间。它们也暗示证据可以先于终评写。

**为什么不按难度级别或阶段数乘一个系数外推？** 没有校准过的系数。任何乘数都是一个新的猜测，只是数字看上去很精确。标明口径的下限是诚实的，而且仍然有用：真实花费至少是这么多。

**为什么不把文件列表用分隔符连起来换行，而要一行一个？** 等宽文字自动换行会把路径从中间截断，也没有地方放每个文件的标注，而标注正是读者要扫的东西。

## Consequences

- **测试数。** eval 1141 个测试通过，datasets 252 个。估算规则、5 条上限、更早作答记录的折叠、停下单元的时间线圆点各有专门的测试。
- **估算文案。** 估算现在可能写成「≥ 9 分钟」，并带一行明确的覆盖说明。在缺的题有过往作答之前，它一直是下限；有了之后，会自动变成「≈」。
- **按钮。** 两包里新写的按钮都必须写明 variant；裸 `<Button>` 渲染出来就是文字。
- **共用控件的改动。** 一旦 datasets 带上自己的副本，改 `Seg` 就要两个 `parts.tsx` 一起改。
- **截图。** 成对截图（实现对 v5，浅色 / 深色 / 400）放在差距文档 §十二 写明的 T83 scratch 截图目录下。
