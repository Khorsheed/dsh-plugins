# Agent Note: mission — generic task management, milestone M1

Status: implemented

English | [中文](2026-08-19-mission-m1.zh.md)

## Problem

The dataseek-eval program (and everyday agent work) needs a generic task manager: batches of work items with a frozen, enforced state machine; deterministic release gates for irreversible resources; re-runs that keep failure history; and one store reachable identically from the host process, model tools, and out-of-process scripts. This is milestone M1 of the [mission proposal](../../../proposals/active/2026-08-19-mission-tasks.md): the store, the declarative state machine with three guards, the template linter, plan data with the five-bucket projection, the `ctx.mission` service face, twelve model tools, and the `dsh-mission` CLI. Slash commands and bundle export are M2; the session tab is M4.

## Decision

Shipped as `packages/mission` (`@khorsheed/dsh-mission`), host-only, skeleton after ankh-guard. One run one `runs/<runId>.json`; `runs/<runId>/data/<missionId>/attempt-<N>/…` is the append-only run-data tree. Every write funnels through `MissionStore.update` (`src/store.ts`): a per-run lock file (hand-rolled `wx`-create carrying `{pid, at}`, reclaimed when the pid is dead or the lock is older than 60 s — no `proper-lockfile` in the dependency tree, and adding one was out of scope), then read → modify → temp-write → atomic-rename. Service, tools, and CLI are three adapters over the one `MissionService` (`src/service.ts`), so in-host and out-of-process writers serialize on the same lock.

The state machine is data frozen into the run at creation (`src/template.ts`): exactly one initial state required; terminal = no out-edge, initial = no in-edge, both derived from transitions only. `transition` rejects anything undeclared (fail loud), executes the declared guard, and appends `history` with the caller (`tool:<sessionId>` / `cli` / `service`). Guards (`src/service.ts` `runGuard`): `file-check` resolves `dir` relative to the attempt's run-data directory with absolute/`..` rejected (no interpolation); `schema-check` validates the recorded submission against a hand-rolled JSON Schema subset validator (`src/schema.ts`: type/required/properties/items/if/then/const/enum/additionalProperties — no ajv); `attested` requires a key registered via `attest`. `submit` validates its JSON payload against every schema-check guard leaving the current state BEFORE writing anything, then appends files, indexes artifacts, records the submission, and registers a NO-REF checkpoint; `addCheckpoint` (service face) fills the `ref` by MERGING into the same-name checkpoint — one moment, one entry.

Lint (`lintTemplate`) reuses existing semantics: with a non-empty `releasableStates`, a guardless transition entering a releasable state is an error (refuses run creation), and a terminal reachable without passing through any releasable state is a warning; schema-check schemas must exist, parse, and stay in the subset. The five-bucket projection (`src/projection.ts`) is pure: done / blocked / scheduled / ready / active from shape + plan data; `dependsOn` and `scheduledAt` never fire anything. `retry` opens a new attempt at the initial state and leaves old attempts immutable. Writes are idempotent (identical transition/annotation/attestation/submission-bytes/artifact/create are no-ops) with `retry` the documented exception.

The built-in `simple` template (`queued → active → done | failed`, **empty** `releasableStates`) backs the zero-config implicit run (`session-<id>`, or `default` from the CLI). The service face adds `setRefs` / `addArtifact` / `addCheckpoint` / `annotate` / `isReleasable` for in-process consumers (lab). Twelve `mission_*` tools register via `defineTool` plus a `tool:mission` system-prompt section; export is deliberately absent from the tool face. The CLI mirrors the semantics with exit codes 0/1/2 (`is-releasable` is 0/1 for teardown scripts). `src/invariant.ts` carries the identity triangle's PACKAGE_NAME and fails on any malformed run file at the default data root.

**The bin entry is a thin module nothing imports** (`src/cli.ts` guard + call only; the implementation lives in `src/cli-core.ts`). tsdown moves any module shared between entries into a chunk; when M2's slash face imported `renderStatus` from `cli.ts`, the direct-invocation guard landed in the chunk, compared the chunk's URL against `argv[1]`, and the published bin silently exited 0 doing nothing — while every source-plane test (imported `runCli`, `tsx src/cli.ts`) stayed green. The guard must be lexically in the entry module, and the built artifact must be smoke-tested (`tests/bin.spec.ts` spawns `node lib/cli.js`: no-args → exit 2 + usage; missing mission → exit 1; a create → annotate → get round trip).

## Alternatives considered

- **YAML templates with a YAML dependency** — rejected for M1: adding a dependency was out of scope for this milestone, so template files are JSON; the document model is identical and YAML can be admitted later without a format change.
- **ajv for the schema-check guard** — rejected: same dependency constraint; the hand-rolled subset validator doubles as the lint-time subset gate, so a schema never silently means less than its author wrote.
- **`releasableStates = terminal states` on the `simple` template** (the proposal's loose phrasing) — rejected: the lint rule would then demand a guard on every `active → done`, making the zero-config implicit run impossible; everyday work items hold no destroyable resources, so `simple` ships an empty list.
- **Submit-time-only schema validation** — rejected: the guard is declared on the transition, so the transition re-validates the recorded submission; submit-time validation is an early failure surface (a violation writes nothing), not a replacement.
- **Duplicate-prevention by checkpoint timestamp** — rejected: timestamps differ across callers; the merge key is the checkpoint name within one attempt, with a conflicting `ref` failing loud.

## Consequences

- The store, engine, service face, tools, and CLI are covered by 48 tests, including a real cross-process race (4 CLI subprocesses + 4 in-process writes on one run file, zero lost writes).
- `retry` is the one non-idempotent write — every call opens a real new attempt; documented in the README.
- The lock is best-effort against pid reuse (worst case: a 10 s lock timeout); the storage layer can move to sqlite without touching the data model.
- M2/M4 (slash, export with the leak gate and expectedNs completeness report, session tab) are designed in the proposal and deliberately absent; the run-status expectedNs report rides with M2's export work.
- `dependsOn` re-blocks not-yet-terminal downstream missions after an upstream retry while their records stay intact — the append-only backfill stance.
- Lesson (latent since M1, surfaced by M2's slash import): **a bin entry must be smoke-tested as a built artifact** — source-plane tests (imported `runCli`, `tsx src/cli.ts`) structurally cannot catch a dead `lib/cli.js`, and a bundler that chunks shared modules silently breaks any entry guard not lexically inside the entry module.

## Testing

`packages/mission/tests/` (48 tests, all fixtures in runtime temp dirs): schema subset validator accept/reject; template validation and lint (guardless releasable entry → error refuses run creation; bypassing terminal → warning); every undeclared transition rejected, declared path + history + idempotent repeat; guard determinism (file-check relative resolution incl. absolute/`..` rejection, schema-check submit-first + transition revalidation, attested); five buckets on the simple and an arbitrary multi-terminal shape; dependsOn blocked→ready; scheduledAt; the ods→dwd→dws→app chain with upstream retry preserving downstream records; ns isolation + append-only + attempt-tagged annotations; attempt/checkpoint separation incl. the submit/addCheckpoint merge; idempotent writes; ambiguous-id disambiguation; the cordis-mounted service face end to end; CLI exit codes (is-releasable 0/1, lint, usage); run-status table output; lock serialization in-process and across CLI subprocesses; the invariant companion's malformed-run report. `tests/bin.spec.ts` (added with the cli-core split) smoke-tests the BUILT bin — `node lib/cli.js` with no arguments exits 2 with usage, `is-releasable` on a missing mission exits 1, and a create → annotate → get round trip works; it skips with an explicit note when lib/ is absent (fresh checkout).
