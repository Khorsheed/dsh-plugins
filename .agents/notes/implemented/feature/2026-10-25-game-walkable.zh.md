# Agent Note: walkable models and groundAt

Status: implemented

## Problem

dsh3d 只从地形的高度函数取地面高度。3D 村子里有楼梯、平台、桥和屋顶，角色一样也站不上去。游戏可以对自己的网格做射线检测，所以这属于便利，而不是一堵墙（见[边界说明](../architecture/2026-10-25-game-plugin-boundary.zh.md)）。但几乎每个有建筑的 3D 游戏都需要它，而且射线很容易打错：从很高的地方往下打，会落在屋顶上而不是地板上。

## Decision

- `world.walkable(object, on = true)` 和 `world.add(object, { walkable: true })` 把一个模型算作地面。标记时会更新它的世界矩阵；在场景里标记的，离开场景时会被忘掉。
- `world.groundAt(x, z, fromY = Infinity)` 从 `fromY` 往正下方打一条射线，打在可行走模型和地形网格上（描边外壳不参与）。它返回 `fromY` 及以下最高的命中点，没有命中就退回高度函数。角色传入「脚底高度 + 台阶高度」，就能一级级上台阶，又不会被吸到头顶的屋顶上。不传 `fromY` 时取最高的面，游戏可以用它判断前面是不是墙。
- 技能文档写了走路的用法，并说明它只管站立，不管碰撞和坡度限制。

## Alternatives considered

**默认把所有实体都当作可行走。** 那样角色和道具会互相成为对方脚下的地面。显式标记清楚，开销也小。

**做一层碰撞和物理**（墙、坡、胶囊体）。那是物理库的工作，游戏可以自己引入，插件不该假装自己是物理引擎。

**用包围盒推算高度。** 更省，但对做成一个整体网格的楼梯、坡道和屋顶都不对。射线看的是真实的表面。

## Consequences

- 移动平台的矩阵是上一次推进或渲染时的结果，所以站在上面的角色最多落后一帧。
- 每次调用 `groundAt` 都会对所有可行走模型打一次射线。可行走模型多达几百个的村子，应该按场景分组，而场景本来就是这样分的。
