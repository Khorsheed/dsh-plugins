# Agent Note: 章节想法进入普通请求，真实写入后归档

Status: implemented

## Problem

读者通读章节时会发现情绪转折生硬、规则解释太满或伏笔说得过早，但逐段复制到对话会打断阅读。评论也不一定要求精确替换选区，很多时候只是希望 Agent 重新考虑整章；逐条生成局部补丁会额外制造候选正文和版本链。

## Decision

- 章节阅读器提供轻量评论浮层和页内想法区，不新增应用侧栏。划选保存完整原文、原始位置、上下文、正文指纹和想法；整章想法无需引用。安装「引用任意内容」时通过 `quoteActions` 复用划选菜单，未安装时章节页提供自己的记录入口。
- 当前想法可删除并撤销。批次存入作品现有小说状态目录下的 `chapter-feedback.json`，每次写入沿用调用会话的围栏和存储版本保护，不与跨章节「灵感」素材库混用。
- 「填入对话」只把可编辑纯文本追加到宿主会话输入框并聚焦，保留已有内容，不自动发送，也不在请求里塞 JSON 或隐藏批次标记。每条引用原文与想法一起携带，并明确不要求只改选区。未修改的插件草稿可在收回时还原；用户改过的输入内容不会被删除。
- 归档必须同时满足：最终 composer 草稿确实进入本轮、同一会话成功写入同一章节、轮次正常结束。浏览器订阅官方输入状态并提交最后一个非空草稿作为候选，`agent/pre-step` 记录真实轮次文本。存储保留有界的轮次文本、写入回执和结束结果，因此候选即使在工具写入或轮次结束后才到达，也能精确核对。无法匹配的草稿始终可收回；无关消息、其他会话和其他章节不能归档本批。
- 批次记录准备时的正文指纹，之后发生冲突会以 `stale` 拒绝写入。只讨论、取消、报错和冲突都保留想法，不归档。完成操作幂等，新想法进入下一批。章节标记为 `byUser` 不排除 Agent 改写，只有 `byPerson` 的面板手动编辑不计入完成。
- 归档只保留想法、原文、实际发送文本和结构化写入回执，不保存候选正文、不伪造版本号，也不解析助手回答来猜完成。找不到原位置时仍可读旧原文；重复原文只有在位置或上下文能唯一确认时才重新高亮。

## Alternatives considered

- **逐条局部补丁与候选版本。** 否决：用户是在整理普通写作请求的方向，不是在审批精确的局部替换，保存每个正文中间态没有帮助。
- **隐藏批次 ID 或自动调用模型。** 否决：composer 必须是普通可编辑请求，是否发送由用户决定；批次关联使用真实轮次文本，而不是隐藏标记。
- **轮次结束或任一章节写入就归档。** 否决：两者都会误归档。会话、轮次、最终草稿和章节写入必须一致，证据不足时保守保留。
- **把评论系统移入引用插件，或替换现有「灵感」页。** 否决：引用插件负责划选与引用，小说负责章节定位、批次和写作完成；素材库与本章修改想法用途不同。
- **修改上游宿主。** 不需要：官方会话输入机、引用动作注册表、agent pre-step 和 turn-stopping 已能覆盖这条链路。

## Consequences

- 无法关联真实发送的批次可能保持待处理，等待用户收回；这是刻意选择，证据不确定就不自动归档。
- 每个会话、作品、章节同时只允许一个开放批次；处理中记录的新想法进入下一批。
- 普通画布卡片评论保持不变，本轮只覆盖小说章节正文。
- 归档原文是快照，不保证当前正文仍有这句话；位置缺失或有歧义时显示快照，不错误高亮。
- 正文先写入、候选后到达时，只有最终草稿与真实轮次文本一致才认领本轮写入；否则仍不归档，并可收回。

## Validation

- 存储生命周期测试覆盖编辑后的请求、正常与迟到候选、无关消息、未发送草稿、跨章写入、版本冲突、中断、删除撤销、幂等归档和下一批。
- 纯函数测试覆盖持久化归一化、完整请求文本、重复原文定位与原始段落 offset；DOM 选区测试覆盖高亮节点和跨段选择。
- 组件测试覆盖整章评论、只填入不发送、无 composer 回滚，以及归档原文和实际请求；现有小说测试补齐新 Remote mock 后保持通过。
