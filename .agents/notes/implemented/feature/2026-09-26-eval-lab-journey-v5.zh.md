# Agent Note: eval — 实验列表、运行记录、人工评估与作答视图对齐交互稿 v5（T80c）

Status: implemented

## Problem

T79 收口走查在真机上把实验室的各页和交互稿 v5（`proposals/prototypes/eval-journey-redesign.html`）逐页对照，发现四个面有同一个毛病：页面摆的是账本知道什么，而不是人来这一页要做什么。

- **列表**
  - 每行都是同样两个按钮，看不出这个实验下一步该做什么。
  - 21 条没有实验认领的旧运行挤在「需要你处理」，没有一步清掉的办法。
  - 一行可以同时写着「评估中」和进度 0/1，因为状态规则和进度计数读的是两套不同的状态集合（P1-3）。
- **运行记录**
  - 只有一个格子的试点先画网格，又把同一个格子在列表里再列一遍。
  - 状态词是模板内部状态「已释放」。
  - 汇总开头就是「未释放单元」「卡住的记录」。
- **人工评估**
  - 页面一打开是空的「先选一道题」面板。
  - 队列上方压着一块全是「—」的试点一致性数字。
  - 判官缺席只是一行灰字。
  - 有一条评分提示按纯文本渲染，`**` 原样露出。
- **作答视图**
  - 400px 宽时第二份作答只在右边露出一条边。
  - 判官没判到的一侧，每条判据都重复一遍「这条判据未判」。

## Decision

### 状态口径（P1-3）

- `JUDGED_OR_BEYOND` = {judged, halted, archived, releasable, released}，放在没有任何 import 的 `packages/eval/src/cell-states.ts`，宿主和浏览器包读同一个文件。
- `progress.done` 恰好数这个集合。状态规则本来就在这个集合上切到「评估中」，所以「评估中」现在总是和 done = total 同时出现。
- `eval_run_status` 也报 `progress`，agent 引用的数字和列表上的一致。
- 运行记录卡片恰好对这个集合说「完成」（`vocab.ts` 的 `recordPhrase`）。

### 列表（P1-1、P1-2）

- 每行做成卡片：名字、问题原文、规模（题 × 组 × 次），外加按状态选出的**一个**主按钮。
  - 对照表是 `client/journey.ts` 的 `ROW_ACTIONS` / `rowAction`：草稿 → 去校验，待批准 → 去批准，停滞 → 重跑，评估中 → 去人工评估，完成 → 看结论，被拒 → 看原因，运行中 / 已取消 / 评估不成立 → 看运行记录。
  - 没有实验认领的停滞运行、或已归档的停滞运行，回落到「看运行记录」：已经没有可以再批准一次的方案。
- 「归档 / 取消归档」收进卡片上的 ⋯ 菜单。
- `legacyInAttention` 找到旧运行时，「需要你处理」的标题行出现「归档 N 条旧运行」。
  - 点开是行内确认，写明这一步只改分组、可以撤销。
  - 确认后逐条归档，部分被拒时如实报数。

### 阶段外壳（P2-1、P2-9、P2-11）

- 每个阶段 tab 带一个点（`stageDots`）。状态写在 `data-dot` 和 tab 的 title 里，点本身 `aria-hidden`，tab 的可访问名仍然只是阶段名。
- 阶段条从不给出指向所在页的按钮，改成一句「下面逐个落地」/「逐份评完，再在页底选这次评估怎么结束」/「对比就在下面」。

### 运行记录（P1-7）

- 格子数 ≤ 12（`CARDS_MAX`）时，页面就是一组卡片，不画网格也不出列表。
  - 每张卡片写组名、状态词（`recordPhrase` / `recordTone`）、题 · 第 N 次和用时。
  - 点一下，在卡片下方就地展开阶段时间线和「看作答」。
- 更大的运行保留网格、筛选和列表，用的是同一个状态词。
- 用时是 `attemptElapsedMs`（宿主侧，`read.ts` → `EvalCellRow.elapsedMs`）：从这次尝试进入的第一个状态，到它第一次进入已判或其后的状态；还在走的就算到现在。
- 本次实验汇总改成「实验卫生」，是一个 `<details>`，摘要行写「题面一致 · 环境一致 · 未释放单元 · 停滞」。
  - 有不变量被破坏时自己展开，否则保持折叠。

### 人工评估（P1-6、P1-9）

- **落题。** 页面打开时落在 `landingItem`：第一道还有未评作答的题，没有就落在第一道。
  - 每次进入只落一次，而且只在没有选中（或选中的题这次运行里没有）时落。
  - 之后打开哪道题由评分的人决定，提交也不会让页面跳走。
- **判官缺席**做成提醒卡（`role="note"`）：写出盲评编号，说明人的终评照常记录，附「补判（可选）」，从不拦路。
- **评分者一致性**放到四个出口下面，默认折叠的 `<details>`。
  - 既没有判官重复采样、也没有跨判官或初评对终评可对照时，摘要行写「数据不足：…」。
  - 否则摘要行给出三组一致率，自评判据另加一个警示 chip。
- **标记。** `judge.scoringMix`、`judge.regrade`、`record.scoreMixed` 去掉 `**`：三处都按纯文本渲染。

### 作答视图（P1-10、P2-10）

- **窄窗格。** 每个网格格子带 `--col: <列序号>`。
  - 视图上的容器查询（< 700px）把网格退成一列，`order: var(--col)` 把每一列的各部分收回到它自己的表头下。
  - 用容器查询，是因为视图放在会话窗格里，窗格宽度不等于窗口宽度。
- **没判到的一侧。** 一列如果没有任何判官或人工判定（来源为 `script` 或 `none`），只在它第一条未判判据处说一次：「只有脚本判定：判官没有判这份作答（N 条判据未判）」，或者 `none` 对应的那句。
  - 所在的面传了 `onRejudge` 时，这一行附「补判」。
  - 该列后面的未判行是空的 `data-quiet` 格子，保证其他列的判据仍然对齐；上下排时隐藏。
  - 人工评估面交给 agent 的是盲评编号，命名入口交给 agent 的是组名和次数。

## Alternatives considered

**用 mission 的 `done` 桶当进度分子。** 列表原本用的就是它。它不含 `halted`，而对编排器来说 halted 的格子已经结束了；「评估中」和 0/1 同屏正是这么来的。两个必须一致的集合，就该是同一个集合。

**小运行保留网格、只去掉列表。** 对试点来说，1 × 1 的网格是一个非点不可才开口的点。卡片保留同样的点击，还多了状态词、第几次和用时。阈值 12 是 T79 走查定的（P1-7）；超过它，一页卡片比网格还长，这时网格才是更好的全景。

**卡片上显示 `inStateMs`。** 它从最后一次状态迁移算起，所以已释放的格子会显示「两天」，那其实是运行结束到现在的时间（W4）。用时停在第一个完成状态，因为判官判分、归档、释放都不是这个格子在跑的时间。

**原地把「未释放单元 / 卡住的记录」改成人话，不折叠。** 它们是卫生不变量，人只在某一条被破坏时才需要看，那时折叠会自己打开。换成人话但仍放在顶部，就是每次来都把卡片往下推，只为了说一句「一切正常」。

**每次渲染都自动落题（选中项由推导得出，不存）。** 评分的人一提交当前题的最后一份作答，下一道未评题就会顶替屏幕上的这道，而人还在读。一次性落题给出同样的首屏，之后也不会把页面抢走。

**用 MarkdownDoc 渲染 `judge.scoringMix`。** 文案两种修法都允许。加粗表达的意思句子本身已经说清楚了，而三条纯文本文案要各接一个 markdown 渲染器，只为一段加粗。去掉标记，三处一次修好。

**作答视图用媒体查询上下排。** 视图在会话窗格里。窗口宽、窗格窄的时候，媒体查询会让 400px 的窗格仍然左右并排，这恰恰就是要修的问题。

**让仅脚本的说明跨越该列所有判据行（`grid-row: span N`）。** 只有未判行连续时，自动排布才会放对。中间某条判据上有一条脚本判定就会断开，这时跨行会把其他列的格子挤出对齐。空的静默格子没有代价，也不会放错。

## Consequences

- 列表、运行记录卡片、网格圆点和 agent 的 `eval_run_status`，每个状态只有一个状态词。「什么算完成」的改动只需在 `cell-states.ts` 改一行，四处一起动。
- 试点的运行记录页现在是几张卡片加一行折叠，网格只在有用时出现。
- 人工评估的首屏就是评分表。一致性数字在页尾，点一下就到；表格里的一排「—」换成了一句「数据不足」。
- 作答视图在窄窗格里从上往下读。代价是 `grid-template-columns` 上的 `!important`（为了盖过内联的列数），以及每个格子都带一个 style 属性。
- 补判仍然是交给 agent 的一句话，不是一个动作。没有补判工具，页面也不会因此得知盲评编号对应哪些组。
