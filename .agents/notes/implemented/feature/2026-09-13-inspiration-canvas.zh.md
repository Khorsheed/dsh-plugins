# Agent Note: 灵感画布 —— 一块模型能读到的工作区级稿纸

Status: implemented

## Problem

用 harness 写作的人需要一块地方放第一版或者一堆碎片，然后需要一条让模型读到它的路径。聊天输入框是错误的位置：写在那里的草稿埋在对话流里，没有名字、没有版本，而且之后每一轮都会被重发。现成的面也都不覆盖它——官方工作区文件树和 `@khorsheed/dsh-local-files` 都是**只读浏览器**，而让模型去写文件意味着动手的不是作者本人。

宿主的三个事实决定了答案的形状，全部在设计定稿前实测过：

1. `ctx.fs.writeText(target, content, expected?)` 本身**已经带守卫写入**（`{ kind: 'createIfAbsent' }` / `{ kind: 'replaceIfVersion' }`），返回值带 `before`/`after` 作为 diff 基准，而 `writeFileAtomic` 会递归创建父目录。新建、重名拒绝、陈旧写入保护都不需要新机制。
2. **官方没有任何删文件的路由**：`FileSystem` 的 13 个抽象方法里没有 `remove`/`rename`；`workspace-controller` 的 `@Remote('delete')` 删的是**工作区注册**（保留文件）；`SandboxedFileSystem` 只给 `writeText`/`editText` 加围栏——所以裸 `node:fs.rm` 是**绕过沙箱围栏**，而不只是少一个通知。
3. 模型的 `read` 工具**不受沙箱限制**（`tool-fs` 只把沙箱控制器交给 `applyWriteTool`/`applyEditTool`），所以绝对路径可以跨工作区读；而写回别的工作区会被围栏拦下。

## Decision

**稿纸就是工作区里的一个纯 markdown 文档目录，插件只是它上面的一层列表 + 写作面。** `<工作区>/灵感画布/` 下放 `文章/<标题>.md` 与 `卡片/<标题>.md`——**子目录即 kind，文件名即标题**。用可见的中文目录名是刻意的：使用者是写作者不是工程师，隐藏的 `.dsh/` 路径在他们眼里等于"我的文件不见了"。

`<工作区>/灵感画布/.index.json` 存 `{ order, archivedIds }`——和官方 workspace registry 用 `workspaceIds` + `archivedSessionIds` 表达的是同两件事。索引缺失或损坏时降级为按文件名排序、无归档项，绝不因此打不开稿纸。注意 `ctx.fs` 不上报 mtime，所以排序依据是索引而不是时间戳。

宿主半边是 `CanvasService`（核心）加 `CanvasRemoteService`（Typert Remote，namespace `canvas`），暴露 `list` / `read` / `create` / `write` / `setArchived`。调用是纯 JSON、绝对工作区根 + 稿纸相对名，**不做会话查找**（local-files 的惯例）。每次写入都走挂载的 `ctx.fs`。

**归档取代删除。** `setArchived` 只切换 `archivedIds` 里的成员资格，**从不碰文件**——这是官方会话归档的语义（"从分组面隐藏"），也是唯一留在宿主 seam 之内的形状。

客户端半边挂 Remote，注册一个页型 `sidebar.right.pane.tab` 并带 `guide` 卡片（当它是某个 pane 唯一的页面类型时，官方注册表会直接进入它），在列表旁边渲染编辑 / 预览 / 并排。

**编辑器的三条不变式，每条都是承重的。** `<textarea>` 非受控、用 load token 作 `key`，所以状态回流永不写回 `value`，保存时光标不可能跳；输入法组合是保存与预览的**硬停**，候选窗不会被从词中间拆掉；textarea 外层容器不滚动，因此**只有一个滚动容器**（两层嵌套滚动是首个原型可见的 bug）。

**粘贴表格会转成表格。** `paste-table.ts` 先试 `text/html` 里的 `<table>`，再试制表符分隔的纯文本，**含糊的一律拒绝**，普通段落因此原样粘贴。只抠表格，绝不转换周边文档。插入用 `document.execCommand('insertText')`，因为赋值 `value` 会清掉浏览器原生撤销栈。空格对齐的表格另有显式的「选中转表格」动作——任何启发式都不敢声称那个可靠。

**复制给的是绝对路径，状态栏显示相对路径。** 使用者会从**别的会话、常常是别的工作区**引用草稿，相对路径在那里解析不到；而留在屏幕上的用相对拼写更好读。

v1 **不注册任何模型可见工具、不向提示词注入任何东西**：约定是使用者自己复制路径。

## Alternatives considered

**用一个 `cards.md` 聚合而不是一条目一文件。** 单一 append-only 的灵感流对 vim 和 grep 友好，也不需要逐条寻址。它输在：引用单张卡就需要一个 markdown 分块解析器，而卡片无法被独立 diff、独立版本化、独立读取——宿主的守卫写入与 diff 机制都是按文件给的，稿纸应该继承它而不是自己重新推导一遍。

**富文本（Lexical）而不是 markdown textarea。** 官方输入框本来就依赖 Lexical，这套栈在这个客户端里被验证过。它输在：稿纸的正本是使用者的纯 markdown 文件，富文本要么放弃这一点，要么每次载入/保存都付一次 dom↔md 转换的代价——而转换损耗恰恰是"文件是唯一真相"承担不起的。

**隐藏目录 `.dsh/canvas/` 而不是可见的中文目录。** 隐藏能让工作区整洁，也避开 `git status` 的转义噪音。它输给目标用户：找不到自己稿子的写作者，比一个显示转义路径的仓库更糟；何况稿子本来就该能用别的软件打开。

**用 `node:fs` 删除（可选地手动查 `ctx.sandboxPolicy.resolve`）。** 这条被详细设计过——向策略服务要解析后的模式、`read-only` 时拒绝、用 `ctx.fs.contains` 验包含，然后 unlink——它能给出真正的删除。它输在：这等于把宿主在别处画的**安全边界**重新实现一遍，而且在只读部署下依然会成功；也因为写作场景真正想要的是归档，而宿主已经为会话建模了它（可恢复，而且文件本来就是使用者自己的）。

**用官方 `workspaceFiles` Remote 读取以省掉自己的读路径。** 能少一个方法。它输在：那个 API 的文本是带行上限的分页，整文件读取返回的是 base64 字节；而 typert 链路无论如何都要有（写方法需要它），所以省下来的只是一个适配层。

**剪贴板给相对路径。** 最初为可读性选了它，随后推翻：复制动作的意义就是把草稿交给**可能在另一个工作区**的会话，而相对路径在那里解析不到任何东西。

**把全局「新建灵感」放进 `sidebar.footer.action`。** 那是官方 root 级动作位，任何界面都够得着。它输在：新建的是**稿纸里的一条**，属于它出现在其中的那个列表——而列表自己的头部就是写作者会找它的地方。若日后确实需要全局入口，那个位置仍然可用。

**用 `turndown` + `@joplin/turndown-plugin-gfm` 处理 HTML 粘贴。** 生态里已经有这一对（在宿主的 `web/tool-web` 里）。它输在：对电子表格的剪贴板 HTML 做整篇转换会把整张表和它的样式一起拖进来；只抠 `<table>` 既更小也更准，而标题、粗体这类更富的元素本就被明确划在 v1 范围之外。

## Consequences

稿纸白白继承了宿主的写入保证：原子写、递归建目录、沙箱围栏，以及陈旧写入时的 `FS_STALE_VERSION`——最后这一条正是阻止"别处改过的草稿被静默覆盖"的东西。

代价同样真实。**没有删除**，所以彻底移除一份草稿要靠使用者自己的文件管理器——这是宿主没有该 seam 的诚实后果，写进了包 README 而不是糊过去。**外部编辑的文件永远不会被告知**：`workspaceFiles.changes` 只报被插桩的文件系统操作、不观察操作系统，所以版本守卫是唯一的发现路径。**跨工作区引用是只读的**——模型能从工作区 B 读工作区 A 的草稿，但写不回去。**列表顺序归索引所有**，因为 `ctx.fs` 不暴露 mtime，从外部丢进稿纸的文件因此按名字而不是按新旧排序。**HTML 表格的合并单元格降级**为文本加空格子。

`packages/canvas` 是第一个小说领域插件，正是 `dsh-novel` 整合包与 mode-switcher 提案的写作 preset 所等的那个。它 provide 了服务，因此不符合那个提案的会话插件化判据；预期的接入形态是它 M2 负责的"全局常驻 + 自隐"路线。

包自身的测试是 53 例，覆盖纯词汇表、针对内存 `ctx.fs` 的服务核心，以及剪贴板转换器；仓库的独立性与卫生、包地图、构建脚本检查全绿。`pnpm gate` 目前停在 `packages/datasets` 的一个**既有红**上（`tests/worktree.spec.ts` 的跨进程受管 worktree 用例），它在 `main` 上原样复现，与本包无关。
