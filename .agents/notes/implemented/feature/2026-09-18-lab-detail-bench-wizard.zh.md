# Agent Note：一条记录、几根柱子、并排的作答，以及四步取代二十个问题

Status: implemented

[English](2026-09-18-lab-detail-bench-wizard.md) | 中文

## 问题

用户走查实验室 tab 的后半，也是 T67 的第二个里程碑。四个阶段立起来之后（里程碑一），阶段里面这四样仍是「投影给什么就摆什么」：

- **格子抽屉**摆着 mission id、`archive/workspace (archive)`、一串注解命名空间和一份 JSON 收据，读的人得自己推断这格到底成没成、时间花在哪儿。
- **结果对比**是一堆表。四条有效性校验各有标题和各自的事实，但看见一个 ⚠ 的人无从知道它让自己损失了什么。每组三个效率数字排成一行digits。
- **判官台**让人点「格子 1」，再点「格子 2」，还得把第一格记在脑子里——同一把尺就是这样在第一份和最后一份之间走形的。
- **新建实验**是一张一次问二十个问题的裸表，没有顺序，也不知道还剩多少。

## 决定

**运行记录详情按提问的顺序答三个问题。** 头部：这条记录带的判定，以及「成功 / 异常」——后者是**账本**说的，不是评价（`halted` 是唯一说「停了」而非「跑完了」的状态）。然后阶段时间轴，然后参数配置，然后附件。只需要读一次的收据——历次尝试、检查点、注解 ns——折起来；verify 输出照旧原样，因为「没人翻译过的退出码」正是这个面板被打开的全部理由。

**时间轴是量出来的，不是讲出来的。** 一个状态从进入它的那次转移开始，到离开它的那次结束，所以**最后一个状态没有时长**——跑到「现在」会让面板报一个账本从没记过的数，而且每次渲染都重报一次。中间少记一次转移就两边都断开，而不是跨着空洞量。

**产物有名字，也对自己做不到的事诚实。** `kind` 变成人话（题面物化 / 归档工作区 / 判定记录 / 阶段提交 / 评测日志），路径挪到悬停，底下一句话说清楚：预览和下载要宿主的文件服务，这个 tab 还没有。文案本来就把「下载」记成不做；预览要的是同一样东西，所以并排记下来，不做假的。

**每条有效性校验在悬停里说清「为什么影响比较」。** 那句话按不变量 id 是常量，所以它是**文案**不是数据——该进词典，那里才有两种语言（宿主端一个中文字符串给不了英文）。旁边的 `details` 还是原来那个：这次 run 自己的事实，从 bundle 来。

**效率柱状图在自己那一项里归一。** 活跃时长、输出 token、cache read 没有公度，一把共用的尺子就是给谎话配一张图；每组按自己那一项的最大值归一，数字仍在柱子旁边，某一项谁都没量到就写一句话、不画空轨道。CSS + 宿主 tokens——为每组三个数引一个图表库不值当。

**判官台按题排队，把同题的各份作答并排铺开**——去指纹、按 run 自己的种子顺序编号，每列一份完整的判据表和自己的按钮。**这不是二选一**：判定契约一个字没动（每格一份分数，按它自己的判据写），并排改变的是判官**看得见**什么，不是账本收到什么。在途答案改成按 ticket 存，一份提交只清它自己那一列；每个证据输入框的标签带上作答编号。

**新建实验改成四步**：① 题库与题目 ② 对比组 ③ 判官、次数、阶段与预算 ④ 环境与确认。每步都能回退，回退不丢答案，只有最后一步的动作会写。启动仍然不在向导上（R1）。

## 影响

- `packages/eval` 843 → 850 条测试；`tsc -b --noEmit` 干净；gate 绿。
- **文案允许加的两处数据面字段，一处都没用上。** `EvalCellAttempt.history` 本来就逐条带 `{from, to, at}`，时间轴用抽屉今天已经拿到的东西就能算；那句不变量解释是文案，进了词典。两个里程碑都没碰投影。
- `judgeTicket` 改成 `judgeTask`，`judgeDraft` 多一层 ticket——并排打分需要的那处 store 改动。`openJudgeCell` → `openJudgeTask`，提交时的整体清空换成 `clearJudgeDraft(ticket)`。
- **又有 15 个词典键**随抽屉和单格判官台一起死了（`drawer.title`、`drawer.refs`、`judge.cell`、`judge.submit`、`judge.filterTask`……）。T67 之前就没人引用的那八个仍然没动。
- **仍然没做、已记下**：运行记录与网格里的**得分数值**（里程碑一的 Note 写了为什么它不该在客户端算）；产物预览与下载（都要宿主的文件服务）；「绑定题库」按钮弹出题集 tab 那张导入表（eval 的 Remote 没有 bind 动词，宿主也没有切 tab 的口子）。

## 测试

`packages/eval` 里 `pnpm test` 与 `tsc -b --noEmit`，然后 `pnpm gate`。两个新的纯函数直接钉住：`timelineOf` 钉四种情况（能量的段、最后一态没有时长、少记一次转移就两边断开、没有 history 就没有时间轴），`byItem` 钉分组**以及**组内绝不重排——种子顺序是盲的一部分。客户端用例断言的是新形状而不是旧字段：记录面板的头部 / 时间轴 / 参数表 / 人话产物，柱子的按项归一（100% 与 71%，都是夹具自己的数算出来的），四条按 id 的悬停，同题作答并排且草稿与按钮各归各列，以及向导四步——包括「上一步」不丢已经填的东西。

## 其它方案

### 为什么不给三项效率指标用一把共用的尺子？

因为三项分别是毫秒、生成的 token、从缓存读的 token。柱状图的全部主张就是「这些长度可比」，跨这三种单位不成立——最长那根只会是原始量级最大的那一项，对这三项来说永远是 cache read。按项归一让每一组只回答一个诚实的问题（「哪一组花的时间最多」），图说不了的，旁边的数字全都说了。

### 判官台为什么是选一道题，而不是把全 run 的格子都摊开？

一个 run 是「题 × 对比组 × 次」，把全 run 摊开只是换了个形状的数据倾倒——而且会毁掉这个布局存在的理由：**不同题**的作答之间没有什么可对着读的。题是 rubric 作用的单位，所以也是判官能用一把尺盖住的单位。同一组的各次作答也各占一列，这是对的：一次 rep 就是对同一个问题的另一份独立作答，本来就该各自打分。

### 为什么每列一个提交按钮，而不是整题一个？

因为写入本来就是按格的。一个按钮要么在一次点击背后发好几个 `humanFinal`——第三个被拒时说什么都不合适——要么就是在暗示这四份判定是一个动作。它们不是：判官可能对两份很有把握，而想再看看第三份。每列一个按钮也让禁用状态可读：它说的是**哪一份**还没写证据。
