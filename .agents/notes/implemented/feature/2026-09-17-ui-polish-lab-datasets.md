# Agent Note: the lab and datasets tabs, read as one design — a word table, condition columns, and honest folds

Status: implemented

English | [中文](2026-09-17-ui-polish-lab-datasets.zh.md)

## Problem

Six sub-pages of the 实验室 tab and two of the 题集 tab were built by different slices, each one correct on its own and none of them looking at the others. The user's verdict after a walkthrough was 「可读性低、设计感弱、体验差」, and the four things they pointed at all have the same shape: a page rendering an INTERNAL value as if it were copy.

- The matrix's column headings were factor VALUES, and a factor value can be a JSON array — `["DEEPSEEK_API_KEY","DSH_HOME"]` was a column heading on a real run.
- The matrix offered every differing key of the condition documents as an equal factor, so `unit.scopedHome.var` and a 64-hex `home.sha` sat in the filter row beside 「model」. A run that varied one thing had five filter rows.
- A cell's stage read `mixed (archived / ws-ready)`: mission's English tokens, glued with English punctuation, in a Chinese interface.
- The report page printed the host's English refusal sentences and absolute paths directly, and the overview printed `run.meta` and the readiness records as raw JSON blocks.

ui-spec §九 was written for exactly this and fixes the rules. This pass applies them to both tabs end to end. The constraint the task set: presentation and copy only — no functional change, no data-plane change, and anything missing from the data plane gets recorded rather than added.

## Decision

**One word table, two copies.** `src/client/vocab.ts` in each package maps every internal token a page can show — ledger stage, mission bucket, retry category, condition leaf path — to one dictionary key, with zh and en entries for each. Every lookup is TOTAL: a token the table has never seen returns a word (「未知阶段（{token}）」) and the caller keeps the raw token on the element's `title`, so nothing renders as a bare key and nothing a person needs to grep the ledger with is lost. Stage names are generated by manifest position (`stage-<n>`, `src/template.ts`), so they are not a closed union — the first six have their own words and anything past them takes a parameterized key rather than a fabricated numeral. The 题集 copy is the same file minus the factor half, duplicated by hand because a client bundle never imports a sibling plugin (§八), the way `ErrorState` already is.

**A cell's stage is computed, not parsed.** `pivotMatrix` composes `mixed (a / b)` host-side. Rather than take that string apart to translate it — which breaks the first time the host rewords it — the page reads `cell.reps[].state` and composes its own phrase. The host string is simply not rendered.

**The matrix column is the condition.** ui-spec §九: the heading is the condition id, the factor value is its subtitle. The pivot did not change; `EvalMatrixColumn.conditions` already said which conditions a column carries, and only the heading and the subtitle swapped sides. A column with several conditions names them all, which is the fact the old rendering buried.

**Designed factors and derived ones are different kinds.** `conditionFactors` is honest and makes no claim about intent — it reports every leaf the declarations disagree on, and that is right. But `unit.scopedHome.var` is dictated by the harness, `env.keys` follows from it, and `home.sha` is whatever the provisioned home hashes to: a reader cannot hold one of those fixed while varying another, so none of them can be a control. `NAMED_FACTORS` is the six ui-spec §九 names (in its order) plus the four other fields the 新建实验 form can mint; everything else is reported in one folded line under the matrix, named and with its values, and is never a chip. A single designed factor therefore has NO filter row, and with more than one the column / band / pin controls live in one disclosure, closed.

**The default column is chosen by the browser half.** Given no `column`, the pivot takes `factors[0]`, and `conditionFactors` sorts alphabetically — which is precisely why `env.keys` became a heading. Teaching the pivot a preference would put a UI opinion in a pure function that three faces share, so instead the matrix effect corrects the arrangement once, on the first answer: if the reader has not chosen a column and the host's pick is not `preferredColumn(factors)`, it asks again for the right one. Naming the column puts `matrixColumn` past null, so the branch cannot run twice.

**One set of components across both tabs.** `Chip` (five tones), `EmptyState` (title + next step + its own action), `Section`, `Detail` and the `Word` renderer, with byte-identical stylesheet rules under identical class names in both packages. A chip's fill is `color-mix(in srgb, currentColor 12%, transparent)`, so it follows its tone and light/dark have exactly one source of truth: the host's tokens. Nothing in either stylesheet invents a colour or a font size.

**Four of the design tokens did not exist.** ui-spec §九 opens with 「沿用宙主的设计 tokens」 and names `--dsw-alias-bg-l2` as an example — and the host theme package defines no such alias, nor `--dsw-alias-label-warning`, `--dsw-alias-label-danger`, `--dsw-font-family-mono`, `--dsw-alias-fill-hover`, `--dsw-alias-fill-selected` or `--dsw-alias-state-success`. Each use failed in one of two ways: with a fallback it froze to a literal colour that cannot follow the theme (`#b8600a` amber, `#b3261e` red, 4% black), and without one it resolved to nothing — which is why every notice, note, `<pre>`, error seat and stuck-cell tint had NO background in either theme. They are now the aliases the theme actually defines: `interactive-bg-hover` for a quiet surface and a hover, `interactive-bg-active` for a selection (hover is a hint, selection is a state — the design system has two fills for exactly that), `state-warn-label`, `state-error-primary`, `bg-layer-3` for the one floating editor, and `--ds-font-family-code` for monospace, which is the alias §九 itself names and the 题集 tab always used.

**Evidence is kept and folded, never printed or summarized.** The readiness gate's refusal, finalize's walk log and per-cell refusals, the report's account of where it looked for a bundle, `run.meta`, the raw readiness records, the plan's absolute path, the bundle directory, the repository root — all still reachable, all under «Details» or on a `title`. This matters most for the refusal: a run the gate refuses never reaches `runCreate`, so the ledger holds nothing about it and that sentence is the only record of why. The one deliberate exception is the drawer's verify block, which ui-spec §五 asks for verbatim and which stays exactly as it was.

**Two digest widths were the odd ones out** (`matrix-view.ts` printed 16, `provision.ts` printed one in full). Both are now 12, like every other digest this family shows.

## Consequences

- `packages/eval` 757 → 771 tests (a new `tests/vocab.spec.ts` pins the table's totality, both dictionaries carrying every key it can produce, and the two regressions by name: the array heading and the alphabetical column). `packages/datasets` stays at 198. Both suites green; typecheck green.
- Five client specs were updated rather than deleted — every changed assertion is a page reading a WORD where it used to read a token, or a fold where it used to read a raw block, and each carries the §九 clause that moved it.
- Toolbar actions stay permanent and empty seats carry their own call to action with its own wording (「新建第一个实验」 rather than a second 「新建实验」). The first attempt hid the toolbar button while a seat was showing, which both duplicated less and read worse: the button appeared during the load and vanished when the answer arrived.
- `report.comparisonClosed` changed shape — it takes a count now and the failing invariants stand beside it as the same chips the list above uses, instead of being pre-joined into the sentence host-side.
- One RPC is added in one case: a run whose host-chosen column is not the designed factor re-fetches the matrix once when the page first opens. A run with one factor, or one whose alphabetical first IS the designed factor, fetches once as before.
- A second gate came out of the screenshot pass: `tests/copy.spec.ts` in each package reads the client sources, collects every literal `t('…')` key and checks it against BOTH dictionaries, plus that the two dictionaries carry the same key set and the same parameters per entry. The client specs render with an identity `t`, which echoes the key — exactly what a missing key renders as — so they could not see this class of defect at all.
- Walking the real instance found four things the code review had not: an absolute repository path still printed on the overview and the plan review, a factor cell that wrapped a list row onto three lines, a condition-count column too narrow for 「1（+1 判官）」, and filter chips whose word and count had no gap. All four are fixed; the screenshots in the report are the second pass.
- **Recorded, not fixed (behaviour).** The composer's dataset chip re-reads on session activity, which is how a slash-command bind produces its receipt (T39 · G2). Binding through the tab's own import form does not move the session, so the chip still reads 「未绑定」 until the next slash command: of the two doors, only one notifies it.
- **Recorded, not fixed (data plane).** `pivotMatrix`'s summary sentences, `report`'s invariant details and `rankReason` are assembled host-side in Chinese, so an English UI mixes the two languages. Fixing it means sending structured fields and composing in the browser half — a data-plane change the task explicitly scoped out.

## Testing

`pnpm --config.verify-deps-before-run=false test` in both packages, and `tsc -b --noEmit --force` in both. `tests/vocab.spec.ts` checks every key the table can produce against BOTH dictionaries, so adding a stage or a condition field without its two entries fails here rather than rendering a raw key in front of a user.

## Alternatives considered

### Why not filter the noise factors in `conditionFactors` itself?

Because it would make a pure, honest function lie. `conditionFactors` answers 「which fields do these declarations disagree on」, and `home.sha` genuinely is one — two conditions differing only in it ARE two subjects. The same function feeds the conditions diff, the list's factor column and `eval_cells`; teaching it that some differences do not count would change what three faces report in order to tidy one page. The distinction being drawn here is not 「real vs. not real」 but 「can a reader hold this fixed」, which is a UI question, so it lives in the UI.

### Why not have the pivot default to the designed factor?

Same reason, one layer up: `pivotMatrix` is a pure arrangement shared by the tab and the tool face, and a preference order taken from ui-spec §九 is a browser-half opinion. The correction costs one extra fetch, only on runs where the two disagree, and it keeps the rule written down in one place (`NAMED_FACTORS`) beside the words it orders.

### Why translate `mixed (archived / ws-ready)` by computing it instead of parsing it?

Parsing would have been three lines and would have worked — until the host reworded the separator, at which point the page silently falls back to printing the host string again, which is the bug. The reps carry their states already; composing from them is the same information with no coupling to someone else's punctuation.

### Why fold the host's English sentences rather than rewrite them as copy?

Rewriting them means the page claims to know what the host meant. The readiness refusal names a scoped home and a credential state; finalize's refusal names a gate and a state. A summary of either is a guess, and for the refused run it is a guess that replaces the only record there is. Folding keeps the evidence intact and keeps the page readable — both, rather than one at the other's cost.

### Why one chip component with tones instead of per-page colour classes?

The per-page classes are what drifted: 「运行中」 was `--dsw-alias-state-business-primary` in the list, plain text in the matrix and a bordered pill in the header bar. A tone is a claim about meaning (`warn` = a human has something to do) that every page can make honestly, and one stylesheet rule then answers it for light and dark at once.
