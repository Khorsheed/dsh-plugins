# Agent Note: video-studio —— 吸顶查找栏 + 命中导航统一改字入口

Status: implemented

## Problem

文稿 tab 的查找/改字界面有四个来自真实使用的摩擦点：

1. 查找栏是 `.body` 滚动容器的普通子元素，正文一滚它就滚走——长文稿最需要它的时候它不在场。
2. 同一个改字意图要学两条平行路径：选中气泡里的内联改字表单（单处修改）对查找栏的全部替换，外加一个只是把查找栏打开的「找同款」按钮。
3. 「存进节目，以后自动改」把替换规则存进节目并静默套用到以后每一期转写。它默认勾选、规则不可见地累积，而且没有任何设置界面列出这些规则——是没有管理界面的跨期静默改动。
4. 「只看这些」把文稿过滤成只含命中的段落，但过滤器 chip 行只在原始视图渲染——在成片视图里过滤看不见也关不掉（只能关掉查找栏）。用户看不出这个按钮是什么意思。

## Decision

查找栏现在是唯一的改字入口，交互对齐 Word 模型：

- **吸顶**：在 `.body` 滚动容器里 `position: sticky; top: 0`（沿用 `.playerBar` 的既有模式），正文滚动时查找栏钉在顶部。
- **命中导航**：`3/12 处` 当前/总数计数，↑/↓ 按钮（循环），两个输入框里 Enter / Shift+Enter 跳转，Esc 或 × 关闭。当前命中用实心高亮（`data-hit-current`，区别于浅色的 `data-hit`），并以 `block: 'center'` 滚入视口；命中段落超出 60 段分页窗口时先扩页（沿用播放跟随的既有模式）。`jumpedTo` 键（`query | index | segment | start`）保证每次导航只跳一次，播放 tick 等无关重渲染不触发滚动。
- **改字只有一个入口**：选中气泡改为竖向菜单（▶ 从这里播放 / ✂ 剪掉 / ↩ 恢复 / ✎ 改字…，点菜单外任意处关闭）——竖向是因为横向空间不够，以后加动作只需加一行。「改字…」把选区交给查找栏：查找词和替换词都预填选中文字（替换词聚焦并全选，打字即覆盖），当前命中定位到被选中的那一处，而不是全文第一处。
- **「替换当前」与「全部替换」并列**：前者对当前命中的区间调已有的 `fixText`（不新增 remote 动词）；替换后命中列表重算、索引原地不动，自然落到下一处——Word 的节奏。「全部剪掉」不变。
- **删除「只看这些」和 `hits` 过滤变体**；导航替代了它的用途。
- **「存进节目，以后自动改」全链删除**：勾选框、`ReplaceRequest.remember`、`service.replaceAll` 的 remember 分支、`Settings.replacements` 字段及其默认值、转写完成后的 `applyReplacements` 调用、技能说明里的对应承诺、README 的对应表述。旧工程/节目文件里残留的 `replacements` 键成为死数据，`normalizeSettings` 会忽略它（它只遍历 `SETTING_KEYS`），无需迁移。

## Alternatives considered

- **保留「只看这些」并让 chip 行在成片视图也渲染**：否决——看不见的过滤器本身就是 bug，而且命中导航已经覆盖"逐个查看"的用途，不需要第二种列表模式。
- **保留气泡内联表单作为第三条路径**：否决——用户抱怨的正是"一个意图两个界面"；预定位好当前命中的查找栏能力上严格更强（还能同时看到其余出现处）。
- **保留节目级替换规则并补一个设置编辑器**：暂不——静默的跨期改动要有真正的管理界面才可信，单期全部替换已覆盖实际校稿流。重新引入的前提是先有编辑器。
- **保留横向工具栏气泡、硬塞更多按钮**：评审否决——横向空间有限；竖向菜单加动作只需加一行。

## Consequences

- `ReplaceRequest` 去掉 `remember`——线上协议变更，但包还是 0.1.0 未发布，无兼容负担。
- `Settings` 去掉 `replacements`——存储格式变更，原地兼容：旧文件照读，死键被忽略。
- `fixText` 从查找栏获得新流量；用户发起的单处替换照旧立即生效，语义与气泡改字一致。
- 技能说明不再承诺跨期自动改字，模型不会再向用户建议用户看不见编辑入口的规则。
