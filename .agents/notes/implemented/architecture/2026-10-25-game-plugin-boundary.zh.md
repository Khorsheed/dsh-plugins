# Agent Note: where the game plugin ends and a game begins; the 3D kit's open doors

Status: implemented

## Problem

正在做的那个 3D 游戏（风格化低多边形，目标是《A Short Hike》那一档）提出要 glTF 模型和骨骼动画、跟随镜头、可行走的平台、投影和泛光。回应时，插件维护者最初提议把泛光往后放，理由是太重。用户指出了其中的风险：插件以「太重」为由不做某样东西，而游戏自己又做不了，那么用这个插件做出来的每个游戏都会被卡在这里。审查 3D 套件后，确实找到了这样的墙。游戏本来已经能直接用 `three` 和 `world.scene/camera/renderer`，但是：

- 模块对照表只认 `three` 和 `dsh3d`，three 自带的扩展（GLTFLoader、EffectComposer）没法正常引入；
- 镜头每帧都被放回固定的 45° 位置，点选也用这台镜头；
- 光源是私有的；
- 绘制固定是 `renderer.render`，后期处理插不进去；
- 4 秒内没就绪的游戏会被检查判为失败；
- 游玩框不允许指针锁定，测试也没法模拟鼠标拖动；
- toon 和 flat 材质按颜色共享，没法只让某一个物体发光或变色。

## Decision

**边界。** 插件分三层：

1. **游戏碰不到的，插件必须做**：沙箱、模块加载、检查，以及面板能看懂的一切（外观预览、元素、点选、场景、版本）。
2. **多数游戏想要的便利**（配方、批量摆放、场景，以及将来的 `groundAt`）由插件提供，游戏可以不用。
3. **少数游戏才要的**（泛光、特殊镜头、物理）插件可以不做，但必须留一扇门，让游戏能自己做出来。

只有插件能打开的墙算插件的 bug，优先修。gamedev 技能要求 agent 撞上这种墙时直接说明，并记进 `design/plugin-requests.md`，而不是悄悄把游戏做差。

**打开的门（全是新增，默认行为不变）。** 运行时不按项目分版本：每个 3D 游戏，包括旧版本，跑的都是当前这份 dsh3d，所以这里的改动不会改变任何已有游戏的行为。

- **扩展。** 模块对照表把前缀 `three/addons/` 映射到 `_dsh/addons/`，加载器按 import map 的规则解析前缀。每个版本只带项目脚本实际引用到的扩展文件，以及这些文件再引用的文件，都从固定版本 three 的 `examples/jsm` 读取（上限 6MB）。
- **镜头。** `world.setCamera(cam)` 让游戏自己的镜头（比如游戏每帧自己摆放的透视跟随镜头）用于绘制、点选和高亮圈；`setCamera(null)` 换回默认镜头。`world.camera` 改成取值器，透视镜头的宽高比会跟着尺寸变化。
- **光源与投影。** 开放 `world.lights.{ hemi, sun }`。`style3d.shadows: true` 打开太阳的柔和投影，投影范围跟着目标走；`world.add` 和 `scatter` 加进来的网格会投影也会受影（描边外壳不会），地形会受影。清单解析会保留 `shadows`。
- **绘制接管。** `world.onRender(fn)` 用 `fn({ renderer, scene, camera })` 代替默认的绘制，并返回一个交还绘制的函数。
- **独立材质。** `toon(color, { own: true, … })` 和 `flat(…, { own: true })` 返回独立的副本，仍然保留风格的明暗层数。
- **加载。** `dshGame.loading` 为 true 时，检查最多等 20 秒让 `ready` 变为 true（否则只等 4 秒），失败提示会指出这个开关。
- **鼠标。** 游玩框允许指针锁定（点击时申请，Esc 释放）。`dshGame.look(dx, dy)` 是可选接口，测试里有 `drag(dx, dy, frames)` 来调用它。

## Alternatives considered

**把泛光和跟随镜头当作「插件功能」往后放。** 这是最初的提议。没有绘制接管和镜头替换，游戏两样都做不出来，往后放就等于把每个游戏都卡住。

**把整个扩展目录打包进 `_dsh/addons/`。** 每次加载都要多背几 MB 用不到的代码。只解析项目实际引用的扩展，每个游戏只付自己用到的那部分代价。

**现在就按项目给运行时分版本**（v1、v2 并存）。只要每次改动都是新增，就用不着。第一次必须修改某个默认行为时才需要。

**把要的东西（泛光、跟随模式、glTF 外观）马上都做成插件功能。** 太慢，还会让插件成为瓶颈。门打开之后，游戏 agent 今天就能自己做泛光和镜头。插件的便利功能（P2 可行走、P3 开关、P1 跟随模式）和 glTF 外观（先静态，后动画）按游戏 agent 提议的顺序跟进。

## Consequences

- 游戏现在可以引入 GLTFLoader 直接摆放 `.glb` 模型。作为元素外观时，面板也能预览和调整它们，见 [glTF 外观](../feature/2026-10-25-game-gltf-looks.zh.md)。
- 游戏接管镜头或绘制后，那部分就归游戏自己管。工作台仍然通过当前的镜头来点选和画高亮圈。
- 投影范围固定为目标周围 48 个世界单位。需要更大范围的游戏，自己调 `world.lights.sun.shadow.camera`。
- 加载器对任何套件的模块对照表都支持前缀键。
