# Agent Note: the evaluation line runs on 3080 — the skill ships with its package, one eval composition, dataset-authoring in dsh-presets

Status: implemented

## Problem

The evaluation line ran only on its own instance (the web-eval pack). That instance had two habits that break on a shared, multi-mode instance like 3080:

- **The planning skill was a copy in the shared skills directory.** `install.sh` / `update.sh` copied `eval-planning` into `$DSH_HOME/skills`. `dsh-skill-filesystem` scans that directory for every preset that composes it, so on a multi-mode instance the skill would appear in 开发模式 and 写作模式 too. That is a leak, not a grant.
- **The eval agents existed twice, and one of them only privately.** The web-eval bundle (`profiles/web-eval/presets`) declared `eval` (评测模式) and `dataset-authoring` (题集整理). The published `@khorsheed/dsh-presets` bundle 3080 runs declared `dsh-eval`: the same rows, an older persona, and no `dataset-authoring`. The datasets core's default `authoringPreset: 'dataset-authoring'` therefore pointed at an id 3080 did not have, so 「整理」 had nowhere to open.

## Decision

**The skill ships with `@khorsheed/dsh-eval` and the eval-tool row grants it.**

- `eval-planning/SKILL.md` lives in `packages/eval/skills/` and is in the package's `files` (`skills/**/*.md`).
- The `./tool` entry (`src/tool.ts`) reads it and registers it through `ctx.inject(['skills'], …)` with `source: 'runtime'`, provider `@khorsheed/dsh-eval`. This is the same mechanism the datasets tool row uses for `dataset-authoring`.
- Registration happens only when the row's `tools` tier is not `none` and the core is present. Only a preset that mounts the eval-tool row (评测模式) sees the skill.
- If the file is unreadable, the row logs a warning and keeps its tools.

**The pack scripts stop copying skills, and they retire their own old copy.**

- `install.sh` and `update.sh` no longer touch `$DSH_HOME/skills` except to remove the copy earlier versions put there.
- `retire_legacy_skill` runs only after a successful install or update. It deletes `$DSH_HOME/skills/eval-planning` only when the first 12 lines carry the pack's signature (`name: eval-planning` plus `  iteration: I5`; every shipped version had both).
- A directory without the signature is a person's own file. The script leaves it alone and says so.
- 3080 never received a copy: its skills directory holds no eval skill. Deploying there has nothing to retire.

**One eval composition, with web-eval as canonical.**

- web-eval's `preset-eval` is the canonical text: it is apparatus, sha-pinned in `web-eval-preset-bundle.spec.ts`, and carries the newer persona.
- dsh-presets' `preset-dsh-eval` was brought to the same composition. The only differences before were the persona: a reworded Execution line, plus four lines on `datasets_list` as the only registry, version ambiguity, paths not being datasets, and drafts never entering a dataset repo.
- The row keeps its id `dsh-eval`, so 3080's existing sessions and chosen presets stay valid. The eval session door selects a preset by what it grants, not by id, so `eval` and `dsh-eval` behave the same.
- `scripts/eval-preset-parity.spec.ts` compares the two `plugins:` blocks after normalizing comments and `name:` quoting, plus `name` / `description`. Drift in either direction is a red test.

**`dataset-authoring` is mirrored into dsh-presets.**

- It is a new row `preset-dataset-authoring`, with the same id, composition and display as web-eval's, at order 11.
- On 3080, the datasets default `authoringPreset` now resolves without a config change.
- 开发模式 and 写作模式 gain nothing. `packages/presets/tests/presets.spec.ts` pins that neither names a datasets / eval / mission tool row or either eval skill.

**No other evaluation package writes into the shared skills directory.** datasets, eval, lab, mission, bundle-eval, the local-agent family and capability-catalog were checked: datasets registers `dataset-authoring` the same runtime way, and the rest ship no skill.

## Alternatives considered

**Keep the copy and filter by preset.** The skill-filesystem row has no per-preset filter, and the directory is shared by every mode on the instance. Any filter would be a new host seam for something a runtime registration already scopes correctly.

**Install the web-eval bundle on 3080 instead of extending dsh-presets.** deploy:3080 packs workspace packages; the web-eval bundle is a profile-local private package outside that flow. It would also add a second 评测模式 chip next to `dsh-eval` and bring the pack's `default: eval` pin onto an instance whose default is 开发模式.

**Make the web-eval pack depend on dsh-presets and drop its own bundle.** That breaks the pack's decision to install only the evaluation apparatus: the pack would gain dev and writing modes it does not want, and lose the `default: eval` pin.

**Rename `dsh-eval` to `eval` so the ids match too.** That would orphan the preset choice recorded on every 3080 session that already uses 评测模式, for no behavioral gain, because the door is grant-based.

**Have the scripts delete any `eval-planning` directory unconditionally.** A person may have put their own skill under that name. Deleting by signature removes exactly what the pack put there.

## Consequences

- On any multi-mode instance, eval-planning is visible only in sessions whose preset mounts the eval-tool row. The skill now updates with the eval tarball, with no script step.
- The eval persona has two copies that must change together. The parity spec turns forgetting into a red test, but an edit still touches two files. If the web-eval preset changes, edit it first, re-pin its sha, then mirror it.
- dsh-presets gains an evaluation-only chip (题集整理) on every instance that installs it, including ones without the datasets core. There the row stays pending and the chip opens an agent without dataset tools. This is acceptable because the dev and writing compositions are untouched.
- Older pack installs keep their copied skill until their next `update.sh`, which removes it.

## Testing

- `packages/eval/tests/tool-row.spec.ts`:
  - the skill registers from the row, with this package as provider;
  - nothing registers when the tier is `none` or the core is absent;
  - the body carries the T87 drafting rules;
  - `npm pack --dry-run` ships `skills/eval-planning/SKILL.md`.
- `packages/presets/tests/presets.spec.ts`: there are four presets; dev and writing carry no eval rows or skills; dsh-eval carries the datasets and eval rows; dataset-authoring carries `datasets-tool` at `tools: organize`, with no eval or mission row.
- `scripts/eval-preset-parity.spec.ts`: the two copies have one composition.
- `scripts/web-eval-install.spec.ts`:
  - neither script copies skills;
  - `retire_legacy_skill` runs after the success trap is cleared;
  - run against a temporary home, it removes the pack copy and keeps a person's own file.
- A throwaway instance used 3080's profile with this branch's datasets, eval and presets tarballs. Typing `/eval` in 开发模式 offered nothing. In 评测模式 it offered the `/eval` command and the `eval-planning` skill. `/dataset` in 题集整理 offered `/datasets` and `dataset-authoring`. 写作模式 offered neither.
