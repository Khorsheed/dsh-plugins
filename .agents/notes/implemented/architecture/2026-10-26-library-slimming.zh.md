# Agent Note：图书馆——瘦身后的工具与只讲旅程的提示词

Status: implemented

## 问题

10-26 那次 Blender 会话量出了图书馆每次请求的成本：十个工具定义共 23,850 字符，占会话全部 25 个工具的 65%（宿主最长的 `bash` 是 2,277）。提示词部分在 5,665 字符的系统提示里占 2,795。返回结果是带缩进的 JSON，一次 `library_read · roadmap` 就返回 7,300 字符。教练还打乱了旅程：学员采用路线之前就写讲义、开讲，部分原因是拒收提示原话就是「先在对话里讲着」。用户问：长度本身是不是让较弱的模型（inkling:free、deepseek-flash）只照字面执行、抓不住意图。

## 决定

与用户对照 `proposals/prototypes/library-journey.html` 和 `library-slimming.html` 定论：

- **提示词只讲旅程**：谁在什么时候做什么、在哪里停下（采用前不写讲义、不开讲、不出题；学员说开始某一站才开始；讲义写好后说一句就等）。格式规则移进工具，少见的规则交给拒收提示。2,795 → 1,208 字符。
- **参数说明只写一种标准写法。** 宽松解析仍在 execute 里。大数组保留两个分支：带类型的列表，加同样内容的 JSON 文本，这样字符串化的参数仍能通过宿主校验。`{ items }` 包装分支、别名字段和逐字段长说明都不再发给模型。小的宽松字段（目标、验收行、选项、目录、目录来源）用 `type: 'json'` 加一句形状说明。
- **服务端能推出的字段不再让模型填。** 题号自动编；出题目标和题目依据由引文、pageId、url 和教材推出。判分只需 task、pass 和 why（criterion、evidence、by 由它补全）。站的关卡类型看有没有验收行。对话卡片默认记为薄弱，类型随项目。
- **`library_resource` → `library_textbook`。** 只管教材；op 为 add | update | move | remove，create 照样能解析。链接不再写给模型看（kind、short、isbn、extras 都隐藏但仍能解析）。所以没有显式链接类型的调用一律按教材处理，拿到的是教材的拒收提示，不会再出现「链接需要 title、url」。
- **`op` 和 `what` 用普通字符串而不是枚举**，旧写法（`create`、`books`）仍能进到 execute。`what` 改成选填：漏了它的读取，按传进来的参数推断要读什么。
- **返回结果用紧凑 JSON，并带下一步。** 排完路线：用两句话介绍，采用前停下。讲义写好：告诉学员，然后等。过关：说出下一站并问要不要开始。`library_read · roadmap` 返回的站不带讲义正文。
- **体积测试**（`tests/size.spec.ts`）：十个工具定义上限 12,000 字符，提示词上限 1,250。改后实测 10,735 和 1,208。

## 考虑过的方案

- **合并工具**（绑定并入项目、判分并入出题）：否决。一个工具多种用法正是这次要去掉的毛病；十个短工具好过七个多用途工具。
- **去掉 JSON 文本分支**：否决。弱模型仍会把嵌套参数字符串化；没有这个分支，宿主校验会在工具开口教之前，用看不懂的提示把调用拒掉。

## 后果

- 历史里记着 `library_resource` 的会话会收到一次「没有这个工具」，之后改用 `library_textbook`；已存数据不变。
- 侧栏「添加链接」填的请求，通过隐藏的 kind 仍然能用。
- 讲义存储、讲义页和路线页改版在第二、三批。

## 测试

188/188 全绿。新增：体积预算；排完路线的停止指令和推断出的关卡类型；不带讲义正文的精简路线读取，以及漏了 `what` 的读取；自动编号的题目和只带 why 的判分；add / update 两种 op。措辞有意改动处的旧断言已同步更新。
