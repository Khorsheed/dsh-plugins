# Agent Note：灵感空间的状态住在哪里，以及为什么

Status: implemented

## Problem

连续三轮「灵感空间忘了 X」，每一轮都单独修：打开的正文与译文（页面记忆）、每次打开都重抓的抓取、阅读位置。最后一轮不是接线错误，而是**单位**错误：阅读位置被记成了像素偏移，而正文第一次渲染时文档高度还不是最终值。

证据来自验收实例自己的缓存：读者报的那篇文章，落盘的正文里有 **27 个 `<img>`，其中没有一个带 `width` 或 `height`**（`extract-article` 保留站点自己的标记）。所以正文渲染完之后，文档随着每张图到达持续变高——而按「布局已稳定」记录的像素偏移，落在一个还很短的文档里，被浏览器钳住，于是读者留在了顶部，内容还在他脚下移动。本该兜住这件事的重试循环检查的是 `scrollHeight >= target + clientHeight`，而这在钳位之后**恒为真**，所以它一次都没有重试。

所以这份 note 就是被要求的那份 review，以及它带出来的改动。

## Decision

### 清点

| 状态 | 归属 | 存活范围 | 从哪里回来 |
| --- | --- | --- | --- |
| 墙上的解析结果（条目） | 面板，来自宿主 payload | 一次挂载 | 每次挂载重新读 + 重新解析——刻意如此，墙永不过期 |
| 正文（html / 侧车文件） | **宿主**（`state.json` + `bodies/`，受缓存 TTL 与预算约束） | 重启 | 打开条目时 `getEntryBody` |
| 位置：视图、打开的条目、正文锚点、墙偏移 | **页面记忆 + `sessionStorage`** | 重新挂载、切会话、页面重启（同一标签页） | 挂载时 hydrate；锚点在每次正文重建时重新应用，布局增长期间重新测量，译文视图改变几何时重新落锚 |
| 译文文本（句子记忆 + 按条目的段落映射） | **宿主**（两层落盘，64 MB 预算，LRU，无 TTL——见[译文落盘 note](../feature/2026-09-20-reader-persistent-translation.md)），页面里有一个写穿透镜像 | 重启 | 翻译开始或条目打开时从宿主热进来；仅页面镜像随页面而亡 |
| 翻译会话（按语言对） | **页面记忆** | 这个页面 | 复用——绝不重建，因为 `create()` 需要用户手势 |
| 地球开关 + 视图（按条目） | **页面记忆** | 这个页面 | 每次正文重建都重新应用 |
| 标签、保存的链接、`recent` | **宿主** | 重启 | 从宿主读 |
| 按条目的抓取状态（正文 / 待解析 / 在飞 / 带原因的失败） | **宿主**（按条目标注），面板 store 里有镜像 | 重启 | `entryFetchStates`：挂载时与在飞期间的整墙轮询，加上每个落定某条目的写入路径对那一条做定向重读 |
| 墙的收窄、排序、搜索、未读游标 | **页面记忆** | 这个页面 | 挂载时 hydrate |
| 对话草稿、引用目标 | dsh 会话 | 这个会话 | 宿主 |

### 四条边界与各自规则

1. **宿主状态是内容的唯一权威。** 正文、源、标签、最近阅读都在那里，按条目 id 索引，所有会话共享；它们是**重新读**的，不是被记住的。
2. **页面记忆只记「读者刚才在哪」，绝不记「读者拥有什么」。** 它跨面板重新挂载、跨 dsh 会话（读者是一个人，读的是一面墙）。其中「位置」还会写进 `sessionStorage`，所以页面重启（刷新，或任何让页面重新初始化的动作）之后读者仍在原处；第三方内容则哪里都不写。
3. **React 状态绝不跨挂载。** 任何需要活过一次挂载的东西，都由拥有它的 effect 写进页面记忆，而不是放在组件状态里碰运气。
4. **翻译会话属于页面且绝不持久化**（新建需要用户手势），地球记录同理留在页面记忆里：重启之后文章和位置回来，地球保持熄灭，等读者点一下。句子**文本**是反转了旧规则的那个例外（自 [2026-09-20](../feature/2026-09-20-reader-persistent-translation.md) 起）：句子对按预算落在宿主侧——因为真正的隐私不变量是「模型不碰网络」，从来不是磁盘。

### 让这件事不再变成「补丁叠补丁」的规则

- **被恢复的状态在每一次**重建**时重新应用，并且以**内容**为键，而不是以坐标为键。** 位置原本是一个只应用一次的偏移；翻译记录有着同一种形状的 bug（从挂载时的副本读、按条目只武装一次）。两者现在都以 `[openEntryId, articleHtml]` 为键——以正文此刻的样子为键——并且都会重新应用。坐标（像素偏移）永远只是兜底。
- **记录就是唯一真相，结束它的那个手势负责删掉它。** 「这一条的地球是亮的」持续到读者关掉地球或要求重新抓取；位置持续到读者滚去别处。任何环节都不再私自保存一份「本该是什么样」。
- **程序化的写入绝不能被当成读者的输入。** 设置 `scrollTop` 同样会触发 `scroll` 事件，而钳位会让回声与目标不同——保存它就会用短文档的高度覆盖真正的位置。回声会被识别并丢弃；而真正关键的那个判断——「读者已经接管」——只看只有人能做出来的手势（`wheel`、`touchmove`、翻页键），绝不比较滚动偏移。
- **布局在每次布局**变化**时只测一次。** 在滚动处理器里读几何，就是 Chrome 报「强制回流」的原因，而一篇文章有几百个块：正文渲染时与每次尺寸变化时一次性测量、缓存，锚点则是在缓存上做二分查找。滚动处理器完全不读布局。
- **恢复是异步的，所以面板必须显示它正在恢复到的那个面。** 条目 id 在第一次渲染就知道了，条目本身来自宿主的 payload。在这个窗口里渲染墙，就是「正文消失又回来」的那一闪；现在改为渲染详情面 + 一行加载中——而一次落定为「条目不存在」的恢复会关掉 store 里的条目，而不是永远停在空的详情页上。

### 改动

- `client/session.ts`：按条目的位置变成 `ReaderReadingAnchor`——视口顶部所在正文顶层块的序号、块内偏移、块内文本的字符偏移（于是同一块的译文渲染也能解析出位置），以及作为兜底的像素偏移（`rememberReadingPosition`）。
- `client/ReaderPane.tsx`：读者滚动时从 DOM 里读出锚点（跳过翻译自己插入的 reveal 行，否则会把块的序号顶偏），每次正文重建都重新应用，**用赋值是否真的到达目标**来判定（而不是 scrollHeight），并在布局增长时重新应用（对正文挂 `ResizeObserver`，窗口 `POSITION_SETTLE_MS`），直到读者自己滚动接管为止；译文视图变化时也重新落锚（一个按 `translateView` / `translatePhase` 键的 effect 重新测量并重新应用——视图切换在 settle 窗口早已关闭之后改写块几何）。
- 恢复窗口渲染详情面，而不是墙。

## Alternatives considered

**保留像素偏移，只是把重试做得更狠。** 重试本来就在，而且一次都没跑（钳位之后它的判定条件恒为真）；用错误的单位重试更多次，在文档变高之后仍然会落在不同的内容上。
**把位置、地球开关和打开的正文落盘，让刷新也能保留。** 否决理由见之前的 note：译文不能落盘，所以落盘的地球记录在刷新后是空的；而读者元数据还没有挣得进入部署状态的位置。
**把墙的解析结果缓存在页面记忆里，让重新挂载瞬时。** 暂时否决：解析结果只对产生它的 payload 有效，而现在没有 payload 版本号可以做失效判断——一面陈旧的墙比短暂的加载更糟。
**不卸载面板。** 那是宿主行为（`RightbarRoot` 只在没有其他活动主面板时渲染），不是本包能改的。

## Consequences

### 仍然成立、也仍然是代价的部分

- **每次面板挂载都会向宿主重读并重新解析墙的 payload。** 这就是读者看到的「每次都在加载」，而且是刻意的：缓存解析结果会在下一次刷新落地的瞬间变陈旧。要让它瞬时，需要一个宿主侧的 payload 版本号来做失效判断。
- **刷新、重启，或浏览器回收后台标签页，会重置全部页面记忆**——位置的镜像、地球记录、打开正文的 React 状态、收窄。宿主状态（正文、源、最近阅读）不受影响；译文文本自[落盘反转](../feature/2026-09-20-reader-persistent-translation.md)起也不受影响：地球的手势之后，它从宿主的两层读回来，而不是重新跑模型。
- **锚点是块序号**，所以被重新抽取成不同结构的正文会让它偏移；越界时由像素兜底接管。

## Testing

`packages/dsh-reader` 共 311 个测试。位置相关的测试把 jsdom 提供不了的几何显式写出来（600px 的滚动容器、每块 300px——译文用例则是块高随文本长度走的桩）：一个断言保存下来的锚点正是读者停下的那个块（含文本偏移），一个断言恢复会把读者放到该块的偏移处——即使记下来的像素偏移是荒谬的值，而那正是读者报的 bug 所在的情形——还有一个断言翻译落地后按文本偏移重新落回同一句。块内映射本身（Range 精确 / 同一分数 / 像素兜底 / 旧锚点兼容）由 `tests/reading-position.spec.ts` 直接钉住。
