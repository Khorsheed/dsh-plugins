# Agent Note: 画布视图按 session 隔离

Status: implemented

## Problem

画布客户端此前为整个浏览器应用只创建一份 `CanvasSelectionStore`，并统一写入 `dsh-canvas.tabs`。因此，即使宿主已经为每段对话保留独立子树，切换会话仍会打开同一组画布标签、同一张卡片或同一篇成稿。普通画布还可能没有持久绑定，新会话进入时没有可靠的作品可恢复。

## Decision

- apply 闭包按 session id 惰性创建独立的 `CanvasSelectionStore`。标签页主体、dock 标题、导航去向、收件箱、引用动作和绑定 chip 都写入本会话的 store；没有 session 的根级组合仍使用未分组键。
- 每个分组 store 使用 `dsh-canvas.tabs:<sessionId>` 持久化。旧的未分组标签状态只迁移给第一个分组读取者，并从旧键删除，不再复制到每段对话。未保存的编辑文字仍由宿主独立的会话子树持有，不新增持久化。
- 画布仍是部署级共享数据，所以写操作和写入通知向所有 store 广播新鲜度；选择、删除后的视图清理和导航保持会话隔离。
- 新挂载且没有恢复标签的会话优先读取持久绑定并打开该作品；没有有效绑定时保留最近活动回退。仅仅浏览另一块画布不会静默改绑。
- Room 等全局入口显式解析当前显示的协调会话。共享作品库不增加推测性的 session 归属过滤。

## Alternatives considered

- **在一个 store 内保存所有 session 的状态。** 否决：宿主已经提供独立会话子树和按 session 的 slot 注入，独立的小 store 能保留现有组件 API，并自然隔离草稿状态，改动更小。
- **继续让所有 session 有意共享标签。** 否决：右侧栏是会话级界面；协作需要显式跳转到协调会话的视图，而不是让每段对话静默控制其他对话。
- **按 session 归属过滤作品库。** 否决：画布没有可靠所有者，多段会话可以共同创作同一作品。应该隔离的是视图和目标，不是数据可见性。
- **保留旧共享键作为所有会话的回退。** 否决：这会让每个新会话重现原来的串视图问题，因此旧状态只迁移一次。

## Consequences

- 现有画布、绑定和协作数据无需迁移，只有浏览器本地的标签状态改变结构。
- 画布包构建和全部 37 个测试文件通过，新增覆盖分组独立恢复、旧状态一次性迁移和绑定作品优先打开。
