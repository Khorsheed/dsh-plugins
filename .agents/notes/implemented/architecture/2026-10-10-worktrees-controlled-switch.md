# Agent Note: worktrees agent-free queries and the controlled switch — admission seam over the Remote wire

Status: implemented

## Problem

A trusted server-side caller that consumes the plugin per authorized workspace needs two things the package could not do. First, READ repo/worktree state for paths it has already authorized: every repo-scoped Remote verb (`summary`, `changes`, `repoFiles`, `listWorktrees`, `commitLog`, `commitFiles`, `fileDiff`, `readFile`, `readFileAtCommit`, `readRepoImage`) took an `agent: Agent` lookup param only to derive a cwd (`activeWorktreeOf(agent.id) ?? agent.session.header.cwd`), and the host's unified agent lookup may RESUME offline sessions — a member-scoped query must never trigger that. Second, WRITE the per-session worktree binding under concurrency: the only switch was last-write-wins on an in-memory map (lost on every host restart), with no compare-and-swap, no way to read the current binding except inferring it from `summary`, and no event when a binding changed.

## Decision

All evolution is additive on the Remote wire (`packages/worktrees`, version stays 0.3.1): the agent-bound verbs and the native UI are byte-unchanged, and a deployment that never calls the new verbs behaves exactly as before apart from the new durability of bindings.

- **Agent-free query verbs** (`packages/worktrees/src/remote.ts`): `summaryAt` / `changesAt` / `repoFilesAt` / `listWorktreesAt` / `commitLogAt` / `commitFilesAt` / `fileDiffAt` / `readFileAt` (a `commit` argument makes it `readFileAtCommit`'s twin) / `readRepoImageAt`. Each takes `{ at, … }` — any absolute path inside the target repository/worktree, validated by the existing `assertSafeLocalPath` — and delegates to the same service core, so parity with the agent-bound twin is by construction. Like the local-files verbs, authorization/jailing is the trusted caller's job; the surface performs no admission.
- **The controlled switch** `switchWorktreeControlled(sessionId, { path, expected? })` (`src/service.ts` `controlledSwitch`, thin Remote wrapper): a plain-string session id, the repository resolved from the TARGET path, and a typed receipt union (`src/bindings.ts` `ControlledSwitchReceipt`) instead of a throw taxonomy — `switched` (WorktreeInfo + effective binding + `persisted`) | `conflict` (carries the ACTUAL current binding) | `not-a-repo` | `no-worktree` | `invalid-request` | `persistence-failed`. A present `expected` (`{ kind: 'override', path }` or `{ kind: 'none' }`) makes the write a compare-and-swap, never a silent last-write-wins. CAS is SINGLE-PROCESS: the in-process map plus its write-through file, no cross-process locking.
- **Persistence**: the override map writes through to `bindings.json` under a resolved state root (`resolveWorktreesStateRoot` — explicit config `stateRoot` → `$DSH_HOME/state/worktrees` → `<cwd>/.dsh-worktrees`, the sidechat/canvas precedent), tmp-file + rename, loaded on mount. The receipt returns only after the write succeeds; a failed write is the `persistence-failed` receipt with memory left untouched (legacy verbs throw), never a fake success. A corrupt/unreadable file degrades the deployment to memory-only and is NEVER clobbered; receipts then carry `persisted: false` — the honest signal. The mutation order is persist-then-mutate-memory, so memory and the file cannot diverge silently.
- **Getter and event**: `worktreeBinding(sessionId)` returns the `WorktreeBinding` (`override`/`none`; `none` = the session follows its own static cwd, which this surface structurally cannot read). Every successful binding SET — legacy switch/create and the controlled switch — emits the cordis event `worktrees/switched` with `{ sessionId, path }` (wired in `apply` via the service's `onSwitched` hook; a clear fires nothing in v1). It is an in-process event, NOT a browser push; bridging/re-read is the consumer's job.
- **Existing executions never migrate**: the seam rewrites only the binding (which worktree the data face follows); an existing execution's resume cwd stays anchored to its own execution record, so a new binding applies only to new members/fresh executions. The READMEs state this as a contract consumers must not contradict.

## Alternatives considered

- **A package-root factory (the file-preview read-surface / canvas workspace-access precedent)**: wrong shape here — file-preview's seam is READ-only over state fully derivable from injected sources, while this seam's core is a WRITE against host-held state: the binding map, its persistence, and the switched event all live in the mounted service on the host instance. A factory in the caller's process would mint a second, divergent CAS state. The query verbs follow the write onto the same wire and the same caller-derived-authorization model.
- **Facade `Agent` passed to the existing verbs**: fabricating an `Agent`/`Session` (the canvas facade precedent) would re-introduce the very lookup semantics the seam exists to avoid — and a fake that accidentally reaches the real unified lookup can resume an offline session. Plain-JSON verbs make "no agent reachable" structural.
- **The `ctx.fs` session-stamped fence for `bindings.json` (sidechat/canvas)**: that fence resolves a sandbox policy per SESSION; bindings key plain session ids that are not host `Session` objects in the consuming topology, so no session-stamped policy can be resolved for them. Bare `node:fs` against the plugin's own state dir has the canvas state-dir precedent (its `rm -r`). The trade-off is recorded: the deployment's read-only MODE is not consulted for this file — it is deployment-level plugin state, not session workspace content.
- **Silent last-write-wins only**: two authorized callers racing one session would each see their own write win with no signal. The `expected` compare-and-swap with a conflict receipt carrying the ACTUAL binding gives the caller the fact it needs to re-decide, while `expected` absent keeps the legacy fire-and-forget semantics available.

## Consequences

- The Remote namespace gains eleven verbs (`summaryAt`, `changesAt`, `repoFilesAt`, `listWorktreesAt`, `commitLogAt`, `commitFilesAt`, `fileDiffAt`, `readFileAt`, `readRepoImageAt`, `worktreeBinding`, `switchWorktreeControlled`); the generated wire types pick them up, and the vocabulary (`WorktreeBinding`, `ControlledSwitchRequest`, `ControlledSwitchReceipt`, `WorktreeSwitchedEvent`, `WORKTREES_SWITCHED_EVENT`, `resolveWorktreesStateRoot`) is re-exported from `./types`.
- `WorktreesService` gains an options parameter (`stateRoot`, `onSwitched`); bare `new WorktreesService(baseRef)` stays memory-only, so every pre-existing test constructs exactly as before. The plugin config gains `stateRoot` (schema-defaulted `''` → the resolve chain). The legacy mutation verbs now await the bindings load and write through; the Remote's `cwd()` awaits the load too, so the badge follows persisted overrides after a restart (the old "in-memory only" known limitation is retired in both READMEs).
- The `worktrees/switched` cordis event is declared on the cordis `Events` interface; clearing a binding (removing the bound worktree) emits nothing in v1 — a consumer needing clear-signals re-reads via the getter.
- All 97 pre-existing tests pass unmodified; 13 new contract tests (110 total) in `packages/worktrees/tests/controlled-switch.spec.ts` pin the seam. The consuming side still owes its own admission layer (deriving the authorized path set and session-id namespace per member) — this package deliberately does none.

## Testing

`packages/worktrees/tests/controlled-switch.spec.ts` drives a real temporary repository (primary checkout on a feature branch, a linked worktree on `main`): agent-free verbs compared `toEqual` against the agent-bound twins over the same fixture (summary/changes/repoFiles/listWorktrees/commitLog/commitFiles/fileDiff/readFile/readFileAtCommit/readRepoImage, from both the primary and the linked anchor); CAS sequences (none → switched, stale none → conflict carrying actual, matching override → switched, legacy↔controlled shared state); not-a-repo / no-worktree / invalid-request classification; persistence round-trip through a simulated remount with the receipt-after-persistence ordering asserted against the file on disk; corrupt-file degrade (memory-only, `persisted: false`, file never clobbered); a forced write failure (chmod 0555) producing `persistence-failed` with memory untouched and the legacy verb throwing; event payload coverage (legacy switch, create, controlled switch; silence on conflict and on clear) including the `apply`-wired `ctx.emit` path on a real cordis Context; and the state-root resolve chain under a stubbed `DSH_HOME`.
