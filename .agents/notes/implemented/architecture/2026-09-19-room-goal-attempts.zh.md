# Agent Note: 区分目标执行、成果提交与证据验收

Status: implemented

## 问题

Room 聊天任务行用成员运行终态表示任务完成，无法表达依赖验收、返工历史、明确的继续授权或原生副作用之前执行的预算限制。进程正常结束不足以证明目标达成。

## 决策

正式目标使用独立的版本化 journal 状态、阶段、任务 ID、父分组、依赖 ID 及尝试。普通消息保留轻量投递路径，不创建正式计划。草稿不派发；execute 或显式继续启用就绪叶子任务自动派发。分组通过已验收子任务完成，继承依赖检查并拒绝循环。

room_plan 工具在原生 DSH、认证外部 MCP 和人类 Remote 之间使用同一有界 JSON 命令语法。room_read 提供语法和当前计划。稳定请求 ID 和 revision 拒绝变更重试或过时的组织决定。角色及成员身份由宿主确定。执行成员只能提交自己的当前尝试，协调者或人类依据证据验收已结算的提交。返工保留被拒尝试并预约新尝试。原生成功产生待验收提交，不直接验收。目标完成要求剩余叶子全部验收，并有目标级证据。

PlanService 串行写 journal，启动工作前持久预约及投递关联，通过 provider 共用回调记录原生准入，按准确执行记录结算。成果回报交给目标的当前协调者。目标暂停时保存结果及回报，显式继续前不唤醒协调者。已在运行的原生工作可以结束，暂停自动推进与成员 Stop 分开。

并发容量、总尝试/单任务尝试上限及活跃时间预算由代码执行。只有人类能修改授权预算，定时器在时间耗尽时暂停后续工作。重启恢复暂停自动推进，并把此前仍活跃的原生尝试标为结果不明；只有人类能带证据对账。不自动重放未知执行。

既有 Room composer 承载可选目标面板，展示阶段、依赖、尝试历史和证据验收，支持暂停/继续、人类预算调整及明确的未知结果对账。保留成员会话导航和单成员 Stop。已验收叶子计数排除分组和取消任务。确认丢失时保留命令身份，不乐观显示验收成功。对账更新准确关联的执行投影，并替代暂存的不确定回报，不自动恢复推进。

## 考虑过的替代方案

**把 run 结束视为工作验收。** 正常退出也可能产出错误或不完整的成果。提交与证据验收保持独立状态转换。

**用成员名表示依赖。** 一个成员可以负责多项任务，名字也会变化。稳定任务及尝试 ID 保留准确的前置任务和被验收成果。

**只用模型指令约束预算和重启行为。** 指令不能阻止丢失确认后的副作用。预约、准入检查及持久状态在原生执行前约束这些限制。

## 影响

已验收成果可释放后续依赖任务，无需轮询，也不阻塞协调者普通聊天。失败、被拒和不确定尝试保留证据及历史。正式任务不创建旧聊天自动任务行。

证据位置是供协调者或人类检查的记录，写入引用不代表已完成文件存在性或语义验证。尝试上限约束正式工作预约，不覆盖协调者全部推理步骤或 token 成本；不编造缺失用量。完整本地成果导航、改派/编辑、更完整上下文和真实 harness/浏览器验收仍在实施。本状态/服务切片不代表 M4/M5 验收或整个提案完成。

## 测试

测试覆盖验收后释放依赖、返工及迟到结果隔离、成员所有权、提交须已结算、证据门禁、分组/依赖循环、并发、尝试/时间预算、暂停/恢复计时、重启对账、重试身份、真实 Room 投递/回报组合、journal 持久化、实际活跃时间定时器、冷启动只读投影、恢复后的投递对账及确认丢失后的回报去重。客户端测试覆盖可选草稿创建、验收证据、会话/Stop 控制、对账、命令重试身份和叶子计数。
