# Agent Note: canvas-novel session-less write fence and dispose guard

Status: implemented

## Problem

A consumer mounting the novel engine per-instance on an isolated Context with its own `stateRoot` (the supported server-side consumption form documented in the README's「工作区接入接缝」) hit two gaps. (1) Every write verb hard-required a `Session` for the sandbox fence (`policyOf(session)` was mandatory), so a host-side caller with no conversation could not write at all — even though the fence semantics for a missing session are well-defined: the deployment default mode, the sidechat store's precedent. (2) There was no dispose guard: the service holds nothing but borrows its Context, and once instances are mounted and unmounted dynamically, a call after the mounting Context's teardown would silently operate on a dead scope — use-after-dispose had to become a coded refusal, not silent operation.

## Decision

All evolution is additive and generically named (no consumer vocabulary in code, types, or comments); the version stays 0.1.0; the client UI and the `novel_*` tool grant are untouched.

- **Session-less write fence** (`src/store.ts`): every write verb's `session` parameter widened to `Session | undefined` — `ensureRefs`, `writeCard`, `writeChapter`, `proposeOutline`, `decideOutline`, `editPlan`, `reviewChapter`, `starForeshadow`, `setCurrentState`, `confirmChapterPlan`, `extractImport`, `decidePending`, plus the private plumbing (`mutateJson`, `appendJsonl`, `writeRelation`, `materializePending`). The new `resolveFence(session)` is the one resolution point: with a session it is today's exact behavior (`sandboxPolicy.resolve({ session })`, exceptions and all); without one it calls `resolve({})` — the deployment default mode and the fallback root, no session id (the sidechat store's precedent; the real `SandboxPolicyService` on main resolves exactly this) — and `policyOf` re-roots the boundary at the plugin state root, the manuscript write at the work's workspace. The fence is never skipped: a read-only deployment default still denies. A policy home that throws on a session-less resolve refuses the write coded `denied` at the `mutateJson`/`appendJsonl`/`writeChapter` gates, before any fs call — never silently allows. `bindWork` keeps a mandatory session (what it binds IS the session). A session-less `writeChapter` has no cwd to attach a missing workspace from (the work must bring its own, else `no-workspace`) and lends no id (`sessionIds: []` on create).
- **Canvas card verbs forward the optional session** (`src/genre.ts` slice): `proposeCard`/`patchCard` accept `FenceSession | undefined` — the engine forwards what it got, and the canvas's own fence stays the canvas package's business (the real service's `resolve({ session: undefined })` is the same deployment-default path). The `canvasBoardOf` probe stays a per-call probe, never an import or dependency.
- **Dispose guard**: `NovelDisposedError` (coded `'disposed'`, package-named through the `PACKAGE_NAME` now exported from `invariant.ts`, itself exported from the package root); `dispose()` is idempotent and terminal and is also wired to the borrowed Context's teardown via `ctx.effect` in the constructor. `assertAlive` sits on EVERY public verb, reads included, so a mounting side never keeps consuming a stale instance; the write boundary — `assertAlive` immediately before every fs write in `mutateJson`/`appendJsonl`/the `writeChapter` body write, deliberately OUTSIDE the try that maps fs errors onto codes — closes the in-flight race: a write either completed before the boundary or refuses there with the coded error, never reaching the disk a rebuilt instance owns. A same-root rebuild stays legal (the disposed instance alone stays dead).
- **Eager fs made honest**: `static inject = ['fs']` already meant cordis never mounts the row without a filesystem, but a direct `new NovelService(ctx)` on an fs-less Context surfaced a property-access TypeError (`ctx.fs` returns undefined on cordis 4). Construction now throws a package-named error naming the contract at once.
- **Tests** (`tests/sessionless.spec.ts`, 14 new): the hand-mirrored policy home (kept as the readable member list) pins the default re-rooting, the no-id-lent shape, both read-only refusal layers (the fs denying the registration vs the service layer refusing the manuscript before any fs write), the cannot-resolve coded refusal with zero fs writes, the unchanged session-passed half, and the eager-fs construction. The REAL chain suite (a true `SessionProjectionRegistry` feeding a true `SandboxPolicyService` on a real cordis Context, the canvas workspace spec's precedent) pins session-less resolution end-to-end — deployment default mode, re-rooted boundaries, never a session id — and the read-only denial, so a harness release that changes session-less resolution turns this suite red before a consumer finds out. The dispose tests pin every public verb refusing the coded package error, idempotence, Context-teardown disposal, the in-flight write race refusing at the boundary with nothing left behind, and the same-root rebuild.

## Alternatives considered

- **Widening the Remote twin** (`remote.novel.*` writes take `agent: Agent` today): rejected by the same typert boundary rule sidechat hit — the wire's agent lookup parameter cannot be optional. The wire always has a browser session behind it, so the calling-less form exists only host-side on `ctx.canvasNovel`; the Remote surface keeps its mandatory agent and the generated typert faces are byte-identical.
- **A `'disposed'` `NovelError` return code instead of a thrown error**: reads return shapes without an error channel (`WorkMeta | undefined`, plain arrays), so a return-shaped code would be invisible there or force every signature wider; a thrown coded package error is the reader/sidechat precedent and covers reads and writes uniformly.
- **Deferring fs the sidechat way** (`ctx.inject(['fs'])` with a memory-only degrade): the novel engine has no memory-only mode worth having — every verb is a state operation and a silently non-persistent engine would betray the work memory's whole promise. The honest behavior is the eager inject, now with a named construction error.
- **Guarding only the writes post-dispose**: reads answering stale state after unload would let a mounting side keep consuming a dead instance indefinitely; the delivery condition is that EVERY public verb refuses, reads included.
- **A session-less-capable `bindWork`**: the verb binds the calling session itself; without a session there is nothing to bind, so the parameter stays mandatory rather than gaining a meaningless form.

## Consequences

- `NovelService`'s write verbs accept `Session | undefined`; `NovelDisposedError` and `dispose()` are new public surface; `PACKAGE_NAME` is exported from `invariant.ts`; the genre slice's `proposeCard`/`patchCard` take an optional fencing session. The Remote and tools surfaces are unchanged, and all 162 pre-existing tests pass unmodified (176 total, 14 new).
- A session-less write is fenced exactly as strictly as the deployment default demands (typically the strictest applicable mode), and omitting the session can never skip the fence — the worst case is a coded `denied`, never a silent allow.
- The mounting side owns the instance lifecycle: disposal follows the borrowed Context (or an explicit `dispose()`), in-flight writes either complete before the write boundary or refuse there, and a rebuild over the same state root is a new instance's business.
- Local behavior with a session passed is byte-identical; the client UI and the `novel_*` tool grant were not touched.
