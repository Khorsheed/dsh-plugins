# Agent Note: datasets exports the service factory and the Remote class for instance mounting

Status: implemented

## Problem

A consumer mounting dataset storage per-instance on an isolated Context needs to build a service over its own roots and mount the native Remote face on the same Context. An earlier source audit concluded "the factory exists, zero changes needed" — but it read the SOURCE, not the ARTIFACT: `createDatasetsService` (`src/service.ts`) and `DatasetsRemoteService` (`src/remote.ts`) were imported by `src/index.ts` for `apply` but never exported, so importing the packed tarball's root resolved `undefined` for both (re-verified against this package's packed 0.2.0-rc.1 artifact before this change). The instance-mounting consumption form was unusable from the public surface.

## Decision

Purely additive public exports from the package root (`src/index.ts`), reusing existing names, moving nothing, changing no behavior; the version stays 0.2.0-rc.1; `apply`, the deployment-default root resolution, and the wire surface are untouched:

- **`createDatasetsService`** — the service factory, with the option/scope types **`DatasetsServiceOptions`** (the four roots: `registryPath` / `bindingsRoot` / `materializedRoot` / `proposalsRoot`, plus the optional `organizing` and `capabilities` overrides), **`DatasetsService`**, **`DatasetScope`**, and **`OrganizingSetup`**.
- **`DatasetsRemoteService`** — the native Remote face (wire namespace `datasets`) whose constructor is the mounting entry on an isolated Context, with its config type **`DatasetsRemoteConfig`** (empty since T73).
- **`DatasetsDisposedError`** and the capability types (**`DatasetsCapabilities`** / **`DatasetsCapabilityAvailability`** / **`DatasetsCapabilityGroup`** / **`DatasetsCapabilityOverrides`**) — added with the dispose guard and the capabilities descriptor below.
- **No Remote verb takes an Agent lookup** — verified by reading all 30 verbs and pinned by test: every verb takes a plain request object (a registration id plus dataset/item/path/commit), and the single host probe is `organizingSetup` reading the `agentPresets` registry SLICE (`list` / `readDocument` / `defaultId`, T102) through `ctx.get` — preset documents, not agent instances; a missing or broken slice degrades to `preset: ''` and never throws. There is therefore no agent-carrying verb to document as unadmitted.
- **Tests** (`tests/instance-exports.spec.ts`, 4): two instances built from the public factory over disjoint registry/bindings/materialized/proposals roots leak nothing across (registrations, reads, writes into the authoring checkout, the legacy-bindings import, materialized views, proposal stores); the Remote class mounts on a bare cordis Context over the instance service and serves only that instance's registry; a recording/poisoned `ctx.get` stub proves the browsing and registry verbs probe no host surface at all, that `organizingSetup` probes exactly `agentPresets` (fail-open when it is absent or throwing), and that a configured `organizing.preset` answers without probing anything.
- **The write boundary is decided on real paths** (`src/safe-write.ts`, added with the boundary hardening): every working-tree write (`putItem`, the skeleton gestures, `importItem`) goes through `writeFileWithinRoot` — the root realpathed once per operation, parent directories `lstat`-verified component by component and created by single-level `mkdir` (a symlink is never followed during creation, so a refused write leaves no partial tree outside), the write a temp file + atomic rename with the parent's realpath re-verified after the temp write and the target's after the rename (a directory swapped for a symlink in either window fails the write coded `PATH_ESCAPE` and the escaped artifact is removed). `importItem`'s source reads go through `readFileWithinRoot` — `O_NOFOLLOW` at the open plus a realpath containment check — so a source substituted between enumeration and read fails closed. Ordinary repositories (no symlinks) behave byte-identically.
- **The dispose guard** (the library/eval family pattern): `DatasetsService.dispose()` is idempotent and terminal, wired to the borrowed Context's teardown by `apply`'s `ctx.effect`; afterwards every public verb refuses with `DatasetsDisposedError` (`code: 'disposed'`, package-named), reads and the `registry` / `proposals` / `organizing` / `bindingsRoot` accessors included (they are guarded getters, so every Remote verb refuses too); a write in flight when dispose lands refuses at the write boundary (`writeFileWithinRoot`'s guard hook runs the service's `assertAlive` immediately before the temp write); a rebuild over the same roots is legal.
- **The capabilities descriptor**: the Remote `capabilities` verb (one additive wire addition) returns `{ protocolVersion: 1, registration, fileWrite, agentOrganize, bindingImport, proposalReview, delete }`, each group `{ available, reason? }` — default all available, no reasons. The mounting side marks groups unavailable via the factory's `options.capabilities` or the plugin config's same-named key (a group id → its reason string; schemastery `z.dict(z.string())`, default `{}`); the tab fetches it once and hides those gestures with the reason in their place (fail-open when the face member is absent — the injected contract's `capabilities` is optional so older doubles still type). A display contract only: the server's admission rules are unchanged. The tab carries no fileWrite gesture since T90, so that group has no client consumer.
- **Tests for the hardening** (`tests/write-boundary.spec.ts`, 15; `tests/DatasetsView.client.spec.tsx`, +4): the probe scenario (a symlinked `datasets/` refuses Remote `scaffoldDataset` coded with nothing outside), the same refusal through every service write verb, a deeper-chain symlink and a symlinked target file, the controlled check→write swap via the boundary module's `guard` hook (the escaped temp is removed), source substitution at the open (`O_NOFOLLOW`) and a swapped intermediate directory, temp+rename inside the root with no leftovers, keepExisting unchanged, dispose (coded refusals, idempotence, the in-flight write race, same-root rebuild, the `ctx.effect` wiring, Remote verbs over a disposed service), and the descriptor (default, overrides, the plugin-config path, post-dispose refusal, tab hiding with reasons). Two genuinely-required expectation updates in `tests/tool-groups.spec.ts`: the hand-built ctx mock gained a no-op `effect` (apply wires disposal now), and the `Config` default assertion gained `capabilities: {}`.
- **Tarball verification**: packed with `scripts/pack-dist.ts` (`--family auto`), unpacked to a scratch dir inside the package, root imported with plain node — the factory and the class resolve, the published `.d.ts` names every exported type, a two-root instance pair constructs, and the face mounts on a bare Context; the scratch dir was removed afterwards.

The generated typert host face's `model.services` catalog now lists `datasets` and `datasetsRemote`: the generator catalogs a cordis-augmented service once its type is publicly exported (the analyzer's `collectServices`), which is exactly the shape eval (`dshEval`) and mission (`mission`, `missionRemote`) already ship. The wire face grew exactly once since: the additive `datasets/capabilities` verb and its descriptor schema (this delivery); every pre-existing invocation is unchanged apart from `sourceLocation` line shifts. The README's 「工作区接入接缝（按实例挂载）」 section documents the factory, the independent-roots construction, the Remote mount, the no-Agent answer, what stays deployment-default via `apply`, the rule that two instances must not share one `authoringCheckout`, the write-boundary guarantees, the capabilities descriptor's semantics, and the dispose guard.

## Alternatives considered

- **Extending `apply`'s config to cover all four roots**: the factory is the consumption entry for isolated instances, and the local default root resolution must not move — a config that could reroot the deployment's registry would couple the two consumption forms for no benefit, and every added key would be a new way to misconfigure the local path.
- **Exporting only the factory and leaving the Remote face internal**: the consumer would have to rebuild the wire face or run its own adapter over the service; the class's constructor already IS the mount entry, so keeping it private would just force a copy.
- **Enlarging the export set to the wire payload types** (`ListRequest`, `ShowResult`, …): not needed for the seam — those already ship from the `./types` subpath; the root export stays the minimal construction surface.
- **Consumer-vocabulary names for the new surface** (workspace/cloud-flavored export names or option keys): rejected by the naming rule — the seam is generic; no consumer's vocabulary enters this package's code, types, or comments.

## Consequences

- New public surface, all re-exports of existing declarations: `createDatasetsService`, `DatasetsServiceOptions`, `DatasetsService`, `DatasetScope`, `OrganizingSetup`, `DatasetsRemoteService`, `DatasetsRemoteConfig`, and (with the hardening) `DatasetsDisposedError` plus the capability types. The plugin row's behavior, the CLI, the slash handler, the tool row are untouched; `apply` gained only the dispose wiring and the `capabilities` config pass-through.
- A consumer can now run several independent instances on one host with disjoint registries and caches, and mount the native Remote face on each — the cross-instance isolation and the no-Agent-lookup property are pinned by the new contract test.
- The host-face introspection catalog grows by two service entries (metadata only); the wire face's one addition is `datasets/capabilities` — additive, and both halves ship from this one package, so halves never mix across it.
- The write boundary fails closed on symlinked components and check→write swaps, leaving nothing outside the repository root; the cost is two extra realpath calls per write (write verbs are human gestures or per-file authoring calls, both far from hot paths). Ordinary repositories behave byte-identically; the full suite is 35 spec files / 411 tests (15 new host-side, 4 new client), and the tarball check re-verified the packed root end-to-end (factory, Remote mount, descriptor, the symlink refusal, the dispose guard).
- A disposed instance refuses every verb coded; the in-flight race is pinned at the write boundary. What dispose deliberately does NOT do: remove partial in-root mkdir trees of a refused write (the same shape any failed write always left), or unregister the Remote face out from under a caller — that is the fiber's teardown.
- The write-race caveat is documented, not enforced: two instances pointing at one `authoringCheckout` are two writers on one working tree, and the plugin never commits — keeping the boundary is the consumer's obligation. The capabilities descriptor is likewise a display contract: the tab hides what it marks unavailable, and the server's own admission rules (and a gateway's unadmitted set) enforce regardless.
