# Agent Note: 在首次提示前准备原生成员

Status: implemented

## 问题

新邀请的外部协调者在用户发送真实提示前没有子会话身份，设为协调者因此依赖无关的测试对话，模型控件和原生会话就绪也没有共用的准备边界。

## 决策

Local-agent core 在付费执行前预留持久成员绑定和子会话记录。四家 live provider 使用原生初始化和控制接口准备：Codex 创建线程，Kimi 创建并配置 ACP 会话，Claude 初始化 stream-json 控制，自有 DSH headless 进程通过准备请求校验模型，不创建 agent 或发送提示。

准备绑定父会话、provider、工作目录、scope 和创建配置。相同的并发请求合并，不同身份被拒绝。认证存在性检查、配置准入和严格会话持久化完成后才标记就绪。显式重复准备会先对账失败的执行前配置再重试，绝不重放已经进入执行的身份。

首次 start 让出执行前，原子磁盘状态从 ready 改成 starting。第一次付费轮次消耗相同子会话身份及其最新准入配置。即使最终 used 标记写入失败，已发布运行仍被跟踪；先前的 starting 标记继续阻止重复执行。预备成员的模型目录使用自己的绑定上下文，不借用其他成员的观测模型。

Room 设定协调者时自动准备新邀请成员，失败不改变角色。交接期间阻止房间输入及成员编辑，并要求新旧双方配置均空闲且已收敛。已有成员会话继续走正常 resume 路径。

## 考虑过的替代方案

**发送测试提示来建立就绪状态。** 会增加无关轮次和费用，污染协调者历史。原生初始化可以在不生成内容的情况下提供所需身份及控制检查。

**只在 room 内存中预留 ID。** 重启可能丢失绑定或意外重复启动。Core 持有 provider 共用的持久身份和准入屏障。

**把原生初始化视为认证生成已通过。** 初始化和模型控制可能在没有端到端推理请求时成功。真实认证验收仍须单独完成。

## 影响

首次对话前即可配置并选择成员。准备失败可显式重试，首次执行结果不确定时继续阻断。空闲原生进程可被回收，首次真实轮次按需重建空原生会话，同时保留持久 dsh 子会话身份。不修改宿主源码。

本次只完成协调者就绪合同中的准备部分。完整协调工具和权限、共用消息队列、目标编排及真实浏览器认证验收仍未完成。Provider 协议 fixture 和 core/room 测试覆盖无提示准备、首次轮次复用、认证及持久化失败、重试、身份冲突、并发首次启动和切换失败后路由不变。
