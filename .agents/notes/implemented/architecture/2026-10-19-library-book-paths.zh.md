# Agent Note：图书馆——路线只属于教材（项目不带路线）

Status: implemented

## 问题

v5 让路线有两处归属：厚资源自己的路线（`primaryResourceId`），或项目自己的路线（缺省），工具再从 covers 推导落点：每站都只用同一本资源就落到那本上，混了别的就落到项目上。3080 上（2026-10-19）教练为《普林斯顿微积分读本》起草路线，带了一个附录阅读站（`topic:` 来源），推导把整条路线送到了项目上。教练发现后改在书上重写了一份，却没撤回前一份；用户在项目页采用的是项目那份——而教练报告的是「已落在本书路径上」。路线两个家、一个看不见的推导在二者间选、两份草稿可以并存：模型和用户都可能错而不自知。

## 决定

按提案（[proposals/active/2026-10-19-library-book-paths.md](../../../proposals/active/2026-10-19-library-book-paths.md)），与用户讨论定论：

- **路线只属于一本教材**——有目录的资源（v5 的厚资源）。项目不带路线：只有 `roadmaps/<resourceId>.json`；遗留的 `roadmaps/project.json`（或根目录 `roadmap.json`）读作不存在，`writeRoadmap` 拒收不带教材的路线。作用域推导（`deriveRoadmapResource`）和「资源自己的路线只能覆盖它自己」及其镜像规则一并删除；`library_roadmap` 的 `resource` 在 schema 层必填。
- **站用 `chapters: "3-4"` 写本教材的行**，用 `also: [url | "r_…#2" | "topic: …"]` 写附带引用，二者都展开成存储的 covers。附带引用从不挪动路线；出题的原文闸在站有本教材来源时只按本教材判（附带一个视频不再让知识型章节变成必须引原文）。两样都不写的站视为整本教材。路线不必覆盖整本目录；没覆盖的行在教材页折叠进「本路线不学」。
- **教材来源由教练决定**——`origin: learner | picked | authored` 取代 `addedBy`（旧的 `coach` 读作 `picked`）：用户自己的书、教练挑的现成书或电子课程（只学部分章节也可以）、或教练自编的大纲（讲义即正文）。电子还是纸质仍由 `kind` + `url` 表达。
- **学习顺序是 `seq`**，在项目的教材上从 1 起连续编号：上架时分配（显式 `seq` 即插队，否则排最后），`library_resource op: "move"` / 侧栏 ▲▼ 调序，删除时后面的前移。顺序是建议，不加锁。不加科目标签、不设科目层——用户的判断：科目定义不完，按要学的内容找教材即可。
- **一本教材一份草稿**——新草稿覆盖旧草稿（工具结果带 `replacedDraft`）；项目页列出所有有待采用草稿的教材。
- **模型永远读到真实状态**：不往会话推「已采用」事件，而是每轮的 `Library:` 上下文按学习顺序列出每本教材的路线状态（已采用 n/m + 当前站、草稿待采用、还没有路线）。`bindingSummary` 以 `textbooks` 取代 `progress`。
- **提示词与工具瘦身**：`tool:library` 段从约 6.5k 字符降到约 1.9k——只讲旅程（项目 → 按序教材 → 每本一条路线 → 讲 → 考 → 判）与红线；逐个调用的规则只写在各自工具描述里（出题细则在 `library_quiz`、拍照在 `library_page`、弱点在 `library_cards`、讲义在 `library_notes`）。工具描述 + schema 从约 25.5k 降到约 21k 字符；整段 JSON 文本的传输分支保留（会把嵌套参数串成文本的模型仍需要）。`library_binding` 扁平化（`project`、`resource`、`unbind`）；`from` 克隆和 `covers` / `chapterRanges` / `addedBy` 的写法仍能解析，只是不再出现在参数表里。学习模式人设里「为项目织一条路线」那段改为：选书或自编教材、按学习顺序编号、每本一条路线。

## 界面

项目页去掉项目路线卡与项目草稿卡，改为：继续学习（按顺序第一本有当前站的教材）、待采用草稿横幅、编号的教材列表（来源标记、进度、当前站）与调序模式、资料链接。空项目给出「我有书 / 帮我选教材」两条路。今日加一张跨项目的继续学习卡。删除项目从编辑表单底部挪到页面菜单；删除项目或教材都弹确认框，列出会删掉什么（教材、卡片及到期数、作答记录、链接 / 路线进度、拍照页、测验）和保留什么。教材页显示编号与来源，采用按钮写作「采用为本书路线」，并折叠不学的章节。站一定属于某本教材（路由的 `resourceId` 必填）。

## 考虑过的方案

- **两处归属都留，修推导**（只按考查站判作用域、撤回同项目其他草稿）：否决——错误变少，但那个看不见、模型仍会选错的选择还在。
- **独立的「课程」实体、书只作素材**（讨论中的中间稿）：否决——没有主教材的课程就是换了名字的项目路线；教练既然能自编教材，多这一层没有收益。
- **项目与教材之间加科目标签或科目层**：用户否决——科目定义不完，模型还要多做一次归类判断。
- **教材之间的先修图**：否决——编号已经说清顺序，对用户和模型都更轻。
- **往绑定会话推送采用事件**：否决——每轮上下文本来就在；在那里写明每本教材的状态，采用、放弃、调序一并覆盖，不需要新的宿主接缝。

## 后果

- 数据：上线时生产数据为空（用户已删掉历史项目），因此没有迁移步骤；残留的项目路线只是不再被读取。
- Remote 面：`getRoadmap` / `adoptRoadmap` / `discardDraft` 必须带 `resourceId`；新增 `moveResource`；`putResource` 接受 `origin` / `seq`。
- 自由测验（不挂教材、不挂站）与教材级测验不变。
- [图书馆 v5](2026-10-17-library-v5-model.md) 里「每个作用域一条路线」那条由本 note 取代；v5 其余部分不变。

## 测试

包内 153/153 全绿。store.spec.ts 钉住按教材存路线、退役的项目路线读作不存在且拒写、origin / seq 的规范化（旧 `addedBy`）与书架顺序。service.spec.ts 覆盖必须带教材的草稿（拒收信息列出书架）、一本教材一份草稿、站内附带引用不挪动路线、链接不能有路线、seq 的插队 / 调序 / 越界 / 删除后前移，以及绑定摘要的教材列表。tool.spec.ts 覆盖 `chapters` / `also` 展开、必填的 `resource`、`replacedDraft` 与 `waitingForAdoption`、`op: "move"`、带 `unbind` 的扁平绑定，以及每轮上下文列出另一本教材的待采用草稿。界面在侧栏 fixture（`examples/sidebar`）里按手机宽度明暗两套核对过；本包 `check:panels` 无问题。
