# Agent Note: eval instance-configurable state root and disposing run jobs

Status: implemented

## Problem

A consumer mounting eval per-instance on an isolated Context (the supported server-side consumption form the README's「工作区接入接缝」now documents) needs each instance to own its eval state tree. Before this seam, the state root was DSH_HOME-global only: `EvalService.stateRoot()` derived everything from `defaultStateRoot()` — experiments, the condition library, and every run's per-cell directories — so two instances on one host could never see disjoint state, and the throw-when-DSH_HOME-unset behavior was the only answer a rootless mount could get. Two further gaps came with per-instance mounting. (1) The Remote `runStart` options omitted `stateRoot` even though `RunOptions.stateRoot` existed, and nothing constrained a per-run cell root to the instance's boundary — a mounted instance could be pointed at writes outside its own tree. (2) `EvalService` had no `dispose()`: nothing cancelled a live run short of process exit (the run jobs are registered unowned by design so they outlive their starter), so an instance being unmounted had no way to stop the runs IT started — while a registry-wide sweep would wrongly kill runs other instances started.

A follow-up gap surfaced on the first real remote-execution topology: eval's fairness evidence was read from LOCAL directories — provision resolved the scoped home through `localAgent.homeDir` and fingerprinted it with `hashHome`, graded the credential and read the effective settings through the same facade, and the readiness/validate freshness checks hashed the scope's preset copy off the local disk (`hashPresetTree(scopePresetDir(...))`). When the credential scope lives on the execution target, the same-named path on the managing process is a different environment, and copying keys, faking a local home, or skipping the fingerprint checks are all rejected answers.

## Decision

All evolution is additive and generically named (no consumer vocabulary in code, types, or comments); the version stays 0.2.0-rc.1; the `./tool` entry and the lab/datasets/mission packages are untouched.

- **Instance-configurable state root** (`src/service.ts`): `EvalService` gains an optional second constructor argument `config: { stateRoot?: string }`, canonicalized at construction by `containmentPath` (absolute, `~` expanded, realpathed as far up as the tree exists, so boundary checks compare real locations). Every call site of the root was audited: the eleven verbs reading through `this.stateRoot()` (experiment records, experiment roots, judge prompts, the condition library listing/diff/endpoint/provision, drafts, imports, started-by checks) reroot by construction; the two degrading call sites that read `defaultStateRoot()` directly — `experiments()` and `experimentOfRun` — now go through a private `defaultedStateRoot()` (instance root when configured, else the DSH_HOME-derived one); `EvalRunJobs`'s working-directory derivation (`runWorkDir`'s fallback) takes the instance root through a new optional second constructor argument; and `runPlan`'s own `options.stateRoot ?? defaultStateRoot()` fallback is never reached from the service path because the service injects the default. Unset keeps byte-identical legacy behavior, including the `EvalReadRefused` "set DSH_HOME" throw. No global mutable state: two instances with two roots see disjoint experiments, conditions and cells.
- **runStart plumbing + containment** (`src/service.ts`, `src/types.ts`, `src/remote.ts`): `resolveRunStateRoot` sits at the service boundary of `run` and `runStart` (so `runExperiment` / `runExperimentStart` / `approve` are covered through them). With an instance root, an absent `stateRoot` defaults to it; a given one must resolve UNDER it — compared by `containmentPath` on both sides, so a `..` segment and a symlink laid inside the root both fail with `EvalRunRefused` carrying the coded diagnostic `STATEROOT_OUTSIDE_INSTANCE`, before any job registers. Without an instance root the option passes through unchecked (today's semantics). The Remote `runStart` request gains the optional `stateRoot` field and carries it across verbatim; the containment check stays host-side. The Typert wire schema regenerated with the field optional — old clients are unaffected.
- **dispose** (`src/service.ts`, `src/run/job.ts`, `src/index.ts`): `EvalDisposedError` (coded `'disposed'`, package-named through `PACKAGE_NAME`, now exported from `invariant.ts`; the error class is exported from the package root). `EvalService.dispose()` is idempotent and terminal, and `apply` wires it to the borrowed Context's teardown via `ctx.effect`. It delegates to `EvalRunJobs.dispose()`, which cancels exactly this instance's not-yet-settled records through the ONE cancellation entry — the registry kill → the job's cancel hook → the run's AbortSignal — so a live run stops starting cells and the caught cells finalize `interrupted` through the normal path (never a force-kill), and a run that opened its own parent session still releases it in its settle path. Jobs other instances started are untouched: the unowned-by-design registration is unchanged and dispose never widens into a registry sweep; settled jobs are skipped; there is never a resume (re-run was already the design). `assertAlive` guards EVERY public verb, reads included. The start-vs-dispose race is closed at the job layer's last await: `EvalRunJobs.start` re-checks disposal after resolving the parent session, releases a session it just opened, and refuses; `runStart` translates any failure surfacing after disposal into the coded `EvalDisposedError`, so a racing start registers nothing.
- **What stays deployment-global**: the credential/scoped-home path (the localAgent facade's `homeDir(harness, scope)`) is untouched and outside eval's root by design; the mission ledger and the registered dataset repositories likewise bind nothing to the instance root.
- **The execution target's evidence face** (`src/faces.ts`, `src/provision.ts`, `src/capability-probe.ts`, `src/run/readiness.ts`, `src/contract/validate.ts`, `src/run/run.ts`, `src/service.ts`): the config gains `evidence?: ScopedHomeEvidenceFace` — five optional verbs answering, as plain JSON-able data, exactly what the local reads produce: `homeHash` (`hashHome` plus the producer-side home identity), `credentialGrade` (`statusOf`'s grade), `effectiveSettings` (the facade snapshot), `rosteredPreset` (`readScopePreset`) and `presetSnapshot` (the `scopeKeepsOwnPreset` / `scopePresetProblem` / `hashPresetTree` trio as one answer). With a face mounted, provision, the capability probe, the readiness gate's copy-freshness, and validate/conditions' freshness check consume the face INSTEAD of local directories — a mounted face is the whole evidence source for its scopes, so a missing verb, an unanswered or misshapen answer, or a throw each lands exactly where the corresponding local failure lands (the "cannot read the home" refusal, "no lock against an ungraded credential", "uncomparable, recorded", "the locked record stands"); no same-named local path is ever resolved, because on that topology it is a different environment. Parity is structural: the producer runs the same `hashHome`/`hashPresetTree` over the home it can see, and the pinned fixture provisions byte-identical locks through both paths. `RunDeps.evidence` threads it into the readiness gate; `ConditionReadinessOptions.scopePresetSha` is validate's additive hook (preferred over `scopeHomeDir` when both are present). The composition write (`localAgent.provisionScope`) is not evidence and stays on the facade, so a preset-copy condition still needs the vouch from it — without one the measurement declines and the gate refuses, fail-closed as before. Unmounted, every local read behaves byte-identically.
- **The producer-side factory** (`src/evidence.ts`, exported from the package root): `produceScopedHomeEvidence(homeDir, { preset? }) → ProducedScopedHomeEvidence` — the face's three filesystem-derived answers (`home`, `rosteredPreset`, `presetSnapshot`) computed by the package's own algorithms, so a producer on the execution target reuses them instead of copying implementations. The input is a caller-authorized ABSOLUTE path (a relative one is refused — what it would resolve to depends on a cwd nobody verified); the factory has no default home and derives none. Fail-closed parity is the local reads' own: a missing home propagates `hashHome`'s throw, no roster is `rosteredPreset: undefined`, no kept copy is `{ keepsCopy: false }`, a copy that cannot be a subject carries `scopePresetProblem`'s text with NO digest (the digest is computed only for a usable copy — the consumer's own order), a copy that is not a plain tree carries no digest. `credentialGrade` and `effectiveSettings` are deliberately not the factory's business: they are the caller's own auth implementation, not files this module may infer. Verified against the packed tarball: pack-dist output unpacked to scratch, imported with plain node, factory resolved and run against a fixture home.
- **The execution-home port** (`src/faces.ts`, `src/run/unit.ts`, `src/run/run.ts`, `src/service.ts`): the config gains `executionHome?: ExecutionHomePort` — one verb, `planScopedHomeMount`-wrapped `planScopedHome(request)`, owning exactly the unit path's three scoped-home decisions: RESOLUTION (the answer's `mount.source` is opaque — a volume name or a target-side path — handed to lab verbatim and never resolved or stat'ed by this process), AVAILABILITY (answering at all is the verification; `checkCredentialsDir` does not run), and the MOUNT plan (`type: 'bind' | 'volume'`, optional `readonly`). The request carries the REGISTERED identity — condition id, harness, scope, the reviewed in-container mount point and variable, and the plan's unit uid — never a caller-supplied volume name or local directory. `resolveCellUnit` keeps its signature (fifth optional `mount` parameter); `CellUnitPlan.scopedHome.host` now documents itself as the mount source (a host path by default, the port's opaque reference with a port), and `acquireSpecFor` consumes `plan.mount` — absent means `bind`, byte-identical. Fail-closed at unit-planning time, before any acquire: no verb or a throw → `EXECUTION_HOME_UNAVAILABLE`; undefined → `EXECUTION_HOME_UNKNOWN`; a misshapen answer → `EXECUTION_HOME_INVALID`; the contract diagnostics (`UNIT_SCOPED_HOME_*`) run first and unchanged. The identity pin with the evidence face: when BOTH seams are mounted, the evidence answer's `homeIdentity` and the port answer's `homeIdentity` must both exist and be equal — otherwise `EXECUTION_HOME_EVIDENCE_MISSING` / `EXECUTION_HOME_IDENTITY_MISMATCH` — so evidence measured on target X can never pair with a mount planned for target Y. The controller/worker boundary was verified before the shape was fixed: the delegation side receives only `exec: { container, workdir, env: { VAR: in-container path } }` plus the scope NAME (cell-once.ts), and the unit annotation records container+var only — the home reference crosses solely controller → lab in the acquire spec, so no credential material and not even the mount source ever reaches the worker side; the port preserves that boundary by construction (its request and answer carry names and plans, never bytes). Cancel/finalize paths never saw the mount: a port-planned run cancelled mid-cell shows the same interrupted shape (the cancelled cell keeps its unit for the release gate later), and the lab verb trajectory is the non-port run's own.
- **Tests** (`tests/state-root.spec.ts`, 10; `tests/evidence-face.spec.ts`, 21; `tests/execution-home.spec.ts`, 12; plus 5 in `tests/run.spec.ts`): two instances with different roots see disjoint experiments/conditions/list rows; the unset root keeps the DSH_HOME default and the throw-when-unset; runStart defaults the cell root to the instance root and accepts one under it; the containment refusal fires on a plain outside path, a `..` escape, and a symlink laid inside the root — coded, before registration; with no instance root the option passes through and DSH_HOME stays the default; the Remote verb carries stateRoot across and surfaces the refusal; dispose cancels this instance's blocking fake run through the AbortSignal (the interrupted cell lands on disk before the job settles `killed`), leaves the other instance's job in the same registry running, is idempotent, refuses every sampled verb coded and package-named, leaves settled jobs alone, follows the Context's teardown, and the racing start refuses coded with nothing registered and the just-opened parent session released. The evidence suite's producer IS the shipped factory (`produceScopedHomeEvidence`) since the factory landed — the parity tests run it through the JSON boundary into the face. It pins parity (preset-less and preset-carrying conditions provision byte-identical locks through the face and through local reads, the capability record included, and the facade's local reads never fire), the fail-closed matrix (missing `homeHash`/`credentialGrade`/`effectiveSettings` verbs, absent and misshapen fingerprints, an ungraded or out-of-vocabulary credential, a mismatching effective answer, a drifted preset-copy digest failing the readiness gate before any delegation, a matching one passing, and a face without `presetSnapshot` leaving the locked record standing), the JSON-boundary cross-process shape, the composition with the instance stateRoot (the lock lands under the instance root while every evidence read goes to the face; the freshness check reads the target's digest and a drift there is `CAPABILITIES_SNAPSHOT_STALE`), and the factory itself (byte-identical answers to the local algorithms over the same home; keepsCopy false with no copy and undefined roster with none; the malformed composition carrying the problem text and no digest; the not-a-plain-tree copy carrying none; relative path refused; a missing home propagating hashHome's throw; and a decoy second tree plus a poisoned DSH_HOME never consulted). The port suite pins the mount plan flowing into the acquire spec verbatim (volume source/target/type, nothing bind-shaped; a bind-shaped port plan honored too), the coded refusals (unknown identity, unavailable port, invalid answer, contract diagnostics first with the port never called), the identity pin (equal tokens pass; mismatch, a missing port token, and a face that cannot answer all refuse coded), and — in run.spec.ts, beside the container loop it extends — the volume-backed whole-loop run with NO local home staged and `homeDir` never called, the coded refusals before any acquire, the matching-identity pass, and the cancel path's unchanged interrupted shape. The one pre-existing accommodation: `plugin.spec.ts`'s hand-built ctx mock gained a no-op `effect` (apply wires `ctx.effect` now) — mechanical, no expectation changed.

## Alternatives considered

- **A `stateRoot` on `RunDeps` instead of the service boundary**: `RunDeps.stateRoot` already exists but is dead (nothing reads it), and routing through it would leave the Remote path and the job layer's working-directory fallback to duplicate the default; defaulting at the service's `run`/`runStart` boundary covers every face (slash, Remote, approve, direct) with one rule.
- **Lexical-only containment (no realpath)**: the package's own artifact reader already learned that a symlink inside the tree defeats a lexical check (`cell-artifact.ts` realpaths both sides for exactly that reason); `containmentPath` realpaths the nearest existing ancestor so a not-yet-created cell tail still compares honestly.
- **Guarding only the write verbs post-dispose**: reads answering stale state after unmount would let a mounting side keep consuming a dead instance indefinitely; the delivery condition is that EVERY public verb refuses, reads included (the library/canvas-novel precedent).
- **Constructor wiring of the Context teardown (the canvas-novel shape)**: `EvalService`'s host accessor is deliberately structural — the CLI builds `new EvalService()` with no hosts at all — so structurally probing `effect` would be magical; wiring in `apply` (the sidechat shape) covers the documented consumption form (`apply(isolatedCtx, config)`), and a directly constructed instance is disposed explicitly by its owner.
- **Cancelling through `controller.abort()` directly in dispose**: the registry kill IS the one cancellation entry (it marks the job stopping and keeps `job_kill` the only stop verb); going around it would split the stop semantics. The direct abort remains only as the fallback when the registry itself errors on the kill.
- **Restart recovery for cancelled runs**: rejected by the existing design, unchanged here — a stalled or cancelled run is re-run, never resumed; mid-stage cells finalize `interrupted`.
- **Copying credentials, faking a local scoped home, or skipping the fingerprint checks on the target topology**: all three were rejected by both sides before this seam was designed — the first leaks secrets across a boundary, the second fingerprints the wrong environment, the third abandons the fairness evidence the checks exist for.
- **A per-verb local fallback when a mounted face lacks a verb**: rejected — the whole reason the face exists is that the same-named local path is a DIFFERENT environment on this topology, so falling back to it can silently pass a check against the wrong tree. A mounted face is the whole evidence source for its scopes; a missing answer maps to the corresponding local failure's outcome instead (the refusal, the uncomparable record, the standing lock).
- **Resolving the evidence face through the host accessor (`hosts.get`)**: the face is per-instance — each mount has its own execution target — so it travels in the constructor config beside `stateRoot`, not through the shared service namespace two instances would collide in.
- **Exporting the five producer internals (`hashPresetTree`, `readScopePreset`, `scopeKeepsOwnPreset`, `scopePresetDir`, `scopePresetProblem`) from the package root**: rejected in favor of one factory. Five loose functions invite a producer to call them in the wrong order (digest before problem, or a digest of a copy that cannot be a subject) and freeze five signatures as public API; `produceScopedHomeEvidence` reuses the same internals, preserves the consumer's check order, and leaves exactly one new runtime export.
- **A literal bind→volume string swap (a `mountType` option on the run)**: explicitly rejected — it would change the mount TYPE while leaving resolution and availability on the management host, so a named volume would still be preceded by a local `checkCredentialsDir` stat of a same-named path that is a different environment. The port owns all three decisions precisely so no management-host path is ever derived, resolved, or consulted.
- **Widening the localAgent facade with target-aware verbs (`homeDir` returning volume names)**: rejected — the facade's `homeDir` contract is "a directory this process can read" (the read-back parses it), and overloading it with unresolvable references would break every existing consumer silently. A separate constructor-injected port keeps the facade's contract honest and the new path opt-in per instance.

## Consequences

- `EvalService`'s constructor config, `EvalConfig`, `EvalService.dispose`, `EvalDisposedError`, `EvalRunJobs.dispose`, the Remote `runStart`'s `stateRoot` option and the `STATEROOT_OUTSIDE_INSTANCE` diagnostic are new public surface; `PACKAGE_NAME` is exported from `invariant.ts`; `apply` takes an optional config and wires disposal to the Context teardown. The evidence seam adds `ScopedHomeEvidenceFace` / `ScopedHomeHashEvidence` / `PresetSnapshotEvidence` (plus the newly exported `LocalAgentCredentialGrade` / `LocalAgentEffectiveSettingsFace`), `EvalConfig.evidence`, `ProvisionOptions.evidence`, `CapabilityProbeDeps.evidence`, `ReadinessInput.evidence`, `RunDeps.evidence`, and `ConditionReadinessOptions.scopePresetSha`; the producer half is `produceScopedHomeEvidence` / `ProducedScopedHomeEvidence` from the package root. The execution-home port adds `ExecutionHomePort` / `ScopedHomePlanRequest` / `ScopedHomePlan`, `EvalConfig.executionHome`, `RunDeps.executionHome`, `planScopedHomeMount`, the optional `CellUnitPlan.mount` carrier, and the `EXECUTION_HOME_*` diagnostic codes. All 1313 pre-existing tests pass unmodified (1330 total, 48 new across `tests/state-root.spec.ts`, `tests/evidence-face.spec.ts`, `tests/execution-home.spec.ts` and the appended describe in `tests/run.spec.ts`); the only edit to a pre-existing test file beyond that append is the no-op `effect` mock in `plugin.spec.ts`.
- A mounting side can run several eval instances on one host with disjoint state, point a run's cell root inside the instance boundary only, and tear an instance down knowing its live runs stop through the normal interrupted-cell finalization — while runs it did not start keep running by design.
- On a topology where the credential scope lives on the execution target, provision and the readiness gate anchor on the target's evidence with every check intact — the locks are byte-identical to the local path's over the same home, and no same-named local directory is ever consulted. What the face does NOT cover, deliberately: composing the scope (`localAgent.provisionScope`, a write) and the unit mount source the run loop passes to lab (run plumbing, not evidence) still come from the facade, so a preset-copy condition on a face-only composition declines measurement and refuses at the gate — fail-closed, and the same outcome as a facade without the verb today.
- The unowned job registration stays the reason runs outlive their starters; dispose is deliberately NOT a registry sweep, so a host disposing one instance never strands another's work. The flip side is also pinned: a run whose instance died without dispose (process exit) is not recoverable — re-run is the design.
- Local behavior is byte-identical when the new options are unused: no config, no wire field sent, no face consulted, and every legacy fallback (DSH_HOME-derived roots, the throw-when-unset, the facade reads) unchanged.
