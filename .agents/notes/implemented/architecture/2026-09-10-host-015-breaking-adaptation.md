# Agent Note: Host 0.1.5-rc.1 breaking adaptation (batch 1)

Status: implemented

English | [中文](2026-09-10-host-015-breaking-adaptation.zh.md)

## Problem

Host 0.1.5-rc.1 (format v2/v3) retired or renamed several surfaces this repo consumes: the `assistant/chunk` session event became the aggregated `assistant/attempt` (and `assistant/message` now embeds its `stream` and forbids `sourceEventSeqs`), surfaceOp `replace` fields `start`/`end` became `startSeq`/`endSeq`, `tool/code-dispatch*` became `tool/ptc-dispatch*`, the one-shot `sessionPersistence.prepare/inspect/load/append` service methods became handle-based (`create`/`open` + per-handle `read`/`append`/`flush`/`close` with single-writer ownership), and the client `MessageText` primitive was retired (official user text now projects through `projectUserText`). The full build poisoned every package through gen-typert's workspace-wide typecheck, so nothing compiled until the consumers moved. The plan and batch split live in [the host-0.1.5 adaptation proposal](../../../proposals/active/2026-09-10-host-015-adaptation.md); this note covers batch 1 (breaking adaptation, no UI rework).

## Decision

**message-tools** (`withdraw.ts`, `index.ts`, `marker.ts`, `client/withdrawn-node.ts`): the restore fold consumes `assistant/attempt` instead of `assistant/chunk`. Each attempt is already the aggregated settlement of one model attempt, so the old per-chunk accumulator (pending/flush machinery) collapses into a per-record fold over the compact stream (packed `text-chunks`/`reasoning-chunks` runs append per block index; a raw `block-end` record overrides its index — the old delta-append/block-end-override semantics verbatim). Finalized steps are collected in a first pass over the span, so a retried step's earlier attempts are superseded by its `assistant/message` regardless of log order. Each unfinalized attempt replays as its own framed assistant entry (the old code merged a whole step into one; attempts are the durable unit now). `surfaceOp` replace reads/writes use `startSeq`/`endSeq`. The client views replace the retired `MessageText` with a local `.textRun` block carrying its exact metrics (pre-wrap, break-word, inherited font metrics).

**file-preview** (`fold.ts`): dispatch matching collapses to the single `tool/ptc-dispatch` name, read through the now-declared `SessionEventMap` merge (no more cast through `tool/code-dispatch`). The dual-name feature detection is retired because the official v2→v3 log migration renames persisted rows — a 0.1.5 host never serves a `code-dispatch` event.

**local-agent family** (core + dsh/kimi/claude-code/codex providers): the token-granularity live mirror can no longer write per-token events, so it doesn't: deltas ride the existing `reportRunProgress` channel only, the fold keeps skipping think/text lines in token mode, and the round settles as ONE combined `assistant/message` (now with `stream: []`, no `sourceEventSeqs`) at the reserved (turn, step) — the final transcript is byte-identical, the typewriter view of the child session is what's lost. The usage backfill (`appendClaudeUsageChunk`/`appendCodexUsageChunk`) is deleted: 0.1.5 has no event that can amend an already-mirrored message, so a round whose usage arrives after its carrier line was mirrored loses the accounting with a `logger.warn` instead of a silent drop. `persistIfStandalone` (all four providers) and the core's `reattachChildSession` move to the handle API: `stat` → `create`/`open(id, 'write')` → append only the unstored suffix → `flush` → `close`. The reattach additionally pushes the constructor-appended `session/end-seed` marker through the handle directly (the seeded constructor appends it before `enter()` installs the publication hooks, so live routing never sees it — the same gap the agent loop's `appendUnstoredSuffix` covers), and holds the write handle for the reattached lifetime (the jsonl backend routes live `session/event`s into the per-id writer only while a write handle is open), closing it on plugin dispose. `SubprocessHandle.pid` is gone (the managed-range abstraction owns termination): the `pid <= 0` spawn-failure guards dissolve into terminate's idempotent no-op contract, and the member-channel pid binding cannot be fed — **the bridge's parentage cross-check fails CLOSED** (an unbound run's callback rejects as foreign), so CLI-member messaging is inert on 0.1.5 until an upstream pid seam or a deliberate token-only decision; `bindMemberRunPid` and the strict check stay in the core for that future. The headless package's test fixtures replace the removed `Inbox` class (an interface in 0.1.5) with a minimal stub.

**room**: `inspectCold` becomes `open(id, 'read')` → `read(0)` → `close`, constructing the same `SessionInspection` shape; the probe face checks `open`. Its persistence spec drives the real jsonl backend through handles, and the agents stub mimics the 0.1.5 agent factory by holding a write handle for created sessions (no coordinator claims `session/created` anymore).

**ankh-guard**: both cold reads (the parked-on-user-input probe and the resume preset derivation) share a structural `ColdReadPersistence` helper doing `open(id, 'read')` → `read` → `close`, probed per call like the plugin's other host surfaces.

**Repo-wide baseline**: every package's `@deepseek-ai/*` devDependency pins move `^0.1.2-rc.1` → `^0.1.5-rc.1`, and the `pnpm-workspace.yaml` `overrides` baseline flips to `0.1.5-rc.1` (the ui-file-preview carve-outs dissolve into the baseline). A `'@deepseek-ai/cordis': '4.0.2'` override forces one cordis instance — the 0.1.5 official line peers `^4.0.2`, and a split 4.0.1/4.0.2 graph duplicates every official package, which makes branded types (`SessionId`) non-identical across instances (the taskpilot build errors were all this phantom). Peer dependency ranges stay wide (`^0.1.0-rc.6` / `^4.0.1`).

**Compatibility labeling**: message-tools, file-preview, the local-agent family, room, and ankh-guard move `dsh.compat` to `minHost`/`verifiedHost` `0.1.5-rc.1` (the four providers carry a `notes` entry for the token-mode degradation); README Compatibility sections match.

**Zero-change conclusions** (verified against 0.1.5-rc.1 sources): the slash-command description thunk applies to the client-side `ctx.commandUi` contribution only — no package uses `commandUi`, and the host-side `ctx.commands.register` (mission, eval, datasets, taskpilot, local-agent) still takes `description: string`. No `profiles/*.yml` carries a `persona:` config key (the split `personaPrefix`/`personaSuffix` belongs to `dsh-system-prompt`, which no profile composes). capability-catalog holds no session-event vocabulary referencing `code-dispatch` or `assistant/chunk` — nothing to update.

## Alternatives considered

**Re-declare `assistant/chunk` via the SessionEventMap merge to keep token-mode chunk writes.** Rejected: `Session.append` cannot stamp `ignorable: true`, and the 0.1.5 persistence read path refuses unknown non-ignorable types — every child session a token-mode round wrote would fail to reload after a restart. Degrading the feature beats corrupting durability.

**Alias token granularity to event granularity outright.** Rejected: token mode's skip-fold + combined settle produces a different (single-message-per-round) transcript shape that deployments may prefer, and the config key staying meaningful keeps the settings surface stable; the only thing lost either way is the per-token log writes, which cannot exist.

**Keep the `tool/code-dispatch` name in file-preview's matching set as dead defense.** Rejected: the v2→v3 migration renames persisted rows, so the name can never appear on a 0.1.5 host; a dead branch would read as if 0.1.2 logs were still servable (they are not — the read path refuses them pre-migration).

**Keep the member-channel pid cross-check alive by weakening it to token-only when unbound.** Rejected: the pid check is a security control (a sibling run's bridge entry, visible in a shared scoped home, must not impersonate another member); weakening it silently is exactly the kind of semantic call this adaptation is not authorized to make. Failing closed preserves the invariant and makes the missing upstream seam visible.

## Consequences

The full workspace compiles and tests green against 0.1.5-rc.1 (npm devDeps and the harness checkout agree). Given up: the token-granularity typewriter view inside child-session transcripts (no replacement seam — the official live text rides agent-owned follow frames, which an append-only mirrored session has no driver for; the proposal's batch 4 evaluates `assistant-stream` follow frames for our own streaming needs), the killed-run usage backfill race (carrier mirrored before usage was knowable now drops the accounting with a warn), and CLI-member messaging on 0.1.5 (fail-closed pending a pid seam or a token-only decision — the member-channel proposal's owner should weigh in). The per-attempt (rather than per-step) restore replay in message-tools can emit multiple framed assistant entries for a retried unfinalized step — more faithful to the log, noted here so nobody "fixes" it back. Every changed package's minHost is now 0.1.5-rc.1; 0.1.2 hosts must stay on the previous published lines.
