# Agent Note: 成员配置持久控制器基础

Status: implemented

## Problem

现有 provider 模型覆盖是私有内存映射，成员忙时拒绝修改。Room 和 composer 若各建队列，会产生冲突的选择语义。原生控制还可能在新选择之后才返回，或在宿主记录成功前已经生效。

## Decision

Core 导出与 provider 无关的成员控制器，包含当前配置、一个可覆盖的待生效槽、意图 revision、请求回执及整轮不可变准入凭据。Model 与 effort 分别区分继承成员、harness 默认和显式原生值。Provider 适配器负责只读验证、有界原生应用和对账，控制器不发起模型生成。

接受操作先持久化意图再返回回执。若验证完成时轮次已经准入，选择影响再下一轮。进行中的模型及工具轮次保持准入配置。新有效选择覆盖尚未发送的选择；原生应用中也可接收修改，并在下轮准入前完成收敛。Revision 冲突或无效组合不改变最后的有效意图。

撤销未发送的选择会直接清除。撤销已经启动的控制会安装恢复最后已应用选择的操作，恢复完成前阻止准入。失败或回执不明时保留意图和操作状态。重试及重启先核对原生当前或操作配置；未知结果继续阻塞，已应用的操作不盲目重复。冻结配置在 provider 验证前拒绝选择。

每个成员使用带版本、结构校验和原子替换的持久文件，rename 前 flush，平台支持时同步目录。请求回执跨重启保留。损坏状态只阻塞该成员，不静默恢复默认配置。写入失败不返回已接受回执，并阻止自动准入或重试循环。每个数据目录只能有一个拥有它的 core 实例，与隔离验收实例的 HOME 规则一致。

## Alternatives considered

**把每次中间选择放入 FIFO。** 拒绝，用户要的是最后有效配置，而非执行所有中间点击。

**收到 provider ack 就先宣称持久成功。** 拒绝，两者之间崩溃会使原生状态不明，必须对账。

**把原生协议或 room 策略写进控制器。** 拒绝，控制器负责一致性和准入，适配器提供事实与动作，room 持有编排策略。

## Consequences

本提交是经过测试的控制基础，尚未接入 provider 准入、gateway 控制或 UI；入口一起迁移前，现有忙时拒绝仍然存在。Effort 传递、评测锁及各家恢复适配仍是产品合同交付的必要后续工作。

## Testing

测试覆盖忙时合并、验证与准入竞争、迟到回执、撤销恢复、revision 冲突、请求去重、冻结配置、写入失败、损坏文件、未知原生状态、恢复后不重复应用，以及真实存储重建。Core 既有测试保持通过。
