# Agent Note: worktrees changes view becomes a right-sidebar tab; badge stays in utilities

Status: implemented

## Problem

The host-0.1.5 adaptation plan ([proposals/active/2026-09-10-host-015-adaptation.md](../../../proposals/active/2026-09-10-host-015-adaptation.md), batch three) assigns worktrees two entry moves: the badge to the new `conversation.session.header.corner` slot, and the diff/commit drawer to a right-sidebar tab type. Source inspection of 0.1.5-rc.1 showed the first move is impossible; the second landed, and the same transaction rewired the external-open gesture, which 0.1.2 had permanently hidden (the `canOpenPath` host-description field had become an RPC probe the loopback gate could never confirm).

## Decision

- **Badge stays in `conversation.session.header.utilities`.** The corner slot is `kind: 'single'` and the shipped web composition (packages/bundle/web-app/cordis.patch.yml) mounts ui-sidebar-right, whose ExpandButton registers there at default priority. Single-slot conflict semantics (packages/client/ui-slots/src/index.ts): a second registration at the SAME priority throws at load; a different priority shadows — the lowest-priority occupant renders and the other never mounts. So the badge could only enter the corner by permanently evicting the ExpandButton (the official way back into a collapsed right sidebar), or by being permanently invisible itself. Neither is acceptable; the badge keeps its list-slot seat.
- **Badge order within utilities is `-20` (leftmost).** List slots sort by `priority` ascending, then `order` ascending, then registration sequence (ui-slots `src/index.ts` — the stable-sort comment at the register path). The neighbors are the official open-in-app split button (`order: -10`, ui-open-in-app `src/client/index.ts`) and the official session-log-export "…" menu (no order → `0`, session-log-export `src/client/index.ts`; the ellipsis button is its `SessionLogDownloadHeaderAction`, `HeaderAction.tsx`). Community registrations sit at 10+ (message-timeline 100). `-20` puts the worktree capsule left of everything without touching any other package's registration. The "…" menu's position is upstream-owned: a list entry's order lives in its own registration, so no plugin can reorder it short of a duplicate-id collision (same id + same priority throws) or a shadow hack (same id, lower priority double-renders) — both rejected; moving it next to the sidebar toggle is an upstream change request, not a local edit.
- **The changes/commits/repository drawer is a page-type right-Sidebar tab**, following the official ui-sidebar-files two-stage shape (and the in-repo taskpilot/ui-file-preview precedents): `src/client/definition.tsx` registers the type into `ctx.sidebarRightTabs` (`id` = the package name, also the keyed-seat key; `kind` = `worktrees`; no `patterns`; default `extension` band; one guide entry), and `src/client/WorktreesTab.tsx` registers into the keyed `sidebar.right.pane.tab` seat under that id. The badge's branch capsule opens it with `ctx.sidebarRight.openTab('worktrees', { params: { mode } })`; `SidebarRightTabParamsMap` is declaration-merged with `worktrees: { mode?: DrawerMode }`, and the body applies the mode ONCE per `navigation.revision` (guarded by a last-applied-revision ref) so a repeat click re-asserts it. The guard is load-bearing: an earlier cut keyed the effect off `mode` as well, so the user's own sub-tab switch re-fired it and snapped the tab back to the navigated mode — the left column read as stuck on 本会话改动 while the counts (mode-independent) kept rendering. Caught in the 3092 live trial; fixed with a regression spec pinning that a user mode switch sticks. No `.title` chip: the registry's static title suffices.
- **The drawer chrome is deleted, not kept**: the `open` state and `open`/`close` store actions, the overlay/width-drag/Escape/document-mark push CSS (the sidebar owns geometry), and the close button (the kit owns tab close). The store is now session-scoped (the keyed seat's scope) instead of root-scoped; `Drawer.tsx` was split into `WorktreesTab.tsx` and `sizing.ts` (the drag-width hooks the surviving local-files browser still needs).
- **The changes view is worktree-scoped, not session-scoped**: the 工作树待提交 mode lists the currently selected worktree's full uncommitted set, following the header's worktree switcher (the switch repoints the session's active worktree and refreshes). An intermediate cut (6aae716) filtered it to session-touched files via the sibling file-preview fold's `list` (probed through `ctx.get`, fail-open); the user reverted that — session-level change attribution has no reliable interface (the fold records display paths as the tool call spelled them, so relative paths only resolve when the session cwd IS the worktree root). The probe/degrade code left with the filter; the two packages are back to fully independent.
- **The local-files browser stays on `shell.overlay`** (the batch-three plan moves only the diff/commit drawer) — but its external-open gate rewired together with the tab's.
- **External-open rides the official open-in-app routes** (`src/client/open-in-app.ts`, mirrored from local-files' same-day landing): a once-per-page `GET /open-in-app/apps` probe publishes the installed catalog ids through a snapshot store bound as an inject hook (`hooks: { openInApp }` → `useOpenInApp`); the "show in folder" gesture renders only when `pickFileManager(apps)` resolves, and POSTs `/open-in-app/open { app, path }` with a directory. A host without the routes (404, or pre-0.1.5) reads as no apps and the gestures stay hidden. The `hostDescription`/`canOpenPath` machinery (`host-description.ts`, the per-host-line probes in `index.ts`) and the legacy `workspaces.openPath` / `remote.session.openWorkspacePath` openers are deleted; `pickHostDirectory` simplifies to the 0.1.5 `uiWorkspace.pickDirectory` face.
- `dsh.compat.minHost`/`verifiedHost` move to `0.1.5-rc.1`; `@deepseek-ai/dsh-client-ui-sidebar-right` joins as a non-optional peer (`^0.1.5-rc.1`, the taskpilot precedent: the tab is the surface, there is no degradation path worth shipping) and the devDependencies move to the 0.1.5-rc.1 line. The version line moves to 0.2.0 for the host-line cut.

## Alternatives considered

- **Occupy the corner at a lower priority than ExpandButton.** Rejected: single-slot shadowing means the ExpandButton would never mount — users lose the official way to reopen a collapsed right sidebar. Evicting shipped chrome for a badge is not a trade this plugin may make.
- **Occupy the corner at a higher priority.** Rejected: the badge would never render (the lowest-priority occupant wins); a permanently shadowed registration is dead weight.
- **Keep the overlay drawer alongside the tab as a fallback.** Rejected (taskpilot's same call): two geometry stacks to keep honest, and the repo rule for host-line moves is a clean cut with a version-line pointer, not a runtime fork.
- **Move the local-files browser into the right sidebar too.** Rejected: the batch-three plan scopes worktrees to the diff/commit drawer; the git-agnostic local-files browser is a separate surface whose placement the plan leaves unchanged.
- **Import the open-in-app probe from `@khorsheed/dsh-local-files`.** Rejected: the no-inter-plugin-dependency rule admits only the sanctioned core/companion pairs; the probe is a small, deliberately mirrored module (the official route constants degrade to "gestures hidden" if they ever move), so both packages carry their own copy.
- **Session-scoped changes view (本会话改动 — git uncommitted ∩ the file-preview fold's session-touched set).** Shipped in 6aae716, reverted by user decision the next day: the fold's display paths are spelled as the tool call recorded them, so relative paths only resolve when the session cwd IS the worktree root — attribution silently breaks otherwise, and no dependable session-level interface exists. The worktree dimension (工作树待提交) is the honest one. The fail-open degrade (null = unfiltered) and the no-dependency probing were right for what they were; the premise was not.
- **Filter the commits log to session-touched files as well.** Rejected by the user: the commit log stays whole (renamed 仓库提交记录 to say so); only the uncommitted view was ever a candidate for session scope.

## Consequences

- The badge click now opens a sidebar tab instead of an overlay drawer; the tab is enterable from the guide page as well, and its open state, docking, and fullscreen are the right Sidebar's own (including undo/redo of layout intents).
- Two worktrees tabs of one session (split panes) share the session-scoped store and mirror each other's mode/selection — accepted: pages deduplicate within a pane, and the cross-pane duplicate is a rare power gesture.
- The 工作树待提交 view's count and overview describe the selected worktree's pending set; the badge's branch capsule keeps the repo-wide uncommitted+committed counts (status signal, not a file list — unchanged).
- The external-open gestures reappear on 0.1.5 after being hidden for the whole 0.1.2 line; they are probe-gated now, so a host without the open-in-app routes shows nothing.
- `sessionId` inside the tab comes from the session scope's standard props instead of `useSessions(s => s.current)`; `openTab` aims at the mounted session, which coincides with the badge's session by construction (the header only renders for the mounted conversation).
- The `drawer.*` / `aria.openDrawer` locale keys keep their names (dictionary stability) even though the surface is a tab now.
- Verified by `pnpm --filter @khorsheed/dsh-worktrees build` and `pnpm --filter @khorsheed/dsh-worktrees test` with `DSH_HARNESS` pointing at the 0.1.5-rc.1 checkout; the drawer spec was replaced by `tests/worktrees-tab.client.spec.tsx` (mount-fetch chain, navigation-params mode) and `tests/browser-plugin.client.spec.tsx` (registration wiring, openTab routing, disposal), plus `tests/open-in-app.client.spec.tsx` for the probe. Live 3080 acceptance is a separate step through `pnpm deploy:3080`.
