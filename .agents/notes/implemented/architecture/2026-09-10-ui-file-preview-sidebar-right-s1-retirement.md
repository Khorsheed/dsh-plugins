# Agent Note: ui-file-preview moves to the 0.1.5 right sidebar — S1 seam retired

Status: implemented

English | [中文](2026-09-10-ui-file-preview-sidebar-right-s1-retirement.zh.md)

## Problem

Host 0.1.5-rc.1 landed the right-Sidebar resource routing (seam registry S1): every file-open gesture (deliverables row, prose mention, tool-result line) converges on `ctx.sidebarRight.openResource()`, and `ctx.sidebarRightTabs.register()` lets third parties register tab types — page types enter from the guide page and claim no address; address types claim `dsh-resource://` globs. ui-file-preview's four workarounds (the `conversation.view` tab, the `shell.overlay` drawer, the mention capture-phase DOM interception, the turnTail `priority: -1` preemption) existed only because that seam was missing, and the DOM interception was the most fragile code in the package. The migration is batch two of `proposals/active/2026-09-10-host-015-adaptation.md`.

## Decision

- **New**: a page-type right-Sidebar tab (`kind: 'file-preview'`, id = package name, guide entry, no address claims — the ui-sidebar-files shape). Its body is the session's touched-file list (latest-first, searchable) navigating IN-TAB to a detail view on row click: breadcrumb header (directory greyed, final segment solid) with copy-path / show-in-folder / open-in-IDE actions, over a 内容/改动记录 toggle — the restored pre-0.1.5 preview stack (FilePreviewPane: markdown/JSON/CSV/sandboxed HTML/code + content search) and the shared DiffHistory. The turn card opens the page with `openTab('file-preview', { params: { path } })` for outside-workspace paths, landing directly on the detail view. (First cut handed content preview to the official document tab via openResource and stacked the history under the list; live use rejected both — detail-in-tab won, while mentions keep opening the official document tab as the quick preview and the change history ALSO stays registered there as a switchable renderer — next bullet.)
- **Deleted**: `conversation.view` registration, the `shell.overlay` drawer, `mention-intercept.ts`, the turnTail `priority: -1`, the panel controller (`panel-service.ts`), host-description probing, and the whole self-drawn content-preview stack (FilePreviewPane's content half, `structured.tsx`, `html-bridge.ts`, `html-src-doc.ts`, copy/reveal/IDE gestures) — content rendering is the official `text` tab type's job.
- **Kept**: the turnTail mutation card (its host data includes bash captures — S2 still绕行中 — so it covers turns the official deliverables row declines). It now registers at default priority: the official entry (same band, registered earlier at host boot) elects first, and the card's unconditional claim is consulted only for turns official data misses. Card clicks route through the owner's `openFile` for in-workspace paths — the official openResource route — and through `openTab` for outside-workspace ones.
- **Boundary**: outside-workspace bash artifacts cannot be named by a `dsh-resource://file/...` address (the official `file` resource is workspace-scoped; the host answers `workspace-file/outside-workspace`), so they never reach the official document tab — but the detail view is this plugin's own and is unbound by it: the host `read` resolves absolute paths and reveal/openExternal take them, so those files get full content + history. The row carries a marker noting they are outside the workspace.
- **The change-history view (per-write diff stepping) stays self-drawn deliberately, as a switchable renderer of the official document tab**: `ctx.documentPreviews.register()` (suffix-matched, no wildcard — `history-definition.ts` enumerates common text suffixes, compound suffixes avoided so a longer suffix never outranks an official renderer at equal band) plus the component in the keyed `sidebar.right.tab.document` seat under the same id (`<pkg>/history`). `priority: 'builtin'` is explicit: the renderer appears in the toolbar dropdown without taking over the official default (the extension band would). The body parses the session-scoped `resourceAddress`, fetches the `filePreview.list` fold, matches by workspace-resolved path, and renders `DiffHistory.tsx`; the owner's prepared `content` is ignored (`loading: 'text-pages'`, the cheapest mode). Files with no recorded changes get the empty notice.
- **Mention opens land in our detail view (S1 tail, new绕行)**: ui-deliverables' `chatFileMentions` routes `present`-delivered files to the native default app and only undelivered ones to the sidebar. `ctx.provide` rejects a second provider and `ctx.set` rejects any fiber but the provider's ("cannot set property in multiple fibers"), so `mentions-wrap.ts` rewrites the provided object's `forClosing` in place — the original keeps its claim logic; every resolved `open` becomes `sidebarRight.openTab('file-preview', { params: { path } })` (our detail view; a throw falls back to `owner.openFile`), and the label is re-worded (the official "open in the default app" was no longer true). The wrap lives in a nested fiber injected on `chatFileMentions` (a one-shot `ctx.get` races the deliverables fiber's provide; the nested fiber pends on the service and re-runs on HMR re-provide). Registered as a supplement of seam S1, retirement when the official side offers an opener override.
- **The tab type also claims addresses**: `patterns: ['dsh-resource://file/**']` + `canOpen` (fold-membership from an apply-scope cache warmed by every list fetch and the turn-card loader, AND a renderable-suffix filter — pdf/binaries stay official). At the default extension band it outranks the official document tab's fallback band, so every openResource route (official deliverables card, file tree, owner.openFile) lands produced files in our detail view; cold cache or unrenderable types decline and fall back (documented best-effort). The guide page entry coexists with the claim. The body derives the detail path from `navigation.address` when `params.path` is absent, applied once per navigation revision (a later list refresh must not yank a user who backed out).
- **Row actions restored** (the detail view's header — a hover row-actions strip was tried and dropped for legibility): copy path always (`writeClipboard` of the cwd-resolved path); show-in-folder keeps the old drawer's semantics — host `reveal` (file selected), falling back to the official open-in-app POST route on the parent folder; open-in-IDE is file-exact, which the official route refuses (directories only), so the host half gained `filePreview.openExternal(path, app)` — macOS `open -a <App>` via dsh-native-command, the catalog-id → .app-name map mirrored from the official catalog's darwin entries (`open-external.ts`). Gesture visibility rides a once-per-page `/open-in-app/apps` probe mirrored from local-files' `open-in-app.ts` (cross-plugin value imports are purity-gated); no probe answer or no handler = buttons hidden.
- **Turn card election made deterministic**: the chain elects the first non-null select in ASCENDING priority (ui-slots ChainSelect contract) and official deliverables carries the default 0, so the entry registers at explicit `priority: 1` — official claims always win, the card covers exactly the turns official data misses. Equal-priority would have drifted with compose order.
- **minHost moves to 0.1.5-rc.1** (the extension surfaces it consumes did not exist before), version 0.3.0; older hosts stay on the 0.2.x line.
- **Dependency mechanics**: the package rides the repo-wide 0.1.5-rc.1 baseline. One repo-level adjustment was forced: the 0.1.5 client packages peer on `@deepseek-ai/cordis ^4.0.2` while the repo line is 4.0.1 — two cordis instances split every `declare module` merge (Context, SlotMap, LocaleNamespaceMap) into per-peer-variant copies, and a plugin's own merges then never reach the copy its imports resolve. the fix shipped repo-wide as an `overrides` pin of cordis to 4.0.2 (bb04c84), so the graph keeps one cordis instance. Separately, the 0.1.5 `dsh-client-store` npm artifact ships unbundled (bare `zustand`/`immer` imports, no declared deps — the official build bundles them; arguably an upstream packaging bug), and the client bundle inlines that engine (`INLINE_SAFE`), so the package dev-depends on `zustand ~4.4.7` + `immer ^10.1.1` to make the inline resolvable.

## Alternatives considered

- **Keep the drawer/view next to the right-Sidebar tab** — rejected: two previews of the same file in two places doubles the maintenance surface the migration exists to delete, and the drawer's only unique content (diff history) moved into the tab body.
- **Claim `dsh-resource://file/**` ourselves at `priority: 'extension'` and render content too** — rejected: the extension band would shadow the official `text` type for every client (a global takeover, not a local preference), and re-draws markdown/code/image/pdf/html renderers the host already ships. The tab type claims nothing; routing stays official.
- **Drop the turn card because official deliverables exists** — rejected for now: official data misses bash writes entirely (S2), so the card is the only per-turn surface for exactly those turns. Re-evaluate once the host's `present` tool普及s or S2 lands.
- **Self-declare the `sidebar.right.pane.tab` SlotMap entry instead of fixing cordis duplication** — rejected: it typechecks but silently forkbes the seat contract (a host-side change to the seat would compile cleanly against the stale copy). One cordis instance is the honest fix; the peer relaxation mirrors what the repo already ran as unmet-peer warnings.

## Consequences

- `pnpm --filter @khorsheed/dsh-client-ui-file-preview build|test` green (46 tests) against `DSH_HARNESS=deepseek-harness-0.1.5-alpha` (pinned `dsh-v0.1.5-rc.1`); the repo-wide build/test and the 3080 acceptance gate belong to the mainline baseline wave.
- The package sheds its most host-structural coupling (DOM interception, chain preemption); what remains is registry + slot + Remote surface only.
- The self-drawn preview stack was first retired, then RESTORED inside the detail view (live use preferred it over the official document tab for produced files): markdown/JSON/CSV/sandboxed-HTML render, content search, and the external-open gestures (copy / reveal / open-in-IDE via the host's new `openExternal`). The official document tab remains the mention path and carries our change-history renderer.
- The cordis split was resolved repo-wide instead: bb04c84 pins cordis to 4.0.2 through `overrides` (the `peerDependencyRules` relaxation this change introduced was dropped again in 5d832bd). The `zustand`/`immer` devDeps remain an interim packaging seam: they retire if the official `dsh-client-store` artifact bundles its runtime deps again. Other client packages inlining `dsh-client-store` need the same zustand/immer resolution — flagged to mainline.
- Seam registry: S1 marked 已退役 (0.1.5-rc.1); S2 unchanged (the host half's bash collector stays).
