# Agent Note: 持久保存 room 协调者路由与投递结果

Status: implemented

## 问题

Room 输入原本固定交给原生 DSH，成员队列依赖可变的显示名，后台完成也没有与请求者的持久关联。重启后无法区分已接受的工作与执行结果不明的工作。

## 决策

Journal 保存协调者成员 ID、revision 和有界交接信息。旧成员从最初加入事件派生稳定 ID，新邀请分配新 ID。人类输入在服务端解析接收者，记录目标 ID 和可选重试 ID，改名后仍保留原目标。邀请保持原协调者；当前协调者须交接后才能移除。

投递生命周期区分排队、运行、已结束及结果不明。恢复保留未开始工作，不重跑不确定执行；该成员队列阻塞，直到人类记录对账结论和证据。协调者发起的后台请求携带请求者稳定 ID，持久完成结果产生去重的回报投递。人类直接消息和回报投递不会递归回报。

输入框改经 room 路由，外部成员的配置与 Stop 跟随协调者，旧原生 Todo 与队列隐藏。公开 agent pre-step 监听器在原生模型调用前接住旧客户端文本输入，持久转交后返回空首步。仍可明确派发给原生成员。未修改宿主源码。

## 考虑过的替代方案

**使用成员名作为队列身份。** 改名或复用已移除成员的名字会改投已接受工作。名字保留为寻址及展示字段，排队接收者使用稳定 ID。

**重启后重放全部未结束派发。** 外部执行中断前可能已经产生副作用。结果不明时阻塞该成员，等待对账。

**让 DSH 模型转发全部外部输入。** 增加不必要的模型调用，也可能改写用户请求。Room 直接负责路由，通过公开宿主接口保护旧客户端路径。

## 影响

现有独立会话、导航及运行记录继续绑定原成员；投递恢复及回报可在同一 journal 追溯。只读 room 检查不唤醒 agent，冷会话写入恢复沿用公开 agent resume 路径。

这是 M3 的路由基础，尚不代表交付 A 完成。首次付费提示前的原生准备、协调者工具能力检查、core 共用消息队列、更完整的交接上下文、目标暂停集成、完整对账 UI 及真实 harness/浏览器验收仍待完成。当前设置协调者要求成员会话已存在且配置收敛，不宣称满足提案的完整就绪合同。已有聊天自动任务行保留到下一实现阶段与正式 task/attempt 模型分离。

## 测试

Room 测试覆盖不经过原生 followup 的外部直达、明确寻址原生成员及切回、角色 revision 冲突、当前协调者移除保护、已接受请求去重、改名后队列和发言身份、单次完成回报、人工消息不递归、崩溃对账和公开 pre-step 的旧客户端保护。输入框测试覆盖外部配置/Stop 及旧原生 Todo/队列归属。
