# Agent Note: sidechat execution-route config, optional calling, terminal dispose

Status: implemented

## Problem

A consumer mounting side-chat per-instance on an isolated Context with its own `stateRoot` (the supported server-side consumption form) hit three gaps. (1) It could not pin WHERE side agents execute: the route/cwd resolution only inherited from the calling session's folded request header / cwd, then fell to the probed `agentDefaultModel` deployment default — so a mount without a calling session had no execution-target control at all, and an optional calling agent alone was never isolation. (2) `send` hard-required a live calling Agent: one un-widened direct access (`await this.persist(calling.session)`) crashed a calling-less send even though the fence itself already tolerated an undefined session. (3) `disposeAgents()` had no use-after-dispose guard and no spawn/dispose race protection: a handle created after disposal leaked into the owned set, and the disposed instance kept answering verbs as if alive.

## Decision

All evolution is additive and generically named (no consumer vocabulary in code, types, or comments); the version stays 0.2.3.

- **Explicit execution route and cwd anchor on `SideChatConfig`** (`agentRoute?: AgentOptions`, `cwd?: string`, `src/service.ts`). The route chain is explicit route > the calling session's folded request header > the probed `agentDefaultModel` deployment default; the cwd chain is explicit anchor > the source session > the calling session. A set-but-unusable route (empty provider/model — a pair that cannot route) reads as unset, mirroring the usability test the chain itself applies. With both keys unset the local behavior is byte-identical.
- **Optional calling agent on the service core**: `send(calling: Agent | undefined, …)`; the one direct access was fixed to `persist(calling?.session)`, so a calling-less send fences at the deployment default mode with no session id. A calling-less send with NO resolvable route refuses `agent-unavailable` instead of creating a deaf agent — with no user-facing session, an unrouted turn's `lastError` has nobody to surface to. With a caller the unrouted path is unchanged (create proceeds, the turn error surfaces through `lastError`, the 3080-fix semantics). `quoteMessage` keeps its mandatory calling: it quotes a message OF the calling session.
- **The Remote twin is deliberately NOT widened**: the typert boundary rejects an optional agent lookup parameter — `agent?: Agent` fails with "lookup parameter for agent cannot be optional", and `Agent | undefined` fails with "Remote boundary contains class instance Session" (a union node carries no symbol, so the analyzer treats the parameter as a JSON payload rather than the agent lookup). The calling-less form exists only host-side, on `ctx.sideChat`; the wire always has a browser session behind it. The generated typert faces are byte-identical to before, and the Remote verb's TSDoc records the boundary rule.
- **Terminal dispose guard** (the reader's disposed-flag precedent, hardened): `disposeAgents()` sets a `disposed` flag, stays idempotent, and afterwards every public verb (`openWith` / `getState` / `listContexts` / `surfaceHints` / `send` / `quoteMessage`) refuses with `SideChatDisposedError` — a coded, package-named error (`code: 'disposed'`, modeled on `SideChatStoreError`), never a bare throw. `refuseLateHandle` closes the spawn/dispose race on both the create and resume paths: a handle that arrives after disposal is disposed on the spot (never leaked into the owned set) and its caller gets the same coded error; the resume path's catch-all rethrows it instead of falling through to create, and `send`'s catch rethrows it instead of mapping it onto `agent-unavailable`. A rebuild over the same state root stays legal — only the disposed instance is dead.

## Alternatives considered

- **Widening the Remote twin (`remote.sidechat.send`) to `Agent | undefined`**: rejected by the typert boundary, with the analyzer evidence quoted above — the wire model cannot express an absent agent. Tried first, reverted, and documented on the verb instead of fought.
- **A second wire verb for the calling-less send** (e.g. `sendDetached(request)` with no agent parameter): adds wire surface for a host-side-only scenario; the browser caller always owns a session, and the mounting side consumes `ctx.sideChat` in-process.
- **A set-but-unusable explicit route wins (fail loudly)**: an empty pair would then guarantee `agent-unavailable` on every send. Reading it as unset keeps the package's degrade-don't-explode convention and mirrors the non-empty test the inheritance chain applies to both the calling header and the deployment default.
- **Guarding only the mutations post-dispose**: reads answering stale state after unload would let a mounting side keep consuming a dead instance indefinitely; the delivery condition is that EVERY public verb refuses, reads included.
- **Routing `disposeAgents` through the mutation queue** so it cannot interleave an in-flight spawn: disposal would then wait behind queued work — an unload hanging behind a stuck create is the worse failure. The late-handle guard closes the race without queue coupling.

## Consequences

- `SideChatConfig` gained two optional keys; `SideChatDisposedError` is exported from the package root; `send`'s service-core signature widened (backward compatible for every existing caller). The wire surface is untouched — the generated typert host and remote-client faces are byte-identical.
- Ten new contract tests pin the seam: explicit route wins over both the calling header and the deployment-default probe, an unusable explicit route falls through, the explicit cwd wins, calling-less send works with the explicit route and through the deployment-default route, calling-less send with no route refuses `agent-unavailable`; post-dispose every verb refuses the coded error, disposal is idempotent, the in-flight spawn vs dispose race disposes the late handle exactly once and refuses the caller, and a same-root rebuild works. All 86 pre-existing tests pass unmodified (96 total); `remote.spec.ts`, `journal.spec.ts`, `vocabulary.spec.ts`, `client.spec.tsx`, and `persistence-probe.host.spec.ts` carry no expectation changes.
- The mounting side still owns the isolation verdict: the Context's `agents` service decides where side agents execute, the explicit config pins route/cwd, and the README's「工作区接入接缝」section instructs verifying a mount by observation (the created side sessions' route and cwd), never by assumption.
- A calling-less send is a host-side-only shape by construction; if a wire-carried absent-agent send is ever needed, that is a typert boundary feature (an optional lookup parameter), not a sidechat change.
- Follow-up (same day): the [execution backend port](2026-10-10-sidechat-execution-backend.md) supersedes this note's implicit "agentRoute/cwd suffice" assumption for non-local targets — the two config keys parametrize creation through the Context's `agents` service only, which in a per-target topology IS the management host's registry. Both keys stay, now consumed through the backend open payload; the default backend's behavior is the extraction of what this note shipped.
