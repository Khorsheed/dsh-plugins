# Agent Note: file-preview read surface — one core behind the Remote face and the admission seam

Status: implemented

## Problem

A trusted server-side caller that consumes community plugins per authorized scope needs file-preview's three read verbs (`list`, `turnFiles`, `read`) for sessions it has ALREADY authorized — but the Remote face takes an `agent: Agent` and resolves it through the host's unified Agent lookup, which RESUMES offline sessions: any member query through the wire can wake sessions on the target host. The plugin reads exactly three things from the Agent — `session.snapshotEvents()` (the fold input), `session.header.cwd` (the path anchor), `session.id` (the collector key and image-route slot) — all obtainable without a session runtime object, but the package exposed no glue: the fold, the read classification, and the bash-write merge lived inside the Remote methods' bodies, unreachable except through the wire.

## Decision

All evolution is additive: no new Remote verbs, no wire change, no behavior change for a deployment that never consumes the seam. Version stays 0.4.1.

- **The read core is extracted, not duplicated** (`packages/file-preview/src/read-surface.ts`). The exact bodies of `list` / `turnFiles` / `read` moved into free functions parameterized on what the methods actually read — an fs face (`FilePreviewReadFs`, the `resolve` / `stat` / `readByteRange` / `readBytes` subset of `ctx.fs`'s shape), the cwd anchor, the caps, and an image-address issuer — and the Remote methods are thin wrappers that unwrap `agent.session` and call the same functions. Parity between the agent path and the agent-free path is therefore by construction, and the extension classifiers, the bounded byte-window read, and the scripted-HTML hint moved with the core (the image route imports its MIME map back).
- **The factory** `createFilePreviewReadSurface` (package root, mirroring the canvas workspace-access precedent) takes a `FilePreviewReadSource` — `events()` (the session's events in ascending seq order, re-read per call; a fixed snapshot or a wrapped `sessionId → events` lookup), `cwd`, `fs`, an optional `imageUrl` issuer, and the service config's caps under the same names and defaults — and returns `{ list, turnFiles, read, readImageBytes, dispose }` producing the EXISTING result shapes. Authorization is entirely the caller's: the surface performs no admission check, and never constructs, resolves, or wakes a session runtime object — it structurally cannot mint the legacy `/file-preview-image/<sessionId>/...` route because it holds no session id.
- **Bash-write parity through the same pipeline**: `BashWriteCollector` gained `replaySnapshot(cwd, events)` — the snapshot twin of the live feed's replay, running the same extraction, shell expansion, and stat verification in event order with every verification awaited (the live path was refactored to share `#verifyInto`, and the collector's fs option widened to the `resolve` | `stat` subset it uses). Captures rebuild from the same session events, so the merge is byte-identical.
- **Images**: with an issuer injected, image `read` results carry its address in the existing `url` field (the client renders `read.url` unchanged, so controlled addresses ship with zero UI change; an issuer returning `undefined` degrades that one read). `readImageBytes(path)` is a minimal authorized byte read — same anchor, same containment, same `maxReadBytes` cap, returning bytes and MIME — for a caller serving bytes through its own authenticated channel; its failure taxonomy mirrors `read` (`missing` / `too-large` / `error`) plus `not-image`. With no issuer, image reads degrade to `kind: 'binary'` exactly as headless does today.
- **Containment is inherited, not re-implemented**: both paths call the same `fs.resolve` with the same anchor, so `..` escapes, symlink handling, and the `missing` / `too-large` / `error` taxonomy are identical verbatim.
- **Lifecycle**: the surface is pure apart from watermark-keyed caches (the per-turn fold and the replayed captures, invalidated by the last event's seq — the service's own discipline); caches are scoped to the returned instance, `dispose()` drops them (the surface stays usable and re-derives), and there are no timers or background work.
- **Local behavior**: the legacy image route and the agent-bound verbs are untouched. The one defensive adjustment: the `list` / `turnFiles` wrappers read `agent.session.header?.cwd` — the pre-core code only touched the cwd inside the existence probe, which an empty fold never reached, and the pre-existing suite's header-less session double pins that tolerance.

## Alternatives considered

- **A facade `Session` / `Agent` (the canvas `workspaceSession` precedent)**: canvas needed a facade because its writes flow through `sandboxPolicy.resolve` → `sessionProjections.stateOf`, which genuinely reads Session members. File-preview's read path has no policy chain — events, cwd, and fs suffice — so fabricating a runtime object would add a cast-boundary for nothing and blur the no-wake guarantee; injecting the three facts directly keeps "no Agent reachable" structural (and source-pinned in the tests). The canvas precedent still supplied the shape: a package-root factory, server-trusted config, zero Remote change.
- **New Remote verbs keyed by session id**: grows the wire surface every client must carry and the typert generation with it, while the consuming topology calls the package in-process; and a session-id-keyed verb still tempts a host-side lookup implementation later.
- **Let the consuming side re-implement the fold**: a second copy of the fold/merge/classification logic drifts silently (the bash-write merge and the per-turn attribution are subtle); parity by construction beats parity by convention.
- **A shared cross-instance capture cache**: rejected — differently-authorized sources must never share derived state; per-instance caches keyed by the log watermark keep each surface's derivations scoped to its own injected source, and `dispose()` retires them with it.

## Consequences

- The package root newly exports `createFilePreviewReadSurface` (also the default export of `src/read-surface.ts`) and the types `FilePreviewReadSource`, `FilePreviewReadSurface`, `FilePreviewReadFs`, `FilePreviewImageBytes`; the core functions (`listFilePreview`, `turnFilesFilePreview`, `readFilePreview`, `readFilePreviewImageBytes`, `retainExistingFiles`, `eventsWatermark`) are module exports for the service, not root exports.
- `BashWriteCollectorOptions.fs` widened to `Pick<FileSystem, 'resolve' | 'stat'>` (backward compatible); `replaySnapshot` is public and stores nothing in the live registry.
- All 197 pre-existing tests pass unmodified; 12 new contract tests (209 total) pin list/turnFiles/read parity over one fixture session (bash-redirect writes merged from events included), containment classification parity for escape attempts, issuer URL and per-path degrade, byte-read taxonomy and caps, watermark invalidation, dispose cache-dropping, the no-session-runtime-lookup source pin, and the empty-log shapes.
- The seam ships in the 0.4.1 line with no version bump; the consuming collaboration plugin still owes its own admission layer (deriving the authorized source per member) — this package deliberately does none.

## Testing

`packages/file-preview/tests/read-surface.spec.ts` drives both paths over one fixture session against a containment-enforcing fs double: `list` / `turnFiles` / `read` results compared with `toEqual` (plus concrete spot-checks so mutual wrongness cannot pass), escape attempts (`../`, nested `..`) classified identically on both paths and dropped from lists, issuer behavior, byte-read success and failure taxonomy, cache invalidation on log growth, dispose (observed through the replay's no-options resolve calls), capture toggle, and a source scan asserting `src/read-surface.ts` contains no session-runtime lookup (`@deepseek-ai/dsh-agent`, `agents.get`, `resolveAgent`, `.resume(`).
