# Agent Note: 章节回收站使用画布原生独立页面

Status: implemented

## Problem

初版章节删除让复选框常驻，并把回收站放在弹窗里。目录因此像管理后台，回收站列表难以扩展，也无法使用画布原生面包屑。Agent 卡片写着「查看回收站」，实际却只到章节目录。

## Decision

- 删除采用显式选择模式。普通目录没有复选框列；点击删除才出现选择控件和影响预览入口。取消或 Esc 返回目录，保留筛选和阅读位置。最终确认继续使用宿主 Modal，完成后用宿主 Toast 提示，不再自动打开另一层窗口。
- 回收站是 `canvas.page`，不是弹窗。画布负责原生面包屑和返回按钮；页面负责容量、删除批次、只读快照和多选。恢复与彻底删除的二次确认仍使用 Modal。
- `CanvasNavParams` 增加可选 `page` 与 `param`，映射到 `selection.openPageTab`。章节删除完成后的 Agent 去向命名为 `novel:chapter-recycle`，卡片入口因此直达同一个原生页面，而不是泛泛的章节目录。
- 操作统一使用宿主 Button、Modal、Toast 和现有图标，不自绘更小的返回按钮或另一套按钮。插件 CSS 只负责布局与语义状态。
- 独立只读 Remote 返回一个仍存在快照的正文和计划。预览和已关闭操作不可读，已清除或已恢复的章节按不存在处理。派生记录不经过这个接口，回收站列表仍只带元数据。

## Alternatives considered

- **保留回收站弹窗并自绘返回按钮。** 否决：会重复画布已有的 `DetailCrumbs`，窄屏导航不一致，较长的删除批次也更拥挤。
- **只在悬停时显示复选框。** 否决：触屏没有可靠悬停；常驻复选框又干扰阅读。显式模式同时适用于桌面和手机。
- **在 `chapterDeletions` 列表里直接带正文。** 否决：会放大每次刷新，也容易把内部派生记录混入只需要正文和计划的读取路径。
- **Agent 去向继续指向章节目录。** 否决：入口文案与实际落点不一致，用户还要再次寻找回收站。

## Consequences

- 目录默认服务阅读与写作，只有用户明确提出时才出现删除管理控件。
- 画布导航现在可以表达体裁独立页，与卡片、成稿、类型页和看板页签使用同一类型化地址；其他体裁页面也能复用，不需要私有跳转通道。
- 快照读取没有新增写入路径，删除、恢复、清理重试和彻底删除的既有语义不变。
- 测试覆盖选择模式与 Esc、当前筛选全选、宿主 Toast 导航、画布原生返回、正文与计划快照，以及清除或恢复后快照消失。
