# Agent Note: 冻结评测成员准入的模型与 effort

Status: implemented

## 问题

评测条件已经把 effort 纳入哈希，但委派此前没有 effort 通道。若交互式成员控制没有冻结准入合同，同一个条件哈希下的不同轮次可能使用不同设置。请求的设置也不能证明原生 harness 实际使用了什么。

## 决策

评测选手、就绪探针、容器运行及裁判通过共享委派选项传递显式原生 effort，并携带条件锁。旧版 `default` 条件保持原始字节与哈希。成员控制器持久保存首次准入的默认模型及 effort，后续轮次和重启对账都固定到该快照。交互选择不能改变已锁定成员。

Registry 按实际返回的 run 对象记录配置证据。评测分别记录声明、请求、准入及原生观测的 effort；缺失观测保持未验证。显式 effort 必须在付费提示之前具备 provider 配置适配器。不匹配的判定不参与比较，但保留消耗及证据。报告导入根据证据重新计算状态，不信任存储的结论。

## 考虑过的替代方案

**重写现有条件基线。** 改写旧默认条件会破坏冻结比较哈希，却不能证明原生行为。现有文档保持不变，由固定哈希测试约束。

**把请求 effort 当作观测。** 命令行选项或已接受配置属于准入证据，不能证明实际生成行为。未知原生观测明确展示，并阻止宣称比较已验证。

**只读取成员最新配置。** 后续轮次可能先于上一轮结果标注改变当前状态。证据绑定具体 run，读取时复制。

## 影响

默认设置变化不再静默改变锁定评测成员的后续轮次或重启状态。不支持的显式 effort 在付费执行前失败。没有新增证据的历史报告保留原有解释。原生 harness 不报告 effort 的新运行仍为未验证；在原生证据可用前，可能阻止比较排名。

## 测试

Core 测试覆盖后续轮次及重启的默认冻结、run 身份与持久控制。评测测试覆盖选手、裁判、就绪探针及容器参数传递，恢复选项不变，不支持 provider 的拒绝，伪造导入证据及旧条件哈希不变。Core 和评测定向构建通过；全量测试分别通过 306 和 619 项。
