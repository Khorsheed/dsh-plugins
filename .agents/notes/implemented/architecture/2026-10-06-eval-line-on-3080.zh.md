# Agent Note: 评测线跑在 3080——skill 随包走，评测组合只有一份，题集整理进 dsh-presets

Status: implemented

## Problem

评测线原来只跑在自己的实例上（web-eval 包）。这台实例有两个习惯，放到 3080 这种多模式共用的实例上就会出问题：

- **规划 skill 是复制进共享 skills 目录的一份拷贝。** `install.sh` / `update.sh` 把 `eval-planning` 复制进 `$DSH_HOME/skills`。凡是组合了 `dsh-skill-filesystem` 的预设都会扫这个目录，所以在多模式实例上，开发模式和写作模式里也会出现这个 skill。这是泄漏，不是授予。
- **评测 agent 有两份，其中一份只在私有包里。**
  - web-eval 自带的预设包（`profiles/web-eval/presets`）声明了 `eval`（评测模式）和 `dataset-authoring`（题集整理）。
  - 3080 跑的已发布包 `@khorsheed/dsh-presets` 只声明了 `dsh-eval`：行相同，persona 是旧版，也没有 `dataset-authoring`。
  - 结果是 datasets 核心的默认值 `authoringPreset: 'dataset-authoring'` 在 3080 上指向一个不存在的 id，「整理」无处可开。

## Decision

**skill 随 `@khorsheed/dsh-eval` 发布，由 eval-tool 行授予。**

- `eval-planning/SKILL.md` 放在 `packages/eval/skills/`，并列入包的 `files`（`skills/**/*.md`）。
- `./tool` 入口（`src/tool.ts`）读取这个文件，经 `ctx.inject(['skills'], …)` 注册：`source: 'runtime'`，provider 是 `@khorsheed/dsh-eval`。这和 datasets 工具行注册 `dataset-authoring` 是同一机制。
- 只有当这一行的 `tools` 档不是 `none`、并且核心在场时才注册。也就是说，只有挂了 eval-tool 行的预设（评测模式）能看到这个 skill。
- 文件读不到时只记一条 warn，工具照常注册。

**安装和更新脚本不再复制 skill，并会清掉自己以前留下的那份。**

- `install.sh` 和 `update.sh` 不再写 `$DSH_HOME/skills`。唯一的例外是删除旧版本放进去的那份拷贝。
- `retire_legacy_skill` 只在安装或更新成功后运行。它只在 `$DSH_HOME/skills/eval-planning` 前 12 行同时带有包的签名时才删除：`name: eval-planning` 加 `  iteration: I5`。历史上发过的每个版本都带这两行。
- 没有签名的目录是用户自己的文件：脚本不删，只提示一句。
- 3080 从来没装过这份拷贝，它的 skills 目录里没有评测 skill，部署时没有东西要清。

**评测组合只有一份，以 web-eval 为正本。**

- 正本是 web-eval 的 `preset-eval`：它是评测装置，在 `web-eval-preset-bundle.spec.ts` 里钉了 sha，persona 也更新。
- dsh-presets 的 `preset-dsh-eval` 已同步到同一组合。此前两者只差在 persona 上：
  - Execution 一行的措辞不同；
  - 正本多出四行：数据集只认 `datasets_list` 的结果；版本有歧义时怎么办；路径不等于数据集；草稿不进题库。
- 这一行保留 id `dsh-eval`，3080 已有会话和已选的预设都不受影响。评测会话入口按授予选预设、不按 id 选，所以 `eval` 和 `dsh-eval` 行为相同。
- `scripts/eval-preset-parity.spec.ts` 对比两份 `plugins:` 块（先归一化注释和 `name:` 的引号），并对比 `name` 和 `description`。任一方向漂移，测试就变红。

**`dataset-authoring` 镜像进 dsh-presets。**

- 新增一行 `preset-dataset-authoring`：id、组合、显示与 web-eval 相同，order 11。
- 这样 datasets 默认的 `authoringPreset` 在 3080 上不改配置就能解析。
- 开发模式和写作模式没有新增任何东西。`packages/presets/tests/presets.spec.ts` 钉住这两个模式不引用 datasets / eval / mission 工具行，也不引用这两个评测 skill。

**评测家族里没有别的包写共享 skills 目录。** 逐个查过 datasets、eval、lab、mission、bundle-eval、local-agent 一族和 capability-catalog：datasets 用同样的运行时方式注册 `dataset-authoring`，其余的包不带 skill。

## Alternatives considered

**保留拷贝，再按预设过滤。** skill-filesystem 行没有按预设过滤的能力，而这个目录被实例上的所有模式共用。要过滤就得新开一个宿主接缝，而运行时注册本来就能把作用域管对。

**在 3080 上装 web-eval 预设包，而不是扩充 dsh-presets。** 不选这条，原因有三：

- deploy:3080 只打包工作区里的包，web-eval 预设包是 profile 内的私有包，不在这条流程里；
- 它会在 `dsh-eval` 旁边再多出一个「评测模式」chip；
- 它会把包的 `default: eval` 钉子带到一台默认是开发模式的实例上。

**让 web-eval 包依赖 dsh-presets，删掉自己的预设包。** 这破坏了包「只装评测装置」的决定：包会多出它不需要的开发和写作模式，还会丢掉 `default: eval` 钉子。

**把 `dsh-eval` 改名为 `eval`，让 id 也一致。** 这会让 3080 上每个已在用评测模式的会话丢掉所选预设，而入口按授予选，改名换不来任何行为上的好处。

**脚本无条件删除任何 `eval-planning` 目录。** 用户可能用同一个名字放了自己的 skill。按签名删，删掉的正好是包自己放进去的那份。

## Consequences

- 在任何多模式实例上，eval-planning 只出现在挂了 eval-tool 行的会话里。skill 随 eval 的 tarball 更新，不再需要脚本步骤。
- 评测 persona 有两份，必须同步改。parity 测试会让漏改变成红灯，但每次改动仍要碰两个文件。改 web-eval 预设时：先改正本，重钉 sha，再镜像到 dsh-presets。
- 凡是装了 dsh-presets 的实例都会多一个只服务评测的 chip（题集整理），包括没装 datasets 核心的实例。在那些实例上，这一行保持 pending，chip 打开的 agent 没有数据集工具。开发和写作的组合没有变动，所以这个代价可以接受。
- 旧版包装出来的实例会一直留着那份拷贝，直到下次跑 `update.sh` 时才被删掉。

## Testing

- `packages/eval/tests/tool-row.spec.ts`：
  - skill 从这一行注册，provider 是本包；
  - `none` 档或核心缺席时不注册；
  - 正文带有 T87 的起草规则；
  - `npm pack --dry-run` 里有 `skills/eval-planning/SKILL.md`。
- `packages/presets/tests/presets.spec.ts`：
  - 共四个预设；
  - 开发和写作不带评测行或评测 skill；
  - dsh-eval 带 datasets 和 eval 两行；
  - dataset-authoring 带 `tools: organize` 档的 `datasets-tool`，不带 eval 或 mission 行。
- `scripts/eval-preset-parity.spec.ts`：两份是同一组合。
- `scripts/web-eval-install.spec.ts`：
  - 两个脚本都不复制 skill；
  - `retire_legacy_skill` 在成功 trap 解除之后才运行；
  - 在临时 home 里实跑，删掉了包的拷贝，保留了用户自己的文件。
- 用 3080 的 profile 加本分支的 datasets、eval、presets tarball 起了一台一次性实例：
  - 在开发模式里输入 `/eval`，没有任何候选；
  - 在评测模式里，出现 `/eval` 命令和 `eval-planning` skill；
  - 在题集整理里输入 `/dataset`，出现 `/datasets` 和 `dataset-authoring`；
  - 写作模式两者都没有。
