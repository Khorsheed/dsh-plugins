# Agent Note: 共用原生模型目录机制

Status: implemented

## Problem

模型菜单把原生目录缩成了标识符。Codex 丢弃显示名和推理选项，没有遍历分页，后台完成时不通知已打开的菜单，刷新失败还会用空列表覆盖成功结果。成员查询也读取默认 scope，而非该委派的 scope。

## Decision

Core 持有丰富目录合同和缓存，区分 loading、ready、stale、error、unsupported。并发刷新合并，失败保留成功数据，失效操作隔离迟到响应，可取消订阅发送初始快照与后续更新。Provider 继续负责原生协议与认证。配置项和历史建议独立标识，不覆盖原生元数据。

Codex 接入此缓存，保留隐藏候选和原生推理选项，遍历 model/list 全部分页。隐藏条目仍不进入旧标识符菜单。分页格式错误或游标循环使查询失败，不冒充完整枚举。完整性只描述来源枚举，不证明账号权限或实际出模成功。

目录键包含成员 scope 和 cwd、CLI 可执行文件身份，以及 scoped 配置、凭据和适用项目配置的文件元数据，不读取凭据内容。已打开的订阅定期检查上下文变化和过期。目录提供显式刷新与流式 Remote；现有模型信息读面同时携带丰富目录和兼容 choices。

## Alternatives considered

**每家菜单各写一套缓存。** 拒绝，因为会重复过期处理，刷新与完成通知语义也容易不一致。

**把最近使用的标识符视为可用模型。** 拒绝，因为历史成功不能证明当前配置、账号权限或原生能力。

**由 core 请求写死的厂商 HTTP 端点。** 拒绝，因为原生协议、端点和认证解析属于 provider。

## Consequences

本提交完成共用目录机制与 Codex 适配。其他 provider、共用菜单、实际 effort 控制和持久选择准入仍属于协调者提案后续工作。仅发生在 Keychain 的认证变化需要 provider 失效钩子，文件元数据无法识别；始终保留手工刷新。查询目录不触发模型轮次或复制凭据。

## Testing

Core 测试覆盖并发冷读、已打开订阅、刷新失败、重试间隔、失效前的迟到响应、账号隔离及空目录/error/unsupported。Codex 测试覆盖原生元数据、隐藏条目、分页、游标循环、超时和进程清理。原有包级测试继续作为兼容门槛。
