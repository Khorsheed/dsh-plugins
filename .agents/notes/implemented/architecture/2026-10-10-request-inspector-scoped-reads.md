# Agent Note: request-inspector scoped reads — one allow-list, fidelity metadata, restart epochs

Status: implemented

## Problem

The request-inspector capture core (see the [host-capture note](../feature/2026-10-09-request-inspector-host-capture.md)) answers every query with the full local picture: all scopes, all requests, all token sums. A trusted server-side caller that proxies READS on behalf of differently-authorized consumers needs the same four verbs to answer for an authorized SUBSET of a session's agent scopes — without the excluded scopes leaking anything (rows, counts, tool names, lanes, token sums), without opening their child logs, and without growing a parallel state surface. Three honesty gaps had to close with it: live-vs-log-reconstructed fidelity was internal-only, "session unknown" vs "collected then evicted" was indistinguishable, and the process-local request `seq` had no restart-invalidation story — after a restart an old seq could silently resolve to a different request.

## Decision

All wire evolution is additive (optional params/fields only); local behavior is byte-identical when the additions go unused. Version stays 0.1.0 (pre-release line).

- **One allow-list on all four verbs** (`ScopeFilter { scopes?: readonly string[] }` as an optional trailing param on `listTurns` / `getTurn` / `getRequest` / `getTurnTiming`): the CALLER derives the set from its own authorization facts — the plugin treats it as an opaque filter and never computes one. Scope identifiers are the ones `AgentScopeOverview.scopeId` already exposes; the main conversation's id is the stable string `'main'`. A filtered-out scope contributes nothing: `turnItem` and `getTurnTiming` aggregate over the authorized subset only, `getTurn` drops the scope rows, and `refreshChildren` skips the child-log open entirely for excluded scopes (the read never happens on an unauthorized query's behalf). The main-session log backfill is session-level discovery (turns + delegation stubs) and still runs; its output is filtered on the wire like everything else. Turn rows themselves (query preview, timestamps) are session-level metadata and stay listed — only their aggregates narrow.
- **Zero-authorized is explicit, not empty-looking**: with a filter, `ListTurnsResult` / `TurnOverview` / `TurnTiming` carry `authorizedScopes` (the authorized scopes that exist); an empty array is the zero-authorized-content signal, three-way distinct from the field's absence (unfiltered) and from `undefined` (unknown session/turn). `getRequest` has no envelope to hang a marker on, so its return type gained a union member: `{ refused: 'no-authorized-content' }` (`ScopedRefusal`) — the address exists but the filter excluded its scope — versus `undefined` for a genuinely unknown seq. The refusal confirms address existence and carries no content; that trade is deliberate (the caller is told "something is here, not for you" rather than being lied to with not-found).
- **Fidelity rides the existing types** (no parallel state surface): `TurnListItem.origin` (`live` once any in-process capture landed — the log lane never merges into such a turn — else `log-reconstructed`) and `AgentScopeOverview.origin` (absent while the scope holds no captured content; the two lanes are mutually exclusive per scope, so one enum suffices). `BackfillInfo` is untouched. `ListTurnsResult.evictedTurnCount` (present only when non-zero) separates "collected then evicted under the retention caps" from "never seen" — with the documented blind spot that evicting the last turn frees the whole session slot, so fully-evicted reads exactly like never-seen.
- **Restart invalidation via one epoch field**: the store mints a `generation` id at mount (injectable for tests) and stamps it on every seq-bearing result (`ListTurnsResult`, `TurnOverview`, `TurnTiming`, `CapturedRequest`, and `ScopedRefusal`). Documented address semantics: `(sessionId, turnSeq)` is a TURN-level address (host turn numbers are restart-durable; negative pseudo-turnSeqs are not), and `seq` is process-local — a caller holding seqs across calls tags them with the generation and treats a changed generation as invalidating every held seq. Every seq-bearing payload is epoch-tagged (not just `listTurns`) because a restart between "list" and "get" must not resolve an old seq silently.
- **The client only narrows**: the panel never sends a filter, so the only client-side change is the generated-union narrowing at the `getRequest` call site (`'refused' in value`) plus the injected-face type; no UI consumes the new fields (server-side consumers render their own states).

## Alternatives considered

- **A thrown error for the getRequest refusal** (the eval `UNKNOWN_JOB` precedent): keeps the success type untouched, but an expected, per-query outcome would ride the error channel stringly-typed; the union member keeps the refusal in the typed success branch where the proxy must confront it. The eval precedent covers "unknown job" — a caller bug — while a scope refusal is normal operation for a filtering caller.
- **Returning `undefined` for filtered-out requests** (refusal indistinguishable from unknown): rejected by the contract — zero-authorized must be an explicit, distinguishable result. Hiding existence entirely was also considered and dropped: the refusal reveals that an address exists, but `listTurns`/`getTurn` already reveal the turn structure to any caller authorized for sibling scopes, and a silent not-found would make proxy caches un-debuggable.
- **Tombstones per evicted turn** (exact per-turn "was it ever there"): the store would retain eviction metadata unboundedly to answer a rare question; the session-level counter plus the retained range answers the same proxy flow ("turn absent + evictions happened + seq below the retained floor ⇒ collected-then-evicted") at one integer per session.
- **A constant export for the main scope id**: `'main'` is already on the wire in every overview row; a constant adds surface without adding information. Documented as the stable identifier on `ScopeFilter` instead.
- **Filtering at capture time** (never store unauthorized content): filters are per-query and callers differ; capture-time filtering would make a later, differently-authorized query unable to see what an earlier one excluded, and would entangle the read policy with the capture lanes.

## Consequences

- The four verb signatures gained an optional trailing param; the generated typert surface (`lib/typert.remote-client.d.ts`) regenerates with it, and old callers (no filter) observe unchanged shapes plus additive optional fields.
- The one pre-existing test-visible shape change: none — every new field is additive-optional, and assertions use `toMatchObject`/per-field checks. Twelve contract tests pin the filter semantics, zero-authorized distinguishability, the child-log gate, fidelity markers, eviction distinguishability, the generation epoch, and response-content non-leakage.
- A filtering caller learns scope existence for its authorized set only; the refusal path confirms address existence for one seq at a time — documented as the deliberate trade.
- The main-session log backfill still reads the session's own log even when `'main'` is filtered out: the read is session-level discovery (child scopes are often only discoverable through it), and its content is filtered on the wire. Only scope-specific reads (child logs) are gated by the filter.
- Fully-evicted sessions remain indistinguishable from never-seen ones (the slot frees with the last turn); the README and the `evictedTurnCount` TSDoc carry the blind spot.
- Reconciled with the response-content capture (`CapturedRequest.response`, `CapturedResponse`): the surface audit found verbatim responses hang ONLY on `CapturedRequest` — `TurnListItem`, `AgentScopeOverview`, `RequestListItem`, and the timing lanes/tools carry none — so the `getRequest` gate (payload vs `ScopedRefusal`) covers them and the child-log gate covers their log records (same open/read path, skipped for excluded scopes). The union type-checks against the widened `CapturedRequest`; contract tests pin the marker scan across all four verbs.
