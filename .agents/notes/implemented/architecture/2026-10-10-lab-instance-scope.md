# Agent Note: lab per-instance container scope

Status: implemented

## Problem

A consumer mounting lab per-instance runs several `LabService` instances against ONE docker daemon (the supported consumption form the README's「工作区接入接缝」now documents). Before this seam every instance saw the whole daemon: `listManaged` filters only `dsh-lab.managed=true`, so each instance's reconcile adopted every instance's containers; the `maxConcurrentUnits` ceiling counted foreign units; and any instance could release / verify / populate any unit on the daemon — the only thing standing between an instance and a foreign container was the mission releasable gate, which answers a different question (may THIS unit be destroyed, not is it YOURS). Per-instance mounting needs each instance to see, count, and touch only its own units, with the unscoped behavior preserved byte-identically for the existing deployments whose containers carry no scope label.

## Decision

All evolution is additive and generically named (no consumer vocabulary in code, types, comments, or docs); the version stays 0.2.0-rc.1; the CLI constructs without a scope and is untouched; eval/datasets/mission are untouched.

- **Instance scope + label** (`src/service.ts`, `src/docker.ts`, `src/types.ts`, `src/index.ts`): `LabServiceOptions.scope` (and the plugin config key `scope`, default `''` = off; `''` normalizes to unset in the service constructor). The scope is a pure instance property — never part of `AcquireSpec`, never a fingerprint component. The service hands it to the provider at acquire time as `UnitProvider.acquire`'s new optional fourth parameter (additive for implementers: a three-parameter method still satisfies the interface), and the docker provider stamps `--label dsh-lab.scope=<scope>`, so the scope rides the same "the daemon is the registry of record" path as the unit id, fingerprint, and mission binding. `SCOPE_LABEL` is exported from the package root next to `COMPONENTS_LABEL` so ops tooling can filter by it.
- **Scoped reconcile + ceiling** (`src/service.ts`): with a scope set, `doReconcile` adopts only units whose label value equals the instance's scope and records the rest in a `foreignUnits` map (id → its scope label, `undefined` when the unit carries none). Pinned: pre-existing UNSCOPED units are NOT adopted by a scoped instance either — a scoped instance never silently adopts a unit it could later release. The ceiling then counts in-scope units only for free, because foreign units never enter the registry the ceiling measures. With the scope unset the filter is inert and reconcile adopts every managed unit, scoped ones included — the legacy full view, byte-identical to before.
- **Cross-scope fail-closed** (`src/service.ts`): `locate` and `status(unitId)` throw through one helper that distinguishes an out-of-scope unit (the message names the scope it belongs to, or that it carries no label) from an unknown one — every unit verb (release / verify / populate / collect / archive / checkpoint) refuses through the same fence, and a refusal never adopts.
- **Unscoped = the operator's view**: the READMEs pin who holds which shape — the unscoped instance is the deployment operator's full view (cross-scope overview and reaping are theirs); a per-instance mount always sets a scope.
- **No dispose semantics**: nothing new tears down. Containers deliberately survive process and host restarts; a fresh instance with the same scope re-adopts that scope's surviving units from their labels at its first (single-flight) reconcile, the fingerprint mirror re-materializing as before. `release` behind the mission gate (or explicit `force`) remains the only destroy path; unmounting an instance does not reap its containers, because the next instance with the same scope still needs them.
- **Tests** (`tests/scope.spec.ts`, 10 new; `tests/docker.spec.ts`, 3 new): acquire stamps the label and an unscoped instance stamps nothing (byte-identical label set); scoped reconcile adopts only its own scope — not other scopes, not unscoped units; the ceiling ignores foreign units and refuses at the in-scope count; the unscoped instance adopts everything and can act on a scoped unit; release of foreign-scope and unscoped units refuses distinguishably from "unknown unit" and terminates nothing; verify / populate / checkpoint refuse through the same fence; status lists only the instance's scope and refuses a foreign id; the label round-trips through a restart (a fresh same-scope instance re-adopts from labels and releases, a different-scope instance refuses); `''` normalizes to unscoped. At the provider level: the stamped argv, the absent label when unscoped, and the run → inspect → listManaged round-trip through the fake daemon.

## Alternatives considered

- **Daemon-side filtering in `listManaged(scope?)`**: pushing the filter into the provider (a `docker ps --filter label=…`) would change the interface for one consumer and force every future provider to reimplement it; filtering in `doReconcile` is provider-agnostic, keeps `UnitProvider` minimal, and leaves the unscoped full view as the same code path with the filter inert.
- **`scope` on `AcquireSpec` (per-call)**: an instance property masquerading as a per-call input — one instance could stamp different scopes per acquire and the adoption/ceiling semantics would fork per call. Construction-time scope is the honest shape for "these are MY units".
- **Adopting out-of-scope units as read-only**: every verb would have to remember to refuse them; refusing at the registry boundary is one check, and the refusal message still names the unit and its scope because reconcile records what it skipped.
- **A `dispose()` releasing the instance's units**: rejected by the surviving-containers design — the next instance with the same scope re-adopts them, so teardown stays `release` through the mission gate; an unmount hook would reap containers a successor instance still needs.
- **Validating the scope charset**: docker label values are arbitrary strings passed as argv elements (no shell interpretation) and matching is exact equality, so there is nothing to inject; `''` normalizes to unset and every other value round-trips verbatim.

## Consequences

- New public surface: `LabServiceOptions.scope`, `LabConfig.scope` (plus the Config schema key), `SCOPE_LABEL`, and `UnitProvider.acquire`'s optional fourth parameter; nothing else moved. All 134 pre-existing tests pass unchanged (147 total, 13 new); no pre-existing expectation was edited.
- Byte-identical when unset: the docker argv gains no flag, the reconcile filter is inert, and the CLI and local behavior are unchanged — existing deployments' unlabeled containers remain adoptable by exactly the unscoped instances that own them today.
- A scoped instance's diagnostics name foreign units as of its first reconcile; a foreign unit created after that single-flight reconcile reads as `unknown unit` — the same once-per-process boundary the adoption path already had (reconcile backfills at first use; the live verbs maintain the registry afterwards).
- The mounting contract is written down in both READMEs (「工作区接入接缝（按实例作用域）」), including who should hold the unscoped instance and why no dispose exists.
