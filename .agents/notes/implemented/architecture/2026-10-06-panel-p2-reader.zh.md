# Agent Note：面板规范 P2——灵感空间（dsh-reader）的紧凑排版

Status: implemented

## Problem

手机上灵感空间是把桌面侧栏的排版直接拉满：表头一行六个图标（刷新、筛选、排序、最近阅读、设置、新增），搜索框常驻一行，每个未完整的来源各占一行提示，卡片灰底加描边，标题和摘要各预留两行（一行的标题下面空出一大块）。文章详情标题旁有五个图标；正文和小标题是写死的像素字号，mobile 包放大的阅读字号传不进来。

## Decision

- **面板套进 kit 的 `PanelRoot`**（`ReaderPane` 变成一层薄包装，原组件不动），`@container dsh-panel (max-width: 560px)` 规则生效，组件从 context 读紧凑状态。jsdom 没有布局，已有测试仍走宽路径。
- **紧凑列表页表头**用 `PanelHeader`：灵感空间 + 未读数；搜索、新增常显；刷新、排序（标签带当前顺序）、整墙翻译（可用时）、最近阅读、订阅管理进「…」。搜索行收在搜索图标后（有查询时保持展开，收起时清空查询）。筛选弹层和排序菜单改为只构建一次、由当前显示的表头摆放；紧凑表头下它们挂在表头右缘的零尺寸锚点下。
- **筛选片**（仅紧凑）：全部、未读、订阅源、保存的链接、读者自建标签、「筛选…」。除「未读」外每个片都写进搜索查询（墙唯一的收窄通道），所以再按一次已选中的片即清掉，「全部」连「未读」一起清。按来源、隐藏重复留在「筛选…」打开的两级弹层里——来源会一直增多，一行筛选片装不下。对照稿里的「已抓取」不是墙现有的筛选维度，没有加。
- **紧凑时卡片变列表行**：去掉底色、描边框和圆角，行间一条细线；来源瓷砖和箭头去掉，未读改为来源名前的圆点；标题用 title 字号（600），摘要用 body 字号次级色（两行），来源时间用 meta 字号；**不再预留行数**——两行预留是为了整墙翻译替换字段时宽网格不跳，单列没有网格可跳。标签、「仅链接」、抓取药丸、加标签按钮统一 26px 的片尺寸，各自保留原来的墨色；加标签按钮常显（触屏没有悬停）。
- **多个未完整来源折成一行**「N 个来源未完整 · 查看」——任何宽度都折，因为桌面侧栏上这一摞也随订阅增多。
- **紧凑详情表头**：返回、标题、翻译控件（地球 + 视图下拉）经 kit 新增的 `PanelHeader.extra` 位放入，复制链接 / 在浏览器打开原文 / 删除作为「…」菜单行。`extra` 是不占图标名额的复合控件位。
- **阅读字号跟随共享变量**，默认值保持阅读器自己的桌面字号：正文 `var(--dsh-panel-text-reading, 13.5px)`，h1/h2 为正文的 1.11 倍（桌面 15px、手机约 19px），h3/h4 同正文，文章标题 `max(17px, 1.3×正文)`（桌面 17px、手机 22px）。中英文各自的行高（1.78 / 1.66）保留，没有换成共享的 1.7：这是刻意的排版区分，且两者都不低于共享值的用意。
- 新增仓库内样例（`packages/dsh-reader/examples/compact`，端口 8876；参数 `?w=`、`&theme=dark`、`&touch=1`），用内存宿主数据渲染真实面板以便截图。包的 `files` 不含 `examples/`。

## Alternatives considered

- **宽面板也加筛选片。** 没做：宽表头已有筛选弹层，桌面墙不在这次的问题里；每种排版只留一个收窄入口。
- **所有宽度都去掉两行预留。** 否决：整墙翻译替换字段时宽网格会跳。
- **正文读 `--dsh-panel-reading-line-height`。** 暂不：会在手机上抹平按语言区分的行高；用户觉得手机行距偏松再议。

## Consequences

- 宽排版除折叠的未完整提示、阅读字号改读变量（没装 mobile 包时数值不变）外没有变化。
- 紧凑面板上，整墙翻译的开关在「…」里；视图下拉（只看译文 / 双语对照）只在宽表头上有。
- 已知的旧问题：详情页标签行和标签选择器的行共用类名 `tagRow`，详情标签行继承了选择器 8px 的左右内边距（各宽度都有）。留作单独修复。
