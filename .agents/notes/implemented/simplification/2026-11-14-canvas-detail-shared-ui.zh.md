# Agent Note: 卡片与成稿页共用详情界面

Status: implemented

## Problem

卡片和成稿此前已经共用面包屑、Markdown 和输入框等底层组件，但头部和 Markdown 原始文本编辑布局仍各自拼装。成稿页在面包屑和标题里重复完整标题，主操作与元信息混排，较长的来源清单还会与正文争夺阅读空间。若为了统一而替换卡片块编辑器，会危及绘图、字段和评论；若保持重复，视觉修正就仍要维护两套。

## Decision

- `DetailHeader` 统一卡片草稿、卡片详情、成稿详情及加载状态的面包屑、可选单行标题、稳定操作区和元信息行。
- `MarkdownEditor` 统一非受控 Markdown 输入框、保存提示、可选显式操作和可选实时预览，用于卡片源码模式与成稿分屏编辑。卡片块编辑器、HTML 渲染器和体裁扩展区按职责保留。
- `DetailModeSeg` 统一视图切换。成稿支持阅读、单列源码编辑和分屏；阅读只隐藏编辑器，不丢弃未保存草稿，并显示未保存标记。只有显式取消、保存成功和载入最新才结束或丢弃草稿，返回编辑或分屏仍恢复相同文字和基准版本。
- 成稿面包屑只表示画布与「成稿」，完整标题只在标题行出现一次。「编辑」和「让 Agent 改」固定在操作区，不再随状态元信息折行。
- 正文、冲突提示和来源区使用一致的居中阅读宽度，标题和正文使用 panel 阅读字号变量。窄容器通过既有 container query 折行操作并切换单列，不另做移动端版本。
- 画布切换器的菜单 portal 到 `document.body`，按视口坐标定位并支持边缘翻转，父级堆叠环境不再让会话区遮住菜单。关闭钩子把 portal 菜单视为第二个内部区域，新建表单内点击不会误关，外部点击和 Esc 仍会关闭。
- 不超过六项的来源保持展开，更多来源使用原生 details 折叠，展开后仍能看到全部条目。成稿的取消按钮与 Esc 退出语义保持区别。

## Alternatives considered

- **用一个组件替换所有编辑器。** 否决：卡片块编辑、绘图、类型字段和成稿版本冲突都是领域能力，不是重复外框。共享组件只覆盖共同的 Markdown 原始文本路径。
- **把卡片与成稿合并成一个数据模型。** 否决：成稿有独立正文、版本、导出和来源清单，统一展示不应改变持久化结构。
- **保留重复标题和混排操作。** 否决：这会让层级不清，并在窄面板产生不稳定的折行。

## Consequences

- 视觉变化只影响详情页外框，不改变画布数据、绑定、工具或版本保护。
- 新客户端文件已显式加入 `tsconfig.client.json`，可选属性遵循仓库的 `exactOptionalPropertyTypes` 约定。
- 画布包构建和全部 37 个测试文件通过，覆盖标题去重、长来源折叠和有改动时取消编辑。
