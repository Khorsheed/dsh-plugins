# Agent Note: 精简 Room 配置菜单与协调者身份

Status: implemented

## 问题

协调者试用版把继承模式、CLI 默认值和目录诊断放进主要模型选择器，用户必须先理解配置层次才能选模型。原生成员的 `main` 名称也容易与可转交的协调者角色混淆，目标预算标签则没有说清共享限制与单成员限制的区别。

## 决策

共享成员控件采用紧凑的模型/强度菜单。选择后立即通过现有 core 版本控制器提交；运行中的轮次保留捕获的配置，待生效项仍可撤销。设置页保留保存按钮。设置和邀请保留已有的已保存模型，否则选目录第一个可见候选。后台继续读取旧的继承模式，但普通菜单不再提供这些选项。自定义 ID 与目录诊断折叠展示，候选来源可悬停查看。缺失原生强度元数据时给出说明，不编造候选。

新 Room 的原生成员命名为 `dsh`，旧日志保留原名，保证历史寻址有效。协调者标识放在 Room 输入栏左上角，与成员身份分开。预算标签明确表达整个目标的并发和总执行次数、每项任务的执行次数以及目标推进时长；首次派发、重试和返工计入次数，普通聊天不计入。

## 考虑过的替代方案

**保留详细配置表单。** 继承和 CLI 默认术语解释的是实现层次，不是用户的模型选择。这些语义保留在兼容边界内。

**重放时重命名已有成员。** 这会改变历史 `@main` 寻址和任务归属，因此只改创建默认值。

**填入固定强度列表。** 各 provider 和模型能力不同，Kimi 只有配置候选的目录在原生运行时准备前可能没有强度元数据。界面明确说明缺失。

## 影响

Room 和成员输入栏共享即时选择与下一轮生效语义，不另设队列。provider 设置继续显式保存，旧 core 仍可使用原有邀请降级控件。本次界面调整不会向额外 preset 授权 Room，也不会把隔离验收 preset 复制到生产。浏览器验收在隔离实例进行，生产部署仍单独处理。
