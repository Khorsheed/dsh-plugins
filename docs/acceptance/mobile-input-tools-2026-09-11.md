# Mobile 副标题与输入工具验收 — 2026-09-11

## 范围

按用户确认的原型，将只读工作区/模式放到标题正下方，输入框用单个加号归并附件、指令与权限。保留官方模型、发送/停止、消息动作和运行统计；上下文占用圆环移到统计旁。新建会话仍使用官方工作区/模式选择器。

开发在 mobile worktree；只向隔离 3181 安装标准 tarball，不修改官方或其他插件源码，也不修改 3080。原生桥接没有变化，无需重编 App。

## 验证

- 包 build 通过；38 项测试覆盖原控件回调、实时权限标签、禁用状态竞争、过期结构回退、显式指令焦点、卸载恢复、未知插件内容、桌面恢复与原有功能。
- Chromium 移动视口 420 / 360：副标题与输入工具无横向溢出；浅色/暗色截图检查；发送按钮实测 44×44。
- 附件入口打开真实 filechooser 事件，未选择或上传文件。
- 权限入口打开官方三项菜单；完全权限仍进入官方确认弹窗。验证中取消，未改变权限。
- 指令入口打开官方 listbox；显式打开时将焦点交还原编辑器以保留键盘操作。普通进入会话不自动聚焦。
- 桌面布局切换后归并标记全部移除，回到移动布局后入口恢复；当前草稿内容一致。
- 新建会话具有加号入口，已有会话具有只读副标题；浏览器无运行时 pageerror。

## 实现与边界

加号贡献使用公共 conversation.input.left 槽位。rc1 具体按钮回调是 InputBar 私有注入，适配器因此通过严格匹配原 DOM 按钮同步调用，不重建权限/命令/附件的业务流程。仅隐藏原触发按钮，其菜单与确认组件保持挂载，缺少已知结构时显示原控件。未知插件动作继续保留，不承诺所有第三方控件自动进入加号菜单。

模式名称来自已识别的官方本地化只读标签，工作区来自官方会话摘要。旧标题区只有在所有子内容都可识别时才整体折叠；未知内容和祖先导航保留。没有实现新的导出、下载或侧栏浏览流程。

浏览器 filechooser、菜单和 CSS 验证不等同于 iOS 实际文件选择、系统键盘或完整视觉验收；手机确认另行记录。
