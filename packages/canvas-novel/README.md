# canvas-novel（画布的「长篇小说」创作体裁）

让 dsh 成为连载长篇小说的写作工作台。一部作品跨几十个会话、上百章，模型要做到四件事：记得住设定，知道上次写到哪，不欠下死伏笔，不把人物写串。全文注入做不到这些，这个包做到了。

**一部作品就是一张体裁为「长篇小说」的画布**。画布上的卡片是设定的唯一正本，按四个分类组织：人物、世界、原则、伏笔。这个包向画布注册体裁，并提供作品记忆引擎：编号、对账、台账和 brief。浏览器端只往画布的体裁接缝里加界面（待审条、伏笔台账页、章节阅读页），自己不开新入口。

它取代了已退役的 `@khorsheed/dsh-story-bible`。旧的 `$DSH_HOME/state/story/` 数据**不迁移**。

## 它提供什么

- **体裁注册**（经 `ctx.canvasBoard` 延迟注入，没有画布就没有体裁）：
  - 新建或切换到「长篇小说」的画布会预置四个分类。
  - 每个分类都带卡片字段定义，例如人物有名字、身份、想要、缺失、旧伤，世界有名称、类型、设定，伏笔有悬念、状态、埋于第几章、答案。
- **引擎服务 `ctx.canvasNovel`**：引擎自己的状态放在 `$DSH_HOME/state/novel/<画布 id>/`，共五个文件：

  | 文件 | 内容 |
  |---|---|
  | `annotations.json` | 卡片的显示编号和引擎注记：张力、当前态、置信度 |
  | `experiences.jsonl` | 人物经历流水，按人物卡 id 记 |
  | `mentions.jsonl` | 伏笔提及流水，按伏笔卡 id 记 |
  | `chapters.json` | 章节索引与 plan |
  | `pending.json` | 待审队列 |

  正文的唯一正本是画布挂载工作区里的 `<工作区>/<画布标题>/第{n}章.md`。
- **模型工具**由 `./agent` 组合入口注册，并打 origin 标：
  - `novel_bind`：列出长篇小说作品，按标题把当前会话绑到其中一部；挂在授予作用域上，没绑定的会话也有；
  - `novel_read`：brief 三个变体、cards、card、chapters、ledger、pending、chapter；
  - `novel_write`：card 落新卡或按编号改卡，chapter 自动编号，review 处理待审（采纳、丢弃）、归档卡片、撤销经历；
  - `novel_extract`：prepare 产出素材包，import 过五道校验闸后落库。
- **轻指引函数段 `novel:pointer`**（order 9500）：会话绑定了长篇小说画布时渲染一行指引，否则渲染空串，闲聊零成本。
- **`novel` skill**：一份按需加载的操作手册（含「阶段与角色」：构思期当编辑做主线梳理，写作期当伙伴执行 plan，卡文时当同伴给最小下一步），不含任何作品内容。

## 关键设计

- **会话绑定决定作用域**：会话头的画布 chip 把会话绑到一张画布。
  - 绑到长篇小说画布的会话才拿得到 read/write/extract 三个工具；工具在会话自己的 scope 上按需授予、按需撤回。
  - 绑定有两条路：模型按对话内容调 `novel_bind`（拿不准是哪部就问用户），或用户在 chip 里手动选。没绑定的会话里，轻指引只说一句「先 novel_bind」。
  - 解绑或画布改掉体裁时，工具即时撤回。
  - 没绑定的会话里，这三个工具不存在，而不是被拒绝。
- **卡片是唯一正本**：
  - 模型新建的设定**直接落卡生效**：立刻进 brief、进台账、能按编号引用。新卡在画布上带琥珀色 ✦ 标记、排在最前，打开或归档即消；分类标签上的小圆点标出哪类有新卡，标签行右侧的 ✓✓ 图标一键全部标为已看（红色只留给待审）。不对的卡直接改，或 ✗ 归档。
  - 卡片从不删除，归档后留在画布上隐藏。
  - 改卡就地合并字段，不另起一张；同名的人物卡或世界卡只能有一张，重名的新卡会被拒绝。
- **编号**：
  - 人物用 `c<n>`。
  - 世界和原则用 `w<n>`，伏笔用 `#<n>`。这三类共用一个号段，所以 `w19` 和 `#19` 不会并存。
  - 新卡取同号段的最大值加一。工具、plan 和对账都可以用编号、卡 id 或人物名字指代卡片。
- **审过收章，永远最后**：
  - 一章的流程是：写完 → 对账 → 处理待审 → 用户「✓ 审过」收章。
  - 正文不满意就先改，不要对账。
  - 对账的五道闸都在插件代码里：
    1. evidence 原文检索，防止编造；
    2. 伏笔白名单；
    3. 新设定、新伏笔、新人物直接落卡，标为新增；
    4. 高置信度直接入库（经历可撤销），中低置信度进待审；
    5. 计划落空单独进待审。
  - 把判卷委派给宿主原生 subagent 是主 agent 的事，插件本身不委派。
- **brief 有 token 预算**：write 约 2k，plan 约 2.5k，extract 随正文长短。任何变体都不注入全部前章或全部伏笔。

## 安装

```sh
dsh plugin add @khorsheed/dsh-canvas-novel
```

这个包需要画布（`@khorsheed/dsh-canvas`）同在。没有画布时没有作品，每个引擎动词都回答 `missing`，不会抛错。

patch 挂两行：

| 行 | 内容 | 出厂状态 |
|---|---|---|
| `canvas-novel` | 核心：体裁加引擎 | 全局可用 |
| `canvas-novel-agent` | 四个工具、轻指引和 skill | 在 profile 根**禁用** |

agent 能力属于写作场景，不属于每个会话。

**启用 agent 能力的唯一正确姿势是 preset 授予**：

```sh
dsh plugin add @khorsheed/dsh-bundle-writing
```

它的 `preset-writing` 在写作 preset 的作用域内挂载 `@khorsheed/dsh-canvas-novel/agent`。用自建 preset 也一样：在该 preset 的 `agent.cordis.yml` 里加一行 `name: "@khorsheed/dsh-canvas-novel/agent"`。

手工打开根行（删掉 `disabled: true`）会让所有会话都生效。**只能在没有任何 preset 授予时这么做**：两处同时生效会重名注册，导致启动失败。

## 快速开始

1. 新建一张画布，体裁选「长篇小说」，再挂一个工作区。在写作会话里聊这部作品，模型会自己 `novel_bind` 绑定；也可以在会话头的画布 chip 里手动绑。
2. 聊设定。模型把设定直接落成卡，画布上带 ✦ 新卡标记；看一眼，不对的改掉或 ✗ 归档，再点 ✓✓ 全部标为已看。
3. 规划。`novel_write(what=chapter, plan=…)` 登记计划：梗概、走向（带时间标签和转折 / 落点的几拍）、冲突、看点、伏笔（推进 / 暗示 / 新埋 / 揭晓，各写明动了什么）、出场（含视角）和章末钩子。会话里出一张计划卡，点「查看并确认计划」到章节页看全文、「✓ 确认计划」后开写；不满意直接在对话里说。
   - 正文经会话围栏落进画布工作区。
   - 落不进去就拒绝登记，绝不出现空槽章。
4. 写完对账：先 `novel_extract(prepare)`，委派给 subagent，再 `novel_extract(import)`。
   - 处理待审项，然后「✓ 审过」收章。
   - 阶段灯依次是：规划中 → 写作中 → 已抽取 → 已审过。

**画布里的界面**：卡面、卡页和会话头绑定 chip 由画布的体裁接缝承载；这个包的浏览器端再加：

- **看板顶部的细条**：当前章（最早有待审的一章，没有就是最新一章，点开是章节页）、待审 N、伏笔台账、「目录 · 共 N 章 ›」。
- **成稿 = 这部书**：长篇小说画布的成稿面是目录加阅读器。目录顶部是全书进度条（每章一格，按阶段着色，有待审标红）、「从这里继续」、全部 / 待处理 / 未审过筛选，章节按十章一组折叠（有活的组和最后一组默认展开）。点一章就地进阅读器。
- **章节阅读器**：阶段灯、计划块、本章待审、正文，正文后是「✓ 审过本章」，再往下是下一章的开头预览和常驻的上一章 / 目录 / 下一章。计划块规划中展开带「✓ 确认计划」；有正文后折成一行，正文为主；抽取后那一行写明走向、伏笔各写到几项，展开逐条标 ✓ / ✗（伏笔落空同时进待审、挡住审过，走向没写到只是提醒）。还没抽取或还有待审时审过按钮不可点，旁边写明还差什么。
- **会话里的计划卡**：`novel_write` 登记章节计划后，会话里显示第几章、梗概、走向几拍、各类伏笔几项、出场几人，等确认时按钮是「查看并确认计划」，直接打开那一章的章节页。其他 `novel_write` 调用显示成一行，结果放在「详情」里。没装画布时卡片没有跳转按钮。
- **伏笔台账**：显示活跃数和超期数，点开是台账页。台账页按伏笔列出状态、张力、休眠章数和每章的提及轨迹，计划了却没写到的格子画成虚线。
- **待审 N**：只在有待审时出现，展开就地处理（采纳 / 丢弃，计划落空项是「知道了」），每次处理后看板刷新。

只读画布（不是会话里打开的）只能看，不能处理待审、不能审过。

## Compatibility

| 宿主线 | 结论 |
|---|---|
| npm release 0.2.0-rc.2 | ✅ 开发基线（verifiedHost），全量 build 和 test 都在这条线上完成 |
| deepseek-harness master | 跟随验证。函数型 prompt 段、ctx.fs 版本守卫和 per-scope 工具注册都是长期 seam |

机器可读标注见 package.json 的 `dsh.compat`（minHost `0.2.0-rc.2`）：

- state 写入经 ctx.fs 围栏，重定界到插件自身的 state 目录；只读部署仍然拒绝。
- 章节正文按会话的沙箱模式写进画布工作区。
- headless profile 没有浏览器，agent 行照常可用。
- 会话里的计划卡挂在宿主的 `tool.call.toolview` slot 上；没有这个 slot 时 `novel_write` 照旧显示通用的工具行。跳到章节页要靠画布提供的 `canvasNav` 服务，画布版本没有这个服务时卡片不显示跳转按钮。
