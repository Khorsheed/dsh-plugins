# @khorsheed/dsh-game

[English](README.en.md) | 中文

和 agent 一起做小游戏：对话里定玩法和细节，右栏「游戏」看分章节的策划、玩每一轮通过检查的最新版本。

没做过游戏策划也能上手——agent 既写代码也当策划搭档：先和你定一句话玩法、有哪几类元素、选哪种美术风格（从示例里挑），再动手做出能玩的最小版本，之后照着你玩下来的感受一点点改。每一轮结束，插件自动检查改过的项目（数据校验、加载冒烟、agent 随代码写的测试脚本）；没过就把问题交回 agent 在同一轮里修（最多 2 次），过了就直接进试玩区。

## 特性

- **游戏开发模式**：`@khorsheed/dsh-presets` 里的 `dsh-gamedev`（游戏开发模式）preset——开发者兼策划导师的 persona，`game_open` / `game_read` 两个工具，`gamedev`（做法）与 `game-design`（带你做策划）两个技能。
- **项目在工作区里**：一个项目就是会话工作区里的一个文件夹（`game.json`、`index.html`、`src/`、`assets/`、`elements/`、`design/`、`tests/`），插件自己的版本快照、检查结果、试玩记录都在项目里的 `.game/`，整个文件夹拷走就带走。`$DSH_HOME/state/game/` 只放项目登记和会话绑定。
- **轻量门**：建项目前必须有游戏名、一句话玩法、元素类型、用户选定的美术风格；缺什么工具就回什么，agent 去问你，不替你编。
- **右栏「游戏」策划操作台**：
  - 试玩：默认不运行（封面 +「开始试玩」，避免大游戏一打开就占资源），开始后游戏画面带状态条（线上/候选版本、报错数、点选、重开），候选版本的「先试玩 / 退回 / 确认上线」条，下面是参数抽屉——游戏在 `game.json` 声明的参数做成滑块，拖动只影响正在玩的游戏（试玩值，标琥珀色），不会记成要告诉 agent 的改动；觉得对了再「告诉 agent」（把试玩值写进对话框）或「定稿」写回 game.json，「还原」丢掉试玩值；「点选」点画面里的东西认出是哪个元素，可一键引用到对话。
  - 元素：按类型筛选的卡片网格（像素外观缩略图 + 关键数值），多选后「交给 agent」；打开一个元素是外观编辑器（画笔 / 整体换色，颜色来自美术风格调色板，多状态）、字段编辑、「让 agent 改外观」，agent 用 `game_propose` 一次给 3 个方案并排展示，挑中即替换进游戏。
  - 策划：一页纸（pitch、元素类型、风格）与设计支柱置顶，章节就地展开、可直接改，「刚更新」标记、定稿进度；「元素与数值」自动成表并画数值对比条，「试玩记录」自动写。
  - 版本：最近一次检查（三层结论、问题、无头浏览器截图）、版本时间线（线上/候选/已退回/历史，可切回、可与线上对比文件差异）、导出单文件 `.html` 分享、试玩记录。
  - 项目切换：标题即切换器（「项目名 ▾」），点开是项目卡片——最近一次检查的画面、线上版本、风格、元素数、最近改动和一句话玩法，当前项目标「本会话」；第一张是「新建项目」，点了把开场白写进对话框（建项目要过轻量门，由 agent 和你在对话里完成）。
  - 美术风格画廊：同一个小场景用六种风格画出来对比；没项目时点选写进对话框，项目中途换风格会让 agent 全部重画、结果一律走候选版本。
- **本轮改动卡片**：agent 每轮做完，回复末尾（不随工具调用折叠）出现一张卡片，列出这轮改了什么——上线或候选版本、检查结果、新增/改动的元素、更新的策划章节、参数、代码与测试——每行「查看」直接跳到右栏对应位置（元素页、策划章节、试玩、版本）。
- **改完询问是否告诉 agent**：改了策划、外观、字段，挑了方案，定稿参数，退回或切回版本后，面板顶上会问「要告诉 agent 吗？」——「写进对话」（进对话框后可改写再发）、「不发这次」、「稍后」，或「关闭提醒」；标题栏的「改完提醒」开关随时可以开关。
- **面板改动由你决定何时告诉 agent**：拖的参数、改的外观/字段/策划、退回或切回的版本都立即生效，并攒在输入框上方的「面板改动」里（可逐项去掉）；点「写进对话」把清单写进对话框，补一句你的想法再发送，发出后清单清空。不会自动塞进你的消息。还没发的改动，agent 用 `game_read` 也看得到，不会把它们改回去。
- **每轮自动检查**：`game.json` 与元素文件校验 → 本机 Chrome 无头加载跑 2 秒冒烟（报错、`window.dshGame.ready`、画面不能全空）→ 跑 `tests/*.test.js`。失败同一轮里交回 agent 修，最多 2 次；通过就生成新版本，自动确认默认开着时直接进试玩区，关掉后要你点「确认上线」。

## 安装

```sh
dsh plugin --profile <name> add @khorsheed/dsh-game
dsh plugin --profile <name> add @khorsheed/dsh-presets   # 游戏开发模式 preset
```

本包的 `cordis.patch.yml` 插入两行：`game`（服务核心、Remote、每轮检查）与 `game-agent`（`./agent` 入口：工具、提示段、技能），两行都**默认使能**——单装即所有会话可用（与 canvas 对齐）。`dsh-gamedev` 模式包不重复挂载根行，只在自己的 preset 组合里授予同一入口：宿主 0.2.x 下该模式的会话看到 scoped 副本遮蔽全局行，不再双注册崩 boot（宿主 scoped.spec.ts 钉死）。想让游戏工具只出现在游戏开发模式，就在 profile 里把 `game-agent` 行停用并改用该模式包。

## 配置

| 键 | 默认 | 说明 |
|---|---|---|
| `stateRoot` | `$DSH_HOME/state/game` | 项目登记与会话绑定的目录 |
| `chromePath` | `CHROME_PATH`，再试常见安装位置 | 每轮检查用的 Chrome；找不到时只跑数据校验，浏览器那部分记为跳过 |

## Compatibility

- npm 发布线（`@deepseek-ai/dsh@0.1.5-rc.1`）：❌ 不支持——每轮检查靠 `agent/turn-stopping` 与 `agent.steer`，preset 靠 `@deepseek-ai/dsh-agent-preset` 行，0.1.5 都没有。
- 源码线（deepseek-harness master）：✅（verifiedHost: 0.2.1-rc.1）——host-021 波对 0.2.1-rc.1 树全量 build+test 绿，无其它表面变化。降级项：插件交回 agent 的检查结果是插件来源的上下文消息，0.2.0 聊天视图不显示这类消息（聊天里的折叠行是后续里程碑）；无头检查要本机装有 Chrome。headless profile 没有浏览器消费方，右栏不出现，但检查照常跑。

## 已知限制

- 只支持 2D（原生 canvas + HTML 界面层）；沙箱 CSP 拦掉一切外部请求，代码和资源都得放项目里。
- 宿主没有文生图，画面全靠代码画，美术风格只在能用代码画好的范围里挑。
- 还不能分享给别人玩（导出单文件、发布到 itch.io 是后续里程碑；排行榜、联机要服务器，更后面）。
- 插件放进对话的「检查未通过 n/2」折叠行，会被宿主收进本轮的步骤分组里：轮次结束后要展开「已完成，用时…」和步骤分组才看得到（宿主决定哪些节点独立显示的名单不对插件开放）。同样的信息在输入框上方的「将附上」和右栏「版本」里都有。
- 元素外观是像素行格式（`look`）；SVG / 矢量外观还不能在面板里编辑。

## 实现原理

- 试玩区与无头检查用同一个加载器（`src/vfs.ts`）：`sandbox="allow-scripts"` 的不透明源 iframe 收到项目文件后，在自己的源里生成 blob URL，改写相对 import 与 CSS `url()`，接管 `fetch`、图片/音频 `src`，再把 `index.html` 写进自身；`localStorage` 由桥接替身代管，写入回传给面板存进浏览器。
- 每轮检查挂在 `agent/turn-stopping`（只在正常结束时触发，用户中止不会被顶掉）；只看绑定了项目、`index.html` 存在、构建文件指纹变了的会话。失败用 `agent.steer` 把结论送回同一轮，每轮最多 2 次，第 3 次失败记为「已停止自动修复」。
- 版本是 `.game/versions/<n>/` 下的构建快照（保留最近 10 个），`current.json` 指向试玩区里的那个，`versions.json` 记历史（含已退回）。
- 用户层在 `.game/user.json`：滑块试玩值、还没告诉 agent 的改动、换风格请求；带「【面板改动】」开头的消息送达模型时（`agent/pre-step`），清单里列到的改动被清掉；外观方案在 `.game/proposals.json`。参数、元素由加载器在启动前放进 `window.dshParams` / `window.dshElements`，面板改动通过 postMessage 热替换，游戏每帧读即可生效；`dshDraw` 画像素外观，`dshGame.pick(x, y)` 支持点选。
