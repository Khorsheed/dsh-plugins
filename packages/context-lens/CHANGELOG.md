# 变更记录

## 0.1.0（2026-10-22）

首个公开发布（npm 首发；包自仓内 request-inspector 更名而来，`requestInspector` 服务与 Remote 命名空间保持兼容——迁移时替换依赖与 bundle 行，不要同时挂载两个身份）。minHost `0.1.5-rc.1`；turn 动作行入口需宿主 0.1.7-rc.1 起，旧宿主只剩会话头部入口（注册走 `ctx.slots.inject`，缺席位不炸 boot）。

按 turn 聚合每一次模型调用，把「这次请求到底装了什么」结构化、不漏内容地展示出来——system 每段来自哪里、带了多少工具定义、历史上下文多少、本次新增多少，外加 token 分布与耗时分布两个视角：

- **两处入口落到同一右栏 tab**：每个已完成 turn 的动作行图标（定位到该 turn 明细）与会话头部 utilities 图标（定位到最新）；面板内 turn 切换器换看本会话任意已采集 turn，切换时会话视图同步滚动到该 turn，「定位到最新」一键回底
- **请求视角**：真实缓存命中/未命中（provider usage 实测）与精确前缀差异（定位到具体字符、高亮变更范围）、新增输入与捕获输出、system/tools/history/added 构成；逐字原文展开、≥40 字符全文重复筛选（只计多余副本）、重复条目跨层互链并带返回导航；请求详情带模型/思考强度/输出上限/温度快照与 `{ }` JSON 切换；请求编号在每个 agent 内从 1 累计、跨轮连续，历史不足显示未知而不伪造
- **耗时视角**：所选 agent 的总耗时/模型/工具执行/间隙四格 + 各 agent 独立泳道（可跳回请求）+ 可按调用/报错/思考/参数/执行排序的工具表；并发区间分摊并标注，请求内余量与请求间隙分开；每次委派独立成 chip，主对话不重复累加已含在委派里的子 agent 模型时间；无请求的失败运行仍可见
- **工具调用卡片展示执行结果**：失败摘要直接可见、成功正文默认折叠（展开限高滚动）；执行结果不改变输入上下文构成与 token 统计
- **历史回溯**：面板查询先顺会话落盘日志重建挂载前的 turn——与实采共用同一套宿主 turn 号、绝不重复，实采优先、按预算从新到旧一次回填；one-shot 子 agent 是独立子进程、父进程瀑布看不到，从子会话落盘日志重建，system 原文与工具定义不落日志的字段显示诚实空态
- **上下文替换与压缩回放**：日志回放遵守上下文替换，已被压缩/裁剪的旧版本不进入后续上下文及重复统计，未改动的保留尾部继续算作历史；压缩摘要单独分类并可跳转到保留的压缩调用与压缩前请求；工具结果裁剪显示前后字符数，原请求仍保留时提供跳转
- **只读采集、只进内存**：三条宿主瀑布接缝（`llm/stream`、`system-prompt/assemble`、`session/event`）全程只读监听，不改写任何请求；每会话 30 turn + 500 条回溯请求 + 全局约 150MB 字符预算，挤压时最旧回溯先淘汰、实采永不被挤掉，被裁 turn 在轮次导航区标注、空间释放后自动补齐
- **服务端消费接缝**：五个 Remote 动词（`listTurns`/`getTurn`/`getRequest`/`getTurnTiming`/`getSessionTrend`）接受可选 `filter.scopes` 尾参，供可信服务端调用方按授权事实过滤——未授权子 scope 的日志连打开都不打开，被排除的 scope 对请求行/计数/token 合计零贡献；不带 filter 的本地调用语义逐字节不变
