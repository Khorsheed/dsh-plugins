# 变更记录

## 0.2.4（2026-10-27）

- **同一个成员的汇报按顺序判断**：几份汇报几乎同时到达时，不再有一份被落下、卡在已经回答过的那一轮后面（「还差 kimi」）。
- **重启后不再卡住攒着的汇报**：重启前攒着没交的汇报，打开协作间时会接着交给协调者。

## 0.2.3（2026-10-26）

**成员怎么协作**

- **成员之间自由通信**：任何成员都能直接给另一个成员发消息（`room_message`，CLI 成员走桥接的 `member_message`）。默认是「派活」，对方做完的最终回复自动汇报回派活人；也可以只是「知会」。为防止来回打转有跳数上限（默认 10），成员页新增「协作设置」：成员消息可设为自由发或要你确认、可暂停，被拦下的消息写明原因，确认或恢复后按原样放行。
- **汇报时机自动判断**：成员的结果是马上交给协调者还是先攒着，先按规则定（设置、失败、最后一份结果等），拿不准时问可选的快速决策服务（TypeSafe）；没装它就一到就汇报。攒着的汇报在协调者下一轮一次带上，不再一份汇报占一轮；协调者正在跑时到达的汇报并进当前这一轮。
- **任务**：你发出的每一条引出工作的消息算一个任务，后续派出的活都记在它名下；新消息归到哪个任务，看输入框的标签，拿不准时由判断模型决定。右栏的「协作」页有「任务 / 团队」两个视图：任务列表可筛选，每个任务能看到说了什么、追问怎么归档、哪里在等你处理、正式目标、子任务树和泳道时间线，还能整条停止（就地确认）；「追问」「＋ 新任务」给主输入框打标签。它取代了原来的任务板、计划页和输入框上方的胶囊。
- **团队视图**：把房间画成一棵树（每个成员挂在最常给它派活的人下面），节点上标派活数、汇报数和知会数，并汇总每个成员的轮次、用时和 token；成员多时改成主干加分支的连线，放不下的一行收成「+N」。成员页的「团队」按钮和每张卡片的「在团队中定位」直达。
- **自动判断看得见**：任务归属和汇报时机统一成一张判断场景表；每次判断（按规则还是问了模型、问了什么、答了什么、用了多少 token）都记下来，时间轴上一行淡色结论，「查看判断」在 Context Lens 的「房间」页签打开那次调用。「协作设置」新增「自动判断」分组：自动归档任务、自动决定汇报时机，以及「立即汇报阈值」和最长等待。
- **精简的成员提示与公开角色**：成员第一轮收到一份房间简报（名字、公开角色、你给它的私下说明、目标、其它成员的公开角色），之后只发变化；成员之间看不到彼此的私下说明。邀请与编辑可填公开角色（≤30 字），卡片上显示成标签。工具用法写进工具描述，简报不再每次重复。
- **移除成员说到做到**：移除时停止它正在跑的一轮、撤回排队的消息、收尾或交接它手上的任务、告诉在等它的人，然后才离开；卡片上就地确认并列出实际后果，五秒内可撤销。

**跨房间求助**

- **向别的会话求助**：成员可以用 `room_help` 点名另一个会话（标题、id 或 @ 引用）请它帮忙；对方会话里出现一张标明来自哪个房间的求助卡片，回复作为汇报送回提问的成员。CLI 成员也能用。
- **@ 菜单能选别的会话**：先列本房间成员，再列其它会话（不输入时是最近五个，输入时按匹配度和新近排序）；展开一个房间可以挑它的某个成员，搜索时也照样列出。
- **向另一个房间或它的成员求助**：点名房间时交给它指定的成员，否则交给它的协调者；对方暂停时照常排队。
- **求助超时变琥珀色**：求助过了提醒时间还在排队或进行中，那一行变琥珀色并显示已等多少分钟（「协作设置 → 求助提醒」，10–120 分钟，默认 30），不会自动取消。
- **外援上团队树**：被求助的会话以虚线「外援」节点挂在提问人下面（都结束后变灰），不计入房间合计；常被求助的会话可一键「加入房间成员」。
- 你的消息里 @ 了外部会话时，派给协调者的提示会点明这些会话并提醒用 `room_help`，入房较早、没见过这个工具的成员也知道去问。

**CLI 成员**

- **CLI 成员能用模式工具**：邀请 Codex / Claude Code / Kimi 成员时可以选模式，成员就能用这个模式的插件工具；简报会告诉它这些工具在 `dsh-member` MCP 服务里。需要确认的工具调用在房间里出「⚠ 成员 要你确认：调用 …」，点「允许一次 / 拒绝」，并计入「需要处理」。邀请对话框里原来的预设/模式标签合成一个「模式」下拉框，名字与宿主自己的模式选择器一致。
- **原生 dsh 成员带模式**：邀请 `native` 成员时可选一个宿主 agent 预设，成员就是这个宿主里按该预设组合的子 agent。
- **CLI 成员向你提问**：成员可以发选项卡问你，你点选或打字回答，答案回到成员手里；30 分钟没答或重启后卡片失效。简报引导 CLI 成员用它，而不是把问题写在回复里。外部协调者的 `room_invite` 也能带模式。
- **子会话以成员名字标注**：宿主的子代理列表里显示「Codex：剪刀手二号」，不再一律是「Codex」。
- **邀请不绕路**：还不是房间的会话里 `room_read` 直接给出可邀请的 harness、模式和当前模式；`room_invite` 认 harness 名或显示名（claude-code、Claude Code、kimi）。会话头部的「邀请 agent」入口也能选模式，并保留角色、类型和模式。

**发言与输入**

- **发言卡片带用量和明细入口**：每条发言显示这一轮计费的 token，统计行新增成员一栏（各成员的模型、轮次、token 和用时）。卡片下方的操作行与宿主消息一致：复制、打开成员会话、请求明细（在 Context Lens 里定位到这一轮）、用量（悬停看拆分）和时间；最新一条常显，旧的悬停出现。
- **折叠更顺手**：最新一条回复房间的发言默认展开、有更新的回复时再收起，汇报和旧回复默认折叠；你自己的展开/收起按发言记在浏览器里；折叠控件换成与消息工具一致的右下角圆形箭头，点渐隐处也能展开。
- **成员实时输出像宿主自己的流式**：思考显示成宿主的思考行，回答直接显示正文；正在跑的成员行与发言卡片同形，回复落地不跳。
- **输入条与官方一致**：字号跟随设置（默认 14px），边距、停靠、圆角和阴影同官方输入框；协调者一行显示「● 名字 · 协调者」及其提供方，用成员的颜色。引用以标签显示在输入框上方（点开预览、× 移除），不再在文本框里摊成原始引用块。
- **成员编辑对话框**：顶部是这个成员的卡片（随编辑实时变化），然后是邀请时定下的提供方和模式，再是可编辑字段与带标签的「模型」控件。

**修复**

- 输入法候选按 Enter 不再直接发送（含 Safari 结束输入时的那次按键）。
- 重启打断的一轮不再卡住后续：你给这个成员发新消息、停止任务、或别的房间向它求助时，都会把它没收尾的普通轮次记为未完成并继续（正式目标的尝试仍需你确认）。
- 外部协调者在场时，用消息工具就地编辑的消息会照常送到协调者，不再悄悄丢掉。
- 用量合计按互不重叠的几部分相加（未命中输入、缓存读写、输出）：缓存多的 Claude 一轮原来只显示几千 token。
- @ 菜单修复：房间每秒重绘时查询被取消、只剩本房间成员；候选结果解包错误导致从不显示别的会话；开头的会话标签被误当成成员 @ 而发送失败。
- 已归档的会话不再出现在 @ 菜单里，也不会被求助（原来打开是空白页，求助石沉大海）。
- 发言的提供方标签恢复为三级灰（误显示成错误红）；任务页的返回改用面板组件的箭头；「请求明细」图标改由本包自带（宿主 0.2.1-rc.1 起不再提供）。
- **README 重写**：改为大白话说明，写明它为什么只在带协作间的套件模式里出现、要随套件一起装；去掉过时的验收说明与失效链接。

**其它**
- **新成员默认用房间的模式**:`room_invite` 新增 `mode`(不填则通过 inheritPreset 沿用房间会话自己的模式;`"none"` 表示只用 CLI 自带工具),回执里写明模式;邀请对话框预选当前会话的模式,模型与思考强度改成两个带标签的下拉框。
- **卡名改为「协作间」**(原「多Agent协同」):与界面里一直使用的叫法统一,也和所在的「多Agent协作」套件卡区分开;英文卡名仍是 Room。
- **run-state 边携带子会话关联**:`room/run-state` 在身份存在后的所有边恒带 `childSessionId`（成员首跑的 running 边早于句柄产生，终态边与后续轮次都有）；终态边（done/cancelled/failed）新增 `childTurn`（该运行写入子会话的轮次号，只读在内存的存活会话）。`room/dispatch`、`room/run-state`、`room/coordinator`、`room/member-added` 是 Context Lens 的外部读取接口（类型注释已标注）。
