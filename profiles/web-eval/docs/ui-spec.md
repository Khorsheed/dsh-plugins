# web-eval 界面规格（I5）

定稿于 2026-09-13，由走查稿第二版收敛而来。本文定的是**人看什么、点什么，agent 用什么，后台调什么**；实现细节归各任务的文案（[iterations.md](iterations.md) §三）。改本文即改口径，改口径要开新任务。

**2026-09-23 修订（T70）**：按提案 [eval-journey-redesign](../../../proposals/active/2026-09-23-eval-journey-redesign.md)（交互稿 [v5](../../../proposals/prototypes/eval-journey-redesign.html)）改 §四–§七 与 §九，外壳不动。每处改动后的「（Dn · 第 k 条）」指回提案的 D 项与 T70 文案条号；I5 收口批 T71–T76 以本版为正本。

## 一、角色

四个「模型」不是一回事，界面按角色分：

| 角色 | 是什么 | 在哪出现 |
|---|---|---|
| 规划 / 分析 agent | 实例里走 `eval` 预设的会话 | 规划期与分析期；起草题目与实验，读进度，写分析初稿 |
| 选手 | 被试的 harness CLI，在容器单元里跑 | 执行期；只看到单元里的题干与验收标准 |
| 判官 | 也是一个条件，一次不带工具的委派 | 评估期；看去指纹产物与评估标准 |
| 编排器 | 确定性代码，唯一执行者 | 全程；调 datasets / mission / lab / local-agent 的服务面 |

人有三个面：**会话**、**题集 tab**、**实验室 tab**。评测模式下 missions tab 隐藏，mission 是评测的账本与释放闸，词不出现在界面。

## 二、口径（不因 UI 化而放松）

- **R1** 批准、登录、终评永远是人的动作。agent 起草题目与实验、validate、读进度；不起 run、不 provision、不登录、不写 human-final。
- **R2** 实验室里的格子与格子详情是 mission 账本的投影；格子只由实验展开生成，人不手建、模型不手建。前端只经 eval 自己的 Remote 读投影与转发动作，零 mission 依赖。
- **R3** 选手看到的只有「题干」与「验收标准」两个槽位的字节；参考答案、评估标准、检查脚本只经服务面以显式单层读，绝不进选手格子。
- **R4** 销毁路径唯一：只有编排器持有 docker socket；lab 不给模型工具。
- **R5** tab 标签「实验室 / Experiments」，插件 id 仍是 `eval`（仓库里 `lab` 是容器单元插件，不撞名）。
- **R6** eval 预设不再挂 `mission-tool`；agent 看进度用 eval-tool 的读工具。

## 三、槽位（题集的词汇）

题集文件按**谁看得到**标注，不按层名。槽位由题集 `dataset.json` 的 `layers` 与 `register` 算出，每个文件恰好落一个角色；层名只在高级视图里出现。

| 槽位 | 文件（harness-comparison 的约定） | 谁看 | 对照 |
|---|---|---|---|
| 题干 | `task.md`、题集级 `prompts/<stage>.md` | 选手 | SWE-bench problem_statement · Terminal-Bench instruction |
| 验收标准（可选） | `standards.yml` | 选手 | Terminal-Bench 写在 instruction 里 |
| 参考答案 | `answers/oracle/` | 判官 | gold patch · solution · canonical_solution |
| 评估标准 | `answers/rubric.yml` 等 | 判官 | rubric 型评测（PaperBench、HealthBench） |
| 检查脚本 | `checks/`、`checks/probes/` | 探针 | FAIL_TO_PASS 测试 · tests |
| 其他文件 | `item.json`、`schemas/`、`conditions/`、`plans/`、README | 所有人可读（透传区） | — |

作答记录不进题库：每次作答的产物在实验的格子里（mission 账本 + 导出 bundle），题目详情按题目投影一份只读的「作答记录」。

## 四、题集 tab

**登记，不绑定**（D1 · 第 5 条）：

- **登记单位是仓库**，worktree 不登记。一个仓库登记一次，所有会话共用；**会话不绑定题库**，一个会话可以跑多个实验、用多个题库。登记表单复用数据集协议的「绑定确认流」。
- **版本由实验钉住**：plan 记 repo@commit，eval 按 commit 取题，只读（`git show` / `git archive`），eval 不为取题开 worktree。已有实验一律读自己钉住的快照，不读任何「当前绑定」。
- **可见层是题集属性**：只管规划 / 分析 agent 能读到哪几层；缺省只勾 modelFacing；只有人能改。选手隔离归 R3 与实验单元，不在此。
- **agent 往哪写 plan / analysis：待 T73 实施计划定。** 题库仓库是多 agent 共享的检出，HEAD 不能动，今天的写都走会话绑定的 worktree——去绑定就拿掉了这个写目标。两条候选：
  - **(a)** eval 按实验开分支与 worktree（`exp/<id>`），plan / analysis 写在里面，人合并；
  - **(b)** 实验成为部署级对象，plan / conditions / analysis 出仓库、存 eval 自己的状态目录，只引用 repo@commit，题库只读。
  
  连带要定的：`eval_repo_write` 的白名单（G16）与 `datasets_put_item` 的写目标。定之前，本文里「写进题库工作树」的说法都按「待 T73」读。
- 输入框上的题库 chip 去掉（第 8 条）；datasets 在非 eval 场景要不要保留可选的「会话收窄」，由 T73 实施计划给结论。

**列表**：按登记的仓库分组，一行一个题集——id、题库版本（分支 @ commit）、题目数、槽位与层的对应、canary 是否设置、validate 结果、用于哪些实验。动作：**新建题集**（生成带 `dataset.json` 的骨架）、**登记仓库**（指一个已按协议组织的仓库，validate 后入列；勾可见层）。

**详情**（题集 › 题目）：文件树 + 预览。树上每个文件标槽位与「谁看得到」，槽位可筛选；「选手将看到」把这道题在单元里的样子原样列出（防泄题自查）；可判性一行（评估标准几条、探针几个、阶段 schema 几个）；「作答记录」区按题目列各实验的格子。动作：**题目骨架**（生成题干 / 验收标准 / 评估标准 / 检查脚本目录的占位文件并落位，正文在编辑器里写或让 agent 写）、**导入题目**（指一个已有的题目目录）、validate。

界面不做题目正文编辑器：检查脚本是代码，评估标准是带权重的 YAML，表单写不了。agent 走同一个动作（`datasets_put_item`，写目标待 T73），commit 仍是人的。

## 五、实验室 tab

**硬口径：只有「启动」有阻塞项**（D9 · 第 3、11 条）。启动之后没有任何一步拦路：数据问题由计算口径自动降级（§五 结果对比），人的判断以标记形式跟着结果走（§五 人工评估）。

**列表**（D8 · 第 2 条）：一行一个实验——名称、题库版本、对比组数（+ 判官）、题数、次数、对比变量（由对比组 diff 自动推出）、状态、进度、开始时间。草稿与 run 同列。

- **分组**：需要你处理（待批准、停滞、评估中待人工评估）/ 运行中 / 已完成（含评估不成立）/ 已归档。归档只隐藏，不动账本。
- **缺省「本会话发起」**：读 run 的 `originSession`，会话本身不存任何东西；可切「全部」。没有 `originSession` 的 run（命令行发起的）不隐藏——页首一句「另有 n 个不属于本会话」，点了切「全部」。
- 动作：**新建实验**（向导）；停滞行上「重跑」；归档 / 取消归档。

状态（第 2、11 条）：草稿（还没过 validate）→ 待批准（validate 过了等人批）→ 运行中（格子在跑）→ 评估中（判官在判或等人工评估）→ 已完成（人走了人工评估的前三个出口之一，见下）；另有被拒（就绪检查没过）、已取消，以及两个新词：

- **评估不成立**（终态）：人在人工评估点了「放弃终评」。只保留原始数据和理由，不给结论；和归档、删除是两回事，写进导出。
- **停滞**（推导态，不写账本）：进程里没有活 job，**并且**格子一段时间没有任何进展。原先设想的「中断」与「卡住」合成这一个。只看「没有活 job」会误判命令行发起的 run——它的 job 在 CLI 进程里，web 实例本来就没有。停滞给「重跑」。账本归 mission，eval 的状态一直是推导出来的（T35a 的边界），启动时不改写账本。

实验不会自己变成「已完成」：判官判完后停在「评估中」，结果对比在「评估中」也随时能看。

**新建实验**是四步向导（v2）：① 选题库与题目（题库版本、题目多选）；② 选对比组（已有的，或从一个已有对比组复制改点名字段：harness、模型、端点、作用域、预设、权限、推理强度——七个可改字段，端点必填）；③ 判官与采样数、次数、阶段、每格预算；④ 环境与确认（镜像、网络、出网自检、顺序 seed，都有缺省，折在「高级」里）。最后一步的动作是「保存草稿并 validate」，产出 plan 与新对比组文件（写到哪待 T73 定，见 §四）；**启动不在向导上**。agent 一句话起草的草稿和人建的落在同一个列表，向导只是同一个服务面动词的另一张皮。

**详情**四个阶段（v2，2026-09-18 定；v1 的七个子页见 git 历史，T63 按 v1 收口，T67 按 v2 重构）。每个阶段一页；页顶一条状态与**一个主动作**：草稿 → 「去 validate」，待批准 → 解决第一条阻塞项，全绿后「批准并启动」，运行中 → 「看运行记录」，停滞 → 「重跑」，评估中 → 「去人工评估」，已完成 → 「看结果」，评估不成立 → 「看运行记录」，被拒 → 「重新检查」。底层信息一律折进「高级」或「详情」。

| 阶段 | 内容 | 人的动作 |
|---|---|---|
| 实验设计 | 两段（D5、第 1 条；交互稿「方案卡」「就绪清单」两场景）。**上半段 · 方案**：① 要回答的问题 / 预期 / 怎么算回答了（plan rev13 的三个字段；rev12 的旧 plan 没有这块就不显示）；② 实验规模（「1 题 × 3 组 × 1 次」）与对比变量（由对比组 diff 推出，人话，键名只在悬停）、题库版本（repo@commit）、判官与采样数——次数、每格预算、判官采样这类数字**就地可改**，写回同一个 plan，**启动后冻结**；结构性改动交给 agent（输入框预填引用）；③ 对比组表（harness / 模型 / 端点 / 作用域 / 预设 / 锁 / 就绪；对比组 diff 只高亮不同项）与计划网格：**同一个网格组件**，行是题、列是对比组，跑前格内是「计划 n 次」，跑中在运行记录里同一网格显示每格状态。**下半段 · 就绪清单**：原 validate 与环境检查结果重排成两组——**阻塞项**（题库未登记、对比组未 provision、validate 不过……，每条一句人话 + 就地修复按钮）与**提醒**（不影响启动，附「让 agent 处理」：只在输入框预填引用，不自动发送）。页顶主按钮 = 解决第一条阻塞项；全绿后变成「批准并启动」，只有人能点（R1）。**高级设置**（默认折叠）：顺序 seed、阶段、判定来源、环境（镜像 / 网络 / 出网自检）、run.meta 原文、作者备注（保留换行）。**已完成与评估不成立的实验**这一页只读，读实验钉住的快照，不读会话、不出现「未绑定」。 | 解决阻塞项（provision：实测 home.sha 写回声明、重算哈希、写 lock，一步变 ready；就地改端点；登记仓库弹出题集 tab 的登记表单，不抛命令行）；批准并启动、退回修改；就地改数字（启动前）；新建对比组（进向导第 ② 步）；「让 agent 处理」 |
| 运行记录 | 顶部同一个网格（每格：圆点、运行状态、得分（有判定即显示）、告警）；单对比组时网格上方一句「只有一个对比组，添加对比组才能比较」+ 按钮。实验停滞时网格上方一句「停滞：已有 x 分钟没有进展，也没有在跑的任务」+「重跑」（第 2 条）。下面是列表：题 × 对比组 × 次、运行状态（桶与阶段并成一列，用词表）、得分、耗时、尝试次数；筛选：全部 / 运行中 / 完成 / 失败 / 阻塞。右侧详情：头部是**判定来源**（终评 / 判官初判 / 脚本判定 / 未判；多层混合时一句「得分来自不止一个来源」）+ 状态标签（成功 / 异常），**不给数值**——分数是 report 从导出的 bundle 逐判据算的（T54），运行记录页照活账本再算一份就是第二套算法，数值与逐判据来源在结果对比页（2026-09-22 按 T54 实现回写）；阶段时间轴（工作区就绪 → 阶段一 → 提交 → 阶段二 → 已判 → 已释放，每段时长）；参数配置键值表（sample、judgeCondition 等注解，不给 JSON）；附件区（产物按人话命名：评测日志、结果、verify 输出，点开预览）；「看作答」进作答视图（D6，见下）；子会话入口（可续聊不干预，T69）。 | 带原因重跑、释放、导出 bundle；停滞时重跑 |
| 结果对比 | 自上而下四块，**结论先行**（第 1 条；交互稿「结果对比」场景）。**① 结论卡**：原样回答方案里的问题（rev13；旧 plan 没有问题块时只给配对结论）；一行判定来源（「来源：判官初判 + 人终评（部分）」；未经人工评估收尾时写「未经人工确认」）；人在人工评估「带标记提交」的原话原样显示在卡顶（D9）；置信区间按下面的门槛给或不给；卡下是收尾 / 导出与「bundle 早于最新终评」的「重新导出」；一行「有效性校验 5/5 ✓」，展开进审计。单对比组：「当前为单对比组实验，无对比数据，下方是基线表现」。**② 判据 × 对比组表**（T54 补充（一）；用户 2026-09-18「看不出每个维度的得分对比和评委的评判依据」）：每题一张，行是判据（id、维度 = rubric 的 axis、权重、极性），列是对比组，格里是该判据在该组的结论（✓ / ✗，负向判据成立即缺陷、用 ✗ 的颜色；按比例给分的写比例；多次写成立次数），格下小字是这格的得分来源（「人 1 / 判官 3」这样的混合，正是逐判据合并之后每条判据取到了哪一层）；点开一格是逐条判定原文——证据、判官条件名与模型（报告页揭盲）、人改判过的标「人已改判」且判官原判仍留；底行是本题总分，与配对表同一份计算。单对比组也给这张表（一列）。配对表与判据表每格都能去运行记录（T69：只有一条记录就直接打开那条，多条就落到运行记录列表并挂上筛选 chip）与作答视图。**③ 效率**：效率表 + 柱状图（活跃时长、输出 token、cache read；数字格式化：31.5k、4 分 48 秒）。**④ 审计**（默认折叠）：配对差值表原表、**实验有效性校验**五条（✓ / ⚠ 各带悬停解释「为什么这条影响比较」；`materialization`、`refs.fingerprint`、`planSha` 这类内部字段名只在这里出现）、判官一致性（高 / 中 / 低，κ 在悬停）、bundle 导出时刻与最新终评对照。<br>**有效性校验**：原四条（题面一致 / 环境一致 / 对比组一致 / 程序一致）任一不过，比较节整份不下发（现状）。第五条 **判定覆盖一致**（D7 · 第 3 条）：每条判据在比较的各格里要么都被判过（人终评与判官初判同属「已判」一类），要么都没有；一侧只剩脚本、或判官采样全部报错（判官缺席），即不通过——这一对降级为描述，不给 Δ 与 CI，`rankReason` 写原因。人只改了一条判据的终评不触发降级。<br>**置信区间门槛按题数**（D7 · 第 3 条），不与排名共用：有差值的题不足 3 道就不给区间，页面写「只有 k 道题有差值，给不出区间」。排名门槛不变，仍是 `comparePair` 的 n（各题配对次数的最小值）≥ 3；给了区间但没达排名条件时标「仅供参考，未达排名条件（每题需跑满 3 次）」。 | 收尾（finalize，过释放闸）、导出（bundle + report 一起写盘，记 run 级注解）、bundle 早于最新终评时「重新导出」 |
| 人工评估 | **可做可不做**（D9 · 第 11 条；交互稿「人工评估」场景）。页首一句提示：有判官缺席的格时写明哪几格，附可选的「补判」——不补也能收尾，不是阻塞项。盲评：**同题的各对比组产物左右并排**（就是作答视图打开盲评开关），去指纹、不露 harness / 模型 / 对比组名，编号按 run 的种子顺序（「P0-placeholder · 第 1 次」）；每格各自按评估标准打分，不做二选一（判定契约不变：每格一份分数）。判官的 llm-draft 与人的 human-final 并排。队列筛选：未评 / 已评 / 按题。一致性通俗化：「评分者一致性：高（κ 0.85）」，低时提示「建议增加判官」。<br>**页底四个出口**：① **提交终评**（结论来源「人终评」）；② **带标记提交**（人觉得评得有问题但让结果往下走，写一句理由，结论卡顶部原样显示、写进导出）；③ **不做终评，直接收尾**（结论标「判官初判，未经人工确认」）；④ **放弃终评**（人认为本轮评估不成立，写理由，实验收成终态「评估不成立」、写进导出）。「已完成」只在 ①–③ 之后出现。<br>**实现形状**（第 11 条定死）：四个出口是 eval 的 **run 级注解**（同 T60 导出注解的做法），不加 mission 状态、不改账本状态机；ns 与字段在 T72 文案定。 | 打分（human-final 的唯一写入口，R1）；补判（可选）；四个出口之一；bundle 早于最新终评时「重新导出」 |

判官不是一行：它的判定是本格的 llm-draft 注解，带 `by` = 判官条件 id。

**跨面旅程**（提案「目标」；交互稿总览）：提问 → 起草方案 → 就绪 → 运行 → 看作答 → 人工评估 → 结论。这条线落在哪一面见 §七；页面有什么以上面的四阶段表为正本，本段只讲串联：

## 九、视觉与文案基线（2026-09-17 补，每个切片自查）

走查稿定的是信息架构，没定这些；六个子页各自长成了各自的样子。以下是硬规则，每个切片按它自查，界面收口时看截图对照它验收。

- **沿用宿主的设计 tokens**，不自造颜色与字号：`--dsw-alias-label-primary / secondary / tertiary`、`--dsw-alias-border-l2 / l3`、`--dsw-alias-bg-l2`、`--dsw-alias-interactive-bg-hover`、`--dsw-font-family`、`--ds-font-family-code`（mission / datasets 的 tab 就是这么写的）。明暗两套都要看。
- **人话标签，内部键不出现**。页面上不出现 `unit.scopedHome.var`、`home.sha` 这类键名；因子显示为「模型 / 作用域 / 权限 / 推理强度 / harness / 版本」，键名只在悬停或详情里。数组、JSON、完整哈希不当标题：哈希缩到 12 位，数组转成人话或折叠。
- **列永远是对比组名**。网格的列头是对比组 id，对比变量的值作副标题；只有多变量时才出现「按哪个变量分组」的选择器，且默认折叠。单变量实验的网格不该有筛选行。
- **一张状态词表**，中英不混：实验状态 草稿 / 待批准 / 运行中 / 评估中 / 已完成 / 评估不成立 / 被拒 / 已取消，推导态 停滞（2026-09-23 加后两个词，D8 · D9 · 第 2、11 条；「评估不成立」是终态用灰，「停滞」用橙）；格子阶段 待起 / 工作区就绪 / 阶段一 / 阶段二 / 已判 / 已归档 / 可释放 / 已释放 / 已停；桶 就绪 / 进行中 / 阻塞 / 排期 / 完成。同一状态在列表、矩阵、格子页、报告页写法一致。
- **错误态三段式**：一句人话说发生了什么（「题库路径不是 git 仓库」），一句说怎么修（「重新登记：在题集 tab 点「登记仓库」」），异常原文与路径折叠在「详情」里。页面上不直接渲染 `error.message`，不裸露绝对路径。
- **空态要说下一步**：没有 bundle 就一句「还没导出，点这里导出」，不是一段英文。
- **同一组件**：空态、错误态、状态 chip、圆点图例、表格、抽屉在两个 tab 里是同一套组件，不各写一份。
- **验收看图**：截图在界面收口任务里统一交一次（每页明暗两套），协调者与用户看图对照本节验收；其它切片不各自截图（每次截图都要登录并发一条消息才进得到聊天界面，成本高），回报里按本节逐条说明落在哪一页即可。重构轮（T67）的验收由协调者自己起临时实例驱浏览器看。2026-09-18 已照做：临时实例拷 3171 的账本（不拷凭据）、playwright 明暗两套、DOM 量尺寸；走查在 `scratch-screenshots/t67/walkthrough.md`（本机 scratch，git 忽略、未入库），一轮 13 条（状态色 token、并排列被三列 grid 裁掉、空态残留旧页名等）见 iterations.md §三「T67 补充」。

以下三条 2026-09-18 补（用户走查 T63 后定）：

- **术语表（v2）**：矩阵形状 → 实验规模；因子 → 对比变量；条件 → 对比组（判官仍叫判官）；快照 → 题库版本；桶 + 阶段 → 一列「运行状态」；格子 → 运行记录；判官台 → 人工评估；四条不变量 → 实验有效性校验（2026-09-23 加第五条「判定覆盖一致」，D7）；物化哈希不单独露出，它是「题面一致」的证据。列头里的英文术语也换：canary → 防泄标记，validate → 校验，attempt → 尝试次数，rep → 次数，harness 保留。
