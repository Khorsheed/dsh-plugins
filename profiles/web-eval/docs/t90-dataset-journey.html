题集接入旅程

首次使用和第 N 次使用都走同一条路：人说清楚「数据在哪、叫什么」，Agent 按 dataset-authoring skill 把它整理成符合协议的题库仓库并提交，最后由人确认一次登记。登记决定模型能看到哪些层，所以这一步必须由人点。

1 · 发起

人只填三项，然后交给 Agent

题集 tab 的空态和「添加题集」按钮打开同一个弹窗。也可以不开弹窗，直接在对话里说一句。

  • 数据在哪（必填）：本地目录或文件、下载链接，或公开数据集的名字。
  • 题集名称（必填）：以后在实验里选它时看到的名字。
  • 想拿它测什么（可选）：帮 Agent 决定怎么取舍字段、要多少题。

点「让 Agent 整理」会新开一个「题集整理」会话并把请求写进对话框，和 T87 新建实验同一种做法。整理会话会看到答案，所以不复用评测会话（见文末待定项 B）。

2 · 看数据　3 · 对齐方案

Agent 先读懂数据，再把方案讲给人听

  • 判断格式、条数、哪些字段是题面、哪些是标准答案、判分方式（精确匹配、rubric、可执行检查）。
  • 公开数据集：先说明来源、许可、下载体积，人同意后才下载。
  • 已经符合协议的仓库：只做校验，直接跳到第 5 步。
  • 开工前先检查本机有没有 git。没有的话用大白话说明用途，征得同意后替人安装（macOS 用系统自带的命令行工具安装，Windows 用 winget）；人不同意就停在这里，不登记。
  • 拿不准的地方只问关键问题，一次问完，给默认值。

方案里写清三件事：题目怎么切、哪些内容选手可见、怎么判分。人回答「可以」之后才开始改造。

4 · 改造、提交、校验

Agent 建仓库、写题目、提交、跑校验

  • 默认在 dsh 数据目录下新建题库仓库；人在第 3 步指定了位置就用指定的。
  • 按协议生成每道题的目录，把题面、答案、判分规则放进对应的层。
  • 写配置文件 datasets/<id>/dataset.json，声明有哪几层、每层选手能不能看到，例如 visible（选手可见，放题面）和 grading（仅判题，放答案和判分规则）。哪些文件归哪一层，是 Agent 读完题后按第 3 步对齐的方案定的。第 6 步人确认的就是这份声明。
  • 每写完一批就提交一次，所以题集 tab 随时看得到进度，不再有「写了但看不见」。
  • 跑协议校验，失败就自己修，修不了的告诉人原因。

5 · 提交登记申请　6 · 确认登记

Agent 只能申请，登记由人点确认

登记表一直只允许人写，这是防泄题的闸：它决定模型能读到哪些层。Agent 提交一份预填好的申请，题集 tab 顶部出现提示，人打开核对后点确认。

  • 人先看到的：原目录和题集左右对照。原目录里每个文件标明去向：拆分、原样复制、未使用，未使用的写明原因；题集里每个文件标明来源：从哪个文件、哪个字段来的，或者是 Agent 新写的。顶部汇总拆分、复制、新写、未使用、删除各有几个。不分层的文件（选手也能看到）标红。
  • 改已有题集时：同一个视图换成「已登记版本 → 新版本」，多出「修改」，删除的文件逐个列出。只有可见层有变化时才需要重新确认。
  • 人要核对的：登记名；每一层是「选手可见」还是「仅判题用」，重点看答案层没有被放成选手可见。拿不准可以点「随机抽看 3 道题」直接看内容。
  • 人可以改的：登记名、各层可见性。
  • 插件自动填、默认收起的：仓库路径、跟踪分支、写入检出。熟手可以在「高级」里改。

Agent 对每一层给出建议和理由，但开关的最终状态以人点确认时为准。

7 · 在实验里选用

登记后马上能在新建实验里选到

  • 新建实验弹窗的「题集」下拉里出现 gsm8k，实验会钉住当时的提交版本。抽题在这里做：选「全部 / 随机 N 题（固定种子）/ 手选」，结果作为实验计划的题目清单钉住；同一份题集可以被不同实验抽不同的题。
  • 以后要加题或改题：还是走同一条路，对 Agent 说「gsm8k 有几道题答案标错了，改一下」。Agent 提交新版本，已登记的题集自动跟到新提交，已有实验仍钉在旧版本。
  • 只有可见层发生变化时，才需要人重新确认一次登记。
